# 必要检查

在仓库根目录运行：

```bash
.venv/bin/python -m pytest -q
```

只保留会影响机制、成绩或实验运行的检查：

- `evotrace_v4/`：全树节点预算分配（含精确副本与半整数并列名次）、合并子树区与路径收缩重连虚拟根、根部子树区不反思、反思结果的比较对象（子树区与起点比较，路径区不与终点比较）与生成前分析的传递、332 节点紧上界与单轮幂等性、空反思沿用已有经验与修订后写回、探索从全树按源码去重抽样与空代表集边界、末步预算守门、三算子上下文（形成路径与个体卡片）与探索输入长度上限、断点恢复与标准库独立运行。
- `evotrace_v3/`：覆盖代表集与结构距离、路径收缩与子树剪枝区域划分、节点数上界与单轮幂等性、事实反思回退、无编号轨迹上下文与 `Explore` 挂根、共享一次修复、断点恢复与标准库独立沙箱运行。
- `evotrace_v2/`：单次保留选择、冷却与真实使用、联合剪枝和路径收缩、逐事件历史守恒、多轮经验交接、提交前后恢复与独立运行。
- `evotrace_v1/`：脱离仓库的独立运行、初始化与修复、模型接口与评价超时、统一选择与完整结构容量、跨方向与重复收缩、跨轮评价计数、路径/旁支归属、参考来源、经验读取与恢复。
- `independent_base/`：Base 的纯 Boltzmann 选择、提示、共享修复、预算、恢复、八任务接入与脱离仓库独立运行。
- `method/`：基线的关键决策与共用实例评价。
- `task/`：基准任务的数据划分、解的合法性与真实目标值。
- `experiments/`：统一实验入口配置契约、结果读取与对应、看板、成本、共享资源调度与远端监控。
- `base/`：模型请求与用量记录、接口故障，以及超时进程清理。

模型回复使用离线假数据，不请求真实模型。测试之间不互相导入；少量共用数据放在 `support.py`。

新增测试应对应一个会改变研究结果的错误，或已经遇到的实际运行问题。同一行为只检验一次。不为提示词原句、旧版本字段、每种部署参数组合或普通辅助函数另写测试。
