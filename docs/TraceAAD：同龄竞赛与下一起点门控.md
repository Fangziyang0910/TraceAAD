# TraceAAD：同龄竞赛与下一起点门控

记录日期：2026-10-28。来源为 Claude Code 会话《TraceAAD 适应度引导保守化问题定义》，取截至 2026-10-28 23:09 JST 的最后一条机制建议。会话 ID：`ea84690e-c70f-47f9-90f9-0f732a1ca27c`。

本文记录的是**机制提案，尚未实现或验证**。第 1–3 节整理原方案与已有依据，第 4–6 节给出独立评判；不将评判中的建议视为已经确定的机制。

**判断：问题切入有吸引力，值得做最小验证。巧妙之处是将高分结果的保留与局部开发状态的更新分开；但行为归路已有直接先例，跨轨迹接收后的收益记账尚未闭合，目前还不足以仅凭组件组合认定为成熟的强方法。**

## 1. 核心问题：一次偏离，如何变成持续接管

同龄竞赛保护的是一条轨迹获得多少次开发机会，但这些机会未必继续用于原来的算法思想。若从思想 A 出发生成了熟悉思想 B 的高分实现，按适应度选择下一父代就可能让 B 接管 A 的开发；随后，B 又进入提示历史，进一步影响后续生成。

这里需要区分两个事件：**生成偏离**是一次尝试产生其他思想的实现；**偏离被接纳**是该实现成为下一父代或本轨迹的成功经验。最新方案主要干预后一个事件，不承诺降低单次生成偏离的概率。

关键思路是：**一个程序值得保存，并不意味着它应该成为当前轨迹的下一起点。** 全局档案保留搜索成果，局部轨迹决定从哪里继续开发。

## 2. 最新机制原案

这一版将上一版的“跨轨迹加权排斥”简化为“下一起点门控”（next-parent gating）：不用排斥权重、核带宽或独立冠军通道，而是按行为决定子代能更新哪条轨迹。

### 2.1 同龄竞赛：按实际尝试分配机会

- 每条轨迹按发起的生成尝试计年龄；失败、被门控拒收或归入其他轨迹的尝试仍消耗发起轨迹的年龄。
- 在 5、10、20 等检查点，与冠军轨迹在相同年龄的历史成绩比较；沿用现有同龄调度的检查点结构。
- 同龄成绩只取**已接受路径上的最好成绩**，不能取该轨迹生成过的全部候选的最高成绩，否则偏向其他轨迹的高分子代仍会替原轨迹通过检查。
- 优先开发投入最少的活跃轨迹；没有其他活跃轨迹时开发冠军，不另设固定比例的冠军通道。

“已接受路径”在这里指被接纳为后续开发起点的程序序列，区别于全部生成记录。

### 2.2 下一起点门控：程序按行为归路

设轨迹 i 发起一次尝试并生成子代 c。评价后，将 c 的行为与各轨迹已接受路径中的程序比较，确定最近的轨迹 j。

| 情况 | 对下一父代的影响 | 尝试成本与成果记录 |
| --- | --- | --- |
| j = i，且 c 的成绩改善 | c 成为 i 的下一父代，进入其已接受路径 | 年龄记在 i；程序及评价进入全局档案 |
| j = i，但 c 未改善成绩 | 保留 i 的原父代 | 年龄仍记在 i；结果仍保存 |
| j ≠ i | c 不能接管 i，只允许更新 j 的父代 | 年龄记在 i，j 的年龄不增加；结果仍保存 |
| 编译、执行或评价失败 | 不更新父代 | 年龄记在 i；保存失败记录，不作为可选父代 |

所有有效高分程序均可更新全局最好结果，不因局部门控拒收而丢弃。**原回复没有单独明确异路接收时的质量门槛**；若延续同路更新的含义，应要求 c 优于 j 的当前父代，但这仍是需要明确的规则。

最近轨迹的比较对象包含自身及其他轨迹，不能表述为“只与其他轨迹比较”。“最近”怎样聚合整条路径中的相似度、平局如何处理，以及新轨迹如何加入，原案也尚未定义。

### 2.3 提示与行为表示

开发提示保留任务接口、当前父代及已接受的开发历史，去掉无关模板函数体。未被接纳或已归入其他轨迹的程序，不作为本轨迹的成功经验进入提示。门控由执行器完成，不要求 LLM 增加输出字段，也不要求访问 logits；锚定解码与检查点反思不属于这一版。

原对话提出：CVRP、OP 的启发式矩阵可在共同固定输入上比较行内排序，JSSP 可比较同一机器上操作的先后关系。前期讨论还包括路线边集合、着色中同色顶点对等输出表示。这些都是**待校准的行为代理**，并非已经验证的思想分类器；矩阵排序绕开了下游 ACO 的随机性，也可能忽略对实际搜索有影响的权重差异。

## 3. 已有证据支持到哪里

[V15 的实现](../traceaad/v15/search.py)在发育期从谱系档案中选择适应度最好的程序作为父代（`_search`），因此较高分的异思想子代可以成为后续开发起点。这说明“偏离被接纳”的通道在代码中存在。

[现有分析记录](记录/2026-W44.md)报告：13 个由 Diverge 起源的最终冠军谱系中，有 5 个后来换回初始做法；逐步追查发现，这些谱系在发散后的前 1–2 步就离开了新思想。OP rep1 中，第 41 条程序转向奖励/距离比，第 42 条程序又看到了它的描述并沿用这一方向。对应材料见 [roots.txt](../experiments_result/analysis/idea_coverage_20261028/roots.txt) 与[前期讨论文档](TraceAAD：脱离、脱轨与以思想为臂的递增收益老虎机.md)。

这些记录支持“谱系获得机会不等于原思想持续获得开发”这一判断，但**不能证明切换降低了最终成绩**：这 5 个案例本身来自最终冠军谱系，切换也可能是有效改进。5/13 不能作为所有生成尝试的偏离率；模板代码、冠军成绩门槛、历史子代与模型先验的贡献也尚未分离。本轮核对了机制文本和代码，未重新运行上述轨迹分析。

## 4. 巧妙之处与已有工作的关系

最有解释力的地方，是将“生成器经常偏离”进一步拆成“偏离发生”与“偏离改变后续开发状态”。如果损失主要来自后者，就不必先解决模型先验，而可以通过父代与历史的接纳规则阻断持续接管。这是一个明确、可干预、可检验的认识。

具体规则已有很近的参照，不能把行为重新归路本身当作全新的操作。

| 工作 | 原文中的机制 | 与本提案的关系 |
| --- | --- | --- |
| [FunSearch + BehaveSim](https://arxiv.org/html/2603.02787v1#A5.SS1) | 评价子代后，按其与各岛成员的平均行为相似度归入最相似的岛，而非原始来源岛 | 与行为归路高度接近；本提案需要检验的增量是同龄调度、已接受历史与成本记账的具体耦合 |
| [ShinkaEvolve](https://arxiv.org/html/2509.19349#S3.SS2) | 在执行评价前进行代码新颖性筛选，使用嵌入相似度，并可借助 LLM 进一步判断 | 本提案在评价后保留结果，改变局部开发的下一起点；两者干预的环节不同 |

因此，吸引力不能只来自“同龄竞赛＋行为归路”的组合。更强的研究主张是：**在有限预算下，防止重复方向接管尚未充分开发的轨迹，能让开发机会转化为更多有效的算法改进。** 目前这是待检验的主张，而非已有结论。

## 5. 三个影响判断的关键问题

### 5.1 外来改进不增加年龄，同龄成绩还代表什么

按原案，A 只发起过 5 次尝试，却可以接收 B 在开发 20 次之后生成的高分程序，随后仍以年龄 5 参与比较。A 的成绩此时包含其他轨迹的开发成果，不再只反映 A 自身 5 次投入的收益。

**如果年龄只表示“给这条轨迹分配过多少次机会”，这套记账是成立的；如果将同龄比较解释为“不同思想在相同总开发投入下的潜力比较”，这一解释就不再成立。** 接收轨迹会在自身未被选择时改善，其收益依赖其他轨迹的活动，也不能直接套用仅随自身拉动次数演化的递增收益老虎机模型。相关理论的适用条件见 [Mussi et al., Best Arm Identification for Stochastic Rising Bandits](https://proceedings.mlr.press/v235/mussi24b.html)。

同龄调度仍可作为启发式，但需要明确收益与成本的解释，并按事件时间保存检查点成绩，不能将后来收到的改善追溯填入早期历史。最小验证可以先将异路子代只留在全局档案，不立即更新其他轨迹，以单独检验“阻止原轨迹被接管”的作用；这是本文提出的诊断变体，不是原案已确定的规则。

### 5.2 行为最近，不等于思想相同

相似输出可以由不同决策规则产生，同一规则也可能因参数和输入而表现不同。BehaveSim 本身使用求解过程信息，而非仅凭最终输出判断算法行为；因此不能将更便宜的输出签名直接视为同等可靠的替代。[BehaveSim 原文](https://arxiv.org/html/2603.02787v1)

这一点会直接影响门控：初始轨迹近似相同时归属可能任意；所有候选强制归入最近的已有轨迹，也可能把真正的新方向并入旧方向。若对整条历史取最近成员，历史更长的轨迹还可能仅因比较样本更多而更易接收子代。

因此，原对话中的两项表述需要收窄：“不需要定义思想”只能表示不要求 LLM 显式标注思想，行为代理仍隐含了区分标准；“门控日志直接给出偏离率”也不成立，日志首先给出的是**行为路由率**，只有经过校准才能用于估计思想切换。全部结果被保存，也不等于所有有益的后续开发机会都得到保留。

### 5.3 “指数变线性”必须比较同一个统计量

原对话将“r 步后仍停留在 A 的概率”与“r 次尝试中产生 A 内子代的期望次数”直接比较，两者不是同一个统计量，不能据此宣称效果或复杂度从指数变为线性。

可以建立一个更明确的简化模型：固定给这条轨迹 r 次尝试；每次从 A 出发，以概率 ε 生成会被成绩选择接纳的 B 子代，否则生成 A 内子代；无门控时 B 一旦接管便不再返回 A；门控能够完美阻止接管。这里 0 < ε < 1，且各次条件概率不变。

令 N_A 表示这 r 次尝试中产生 A 内部子代的次数，不要求这些子代都提高成绩。比较同一统计量可得：

\[
\mathbb{E}[N_A^{\mathrm{无门控}}]
= \sum_{t=1}^{r}(1-\varepsilon)^t
= \frac{(1-\varepsilon)\left[1-(1-\varepsilon)^r\right]}{\varepsilon},
\qquad
\mathbb{E}[N_A^{\mathrm{完美门控}}]
= r(1-\varepsilon).
\]

这个模型说明：**在不可逆接管、固定偏离概率和完美识别的假设下，门控可以避免 A 内部生成次数的期望随预算增长而饱和。** 它不证明现实中偏离不可逆、行为识别准确或最终成绩提高；也不包含同龄调度可能提前暂停 A 的影响。因而它适合作为机制解释，尚不是完整算法的性能保证。

## 6. 最值得做的验证

先校准行为表示：检查已知思想切换能否被识别，同时检查同一思想的正常精炼是否被误判。若这一步不能区分二者，增加在线门控只会把测量误差变成搜索决策。

随后做一个只改变**父代与成功历史接纳规则**的配对对照：固定模型、同龄调度、任务与随机种子、提示格式及总生成预算，两组都去掉模板函数体并保存全部高分结果；实验组阻止异路子代接管原轨迹，对照组沿用按成绩接纳。先用上一节的最小诊断变体隔离接管效应，再决定是否加入跨轨迹接收。

核心结果是同等预算下最终算法的独立测试成绩，同时记录接管发生后原方向还获得多少次实际开发。行为诊断应在两组采用相同流程，并单列额外执行成本；仅得到更低的路由率或更多不同轨迹，不足以证明机制有用。

如果门控保留了不同方向，却没有改善最终发现能力，就应降低“接管是主要瓶颈”的判断；如果它提高了同预算成绩，才有依据进一步比较 BehaveSim 式归路与同龄调度的组合，检验完整方案的额外价值。

**最终评价：作为问题理解，这个 idea 清楚且有吸引力；作为具体算法，当前还需要把行为判别与收益记账闭合。值得投入的是一次能检验接管效应的简洁实验，而不是继续叠加排斥、反思或解码模块。**
