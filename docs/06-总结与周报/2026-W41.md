# TraceAAD 周报｜2026-W41（10月5日—10月11日）

这周我比较了几种继续开发方式，并重新整理了研究主线。现在明确的目标是利用搜索轨迹中的反馈经验改善后续决策。计算保留、真实diff和问题级开发都是可能的机制，不应提前成为整个研究的成功标准。

V10.18中，首版落后于原程序的探索在三步内超过原程序的比例为4.6%，V10.17为21.6%。但两版同时改变了上下文、开发方式、停止规则和预算分配，所以这个差异不能直接归因于原程序是否可见。代码抽查确认部分收益来自恢复成熟部件；恢复本身可以是有效决定。接下来需要比较它的收益和其他预算用途，而不是只要求保留新计算。[开发配置与案例](../03-现象与检验/2026-10-06-新设计开发诊断与改动检验.md)

V10.24完成18路、每路1000候选的搜索，TSP和CVRP偏弱，FSSP与JSSP改善，没有显示跨任务稳定优势。这使我撤回“统一开发过程自然带来更好资源判断”的预设。V10.25两套批次也已停止；原V10.17保留为工作底座，但尚未被确定为最优机制或最终论文版本。[完整结果与成本](../03-现象与检验/2026-10-10-V10.24完整搜索与开发成本.md)

我核对了七种基线的官方执行路径，发现辅助函数、消息角色、逐实例反馈和反思材料的适配错误，并完成修复。新实验共同条件已集中到实验规范；历史成绩仍绑定启动源码和原协议，不能用修复后的实现替旧批次背书。旧本地模型数据已封存，DeepSeek实验的执行状态按批次查询。[基线核对](../03-现象与检验/2026-10-11-七种基线官方实现忠实性审查.md)

10月11日，我按26项审查重构了默认入口、方法说明、结果解释和汇报材料。我复算父代历史对照，纠正了OP均值、CVRP方向及OBP测试设置汇总；也把19/45→2/45放回撤回指令对照。回查原始请求发现V10.15-6的目标句与Analysis使用不同参照，因此暂不把11.2%→2.6%的历史读数归因于单条目标句。旧诊断中的局部观察继续保留，普遍排序、通用禁令和单因素归因退回对应实验范围。同一结果被周报和汇报反复引用，不算新增证据。 随后的内容复查发现方法页和讲稿仍有归因遗漏，我补修了正文，并纠正详细过程中的五处章节链接。[重构与核验记录](../03-现象与检验/2026-10-11-研究主线与文档重构.md)

随后我按轨迹视角重新检查了研究入口。上一轮修正了数值和归因，但讨论仍容易落到父代形成链与单次改写。核对V10.17实现后，我区分了记录与使用：系统保存尝试、来源、失败修复和探索过程，生成只读取部分历史，选择主要使用质量与直接尝试计数，续写采用固定抽签和步数。记录比实际利用的内容丰富，这是待研究的空间，不是已证明的性能问题。

我将早期路线竞争、延迟收益、阶段开发与Continue/Branch重新接回当前问题，并增加跨版本用途、重点检验和相关工作的横向索引。它们共同帮助回答搜索如何利用自己走过的路；具体版本与复杂度不代表认识进步。[轨迹记录与使用](../01-搜索方法/搜索轨迹的记录与使用.md)

下一步先从完整搜索中确定最影响判断的现象：机会为什么持续集中在某些程序，停滞与失败怎样改变后续选择，哪些经历能影响其他路线。再根据问题选择局部对照、多步窗口或完整搜索。固定父代是可选检验，不再提前规定为下一步；本轮没有新增机制或实验。 随后我把调整扩展到各篇方法、结果、诊断、构想与相关工作，分别说明轨迹范围和决策用途，并修正正文里的局部视角偏差；历史规则、表格数值和原始材料保留。

收尾审阅发现，逐篇轨迹说明覆盖了部分历史身份，而且重复提示过多。我恢复版本与适用时点，将开头收敛为各篇独有的定位；中央索引保留完整说明。文档整理到此停止，下一项研究工作是从一条完整搜索的关键决策时刻重读已发生的事件和系统实际使用的信息。
