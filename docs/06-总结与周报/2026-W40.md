# TraceAAD 周报｜2026-W40（9月28日—10月4日）

这周我完成了 V10.14 在五个任务上的各四路搜索与独立选择。它偶尔能找到较强程序，但不同路次之间波动明显：TSP 训练最好值为 6.0749，四路均值为 6.1943；VRPTW 四路从 18.9005 到 20.2585。训练前沿与独立选择集使用不同实例，其分数差不能直接解释成选优损失。正式 held-out 尚未完成，因此我现在不会把单路最好值当作稳定的算法改进。

更重要的收获来自回看机制和已有反例。原先想用“轨迹重验”作为核心主张，但正式版本并没有启用在线重验；即使历史修改在新背景下作用改变，这个事实本身也还没有说明重验会改善设计。此前的 Pivot 两步实验也没有发现“先退步、再经一次 Refine 超越起点”的案例；大幅回升可能只是修复自己造成的退化。这让我意识到，收集更多轨迹、扩大行为差异或增加续投规则，都不能代替观察程序实际改变了什么，以及最终是否超过原起点。

我暂时冻结 V10.14 的机制扩展，完成了 V10.15 的独立代码实现。它把轨迹限定在生成提示里，用当前训练质量分配搜索机会；这与已有的护栏证据相符，但整套新机制的收益仍需验证。实现时核对并固定了两个复现口径：在线装箱和 VRPTW 的训练超时与评价器配置一致，取 30 秒，同现行 V10.14 入口；交付解析要求明确的 `stop` 结束原因和完整程序。离线测试覆盖预算、去重、一次修复、ESS、提示裁剪与选择集隔离，五个真实任务的小实例也通过了假模型输出的生成到选择闭环。这确认了工程链路能执行，不说明 V10.15 已提高算法质量。随后我启动了五任务各四路的正式搜索，目前 16 路已完成、CVRP 四路仍在运行，有效候选率在 73%—97% 之间。已完成的各路中，TSP、VRPTW 和在线装箱的独立选择集只是在同一生成器下换了种子，选中程序的分数仍普遍比搜索分差 1%—5%，说明在大量候选中取最大值带来了可见的乐观偏差，这也是需要独立选择与 held-out 的原因。另一个意外是 top-5 finalist 常常行为等价：OP 有两路、在线装箱有一路的五个 finalist 选择分完全相同，选择阶段实际上没有可比较的对象。finalist 目前只按代码文本去重，这个问题从 V10.14 起就存在，值得改为按行为去重。为了让版本之间的比较不再靠手工拼表，我重写了实验监控，新增跨批次对比：同一最终程序的训练分、选择分、同规模测试与其他规模泛化结果并排显示均值、标准差和相对参照的差值。V10.15 的 held-out 将在 CVRP 完成后统一运行，届时再与 V10.12、V11.1 和基线方法比较，判断整套新机制是否带来稳定收益。[正式结果](../03-机制探索与验证/2026-09-29-V10.14-正式实验结果与分析.md)和[研究认识](../04-研究认识与构想/研究主线与问题.md)保留前期依据。
