## 2. 做得好的路线，实际发生了什么

### CVRP 第 3 路：完整链条确实成立

该路线从 n4/e5 的 9.4221 出发，核心逐步从距离、局部密度扩展为“距离与邻近性 × 节约值 × 方向与容量约束”。下面是当前最优节点的形成路径中的关键步骤，部分中间节点并非当时全档案最优。

1. n40/e46，9.2482：Fuse 从 donor n37 引入 Clarke–Wright 节约值。它直接刻画连接两个客户相对分别经仓库连接的距离收益，不只是再堆一个任意特征。
2. n63/e72 → n85/e96 → n105/e117，9.0627 → 8.8787 → 8.8566：保留主要计算，逐步调整距离衰减、节约值幂次及其与方向项的相对作用。
3. 旁支 n112/e124 引入节约值的行几何均值归一化，经 n184 传给 n185/e199，达到 8.5703。核对 donor、host、child 实码可以确认这次计算迁移真实发生。由于节约值还要与方向项相加，归一化会影响二者的相对作用，不能简单当成完全抵消的行缩放。
4. n214/e230 → n279/e297 → n338/e359，8.5246 → 8.5198 → 8.4689：继续校准幂次、距离权重及容量软因子，保留强结构。

这正是“形成有效结构—借入有用组件—反复校准”。同时，最终 n338 虽标为 Fuse，实际大部分变化是参数校准；**算子标签不是机制证据，代码变化才是。**

第 1 路主要依赖角度、径向差与局部距离的乘积；第 2 路是距离幂次、固定扇区、需求相似性与仓库进出偏置。它们都在增加几何或需求因子，却没有形成第 3 路这套节约值主导、经校准的组合。对这两路，继续堆相似评分因子的收益空间可能有限。

### OP 前两路：有效评分结构可以被持续精炼

第 2 路 n108/e114 的 Pivot 形成“收益/距离 × 预算余量”的核心，达到 14.452；n127/e133 调余量系数与幂次，达到 14.622。n241/e252 借入 donor n106 的绕行成本，达到 14.836；n243/e254 局部改动到 14.842；最终 n411/e426 主要把绕行权重 0.2 改为 0.5、整体幂次 3 改为 4，达到 14.850。

这里计算直接对应 OP 的收益与路程预算，且幂次会改变 ACO 的抽样集中程度。这解释了为何数值精炼确实能有作用。第 1 路也形成了收益、距离、预算余量及可达性相结合的结构，随后多次改进到 14.816。

第 3 路当前结构主要是 `prize / distance**3 × slack**2 × radial_factor`，仍停在较固定的局部权衡。它不是完全没开发：最优 host 形成链有 21 个节点；但开发集中在这一类权衡内部，尚未得到前两路同样有效的组合。

### OBP 第 3 路：结构突破成立，“充分精炼”尚不成立

n303/e307 的 727.00 使用当前物品大小定义残余容量区间；n349/e354 的 Pivot 改为维护物品大小的指数移动平均，优先留下接近这一估计值的残余空间，同时奖励恰好装满，达到 724.75。它使用已到达物品的统计信息；评价器在连续装箱时复用该函数，状态确实参与后续决策。

前两路仍主要使用当前物品大小、残余空间区间或倍数关系打分。第 3 路的区别在于残余空间目标具有在线适应性，而不是单纯增加奖励系数。

但 n349 之后已过 447 次评价；它自身被选择 55 次，产生 48 个有效直接子节点，其中 47 个更差、1 个相同。一次结构突破足以解释其好成绩，不能把它写成后续精炼成功。

## 3. TSP 与 VRPTW：生成了计算，还需要保证它真的表达了思想

### TSP 的三个层次

当前最好代码分别是：

- 第 1 路：候选筛选后进行贪心剩余路径补全，再加一个近邻成本估计。
- 第 2 路：距离、近邻与 regret 等量组成的局部标量评分。
- 第 3 路：两步候选展开、贪心补全，以及剩余不超过 8 点时的穷举。

它们都没有在当前最好程序中实际优化剩余路径。历史强结果已经显示内部贪心补全、剩余路径 2-opt、小尾段 DP 可以在该接口下工作；V10.6 revised 在同一 TSP50 训练面板的 e500 成绩为 5.8164 / 5.9559 / 5.8770。返回一个节点的接口允许先在内部规划，再提交第一步。

但不能简单归结为“V10.10 从未想到 2-opt”：

| 实际候选 | 记录成绩 | 代码核查 |
|---|---:|---|
| rep1 n318/e372 | 6.1925 | Idea 写 2-opt improvement potential；实码只算边长方差，没有交换边或优化路径 |
| rep1 n337/e391 | 13.1630 | 真正执行路径翻转，但翻转允许改变第一个候选节点；比较优化后成本，最终却返回旧候选节点 |
| rep3 n289/e307 | 8.8306 | 真正执行翻转，但增量距离用路径位置查原始节点距离矩阵，且循环可能移动终点 |

因此存在两个缺口：思想没有落实为所声称的计算；计算已出现，却有评价器不会报错的语义错误。运行成功和分数较低不能区分这两种情况。

对 rep1 n337 的独立复评只改一行：记录 `candidates[idx] = tour[1]`，让返回动作对应实际被评价的优化路径，成绩为 **6.130392**，同面板、同 20 秒上限下完成，用时 16.11 秒。原档案程序成绩为 13.162958；本次重跑原程序及“固定首步”的另一种修正均触及 20 秒，故不能把旧、新成绩写成同一时刻成功完成的成对计时比较。完整代码和复评结果见 tsp_semantic_check.json，复现见 check_tsp_semantics.py。

修正并没有直接到 5 字头，却把一个表面极差的候选变为有竞争力的算法。**当前分数会把“结构本身不好”和“结构实现有错”混在一起，质量抽样随后自然很少再选这些坏分候选。增加任意新节点的保护期无法直接解决这一点。**

### VRPTW 第 2 路：有充分机会，缺少有效改法

n85/e88 达到 20.6256 后，至 e498 未再刷新。它已获得 99 次直接生成机会：Refine 27、Tune 27、Fuse 33、Pivot 12；83 个有效直接子节点全部更差。

当前最好程序是距离、等待、紧迫度、容量惩罚与接近最优时的 deadline tie-break。第 3 路已经加入一次可行后继检查，达到 20.0833，但距离历史 V9.19 的多步容量与时间窗模拟还有差别。历史强程序及形成过程见五任务强结果分析。

这些观察支持“当前生成方向及其实现质量限制了进一步改善”，不支持直接把瓶颈归为好父代分配次数不足。

## 4. 现有机制的具体缺点

**第一，思想、实码、实际返回行为之间缺少有效核对。** 一次运行异常修复抓不住上面的两种 TSP 错误；当前 Idea 还可能把边长方差称为 2-opt。应该减少这种静默错误，不必构建一个自动证明算法正确的系统。

**第二，精炼的分工偏松。** Tune 目前只有“识别主要参数并改善设置，保留核心方法”的一句话。1,803 个有效 Tune 中，239 个是严格意义上的仅数值常量变化，131 个优于父代，42 个刷新前沿。仅数值比例低本身不证明其余都违背 Tune，但结合实际重写样本，说明它尚未稳定形成独立于 Refine 的精细校准行为。CVRP 和 OP 的成功过程恰好说明保留强结构、改少数关键参数是有用的。

**第三，借鉴来源有随机覆盖，但迁移是否针对短板仍主要靠模型临场发挥。** 1,783 个有效 Fuse 中，146 个同时超过 host 与 donor（8.19%）；有实际迁移成功，也有最终只调参的情况。这个统计不能用来否定 Fuse；它说明“展示两个算法”与“借对一个计算”之间仍有差距。没有证据表明此时值得再引入 donor 相似度模型或额外筛选层。

**第四，上下文有可以删除的重复。** 当前每条形成边都独立附完整 source、完整 diff，若曾用 Fuse 又附完整历史 donor；host、donor 和这些历史代码可能重复展示。Refine/Fuse 的实际输入最高达到 25,220 tokens。长文本尚不能被证明造成分数下降，但重复展示增加生成成本和辨认关系的负担。OBP rep3 n564 的说明甚至把后生成的 donor 侧节点误称为当前 host 的祖先，并错误描述其成绩关系。应让来源关系更清楚，而不是再设一个紧的输入阈值。

**第五，格式恢复仍然浪费明显。** 共 3,744 次 `invalid_output`，其中 3,728 次报缺少 `Idea:`。生成记录中至少 1,297 次实际用了加粗或 Markdown 标题形式的 Idea。真正无 Idea 与标题装饰不兼容被混在同一个错误里。现有修复也确实有作用：3,054 次修复得到 1,989 个有效程序；不能因此说错误兜底无效。

这些统计包含原始生成与修复事件；解析失败不消耗评价槽，主要消耗模型调用、时间，并导致部分候选被放弃。不能把它们写成 3,744 次评价预算损失。

## 5. 最推荐的改进顺序

### 优先一：把思想到行为的最后一步写清楚

修改现有生成提示即可，不加额外规划调用。要求本次 Idea 说明真实采用的计算，以及它怎样改变最终选择；生成结束前核对关键计算确实执行、索引使用正确、比较的方案与返回的动作一致。TSP/VRPTW 的任务说明可简短说明：允许在内部构造、检查和改善剩余方案，再返回第一步；模拟必须与真实约束一致。

这不是要求所有任务都使用 rollout 或局部搜索，而是避免把“返回一个动作”误解成“只能设计局部评分”，也避免把一个未实现的算法名称当作突破。当前 TSP 的直接证据最支持优先处理这一层。

### 优先二：使 Refine、Tune、Fuse 真正围绕一个目标工作

- Tune：默认只校准一到两个影响实际决策的已有参数，保留其余计算与返回流程；采用提示约束，不增加机械 AST 拒绝器。
- Refine：围绕一个具体计算缺陷或近似误差改进；优先保持已有有效结构，避免将内部规划随手改回局部打分。
- Fuse：明确借入哪个实际计算、接到 host 的哪个位置、解决什么短板；继续允许 donor 无用时不强混合。

这些都是现有算子的一两句澄清，不增加算子、阶段或分配状态。初始化、Pivot 的差异也应落在实际信息利用与求解过程上，保持现有“允许重用有用组件、兼顾竞争力”的原则。

### 优先三：删除可避免的格式与上下文成本

本地容错接受 `**Idea:**`、`## Idea` 等无歧义形式；真正缺描述或代码有错时沿用一次修复。上下文中每个节点代码只出现一次，形成关系引用节点编号、变化与分数，保留完整来源，不反复附同一程序。此处只去重呈现，不限制档案重复评价，也不新增紧的上下文截断。

**当前最优先的机制方向是提高每次扩展的有效性。** CVRP/OP 的成功表明现有档案、借鉴与持续开发可以工作；VRPTW/OBP 的停滞表明仅给更多机会不能自动兑现；TSP 的复评指出一类可以直接纠正的失败原因。现阶段保留父代与 donor 的基本抽样、四算子框架，比同时再改分配公式更容易解决主要问题，也更容易判断改进来自哪里。
