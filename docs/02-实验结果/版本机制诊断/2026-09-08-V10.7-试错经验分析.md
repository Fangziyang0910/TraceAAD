# V10.7：试错经验在什么地方没有转化为设计能力

2026-09-09。研究出发点：核心研究认识。分析对象是原 V10.7 的 `20260907_bounded_formal / sampled_trajectory_v1`，不是当前工作区默认的 V10.7R，也不是 V10.8。

## 1. 核心判断

**V10.7 扩大了已有程序参与下一次生成的机会，但没有建立相应机制，帮助模型区分“程序得到了什么成绩”和“这次设计实验实际证明了什么”。** 它实际实现了一个跨质量程序参考生成器；真实修改关系、失败条件和既往开发结果，在进入下一次决策时被大量丢失。因而，用这一版直接检验“试错经历能否改善设计能力”，研究命题与机制之间存在错位。

这不是说模型从程序对照中不可能学到东西。OP、CVRP 和 OBP rep1 都留下了有效改进。问题在于：**“材料有机会被看见”被过早当成了“试错经验会被理解并有效利用”的机制替代。** 当程序、Idea 和 fitness 一起被反复采样时，模型既可能继承有效方法，也可能继承无效计算和未经证实的解释；V10.7 没有可靠地区分这两种积累。

这里的“认知偏差”指方案论证中的推理跳跃，包括此前协作建议中的判断，不是对研究者个人心理的诊断。原始讨论已经写出不少正确边界，例如低分不代表无价值、代码变化不等于行为变化；偏差主要发生在从这些认识推导具体机制时：**承认某种信息“可能有用”，不等于所选代理指标已经能把它组织成有用证据。**

现阶段最有依据的结论是：

1. **生成更顺畅、成本明显降低，但搜索质量的收益依任务而异。** 不能把取消第二调用或全档案取材整体判成失败。
2. **TSP 的重要问题是持续开发了主打分失效的路线；OBP 的重要问题是大量不同写法没有改变主要选择规则。** 两者都超出了格式、有效率和节点数量能够诊断的范围。
3. **“没有给新方向足够机会”只适用于部分观察，不能统摄全部退化。** 有的路线已持续开发，有的弱候选只有参考曝光，有的运行始终没有发现有效突破。
4. **V10.7 暴露的是具体经验表示与使用方式的问题，不是对轨迹价值的否定，也不是对 V10.8 有效性的证明。**

## 3. 从 idea 到机制：哪些推理环节发生了偏移

### 3.1 原始动机有价值，但研究对象在落地时改变了

原始讨论先提出单调用替代独立摘要，再提出从全档案抽取少量程序。其合理动机是：一个没有登顶甚至暂时退步的实现，仍可能提供有用组件；材料不应被严格限制在当前祖先链。

但正式批次同时改变了材料来源、材料内容、展示顺序、donor 规则、算子措辞及注释视图。冻结设计明确规定：三份程序按质量排序，只显示 Idea、完整 Code 和单点 fitness，不显示来源、实际父子关系或创建算子。

因此，正式版输入可以近似写成：

$$
C_t = \operatorname{Sort}_{f}\{(x_i, f_i, \text{Idea}_i)\}_{i \in \text{sample}(H_t)}
$$

它保留了搜索的**产物**，却没有显式保留“哪次操作把哪个源程序变成了这个结果”。失败评价和解析失败虽然有日志，但不进入有限 fitness 的程序采样池；选父主要接收质量与选择次数，未把失败的内容及成因作为反馈输入。失败仍会通过消耗预算、增加父代次数影响搜索，不能说它完全没有影响；但这些影响不同于理解和利用失败证据。

若两段历史留下相同的程序/评分/Idea 材料以及相同选择计数，却有不同的已失败修改和转移关系，正式采样模式没有专门的输入去区分这些经验。**保存完整档案，并没有自动形成更充分的设计状态。**

这也不意味着必须恢复祖先链。祖先链只记录形成过程，也可能漏掉出生后的失败尝试。真正要识别的是哪些历史事实对下一次实验有增量，而不是先把某种存储结构等同于经验。

### 3.2 六个具体认知偏差

| 方案中的推理跳跃 | 实现中的表现 | 实验给出的纠正 |
| --- | --- | --- |
| 低分可能有用 → 跨质量抽样就能提供有用经验 | 同一分层规则给三种算子选参考 | 分数不是证据角色；弱方案能作对照，不表示适合作为融合主输入 |
| 多份完整程序 → 信息更充分 | 去掉转移关系，展示三份结果快照 | 增加代码量与补充设计状态是两件事；OBP 大量材料只重复同一排序 |
| Code 为准 → 模型自然会识别 Idea 的错误 | 原始说明和注释随代码反复复用 | TSP 中无效主打分的解释连续流传；OBP 中单调变形被描述为新权衡 |
| 放宽算子约束 → 自动获得有效探索 | Pivot 不绑定明确比较对象，Fuse 强调连贯组合 | 调用 Pivot 或 Fuse 不保证产生新的有效选择规则或互补收益 |
| 给参考曝光 → 已给该方向发展机会 | 低分程序可进入别人的上下文 | 被看见、被采用、被作为底座开发、收益兑现必须分开 |
| 主循环忠实、有效率高 → 机制运行良好 | 编号/字段/预算检查通过，大量候选可评价 | 文本内部指代和真实执行行为仍可能失真；工程通过不能替代机制证据 |

原讨论其实已承认部分风险，因此不能把这些假设描述为当时完全没有意识到的问题。更准确的批评是：**关键不确定性被留给模型隐式处理，而实验没有把这些环节单独验证。** 特别是“保持父代与算子比例，就能判断收益来自哪里”的早期协作建议说得过满；生成端同时变化的因素仍然很多。

## 4. TSP：试错带来了真实小收益，却没有纠正对收益来源的理解

### 4.1 有连续开发，开发的却主要是精确尾部

原 V10.7 rep1 的真实父链为：

| 节点 / 评价 | 实际继续发展的部分 | fitness |
| --- | --- | ---: |
| n169 / e170，Pivot | 最近邻式主体＋最后 3 点精确求解 | −6.775270 |
| n196 / e198，Refine | 尾部扩大到 4 点 | −6.754435 |
| n201 / e203，Refine | 尾部扩大到 5 点 | −6.731041 |
| n203 / e205，Fuse | 尾部扩大到 6 点 | −6.710856 |
| n205 / e207，Refine | 尾部扩大到 8 点 | −6.685091 |
| n215 / e217，Fuse | 保留 8 点尾部 | −6.685091 |
| n220 / e222，Refine | 换为缓存 DP，扩大到 10 点 | −6.614621 |

原始代码和后续曝光见本次快照；阈值与公式解释也可对照此前代码路线核查。主打分反复对已填 `inf` 的距离矩阵求均值并归一化，最终产生 NaN。评价器按距当前点的距离排列候选，因此取首候选实际执行最近邻；小规模精确尾部仍然有效。

这条链条中的改进是真实的，不能称为“全部无效搜索”。但 n196 的 Idea 同时声称自适应 lookahead、孤立惩罚和尾部扩展更有效；n220 又声称改进了第二小出边和中心性。分数上涨没有证明这些主打分设计有效，它只能证明整份程序在本次面板上更好。

**当前机制把“整份程序的成绩”与“整段设计解释”一起保存并传播，形成了让错误解释继续获得表面支持的条件。** 这是机制风险与代码观察之间的解释，不等于已经证明模型内部相信了某个错误，也不能定量声称这造成了多少终局损失。

### 4.2 终局仍保留同类退化，不能只归咎于早期状态

本次读取三路终局最佳，发现后期成绩提高后，问题仍存在：

| 重复 | 终局节点 / 评价 | fitness | 静态代码与合成输入核查 |
| --- | --- | ---: | --- |
| rep1 | n567 / e644 | −6.458196 | DP≤15；孤立度由含 inf 的行均值得到，归一化 NaN，主分支取最近候选 |
| rep2 | n904 / e916 | −6.478631 | DP≤14；cohesion 含 inf，最终检测到非有限分数后显式回退最近邻 |
| rep3 | n825 / e872 | −6.533894 | DP≤12；lookahead 矩阵含 inf，均值/方差及归一化失效，主分支取最近候选 |

在 8 个合成坐标 seed、每个 16/20/35/48 个候选的 32 个状态上，每份终局程序都与最近邻选择一致。输入避开所有精确尾部分支；这是对所审查主分支的核验，不是整份程序与纯最近邻等价的声明，也没有重新评价三份终局程序的总成绩。

rep2 从 e68 的 −6.823969 平台，到 e775 才再次提高，并在最后阶段扩展精确尾部。rep1 最终共有 196 次 timeout。这提示该路线继续依赖更大尾部计算时面临实际代价限制；不能把所有 timeout 都直接归为 DP 扩张，逐个失败仍需查看代码。此前已有明确扩大穷举/DP 后超时的代表案例。

### 4.3 修复错误不等于挽救一个本来优秀的 idea

此前对旧最佳 n279/n67/n391 的 9 次隔离评价显示：只修 `inf` 均值后，三份程序全部更差；显式最近邻主体＋原尾部则逐一复现原成绩。该反事实不适用于本次新的终局节点，但已经否定了那三份旧候选“只是代码错误掩盖了强设计”的解释。

研究上的偏差是先认可一个听起来合理的改进，再将实验不佳归给实现。这里实现错误确实存在，但错误被修复后，原有权重和公式反而更弱。**需要评价的基本单位是实际执行的设计，不能先让自然语言 idea 获得豁免。**

### 4.4 V10.6 的成功对照说明缺口在哪，也说明不能过度归因

V10.6 rep1 的 n26/e36 同样有 NaN 主打分；n29/e42 的 Pivot 改为真正执行的“逐候选首步—完整近邻补全—2-opt—比较路径代价”，达到 −5.933370，随后 n63/e95、n64/e96 提升到 −5.839114。前 250 次评价期间三者分别获得 23/14/25 次父代尝试，其中真正进入评价的是 20/11/18 次。

两版差异在这组案例中表现为：一个过程发展了有效的新主决策，一个过程持续改善退化主体的尾部。它不是“旧版没有错误、新版有错误”，也不是“新版完全没有开发机会”。但这仍不是祖先上下文或第二摘要调用造成差异的独立因果证明：初始材料、生成分布与筛选均不同。

## 5. OBP：同分平台怎样变成了“经验很多、行为变化很少”

### 5.1 两路停滞不是节点不够分散，也不是看不到最好程序

rep2/3 全部 1,000 次评价都没有超过最初的 −744.5。两路分别有 913/946 份不同完整代码，977/995 个节点与终局最佳同分；各有 547/555 个不同节点被选为父代，最大单节点选择占比仅约 1.11%/0.60%。三程序上下文全同分的比例分别为 916/992＝92.34%、978/992＝98.59%；质量分位边界全程重合。

同分不证明行为等价，但代表代码直接揭示了问题。rep2 n61 声称加入保持大容量灵活性的惩罚，主要公式却是：

$$
-(b-s)-10^{-6}b = s-(1+10^{-6})b.
$$

在同一当前物品大小 $s$ 下，它仍偏好较小的可行剩余容量 $b$，即 Best-Fit；微小索引项影响平局处理，不能据其否定所有边界差异，但没有建立所声称的容量权衡。

因此，当前系统可以拥有越来越多代码、Idea、节点和参考组合，而没有增加同等规模的有效设计证据。**代码身份去重解决的是文本副本，分数分层解决的是结果覆盖；两者都不能保证算法选择规则的多样性。** 这不自动要求引入昂贵行为聚类，首先要求研究解释不再把这两项统计当作探索已发生的证据。

### 5.2 rep1 的突破揭示了怎样的改变才有用

e196 的 Pivot 生成 n195，首次从 −744.5 改善为 −744.0。它的真实输入是 n119/n130/n177，三者均为 −744.5：

- n119 是负 slack 的 Best-Fit。
- n130 加微小正容量项，主要排序仍为 Best-Fit；Idea 还称其在箱数最小化上具有理论优势，这并未由该次实验建立。
- n177 声称防止小残余碎片，但实现为 $-\text{slack}-0.001\text{slack}^2$，在可行域仍随 slack 严格递减。它没有实现文字所述的“小间隙可能比大间隙更差”的权衡。

n195 则真正加入 `0 < slack < item` 的分段惩罚，允许跳过留下小间隙的更紧箱子。e198 的 Refine n197 沿此思路，把主评分改为 perfect-fit bonus 与区间内二次惩罚之差，达到 −728.5。它不仅换了系数，也改变了主要评分结构。

合成选择例子：当前物品为 10，可行箱剩余容量为 `[11, 20]`。上述三个输入程序和 n61 都选 11；n195/n197 都选 20。这个反例证明这里出现了实际选择变化。它不表示选择 20 一般更优，收益仍以原正式评价为准。

到前 250 次评价，n195 已获得 3 次父代评价、11 次额外参考曝光；n197 获得 9 次父代评价、8 次参考曝光。终局 rep1 又在 e743 达到 −728.25。这里确实存在“发现有效改变—继续开发—兑现较大收益”的过程，应当作为 V10.7 的正例保存。

但不能据此说三份样例已提供充分的试错知识：n195 的输入没有任何比 −744.5 更好的实例，输入代码也没有实现同样的非单调偏好。突破可能来自模型先验、Idea 的启发、比较材料或随机生成，现有日志不能区分。**同一段不准确描述既可能维持错误认识，也可能启发有效新实现；这正是不能凭错误率直接宣布删除全部 Idea 的原因。**

### 5.3 对设计器的含义

V10.7 在一路中完成了突破，另外两路没有。不能由此证明其无法创新；更准确的问题是它没有稳定地让“反复看见 Best-Fit 变体”转化为下一次更有价值的实验。抽样器不识别已经充分尝试的设计内容，Pivot 的名字也不能保证突破这一循环。

三路 OBP 共 1,096 次 Fuse 尝试，1,094 次有效；48 次超过父代，16 次超过当前三份上下文最好值，**没有一次刷新当时全局最好值**。这些数据说明局部超父和全局搜索贡献不同；它们不证明 Fuse 没有间接价值，因为未登顶候选还可能成为后续参考或底座。

## 6. 不能把所有问题归给同一种预算瓶颈

原设想正确指出：低分程序即便没被继续改写，也可能作为参考参与别的生成。然而，这是另一种作用通道，不是已经兑现的价值。

本次将此前追踪的 TSP rep3 n136/e140、n148/e152 延伸到终局：两者仍未获得任何直接父代尝试，各有 4 次额外参考曝光。它们分别包含实际局部 lookahead 或退出代价，但当时分数较弱。这个事实支持“参考曝光没有替代直接开发”；它不支持“已知优秀的新方向被调度错杀”。没有相同后续预算的干预，潜力仍未知。

与之相对，TSP rep1 的精确尾部路线已连续开发，OBP rep1 的新规则也及时获得扩展。因而至少应区分：

| 过程类型 | 本次代表 | 能支持的诊断 |
| --- | --- | --- |
| 很多表面改写，未形成有效突破 | OBP rep2/3 | 先查生成内容与信息重复，不能先归因预算不给机会 |
| 形成改变且获得开发，但未解决主要瓶颈 | TSP rep1 尾部链 | 开发对象与作用机制需要核查 |
| 弱候选仅有参考曝光，没有直接开发 | TSP rep3 n136/n148 | 存在机会缺口，但缺乏潜力与续投收益证据 |
| 有效改变及时获得开发并兑现 | OBP rep1 n195→n197 | 现有调度可以支持成功链，失败不宜统一归咎调度 |

此外，Pivot 在原模式不绑定必须继承的底座，却仍保存一个结构父节点。仅沿 `parent_id` 解释它的思想来源会遗漏另外两份输入；`context_node_ids` 表示可见材料，也不能证明模型实际采用了每份材料。**结构谱系、输入依赖、实际代码继承和收益信用，是四种不同关系。**

## 7. Fuse 与正面任务：有用程序参考不等于已经学会利用试错

### 7.1 质量覆盖与融合材料的角色冲突

原方案先跨质量层抽两份参考，再选其中较强者作 donor。父代已经经过质量偏置选择，donor 却不一定同样强。此前同预算前 250 次评价中，VRPTW donor 弱于父代的比例从 V10.6 的 44.8% 增至 88.5%，有效 Fuse 超父率由 27.3% 降至 12.8%。这些是原规则的实际后果，不是 donor 指针选错。

低分程序整体较弱不表示组件无用，但仅给出完整代码和总分，模型还需要自行判断哪个组件能迁移、如何兼容以及为什么值得用。**把较弱参考选为主输入，并没有提供关于其局部价值的新证据。** 更高分 donor 也不自动提供互补性：此前两个 seed 的局部更换 donor 对照没有稳定改善。

终局 TSP 三重复共 958 个有效 Fuse，其中 83 个超父、39 个超上下文最佳、7 个刷新全局最好。OP 对应为 1,038/76/35/14。相同算子在不同档案和任务上承担的作用不同，不能用一个全局超父率评价其固有能力。

### 7.2 CVRP、OP 的正面结果限制了负面叙事

CVRP 三路后半程都继续改善，均值由 @250 的 9.6950 降到终局 9.1675。rep3 最佳 n652/e731 来自较早的 n131/e140，fitness 从 −9.118983 到 −9.068464；n131 在完整运行中获得 32 次直接评价。这表明旧节点仍可能在后期成为有价值的开发底座，不能把近期性或连续谱系当作材料价值的必要条件。

其最终程序用距离、角度、径向关系与需求组合生成静态 ACO 边先验。“remaining capacity”只由单个源点需求近似，接口并没有提供蚂蚁当前累计载重。这不是说程序不可用，而是提醒：**即使成绩较好，仍不能把 Idea 中的状态感知表述直接作为已实现能力。** 是否有用和解释是否准确需要分别判断。

OP rep3 的 n830/e851→n844/e865 将 14.538 提高到 14.554，继续修改 prize/distance³ 基础上的预算可行性门控和边权调制。其所谓动态剩余预算也是由静态距离和 maxlen 计算的近似，不接收当前路线已用预算。这条过程支持已有实现经过连续改写产生有效结果；还不支持模型从转移反馈中学到了可迁移策略。

任务结构也提供了一种值得验证的解释：OBP 通过最大优先级选箱，许多严格单调变换不改变选择；CVRP 和 OP 的 ACO 则把启发值与信息素组合成采样权重。非线性变换即便不改排序，也可能改变相对权重和实际路径分布。因此，类似的公式改写在不同任务中可能具有不同的行为价值。这个接口差异有代码依据，但它是否解释本次跨任务收益差异，尚未通过受控实验识别。

所以，负面任务不能让我们认定全档案程序参考没有价值；正面任务也不能填补“真实过程信息是否带来独立增量”的证据缺口。当前方案可能在某些任务上有效，即便它不是一个充分的经验利用机制。

## 8. 实验过程本身暴露的认识问题

### 8.1 原意被拆成两个阶段，正式比较却没有保留对应识别条件

最初是取消独立摘要的单调用基线，后来又加入全档案分层模式。正式批次只运行分层方案，没有同时完成匹配的祖先与均匀采样对照。于是 V10.6→V10.7 的差异包含多种机制，难以回答：省掉摘要是否有损失、展示多份完整代码是否有收益、分层是否胜过均匀、真实转移关系是否重要。

这不是结果分析多算几个统计量能弥补的。档案是此前生成和调度共同形成的结果；同预算时不同版本已经面对不同材料。把终局 donor 分位、Idea 错误率或算子收益并列，不能直接分配各因素的因果贡献。

### 8.2 检查覆盖了记录一致性，但没有覆盖跨上下文语义一致性

历史 Idea 中的 `Algorithm N` 随节点重新采样、排序、编号，可能指向不同代码。此前冻结快照确认 12,566/26,004 个展示块有明确编号对应不同代码，约 48.3%；这是旧快照口径，本次没有扩展为终局比例。

TSP rep2 n8 创建时的上下文为 `[0,6,3]`，后续展示于 `[4,5,8]`，相同文字里的编号已经改变含义。字段和索引各自正确，文本内部关系却失真。原始代码注释还会继续携带类似引用，只删 Idea 不会完全清除。

这个问题既是可修正的表达缺陷，也揭示经验复用接口的要求：一条记录离开原来的提示环境后，必须仍能被准确解释。但错指占比不是模型误解率，更不是性能损失比例；OP 同样存在大量错指却没有整体落后。不能把这个修复写成预计恢复全部质量的承诺。

### 8.3 有效候选比较受到生成筛选影响

V10.6 共 3,829 次无效输出，V10.7 仅 52 次。旧版被格式拒绝的样本不占评价预算，却消耗调用，并增加相应父代的生成尝试计数。两版有效候选的分布不是同一个生成分布简单取样后的结果。

因此，同评价预算上的质量差异是真实观测，但“新版有效 Fuse 超父率更低，所以 Fuse 本身变差”的机制解释仍需考虑父代状态、材料和格式筛选。生成通过率提高可能有工程价值，也可能改变此前偶然形成的筛选效应；不能未经评价就给被拒样本判定好坏。

### 8.4 局部干预应该约束解释，而不是承担过大的结论

此前 24 次固定 Prompt 试验中，删除 Idea 在一个 TSP Pivot 锚点有利，其他锚点混合；恢复祖先组合的四个 Pivot 候选更差；更强 donor 未稳定改善。它们纠正了“删掉/恢复某项就会好”的直觉。

但每臂仅两个 seed，锚点回顾性挑选，又处在 V10.7 已经形成的档案中；祖先对照还同时改变提示指令和注释视图。它们不能给完整搜索判死，也不能鉴别所有具体因素。**过程审查负责定位值得干预的机制，受控实验负责判断干预是否真的提高设计能力。**

## 9. 对 TraceAAD 贡献主线的修正与下一步

### 9.1 应保留什么，撤回什么

应保留单调用的成本优势、完整事实归档、逐步重决策、允许非最优程序参与设计，以及分开记录父代和参考关系。当前证据不要求恢复第二摘要、强制新颖性、失败保活或行为距离奖励。

应撤回或收窄三类表述：

- “质量排序的程序序列已经表达了设计经验”：它首先表达结果对照，真实过程增量仍需另证。
- “低分材料曝光已经解决方向保留”：它提供传播机会，没有证明实际迁移，更没有保证后续开发。
- “程序提分证明其 Idea 中提出的机制有效”：只能支持整份被执行程序的评价结果，具体作用要由代码、行为和干预核查。

### 9.2 最值得先做的三项辨识

本次只提出实验优先级，不启动新实验，也不把下表当作已经获得的结论。

| 优先问题 | 最小有解释力的比较 | 什么结果会改变判断 |
| --- | --- | --- |
| 真正增加的是程序样例，还是设计过程信息？ | 在同一底座、算子、模型和相同参考程序下，对比普通代码/评分展示与明确真实转移关系的展示；控制顺序与表达变化，报告实际 tokens。多步历史另与单边比较，不让更多代码成为唯一差异 | 过程关系在匹配材料后仍有稳定增量，才支持轨迹特有价值；否则转向程序检索/比较解释 |
| 改善生成是否兑现为搜索收益？ | 固定调度、解析和成本记录，从头进行完整同评价预算重复，并冻结最佳算法做未见实例测试；同时展示 token 成本和预算曲线 | 单步改善能延续到终局且跨实例成立，才支持设计器效率贡献 |
| 未获开发的候选是否值得续投？ | 仅针对前瞻性固定的弱候选与匹配底座，随机分配少量相同后续评价机会；不按事后最好后代挑锚点 | 续投有可重复的净收益后，再考虑在线分配改动；曝光次数和代码新颖不能替代这一证据 |

这里不建议伪造历史或把无关程序排列成虚假因果链。要区分表示因素，就对真实材料进行显隐或等价呈现；真实转移记录本身也不保证某个代码组件的因果贡献已被识别。

过程观察应围绕少量有判断价值的问题：模型是否依据可见证据改变了具体设计；改变是否影响实际选择；是否获得后续开发或被迁移；收益是否超过已有最好实现。观察者对代表程序的离线解释，不应未经验证就变成在线 critic 或新增控制器。

### 9.3 对 V10.7R / V10.8 的意义

V10.7R 修复角色和指代、V10.8 引入可核验形成转移，都更接近当前提出的状态信息问题。但本次没有评价它们的效果，不能把概念对齐当作性能结论。尤其 V10.8 的祖先形成轨迹仍不等于围绕当前程序的全部试错经历，不能直接继承“模型已知失败尝试”的论证。

**V10.7 留下的核心研究认识是：经验复用的难点不仅是让更多历史材料进入上下文，还在于让“做过什么、实际发生什么、哪些判断仍未被证明”保持可区分，并让这种区分改善后续设计。** 本版已经显示程序参考可以产生收益，也显示错误解释和行为重复可以随参考一起传播。TraceAAD 接下来应把两者的分界变成可检验的方法问题。

## 10. 复核方式与资料边界

在仓库根目录运行（只读正式实验）：

```bash
python3 docs/01-主线版本/V10.7/试错经验与机制分析/replay.py --verify docs/01-主线版本/V10.7/试错经验与机制分析/终局与过程快照.json
.venv/bin/python docs/01-主线版本/V10.7/试错经验与机制分析/probe.py
python3 docs/01-主线版本/V10.6/机制运行核查/verify_evidence.py
```

第一条需本地完整原始日志与 Git 冻结提交；远端只凭紧凑快照不能独立重算全部运行。快照保留逐路数据、原始文件指纹和代表代码，供离线审阅。第二条执行快照中列明且已审读的少量程序，不加载训练数据或正式 evaluator；输出可与合成核查 JSON 比较。第三条核验此前凝练证据的 72 个文件、30 路前沿摘要、12 个 Prompt、33 份候选哈希。

本次没有重新执行旧反事实评价，没有把旧最佳程序当作新终局程序，也没有把源码一致性核验当作历史服务权重、量化和负载一致的证明。全文的新统计来自本次原始日志重放；旧报告中的编号比例、donor 分位与局部对照均保留旧截点。
