# V10.6：第二次调用是否让 Idea 更贴合 Code？

**判断：有可验证的局部收益，但尚未形成可靠的语义校准。** 二次 Idea 可以纠正原版的部分公式、参数与实现方式，也能识别某些没有功能变化的子代；同时，它会保留原版的错误解释，遗漏决定实际行为的代码问题，并新增错误的父代比较。因此，当前证据支持“有用的实现描述生成”，不支持“经过第二次调用，Idea 就已经与 Code 对齐”。本次也不检验这一流程是否提高最终搜索成绩。

## 样本与判断口径

批次 `20260906_215231_revised`，冻结时间 **2026-09-07 19:15:38 +08:00**。逐运行读取 checkpoint，合计 10,872 次已完成评估、10,116 个有效节点。运行仍在进行，以下数量是冻结快照。

按 task、repeat 排序，固定随机种子 `20260907`，每条运行在评估序号 1–200、201–400 两段内，各均匀抽取一个有效非根子代。共 **5 个任务 × 3 次重复 × 2 个阶段 = 30 组**；没有按分数、算子、摘要是否成功或文本内容筛选。实际抽到 Refine 16、Fuse 11、Pivot 3。研究对象是会进入档案的有效子代；无效程序的语义质量没有纳入这 30 组。

每组检查前置 Idea、最终完整代码、二次 Idea、完整父代码与两次原始调用。30 组均确认：前置 Idea 来自第一调用；归档代码等于第一调用代码；第二调用看到了这份代码；归档 Idea 等于第二调用输出。不存在配错代码或把原版 Idea 当作二次输出的问题。

人工审阅按具体主张核对：计算公式与参数、argmin/argmax 的偏好方向、实际生效分支、归一化和截断的作用、父子实现差异。**补充正确细节、纠正错误、保留错误、新增错误分别判断**。同一组可能同时有收益与错误，故没有将其压成一个主观准确率。

原版与二次版的词数中位数分别是 **175.5 / 486.5 个英文词**，范围分别为 76–924 / 340–734。两者职责和长度不同：前置 Idea 是设计计划，二次 Idea 是代码描述。内容更多本身不能证明更正确。本次为单名审阅者的非盲核查，也未对同源谱系样本假设统计独立。

## 确认有用的部分

30 组中，**12 组至少有一处可定位的具体纠错**；这不是“12 组完全正确”或“12 组总体胜出”。另有一组正确识别父子功能等价，原版未明确声称产生变化，因此作为新增事实单列。

## 最影响历史可信度的五类失败

### 1. 公式展开正确，实际选择行为仍解释错误

**OBP / 3 / 68** 的两版都把新增项解释成避免碎片的“稳定性偏好”。二次版更明确声称决策由严格 Best Fit 变成平衡紧密度与稳定性。但设 `g=bins-item>=0`，实际代码是：

```python
s = 0.9 / (1 + g) + 0.1 * g / (1 + g)
  = 0.1 + 0.8 / (1 + g)
```

gap 越大，分数严格越低，argmax 仍选择最小 gap。正常有限数值下，没有这种新的决策偏好。OBP / 1 / 121、OBP / 2 / 138 也分别是 Best Fit 的单调变换。对三份实际代码，各构造 1,000 个正 item、可行 bins 状态，选择均与 Best Fit 一致；数学式给出原因，探针只作核对，未覆盖溢出等极端情况。

**含义：更丰富的解释，可能只是在给同一行为增加新的算法名称。**

### 2. 找到了修改位置，却未识别修改没有生效

**OP / 2 / 354**：父子代码唯一差异是 `clip(..., 0, 2.5)` 改成 `clip(..., 0, 2.0)`。二次版准确定位该差异，但解释成减弱极端 prize-to-distance 值的影响。

前面实际有：

```python
scale_r = max(r_mean, 0.5 * r_max, eps)
ratio_norm = ratio / scale_r
```

因而 `ratio_norm<=2`，两种上限都不会改变正常非负输入的结果。100 个随机欧氏实例上，父子返回矩阵逐元素完全相同；已记录父子 fitness 也相同，为 `14.59`。等价判断依据代数与代码，分数相同仅为补充。

同类问题还出现在 CVRP 的行归一化解释中：在乘法 ACO 权重再除以行和的理想计算下，整行公共比例因子会抵消。实际 evaluator 的加 epsilon、floor、浮点效应需另算，不能直接讲成改变信息素与启发式的相对权衡。

### 3. 忽略数值语义，描述了实际未执行出的算法

**TSP / 2 / 236**：两版都描述前期结构感知、后期 rollout。实际前期对角线先设为 `inf`，随后：

```python
mean_conn = np.mean(masked[:m, :], axis=1)
structural = 0.7 * sum_2nn + 0.3 * mean_conn
struct_norm = structural / np.max(structural)
```

每行都含 `inf`，于是结构值全为 `inf`，归一化全为 `NaN`，最后 scores 全为 `NaN`，`np.argmin` 返回第一个位置。用实际完整函数跟踪一个 29 候选状态，确认全部 scores 为 NaN，反转候选顺序后结果跟着变成新的首元素。当前 TSP evaluator 按距当前节点的距离排列候选，故正常欧氏数据下 **m>12 阶段实际退化为最近邻选择**；m<=12 的 rollout 仍按另一分支执行。

这份程序仍有有效 fitness `-6.65335`，二次 Idea 完全没有指出该退化。

**OP / 3 / 204** 也存在类似问题。摘要说使用累计和得到半径内全部奖品，但代码：

```python
cum[:, 0] = prizes[:, 0]
cum[:, 1:] = prizes[:, 1:] + cum[:, :-1]
```

右侧读取赋值前的数组，不能逐列累计。例如 `[2,3,5,7]` 得到 `[2,5,5,7]`，正确累计和应为 `[2,5,10,17]`。实际函数的局部变量跟踪同样确认累加结果错误。因此，二次版虽然修正了分母，仍把错误实现描述成完整的 cluster-prize 估计。

### 4. 参数值和偏好方向继续沿用设计叙述

**OBP / 1 / 266**：两版均写 Gaussian 标准差 `0.5*item`，代码是 `max(item,1)`；item=10 时实际 sigma=10，描述是 5。

**VRPTW / 2 / 56**：二次版说紧窗惩罚促使优先访问紧急客户，但代码把正的紧窗项加入要最小化的 score。控制其他项后，越紧急反而分数越高、越不受偏好。两版还把需求方向说反：`p>.5` 时实际偏好低需求，`p<.5` 时实际偏好高需求。二次版称 urgency 为 quadratic，实际幂次为 1.5。

**VRPTW / 3 / 114、/ 3 / 300** 也把正的紧迫度代价解释成优先紧迫客户。**TSP / 3 / 17** 新增了 `n<20` 时 gamma 恒为 0.8 的错误说法，代码实际上按 `0.8*n/20` 下降。

### 5. 新增不真实的父代改进历史

**CVRP / 2 / 126**：二次版声称父代加法组合、子代改成乘法；父代实际已经是 `geo_component * modulation`。这是第二调用新增的错误变更叙事。

**VRPTW / 1 / 202**：二次版断言代码与父代完全一样，但实际改了两项权重条件。例如 `slack_norm=.4` 时，父代 `W_CONT=.3`，子代 `.39`；`.1` 时父代 `W_URG=.2`，子代 `.15`。原版所说的权重改进方向反而更符合“确实有修改”这一事实。

两次调用中都有完整父代码，这些错误无法归因于缺少父代码。OBP / 3 / 243 的正确等价识别与这里的错误等价识别并存，说明这项能力还不能作为可信的历史标注器。

## 运行是否正常，以及证据边界

10,872 次已完成评估对应的事件中，**10,870 条有二次 Idea，2 条 unavailable**。10,116 个有效节点中有 2 个空 Idea。30 个抽样对子都通过了四项来源核对。当前首先暴露的是内容可靠性问题，接口链路整体在正常工作。

有效节点摘要 token 中位数 680、最大值 2,310；47 条原始摘要超过单条上下文上限 1,024 tokens。`present` 表示二次输出被接收，不能解释为日后全文都进入历史；当前 builder 会按段落保留前缀或省略。本次没有把“超过上限”计为语义错误，也没有据此估算实际历史截断次数。

本次能够确认的是**原版与二次版对同一代码的具体描述差异**。它不能单独回答：第二调用相对于直接只看代码摘要是否更好、前置 Idea 是否产生锚定影响、是否比旧单调用 V10.6 更好、是否提高 SOTA 搜索成绩、是否值得其全部调用成本。旧批次与新批次之间还包含任务模板恢复等变更，搜索分数的前后差异不能直接归因于校准。

代码可见但摘要未识别的数学问题，与评估器调用链的信息边界也应区分。OBP 单调性、TSP 的 NaN、OP 的累计和与无效 clip，均可以仅从提供的代码判断。OP 中返仓列不参与主动终止，需要核对 evaluator；该事实可用于研究者解释观察，但本次没有增加方法专用任务提示。

## 当前决策

**保留现有两阶段流程作为工作方案，但将第二输出定位为“有一定纠错能力的实现描述”，不能把它视为已经验证的算法事实。** 保留的依据是这次发现了明确的信息收益；这不是已经证实额外调用的净收益最优。

下一步最值得解决的是：摘要能否准确说明真正参与最终选择的计算，并如实描述父子变化。继续增加字数或要求更多收益解释，都没有对准本次暴露的主要问题。当前提示词已经要求以代码为依据，实际失败说明“再强调一句贴合代码”本身不足以构成解决方案。

若继续改进摘要机制，优先在这些冻结配对上离线比较少量职责更集中的提示，让描述围绕最终返回值、真实参数与生效条件、可核对的父子差异展开，并将收益判断写成假设。用明确错位是否消失以及是否新增错误作判断，再决定是否进入下一批正式实验。这样的离线验证检查描述质量；是否提高搜索表现仍需后续完整搜索比较。

本次仅新增核查材料，没有修改实验实现、提示词、共享任务说明或运行中的实验。

## 结论与启示

二次 Idea 在代码与意图描述上提供了有用的局部细节纠偏，但无法替代对实际执行语义与搜索收益的真实评测。后续设计应重点保证关键返回值与控制流逻辑的准确说明，避免单纯堆砌形式化解释。
