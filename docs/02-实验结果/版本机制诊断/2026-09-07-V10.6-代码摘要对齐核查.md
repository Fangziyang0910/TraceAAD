## 数据与核查方法

快照时V10.6累计2091次真实评价，15路均超过90次；V10.5各路已到1000。为避免搜索阶段差异，本次比较两版各15路的前90次真实评价，各1350次评价。V10.5有1258个有效入档节点，V10.6有1301个。文本统计覆盖这些有效节点；**语义核查只覆盖下面选定的30个样本，不能说已人工核对2559段摘要**。

取样规则在读取个体内容前固定：每版、每任务、每个重复，取evaluation_id=80的有效非根节点；若80无效，则取80—90范围内下一个有效非根。各版15个，共30个。只有V10.6 VRPTW r3顺延到eval81。核对代码、摘要与父代代码；涉及求解器调用时再核对实际evaluator。取样没有按fitness、摘要好坏或算子筛选，也未使用此前冒烟反例替代正式数据。

这是固定位置分层抽查，不是随机独立样本、盲审或多评审者标注；不同运行的谱系、模型输出与代码复杂度不同。V10.6还有两路本地量化服务，V10.5本批次全部远端。两版同时改变了摘要长度、任务说明、算子措辞和历史上下文。因此不将任何差异单独归因于输出顺序，也不把发现错误的段落比例当作可比较的准确率。

## 具体发现

### 实现细节更充分，有实际价值

V10.6 CVRP r3 node76清楚记录k从3到4、customer边bridge系数从1.2到1.8、logistic斜率5到7和中点0.75到0.70，以及角度与sweep参数变化，这些能与代码逐项对应。OBP r3 node77也准确描述了bounded waste ratio、0.3倍future_utility和移除旧tie项。旧版短Idea常只给算法标签或设计意图；新摘要给下一次生成提供了更具体的实现材料。

这证明部分摘要包含有用事实，不证明整个版本准确率提高，也不证明这些描述已经改善了搜索。

### 写对公式，仍然说错执行作用

V10.6 OBP r2 node79把新评分称为Best-Fit与额外利用率偏好的结合：

`score = -(b - item) - 0.1*b/M = -(1 + 0.1/M)*b + item`。

一次调用中item、M相同，M>0，排序和平局与纯Best-Fit一致。摘要中公式正确，但“额外信息会改变近似平局、提高整合效果”的解释没有相应机制。1000组整数可行输入的直接函数检查均与Best-Fit选择相同；完整等价性来自上述代数化简，而非由这1000例或相同fitness单独证明。

V10.6 VRPTW r2 node77的`urgency=(max_end-end)/range`以正号进入最小化评分。其他项相同时，较早截止客户受罚；摘要却说优先紧急客户。VRPTW r3 node75列对了回仓阈值，却说反“大/小集合时更容易回仓”的方向。公式复述与行为解释是两个不同能力。

### 算法组件存在于文字中，却没有按文字工作

V10.6 TSP r3 node76声称使用第二近邻和连接度，代码为：

```python
np.partition(sub_dist, 1, axis=1)
min2 = sub_dist[:, 1]
```

返回值被丢弃，原数组未变，min2实际是固定列。另一方面，sub_dist的对角线设为inf，行均值全部inf，因此`ac_max > ac_min`为False，连接度分支不执行。小矩阵复核确认这两个事实。摘要仍把二者解释为算法的有效决策信号。

在发现这一反例后，对该路前90评价做定向模式检索：87个有效节点中，44个含相同“丢弃partition返回值、随后取固定列”的代码模式，其中43个摘要含second一词。此处是代码模式与关键词覆盖数，不能把43直接当作独立语义错误数。样本的多个祖先也含同一代码模式，说明错误可沿谱系延续；不能因此断言是摘要本身因果导致了传播。

旧版同样有这类问题：V10.5 VRPTW r2 node71把距离子矩阵对角设0，再取行最小值，使forward_cost恒0；Idea仍称其包含有效前瞻。V10.5 OBP r3 node78则把正remaining经argmax选出的较松箱解释为Best-Fit。代码后描述没有自动消除旧版的根本失效类型。

### 摘要可能漏掉比所列调参更重要的变化

V10.6 CVRP r1 node77列出了指数、角度衰减与回仓惩罚等变化，却漏掉`angular_heuristic`由zeros初始化改为ones，以及组合中的角度幂从0.6改为0.5。对未被customer子块覆盖的customer→depot边，该因子从约`(1e-10)^0.6=1e-6`变为约1。

这发生在其他乘子及最终归一化之前，不能把1e6倍直接当作最终转移概率比；它足以说明这次变更不只是摘要列出的温和调参。该子代fitness由父代-9.346529变为-17.797306，但本次没有通过受控重评把全部退化归因到这一变化。

## 为什么会这样，以及该怎样使用V10.6

同一次自回归生成中，后置摘要可以以已经生成的代码为条件；前置Idea不能读取尚未生成的完整实现。因此代码先行具有合理的信息优势。但模型仍需正确理解算子符号、数组API、分支、覆盖赋值和调用框架，也可能继续沿用代码注释与历史摘要中的错误解释。输出顺序并没有提供执行观测或独立事实校验。

当前流程在摘要完成后才评价新代码。准确名称应是**代码实现摘要**：它不是根据运行轨迹生成的执行报告，也不能知道这次改动实际提高了fitness。一个整体性能不错的程序可以含无效组件；一个解释准确的程序也可以得分差。fitness不适合作为摘要真实性标签。

保留Code→Summary；现有约500 words软目标和1024-token上限可继续沿用。本次优先调整的是摘要的写作任务：把篇幅用于实际计算、关键参数、分支与父代差异，收益解释保留为假设。可供后续版本使用的正向措辞为：

> Describe how the implementation above computes its output, including its main rule, important formulas and parameters, and the conditions under which each rule applies. When a current algorithm is provided, describe the concrete implementation changes. Explain effects that follow from the code, and frame expected performance benefits as hypotheses.

这段措辞是一项待验证的改进建议，不保证消除语义错误；本次未修改正在运行的V10.6提示、源代码或历史摘要，也未增加独立LLM调用。若以后需要证明“输出顺序本身有效”，应控制摘要长度、同一任务/父代材料和生成设置，只改变顺序；现有两个完整版本的过程数据无法完成该因果识别。当前可先完成正式配方，评价最终搜索收益。
