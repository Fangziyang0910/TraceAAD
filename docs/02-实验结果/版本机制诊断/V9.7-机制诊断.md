# TraceAAD V9.7 机制诊断

V9.7 是代表性同场中综合表现很强的联合系统。完整版本同时包含父代来时路、Refine/Explore、路线—锚点选择和原子反馈，优势不能归因到某一条分配公式。路线乐观项几乎没有持续改变选择。

## 1. 核心判断

1. **来时路帮助本轮改写。** 同一锚点下，父代改进来时路在四任务上改善单步质量，并减少大幅改写。
2. **预算很快集中到少数来源。** 顶路线份额 99.4%–100%。TSP、CVRP 上这条深改写链与较好结果相容；OP 上同样的早期集中与后续难以换方向相容。这是当时公式的过程事实。
3. **两种提示改写行为不同。** Refine 改得更小、即时质量更高，终局最好程序由 Refine 步产生；Explore 改动更大、即时质量更低，离线静态机制标签切换更勤。
4. **每次选一个节点、生成一个候选、真实评价一次、立刻再选。**

V9.7 是联合系统结果。两级分配公式、固定 `0.7/0.3` 各自的贡献没有单独识别。

| 判断 | 证据层 | 当前结论 |
| --- | --- | --- |
| 父代来时路改变并改善单步生成 | 固定锚点配对实验 | 已支持 |

| 路线层几乎不改写选择 | 决策日志反事实重放 | 已支持 |
| 锚点乐观项持续改变局部选择 | 决策日志反事实重放 | 已支持 |

## 2. V9.7 在历史演化中的位置

V9.7 的形成不是一次公式设计，而是连续删除错误抽象后留下的最小有效结构。

| 阶段 | 主要尝试 | 结果与留下的认识 |
| --- | --- | --- |
| V1–V2 | 图、岛模型、多分量价值、算子 bandit、Elo、novelty、Pareto 和多层记忆同时叠加 | 附属控制层没有独立证据，联合系统难以归因 |
| V3–V7 | 在轨迹种群中逐步删除岛、趋势、复杂度和部分信用；尝试语义算子、跨路线迁移、去重与衰减探索 | 种群生存把当前保留与未来潜力绑定；趋势和成熟度等代理容易奖励噪声 |
| V8–V9 | 用完整单亲树保存所有有效状态，引入递归选择、max-backup 和局部历史 | 树适合保存形成事实；复合信用、深度上限和 max-backup 没有稳定增益 |
| V9.1–V9.4 | 路线推进率、直接子代均值、三步 rollout、折扣后代信用 | 信用要么改变错误选择，要么几乎不改变选择；V9.4 确立原子决策骨架 |
| V9.5–V9.6 | 将锚点、父代形成历史和已有子代尝试拆开，修正历史表示 | 父代来时路与局部已试边界是不同信息；提示信息应按生成作用识别 |
| V9.7 | 父代来时路、Refine/Explore、路线—锚点分配、原子评价循环 | 形成当前最强的联合运行体制 |
| V9.8–V9.11 | hypothesis、边界宽限、几何秩、动态算子概率、Thompson、延迟信用、停滞触发和 Landing | 新机制分别出现状态膨胀、动态退化、反馈不可结算和任务无关 horizon，均未统一超过 V9.7 |

历史上真正保留下来的不是某一种轨迹价值函数，而是四个原则：单结构父代、真实 evaluator、失败与退步作为形成事实、一次模型级决策只产生一个新 `Idea + Code`。V9.7 第一次把这些原则与经过单步证据支持的来时路上下文结合起来。

## 3. 机制骨架与运行职责

### 3.1 状态与形成事实

V9.7 用森林保存 8 个代码互异根及其单亲形成树。一个锚点表示某个程序沿一条具体父链形成的位置；程序代码相同但来时路不同，可以构成不同生成状态。路线只表示共同根来源，不能自动解释为算法簇。

搜索事实分为三类：

- 程序及其真实 fitness；
- 父子形成事件中的 Idea、实际修改、结果与 fitness transition；
- 从某个锚点出发但没有成为其父链组成部分的直接尝试。

默认提示只读取当前完整程序与最近至多 8 个父代形成事件。已有子代尝试继续保存在工件中，但不常驻生成上下文。

### 3.2 提议机制

每次选择一个生成意图：

- `Refine`：在当前设计内做一次聚焦修改，固定概率为 `0.7`；
- `Explore`：改变重要决策原则或重构关键部分，固定概率为 `0.3`。

两者共享任务、当前代码、fitness、父代来时路和输出契约，仅意图指令不同。它们控制条件生成分布 $P(x'\mid x,h,o)$，不直接决定候选是否继续获得预算。

### 3.3 分配机制

路线层选择分数为

$$
S_t^{\mathrm{route}}(r)=q_t^*(r)+\frac{s}{\sqrt{N_t(r)+1}},
$$

选定路线后，锚点层分数为

$$
S_t^{\mathrm{anchor}}(a)=q(a)+\frac{s}{\sqrt{n_t(a)+1}}.
$$

$s$ 来自每个根一次 Refine bootstrap 的绝对一步变化中位数。路线层的 $N(r)$ 是路线累计投入，锚点层的 $n(a)$ 是锚点直接尝试次数。两层公式同形，但比较对象、质量跨度和决策作用不同。

### 3.4 原子反馈循环

正式搜索始终执行：

$$
\mathrm{select\ anchor}
\rightarrow
\mathrm{select\ intent}
\rightarrow
\mathrm{generate\ one\ candidate}
\rightarrow
\mathrm{evaluate}
\rightarrow
\mathrm{update\ facts}
\rightarrow
\mathrm{reselect}.
$$

系统不预先承诺固定多步 rollout，不等待未来后代后再更新本次选择，也不根据最终谱系给祖先回传成功信用。这个短反馈环是 V9.7 相对 V9.3 和 V9.10 的关键稳定条件。

## 4. 证据来源与因果结构

证据分四层，前一层不能替代后一层：

1. **实现与机制规范**：确认组件如何运行；
2. **过程激活与选择重放**：判断组件是否实际改变选择；
3. **固定锚点生成实验**：识别来时路与意图如何改变下一候选；
4. **正式搜索与同规模独立测试**：评价完整联合版本的搜索能力与同任务质量；跨规模测试补充迁移信息。

正式结果使用每任务三次独立搜索、每次 1000 次真实评价和同规模独立测试。搜索 best、过程曲线、固定锚点 trial 和同规模测试分别回答不同问题。

V9.6 到 V9.7 同时改变路线分配、生成意图与历史组成，只能评价联合系统。来时路的 code-only 完整搜索消融已完成，净贡献依任务画像（§6.4）；固定锚点收益不能外推为跨任务一致的完整搜索收益。Refine 与 Explore 在完整搜索中面对分配器选出的不同锚点，完整日志中的意图差异也不能替代固定锚点意图实验。

## 5. 正式质量与任务异质性

### 5.1 综合位置

在代表性同场比较中，只放入 V8、V9、V9.7 与 5 个外部对照，7 个同规模测试设置上的描述性平均名次为：

| 方法 | 平均名次 |
| --- | ---: |
| TraceAAD V9.7 | **3.429** |
| TraceAAD V9 | 3.571 |
| MCTS-AHD | 4.786 |
| TraceAAD V8 | 5.000 |

若每次只放一个 TraceAAD 版本与 5 个外部对照比较，V9 的同规模平均名次为 1.857，V9.7 为 2.000。这个口径支持 V9.7 与 V9 是当前最强的两个代表性版本，但不能把 V9.7 写成对所有内部版本和任务的支配性升级。

相对 MCTS-AHD，V9.7 在 7 个同规模设置中的平均名次更低；TSP、CVRP、OBP 的同规模质量占优，OP 低于 MCTS-AHD。这个结果支持“存在超过 MCTS-AHD 的 TraceAAD 版本”，不支持跨任务、跨设置的一致支配。

### 5.2 四任务结果画像

| 任务 | V9.7 的同规模测试画像 | 过程解释 |
| --- | --- | --- |
| TSP | TSP50 均值 5.991，接近主表最佳 V9.9 的 5.976 | 搜索前期已领先，后期仍有小幅刷新；联合协议抬高可达前沿 |
| CVRP | CVRP50 均值 9.021，优于 V9 与 MCTS-AHD，低于主表最佳 V8 | 长精炼链明显，同规模质量与深度发展相容 |
| OP | OP50 均值 15.003，低于 V9 与 MCTS-AHD | improve 稀疏，早期耗尽较低前沿；强局部化没有找到更高质量区域 |
| OBP | 多数版本差在 1% 内，方向混合 | 分数离散和平局使多路线维持更久；过程差异没有转化为稳定质量差 |

### 5.3 搜索效率、天花板与稳定性

- **TSP**：三次最后刷新在第 769/912/974 次评价。V9.7 从约第 100 次评价起领先 V9.6，前 250 次已获得约 94% 的搜索增益，之后仍有小幅刷新。优势同时包含较高前期效率与更高终点。
- **CVRP**：最后刷新均值约为第 806 次；V8 更晚刷新且 CVRP50 更好，V9.7 在 CVRP100/200 更好。V9.7 的运行间标准差高于 V8，不能称为更稳。
- **OP**：前 250 次已获得约 98% 的搜索增益，90% 增益平均在第 82 次评价达到；后续预算很少提高全局最好。
- **OBP**：三次最后刷新都在第 732 次之后，但总增益小，曲线形态没有转化为稳定版本差。

V9.7 不是跨任务统一的 sample-efficiency 方法。TSP/CVRP 更接近“抬高可达前沿并保留后期精炼”，OP 更接近“较早耗尽一个较低前沿”。

## 6. 轨迹条件生成：V9.7 最坚实的机制价值

### 6.1 父代来时路的固定锚点作用

第三轮固定锚点实验比较 `code_only`、`parent_path` 和 `parent_path_child`。72 个锚点覆盖四任务与三个质量层，每个条件重复 3 次，共 648 次生成；任务、当前代码、输出契约和块内采样 seed 保持一致。

| 任务 | `parent_path - code_only` 配对 conditional $\Delta q$ | Improve rate | Valid rate |
| --- | ---: | ---: | ---: |
| TSP | **+1.233 [0.283, 2.375]** | 0.0% → 12.0% | 81.5% → 98.1% |
| CVRP | **+4.298 [2.475, 6.034]** | 3.7% → 18.5% | 98.1% → 96.3% |
| OP | **+0.250 [0.078, 0.437]** | 4.6% → 3.7% | 90.7% → 98.1% |
| OBP | **+111.8 [14.1, 224.3]** | 0.0% → 1.9% | 98.1% → 98.1% |

四任务配对区间均不跨 0，72 个锚点中 58 个方向更好。来时路的主要作用不是稳定制造更多 improvement，而是压缩灾难性偏离：

- trial 级中位 $\Delta q$ 在四任务上一致右移；
- TSP/CVRP/OP 落入最差十分位的改写从 `16%/23%/16%` 降到 `6%/4%/8%`；
- 修改比例从约 `0.71–0.80` 降到 `0.36–0.64`。

因此，来时路提供的是**当前设计怎样形成的局部约束**。它帮助模型保留已经形成的有效结构，减少与当前程序不相容的大幅重写。该作用已被识别到单步生成层；完整搜索层的净贡献依任务画像，见 §6.4。

### 6.2 已有子代尝试没有稳定额外价值

在父代来时路上追加已有子代尝试后，四任务配对区间均跨 0，总方向为 35 好、34 差、3 平。TSP 的 paired $\Delta q$ 为负，CVRP 的 improvement rate 从 18.5% 降至 9.3%。

这说明形成路径和局部已试边界不应在默认上下文中占同等位置。V9.7 保留 direct attempts 作为可审计搜索事实，但不让其持续占用生成注意力，是当前证据支持的上下文选择。

### 6.3 来时路没有单调适用区

将固定锚点按质量三等层拆分后，12 个任务乘质量层的 parent-path 效应点估计全部为正，7 个区间不跨 0；收益不只出现在低质量锚点，也不随质量单调变化。深度、发生时点、历史 improve/regress 比例、路径净增益和最后一步 $\Delta q$ 也没有形成跨任务稳定的 effect modifier。

因此，当前不应设计“只在成熟锚点展示历史”或“只在低质量状态关闭历史”的规则。已有证据支持 parent path 作为 Refine 的默认 development context，不支持基于深度或质量的启发式开关。

### 6.4 单步收益向完整搜索的转化依任务画像

PP/CO 完整搜索消融（V9.7 协议、同 seed 配对，4 任务 × 3 seed × 1000 eval，批次 `ppab_20260820_131000`）补上了 6.1 单步证据与完整搜索之间缺的一层：来时路的净贡献不是跨任务常数。OP 的 search best 与同规模 OP50 测试均支持 PP；TSP 的 search best 与 TSP50 均偏 CO；CVRP 的 search best 偏 PP、CVRP50 偏 CO；OBP search best 相等，同规模四设置中 CO 占三个。

净贡献方向与“锁定区域是否低于可达上限”的任务画像对齐：

- OP 正是强局部化锁进较低上限区域的任务（§12.3，V9.7 三个规模均弱于 V9）。区域低于上限时，提议质量是终点的瓶颈，来时路对每步提议的改善累积为区域内更高的可达终点。
- OBP 评价离散、总增益小（§5.3），两臂终点重合；TSP 前期已领先、区域开发充分，臂差在噪声内。区域接近自身上限时，提议质量的差异不再改变终点。

机制上，完整搜索的存档始终保留最优程序，一次灾难性子代只消耗一份评价、不损害基线。单步“压缩灾难性偏离”的收益因此有两条兑现路径：提高锁定区域的可达终点（OP 的形态），或减少浪费评价、加快收敛而终点不变。第二条路径与三重复空结果相容——n=3 下臂差与 seed 方差同量级，空结果说明检验力不足，不证明无贡献。[待验证]

检验：ppab 批次 24 个 run 的中途预算 best-so-far 曲线（如 200/500/1000 对照）用现有工件即可完成——PP 中途领先而终点追平，则效率路径成立；更短预算（如 200 eval）的同协议对照需要新运行，预算越紧来时路优势应越明显。

## 7. Refine 与 Explore：稀疏换簇后继续开发

### 7.1 正式搜索中的提议差异

| 任务 | Improve：Refine / Explore | 静态宏簇切换：Refine / Explore | Explore 的全局增益份额 |
| --- | ---: | ---: | ---: |
| TSP | 14.6% / 4.2% | 7.4% / 37.2% | 36.5% |
| CVRP | 36.7% / 2.2% | 2.3% / 48.9% | 22.1% |
| OP | 6.3% / 1.3% | 12.0% / 53.9% | 20.2% |
| OBP | 29.1% / 6.3% | 5.3% / 36.9% | 21.9% |

Explore 在四任务上都更少产生普通 improve，却更常改变静态机制代理，且全局突破的中位增量高于 Refine。V9.8 的固定锚点 History × Intent 实验进一步确认：在 code-only 和 parent-path 两种上下文中，Explore 都形成更大的代码修改和更多静态宏簇切换，即时有向质量低于 Refine。两种指令确实改变 proposal behavior。

静态宏簇是任务内、解释型代理，不能等同于真实算法 family；完整搜索中的 Refine 与 Explore 又面对不同锚点。因此，当前只支持“意图改变提议分布”，不支持“Explore 已稳定发现更优算法簇”。

### 7.2 最终谱系中的互补角色

从根程序到最终最好程序，12 次运行中有 9 次发生静态宏簇变化：

- 6 次由 Explore 首次进入终局宏簇；
- 3 次由 Refine 首次进入；
- 12 个最终最好程序的出生事件全部是 Refine。

这形成如下描述性链条：

$$
\mathrm{Explore: sparse\ structural\ relocation}
\rightarrow
\mathrm{Refine: within\ region\ development\ and\ final\ hit}.
$$

Explore 不是仅凭低 improve rate 就可以删除的破坏性算子；Refine 仍是最终质量的主要兑现者。固定 `0.7/0.3` 只是当前协议，尚无证据说明这个比例或固定混合优于任务条件调度。

## 8. 分配几何：路线早期吸收，锚点层持续工作

### 8.1 路线分数的不可恢复区

若欠投入路线满足

$$
q_t^*(r)+\frac{s}{\sqrt{N_t(r)+1}}<\max_j q_t^*(j),
$$

它当时无法入选；不入选又使质量与访问数保持不变。其他路线的历史最好质量只升不降，因此该路线以后无法自行返回竞争前沿。初始化后每条路线已有一次 bootstrap，一条不再访问的路线最多只保留 $s/\sqrt{2}$ 的补偿。

这是一种由确定性分数产生的吸收态，不是普通的“逐渐集中”。

### 8.2 实际集中

| 任务 | 单路线吸收决策，rep1/2/3 | 顶路线份额 | bootstrap 后零次正式访问 |
| --- | ---: | ---: | ---: |
| TSP | 5 / 40 / 7 | 99.4%–100% | 19/24 |
| CVRP | 1 / 2 / 1 | 100% | 21/24 |
| OP | 1 / 1 / 1 | 100% | 21/24 |
| OBP | 28 / 176 / 147 | 85.9%–98.0% | 3/24 |

12,152 次正式决策中：

- 路线乐观项改变 130 次选择，占 1.07%，且全部发生在前 1/3；
- 锚点乐观项改变 7,877 次，占 64.8%。

因此，V9.7 的长期运行形态不是多路线自适应分配，而是：

$$
\mathrm{early\ provenance\ gate}
\rightarrow
\mathrm{within\ route\ anchor\ search}.
$$

路线层近似未激活是过程负结果；路线集中本身却形成了强局部化体制。两件事必须分开：没有证据表明路线 bonus 成功估计了多路线延续价值，但预算确实长期集中在一个来源区域。

### 8.3 路线不保持算法簇身份

每次运行的 8 个代码互异根只覆盖 2–3 个静态宏簇，最终最好程序有 9/12 次改变所在根的宏簇。路线保存的是 provenance，同一路线内部可以从 local score 迁移到 rollout、从 angular heuristic 迁移到 sweep partition、从 best fit 迁移到 distribution model。

因此，路线集中不等于始终停留在初始算法族；跨簇搜索主要发生在主路线内部。现行 route 可以作为事实来源单位，尚未被验证为稳定的 family 或理想投资单位。

### 8.4 被放弃路线的潜力不可识别

96 条路线中有 64 条没有 bootstrap 后续段。它们的观测终点只是 root 与一次 Refine 的最大值，不是路线 ceiling。现有日志无法区分：

1. 领先路线确实具有更高后续潜力，集中是正确选择；
2. 多个根实际上属于同一算法族，路线层没有可利用异质性；
3. 路线存在潜力差异，但当前 $q^*+s/\sqrt{N+1}$ 看不见 continuation value。

用被放弃路线的观测终点比较主路线，会把投资不足误写成潜力不足。路线分配的净价值必须通过匹配根和强制前缀覆盖建立可比较续段。

### 8.5 一个尺度承担了三个不同问题

$s$ 来自 Refine bootstrap 的一步变化，却同时用于：

1. 不同根来源之间的路线竞争；
2. 同一路线内常规 Refine 锚点竞争；
3. Explore 大幅换簇后的新锚点存活。

TSP、CVRP、OP 的初始化路线质量跨度分别约为 `3.8–6.2`、`5.5–7.2`、`12.4–19.3` 个 $s$，路线补偿很快失去作用；Explore 的质量变化又远大于普通 Refine，大量新 child 的退步超过一个 $s$。共享尺度没有同时匹配路线覆盖、局部回访和跨簇着陆。

## 9. Proposal 与 Allocation 的接口错位

新 child 的锚点访问数为 0，最大锚点补偿为 $s$。若

$$
q_{\mathrm{child}}+s<q^*(r),
$$

它无法获得第一次后续生成，并因不再更新而永久失去机会。

| 任务 | 出生即淘汰：Refine / Explore | 有观察后代：Refine / Explore | 后代越过原父代：Refine / Explore |
| --- | ---: | ---: | ---: |
| TSP | 13.6% / 55.9% | 75.3% / 29.1% | 28.8% / 8.7% |
| CVRP | 3.8% / 86.9% | 88.8% / 7.0% | 43.7% / 3.9% |
| OP | 48.4% / 85.7% | 37.5% / 10.8% | 10.0% / 3.4% |
| OBP | 5.6% / 35.9% | 85.5% / 32.7% | 34.6% / 10.3% |

跨静态宏簇 child 的淘汰率为 TSP 73.5%、CVRP 81.8%、OP 84.8%、OBP 33.9%，明显高于多数不换簇 child。Explore 的 realized descendant value 同时受到两层作用：它产生更大即时退步，分配器又更少让这些 child 长出后代。

V9.8 的强制五步续段证明部分 Explore child 可以恢复或内部发展，但 parent recovery 高度任务相关：OBP、OP 增加明显，TSP 仅小幅增加，CVRP 基本没有越过原父代。由此只能得到：

> **跨边界即时低质量不等于零延迟价值；development opportunity 也不等于 guaranteed budget。**

## 10. 为什么 V9.7 会形成优势

### 10.1 最小有效信息提高了每一步的可用率

V9.7 保留当前完整代码和匹配父链，删除没有稳定额外价值的 direct attempts 常驻上下文。来时路让 Refine 更少破坏已有设计，真实 evaluator 又在每一步立即判断结果。与早期多记忆、多价值分量相比，这条链的信息来源更直接、信用路径更短。

### 10.2 强局部化让局部改进可以复利

路线吸收态是 V9.7 的缺陷，也是它在运行上形成深精炼体制的直接原因。路线层很早锁定后，预算没有持续摊薄到多个根来源；锚点层仍在同一来源区域内频繁改变选择，形成“区域集中、局部多锚点”的体制。该体制是否提高最终质量仍需受控分配实验识别。

V9.9 提供了最清楚的跨版本对照：

| 版本 | 胜选区域预算份额 | CVRP 胜选路径有效 improve 深度 | CVRP search best |
| --- | --- | ---: | ---: |
| V9.7 | 顶路线 99.4%–100% | 65–73 | −8.66 |
| V9.9 | 胜选血统 12%–18% | 27–37 | −9.00 |

V9.9 的恒定宽度光束持续追逐新生锚点，最终血统得到的预算和有效深度都明显下降，CVRP 搜索与同规模 CVRP50 测试同向退化。这个观察支持“深精炼是 V9.7 的重要运行优势”，但不能单独证明路线吸收导致质量提升，因为两个版本还同时改变了初始化、分数和算子调度。

### 10.3 稀疏 Explore 让局部化不等于固定算法族

虽然路线层几乎不探索，proposal 可以在主路线内改变算法宏簇。Explore 提供低频结构迁移，Refine 负责随后的长链发展，使 V9.7 同时具有局部化与一定可达性。它避免了纯单点 greedy 的完全封闭，也没有像 V9.8–V9.10 那样为每个新方向建立复杂长期信用。

### 10.4 原子反馈避免未结算信用污染搜索

V9.3 的三步 rollout 把历史条件误写成未来预算承诺；V9.10 的三代结算又使大量动作长期 pending。V9.7 只使用当前真实质量和直接访问计数，每次评价后立即重选。它没有估计长期 continuation value，却也没有让错误或不可观测的长期估计扩散预算。

因此，V9.7 的优势更像**少犯系统性错误**：生成侧使用已经获得正证据的上下文，分配侧保持简单，搜索体制又恰好允许深局部精炼和稀疏结构迁移共同发生。

## 11. V9.8–V9.11 提供的后续反证

后续版本没有证明“V9.7 的所有机制都是正确的”。它们从不同方向显示：改变 V9.7 的局部化、反馈时效或状态复杂度时，综合表现损失也随之出现。

| 版本 | 想解决的问题 | 实际运行结果 | 对理解 V9.7 的贡献 |
| --- | --- | --- | --- |
| V9.8 | 用 Explore-defined hypothesis、边界宽限和历史发展收益保护跨簇 child | 产生约 227–303 个新 hypothesis；$C/M$ 被激活但无单因素反事实；OP 改善、CVRP 三档退化，综合未超过 V9.7 | 更多状态与宽限不自动等于有效探索；任务间恢复性不同 |
| V9.9 | 取消 route/hypothesis 信用，改为全局锚点几何秩与条件算子概率 | 分配熵几乎时不变，算子概率接近固定混合；75%–90% Explore child 未被再次选择，胜选血统只获 8%–18% 预算 | 恒定宽度摊薄深精炼；自适应公式可以在运行中退化为静态协议 |
| V9.10 | 用折扣 Thompson 学习锚点×意图的短程改进价值 | 臂空间接近评价数增长，约半数锚点不再访问；36%–53% 动作终局仍 pending，分配接近均匀 | 信用必须在有限响应时间内可观测；长期 pending 无法形成有效后验 |
| V9.11 | 用停滞触发 Explore，并给一次无条件 Landing | Landing 经常改善 Explore child，却很少恢复到 Explore 前父代；对 V9.7 仅 5/15 设置更好 | 简化即时反馈能止跌，但固定停滞阈值和一次 Landing 不能处理任务异质性 |

V9.8–V9.11 均保留了 V9.7 的部分生成骨架，却没有统一追回 V9.7。最稳妥的解释是：V9.7 已经处在一个“信息足够、控制偏差较少、深度投资没有被摊薄”的协调点。这个解释仍需匹配消融验证，不能把后续版本退化反向写成 V9.7 各组件的独立因果证明。

## 12. 四任务为什么表现不同

### 12.1 TSP：可靠局部改动与后期小突破共同有效

V9.7 从约第 100 次评价起领先 V9.6，三次最终最好程序在较晚阶段出现。来时路明显减少灾难性改写，Explore 仍贡献 36.5% 的累计全局增益。TSP 的结果与“可靠 Refine 加少量较大结构迁移”相容。

TSP 相对 V9.6 的变化是分配、意图和历史组成的联合结果，不能归因到来时路或 Explore。长谱系也是高度路线集中的结果，不能把路径长度本身解释为价值来源。

### 12.2 CVRP：深精炼回报最长

CVRP 的 Refine improve rate 为四任务最高，最终形成链包含大量 improve、regress 和修复。V9.7 的有效精炼深度明显高于 V9.9，同规模 CVRP50 测试优于 V9.9、V9 与 MCTS-AHD，低于 V8。

与此同时，CVRP Explore child 出生即淘汰率最高，固定五步续段也几乎没有提高 parent recovery。当前结果说明 CVRP 的主要优势与深局部发展相容，不说明更强的跨簇保护会有益。

### 12.3 OP：局部化集中在较低上限区域

OP 的 Refine improve rate 低、plateau 多，90% 搜索增益很早获得；来时路虽改善平均 $\Delta q$，却没有提高 improvement rate。V9.7 的同规模 OP50 测试弱于 V9，后续版本在 OP 上不同程度追回。

这与“V9.7 过早锁定一个较低上限区域”的解释相容。它也说明强局部化不是通用优势：当好算法簇稀有或初始锚定不佳时，深度只能充分开发当前区域，不能自动提高区域天花板。

### 12.4 OBP：离散评价与早饱和削弱版本差

OBP 初始最高质量存在大量平局，路线吸收更晚；多数同规模测试设置的版本差小于 1%。Landing 可以让 Explore child 局部恢复，但不稳定产生新的全局突破。固定后期 Explore 在早饱和任务上还可能变成预算耗散。

OBP 提醒我们：路线覆盖、选择干预率和着陆恢复都只是过程量。若任务的可区分质量跨度很小，它们不一定转化为可观测同规模测试差异。

## 13. 竞争解释与因果边界

### 13.1 仍然成立的竞争解释

1. **初始根质量或随机性解释。** 路线很早吸收，主路线的早期根与 bootstrap 质量可能强烈影响终局；三重复不足以完全消除这一来源。
2. **任务匹配解释。** V9.7 的强局部化可能恰好适合 TSP/CVRP，却不适合 OP；综合排名不能推出普遍最优搜索体制。
3. **联合版本混杂。** V9.6 到 V9.7、V9.7 到后续版本都同时改变多个机制。
4. **长谱系反向因果。** 好路线获得更多预算自然会更长；成功程序位于长谱系，不证明预先奖励深度会改善搜索。
5. **静态宏簇构念有限。** 宏簇切换是可审计代理，不能替代执行行为簇或人工语义标注。

### 13.2 明确不能声称的内容

- 不能声称两级 $q+s/\sqrt{n+1}$ 已证明优于单路线、均匀路线或纯质量分配；
- 不能声称路线 bonus 带来了 V9.7 的最终优势；
- 不能声称来时路单独造成 TSP 约 4% 的完整搜索提升；
- 不能声称 Explore 的 30% 比例最优，或所有 Explore child 都应获得固定发展预算；
- 不能声称 route 等于 algorithm family；
- 不能把 V9.7 的代表性平均名次第一写成无条件 SOTA。

## 14. 下一步识别顺序

V9.7 应作为冻结基座，生成与分配分开识别。

### 14.1 生成线

1. 用 ppab 批次的 24 个 run 分析中途预算 best-so-far 曲线，识别来时路单步收益转化为可达终点还是收敛速度（消融结果见 §6.4）；必要时以 200-eval 短预算同协议对照。
2. 固定锚点与 parent path，比较 Refine-only、Explore-only 和固定混合，识别两种 transition kernel 及比例作用。
3. 比较 Explore 的完整 parent path、局部路径、机制摘要和已探索区域摘要，检验来时路是否一边提供问题信息、一边锚定替代方向。
4. 对有效 Explore child 给予匹配的 0/1/3/5 步 Refine 续段，分别报告内部发展、恢复父代和产生全局突破。

### 14.2 分配线

1. 固定 V9.7 proposal，使用匹配根比较 Single/Greedy、Uniform 或 Random over $K$ routes、Adaptive allocation。
2. 先给每条路线相同强制前缀预算，建立 continuation value 的可比较观测；没有 overlap 时不训练路线价值预测器。
3. 将池效应与分配效应分开：Single 到 Uniform/Random 测多根池本身，Uniform/Random 到 Adaptive 测根据历史重分预算。
4. 锚点层比较纯质量、现行乐观项和匹配随机回访，判断 64.8% 的选择改变是否改善了有限预算前沿。

### 14.3 评价标准

每个候选机制依次报告：

1. 机制是否计算并运行；
2. 是否改变实际选择或生成分布；
3. 是否改变 best-at-budget；
4. 是否改善三重复同规模独立测试；
5. 效果是否随任务的簇稀有度、族内可改进性和跨簇恢复性变化。

干预率、路线数、树深和 Explore 份额不是优化目标。最终要识别的是：什么轨迹事实能够预测额外一份计算的边际价值，并且这种预测是否在不同任务上形成可复用的在线行为。

## 15. 机制区域重访与静态语义空间分析

对 V9.7 正式四任务三重复搜索按程序创建顺序重放，测量每次生成落在静态机制代理区域的新颖度：

### 15.1 语义空间小且早期耗尽
每 run 访问宏簇 4–6 个、不同标签组合 10–48 个，对照每任务 2,400–2,900 个 code-novel child。进入初始根之外的新宏簇每 run 2–3 次，全部发生在前 125 次评价（四任务进入时点中位数为第 4–73 次）。此后约 85% 以上的预算在已访问宏簇内运动。

### 15.2 Explore 的换簇几乎全部落在已访问宏簇

| 任务 | Explore child | 换簇率 | 换簇后落回已访问宏簇 | 标签组合重访 | 宏簇重访（全部 child） |
| --- | ---: | ---: | ---: | ---: | ---: |
| TSP | 709 | 37.2% | 98.1% | 92.2% | 99.3% |
| CVRP | 786 | 48.9% | 97.9% | 92.2% | 99.0% |
| OP | 854 | 53.9% | 99.8% | 98.7% | 99.9% |
| OBP | 845 | 36.9% | 98.4% | 97.4% | 99.4% |

Refine 参照：换簇率 2.3%–12.1%，换簇后落回已访问宏簇 98.7%–100%。

### 15.3 重入来自下方且亚前沿重入显著
- Explore child 只有 5.2%–7.4% 在出生时达到所在宏簇的当时前沿；三分之一到五分之四低于前沿超过一个 $s$。换簇目的地集中在主导家族（TSP 为 `local_score` 68%，CVRP 为 `angular_radial` 57%）。
- 无新标签的 Explore child 占总搜索响应的 23.4%–27.8%（亚前沿重入占用约四分之一预算）。
- 被放弃路线几乎没有宏簇级独有知识（12 run 中仅 3 例，吸收态没有造成宏簇知识损失）。

### 15.4 分析结论
1. **全局信息的信息量小**：每 run 4–6 个宏簇即可完整描述已访问区域及其前沿。
2. **发现事件前置且稀有**：新宏簇进入集中在初始化后前 100 余次评价，awareness 机制的设计目标是避免亚前沿重入，而非延长发现期。

## 16. 结论

V9.7 的科学价值不在于证明了复杂预算分配，而在于找到了当前最可靠的工作点：

$$
\mathrm{matched\ parent\ path}
\rightarrow
\mathrm{reliable\ local\ proposal}
\rightarrow
\mathrm{strong\ regional\ localization}
\rightarrow
\mathrm{deep\ refinement}
$$

并由少量 Explore 在同一路线内部提供结构迁移。路线层几乎没有持续估计多路线价值，锚点层却保持区域内的局部宽度；真实评价和原子更新又避免了长期信用的不可观测性。

因此，V9.7 当前支持的最强结论是：**改进来时路可以成为有效的生成条件，而一个简单、局部化、即时反馈的搜索体制能够把这种生成能力兑现成强综合结果。** 它尚未证明轨迹感知分配已经解决。下一阶段的目标是在不破坏这条深精炼主链的前提下，识别何时应继续集中、何时应重新开放，以及哪些跨簇入口值得获得有限发展机会。
