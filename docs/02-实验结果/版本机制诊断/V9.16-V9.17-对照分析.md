# TraceAAD V9.16 与 V9.17 对照分析

## 1. 核心判断

V9.17 没有形成对 V9.16 的整体升级。V9.16 在五任务、18 个 held-out 设置上的综合平均名次为 `1.900`，V9.17 Adaptive 为 `2.367`；V9.16 仍是当前更稳健的通用工作点。V9.17 的搜索 best 只在 CVRP 和 OBP 的聚合训练口径改善，在 TSP、OP 和 VRPTW 退化；held-out 的收益集中在 CVRP、OBP capacity=100 以及少数较大规模设置，不能支撑统一的性能改善。

V9.17 的研究价值在于识别出一个有条件成立的机制：对已经进入竞争集合、且短发展块仍能产生前沿增益的方向，连续投入确实可能有价值。这个信号在 CVRP 上最清楚，在 TSP200、VRPTW100/200 和 OBP capacity=100 的部分设置也兑现。它没有成为跨任务通用的 continuation value 估计器，因为正 block gain 后下一 block 继续成功的比例只有 `0.061`–`0.469`，追加 blocks 很少推进全局前沿。

V9.17 的主要问题不是自适应规则没有运行，而是它改变了搜索几何：V9.16 的宽全局竞争和固定 Explore 入口被替换为低频 Discovery、每个新方向的三步成熟、固定大小的质量竞争和以当前最好 active hypothesis 为来源的反复 Discover。结果是结构性提议数量大幅减少，来源集中度明显升高，有限预算更多用于已有假设内部的 Refine。这个形态适合需要较长族内发展的任务，却牺牲了 V9.16 在高入口价值、浅链或多条件 trade-off 任务上的覆盖能力。

因此，V9.17 应被理解为对 V9.16 搜索几何的诊断性收缩和局部机制验证：它证明了成块发展可以在特定任务兑现收益，尚未证明以 hypothesis portfolio 为中心的完整协议优于 V9.16。

## 2. 比较对象与证据口径

V9.16 与 V9.17 的整体比较包含多个机制变化，不能把两版差异归因到 Adaptive 调度一个因素。V9.17 同时引入了 hypothesis、三步 maturation、前八竞争、假设内父节点选择、Discovery 来源规则、block gain 调度，并把形成事件中的实际 Change 纳入轨迹记录。这个比较评价的是两种完整搜索几何。

V9.17 Adaptive 与 FixedCycle 是配对的单因素对照。两臂共享八个初始化根、三步初始化 maturation、冻结的 `s_R`、`K=8`、`H=3`、父节点选择、parent-path prompt、Explore 来源、bounded repair 和 `1000` 个 primary evaluator slots；唯一改变是全体 active sweep 结束后是否继续执行正 block gain 的假设。因此，这组比较可以识别 block-response 调度的作用。

所有正式搜索均按 primary evaluator slots 计数，repair evaluator calls 单独记录。两版运行均达到 `1000` 个 primary slots；额外 evaluator 调用数的差异是失败候选修复成本，不改变搜索预算比较。

## 3. 最终结果：V9.17 的改善是局部的

下表给出三次重复均值。差值为 `V9.17 Adaptive - V9.16`；TSP、CVRP、OBP、VRPTW 越低越好，OP 越高越好。负差在最小化任务上表示改善，在 OP 上表示退化。

| 任务 | 搜索 best：V9.16 -> V9.17 | 同规模 held-out 差值 | 结果形态 |
| --- | ---: | --- | --- |
| TSP | `5.847 -> 5.948` | `+0.115 / -0.097 / -0.022`（50/100/200） | 小规模退化，大规模略有改善 |
| CVRP | `8.833 -> 8.725` | `-0.086 / -0.171 / -0.131`（50/100/200） | 三个规模均改善 |
| OP | `14.865 -> 14.756` | `-0.156 / -0.527 / -1.412`（50/100/200） | 三个规模均退化 |
| OBP | `726.417 -> 725.833` | capacity=100：`-9.867 / -4.600 / -5.466`；capacity=500：`+0.067 / +0.467 / +0.133` | 修复小容量，轻微损失大容量 |
| VRPTW | `18.834 -> 19.064` | `+0.262 / -0.139 / +0.445`（50/100/200） | 只在 100 节点改善 |

按各任务指标方向，V9.17 Adaptive 在 18 个同规模设置中有 9 个改善、9 个退化。这个数量平衡掩盖了任务结构：CVRP 的改善幅度在三个规模都同向，OP 的退化也在三个规模都同向；OBP 的方向沿 capacity 分裂；VRPTW 只在中间规模出现改善。平均名次从 `1.900` 降到 `2.367`，说明局部改善没有抵消整体覆盖损失。

V9.16 的重复稳定性也更符合当前通用版本的定位。搜索 best 的三重复标准差在 TSP/CVRP/OP 中分别为 `0.038/0.016/0.020`，V9.17 Adaptive 为 `0.166/0.137/0.192`。这不是所有任务上的统一方差结论，OBP 和 VRPTW 的尺度不同；它说明自适应调度引入了更强的路径依赖，尤其放大了 TSP、CVRP 和 OP 的运行间差异。OP held-out 的标准差也从 `0.074/0.272/0.746` 增至 `0.253/0.942/3.186`，与单个运行的调度判断对最终程序影响较大相容。

### 3.1 V9.17 与 FixedCycle：调度本身有条件有效

配对结果给出了比整体版本比较更清楚的调度结论：

- **CVRP**：三个规模、三次重复共九个 held-out 单元全部由 Adaptive 更低；三次搜索 best 和 `500` slots best-at-budget 也同向。这里的 block-response 调度具有最强的完整搜索证据。
- **TSP**：TSP200 三次重复全部由 Adaptive 更低，TSP50/100 方向不一致；FixedCycle 在 `250` slots 的训练前沿三次都更快，Adaptive 在后期和大规模迁移上追回一部分收益。连续发展信号对长视界有帮助，但不能替代小规模的早期覆盖。
- **VRPTW**：VRPTW100/200 的六个 held-out 单元全部由 Adaptive 更低，VRPTW50 方向不一致。调度改善集中在中、大规模，训练 best 的方向却不稳定。
- **OBP**：`1k_100` 三次均由 Adaptive 更低；`5k_500` 和 `10k_500` 三次均由 FixedCycle 更低；其余设置方向分化或幅度很小。该结果直接呈现 capacity 条件下的不同搜索需求。
- **OP**：三种规模均出现相反方向，Adaptive rep2 在训练和三个 held-out 设置同时偏弱；正 block gain 对后续投资的区分度最低，不能形成稳定的调度收益。

这组结果支持“自适应调度依赖任务的族内可改进性和反馈视界”，不支持“正 block gain 在所有任务上都应带来更好的下一段预算”。

## 4. 搜索过程：V9.17 实际把预算投向了哪里

### 4.1 从宽入口到低频 Discovery

V9.16 的普通 Explore 每路使用 `273`–`282` 个 primary slots，固定 `0.3` 的 Explore 先验与增长型 ESS 共同形成宽入口；随机 landing 另外使用 `81`–`99` 个 Refine slots。五任务十五路合计有 `456` 个 landing ticket，使用 `1,368` 个 landing slots。V9.16 的普通 Explore 父节点在每路覆盖 `125`–`175` 个不同节点，最常用父节点只占 `2%`–`6%` 的 Explore 决策。

V9.17 Adaptive 每路只有 `23`–`31` 个 Explore/Discovery slots，Refine slots 为 `961`–`969`。它把新方向的三步 maturation 和 active portfolio 的 Development 都放在同一 primary budget 内，因此一个 Discovery 周期至少包含一次 Explore、一次三步 maturation 和一轮 active hypotheses 的发展。实际运行中 Adaptive 的平均 sweep 数为 `1.59`–`3.25`，FixedCycle 恒为 `1`；Adaptive 的 Discovery 间隔为 `30.0`–`41.3` 个 slots，FixedCycle 为 `27.6`–`27.9` 个 slots。

这是一种实质性的搜索宽度变化。V9.17 的连续 Refine 增加了局部形成视界，却同时把可尝试的结构性入口压缩了一个数量级。V9.16 的宽度来自全局节点重选，V9.17 的宽度主要由八个 active hypothesis 的竞争和其内部父节点重选决定；二者不能用同一个“探索率”概括。

### 4.2 Discovery 来源发生了集中

V9.17 的 Discovery 总是从当前质量最高的 active hypothesis frontier 发起。十五路 Adaptive 中，Discovery 来源 hypothesis 的不同数量只有 `3`–`7` 个，单一来源占全部 Discovery 的 `27%`–`87%`。例如 CVRP 一路的最高来源占 `80%`，OBP 一路占 `87%`，TSP 一路占 `52%`。

这个统计只说明 provenance 来源集中，不把 hypothesis 当作算法簇标签。它仍然揭示了一个行为事实：V9.17 的全局重开大多围绕当前最好方向反复生成，替代算法区域获得的提议机会有限。相较之下，V9.16 的 Explore 父节点分布明显更宽。若不同来源确实对应可利用的算法区域，V9.17 会错过其中一部分；若来源之间只是同一簇的轻微变体，集中本身也不能证明损失。当前工件支持“来源覆盖收缩”，尚不能把它等同于“算法簇覆盖收缩”。

### 4.3 追加发展块很多，但全局兑现很少

Adaptive 在第二及后续 sweep 中追加了 `25`–`103` 个 development blocks，中位数为 `56`。这些 blocks 中只有 `2`–`47` 个推进对应 hypothesis 的前沿，只有 `0`–`8` 个推进全局前沿。平均每路追加 `54` 个 block，但平均只有约 `17` 个推进 hypothesis frontier、约 `3` 个推进 global frontier。

按任务观察：

| 任务 | 追加 blocks（三重复） | 正 block 后下一次仍成功 | 推进 global frontier |
| --- | --- | --- | --- |
| TSP | `58 / 26 / 61` | `0.24 / 0.08 / 0.26` | `1 / 0 / 1` |
| CVRP | `72 / 81 / 103` | `0.42 / 0.47 / 0.46` | `4 / 7 / 7` |
| OP | `50 / 25 / 33` | `0.22 / 0.24 / 0.06` | `1 / 1 / 0` |
| OBP | `42 / 62 / 35` | `0.26 / 0.32 / 0.29` | `4 / 3 / 2` |
| VRPTW | `56 / 57 / 49` | `0.34 / 0.30 / 0.16` | `8 / 3 / 2` |

CVRP 同时拥有最高的追加量、最高的 block 延续成功率和较多的全局前沿推进，最终结果也最稳定地改善。TSP、OP 的追加 block 更多体现为假设内部的局部活动，难以转化为全局收益；OBP 和 VRPTW 的局部响应与跨条件泛化之间存在分化。由此可见，`g>0` 更接近“当前方向还有即时响应”，尚未达到“下一份预算应继续投给它”的强度。

## 5. V9.17 做得好的地方

### 5.1 把分配中的两个事实分开

V9.17 让 hypothesis 前沿质量 $Q$ 负责跨方向竞争，让 block gain $g$ 只负责 active hypothesis 的连续发展。历史投入、谱系深度和过去累计增益没有被重新叠加到跨 hypothesis 排名中。这遵守了 V9.15 以来形成的认识：历史 realized gain 是过程事实，不能直接充当未来 continuation value。

这种分层使每一次决定都有清楚的语义：新方向先通过三步 maturation 暴露当前可见质量，已进入竞争集合的方向再用短 block 响应决定是否追加预算。即使最终收益不稳定，过程也比把质量、历史信用和观察次数放入一个节点分数更容易解释。

### 5.2 让 delayed development 从随机干预变成可观测过程

V9.16 的 landing 证明了结构性入口有时需要连续机会，但随机 ticket 只解决“给不给机会”，没有解决“给谁机会”：`415` 个出生回撤 landing 入口中只有 `45` 个在三步内恢复来源父代，只有 `23` 个超过来源父代，landing 步没有直接产生最终最好程序。

V9.17 为每个新 hypothesis 使用统一 maturation，并记录成熟后的 $Q$、竞争线和后续 block gain。它将入口形成、成熟、竞争和发展拆成可比较事件，确实观察到了不同任务的连续发展长度，而不是把所有 delayed development 混在一个随机 landing 计数中。

### 5.3 Adaptive 调度在 CVRP 等任务上兑现了 V9.16 暴露的短板

V9.16 已显示 CVRP 的三步 landing 恢复很弱，最好谱系需要更长的局部形成过程。V9.17 Adaptive 在 CVRP 上让成功方向连续获得更多 blocks，三次正 block 后续成功率保持在 `0.42`–`0.47`，并在搜索和全部 held-out 规模上改善。这个结果与“CVRP 具有较高族内可改进性，需要更长发展视界”的研究认识一致。

TSP200、VRPTW100/200 和 OBP capacity=100 的配对改善进一步说明，成块发展不是只对单一任务偶然有效；当跨规模收益依赖成熟后的持续修正时，Adaptive 能比 FixedCycle 保留更多有效发展机会。

### 5.4 配对实验本身具有较好的因果识别质量

Adaptive 与 FixedCycle 从首次 Development 决策前的共享 checkpoint 分叉，保留了相同初始化、随机状态和 primary budget。过程量预先覆盖了 block 延续、Discovery 间隔、前沿推进和预算集中度，最终结果同时报告中期 best-at-budget、搜索 best 和 held-out。这个设计足以回答“block-response 调度是否在 V9.17 状态下改变搜索行为及任务结果”，也避免把 V9.17 的联合结果直接归因于调度器。

## 6. V9.17 没有解决的问题

### 6.1 入口覆盖被压缩，牺牲了 V9.16 的强项

V9.16 的优势来自宽全局竞争、当前质量驱动的即时重选和有限的 landing；它在 OP、VRPTW 以及 OBP capacity=500 等设置上能够持续找到新的高质量入口。V9.17 把 Explore 变成停滞后的 Discovery，并让每个有效新 hypothesis 都承担三步 maturation 成本。相同预算下，V9.17 只能尝试约三十个 Discovery，且多数来自少数当前最好来源。

OP 的结果最直接地显示了这一损失：V9.16 三个规模均强，V9.17 Adaptive 的训练 best 和三个 held-out 规模均下降；正 block 后续成功率最低的运行只有 `0.06`，说明连续投资判断没有提供足够的未来信息，却延迟了新的高上限入口。

OBP capacity=100 的改善与 capacity=500 的损失也说明入口与发展之间存在条件 trade-off。V9.17 在一个容量条件中弥补了 V9.16 的短板，同时削弱了 V9.16 已经较强的另一组条件。聚合质量 $q$ 与单一竞争线无法表达这种条件差异。

### 6.2 三步 block gain 仍然是短期响应，不是 continuation value

V9.17 的二值规则只问 block 末端是否超过该 hypothesis 之前的 frontier。它没有使用增益幅度、连续改善的稳定性、相对竞争线的距离、入口出生折损或跨实例一致性。即使某个 block 为正，下一 block 仍然很可能不再推进；全体追加 blocks 中大量只改善 hypothesis 内部，极少刷新 global frontier。

这个信号边界与既有认识一致：局部突破是入口的即时响应，不是高质量算法簇的身份证明；固定视界内的恢复也不等于长期前沿形成。V9.17 将 $g>0$ 直接作为下一 sweep 的资格，仍然把测量信号和投资决策压缩在同一个短视界中。

### 6.3 hypothesis 是可审计的投资单位，不是算法簇

V9.17 的 hypothesis 由一个 Explore child 开启，Refine 后代继承 ID。它很好地记录了“从哪里开始的一段发展”，却不保证同一 hypothesis 内始终保持同一算法机制，也不保证不同 hypothesis 属于不同算法簇。Discovery 来源集中因此只能解释为来源集中，不能直接解释为算法空间覆盖率下降。

这保留了 TraceAAD 当前最重要的科学边界：树、entry、route 和 hypothesis 都是 provenance unit。真正的算法簇需要由算法行为轨迹或语义机制定义，并检验其对固定视界发展和 held-out 的预测能力。V9.17 没有完成这一步，也不应从 active/reserve 状态直接推出簇价值。

### 6.4 固定 $K=8$ 与 $H=3$ 仍是强先验

三步 maturation 使新方向可比较，但也把延迟收益限制在固定视界内；八个 active capacity 使竞争可控，但把低于竞争线的方向置于 reserve 后不再获得常规预算。CVRP 的结果表明长发展在某些任务上确实需要更多机会，OP 的结果则表明同样的机会会挤压高价值入口。当前证据支持任务依赖，尚不足以选择一个跨任务固定的 $K$、$H$ 或竞争线规则。

## 7. 按任务回看 V9.16 与 V9.17

### 7.1 TSP：方向正确，但入口与长发展尚未同时满足

TSP 的既有证据指向“全局竞争后进行深、稳定的局部发展”。V9.17 Adaptive 在 TSP200 的三次 held-out 配对中都优于 FixedCycle，也略优于 V9.16；这说明成块发展确实帮助较大规模的形成过程。但 TSP50 退化，训练 best 低于 V9.16，Adaptive 的正 block 后续成功率在一个重复中只有 `0.08`，说明当前信号无法稳定识别真正值得长投的谱系。

V9.14 仍是 TSP 的强工作点，表明 TSP 需要更深的有效谱系。V9.17 已经减少了 V9.16 的宽度，却没有形成足够稳定的深发展，结果落在两种几何之间。

### 7.2 CVRP：V9.17 最清楚的成功

CVRP 是 V9.16 的主要短板，也是 V9.17 最有说服力的改善。Adaptive 三次均形成较多追加 blocks，正 block 后续成功率最高，且追加 blocks 推进 global frontier 的数量为 `4/7/7`。搜索、CVRP50/100/200 held-out 均改善，Adaptive 与 FixedCycle 的九个 held-out 配对也全部同向。

这组证据支持成块发展的条件性价值：CVRP 的高质量方向需要连续局部修正，短期响应能够在一定程度上预示下一段发展收益。它没有证明 `g` 是一般 continuation value，也没有说明当前的 Discovery 来源和 `K/H` 已经最优。

### 7.3 OP：宽入口仍是主要杠杆

OP 的高质量算法区域具有较高入口价值，进入后通常用浅到中等链即可形成竞争力。V9.16 的宽竞争在三个规模都强，V9.17 的低频 Discovery 和局部续投则在三个规模退化。OP 的正 block 后续成功率低，追加 blocks 很少推进 global frontier，说明 V9.17 把预算放在了不能持续产生有效前沿的方向上。

### 7.4 OBP：容量条件揭示聚合质量的盲区

V9.16 已经显示 OBP capacity=100 与 capacity=500 的搜索几何不同。V9.17 Adaptive 在 capacity=100 上稳定改善，在 capacity=500 上轻微退化；FixedCycle 也呈现相同的容量方向分化。自适应调度能够改变预算节奏，却没有观察到容量条件下的行为向量，因此只能在部分条件上碰巧匹配正确的搜索几何。

### 7.5 VRPTW：中间规模受益，整体仍未超过 V9.16

V9.16 在 VRPTW50/200 取得更强结果，表现为宽入口与中等深度共同兑现。V9.17 Adaptive 只在 VRPTW100 超过 V9.16，但相对 FixedCycle 在 VRPTW100/200 均稳定更好。这里的调度信号有局部价值，却没有替代 V9.16 对入口覆盖和形成深度的组合。

## 8. 研究认识

V9.16 和 V9.17 共同把 TraceAAD 的两个核心机制边界刻画得更清楚：

1. **轨迹条件生成负责制造可达的算法区域。** Parent path、Refine/Explore 意图和 repair 影响提议分布；如果入口覆盖不足，分配器没有足够异质性可以兑现。
2. **轨迹感知分配负责在有限预算中决定继续哪里。** 当前质量可以支持竞争，短期 block 响应可以提供局部续投线索；二者都不能单独代表长期算法簇价值。
3. **搜索宽度、Explore 率、反馈视界和承诺方式是四个不同变量。** V9.16 的宽 ESS 与 `0.3` Explore 共同提供覆盖，landing 只占少量连续预算；V9.17 的 block policy 增加了反馈视界，却同时降低了入口率和来源宽度。
4. **任务泛化来自搜索几何与任务结构的匹配。** CVRP 的族内可改进性使 Adaptive 续投兑现；OP 的高入口价值使低频 Discovery 受损；OBP 的容量条件说明聚合质量不足以表达行为 trade-off；TSP 和 VRPTW 需要在入口覆盖与长发展之间保留不同程度的组合。

从这个角度看，V9.17 的负面结果具有明确的科学含义：把“成功了一小段”当作“继续投资”能够识别一部分深发展任务，却会把有限预算从新区域发现中抽走。V9.17 证明了分配需要反馈视界，同时也证明反馈视界必须与入口覆盖、来源异质性和任务条件共同判断。

## 9. 对照结论

V9.16 仍应作为当前综合基线和主要工作点：它的宽全局竞争、纯当前质量分配、轨迹条件 Refine/Explore 和有限 landing 组合，在五任务上取得了更高的综合排名和更强的重复稳定性。

V9.17 的有效部分应保留为一个条件性认识：当某个方向具有较高的族内可改进性，且短发展块的响应能够重复出现时，成块连续 Refine 可以显著提高有限预算的兑现率。CVRP 是目前最完整的证据，TSP200、VRPTW100/200 和 OBP capacity=100 提供了任务或规模受限的支持。

V9.17 的不足集中在三个机制环节：Discovery 频率和来源覆盖过低，成熟后的质量竞争对延迟价值仍然过早，`g>0` 对下一段投资的预测力不足。后续机制应把 V9.17 的 block response 当作局部发展观测，与 V9.16 的全局入口覆盖保持可比较的预算关系；不能继续把单一短期增益直接升级为跨任务的长期信用。

完整结果数值见实验结果，V9.16 的机制背景见V9.16 机制诊断，V9.17 的配对过程量与结果见自适应调度单因素消融。下一步不沿着 V9.17 继续增加状态，而是回到轨迹如何改变生成与预算机会这两个原始接口。

## 10. 重新界定两个问题

当前需要把两个问题重新分开。预算分配是每次评价前衡量所有锚点的价值，选择一个锚点并支付一次 LLM 生成和一次 evaluator 预算；landing 是对延迟发展的测量或保护干预，它把一个已经选中的新边界暂时绑定到后续步骤，不能代表锚点级预算分配。

因此，V9.16 的核心循环应明确为：

````text
score every anchor
    -> select one anchor
    -> choose one operator
    -> generate one Idea + Code
    -> evaluate once
    -> update trajectory facts and scores
````

每个决策只启动一个 transition，响应完成后立即重算。landing 可以作为独立的 continuation probe 报告，但不再作为 V9.16 分配机制的定义。这样才能回答“哪个锚点值得下一次投入”，而不是“已经进入某个 landing 后要不要再执行几步”。

### 10.1 锚点价值的语义

锚点不是一份孤立代码，而是“当前程序 + 走到这里的形成路径”。下一次预算的价值应写成一个当前可观测的下一步机会分数：

$$
S_t(a)=q_t(a)+\lambda_T \sigma_q T_t(a).
$$

其中 q 仍是跨锚点竞争的主轴，$\sigma_q$ 是在运行前固定的任务质量尺度，T_t(a) 是从该锚点来时路中读出的、经过时间衰减和截断的轨迹效用。$\sigma_q$ 可以来自初始化质量池的预先规定稳健尺度；它不应在搜索中通过额外 primary budget 在线估计。$\lambda_T$ 和轨迹项上限在运行前固定，不做在线调参。这个分数不是长期 continuation value，也不是算法簇价值；它只表达“在当前状态下，从这个具体锚点再发起一次生成，轨迹证据是否值得给它更多机会”。

理想的锚点值应接近下一次原子响应的条件期望，但有限搜索无法为每个新锚点稳定估计这个量。第一版不假装解决这个预测问题，而是用 q 加一个有界、可重算的轨迹状态项，先检验轨迹信息是否能改善预算路由。

T_t(a) 的第一版应只使用选择时已经存在的直接事实：

| 轨迹量 | 读取的事实 | 分数中的作用 |
| --- | --- | --- |
| D_t(a) | 最近形成事件的直接 improve/plateau/regress 与全局 best 刷新，按路径距离衰减 | 近期轨迹是否仍能产生有效响应 |
| C_t(a) | 当前节点相对最近较好祖先的有限回撤，以及已经尝试的 Refine 次数 | 这是一个可修复的非单调状态，给一次机会，不把退步当成奖励 |
| U_t(a) | 该锚点已获得的原子预算次数 | 只用于保持未充分观察锚点的概率尾部，不形成永久信用 |

可将前两项合成为：

$$
T_t(a)=\operatorname{clip}\left(D_t(a)+\kappa C_t(a),-1,1\right).
$$

D_t 是最近窗口中直接形成事件的衰减加权结果，C_t 由当前路径事实即时计算并随 Refine 尝试衰减。这里把“轨迹展示价值”操作化为：这条来时路在最近的直接生成中是否持续提供了可利用的响应状态，而不是展示了多少文字或代码字段。U_t 第一轮不直接加到质量分数，而由对 S_t 的 Boltzmann/ESS 抽样提供非零尾部；这样不会重演 V9.9 中由固定几何秩造成的静态分配形状。

这里有三个重要约束：

1. 轨迹效用只从当前锚点的形成路径和直接尝试重算，不把后代成功回传到祖先，也不维护需要未来访问才能结算的 pending 后验。
2. T_t 有界，且其最大影响不超过预先设定的一步质量尺度；低质量锚点不能凭借“在低水平内卷中频繁改善”压过明显更好的当前程序。
3. C_t 是分数中的状态项，不是 landing ticket，也不保留后续三次预算。每次选中后只支付一个原子预算，下一次是否再选由更新后的 S_t 决定。

这比单纯使用 q 多读了一层轨迹价值，又没有把历史实现收益包装成长期信用。它还保留了 V9.1、V9.2、V9.10 的失败教训：不使用路线推进率作为独立奖励，不把子代质量平均倒灌进锚点，不为每个锚点维护稀疏且右删失的独立后验。

严格的“展示价值”其实是一个 operator-conditioned 反事实量：

$$
V_{\mathrm{show}}(a,o)=
\mathbb{E}[q(x')\mid x_a,h_a,o]
-
\mathbb{E}[q(x')\mid x_a,\varnothing,o].
$$

它比较同一个当前程序在展示与不展示该来时路时的下一步生成质量。普通完整搜索只观察其中一个条件，不能直接把这个因果差异写进在线分数。因而 T_t 只是由直接响应构成的可审计代理；是否真的代表上下文价值，仍需固定锚点的 History 对照验证。该对照应按 Refine/Explore 分开，因为已有证据不支持同一历史对两个 operator 具有相同效应。

### 10.2 分配协议

第一版分配实验应保持 V9.16 的树、初始化、错误处理、模型和预算口径，只替换普通锚点评分：

| 实验臂 | 普通锚点评分 | landing | 目的 |
| --- | --- | --- | --- |
| q-atomic | 当前 q | 关闭 | 建立纯原子质量分配基线 |
| trajectory-score | q + bounded trajectory utility | 关闭 | 检验轨迹效用是否改变锚点选择和有限预算结果 |
| q + landing | 当前 V9.16 协议 | 保留为独立诊断 | 评价 landing 的延迟发展干预，不把它当分配器 |

trajectory-score 每次用相同的 target ESS 规则从 S_t(a) 抽样一个锚点。抽样完成后只生成一个候选；有效、无效、修复和回撤都立即写入事实并影响下一次分数。比较首先报告选择几何和过程响应，再报告 best-at-budget、搜索 best 与 held-out。

q-atomic 是必要的控制，不是对 V9.16 综合结果的否定。它把 landing 从预算分配中拿掉，才能识别评分机制本身是否改变了“下一次从哪里继续”。

## 11. 重新设计生成算子：从提示附加转向全局诊断算子

生成侧当前真正的缺口不是缺少一项代码差分，而是 Refine/Explore 只有两端意图，且两者共享同一套局部上下文。已有证据支持 Refine 的来时路条件，但 Explore 共享完整 parent path 可能受到原方向锚定；V9.13 的全局机制标签又曾导致跨区域盲目重写和有效率下降。因此，下一步应改造算子契约，而不是继续向历史事件中塞更多字段。

### 11.1 ReflectiveExplore 的最小语义

保留 Refine 作为局部发展算子，把当前 Explore 槽位改成一个受约束的 ReflectiveExplore：

| 算子 | 主要问题 | 可见上下文 | 期望输出 |
| --- | --- | --- | --- |
| Refine | 当前锚点怎样沿已有方向继续变好 | 当前完整代码、局部 parent path、真实结果 | 一个聚焦的局部修改和完整程序 |
| ReflectiveExplore | 从全局搜索事实看，当前问题还有哪个未解决瓶颈或未覆盖方向 | 当前锚点代码、任务说明、全局搜索板、必要的局部路径 | 一条全局诊断、一条可检验 Idea 和完整程序 |

全局搜索板不展示所有代码，也不让模型自行编造全局总结。它由真实工件压缩出：

- 当前 global best 与 best-at-budget 的最近变化；
- 按质量和轨迹状态挑选的少量代表锚点；
- 每个代表锚点的当前质量、最近直接响应、最近使用的算子和是否处于回撤状态；
- 最近被验证的成功方向、停滞方向和失败/无效比例；
- 当前搜索覆盖与重复选择的简单统计。

ReflectiveExplore 的一次 LLM 响应仍然只产生一个候选，输出契约保持为：

````text
Diagnosis: <one evidence-based bottleneck>
Idea: <one testable design change>
Code:
```python
<complete executable program>
```
````

Diagnosis 是生成上下文和审计记录，不是新的奖励，也不参与锚点评分。模型不能只返回反思文字；没有完整程序就按普通无效候选处理。这样吸收了“全局反思”想法，同时避开 V5 中自由文本反思和结构化 Action 无法稳定执行的失败。

### 11.2 为什么反思应当是算子而不是独立预算阶段

全局反思若单独占用一个调用，再把反思结果交给另一个调用生成代码，会把一次预算拆成两个不可比较的动作，并重新引入 pending 状态。把诊断和实现放在同一个 ReflectiveExplore 响应中，有三个好处：

1. 每个 primary evaluator slot 仍对应一个完整候选；
2. 反思是否真正转化为算法改变可以由真实 evaluator 直接检验；
3. 反思文本不需要被当作可执行 DSL 解析，失败只在候选层可见。

第一版不建立长期 global reflection memory。每次 ReflectiveExplore 读取当前搜索板并一次性作出诊断；若这一算子在固定锚点上显示清晰行为收益，再研究周期性持久化反思。持久化记忆必须有版本、来源和失效时间，不能让一次错误诊断永久污染所有锚点。

### 11.3 算子节律

为隔离算子效果，第一轮让 ReflectiveExplore 直接替换原来的 Explore 槽位，保持 Refine=0.7、ReflectiveExplore=0.3。不同时改变锚点评分、温度、landing 或全局停滞触发。锚点评分仍是单层的 aggregate score，不把稀疏的 anchor × operator 组合扩成独立 bandit 臂；算子条件统计只在固定锚点探针中作为解释量。后续若过程证据显示全局诊断只在停滞时有效，再测试预先规定的稀疏触发规则；当前不把“每次停滞都反思”写成新的阶段控制器。

## 12. 两个单因素实验

### 12.1 V9.16-S：轨迹效用评分

固定生成协议为当前 V9.16 的 Refine/Explore，关闭 landing，比较 q-atomic 与 trajectory-score。同一 task × repeat 使用配对初始化、seed、模型、错误处理和 1000 个 primary evaluator slots。

重点过程量：

- 锚点选择熵、top-k 质量和轨迹状态的预算份额；
- T_t(a) 的激活范围、实际改变选择的比例和与下一次直接响应的关系；
- 低质量局部改善是否被质量主项抑制；
- 回撤状态、最近突破状态和普通状态的后续单步改善率；
- 100/250/500/750/1000 slots 的 best-at-budget、搜索 best 和 held-out。

过程相关性只能证明分数读取了轨迹事实，不能证明分数已经估计了长期算法簇价值。最终判断仍以配对搜索和 held-out 为准。

若要把“展示来时路本身的价值”更直接地纳入分数，应先用固定锚点的 History 对照估计一个跨锚点的上下文效应，再把它作为轨迹项的全局先验或尺度。不能在 1000-slot 搜索中同时为每个锚点学习自己的展示效应，否则会重现 V9.10 的稀疏重访和右删失问题。

### 12.2 V9.16-R：全局诊断算子

固定锚点评分和普通原子分配，先做固定锚点的 Explore 对 ReflectiveExplore 单步生成对照。当前代码、任务、抽样条件和锚点集合保持一致；全局搜索板由同一批冻结的过程事实构成。

若单步层面显示反思算子确实改变了提议方向、有效率或质量，再做完整搜索。完整搜索中只替换 Explore 的生成契约，报告反思调用的解析率、候选有效率、修改尺度、全局 breakthrough 份额、best-at-budget 和 held-out。不得把“模型写出更长诊断”当成算子成功。

### 12.3 联合版本

只有 V9.16-S 和 V9.16-R 各自在直接证据层成立后，才做联合版本。联合版本评价“轨迹评分选择哪里 + 反思算子怎么走”的整体行为，不把联合差异重新归因给 T 或 ReflectiveExplore 单项。

## 13. 当前不应加入的内容

- 把 landing 的连续步数当作预算分配器，或用固定三步替代锚点评分；
- 用历史累计 gain、子树最好值、谱系深度或后代成功构造永久信用；
- 为每个锚点建立独立 Thompson 后验；V9.10 已显示在有限预算和稀疏重访下会产生严重右删失；
- 把路线、hypothesis 或算法簇作为新的在线信用容器；
- 让全局反思只输出文字、JSON/DSL 动作或未经 evaluator 验证的全局规则；
- 把跨区域机制标签直接塞进 Explore 提示；V9.13 的有效率风险说明全局信息必须先经过受控压缩；
- 同时改变评分、算子、landing 和 Explore 比例。

## 14. 修订后的研究认识

V9.16 的微调目标不是“让轨迹出现得更多”，而是让轨迹在两个正确的接口上发挥作用：

1. 分配接口：轨迹事实进入锚点评分，决定下一次一个原子 LLM 预算从哪里开始；分数随每次响应更新，不承诺未来预算。
2. 生成接口：轨迹被组织成算子所需的上下文。Refine 读取局部形成路径，ReflectiveExplore 读取由事实压缩出的全局搜索板；算子决定如何把这些信息转成一次具体修改。
3. 评价接口：真实 evaluator 仍是唯一质量来源，反思、轨迹标签和搜索板只能改变提议分布，不能替代目标函数。

这形成一个比 landing 更准确的闭环：

$$
\text{trajectory facts}
\rightarrow
\text{anchor score}
\rightarrow
\text{one atomic budget}
\rightarrow
\text{operator-conditioned generation}
\rightarrow
\text{real evaluation}
\rightarrow
\text{score update}.
$$

轨迹的“价值”在这里有明确的操作含义：它既不是一段需要无条件展示的文字，也不是事后成功的信用，而是能够改变下一次锚点选择和算子提议的、可重算的状态证据。

本节中的 `D/C/U` 分解是 V9.16 之后的探索性草案，不是最终在线协议。V9.18 将其进一步收缩为近期形成响应 `F` 与边界再选择机会 `B` 两项，删除直接访问奖励和多重信用，具体定义见TraceAAD V9.18 完整机制设计。

## 15. 当前建议

这里的“下一版 V9.16”是本分析形成时的过渡性称呼，现已由 V9.18 设计取代。正式下一步应按以下顺序实现两个正交、可单独验证的改变：

- 先做锚点级轨迹状态评分：以当前质量为主，使用近期形成响应和有界软 landing 机会，保持一次选择一次生成一次评价；
- 再做 ReflectiveExplore 算子：用全局事实搜索板帮助模型诊断未解决瓶颈，并在同一次响应中输出完整候选。

landing 继续作为历史延迟发展诊断，不再承担在线预算分配角色。代码形成细节可以继续作为审计事实保存，但不作为默认生成主线。所有新分数和反思收益都仍是待验证主张，必须由过程激活、配对搜索曲线和完成的 held-out 共同支持。
