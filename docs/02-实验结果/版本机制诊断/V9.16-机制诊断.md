# TraceAAD V9.16 机制诊断

## 1. 核心判断

V9.16 是当前五任务综合表现最强的 TraceAAD 版本之一，但它没有形成五任务统一占优。它在 TSP、OP 和 VRPTW 上表现强，在 CVRP 上没有追回 V9.7，在 OBP 上又分成 capacity=100 偏弱、capacity=500 强的两种表现。与五个外部对照同场时，全部 18 个 held-out 设置上的平均名次为 `1.750`，列六方法第 1；这一压缩排名不能替代任务级方向。

V9.16 真正主导搜索行为的是**纯质量打分下的宽概率采样**。普通父节点虽然只用当前质量 `q` 打分，`ESS=max(0.1N,2)` 却使有效采样宽度随节点池线性增长；运行后期每次选择的 ESS 已接近 95–97，每路运行实际选过 196–335 个不同父节点。V9.16 因而不是质量贪心，而是以质量排序的、随树增长不断扩宽的全局搜索。

三步 landing 确实运行，也确认了一个真实问题：Explore child 一旦出生回撤，普通 `q` 分配几乎不给它后续机会。然而随机三步承诺的选择精度较低。五任务共有 456 次 landing、消耗 1,368 个 primary slots；415 个出生回撤入口中，只有 45 个在三步内曾恢复来源父代，只有 23 个曾超过来源父代。15 个最终最好程序没有一个由 landing 步直接生成。当前工件中又没有同 proposal protocol 的 `q baseline`，因此 V9.16 只能支持“landing 被激活并揭示了延迟发展机会”，不能支持“landing 改善了最终搜索”的净效应判断。

V9.7 与 V9.16 体现的是两种不同的有限预算先验：

- V9.7 很早选择一个 provenance 区域，随后在该区域内保持锚点回访和深精炼；
- V9.16 让全树节点持续竞争，把预算分散到不断增长的高质量候选集合，再给随机 Explore 入口一次很短的局部承诺。

这不是同一条探索—利用轴上的两个系数。二者对**投资单位、分配宽度、反馈视界和承诺时长**的定义都不同。V9.7 适合“早期已进入有价值区域，区域内还能长期发展”的情形；V9.16 适合“高质量方向可由较宽提议覆盖发现，短链即可形成竞争力”的情形。任务无法统一泛化，主要来自方法的固定搜索几何与任务实际提议几何之间的匹配差异。

V9.17 可以融合两者，但融合对象应是两种行为：**有界的全局重开**与**成块的区域发展**。直接把 V9.7 的 bonus、V9.15 的轨迹奖励和 V9.16 的 landing 相加，会重新混合当前质量、历史事实与未来价值。更有识别力的 V9.17 应维持一个固定大小的 active-entry portfolio，在 entry 之间保留重开，在 entry 内用短 Refine block 形成可观测、可重复的局部发展响应，并在 block 结束后立即重选。

## 2. 五任务结果事实

正式 held-out 每个单元格均为三次独立运行的均值。TSP、CVRP、OBP 和 VRPTW 越低越好，OP 越高越好。完整数值（搜索集 best 与全部 held-out 规模）见实验结果。

- **OBP**：capacity=100 与 capacity=500 方向分裂。V9.16 在前者落后于 V9.7/V9.15，在后者取得最好或并列最好结果。OBP 不能再用单一“任务画像”概括。

### 2.2 与五个外部对照的关系

- TSP 三个规模上，V9.16 均好于 EoH、ReEvo、MCTS-AHD、PathWise 和 CALM (w/o GRPO)。
- CVRP50/100 上，V9.16 落后于 EoH 与 MCTS-AHD；CVRP200 落后于 MCTS-AHD，优于其余四个外部对照。
- OP 三个规模上，V9.16 均好于五个外部对照；OP50 为当前结果表最佳均值，OP100/200 仍低于内部版本 V5。
- OBP 的外部相对位置随 capacity 改变。capacity=500 的三列均为最好或优于全部外部对照，capacity=100 的三列只处于中游。
- VRPTW50/100/200 上，V9.16 均为七个参跑方法中的最佳均值。

因此，V9.16 的综合排名来自 TSP、OP、VRPTW 与 OBP capacity=500 的共同贡献。CVRP 和 OBP capacity=100 仍是方法的主要短板。

### 2.3 best-at-budget 揭示的时间结构

四个已有完整版本的逐评价曲线显示：

- TSP 中 V9.16 在 `100/250/500` 评价均落后于 V9.14/V9.15，后期仍未追回 V9.14；
- CVRP 中 V9.16 前 100 评价领先近期版本，但 V9.7 在后期持续改善并取得最好终局；
- OP 中 V9.16 从约 250 评价起保持领先，终局 search best 为 14.865333；
- OBP 中 V9.16 在 250 评价后持续落后于 V9.7/V9.15，终局为 726.417；
- VRPTW 中 V9.16 在 500 评价时仍落后于 V9.14，约 750 评价后反超，终局为 18.834263。

这些反转说明“前 100 次谁进步更快”不能直接决定后续预算。CVRP 的 V9.7 与 VRPTW 的 V9.16 都需要较长视界才显出优势；V9.17 若采用策略级 racing，必须保留非零预算下限和周期性重新比较，不能用一次早期胜负永久淘汰一种搜索体制。

## 3. V9.7 到 V9.16 的本质变化

| 版本 | 搜索状态 | 普通预算分配 | 长期运行形态 | Explore / Refine | 轨迹提示 |
| --- | --- | --- | --- | --- | --- |
| V9.7 | 8 路森林、route、anchor、attempt | route 与 anchor 两层确定性 `q + s/sqrt(n+1)` | 很早锁定一条 route，在 route 内持续锚点搜索 | 固定 0.3 / 0.7 | `Idea + actual Change + Result + Fitness` |
| V9.14 | 单父 Algorithm 树 | 全树确定性 `q + 1/sqrt(c+1)` | 全局竞争后形成很深的最好谱系 | 固定 0.3 / 0.7 | `Idea + Result/Fitness` |
| V9.15 | 单父 Algorithm 树 | `q+B+C_traj` 经目标 10% ESS 采样 | 宽概率采样、短谱系、更多换向 | 停滞驱动，实际约 35%–37% Explore | `Idea + Result/Fitness`，带修复 |
| V9.16 | 单父 Algorithm 树与 entry 记录 | 纯 `q` 经目标 10% ESS 采样；随机入口三步 landing | 宽概率采样 + 少量连续 Refine | 普通决策固定 0.3 / 0.7；landing 使总 Explore 约 28% | `Idea + Result/Fitness`，带修复 |

### 3.1 V9.7：强局部化中的深精炼

V9.7 的 route bonus 只改变 1.07% 的路线选择，TSP/CVRP/OP 的顶 route 获得 99.4%–100% 预算。其真实形态是早期 provenance gate 之后的 route 内 anchor search。anchor bonus 改变 64.8% 的选择，因此局部区域内仍有较宽的锚点回访。这个体制形成长谱系，并允许少量 Explore 在主 route 内改变算法机制区域。

V9.7 的优势不是“路线层已经学会了任务”。大量路线只得到 root + bootstrap，潜力被右删失。它的有效行为是**有限区域内的信息充分、即时反馈和持续精炼**。CVRP 的高 Refine improve rate 与长形成链最符合这一行为；OP 则显示同一局部化可能锁进较低上限区域。

### 3.2 V9.16：质量排序下的增长型宽度

V9.16 删除 `B` 与 `C_traj` 后，在线分数只读真实质量。这恢复了事实与信用的边界，却没有恢复 V9.7/V9.14 的深度，因为父节点选择仍沿用 V9.15 的 ESS 采样。

目标 `ESS=0.1N` 维持的是**相对宽度**。当树增长到约 970 个有效节点时，一次选择的有效支持接近 97 个节点。五任务每路运行最终选过 196–335 个不同父节点，单个最常用父节点只占约 1.6%–5.2% 的普通决策。V9.16 的最好谱系深度为：

| 任务 | 三次最好谱系深度 | V9.15 平均深度 | V9.14 平均深度 |
| --- | --- | ---: | ---: |
| TSP | 15 / 16 / 19 | 13.3 | 约 77 |
| CVRP | 41 / 29 / 36 | 22.3 | 约 115 |
| OP | 11 / 6 / 11 | 15.7 | 约 95 |
| OBP | 19 / 17 / 6 | 14.3 | 约 47 |
| VRPTW | 24 / 14 / 16 | — | — |

V9.16 在 TSP/CVRP 上相对 V9.15 恢复了一部分深度，但仍远低于 V9.14。它在 OP 上反而以 6–11 步的浅谱系取得最好结果。谱系深度不是目标变量；这些数字说明不同任务兑现高质量算法所需的搜索形态不同。

### 3.3 生成上下文也发生了变化

V9.7 的父代来时路包含模型声明的 Idea、父子代码实际差异、结果方向和 fitness。V9.14–V9.16 的历史只保留 Idea 与 Result/Fitness。两者都使用最近 8 条父链事实，Refine/Explore 指令文本也基本相同，但 V9.16 中模型看不到 actual Change。

固定锚点证据支持的是包含真实形成事实的 parent path 对 Refine 的单步价值。V9.16 的简化历史没有独立消融。CVRP 的最好谱系包含多次引入、回撤与参数修正；在这种形成过程中，模型声明的 Idea 可能与实际代码变化错位，缺少 actual Change 会削弱历史的可用性。因此 V9.7 与 V9.16 的任务差异不能全部归因到分配，轨迹表示也是一个未匹配因素。

### 3.4 repair 已成为第三种生成操作

V9.16 为一次失败候选提供最多两次带完整错误反馈的修复。15 路运行共使用 15,000 个 primary slots，却实际调用 evaluator 16,175 次；1,175 次额外调用来自 repair。929 个 initial attempt 失败，其中 810 个经修复后形成有效 child。

| 任务 | 三路额外 evaluator 调用 | initial 失败 | 修复成功 | 最终失败 slot |
| --- | ---: | ---: | ---: | ---: |
| TSP | 765 | 577 | 486 | 91 |
| CVRP | 161 | 137 | 124 | 13 |
| OP | 76 | 67 | 62 | 5 |
| OBP | 53 | 48 | 48 | 0 |
| VRPTW | 120 | 100 | 90 | 10 |

repair 读取 evaluator 错误、再次调用 LLM 与 evaluator，并能把失败 proposal 修成新节点；它是附着在 primary candidate 上的 failure-conditioned generation。TSP 每三路的 repair evaluator calls 最多，说明不同任务产生有效程序所需的生成成本不同。

正式搜索预算仍是每路 1000 个 primary evaluator slots。repair evaluator calls 与 LLM calls 是独立成本量，单独报告，不改变搜索质量比较的 primary budget 口径。

## 4. 哪些机制已经 work

### 4.1 轨迹条件 Refine 与 Explore 的角色仍然成立

既有固定锚点证据表明，parent path 能改善 Refine 的单步生成，Refine 与 Explore 也确实产生不同的 proposal behavior。V9.16 的 15 个最终最好程序中，13 个由 Refine 生成，2 个由 Explore 生成；TSP、CVRP、OP 与 VRPTW 的最好谱系末段普遍由连续 Refine 完成。V9.16 因而继续呈现“结构入口 + 后续精炼”的总体分工。

这一判断来自既有受控实验与 V9.16 描述性谱系的共同支持。V9.16 没有重新隔离 parent path 或 operator，因此它不增加二者的单组件因果效应估计。

### 4.2 去掉错误轨迹信用是有效修正

V9.15 的 `C_traj` 在 71%–92% 的候选上非零，并改变 31%–76% 的父节点排序；它把祖先已实现增益当作未来边际价值。V9.16 删除 `C_traj/B` 后，CVRP 三个规模相对 V9.15 改善 2.4%–3.4%，OP 保持强势，VRPTW 形成当前最佳结果。

联合版本差异仍包含固定 Explore 率、landing 和 repair，因而不能把数值全部归因到删除 `C_traj`。机制层可以确认的是：V9.16 不再让低质量但历史易改善的谱系依靠祖先斜率广泛改写父节点排序，在线信用重新由当前真实质量承担。

### 4.3 全局宽竞争对 OP 与 VRPTW 有价值

OP 的三个最终最好谱系只有 6–11 步，V9.16 在约 250 评价后持续领先；相对强局部化的 V9.7，跨规模改善随规模增加。这个形态与“OP 的高质量算法区域需要更多全局入口覆盖，进入后不需要极长精炼链”相容。

VRPTW 的 V9.16 在 750 评价后超过 V9.14，三次最好谱系为 14–24 步。它显示较宽入口覆盖与中等深度发展可以在后期兑现。由于 VRPTW 没有 V9.7 和 `q baseline` 对照，这里只评价 V9.16 联合体制。

### 4.4 repair 能把大量失败 proposal 转为有效算法

五任务 929 个 initial failure 中有 810 个被修复，说明完整错误反馈与有界修复具有明确的有效性恢复作用。这个能力尤其影响 TSP：三路共修复 486 个 slot。该数字说明 proposal 被转化为有效程序，不说明 repair 提高了最终搜索质量。

## 5. 哪些机制还不 work

### 5.1 随机三步 landing 只解决了“给机会”，没有解决“给谁机会”

V9.16 的 landing 过程量为：

- 456 次 ticket 命中，共 1,368 个 slot，占初始化后预算的 9.19%；
- 1,364 个 landing 步形成有效 child，585 步严格优于各自直接父节点；
- 415 个 ticketed Explore 入口出生时低于来源父代，占 91.0%；
- 其中 45 个在三步内曾恢复来源父代，23 个曾超过来源父代；
- landing 只产生 7 次运行中间的全局新 best，没有产生任何一路最终 best；
- 6/15 个最终 best 位于曾获得 ticket 的 entry，但其中部分 entry 的三步 landing 没有恢复父代，后续普通搜索才继续发展为最好程序。

普通 `q` 分配对出生质量高度敏感：未抽中 ticket 的 Explore entry 中，出生回撤者只有 145/3,246（4.5%）后来得到普通 Refine；出生不回撤者为 174/294（59.2%）。因此“低出生质量导致早夭”的前提已经得到很强的过程支持。

landing 的选择规则却没有读取入口质量损失、第一步响应、行为新颖性或任务状态。所有有效 Explore child 以相同 0.125 概率获得同样三步。大部分预算由未恢复来源父代的入口消耗，说明随机 ticket 适合作为识别干预，不适合作为最终分配器。

### 5.2 固定三步与 latest-child chain 没有利用中途反馈

landing 一旦启动便连续运行三步，后一步始终从最新有效 child 继续。部分入口在第一步或第二步已经恢复父代，之后又回撤；CVRP 出生回撤入口的 final recovery 从第一步的 4 个降至第三步的 2 个。所有中间 child 都保存在主树，因此搜索不会丢失曾达到的最好质量，但后续 landing slot 仍可能投入到正在退化的 latest-child chain。

三步内 stepwise improvement 又不能可靠认证长期价值。CVRP 与 OBP 都存在 landing 最终仍低于来源父代、该 entry 后来却产生全局最终 best 的运行。由此应把三个量分开：

1. child 是否对直接父代产生局部响应；
2. entry 是否在固定视界恢复来源父代；
3. entry 是否在更长预算中形成新的全局前沿。

当前 landing 同时用一个三步链承担测量、保护和开发，反馈视界过于固定。

### 5.3 增长型 ESS 稀释了深精炼

V9.16 的 target ESS 从早期 2 增长到后期约 97。固定比例没有保持固定搜索宽度，而是持续扩大绝对支持集。TSP 的 V9.14、CVRP 的 V9.7 都说明部分任务需要更强、更长的区域开发；V9.16 在这两个任务上分别没有达到最好版本。

V9.15 已经显示恒定节点比例会把程序数量误当成算法簇数量。V9.16 虽然修正了节点分数，仍保留同一宽度控制，因此没有解决这个问题。节点池持续增长还会让同一行为区域中的大量近邻共同占用 ESS，表面多父节点不等于真实多算法簇。

### 5.4 固定 0.7/0.3 不是任务自适应

V9.16 的普通决策按 0.3 抽取 Explore；landing 又额外加入 Refine，最终初始化后的 Explore slot 份额约为 27.9%–28.1%。这个实际比例对所有任务几乎相同。

TSP/V9.14 支持更强深开发，OP/V9.16 支持较宽全局竞争，OBP/V9.15 又受益于约 37% Explore 的制度。统一比例只提供可比基线。任务自适应需要读取 proposal 与 development 的响应，而不是从统一全局停滞计数直接映射到 Explore 率。

### 5.5 当前 entry 仍不是算法簇

entry 只记录 root 或一次 Explore proposal 的来源边界。同一 entry 可以在后续 Refine 中替换核心机制，不同 entry 也可能实现相同算法行为。V9.16 的 ticketed entry 结果能评价某个来源段的短期响应，不能估计真实算法簇稀有度或簇间质量方差。

行为簇需要由算法在诊断实例上的决策轨迹定义；代码、Idea 与 lineage 只能提供代理。在线引入 clustering 之前，应先离线检查这些代理能否预测 held-out、固定视界发展和区域重访。

## 6. 五任务的底层任务画像

### 6.1 TSP：全局竞争后需要深、稳定的局部发展

V9.16 好于 V9.7，说明 V9.7 的早期 route gate 不是 TSP 的最佳全局入口策略；V9.14 又全面好于 V9.16，说明随树增长的宽 ESS 也不是最佳后期策略。TSP 更接近“先让全树高质量节点竞争，再对胜出方向进行长链精炼”。

V9.16 的三个最好程序都形成了 2-opt/lookahead、bridge cost、candidate-pool 等机制的连续修正，深度为 15–19；V9.14 的平均最好深度约 77。当前证据支持较高的族内可改进性。V9.17 在 TSP 上需要收缩 active width，而不是增加随机 landing 数量。

TSP 也是 repair 最活跃的任务。大量复杂 lookahead 程序经错误反馈修复后进入搜索，说明代码有效性与算法质量在此强耦合。后续比较必须把 repair 作为有成本的生成动作。

### 6.2 CVRP：长视界发展有效，三步恢复很弱

CVRP 的 V9.7 在搜索与三个 held-out 规模上保持优势。V9.16 相对 V9.15 恢复了深度并显著改善，但仍落后 V9.7；三步 landing 的出生回撤入口中只有 6/86 曾恢复来源父代。

V9.16 的最好谱系深度已经达到 29–41，末段反复调整 savings、angular coherence、capacity feasibility 与 depot relation。V9.14 的深度更长却仍不及 V9.7，说明 CVRP 的关键不只是“越深越好”。V9.7 的 richer actual-change history、route 内 anchor 回访与任务尺度 `s` 都是尚未匹配的候选解释。

CVRP 三路 search best 标准差只有约 0.016，CVRP50 held-out 标准差却为 0.205，跨规模离散度更大。搜索 evaluator 对候选的细微排序没有完全转化为独立实例质量。预算分配之外，还需要诊断算法在不同搜索实例上的行为稳定性与 train–held-out 排序一致性。

### 6.3 OP：高上限区域发现比超长谱系更重要

V9.7 在 OP 上很早进入单 route 吸收态，90% 增益也较早获得；V9.16 的宽竞争则在 250 评价后持续形成更高前沿。三个最好程序只需 6–11 步，围绕 prize density、budget headroom、spatial sweepability 等结构形成竞争力。

这个形态与“高质量区域的入口覆盖具有较大杠杆，进入后中短链 Refine 足够兑现”相容。V9.16 的 growing ESS 在 OP 上发挥了作用，V9.7 的强局部化则较容易充分开发一个较低上限区域。

### 6.4 OBP：标量质量掩盖了容量条件下的不同算法行为

OBP 搜索集同时包含 `1k/5k x capacity {100,500}`。V9.16 在 capacity=500 三列强，在 capacity=100 三列弱；同一 item 规模、相同 item 序列仅改变 capacity，就出现了稳定方向差异。

因此 OBP 的问题不只是“探索多还是少”。搜索 `q` 是四个条件的聚合标量，两份平均质量相近的程序可能分别偏向小容量的碎片控制与大容量的空间保留。ESS、landing 和 `C_traj` 都只读取聚合 `q`，无法感知这种 trade-off。

OBP 的三步恢复率反而是五任务最高：出生回撤入口中 17/79 曾恢复父代，但 V9.16 终局仍落后 V9.15/V9.7 的 capacity=100。这说明局部恢复不是高质量算法簇的身份证明。后续应在不使用 held-out 的前提下，离线记录四个搜索条件的 score vector 与装箱决策行为，再判断哪些 entry 真正提供互补前沿。

### 6.5 VRPTW：宽入口与中等深度在后期共同兑现

V9.16 的优势在 750 评价后出现，最好谱系围绕 savings、time-window urgency、capacity feasibility 和短 lookahead 连续修正。它既没有 V9.14 式极深谱系，也没有 OP 式很早饱和，表现为宽入口与中等深度共同有效。

VRPTW 只有 V9.14/V9.16 两个内部版本参跑。当前最强结论是 V9.16 联合协议在该任务上有效；entry 稀有度、landing 与 growing ESS 的单独贡献仍需匹配对照。

## 7. 为什么一个固定版本不能在五任务统一最好

AAD 搜索中的观测质量可以写成以下形成过程：

$$
q_t = G(F, m_t, e_t, S_{search}),
$$

其中 `F` 是潜在算法区域，`m_t` 是该实现的成熟程度，`e_t` 是模型本次具体修改，`S_search` 是有限搜索实例。分配器只看到当前 `q_t`，却需要判断继续投入后的边际价值。不同任务至少在五个量上不同：

1. **好区域提议率**：LLM 一次 Explore 或 root generation 命中高上限区域的概率；
2. **入口实现折损**：新结构第一次实现相对成熟父代会下降多少；
3. **发展视界**：需要多少次 Refine 才能看见区域的真实竞争力；
4. **区域内可改进性与区域间上限方差**：深度和广度各自能够兑现多少收益；
5. **搜索质量的分辨率与迁移一致性**：聚合 search `q` 能否稳定排序不同实例、规模和约束条件上的算法。

V9.7 固定了“早期承诺 + 长区域发展”，V9.16 固定了“增长型全局宽度 + 随机三步保险”。两者各自只覆盖了这五维空间的一部分。真正的任务自适应不是预先把某个 task 标成“平滑”或“崎岖”，而是从统一的受控 proposal 与 development 响应中在线读出当前搜索所处的区域。

还有两个此前容易忽略的认识：

- **分配宽度与 Explore 率是两个不同变量。** V9.16 即使只有 30% ordinary Explore，也能通过近 100 的 ESS 保持很宽的父节点来源；V9.7 即使有 30% Explore，仍可在单 route 内完成结构迁移。
- **反馈视界与承诺方式是第三个独立变量。** 逐评价重选、latest-child 三步链、entry 内 best-first block 和长期 route 投资会产生不同的可观测价值。它们不能压缩成一个 exploration coefficient。

## 8. V9.17：重新审查后的机制收缩

### 8.1 随机 landing cohort 对分配信号的检验

按每次 landing 结束时已经存在的 entry frontier 重新排名，456 个随机 ticket entry 可分为两组：

| 三步成熟后的状态 | entry 数 | 后续再次提高自身前沿 | 比例 |
| --- | ---: | ---: | ---: |
| 当时前 8 | 126 | 24 | 19.0% |
| 前 8 之外 | 330 | 3 | 0.9% |

这里的“后续”是 V9.16 普通 `q` 分配下已经实现的结果，包含后续选择造成的右删失，不能估计前 8 之外 entry 的反事实 continuation value。它仍能否定一个更强的推断：前 8 之外有 209 个 entry 的三步 frontier gain 为正，后来只有 1 个再次提高前沿，现有证据不足以把“低位正增益”直接当作追加预算资格。

另一方面，6 个最终最好程序位于 ticket entry；它们在 landing 结束时全部进入当时前 8。其中 3 个 entry 出生时只排第 11、13、20，三步后分别升到第 4、1、1。这个现象支持“先成熟、再按当前质量竞争”，但仍不能证明随机 landing 的净收益，因为没有匹配的 `q baseline` 完整搜索。

在成熟后前 8 的 126 个 entry 中，三步正增益组后来再次提高前沿的是 `20/92`，零增益组是 `4/34`。方向与“近期响应可用于一次续投”相容，区分度有限且同样受后续选择影响。因此 V9.17 只让该信号控制下一 sweep，不把它解释成长期 continuation value。

### 8.2 V9.17 的两个信号边界

重新审查后，V9.17 只让两个观测承担各自能够支持的职责：

1. entry 完成统一三步成熟后，当前 frontier $Q$ 决定是否进入固定大小的 active portfolio；
2. 只有已经进入 portfolio 的 entry，近期三步 block gain 才决定是否连续获得下一个 block。

block gain 不进入跨 entry 排名，也不给竞争线以下的 entry 发放 runway。active portfolio 中全部方向都停止推进后，再从当前最好方向发起 Explore。完整状态、父节点分配、预算规则与伪代码见V9.17 完整机制设计。

### 8.3 删除的过分设计

重新审查删除了以下规则：

- 以正 block gain 为低质量 entry 发放第二个 maturation block；
- 用历史投入多少作为 hypothesis 质量平局条件；
- 按 Explore 发起次数轮转 Discovery 来源；
- 周期性重开 reserve 与额外 Discover 下限。

这些规则没有直接证据，并会把一个可检验的发现—发展循环扩展成多状态控制器。V9.17 保留固定 $K=8$、$H=3$ 与 entry 内局部锚点重选作为首个完整 policy；它们是否合适由过程激活和完整搜索共同判断。

## 9. V9.17 的最小识别协议

V9.17 首先需要两个匹配对照：

| 对照 | 唯一变化 | 识别对象 |
| --- | --- | --- |
| `portfolio + maturation + fixed` | active portfolio 与三步成熟相同；每轮固定执行一次全体 Develop 后 Discover | portfolio 与 maturation 的联合基线 |
| `V9.17` | 成功 Develop entry 连续进入下一 sweep；全体无增益后 Discover | block-response 自适应调度 |

若需要单独判断 maturation，再增加同一 portfolio 下的 `Explore birth only` 对照。所有方法保持同一模型、prompt、operator、seed、primary budget 与 repair 规则。过程层报告成熟前后排名、active/reserve 后续突破率、连续成功 block 长度和实际 Explore/Refine 份额；结果层继续分开报告 best-at-budget、搜索 best 与 held-out。

## 10. 研究认识

V9.16 最重要的价值不是找到了一条普遍更好的分配公式，而是把 V9.15 的错误历史信用拿掉后，让任务真正需要的搜索几何显现出来：

- TSP 需要全局竞争后的深发展；
- CVRP 需要比三步更长、并带局部锚点回访的区域形成过程；
- OP 受益于较宽入口覆盖和浅到中等精炼；
- OBP 的关键差异进入了容量条件下的行为 trade-off，单个聚合 `q` 已不够；
- VRPTW 显示宽入口与中等深度可以在后期共同兑现。

LLM 作为进化算子的优势在于它能沿当前算法做结构化、语义一致的修改。分配机制的职责是让这种能力在合适的区域、合适的视界内积累。区域尚未找到时，深度只会充分开发较低上限；区域已经找到时，无界增长的宽度又会稀释精炼。有效的探索—利用平衡因此是一个在线形成过程：

$$
\text{discover a candidate region}
\rightarrow
\text{observe a matched development block}
\rightarrow
\text{continue, reserve, or reopen}
\rightarrow
\text{repeat under a fixed budget}.
$$

V9.17 应把这条过程变成少量、及时结算、可受控比较的决策，而不是继续增加节点分数项。V9.7 提供了区域内深精炼的可靠工作点，V9.16 提供了全局重开与短期发展观测；有界 portfolio 与 block feedback 是当前最自然的融合接口。
