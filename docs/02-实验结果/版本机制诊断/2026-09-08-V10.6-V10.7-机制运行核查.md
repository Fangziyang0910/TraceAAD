## 3. V10.6：第二调用和历史正确落地，但损耗明显

17,911 次生成中，14,324 条代码通过解析，全部执行了第二次 `thought_alignment` 调用，再进入评价。摘要 14,320 次 `present`、4 次 `unavailable`，没有摘要截断或 API 错误。4 次缺失由输出格式引起，其中 3 个候选评价成功，按原降级规则以空摘要入档，未阻断运行。

历史均为真实祖先形成链的最近后缀，最多 8 代。645 次摘要展示使用了受限前缀；未发生额外因历史容量或总输入容量而删除历史事件。最大生成输入 12,285 tokens，低于 16,128 的输入预算。

第二调用累计消耗 **62,547,457 tokens**，占两阶段 LLM tokens 的 **27.18%**；累计 **349,328.7 秒**，占 LLM 调用时间的 **23.07%**。这是各路调用时长之和，不能解释为单路墙钟耗时。它发生在评价之前，因此之后评价失败的候选同样支付了摘要成本。摘要字段存在只说明流程执行成功，不证明解释事实准确或改善了后续搜索。

更直接的运行损耗是严格输出协议：全量分类 3,587 次无效生成如下。

| 解析拒绝原因 | 次数 |
| --- | ---: |
| 外层格式不符 | 3,377 |
| 额外代码围栏/多代码块 | 137 |
| 代码语法错误 | 65 |
| 目标签名错误 | 6 |
| 目标函数缺失或多定义 | 2 |

其中 **3,228 条（90.0%）实际包含唯一完整、可编译且目标签名正确的代码块**，但因为自由分析前言、`## Idea` 等外层格式被拒。它们具备进入评价的语法条件，不代表运行一定成功。典型样本：CVRP rep2 candidate 23/24/1310/1313 以 `Looking at...` 开头；VRPTW rep2 candidate 11/1109 使用 `## Idea`；OBP rep2 candidate 1552/1553 带自由分析前言。OBP local rep2 共拒绝 555 次，其中 460 次属于上述单代码块情况。

这符合当前 `fullmatch` 解析规则，属于协议脆弱带来的实耗。日志不足以将其单独归因于祖先历史、后端或第二次校准；V10.7 复用了同一解析器，但实际格式拒绝显著少得多。

评价失败中有 685 次 timeout、598 次 runtime_error、50 次 invalid_result、1 次 exec_error。**TSP 占 682 次 timeout**，三路总计 902/2,542 次评价失败（35.48%）。其每个候选的评价时限是 20 秒，预算损耗明显。V10.7 TSP 目前为 83/1,772 次失败（4.68%），其中 65 次 timeout。较少失败不能直接等同于更强算法。

## 4. V10.7：单调用、采样和成本控制正常

单调用专项覆盖 8,799 个已完成候选，恰好对应 8,799 次 LLM 调用，没有第二次校准。8,668 次非 Init 均显示 3 份程序，没有参考不足或 fit rejection；本批尚未自然触发 32 次容量重试上限。

参考均来自生成前已评价的档案，排除了父代同代码，单次上下文没有重复代码。完整代码、Idea 与 fitness 对应原记录；排列按分数升序，父代和 donor 索引正确。17,336 次参考曝光中，16,657 次不是父代祖先（96.1%），说明取材确实已走出祖先链。对 1,700 个没有重复代码代表选择歧义的事件重新计算分位数，结果一致。

最大输入为 8,438 tokens。26,004 个程序展示块中省略了 97 个过长 Idea（0.37%），对应计数为 259–2,513 tokens，完整代码仍保留。100 words 是提示要求，并非硬输出约束：8,570 个节点中 2,928 个超过 100 个空白分隔词，最长 1,818 词；256-token 提示视图保护正常生效，没有让这些长 Idea 挤掉完整代码。

## 5. 最关键的问题：采样分散，算法仍然停滞

两路已经结束的 V10.7 OBP 都在第 1 次评价得到 −744.5，之后跑满 1000 次仍未改善。

| 现象 | OBP rep2（server3b） | OBP rep3（local） |
| --- | ---: | ---: |
| 有效节点 | 997 | 1000 |
| 不同完整代码 | 913 | 946 |
| 与最优同分的节点 | 977（98.0%） | 995（99.5%） |
| Pivot 执行次数 | 132 | 155 |
| 所有算子全局刷新 | 0 | 0 |
| 三份上下文全同分 | 916/992（92.3%） | 978/992（98.6%） |
| 最后100次上下文全同分 | 94 | 98 |
| 父代节点 HHI | 0.00253 | 0.00240 |
| 合并完全相同代码后的 HHI | 0.00294 | 0.00257 |

两路分位数边界始终为 `[-744.5, -744.5]`，按“同分不拆层、边界归较低层”的规则，全档案均落在 low 层。每轮仍可抽到两份不同代码，但分层采样已失去质量差异对照。父代选择次数修正也正常运作：节点分配很分散，最高分大量并列时 ESS 目标按规则抬高。**继续分散 node ID 并不能解决这些程序决策规则相似的问题。**

对两路合计 12 个代表节点进行静态公式抽查，可具体看到行为等价。令 `r=b-item≥0`，`b` 为可行箱剩余容量：

- rep2 node 995 / evaluation 999，Pivot：`-r+1e-9*b`；node 996 / evaluation 1000，Fuse：`-r-1e-9*b`。固定 item 时均严格随 r 递减，仍是 Best-Fit。
- rep3 node 15 / evaluation 16，Pivot：`-r+1e-6*b`；node 997 / evaluation 998，Pivot：`1/(1+r)`。同样保留 Best-Fit 排序。
- 相同 r 必然意味着相同 b，所谓使用容量微扰打破“相同残余”的平局，对这些公式不起作用。

也有真实行为变化。rep2 node 41 / evaluation 43，Pivot 用递增的 `r-1e-12*b`，变为 Worst-Fit，得 −3000；rep3 node 873 / evaluation 874，Pivot 用 `r+1e-12*b`，同样为 Worst-Fit，但注释误称 First-Fit，也得 −3000。rep2 node 951 / evaluation 955 的 Fuse 让剩余 1 优于精确装满，得 −746.75。所抽查的 5 个明确改变排序的程序都退步。

这说明两路既有行为等价的公式变换，也有探索后退步的尝试。不能把全部同分节点都判为行为等价；本次没有执行全档案行为探针。

TSP rep2 也有停滞信号：评价 68 达到 −6.82397，随后 553 次评价没有刷新，298/617 个有效节点与最优同分。末 100 次参考仍来自 low+middle 两层，未发生三程序全同分。因此 OBP 的“分层边界重合”不是所有停滞的共同原因，质量差异也不足以保证算法行为差异。

## 6. 研究判断与下一步

当前证据支持保留“第二调用已去掉、采样成本可控”的工程判断，**不支持直接把 V10.7 判为搜索效果更好**。取共同的前 250 次真实评价，三重复平均最好分如下，均为 higher-is-better：

| 任务 | V10.6 | V10.7 |
| --- | ---: | ---: |
| TSP | −6.10727 | −6.72826 |
| CVRP | −9.52619 | −9.69499 |
| OP | 14.39600 | 14.47467 |
| OBP | −727.25000 | −739.16667 |
| VRPTW | −19.91977 | −20.71824 |

这些训练集结果只用于识别过程问题，三重复也不足以隔离机制因果。两版同时改变校准、材料、代码展示和算子指令，不能用当前差异证明独立校准有益或分层采样无效。

后续最值得验证的两点：

1. **减少可恢复的格式拒绝。** 用已拒绝的单代码块样本离线验证更明确的输出约束或最小格式兼容，保留签名与编译检查，先确认能回收多少有效候选，再考虑下一版。不要直接把 3,228 条全部计作有效算法。
2. **直接测量行为差异与后续开发。** 先围绕 OBP 的排序等价、Pivot 是否改变选择、改变后的候选是否得到后续扩展做小规模离线诊断。当前最强证据是“不同代码和不同节点仍可能指向同一规则”，没有必要先增加更复杂的父代分配或再次解释代码。

本次按原配置继续运行剩余实验，未新增机制、补跑、停止或重启任何 run。
