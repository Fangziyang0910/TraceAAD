## 版本一（首版机制，2026-09-10）

自 V10.9 复制后：移除新结构试用与直接子代试错上下文，简化算子提示与上下文，加入宽容解析、具体错误记录与最多一次错误条件修复。

## 版本二（2026-09-11 修订，git 8ba1c0ba）

相对版本一的改动：

1. 初始化收缩为 sequential informed initialization；删除 Init 阶段的 AST 去重与提示中的防御性约束。
2. 父代分配从 V10.8 的 A/B/C/D 消融框架显式抽出为固定策略（ESS-8 质量父代选择、Pivot 50% 均匀；声明为行为不变）。
3. 正常搜索上下文修订为统一短形成路径（`unified_short_formation_path_v1`）。
4. 解析协议改为代码优先（`code_first_description_extracted_v1`）：说明为 tagged/prose/missing 均不作为接受门槛。
5. VRPTW 四个非法构造出口（depot 上无可行客户、已在 depot 又返回 depot、返回节点超出可行候选集、路线覆盖不全）各自携带条件消息，经 `InvalidEvaluationResult` 映射为 `invalid_result`；TSP 任务契约补充调用语义事实与运行环境记录。
6. 算子指令改为「设计对象 + 认知操作 + 结果目标」三要素结构；输出契约改为顺序中性；Fuse 组装中形成路径归属当前算法、donor 标题独立。
7. 修复（repair）使用最后响应缓存。

## 版本三（2026-09-12 修订，git 787f12e9；含 1e0e660a 与 787f12e9 两个提交）

相对版本二的改动：

1. **生成对象改为目标函数**：LLM 输出只包含目标函数定义；解析后由系统将其放入冻结任务模板重建完整程序再评价，模板提供 import 与任务脚手架（解析策略 `target_function_rebuilt_from_template_v2`，生成策略 `target_function_idea500_template_rebuild_one_repair_v3`）。
2. **输出格式改为两段标注**：`Idea:`（至多约 500 词）在前，`Code:`（一个 Python 代码块）在后。
3. **输出说明收紧**（787f12e9）：Idea 须陈述主决策规则、关键计算或参数、相对所给算法的有意义变化；函数体不写注释，Code 只含可执行语句。
4. **机制侧函数视图**：节点函数文本经 `ast.parse`/`ast.unparse` 重建（ast.unparse 去除生成注释）；上下文策略名改为 `unified_short_formation_path_compact_code_v2`。
5. **存储格式变化**：tree_state 与 run_summary 中的节点/best 代码为**函数级文本**（版本一/二为完整程序文本）。
6. run.py 机制描述串改为 "function-level generation"。
