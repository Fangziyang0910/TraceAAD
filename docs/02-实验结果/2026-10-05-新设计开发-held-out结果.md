## 新设计开发在搜索中做了什么

每路约 94–135 次 Explore 提出，其中约 86–110 个设计开启了开发。开发占全部搜索生成的 27–32%。

| 汇总（13 路） | 观察 |
| --- | --- |
| 开发结束原因 | 绝大多数是连续 2 步没有更好版本（stalled，75–100 个/路）；设计的最好版本进入前 5 名（competitive）每路 2–39 个，多数任务在 3–15 个 |
| 开发的收益 | 开发使版本变好的次数每路 39–64 次；`development_gain_median` 在抽查的 CVRP rep1 为 0 |
| 最终前列程序的来源 | 13 路的 `top_programs_from_development` 均为 0；新增最好程序中，Explore 与 Develop 的占比在各路均为少数，主要来自 Refine 与 Crossover |

这说明开发机制按设计运行，但开发步骤产生的是对设计自身的小改进，很少让设计进入全搜索前列。大约三成生成预算流向这些开发，Refine 与 Crossover 得到的预算相应减少。CVRP 与 TSP 的退步与此方向一致，但只有 2/3 路，并混有主机差异，尚不能把退步归因于预算转移。判断它需要 rep2 完成，并比较 V10.17 每路按动作的预算与最终程序的来源。
