# V10.10 之后版本：机制、实验结果与研究发现

本页截至 2026-09-23，仅比较当时已完成的 V10.10–V11.1 批次。“当前”和“下一步”均为当时口径；V10.13 的运行中数据与后续实验应从[文档导航](../README.md)进入，不回填为本页的因果证据。

## 总结

TraceAAD 的搜索结果由三层共同形成：机会分配决定哪些候选继续开发，算子决定本轮改进动作，上下文提供动作所需的历史材料。V10.10 在当时所比批次中表现较强；V10.11 显示任务间的历史材料效果不同；V10.12 和 V11.0 分别暴露了参考卡片追加和精英选择的代价；V11.1 将节点级机会分配与算子条件化上下文组合，改善了 CVRP、OBP 和 VRPTW 的部分规模，但 TSP 与 OP 仍需修正。联合改动的结果不单独识别某一层的作用。

| 版本 | 机制 | held-out 结果 | 研究发现 |
|---|---|---|---|
| V10.10 | ESS-8 质量分配、四算子均分、短形成轨迹、一次修复 | 平均名次 2.133 | 质量开发、路线覆盖和提示约束形成较均衡的组合 |
| V10.11 generic | 比较短轨迹、无轨迹、全代码轨迹和档案卡 | 平均名次 3.000 | TSP/VRPTW 使用短轨迹，CVRP 使用档案卡，OBP 使用轻量材料 |
| V10.11 rand_ctx | 四算子统一使用档案 Idea+fitness | 平均名次 2.367 | 跨分支参考对 CVRP 有效，对 TSP/VRPTW 不适合替代形成关系 |
| V10.12 | 在短形成轨迹外增加两张 profile card | 平均名次 2.733 | 参考数量增加没有带来跨任务的稳定收益，OBP 获得局部改善 |
| V11.0 | AST code 级精英选择、Idea 长尾参考 | 平均名次 2.600 | CVRP 受益，其他任务受到父代集中和弱参考的共同影响 |
| V11.1 | 节点级固定温度抽样；Refine/Tune 用轨迹，Pivot 用档案，Fuse 用档案加参考代码 | 平均名次 2.467 | 局部父代改进增加，但前沿推进仍弱；CVRP/OBP/VRPTW 部分规模改善，TSP 退步 |

## V10.10：质量开发与路线覆盖

### 机制

V10.10 使用 ESS-8 质量 Softmax 分配父代，Pivot 保留 50% 均匀抽样，Refine、Tune、Fuse、Pivot 各占 25%。初始化采用 8 个 sequential informed 根节点，普通搜索使用当前程序、fitness 和最近形成路径；失败候选最多进行一次修复。每次真实评价统一计入预算。

### 实验结果

V10.10 首版在 TSP、OP、CVRP、OBP 上同批走强，平均名次为 2.133；VRPTW 各重复结果方向不一致。V10.10R 收紧初始化并修订提示和解析后，TSP、VRPTW、OBP 改善，OP/CVRP 三个规模回落，平均名次为 2.867。

### 发现与结论

V10.10 是后续版本的质量基线：它保留质量偏置，同时给 Pivot 留出独立探索机会；短形成路径能够支持连续改进，代码优先解析和一次修复提高了有效候选比例。后续改动应分别观察机会分配、上下文材料和实际代码行为。

## V10.11：历史材料的任务差异

### 机制

V10.11 generic、no_traj、idea_code 和 rand_ctx 在相同真实评价预算下比较四类上下文：短形成轨迹、无历史、完整代码轨迹和档案 Idea+fitness。四组批次统一使用四个算子，差异集中在历史材料。

### 实验结果

- 短形成轨迹在 TSP 和 VRPTW 上最好，保留了当前路线的修改顺序和评价变化。
- 档案 Idea+fitness 在 CVRP 上最好，在 OBP 上也优于带轨迹方案。
- 完整代码轨迹带来上下文超限和更大重复方差，信息量增加没有转化为质量提升。
- rand_ctx 在 CVRP 上最强，OBP 与无轨迹接近；TSP/VRPTW 仍需要形成关系，OP 的方差随规模增加。

### 发现与结论

历史材料的价值取决于当前算法正在完成的改进动作：形成关系适合连续协调，档案材料适合跨分支传播，代码材料适合提供可执行细节。V10.11 的四个批次同时作用于全部算子，因此它直接识别了任务间材料差异，下一步需要把材料差异与算子动作拆开。

## V10.12：参考卡片的追加

### 机制

V10.12 保留 V10.11 的 ESS-8、短形成轨迹和四算子比例，在上下文中为所有算子增加两张 `Idea+fitness` profile card。

### 实验结果

V10.12 平均名次为 2.733。TSP、CVRP、OP 和 VRPTW 没有稳定收益，OBP 六个规模中五个小幅改善。held-out 中 TSP/VRPTW 的回落触发了原定的档案卡数量控制条件；ACO worker 导入事故已经单独恢复，最终结果按恢复后的完整批次统计。

### 发现与结论

参考材料增加后，模型获得了更多思想文本，但缺少代码、算子、形成顺序和行为变化。对 Refine/Tune，外部 Idea 会分散当前局部改进；对 Pivot/Fuse，Idea 又不足以支持可执行的替代机制。参考卡片需要与动作匹配，并提供能进入代码的具体材料。

## V11.0：精英选择与长尾参考

### 机制

V11.0 把父代单位改为唯一 AST code，按 fitness 百分位和探索加分计算分数并选择最高分 code；Pivot/Fuse 共享最多 8 个 Idea+fitness 参考节点，采用 reciprocal-rank 抽样。Refine/Tune 继续使用短形成轨迹。

### 实验结果

V11.0 相对 V10.11 generic 在 CVRP50/100/200 改善约 3.70%/4.46%/3.75%，TSP 退化约 3.5%–4.3%，OP 随规模退化约 0.37%–3.58%，VRPTW50/100 退化约 4.92%/2.34%，OBP 基本不变。

正常开发请求中约 99.7%–100% 落在 `q≥0.95` 的 code，best 节点深度约 50–72；V10.11 对应约 9–34。Pivot 的父代改进率从约 9%–16% 降至约 1.5%–3.2%。参考样本中约 40%–43% 来自前 32 名之外，V10.11 rank-softmax 对应约 2%。

### 发现与结论

V11.0 把机会集中到极少数高分 code，同时把参考范围扩展到长尾 Idea。CVRP 能从高质量 Idea 中提取几何、容量和节约机制；TSP/VRPTW 更依赖连续形成关系；OBP 需要观察排序变化；OP 需要结合规模选择参数和组合。V11.0 的主要问题是父代集中与参考执行细节不足同时发生。

## V11.1：节点级机会分配与算子条件化上下文

### 机制

V11.1 将机会分配单位改回独立节点。节点分数为 fitness 百分位加低 `attempts` 奖励，父代按固定 `tau=0.2` 的 softmax 抽样。Refine/Tune 使用当前程序和短形成轨迹，Pivot 使用档案 Idea+fitness，Fuse 在此基础上提供一份完整参考算法代码。四个算子共享父代分布，各占 25%。

### 实验结果

V11.1 五任务五重复完成每路 1000 次评价，held-out 平均名次为 2.467。相对 V10.11 generic：

- TSP50/100/200 退步约 5.61%/5.05%/4.09%；
- CVRP50/100 改善约 3.73%/2.68%，CVRP200 基本持平；
- OP50/100/200 变化约 −0.03%/−0.96%/−2.28%；
- OBP 六个规模中五个小幅改善；
- VRPTW100/200 改善约 0.77%/0.45%，VRPTW50 接近持平。

五任务五重复汇总中，V11.1 的 Fuse parent improvement/frontier improvement 约为 55.1%/3.0%，V10.11 generic 对应约为 8.6%/2.6%。

### 发现与结论

V11.1 的档案卡和完整参考代码提高了当前父代的局部改进，前沿推进增长较小。节点级抽样改善了 V11.0 的精英集中，但仍主要围绕高分节点分配机会。当前最直接的下一步是固定机会分配，只比较通用短轨迹与算子条件化上下文；随后固定上下文，再比较机会分配规则。

## 跨版本研究发现

1. 机会分配应关注路线的后续开发价值，而不是只追逐当前最高 fitness。
2. 形成轨迹、档案思想和完整代码承担不同信息功能，材料数量增加不会自动提高算法质量。
3. parent improvement 与 frontier improvement 是两个不同结果，局部改进必须经过后续开发和 held-out 测试才能转化为版本收益。
4. 算子提示需要指向实际算法动作；算子名称、Idea 和代码结构本身不等同于行为变化。

## 下一步实验

第一步固定 V10.11 的 ESS-8、算子比例、解析、修复、任务契约和模型，只比较 V10.11 generic 与 V11.1 的算子条件化上下文。第二步固定通过的上下文配置，只替换算子提示，并记录实际决策、上下文材料、parent/frontier 改进和后续开发。第三步在前两步结果基础上比较 ESS-8 与节点级 softmax。
