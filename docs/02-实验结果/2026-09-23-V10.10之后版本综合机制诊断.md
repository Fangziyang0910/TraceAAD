# V10.10 之后版本综合机制诊断

## 核心判断

V10.10 之后长期没有稳定突破，主要原因不是某个单独算子失效，而是三层机制没有同时对齐：预算分配决定了哪些设计路线能继续发生，算子提示决定了模型要做什么动作，上下文决定了模型是否有足够证据把动作落实到代码。后续版本分别强化了其中一层，却多次让另外两层失配。

用户坚持的方向是成立的，但需要把三个概念定义得更严格：多样性应当是**决策行为和设计路线的多样性**，而不是四个算子各占 25%；预算分配应当分配“继续开发某条路线的机会”，而不是只偏好当前分数最高的节点；算子上下文应当提供该动作所需的可执行证据，而不是把更多 Idea 或程序塞进提示。V10.10 的优势正是在有限预算下保持了较好的质量偏置、探索覆盖和提示约束的平衡。它仍有思想没有落实到实际返回行为的问题，因此它是目前最好的机制基线，不是已经完成的机制。

## 结果总览

以下名次只作描述性参考。各批次重复数不同，V11.0 早期汇总与 V11.1 的测试口径也不是完全相同的配对试验，不能把名次差异解释为单一机制的因果效果。

| 版本或对照 | 主要改变 | held-out 总体信号 | 最有力的证据 |
| --- | --- | --- | --- |
| V10.10 首版 | ESS-8 质量分配、四算子均分、短形成路径、一次有界修复 | 平均名次 2.133，V10 系列中最均衡 | TSP/OP/CVRP/OBP 同批走强，VRPTW 尚未稳定 |
| V10.10R | 收紧初始化、算子三要素提示、解析与短路径实现修订 | 平均名次 2.867 | TSP、VRPTW、OBP 变好，但 OP/CVRP 三规模全面回落 |
| V10.11 generic | 保留 ESS-8，系统比较短轨迹、无轨迹、全代码轨迹和档案卡 | 平均名次 3.000 | 短轨迹在 TSP/VRPTW 最好，档案卡在 CVRP/OBP 有效 |
| V10.11 rand_ctx | 用 8 张 Idea+fitness 档案卡替代形成轨迹 | 对照名次 2.367 | CVRP 明显最好，OBP 与轻上下文相当，TSP/VRPTW 不如短轨迹，OP 方差最大 |
| V10.12 | 在短形成轨迹之外，给所有算子增加 2 张档案 profile card | 平均名次 2.733 | OBP 多数规模改善；TSP、CVRP、OP、VRPTW 没有稳定收益，预设扩大卡片门槛未通过 |
| V11.0 | AST code 级精英选择、Idea 长尾参考 | 平均名次 2.600 | CVRP 改善约 3.70%/4.46%/3.75%，TSP、OP、VRPTW 回落 |
| V11.1 | 节点级固定温度抽样、Refine/Tune 用轨迹、Pivot 用档案、Fuse 用档案加一份代码 | 平均名次 2.467 | CVRP50/100、OBP 多数规模和 VRPTW 获益；TSP 明显退步，OP 仍弱 |

V10.11 的四组上下文对照是最重要的证据。共同真实评价预算下，短形成轨迹在 TSP 和 VRPTW 上最好；CVRP 偏好档案参考；OBP 偏好无轨迹或轻量档案；OP 对上下文存在规模和阶段依赖。这个结果证明了上下文需求的异质性，但还没有证明“哪个算子应该使用哪种上下文”，因为当时每个上下文批次都同时作用于四个算子。

## V10.10：为什么它暂时是最好的基线

V10.10 的预算策略有三个正确的地方。ESS-8 让质量偏置不会立即退化为只开发当前头部；Pivot 保留 50% 均匀混合，给替代主机制留下独立机会；四个算子各占 25%，避免在还不了解任务差异时提前把预算押在某一种动作上。V10.10 不是证明 ESS-8 数值最优，而是目前唯一同时体现质量开发和路线覆盖的可复用预算配置。

它的短形成路径也与预算策略匹配：当前节点和最近形成关系足以支持 Refine/Tune 延续一条有效路线，提示又没有像全代码历史那样把容量消耗在重复实现上。代码优先解析、具体错误记录和一次有界修复提高了有效候选比例，使真实评价预算更多地用于算法搜索。

V10.10 的问题有两类。第一，ESS-8 仍然按节点质量分配机会，不知道一个节点代表的是强路线、弱路线、尚未验证的替代机制还是已经停滞的局部结构。第二，算子提示虽比早期版本清楚，但仍主要描述意图：Refine 要“改进”，Tune 要“校准”，Fuse 要“整合”。它没有强制模型说明本次改变哪个实际决策、为什么适用于当前父代、返回动作是否真的使用了所声称的计算。

这一缺口在 V10.10 诊断中已经直接出现：有候选在 Idea 中声称使用 2-opt，代码只计算边长方差；也有代码确实翻转了路径，却返回翻转前的候选节点。也就是说，运行成功和短期分数都不能证明提示中的算法思想已经进入实际行为。V10.10R 的结果进一步说明，提示和输出协议的修订会改变搜索分布：TSP/VRPTW/OBP 变好，但 OP/CVRP 三规模全面变差。当前没有逐项消融，不能把这次回落归因于某一句提示，但它说明“提示更严格”不等于“所有任务都更好”。

## V10.11：证明了上下文异质性，但没有完成算子匹配

V10.11 的贡献不是最终主批名次，而是把“经验如何表达”做成了可比较的对照。

- 短形成轨迹在 TSP 三个规模都优于无轨迹，在 VRPTW 三个规模优势更明显；它保留了当前路线怎样形成、哪次修改带来什么结果的信息。
- 档案 Idea+fitness 在 CVRP 上明显优于短轨迹，在 OBP 上也优于带轨迹方案；跨分支机制材料对这两类任务有价值。
- 全代码轨迹没有形成稳定收益，TSP 变差、上下文两次超限，VRPTW 重复方差显著扩大。信息更多没有转化为更好的开发证据。
- rand_ctx 在 CVRP 上成为四方中最强，OBP 与无轨迹同档；但 TSP/VRPTW 无法替代形成关系，OP 出现最大方差和一个运行代价随规模爆炸的程序。

V10.11 的长期问题是上下文策略仍是“批次级”的。一个批次把同一种经验给 Refine、Tune、Pivot、Fuse，而不是让上下文服务于动作。并且 generic、no_traj、idea_code、rand_ctx 不仅改变了信息来源，也改变了上下文长度、参考质量、关系结构和生成难度。因此它支持“不同任务需要不同信息类型”，只能间接支持“不同算子需要不同信息”，不能单独验证后者。

提示层也仍然偏泛化。V10.11 的短轨迹告诉模型“使用记录的设计变化和结果”，但没有要求 Refine 只改一个可定位缺陷、Tune 只校准影响实际排序的参数、Pivot 解释替代机制为何能跨越当前短板、Fuse 指出 donor 中哪一个计算被接入 host 的哪个位置。于是算子标签和 Idea 仍然不能代替代码行为检查。

## V10.12：为什么盲目增加参考卡片没有奏效

V10.12 是一个有价值的负结果，因为它基本保持了 V10.11 的 ESS-8 预算和短形成轨迹，只增加两张 `Idea+fitness` profile card。它说明失败不在于“参考信息绝对无用”，而在于参考信息没有被组织成当前动作可以使用的证据。

具体问题有四个：

1. 两张卡片对四个算子一视同仁。Refine/Tune 需要当前计算和形成关系，额外的外部 Idea 可能分散模型对局部缺陷的注意；Pivot/Fuse 需要可执行的替代机制，只有 Idea+fitness 又不足以判断怎样实现。
2. 卡片没有代码、算子、形成关系、适用条件或行为变化。模型知道某个节点分数较好，却不知道它改变了哪个排序、阈值、容量处理或可行性决策。
3. 卡片没有整合协议。提示没有要求模型选择一张卡、说明采用或拒绝的原因，也没有要求把卡片中的具体计算映射到当前算法，因此两张卡只是追加文本，不是可验证的设计材料。
4. 卡片抽样按排名 softmax，不按当前父代短板或动作兼容性抽样。高质量不代表适合当前算法，长尾覆盖也不等于有效多样性。

held-out 结果与这个解释一致：V10.12 的 TSP 三规模、CVRP 三规模、OP 三规模均未超过 V10.11 generic；VRPTW 也未稳定改善，只有 OBP 六列中五列小幅改善。V10.12 预设的“TSP/VRPTW 恶化超过 1% 就不扩大卡片数量”已经被测试触发，因此不应沿着增加卡片数量的方向继续。V10.12 的 ACO worker 导入故障和恢复过程是运行基础设施问题，已单独诊断并修复，不能当作该机制失败的证据；最终 held-out 仍应按恢复后的完整批次统计。

## V11.0：预算和上下文同时走向极端

V11.0 的 CVRP 收益说明精英开发和 Idea 参考在某些任务上确实有用，但版本整体失败的原因非常具体。

预算方面，V11.0 用唯一 AST code 作为开发臂，并对最高分 code 直接选择。实际运行中 `num_codes` 通常接近 `num_nodes`，说明代码聚合没有形成重复行为的稳定统计单位；探索次数几乎不能估计一类机制是否得到过足够机会。约 99.7%–100% 的正常开发请求落在 `q≥0.95` 的 code，低分节点几乎没有开发机会，最强路线形成深度约 50–72，V10.11 约为 9–34。父代改进率从 V10.11 的约 9%–16% 降至约 1.5%–3.2%。这不是合理的质量优先，而是把早期偶然优势锁定成长期开发路线。

上下文方面，V11.0 把 Pivot/Fuse 参考压缩成 Idea+fitness，并用 reciprocal-rank 引入很长的尾部；约 40%–43% 的参考来自前 32 名之外，而 V10.11 rank-softmax 约为 2%。这些条目没有代码、算子和形成顺序，参考覆盖变宽，执行证据却变弱。CVRP 能从 Idea 中提取距离、容量、节约等高层机制，所以受益；TSP/VRPTW 需要连续形成关系，OBP 需要观察排序变化，OP 需要考虑规模和阶段，因此不能稳定受益。

V11.0 同时改变了父代选择和 Pivot/Fuse 上下文，没有同预算单因素对照。当前最准确的结论是“窄而确定的父代选择与宽而弱的参考上下文耦合后，只有 CVRP 适应了这种搜索结构”，不能把失败单独归因于预算或卡片。

## V11.1：方向正确，但还没有完成验证

V11.1 修正了 V11.0 最明显的实现问题：预算单位回到独立节点，`attempts` 只记录直接父代机会，所有有效节点通过固定温度 softmax 保留机会；上下文则首次按算子固定分工：Refine/Tune 使用短形成轨迹，Pivot 使用档案卡，Fuse 使用档案卡加一份完整参考代码。这是目前最接近用户目标的版本。

held-out 结果支持它取得了部分折中：相对 V10.11 generic，CVRP50/100 改善约 3.73%/2.68%，OBP 六列中五列小幅改善，VRPTW100/200 小幅改善；代价是 TSP 三规模退步约 4%–6%，OP100/200 退步约 1%–2%。因此它说明算子条件化上下文可能有效，但没有证明当前四路映射就是正确映射。

V11.1 的原始事件更能说明问题。五任务五重复汇总后，V11.1 各算子的父代改进率/前沿改进率约为：Refine 17.7%/0.8%，Tune 23.2%/1.4%，Pivot 19.9%/1.3%，Fuse 55.1%/3.0%。V10.11 generic 对应约为 Refine 5.9%/1.9%、Tune 7.3%/2.6%、Pivot 11.7%/0.4%、Fuse 8.6%/2.6%。这表明 V11.1 的参考上下文，尤其是 Fuse 的“档案卡+完整代码”，很容易制造超过当前父代的局部改进，但没有按同等幅度提高全局前沿改进。它改善了“能改好当前父代”，没有解决“能否形成更好的路线并被继续开发”。

预算也只是修正到合理范围，并未成为完整的路线分配器。V11.1 全批约 20,707 次有效父代选择中，被选节点概率中位数约 0.56%，第 90 百分位约 2.60%，第 99 百分位约 14.0%，最高达到约 52.4%；它比 V11.0 的精英锁定健康得多，但仍没有针对分支覆盖、停滞路线、算子—父代组合或行为簇提供独立机会。一个高分节点在局部阶段仍可能拿走过多机会。

V11.1 的提示也还没有达到“优秀算子提示”的要求。当前指令仍是“围绕主意图改进”“校准有影响的参数”“借鉴参考算法形成协调改进”。它们比单纯的 operator label 清楚，但没有明确要求：本次只改变哪个决策、采用哪条证据、实际排序或返回动作如何改变、哪些结构必须保持、如何检查 Idea 与代码一致。Fuse 的父代改进率高而前沿改进率低，正是“提示鼓励组合”与“组合是否真正解决前沿短板”之间的缺口。

此外，V11.1 的结果不能严格验证“算子适配上下文”这一因果假设：它同时改变了 V11.0 的预算实现和上下文配置，且没有在同一 ESS-8 调度下只替换上下文的对照。V10.11 已经证明任务间存在上下文差异，V11.1 提供了与算子映射相容的结果信号，但还不是算子级验证。

## 长期瓶颈的统一解释

从 V10.10 到 V11.1，反复出现的核心错位是：系统记录了“模型说了什么、候选得了多少分、父代是否被超过”，却还没有稳定记录“哪个实际决策被改变、这个决策为什么适用于当前父代、这条路线是否值得继续开发”。因此：

1. **预算层**把当前 fitness 当作路线价值。它能找到并开发强节点，却不能区分一个强节点的继续精炼空间、一个弱节点的突破潜力和一个已经停滞的分支。
2. **上下文层**把 Idea、代码和形成关系当成可互换的信息。V10.11 说明它们不等价：形成关系适合连续改进，档案材料适合跨分支传播，完整代码只有在需要执行证据时才有价值。
3. **提示层**把算子定义成语言意图，而没有把它定义成可核验的设计契约。Refine/Tune/Pivot/Fuse 的名字和说明不能保证代码行为分别是局部改进、数值校准、主机制替换和针对性融合。
4. **多样性层**把四个算子各 25% 当成多样性。实际可能是同一类局部评分被四个算子重复生成，也可能是算子标签变化而 `argmax`、候选排序或返回动作没有变化。
5. **评价层**把训练 best 的局部收益当成方法收益。V10.10R 的 OP 训练变好而 held-out 全面变差，V10.11/V11.1 的 parent improvement 与 frontier improvement 差距也说明局部适应不是泛化证据。

因此，真正需要的不是更多参考卡或更复杂的单一选择公式，而是一套闭环：**算子提示提出一个可执行的改变，匹配上下文给出该改变的证据，预算把后续机会给到路线而不是偶然节点，代码行为核验确认决策真的改变，held-out 再判断改变是否迁移。**

## 对下一版机制的最小验证建议

第一步应先隔离上下文，而不是继续同时改预算和提示。固定 V10.11 的 ESS-8、Pivot 1:1 均匀混合、四算子 25%、解析与修复、任务契约和模型，只比较两组：A 为 V10.11 generic 的短形成轨迹统一上下文，B 为 V11.1 的 Refine/Tune=T、Pivot=A、Fuse=A+C。五任务各三重复、每路 1000 次真实评价，使用同一 held-out 口径。若 B 不能在至少三个任务上改善且没有超过 1% 的 TSP/VRPTW 回落，则当前算子映射不足以支持继续扩展。

第二步在通过的上下文配置上只替换算子提示，保持预算和上下文完全不变。提示必须要求模型给出四个可核验字段：改变的实际决策、采用的上下文证据、对父代短板的对应关系、代码中改变排序或返回动作的位置。字段可以写入 Idea，也应从代码行为日志中复核，不把字段存在本身当作质量。重点指标为 parent improvement、frontier improvement、超过 donor/参考算法的比例、实际 `argmax`/选择排序变化和后续被继续开发的比例。

第三步再检验预算。比较 ESS-8 与 V11.1 节点 softmax 时，不只看最终 best；应同时报告父代机会的分布、每类行为路线覆盖、停滞路线获得的机会、局部改进到 frontier 的转化率和 held-out。预算版本的停止条件应是“在相同真实评价预算下提升前沿迁移”，不是“高分节点被选得更频繁”。

如果三步证据成立，最终版本应保留 V10.10 的预算稳定性、V10.11 的上下文异质性、V11.1 的算子分工和更强的行为约束提示。若只观察到 Fuse 的 parent improvement 上升而 frontier improvement 不升，则应收紧 Fuse 的参考证据和路线分配，而不是增加参考数量；若 TSP/VRPTW 仍退步，应优先保留短形成轨迹并减少档案卡干扰；若 OP 仍随规模退步，应把规模适应作为上下文和提示中的待检验决策，而不是继续扩大统一档案。
