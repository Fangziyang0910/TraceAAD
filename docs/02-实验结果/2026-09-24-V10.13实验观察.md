# V10.13 实验观察与分析（partial）

数字固定在 **2026-09-24 11:32 +08:00** 快照：9 条路径完成 1000 次评价，其余进行至 451–931 次。数据来源为逐路径事件日志、调用日志与节点日志，批次仍在运行，所有数字会随进度变化。

## 1. 响应无法解析

**观察**：17,539 次生成请求中 506 次（2.9%）无法从响应文本得到可运行程序。原因分布：

| 次数 | 占比 | 现象 |
| ---: | ---: | --- |
| 312 | 62% | 响应中出现多个或界限不明确的 Python 代码块，无法确定哪份是程序 |
| 94 | 19% | 响应给出"查找原文→替换"式局部修改，但所引原文在程序中找不到或出现多次 |
| 63 | 12% | Python 语法错误（缩进、未闭合括号、未终止字符串等） |
| 19 | 4% | 同时给出完整程序和修改指令，二者混用 |
| 18 | 4% | 其他（多个互相冲突的 JSON 提案、字段不合法等） |

**简单归因**：多为表述层问题——模型在代码块外叙述、给备选实现，或转述原文时与程序实际文本有出入；真正的语法错误只占少数。

**对比**：上一批 r2 固定快照中，同位置失败占 25.8%，集中在说明文字与 JSON 包裹导致内容无法识别。降到 2.9%，约九倍改善。

## 2. 程序运行失败

**观察**：17,538 次真实评价中 1,292 次（7.4%）程序进入评测后失败：939 次运行报错、289 次超时、79 次返回了无法作为分数的值。按任务：

| 任务 | 失败次数 | 主要现象 |
| --- | ---: | --- |
| TSP | 283 | 超时为主（274 次） |
| VRPTW | 366 | 报错为主，另有 69 次返回非法值 |
| CVRP | 214 | 报错为主 |
| OP | 210 | 报错为主 |
| OBP | 34 | 少量 |

**简单归因**：TSP 的超时大概与生成程序写得循环过深、构造过慢有关；VRPTW 的非法返回集中在少数重复出错的行为上（未逐条核实）。

**对比**：r2 同深度口径（每路前 50 次评价）失败率 5.84%，同口径 7.00%——略差，量级相近。

## 3. 失败后的修复

**观察**：失败后共发起 1,482 次修复请求（把原程序与错误信息送回重新生成）：1,149 次（78%）得到可运行且获得分数的程序，295 次修好后运行仍失败，38 次再次解析失败。修复产生的评价占全部评价的 8.2%。

**对比**：r2 在 E50 截面修复占用评价 35.6%；本批降到 8.2%。修复成功率本身两批接近。

**OP-2 停滞段细看**：E68 之后的 446 个生成程序中，99% 的代码与其所基于的程序不同（不是重复输出），93 个不同程序被作为修改基底，四类请求均匀出现；67% 的程序分数落在最好分 1.0 以内（最好分 14.598，中位差距 0.598），只有 9% 超过自己所基于的程序；最好分被若干不同程序**并列达到但从未被超过**。

**简单归因**：停滞不是"反复生成相同内容"，而是持续生成**不同但都无法超越**的程序；大量不同写法在训练实例上得到相同或接近的结果，分数无法进一步区分它们。

**终点对比**（partial，未完赛路径按当前值）：TSP 四路均值 -6.009（generic 完赛均值 -5.840，V10.12 -6.010）；CVRP 进行中，当前 -8.75～-9.63（rand_ctx 完赛 -8.718）；OP 均值 14.75（历史区间 14.68–14.87）；OBP 均值 -727.2，四路全部突破 -730（r2 三路卡在 -744.5）；VRPTW 均值 -19.01（generic -18.67，V10.12 -19.32）。TSP-1 的 -5.775 优于 generic 历史最好单路 -5.803。

## 5. 不同程序得到相同分数

**观察**：OBP 第 3 路在 E100–E800 间，71% 的有效程序与其所基于的程序分数完全相同（-744.5）；E800 之后出现结构明显不同的程序，把分数推到 -726。OP-2 的最好分 14.598 被多个不同程序复现。OBP 其余路径同分占比 12–27%。

**简单归因**：分数由有限训练实例上的选择结果决定；整数输入下不同公式可以做出完全相同的选择，分数分辨率到此为止。
