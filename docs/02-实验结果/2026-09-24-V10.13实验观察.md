数字固定在 **2026-09-24 11:32 +08:00** 快照：11 条路径完成 1000 次评价，其余进行至 451–931 次。2026-09-25 复核时，以下表各路径的评价编号为边界，截取 `events.jsonl`、`evaluations.jsonl` 与 `llm_calls.jsonl` 的对应前缀重算计数；生成与修复次数只包含该边界之前的事件。下文不代表最新进度或完赛质量；后续状态以 `experiments/traceaad_v10_13/results/batch_20260924_v1013r3.json` 和逐路摘要为准。2026-09-25 的[工作流水](../06-成果与报告/工作流水/2026-W39.md)还记录了运行恢复与实现收敛，旧快照的质量结果不能直接外推到收敛后的实现。

## 1. 响应无法解析

**观察**：17,556 次生成请求中 510 次（2.9%）未解析成可评价程序。按事件日志的 `reason` 前缀分类：

| 日志类别 | 次数 |
| --- | ---: |
| `format_error` | 335 |
| `edit_error` | 95 |
| `syntax_error` | 73 |
| `signature_error` | 4 |
| `target_function_error` | 3 |

**简单归因**：格式与编辑协议错误占多数，语法错误占少数。日志类别不能进一步证明每次失败都由某一种具体表述习惯导致。

**对比**：早期接口实验的固定快照中，同位置失败占 25.8%，集中在说明文字与 JSON 包裹导致内容无法识别。正式批次降到 2.9%，约九倍改善。

## 2. 程序运行失败

**观察**：17,046 次真实评价中 1,309 次（7.7%）程序进入评测后失败：940 次运行报错、290 次超时、79 次返回了无法作为分数的值。按任务：

| 任务 | 失败次数 | 主要现象 |
| --- | ---: | --- |
| TSP | 484 | 超时为主（275 次） |
| VRPTW | 366 | 报错为主，另有 69 次返回非法值 |
| CVRP | 215 | 报错为主 |
| OP | 210 | 报错为主 |
| OBP | 34 | 少量 |

**简单归因**：TSP 的超时大概与生成程序写得循环过深、构造过慢有关；VRPTW 的非法返回集中在少数重复出错的行为上（未逐条核实）。

**对比**：早期接口实验在同深度口径（每路前 50 次评价）的失败率为 5.84%，正式批次为 7.00%，略差但量级相近。

## 3. 失败后的修复

**观察**：失败后共发起 1,485 次修复请求（把原程序与错误信息送回重新生成）：1,152 次（77.6%）得到可运行且获得分数的程序，295 次修好后运行仍失败，38 次再次解析失败。修复产生 1,447 次评价，占全部评价的 8.5%。

**对比**：早期接口实验在 E50 截面中，修复占用评价 35.6%；正式批次这份快照为 8.5%。修复成功率接近。

## 5. 不同程序得到相同分数

**观察**：OBP 第 3 路在 E100–E800 间，71% 的有效程序与其所基于的程序分数完全相同（-744.5）；E800 之后出现结构明显不同的程序，把分数推到 -726。OP-2 的最好分 14.598 被多个不同程序复现。OBP 其余路径同分占比 12–27%。

**简单归因**：分数由有限训练实例上的选择结果决定；整数输入下不同公式可以做出完全相同的选择，分数分辨率到此为止。

## 6. 成本

**观察**：生成请求与评价之比 17,556 : 17,046 ≈ 1.03:1；日志 `usage` 合计输入 token 30.9M，输出 18.1M。

**对比**：早期接口实验在 E50 截面为 1.66 次请求/次评价（额外请求与修复带来）；正式批次的这份固定快照约为 1.03:1。
