# EoH-S

- 论文：*EoH-S: Evolution of Heuristic Set using LLMs for Automated Heuristic Design*；本地来源：`eohs.tex`；设计对象：一组协作/组合使用的启发式，而非单一启发式。

## 1. 核心问题与方法

EoH-S 指出单一启发式通常只能覆盖问题的一部分状态或实例分布，因此将演化对象扩展为启发式集合（Heuristic Set）：搜索目标从寻找单个通用启发式 $h$，变为寻找一组互补算法集合 $H=\{h_1, \dots, h_k\}$。

**评价与选择机制**：
- **个体评价**：每个算法在 $m$ 个训练实例上独立测试，获得实例级性能表现向量 $v(h) = (f(h, x_1), \dots, f(h, x_m))$；
- **集合覆盖指标（CPI）**：集合分 $\mathrm{CPI}(H) = \frac{1}{m}\sum_{i=1}^m \max_{h \in H} f(h, x_i)$，即每个实例上最优成员表现的平均值。**注意：这是事后 Oracle 聚合评价目标，假定面对每个实例已知哪个成员最优；它绝不等于无需额外成本即可获得的实际部署性能。实际部署面对未知新实例时，必须搭配成员选择器/路由器（消耗特征提取与分类模型开销），或对所有 $k$ 个成员全量运行一遍取最优（消耗 $k$ 倍实际求解时间与算力）**；
- **互补种群管理（CPM）**：从 $2n$ 候选个体中贪心选出 $n$ 个构成下一代集合（每步选取使 $\Delta \mathrm{CPI}$ 增益最大的个体，由目标函数的次模性保证近似比）；
- **互补选择算子（CS）**：计算个体间性能向量的 Manhattan 距离，挑选距离最大的父代对作为“互补代理”（非互补事实）进行交叉提示。

## 2. 论文宣称的机制贡献（逐项）

- 启发式集合利用多算法间的互补性覆盖异质实例分布；CPI 目标具有单调性与次模性，贪心选择具备 $(1-1/e)$ 近似保证。
- 互补选择算子（CS）以实例性能向量的 Manhattan 距离作为互补代理，提示双亲在不同实例上各有所长。
- 互补种群管理（CPM）是主要收益来源：消融中移除 CPM 退化为常规平均分保留（0.0373 vs 0.0326），说明集合级覆盖目标至关重要。

## 4. 机制的底层逻辑与关键边界澄清

1. **集合评价目标 $\neq$ 免费获得的部署性能**：
   CPI 衡量的是集合的潜在覆盖能力上限（假设面对新实例能自动分发给最优成员）。在真实部署中，“按实例选最优成员”需要额外的选择机制：要么提取实例特征调用学习型分类器（存在误选风险与计算开销），要么把集合内全部 $k$ 个成员并发或串行运行一遍取最优（消耗 $k$ 倍实际求解算力）。集合评价中的逐实例最优聚合不能自动成为无额外成本的部署策略。
2. **成绩向量距离大只是“互补代理”，绝非“互补事实”**：
   两算法在实例成绩向量上的距离大，既可能是由于优势区间正交互补（真正的互补），也可能仅仅是因为一个算法在所有实例上都全面劣于另一个算法（全面被支配）。一个在所有实例上都更差的退化算法，也可以与另一个优秀算法保持极大的欧氏/Manhattan 距离，但它根本没有增加集合覆盖。因此，成绩向量距离只能称为“互补代理”，绝不能视为“互补事实”。

## 5. 对 LLM4AD / TraceAAD 可学习之处

- **严格区分集合评价目标、成员选择策略与运行成本**：若探索启发式集合或组合求解，必须将“成员选择/路由机制的开销与误差”或“$k$ 倍求解开销”显式核算，不以理想 Oracle 掩盖部署成本。
- **互补性度量必须排除纯支配关系**：把向量距离视为互补代理而非互补事实；真正的互补必须以 Pareto 支配或在已覆盖集合外的边际增益（$\Delta \mathrm{CPI} > 0$）为准，避免将劣解当作互补伙伴。
