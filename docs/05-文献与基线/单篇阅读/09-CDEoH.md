# CDEoH

- 论文：*CDEoH: Category-Driven Automatic Algorithm Design With Large Language Models*；本地来源：`main.tex`；设计对象：启发式/算法代码（Online Bin Packing、TSP）。

## 1. 核心问题与方法

CDEoH 针对 LLM 启发式搜索易早熟收敛至单一实现范式的问题，提出**基于事后类别归纳的小生境种群选择**与**执行报错反思修复**。

**实际运行流程（信息路径追踪）**：
1. **单父代候选生成**：从当前种群采样单个父代，交替使用两类独立 prompt：**Improvement prompt**（局部参数与结构微调）与 **Innovation prompt**（重构 design thought、提出新求解范式），生成候选的 thought 与 code。**生成 prompt 中完全不包含类别标签或类别描述，也不使用两父代交叉**。
2. **执行评估与反思修复**：候选代码由 evaluator 运行评估；若发生执行报错，调用带 traceback 信息的 Reflection prompt 进行限次修复重跑（最多重试 $B$ 次），修复成功则保留其评价结果。
3. **类别归纳（事后标注）**：在候选生成与评估完成后，独立调用 LLM 根据该算法的 thought 与 code 归纳其算法类别标签并录入分类池。
4. **两阶段种群选择（类别唯一作用位置）**：更新种群时，第一阶段优先保留每个类别的 Top-1 算法（强制保留不同类别的精英代表）；第二阶段对其余候选按性能与稀有度综合分 $S_i = \text{norm}(f(h_i)) + \lambda / |C(i)|$ 择优截断。

## 2. 论文宣称的机制贡献（逐项）

- 算法类别建模与事后归纳：显式维护类别池管理已发现的算法范式（仅用于候选生成与评价之后的两阶段种群管理，不组织生成语义，不进入生成 prompt 上下文）。
- 两阶段种群选择：结合类别内 Top-1 保留与类别稀有度加成，主动维持范式级多样性。
- 生成指令拆分与反思修复：生成阶段使用单父代创新（Innovation）与改进（Improvement）两类独立指令；执行报错由带 traceback 的反思修复算子（Reflection）独立处理，将实现层修复与语义生成解耦。

## 4. 机制的底层逻辑

类别在 CDEoH 中充当的是**外层种群多样性管理的小生境（niching）过滤准则**，而非内层生成提示或上下文结构。其有效性依赖于：
1. 类别划分能否反映算法机制的实质差异；
2. 牺牲部分高分名额保护稀有类别，是否能在后续世代兑现突破。
生成侧的多样性实际由 Innovation prompt（强调 thought 重构）和温度采样承担，改进侧由 Improvement prompt 承担，错误处理由 Reflection 单独承担。

## 5. 对 LLM4AD / TraceAAD 可学习之处

- **信息作用位置严格解耦**：事后分析标签（如类别、策略类型）可用于多样性监控与外部保留决策，不必强行塞入生成 prompt 导致模型注意力分散。
- **算子功能专门化**：将“探索新路线（Innovation）”、“局部利用（Improvement）”与“错误修复（Reflection）”明确拆分为不同 prompt 机制，比笼统的单提示更可控。
- **风险防范**：纯依赖 LLM 文本语义划分类别极易陷入伪多样性（代码换皮不换行为）；TraceAAD 应以可执行状态、决策行为轨迹或性能互补性作为多样性判断基准。
