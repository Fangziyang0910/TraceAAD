# ELM（Evolution through Large Models）

- 论文：*Evolution through Large Models*；本地来源：`papers/Evolution_through_Large_Models/main.tex`；设计对象：可执行 Python 程序（Sodaracer 的生成程序）。

## 1. 核心问题与方法

ELM 问的问题是：通用遗传编程的局部、随机代码突变很难同时做多处相互依赖的修改。它把预训练的代码 diff 模型用作变异器：给定父程序和提交消息，模型采样 diff，应用后执行评估；主实验将其嵌进 MAP-Elites，以行为描述符维护多样化的高质量机器人。随后论文还把搜索所得程序作为数据，先微调生成器，再以地形条件和 RL 微调得到条件式发明器。这是“模型作为变异算子”与“搜索产物反哺模型”的三阶段流水线，而不是一个已验证的通用开放式学习结论。

## 2. 论文宣称的机制贡献（逐项）

- diff 预训练使一次变异能协调多处代码改动；提交消息提供可控的变异语义。
- MAP-Elites 保留不同 niche 的程序，令 LLM 变异不只追逐单一最优。
- 演化产生的数据可训练下游、按条件生成的模型。

## 4. 机制的底层逻辑

以下是阅读分析：代码 diff 的训练分布把“修改”而非完整程序作为条件分布，故它可能保持大段有效结构并在局部施加语义相关变化；MAP-Elites 使这些变化在多个行为区域累积。有效性依赖表示接口接近模型熟悉的 Python 风格，论文也报告该接口选择影响初始变异质量。它并不自动解决 evaluator 噪声、代码执行安全或模型把训练先验误当任务规律的问题。

## 5. 对 LLM4AD / TraceAAD 可学习之处

- 可学习点：把“父代—修改意图—结果”作为可审计生成上下文。成立前提：意图能和可执行改动对应。风险：文字意图只制造表面差异。最小验证：固定父代，对比有无意图时有效候选率和改进率。
- 可学习点：保留多条行为不同的成功支路。成立前提：描述符与任务质量相关。风险：人为 niche 稀释预算。最小验证：相同调用预算下比较轨迹覆盖和 held-out 分数。
