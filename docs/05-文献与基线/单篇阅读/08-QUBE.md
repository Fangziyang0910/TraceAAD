# QUBE

- 论文：*QUBE: Enhancing Automatic Heuristic Design via Quality-Uncertainty Balanced Evolution*；本地来源：`main.tex`；设计对象：启发式算法代码。

## 1. 核心问题与方法

QUBE 针对只按当前质量选父代会过早收敛的问题，在 FunSearch 框架内重定义两个决策点的优先级准则。质量项是**簇的进化质量** $Q_t(C)$——簇内样本历史子代的平均分（直接估计"当亲代的价值"，与簇自身分数区分）；不确定性项是 **UCB 式访问计数** $k\sqrt{\ln t/N_t(C)}$（$N_t(C)$ 为簇内样本被选为亲代的次数）。UIQ 用于亲代选择与岛重置（按各岛最高 UIQ 簇评估存亡，替代 FunSearch 的最高分规则）。

## 2. 论文宣称的机制贡献（逐项）

- 不确定性补偿能避免质量选择的过度开发。
- 质量与不确定性联合选择提高启发式设计效率。
- LLM 代码生成可在该反馈下维持更有价值的多样性。

## 4. 机制的底层逻辑与不确定性辨析

质量项 $Q_t(C)$ 把选择信号对准“当亲代的价值”（子代平均表现）而非“自身代码分数”，修正了选择信号的语义；不确定性项是基于访问计数的 UCB 形式，无需额外评价成本。

**必须严格区分两种本质完全不同的不确定性及其观测动作**：
1. **后代生成潜力的认识不确定性（Epistemic Uncertainty over Offspring）**：
   - **对象**：该父代/簇在给定提示算子下，还能生成何种分布的未知新算法（“这个父代还能产生怎样的子代”）；
   - **所需观测**：**向该父代分配算子与生成预算以采样新子代**并提交评估。**重复评价父代代码本身完全无法减少对后代分布的不确定性**。
2. **父代自身适应度的测试偶然不确定性（Aleatoric Fitness Noise）**：
   - **对象**：该父代程序自身由于 evaluator 随机测试实例采样带来的评分方差与噪声；
   - **所需观测**：在更多实例上**复评父代自身代码**以降低评分估计方差。

QUBE 的不确定性项 $k\sqrt{\ln t/N_t(C)}$ 针对的是第 1 类（访问/采样次数少，因而对该簇后代潜力的统计置信度低），其对应动作是**将该簇选为父代进行后续生成扩展**，而非对其执行复评。

此外，尺度耦合是其主要风险：最优 $k$ 跨任务相差 5 个数量级（OR3 上 0.0008，cap set 上 32），量纲完全依赖任务目标尺度，难以零样本跨任务迁移。

## 5. 对 LLM4AD / TraceAAD 可学习之处

- **探索原因与质量统计分离**：选父时将“该路线已知质量”与“对该路线后代探索的未充分程度”分别记录，但不能用纯粹的访问倒数掩盖退化路线。
- **动作与不确定性对象严格匹配（绝不统一写成“追加验证”）**：
  - **对子代价值不确定，不等于父代分数需要复评**；
  - 若不确定的是“该父代后续能否生成更好的算法变体”，正确的动作是**给予其扩展算子与生成调用**（采样新子代）；
  - 只有当不确定的是“该父代当前测试得分是否受评测随机性干扰”时，正确的动作才是**追加测试实例复评父代自身**；
  - 切忌将访问不足导致的生成潜力未知与评估噪声混淆，统一写成含混的“追加验证”。
