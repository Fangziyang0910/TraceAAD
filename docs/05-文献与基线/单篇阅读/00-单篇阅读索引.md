# LLM 自动算法设计方法阅读笔记

逐篇记录 71 篇 LLM 自动算法设计、广义程序发现与机制分析论文，覆盖 59 个方法与 12 篇机制分析、奖励进化、记忆理论与轨迹结构化研究。

## 证据口径：问题导向的证据分级与边界对齐

证据体系的核心原则是：**不要从“轻信整法结果”走向“没有全消融就什么也不能说”**。阅读笔记中的证据等级（直接支持、部分支持、间接支持、未验证、反向或混合证据）不是抽象的孤立标签，**必须严格对齐所判断的具体主张**。

例如，“某方法在所测基准上优于基线”的主张，可以由匹配协议下的整法比较**直接支持**；只有当主张变成“其中某个特定模块导致了提升”时，同一整法结果才是**间接证据**（需要针对该组件的受控消融来提供直接/部分支持）。既不能把整套方案的基准胜出等同于其内部所有细节设计都必然正确，也不应因为缺少个别模块的独立消融，就武断认为整法比较实验没有研究价值。

统一采用以下“问题—证据—边界”对齐框架：

| 要回答的问题 | 相应证据可以支持什么 | 不能顺带推出什么 |
| --- | --- | --- |
| **这套方案是否有效？** | 匹配协议下的整法结果（直接支持该方案在所测环境中的整法有效性） | 不能顺带推出每个组件分别有效 |
| **这个改动是否改变行为？** | 输出分布、有效率、修改幅度及求解质量等过程统计（直接支持行为改变） | 不能顺带推出行为变化一定提升最终搜索 |
| **某组件是否贡献结果？** | 针对该组件的匹配消融与受控比较（直接/部分支持该组件有贡献） | 不能顺带推出在所有任务和模型上都成立 |
| **某指标是否适合在线决策？** | 前瞻预测检验或使用该信号后的实际决策收益（直接支持控制可用性） | 不能顺带推出事后相关性已经证明在线可控性 |
| **某理论是否适用于 TraceAAD？** | 概念严格映射且满足其理论假设前提（直接支持理论借鉴） | 不能顺带推出相似术语即构成同构理论保证 |

### 五类证据等级的精准界定

- **直接支持**：实验证据与所评估的主张严格匹配。若主张“整套方案在测试基准上有效”，则匹配协议下的端到端对比即构成直接支持；若主张“某特定模块贡献性能”，则必须有针对该模块的独立受控消融或单变量替换；
- **部分支持**：证据直接关涉该主张，但存在变量混杂（如同时变动了提示词与种群大小）、仅在部分任务成立、或主要依赖过程观测指标而缺乏最终性能隔离；
- **间接支持**：证据无法直接对应所声称的主张，只能作为高层关联推论的旁证（如仅凭整法胜出推断特定组件的优越性，或仅凭事后静态相关性推测其具备在线控制力）；
- **未验证**：论文提出了该机制假说或概念设计，但未在正文或附录中提供能够检验其独立作用的针对性数据与受控比较；
- **反向或混合证据**：实验数据明确不支持该主张，或在跨任务、跨模型、跨预算设置下呈现方向相反的不一致结论。

**核心方法论准则**：
> **既不把联合方案胜出解释成所有细节都正确，也不要求所有细节完成独立消融后才承认联合方案有研究价值。**

### 文献笔记与科研认知的信息流规范

单篇笔记负责忠实理解作者；专题综述负责比较机制；knowledge 负责形成我们自己的独立判断。信息流应当严格单向演进：

$$\boxed{\text{原文事实} \longrightarrow \text{单篇笔记} \longrightarrow \text{跨文献机制比较} \longrightarrow \text{TraceAAD 的条件性认识}}$$

**严禁反向叙事**：不能先确定 TraceAAD 最新立场，再把每篇文献改写成对其立场的支持材料。

**单篇笔记第 5 节（对 TraceAAD 可学习之处）的四问结构**：
1. **对应疑问**：它对应我们当前体系中的哪个具体科学或实现疑问？
2. **影响环节**：它实际改变了系统闭环中的哪个具体机制环节（搜索决策、上下文构建、生成核还是评估更新）？
3. **推导边界**：论文给出的证据允许我们将结论推到哪里？
4. **决策取舍**：当前阶段为什么采纳或暂不采纳？
> “最小验证实验”作为有条件的备选思考，不必每篇都机械衍生一个新实验任务，避免被海量算子、分类器与复杂外壳带偏当前主线问题。

## 跨论文认识

71 篇笔记共记录 283 项“主张—证据”判断。

> **特别提示**：这里的 283 项判断只是逐篇阅读笔记中的条目计数，用于辅助把握文献内部的论证颗粒度，**绝非形式化的定量元分析**，更不能把来自同一实验或论文的多个条目判断误当作独立重复的实证证据。

### 1. 最稳定的共同基础是可执行外部反馈

ELM、Evolving Code 和 FunSearch 说明，LLM 的程序先验只有进入执行—评价—选择闭环后，才会转化为可积累的算法改进；Understanding the Importance of Evolutionary Search 在统一基准下给出量化版本：最小 (1+1) 循环 500 次查询超过独立采样 10000 次，且搜索增益在任务×模型格间高度不均匀。底层逻辑是 evaluator 把语言上合理的候选筛成满足任务目标的可执行程序。可学习之处是先保证 evaluator 的可行性、方向、超时和测试边界可靠；否则更强的搜索只会更快利用评价漏洞。

### 2. LLM 的优势在语义变化，但变化幅度必须受控

Language Model Crossover 支持 LLM 从多个父代产生可继承的语义组合，Controlling Mutation 则直接显示提示控制会改变变异比例和代码差异。底层逻辑是 LLM 可以调用预训练得到的程序修改先验，跨越随机字符串或语法树变异难以协调的修改。可学习之处是记录“父代—修改意图—实际 diff—评价结果”，并在固定预算下验证修改是否带来行为差异，而不是只统计文本新颖性。

### 3. 历史有用的关键是可追溯，不是摘要越多越好

DeltaEvolve 的受控比较支持代码上下文比只有标量分数更有信息；ReEvo、HiFo-Prompt 和 PathWise 分别探索反思、前后视提示和路径反馈，但独立证据强度并不相同；LinTree 的显式树拓扑来自小模型 SFT/GRPO 微调且在推箱子上仍低于 BFS(RL)，Experience Memory Graph 依赖具正确性保证的专家轨迹而 AAD 的 best-so-far 并无此保证，Memento 2 的双时间尺度渐近收敛和慢更新假设不能直接证明有限预算 AAD 或推迟记录事实——这些工作提供表示、检索与信用分配的良好启发，但**严禁直接当作 TraceAAD 的理论证明，无法对应处绝不能用“同构”略过**。底层逻辑是历史改变下一次生成的条件分布；只有历史与真实父子边、操作和结果绑定，模型才可能区分可延续变化与失败。可学习之处是优先保留结构化 action–result 事实，再检验摘要或记忆是否在相同 token 预算下产生额外增益。

### 4. 树和规划首先是预算分配机制

Planning of Heuristics 对搜索策略进行了受控比较，PathWise 对 critic 和提示多样性给出消融，Compute Allocation / BaSE 直接研究深度与广度的调用分配，Code Repair EET 给出分配层的理论模板（失败计数 Beta 后验 + Thompson 采样）；MCTS-AHD 的整法结果则直接支持其整套方案在所测基准有效，但不能自动证明 UCT、回传和渐进扩展各自独立有效。底层逻辑是搜索结构决定有限预算落在哪些候选和路线，而不替代 LLM 单步生成。可学习之处是分开评价起点选择、下一步生成和最终输出，并同时报告 evaluator 次数、LLM 调用和 token。

### 5. 多样性只有转化为有效路线覆盖才有价值

MEoH、HSEvo、QUBE、CDEoH、EoH-S、ShinkaEvolve 和 RoCo 分别用 Pareto、和声搜索、不确定性、类别、启发式集合、过滤或角色维持多样性，其整套方案在各自基准上展现出有效性，但具体多样性组件的独立因果贡献多数为部分支持。同时须注意避免两类常见迁移误读：
- QUBE 中对后代生成潜力的认识不确定性，需要分配生成调用采样新子代来减少，不等于对父代自身测试分数进行“复评/追加验证”；
- EoH-S 的集合 CPI 是逐实例 Oracle 评价上限，并不等于可免额外成本获得的部署性能（部署需路由选择器或全量运行全部成员取优），其实例成绩向量距离仅是“互补代理”而非“互补事实”。
底层逻辑是多样性可能降低搜索路线的相关性，增加至少一条路线突破的机会；代价是稀释有限评价预算。可学习之处是测量算法行为、路线贡献和 held-out 结果，不把代码差异、角色名称或 embedding 距离直接当成有效多样性。

### 6. 扩大设计对象会增加表达力，也会扩大无效空间

RedAHD、Hercules、A2DEPT 和 BEAM 将设计对象扩展到问题规约、搜索方向、程序组件或完整求解器。底层逻辑是固定单函数模板可能排除真正需要的结构变化；同时，更大的表示空间会增加不可执行候选、错误归因和 evaluator exploit。可学习之处是每次只扩大一个可验证层次，并报告合法率、有效候选率、复杂度和独立测试表现。

### 7. 把搜索经验写入模型，需要与在线搜索分开证明

CALM、EvoTune、Fine-tuning LLM for AAD、AHD Agent 和 Beyond Inference-Time Search 分别用 GRPO、搜索反馈训练、DPO、agentic RL 或 solver synthesis 内化设计能力。底层逻辑是参数学习可以摊销未来搜索成本，但也可能只记住任务模板、可执行格式或 evaluator 偏好。可学习之处是将训练成本与在线搜索成本分开，并用权重固定的模型、固定代码和未见实例检验能力是否真正转移。

### 8. 历史应按作用范围分层，且不是越长越好

MEMOIR 的受控消融支持分离 branch-local 调试事实与 global 跨路线知识，并显示失败记录本身有价值；DGA²D 的组件信用转移讨论的是单个求解器 Pipeline 内部功能组件的前后调用执行拓扑，**既非外层搜索的祖先演化谱系，亦非 LLM 提示词的上下文长度**，其“full-path 较差”不能直接证明“TraceAAD 只应使用短历史”。底层逻辑是组件或步骤组合存在偏差—方差权衡：过度细分的组合路径需要过多真实样本来估计信用。对 TraceAAD 的真正启发是组件价值依赖运行环境上下文，应完整保存可重放事实，生成时按当前动作挑选局部相关事实送入 prompt。

### 9. 算子本身会收敛，多样性要测行为而不只测代码

Mutation Without Variation 在移除选择压力后仍观察到结构 attractor、自环和短周期；Fitness Landscape 显示经验景观无漏斗、低连通，Code Evolution Graphs 显示不同 LLM 的代码指纹互不重叠且复杂度默认单调上涨；What Makes an LLM a Good Optimizer 在 15 模型 × 8 任务进化实验中显示，世代级严格局部改进率（LRR）相对平均新颖性展现出显著更高的统计解释力，新颖性仅在局部化条件下显出正向交互（说明优质区域的持续小步精炼是重要的关联特征，而非脱离任务与协议的绝对因果铁律）；Behaviour Space Analysis 支持双意图提示 + 精英保留；BehaveSim 与 PartEvo 分别说明执行轨迹和有意义特征构造的 niche 比随机或静态表面差异更能组织搜索。在分析时必须严格区分【形成谱系】、【搜索几何】、【求解行为 PSTraj】与【Pipeline 拓扑】四类不同轨迹；行为距离高但未改善不能立即判为无效漂移，行为距离低也不能直接武断判为停滞，它们应首先作为条件性诊断信号，而非自动触发分配的排他结论。

### 10. 外部知识只有与当前失败证据对齐时才稳定有用

GeoEvolve 让代码诊断触发领域文献检索；其静态知识 prompt 在部分指标退化，而动态检索完整系统更好。AutoSND 进一步把执行证据编译成结构政策。可学习之处是保存“失败状态—查询—证据块—代码修改—结果”的闭环 provenance，不把增加上下文长度本身当成知识机制。

### 当前最可靠的研究顺序

这些论文共同支持的不是某个复杂控制器必然最优，而是一条较稳妥的验证顺序：先建立可靠 evaluator 和可重放 lineage，再验证上下文是否改善单步生成，然后在相同评价与调用预算下验证路线选择，最后才考虑共享记忆、系统级表示扩展或模型参数训练。联合方案在基准上的胜出直接支持其整套配方的工程有效性；若要断言具体哪个细节机制起关键作用，则必须依靠严格的单变量消融。
