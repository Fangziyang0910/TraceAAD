# PhyloEvolve

- 论文：PhyloEvolve: LLM-Powered Evolutionary Code Optimization on a Phylogenetic Tree；本地来源：main.tex，含 `4_method.tex`、`5_experiments.tex`；设计对象是代码优化的谱系树搜索。

## 1. 核心问题与方法

PhyloEvolve 将候选代码及其亲缘关系组织为系统发育树，而非只保留平坦种群或单条链。每个分支代表从祖先出发的一组修改；LLM 在祖先、子代和表现上下文中扩展分支，以在保留多样历史的同时选择值得继续的谱系。

## 2. 论文宣称的机制贡献（逐项）

1. 用系统发育树显式保存代码演化关系。
2. 通过谱系级选择平衡探索与利用，减少过早丢弃有潜力分支。
3. 在代码优化任务上提高有限预算效率。

## 3. 实验究竟支持了什么

|机制主张|论文证据（具体表/图/消融/章节）|证据等级|判断|
|---|---|---|---|
|整体优化表现|`tex/5_experiments.tex` 的 LLG、LTSA、GraphWave 加速图|直接支持（整法有效性）|匹配协议下的加速与优化表现直接支持 PhyloEvolve 方案在所测工作负载上的整体有效性；不能顺带证明谱系树或轨迹复用各自独立有效（因果消融仍属未验证）。|
|树/谱系组织有益|本地正文未发现平坦树对照或仅移除谱系结构的受控消融|未验证|不以加速图、方法描述或作者解释补足树结构因果。|
|谱系带来多样性|方法图和分支案例|间接支持|结构存在不等于多样性是性能原因。|

## 4. 机制的底层逻辑

阅读分析：树把“当前分数”与“来自哪个改进方向”分开保存，使低分但尚未充分扩展的家族仍可获得机会。其有效性依赖分支评分能预测后继潜力；否则树只是更昂贵的候选索引，且会把 token 预算分散到过多浅分支。

## 5. 对 LLM4AD / TraceAAD 可学习之处

|可学习点|成立前提|主要风险|最小验证方式|
|---|---|---|---|
|以轨迹/分支而非孤立程序作为搜索单位|父子边可恢复|树形记录增加复杂度却无决策作用|同预算比较保留谱系/只保留 best 的后续改进率。|
|给未充分验证的新分支保留少量扩展额度|评价噪声或迟发收益确实存在|浪费预算在弱支|记录每个分支扩展次数与首次/后续增益。|
