# 进化搜索怎样分配探索与开发机会

## 结论

成熟机制可以提供清楚的对照，但“更成熟”不能替代与当前搜索问题的适配验证。最容易直接用于 TraceAAD 的是锦标赛或排名选择；年龄淘汰控制可继续开发的种群，自适应算子选择控制 Refine/Fuse/Pivot 的机会，MAP-Elites 控制不同实际行为的保留。这几类方法作用在不同决策上。

第一轮优先检验两个问题：次数衰减是否有收益，以及有效竞争规模随全档案增长是否合适。锦标赛适合作为随后更换选择函数的对照。年龄淘汰和行为档案涉及更大的结构变化。

## 1. 锦标赛与排名选择：直接改变父代分布

锦标赛从可用节点中有放回均匀抽取 k 个，选评分最高者；并列时随机选择。k 控制选择压力，k=1 是均匀父代抽样。排名选择根据次序分配概率，保留评分的顺序信息。Blickle 与 Thiele 系统分析了锦标赛、线性排名、指数排名等选择方法的选择强度、方差和多样性损失，并讨论二元锦标赛与线性排名的联系。[作者机构技术报告，第 3、5、6 章](https://tik-old.ee.ethz.ch/file/6c0e384dceb283cd4301339a895b72b8/TIK-Report11.pdf)

**适配判断：**这两类规则可直接选择现有节点，无须为每个新节点估计未来回报。它们对保序的评分变换不敏感，适合不同任务的评分尺度。代价是舍弃分差大小：非常接近的第一、第二名，与明显领先的第一、第二名，会得到相同的排名待遇。大量同分时必须保持对称，不能按节点 ID 或插入顺序拆出假优劣。

### 参数不能凭“常见”直接比较

以下是本文的数学推导，用于设计对照，不是引用论文的实验结果。无并列时令 r=1 为最差、r=N 为最好，有放回 k 元锦标赛选中第 r 名的概率为：

$$p_r=(r/N)^k-((r-1)/N)^k.$$

N 较大且 k 固定时，概率密度近似为 k x^{k-1}，从而：

$$\frac{\mathrm{ESS}}N\approx\frac{2k-1}{k^2}.$$

| k | 近似 ESS/N |
|---:|---:|
| 2 | 0.7500 |
| 4 | 0.4375 |
| 10 | 0.1900 |
| 20 | 0.0975 |

因此，当前质量分布目标约为 0.1N 时，直接换成 k=2 或 4，会同时明显放宽分布。若结果改善，只能说明这一组合改变有帮助。要区分评分间隔与排序的作用，应优先比较实际 ESS 接近的分布。k=20 只是在大 N、无并列条件下的起点；小档案或大量同分时应计算精确概率并核对实际 ESS。

## 2. 年龄淘汰：控制哪些节点持续参与搜索

Real 等人的 regularized/aging evolution 维护大小为 P 的活动种群，使用 k 元锦标赛选父代；每次加入评价后的子代，删除活动种群中最老的个体。所有历史结果仍可保存在独立档案中，最终返回历史最好者。原文实现为有放回抽样，NAS 实验使用过 P=100、k=25，并比较了多种配置。作者对缓解训练噪声的解释带有假设性质，另用带噪声的简化问题检验其合理性。[原论文算法 1、Methods Details 与 Discussion](https://arxiv.org/html/1802.01548)

**适配判断：**有限活动种群能避免全档案不断扩大，并保证成员持续更新。但年龄只是出生先后，未直接衡量一条路线是否值得继续开发。LLM 的突变可以跨越很大，固定评价面板的噪声也可能小于 NAS 训练噪声，所以不能直接移植其正则化解释。

独立检验年龄规则需要保持父代选择一致，只比较“全档案可选”与“最近 P 个有效节点可选”；若同时换锦标赛和淘汰规则，属于整个搜索器的对照。P 需要依据预算与实际节点增长确定，论文中的 100 不是 TraceAAD 的现成最优值。档案和真实形成历史仍可保留，活动资格与证据存储应分开。

## 3. 自适应算子选择：把反馈用于三个算子的配额

Da Costa、Fialho 等人的 Adaptive Operator Selection 将“怎样计算算子回报”和“怎样按回报选算子”分开。其动态多臂老虎机方案用 UCB 配合 Page–Hinkley 变化检测，在检测到分布变化后重置统计。2008 年论文主要在人工变化场景中检验调度规则，不能把它当作 LLM 算法生成的直接效果证据。[原论文第 2—4 节](https://gpbib.pmacs.upenn.edu/gecco2008/docs/p913.pdf)

**适配判断：**对 TraceAAD 而言，固定的 Refine、Fuse、Pivot 三个动作比持续新增的数百个节点更容易积累统计。它能检验固定算子比例是否合适。但观察到的算子收益混合了父代质量、donor、任务和搜索阶段；更新统计无法自动消除这些影响。

参数包含回报定义、探索强度、检测阈值等。若使用近期窗口，还需窗口长度。以单步正增益为回报，会偏向容易立即兑现的改进，可能压制需要中间退步的换向。因此第一步应先做按阶段与父代分位数分层的算子效果统计，再决定是否值得启动在线适应。

## 4. MAP-Elites：把探索定义为实际行为覆盖

MAP-Elites 用预先选择的特征描述行为区域，每个区域保存其中评分最高的个体；基础版本从已占用区域随机选精英，变异后按行为区域竞争。其目标兼顾区域覆盖与区域内质量。[Mouret 与 Clune 原论文算法 1](https://arxiv.org/html/1504.04909)、[作者教程](https://github.com/jbmouret/map_elites_tutorial)

**适配判断：**它直接针对“不同代码执行相似决策”这一可能瓶颈；有效的行为描述可以让少见路线保有开发入口。但描述维度、分箱尺度、探针状态与计算成本会成为新的关键设计。代码长度或文本距离并不能天然代表算法行为。这更适合作为后续机制研究，当前可以先对真实候选做只读行为探针，检查是否存在足够清楚的多样性塌缩。

## 5. 对当前规则的单因素实验建议

当前 V10.8 的 `node_distribution` 先按评分校准 beta，再施加平方根次数衰减，Pivot 再混合均匀概率；质量 ESS、衰减后 ESS 与算子条件 ESS 是三个不同量。当前实现

| 候选 | 唯一主动改变 | 检验的问题 | 观察重点 |
|---|---|---|---|
| 无次数衰减 | 指数从 1/2 改为 0 | 已开发节点的统一降权是否帮忙 | 重复开发收益、父代集中度、最终质量 |
| ESS 上限 | 目标改为 min(N,max(2,min(0.1N,K))) | 后期随档案增长的有效竞争规模是否过宽 | 后期前沿增益、未开发节点等待时间、实际 ESS |
| 强度匹配的排名/锦标赛 | 替换质量概率，其余不变 | 评分分差是否提供有用信息 | 实际选择强度、同分处理、跨任务稳定性 |
| Pivot 均匀混合比例 | 只调整均匀系数 | 换向起点的额外分散是否必要 | 低分起点的真实行为变化及后代收益 |

这些都是待验证的假设。ESS 上限 K 应依据现有档案规模选一个事先声明的诊断值；它增加了有限开发宽度这一假设，而非自动成为更成熟的策略。大量最高分并列会限制可达 ESS，需要报告实际值与目标的偏差。排序方案保留次数衰减时，最终集中度仍会受次数影响。

若本轮仅有 12 路，优先让“基线＋两个单因素方案”覆盖“两个有差异的任务×两次重复”，作为筛选实验。两次重复只足以筛选方向；推广到全部任务或断言小幅优越仍需后续重复。若已有完全同版本、同预算、同配置的基线可以复用，才可以把空余并发用于更多重复。不要把旧 V10.7 或去重前 V10.8 的结果当作严格基线。

预先固定预算和配置，比较同评价预算的终局及曲线，同时报告生成调用与 token 成本。历史轨迹上的重新计算只能显示新分布会把机会投向哪里；生成结果会随选择改变，无法由旧档案回放得到新机制的终局收益。
