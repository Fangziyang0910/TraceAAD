# 自动算法设计与模型训练结合的方法

从现有 60 篇逐篇阅读论文中，筛选把**算法设计数据或反馈用于模型参数更新**的方法。这里的“模型训练”不应统称为笼统的“模型”，而必须细分为：**代码生成 LLM**、**搜索控制策略**、**程序连续表示/流映射**或**性能 surrogate**；只使用提示词、反思、经验库、多智能体协作或已训练模型提供候选，不算作训练型闭环。

按这一口径，共筛出 **10 个独立方法家族、10 篇论文**。注：*Evolving Code with a Large Language Model*（Hemberg 等，MIT CSAIL）是独立的 LLM-GP 算子代数形式化框架，并非 Lehman 等人的 ELM 技术谱系（不含 diff 模型、Sodaracer 或 MAP-Elites）；按训练型闭环标准独立复核，其全程基于预训练 GPT-3.5 零/少样本提示，**未对任何模型参数进行微调或更新**，因此明确排除在训练方法表之外（详见第四节）；Teacher-Aware Evolution 使用预训练外部教师，但 AAD 过程不更新教师或设计 LLM，同样不计入。

## 一、方法总览

| 方法家族 | 范围 | 训练对象 | 训练信号来自哪里 | 训练与搜索的关系 | 当前证据判断 |
| --- | --- | --- | --- | --- | --- |
| ELM | 广义程序发现 | 代码变异生成模型（CodeGen 微调）与 RL 条件策略 | 演化搜索产生的程序、diff、地形条件和任务回报 | 搜索先产生数据，再微调生成器并进行 RL 条件化 | 搜索数据支持下游条件生成，但阶段耦合、任务窄，属部分支持 |

| EvoTune | 直接 AAD/AHD | 算法程序生成 LLM（1–2B 开源小模型） | 进化数据库中的程序表现与偏好对 | 进化持续供给训练样本，DPO／ReST-EM 改变后续采样分布 | 无训练搜索基线支持加入训练阶段这一整包机制的收益；未必隔离训练阶段内部每个设计，且总训练算力需另计 |

| Beyond Inference-Time Search / Hero | 广义算法发现 | 直接生成完整 solver 的代码模型 | 格式、执行、结构、可行性和目标质量分层奖励 | 用 GRPO 把实例内搜索摊销成一次生成、跨实例复用的 solver | 固定 solver 跨 held-out 实例复用获直接支持；RL 相对 base pass@k 获部分支持 |

| AlgoPilot | 广义程序发现 | Trajectory LM 与排序 RL policy | 随机 Python 程序轨迹；排序环境和 TLM 软奖励 | 先训练轨迹先验，再引导 RL 产生可恢复程序轨迹 | 能恢复 Bubble Sort，但最终依赖已知算法的 GPT-4o-mini，证据混合 |
| LLaMEA-SAGE | 直接 AAD/AHD | 结构—性能 surrogate（代码生成 LLM 冻结） | archive 中 AST/控制流特征与真实 fitness | 在线重训 surrogate，以 SHAP 反馈指导固定 LLM mutation | 与 vanilla LLaMEA 的受控比较支持结构反馈；surrogate/SHAP 未分别消融 |

## 二、按训练—搜索耦合机制分类

### 1. 搜索产物作为离线训练数据

ELM 和 Fine-tuning LLM for AAD 都先运行搜索或采样，再把高质量程序、条件标签或偏好对写入训练集。训练完成后，新的模型作为更强的生成先验重新进入搜索。

```text
候选生成 → evaluator → 程序数据／偏好对 → 模型微调 → 新一轮生成或搜索
```

底层逻辑是把一次搜索中反复发现的可执行结构压缩进参数，使模型提高“首次采到可用变体”的概率。它最容易审计，因为训练和搜索可以分别固定后比较；主要风险是训练集只保留赢家，导致幸存者偏差、模式坍缩和程序族泄漏。

当前证据中，Fine-tuning LLM for AAD 最强：它在相同 EoH/FunSearch 框架下比较 base 与 fine-tuned 模型，并报告 ASP、CVRP 和论文定义的 OOD 设置。ELM 证明了演化数据可以支持条件生成，但搜索、微调和 RL 阶段交织，且集中于 Sodaracer/4-Parity。

### 2. 搜索与模型在线共同更新

CALM 和 EvoTune 不把训练放在搜索结束以后，而是在搜索过程中反复用新评价结果更新生成模型。

```text
当前模型采样候选
  → evaluator 给出可行性与质量
  → 候选进入种群／数据库
  → 评价结果更新模型参数
  → 更新后的模型产生下一批候选
```

这类方法的关键不是简单“边搜边训”，而是数据分布和 policy 同时变化：更好的搜索算子产生更有学习价值的数据，更新后的模型又改变后续搜索空间。CALM 使用父代相对 reward，尝试避免把强父代的已有质量全部归因给子代 response；EvoTune 用进化程序数据库为 DPO 或 ReST-EM 提供反馈。

CALM 的 `w/o GRPO` 是目前较有辨识度的在线训练消融对照（证实去掉在线 GRPO 参数更新会导致性能大幅下滑），但仍不能分离 GRPO 优化器、训练数据闭环与特定算子的耦合。EvoTune 原文明确比较了同构的无训练（FunSearch-style）基线，共享 prompt 构造、数据库/岛架构和评估协议，仅关停 RL 更新。无训练搜索基线支持加入训练阶段这一整包机制的收益；但该对照检验的是训练阶段整包引入的整体增益，未必隔离全历史采样覆盖、百分位退火调度、从基模型 $\pi^0$ 重启等内部每个设计的独立贡献，且总训练算力需另计（未计入对齐预算中）。

### 3. 训练算法设计过程的控制策略

AHD-Agent 训练的重点不是单次代码分布，而是长程设计策略：模型学习何时提出方案、何时运行 evaluator、怎样读取工具反馈、何时修改或停止。它把固定的进化循环替换成可学习的 agent policy。

底层逻辑是把信用从“某个程序最终得分”扩展到“产生该程序的一串设计动作”。这与 TraceAAD 的轨迹结构接近，但多了一步参数化信用学习。困难也更大：若不保存动作、观察、候选 lineage 和每步成本，就无法判断收益来自策略学习，还是来自更多调用、更多工具或更长上下文。

论文支持完整 agentic 系统、训练域混合规模和工具组合的作用，但没有完全匹配的 frozen-policy／RL-off 对照，因此尚不能单独证明长程 RL 控制优于同预算的固定搜索器。

### 4. 直接训练可复用求解器生成策略

Hero 不以“让在线搜索器更会搜索”为最终目标，而是用 GRPO 训练模型一次生成完整 solver。生成代码固定后在同一问题类的多个 held-out 实例上重复执行，将训练成本摊销到未来调用。

其奖励先处理格式、执行和可行性，再优化目标质量。这种分层适合算法代码的稀疏奖励：不可执行程序没有必要直接比较解质量。论文的固定代码实验直接支持 solver 可跨实例复用；但“比 inference-time search 更便宜”的解释必须计入训练成本，不能只比较部署阶段的 LLM 调用。

### 5. 训练辅助表示与性能模型

**训练对象不能统称为“模型”**：生成 LLM、动作控制策略、程序连续表示、性能 surrogate 分别对应系统的不同功能环节。**冻结代码生成 LLM 绝不等于系统没有学习**：
- LLaMEA-SAGE 冻结代码生成 LLM，在线重训的是结构—fitness 代理模型，并用 SHAP 转成提示反馈；
- Latent Heuristic Search（LHS）同样**冻结了预训练代码编码器（UniXcoder/Embedding 模型）与解码代码 LLM**（不存在联合训练/微调 encoder），其训练对象是 Normalizing Flow（$f_\psi$）、Latent-to-Soft-Prompt Mapper（$M_\omega$）和可微任务 Surrogate（$S_\theta$），在学出的潜流形上进行梯度引导搜索。应当严格区分潜空间优化步骤（纯神经网络前向与反向，零 evaluator 成本）与最终解码候选由真实 evaluator 进行的真实评价。

这条路线的优势是训练目标与主生成器解耦，更新成本较小；风险是 surrogate 只拟合已访问分布。最小证据必须同时报告预测校准、越界距离、可执行率和执行后的真实增益，不能用 surrogate score 代替 evaluator。

### 6. 发现—训练—再发现的递归闭环

Self-Developing 是最清楚的顶会实例：生成模型合并代码，以合并后模型成绩构造 DPO 对，更新 algorithm factory 后再生成新算法。它说明算法产物可以反过来改变算法生成器，但目前跨迭代趋势没有排除累积采样和 seed model 同时变化。

GAE 则把递归闭环拆为图表示学习、mutation-type controller 和在线 GRPO 三条训练链。架构上职责清楚，实验证据上却高度耦合；在借鉴前必须补 frozen LLM、uniform controller、stale GNN 的独立与组合消融。

### 7. 从执行轨迹学习程序先验

AlgoPilot 使用随机程序产生的执行轨迹训练 TLM，再把 TLM 作为 RL 的密集软约束。这与“训练算法设计 LLM”不同，却直接说明轨迹模型可以塑造候选程序的路径结构。其主要边界是最终 trajectory-to-code 仍调用懂 Bubble Sort 的 GPT-4o-mini，因此更适合看作概念验证。

## 三、哪些训练机制目前最值得信任

按证据辨识度，而不是按论文最终分数排序：

1. **微调模型确实可以提高固定搜索器的候选质量和搜索效率。** Fine-tuning LLM for AAD 在相同搜索框架下比较 base/fine-tuned 模型，是这一主张最直接的证据。
2. **在线参数更新能改变搜索结果，但具体收益仍与数据闭环耦合。** CALM 的 GRPO 消融和 EvoTune 的无训练对照均支持加入训练阶段这一整包机制的收益，却没有证明任意内部配方都独立有效。
3. **可行性—质量分层奖励适合完整 solver 训练。** Hero 的结构、硬 gate 和固定代码实验共同支持这一方向，但不同 reward 项的独立贡献仍未完全分离。
4. **搜索轨迹可以成为训练数据。** ELM 证明了可行性，CALM/EvoTune 将其变成在线闭环；目前仍缺少对 lineage 完整度、失败样本保留和数据选择偏差的系统消融。
5. **长程 agent policy 是否优于清晰的固定控制器仍未定论。** AHD-Agent 展示了端到端能力，但因缺同预算 RL-off 对照，证据尚不足以把优势归因给 agentic RL 本身。

## 四、容易误纳入、但不属于本筛选的工作

- **Evolving Code with a Large Language Model**：该论文是 Hemberg 等人（MIT CSAIL）提出的独立 LLM-GP 算子代数形式化框架，并非 Lehman 等人 ELM 工作的延续或期刊版（不含 ELM 的 diff 模型、Sodaracer 或 MAP-Elites）。按训练型闭环标准独立复核：其实验全程基于预训练 GPT-3.5-turbo 的少样本 prompt 补全，**全程未训练或微调任何模型参数**，不属于参数更新范畴。
- **RoCo、CORAL**：使用多智能体角色、协作和记忆，但没有训练模型参数。
- **HiFo-Prompt、ReEvo、DeltaEvolve**：把历史写入提示、反思或语义增量；这里的“蒸馏”是文本经验压缩，不是参数训练。
- **PathWise**：使用 policy/world-model critic 组织规划，但现有论文笔记没有显示在 AHD 搜索中训练这些模型参数。
- **MoH**：外层搜索的是可执行 meta-optimizer，论文中的“训练／测试”主要指任务划分，不等于梯度更新 LLM。
- **Evolutionary Discovery of RL Algorithms**：候选 RL 算法在 evaluator 内训练策略网络（即被生成的算法在解题时训练模型），但**外层算法设计器（LLM）本身并未被训练**。在 evaluator 内训练被设计的算法，绝不等于训练算法设计器。
- **Teacher-Aware Evolution**：外部 teacher policy 在进入 AAD 前已独立训练，搜索期间只查询其动作偏好；它是 learned feedback source，不是 AAD feedback 驱动的参数更新。
- **FunSearch、EoH、MCTS-AHD 等**：使用固定模型进行 inference-time 搜索，没有把 evaluator 反馈写入模型参数。

## 五、对 LLM4AD / TraceAAD 的直接启示（四个核心问题）

不再以“搜索最终必然转向 RL”作为预设路线，而是围绕学习机制的实质回答四个核心科研问题：

### 1. 学习发生在哪里？（训练对象解耦）
- 训练对象不能统称为笼统的“模型”，必须拆分为：**代码生成 LLM**、**动作控制策略**、**连续程序潜流形**与**性能 surrogate**；
- **冻结代码生成 LLM 绝不等于系统没有学习**（如 LHS 冻结 LLM 但学习流模型与代理，LLaMEA-SAGE 学习结构代理）；
- 在 evaluator 内部训练被设计的解题策略（如被设计算法跑 PPO），属于求解算法的执行机制，绝不等于外层算法设计器发生学习。

### 2. 学习了什么？（目标与先验形式）
- 离线微调（Fine-tuning AAD）学习高质量可执行算法的代码语法与结构先验，提升首次命中可用候选的概率；
- 在线参数更新（CALM / EvoTune）通过成对偏好或相对父代奖励学习局部变异方向；
- 潜空间与代理模型（LHS / LLaMEA-SAGE）学习连续嵌入空间中的平滑流与适应度地形梯度；
- 智能体策略（AHD-Agent）学习长程设计动作序列与工具调用控制。

### 3. 付出了什么成本？（显式计账与资源公平性）
- 训练算力绝不能在对比中隐形消失：在线更新消耗的额外 GPU 训练 FLOPs、离线构建训练集消耗的巨量采样评估，必须与 inference-time 搜索预算严格分账；
- 不能在仅对比部署期 LLM 调用量时，片面宣称参数化方法“成本更低”或“预算对齐”。

### 4. 证据隔离到哪里？（因果归因与数据原则）
- **保存全部失败事实与将全部失败用于训练，不是同一原则**：
  - 前者是**事实库因果审计与分配诊断**的底线要求（必须完整记录包括语法错误、崩溃、超时与退化在内的全部轨迹）；
  - 后者则完全取决于**具体的训练目标与采样策略**（如 DPO 的负样本构造、分档惩罚 reward 塑形、或过滤不可行样本以防模式坍缩）。绝不能把“未把所有失败丢入训练集”直接等同于不合理的幸存者模仿。
- **消除“转向 RL”的主线偏见**：参数训练不是自动算法设计的必然终点，而是与固定模型上下文搜索并行的研究分支。参数训练提供更好的初始提议先验，在线上下文搜索负责在具体 evaluator 上执行针对性验证、反思与动态资源分配；两者是先验构建与后验验证的分工，互不排斥。
