# MEoH：多目标机制与单目标收益核查

核查时间：2026-09-05。直接阅读本地论文 TeX 主文、附录 A–I，并在线确认 arXiv v2 和论文链接的作者仓库。本文只研究 MEoH 的证据与迁移约束，不诊断当前 TraceAAD 运行，也不变更实验。

**核心判断：MEoH 足以支持“保留质量与效率的不同折衷可能改善搜索”，不足以支持“加一个运行时间目标就会提升原来的单目标 fitness”。论文某些任务的质量更好，另外一些更差；主要优势是质量—时间折衷。它也没有验证把多个指标数值写进 LLM 上下文的独立收益。**

## 1. 证据版本与边界

- 论文：Yao 等，*Multi-objective Evolution of Heuristic Using Large Language Model*，arXiv:2409.16867。在线记录当前为 2025-02-04 更新的 v2；作者原文链接代码为 Optima-CityU/LLM4AD。[arXiv 记录](https://arxiv.org/abs/2409.16867)、[官方全文](https://arxiv.org/html/2409.16867v2)。
- 本地原始文本：MEoH.tex。文中数值和算法来自该原文，与在线 v2 对照。
- 作者**当前**代码能确认计时边界，但不能倒推其完全等同论文实验快照。当前 TSP evaluator 默认 16 个实例、外层超时 20 秒，论文训练为 64 个实例，说明已有设置差异。当前代码的目标是负平均路径长度与负平均时间，也不是论文表格中的 gap。[作者 TSP evaluator](https://raw.githubusercontent.com/Optima-CityU/LLM4AD/main/llm4ad/task/optimization/tsp_gls_2O/evaluation.py)。本地同名目录另有改动，不能把本地实现直接标注为作者实验实现。

## 2. 它究竟优化什么，运行时间测什么

论文两个目标均为最小化：相对基准的解质量 gap，以及启发式运行时间。BPP 用箱数相对松弛下界的 gap；TSP 测试用相对最好已知解的 gap，随机实例的基准由 Concorde 给出。训练时 BPP 是 5 个 Weibull 5k/C100 实例；TSP 是 64 个随机 100 节点实例、在固定 GLS 框架内生成扰动阶段的距离矩阵更新函数。主文 §5.1、§5.2。

**运行时间不是代码长度、AST 大小、渐近复杂度，也不是 LLM 生成耗时。** 原文只称其为启发式运行时间，没有完整描述预热、重复计时、进程调度噪声控制等协议。作者当前实现给出了更明确的边界：

| 当前作者实现 | 计时边界 | 返回目标 |
|---|---|---|
| BPP | 实例循环前开始，包含箱初始化、可行箱过滤、全部评分调用与贪心装箱，循环结束后除以实例数 | `[-mean(num_bins), -mean_runtime]` |
| TSP | GLS 内部开始，包含最近邻初始化、初始局部搜索、1000 轮扰动与局部搜索 | 先得到每实例 `(tour_cost, runtime)`，再取均值并取负 |

代码证据：[作者 BPP evaluator，evaluate](https://raw.githubusercontent.com/Optima-CityU/LLM4AD/main/llm4ad/task/optimization/online_bin_packing_2O/evaluation.py)、[作者 TSP GLS，_guided_local_search_with_time](https://raw.githubusercontent.com/Optima-CityU/LLM4AD/main/llm4ad/task/optimization/tsp_gls_2O/gls.py)。TSP 的计时包含函数诱导的后续局部搜索工作，因此不只是那次矩阵更新调用的成本。当前 `with_time` 分支没有非计时分支的 60 秒内部停止检查；不可把论文的 60 秒声明直接当作当前代码实际执行条件。

迁移含义：应同时区分**求解总时间**与**生成函数调用耗时**。前者决定部署效率，后者帮助定位慢在哪。两者都应排除 LLM 等待和调度排队；否则模型或机器负载会伪装成算法质量差异。这是基于计时边界的设计推论，不是论文的新实验结论。

## 3. 多目标究竟进入了哪里

它进入**选父概率与种群生存**。对于最小化目标，令 `i ≺ j` 表示 i Pareto 支配 j；只有至少一个严格更好、其余不差时才成立。论文定义：

$$
v_j=-\sum_{i\ne j}\mathbf 1[i\prec j]\operatorname{Sim}_{AST}(i,j),\qquad
p_j=\frac{\exp(v_j)}{\sum_k\exp(v_k)}.
$$

`Sim_AST` 是代码 AST 匹配子树比例。论文所谓 dissimilarity 在这里用的是**负相似度**，不是 `1-Sim`；不能混淆符号。种群按 `v` 降序截断，选父用 softmax；主文“概率正比于 score”的简述应以附录明确算法为准。§4.2、附录 A、选父与生存伪代码。

由公式直接得到：

1. 非支配解均为 `v=0`；只看该分数时，它们之间没有额外质量偏好。
2. 被更好且代码非常相似的候选支配时，受到较大负惩罚；结构相异的劣解可能保留一定机会。
3. 这不是“新颖性作为第三目标”，也不是所有节点的通用 AST 新颖性奖励：只累加**支配者**产生的惩罚。
4. 多目标过多、计时噪声过大时，很多节点可能都变成非支配，`v=0` 增多，选择压力变弱。这是公式推论，论文未系统量化。
5. AST 差异不能直接等同执行行为差异。无效分支、代数改写也会改变结构；整个档案两两比较还引入额外成本。

作者当前 `population.py` 在负目标的“越大越好”约定下实现列求和、softmax和降序截断，但支配判断只检查逐维 `>=`，没有严格改善条件，等值情况下可能出现顺序依赖；不能照抄这一细节当作论文的严格 Pareto 定义。[作者种群代码](https://raw.githubusercontent.com/Optima-CityU/LLM4AD/main/llm4ad/method/meoh/population.py)。

**上下文方面：没有证据证明论文把父代的每项目标数值直接展示给 LLM。** 附录 B、G 的提示模板给出任务、算法描述和代码，以及 E1/E2/M1/M2/M3 指令，没有父代 gap、runtime 或目标向量槽位。作者当前 prompt.py 同样拼接算法描述与代码，不读取 `indi.score` 或 `evaluate_time`。这意味着“多指标影响选择”和“把多指标反馈写入上下文”必须分开验证。附录 G、[作者提示代码](https://raw.githubusercontent.com/Optima-CityU/LLM4AD/main/llm4ad/method/meoh/prompt.py)。

## 4. 单目标 fitness 是否真的更好

下列均是论文报告的测试均值；gap 越小越好。不能把表中差值自动称为统计显著，也不能把挑出的代表启发式当作每次搜索的完整分布。

| 任务 | EoH gap / 秒 | MEoH gap / 秒 | 关于单目标质量的结论 |
|---|---:|---:|---|
| BPP 5k C100 | 0.753% / 1.362 | 1.387% / 0.191 | MEoH 更快但更差 |
| BPP 100k C100 | 0.391% / 502.938 | 0.080% / 59.078 | MEoH 两项都更好 |
| BPP C100 三规模平均 | 0.560% / 169.809 | 0.706% / 19.973 | MEoH 更快但平均质量更差 |
| BPP C500 三规模平均 | 0.108% / 218.279 | 0.411% / 7.495 | MEoH 更快但平均质量更差 |
| 随机 TSP100 | 0.113% / 22.434 | Best: 0.109% / 1.373 | MEoH 略好、更快；FunSearch gap 0.100% 更好 |
| 随机 TSP500 | 1.750% / 43.541 | Best: 1.733% / 30.945 | MEoH 略好、更快 |
| 随机 TSP1000 | 2.524% / 262.603 | Best: 4.208% / 26.844 | MEoH 明显更差但更快 |
| TSPLIB ≤200 | 0.093% / 25.917 | 0.018% / 2.354 | MEoH 两项都更好 |
| TSPLIB 201–1002 | 1.376% / 1515.992 | 1.50% / 355.754 | MEoH 更快但质量略差 |

直接出处：表 1：BPP、表 2：随机 TSP、表 3：TSPLIB。主文表 4 的 TSPLIB 汇总是小规模组的数值，不宜当作全部 TSPLIB 的平均。

论文 §5.4 进一步将 MEoH 的候选与最优 EoH 启发式的不同 GLS 迭代数比较。结果支持“可以找到优于单纯调整同一启发式迭代数的时间—质量曲线”，不是“更快只是把同一算法少跑几步”。但是比较仍是整套 MEoH 与 EoH 产物，不能从中单独识别加时间目标的因果贡献。§5.4。

## 5. 消融、预算公平性与未解决问题

**消融范围。** §5.3 比较的是 MEoH 与 NSGA-II、MOEA/D 的多目标种群机制，报告 HV/IGD。它支持 dominance-dissimilarity 在这些多目标实验上更好，不等价于下列消融：同一算法、同一提示与预算，只开关 runtime 目标，再比较最终 best fitness。HV 变好也可能完全来自更快的候选，不能据此推出最小 gap 下降。§5.3。

**公平性口径。** 附录 C 明确 MEoH 与 EoH 同为 20 代、TSP 种群 10、BPP 种群 20，称分别生成 1000/2000 个启发式；FunSearch 则是两个任务各 10000。由此能说 MEoH/EoH 对齐了作者报告的候选生成数量，不能说三个方法对齐了 LLM 请求数、token、真实评价调用数或墙钟时间。解析失败/非法代码如何计入额度也没有在该段给出完整会计协议。不同提示包含多个父代，等候选数尤其不代表等 token。附录 C。

**三目标不意味着“指标越多越好”。** 附录 I 增加 Halstead difficulty 作为可读性代理，报告 HV/IGD 趋势；没有证明这个静态代理等于运行时复杂度或能提升单目标最优质量。附录 I。

**快可能来自弱化算法。** 原文附录 H 主动指出最快 BPP 候选恒定输出 1、最快 TSP 候选不改变边距离，且描述与代码不一致。于是“极快”的非支配角落可能是接近空操作的启发式，未必适合持续投入大量预算；这是迁移到质量优先搜索时需要处理的实际张力。BPP 说明、TSP 说明。

## 6. 对 TraceAAD 可以迁移的思想与必要检验

以下为基于论文的设计推论，**不是已经在 TraceAAD 验证的结论**。

保留高质量但昂贵、稍逊但便宜的不同路线，可能扩大可利用的搜索出发点。一个快而稍差的父代，若后续能把质量补回来，就可能产生快且更好的子代；这就是“辅助目标帮助主目标”的一种合理路径。但一个节点当前快，并不保证它的后代更容易改好；应该观察这种节点的子代改进率及最终贡献，不能仅用解释代替证据。

首选最小验证是一个 2×2 实验：原上下文/增加简短质量与时间反馈 × 原选父/质量—时间选父。其余算子、档案、初始根、模型参数与评价口径保持一致。这样可以分别辨认信息反馈、预算选择与二者交互。所有组保留相同的 1000 次真实评价主预算，同时记录 token、总求解时间和墙钟时间作为成本轴，不把一个预算下的收益自动迁移到另一个预算下。
若后续研究需要正式回答“多目标机制能否迁移并改善 TraceAAD 的单目标搜索”这一问题，一个规范的**备选实验设计**是 2×2 受控验证：原上下文/增加简短质量与时间反馈 × 原选父/质量—时间选父（这是按需选用的探索方案，**而非当前主线必须执行的下一步**）。其余算子、档案、初始根、模型参数与评价口径保持一致，以分别辨认信息反馈、预算选择与二者交互。所有组保留相同的 1000 次真实评价主预算，同时记录 token、总求解时间和墙钟时间作为独立成本轴。

上下文首先只加**测量可信且可行动**的信息，例如父子质量变化、同一实例集的总求解时间比、必要时生成函数时间占比和超时原因；不要立即把 AST 节点数、代码行数、所谓新颖度都当作并列目标。运行时间需要固定实例、统一机器资源和计时边界；临界相近候选用重复测量或容差处理，避免 CPU 争用产生虚假 Pareto 关系。
**度量与目标的界限**：在评测中记录候选算法的求解运行时间是关键的执行层观测数据，但**记录耗时绝不意味着必须将运行时间升级为外层搜索的第二优化目标**。若上下文需要引入时间，首先只加**测量可信且可行动**的信息（例如父子质量变化、同一实例集的总求解时间比）；运行时间需要固定实例、统一机器资源和计时边界，避免 CPU 争用产生虚假 Pareto 关系。

若最终目标仍是最优 fitness，则多目标分配应保留明确的质量主通道，辅助通道用于探索高效率候选；不建议直接把全档案替换成“所有非支配节点等机会”。具体混合比例需要数据决定，论文没有给出可直接迁移的最优比例。评价应首先报告相同真实评价预算下 best fitness 的重复实验分布，再报告效率前沿和达到质量阈值的时间；如此才能回答用户真正关心的“有没有更利于单目标搜索”。
