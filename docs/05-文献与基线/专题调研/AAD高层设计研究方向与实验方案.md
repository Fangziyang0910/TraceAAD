# AAD 高层设计研究方向与实验方案

核查日期：2026-09-20。本文承接 [AAD 高层设计与系统级算法发现综述](</home/fang/code/LLM4AD/TraceAAD/docs/05-文献与基线/专题调研/AAD高层设计与系统级算法发现综述.md:1>)，记录在“设计对象高于单个 heuristic / scoring function / operator”的 AAD 方向上，当前最值得研究的问题、可证伪假设、具体实验和创新边界。

本文将研究建议分成三类：

- **先识别机制**：确定什么历史证据、什么设计层级和什么路线决策真的有增量；
- **再设计控制器**：在机制效应成立后，学习机会分配和搜索粒度切换；
- **最后扩展系统**：只有前两类证据成立，才进入完整 solver 合成、portfolio 共设计和模型内化。

当前最重要的原则是：**不把扩大搜索对象、改变上下文、改变预算、增加修复和更换模型同时放入一个版本。每个研究方向必须先说明它改变 `R`、`A`、`H`、`controller`、`router` 或 `model` 中的哪一项，并用相同真实评价预算估计增量。**

## 1. 研究对象与不确定性

把可部署算法系统写成：

```text
z = (R, A, H, controller, router, model)
```

其中：

- `R`：问题表示、规约和数据接口；
- `A`：solver 的控制流、阶段和组件拓扑；
- `H`：heuristic、scoring function 和组件实现；
- `controller`：候选生成、选择、修复、预算和停止决策；
- `router`：实例到 solver/heuristic 的部署选择；
- `model`：生成模型或 agent policy 的参数。

当前真正需要减少的不确定性有六个：

| 编号 | 未知量 | 为什么重要 | 最小可识别证据 |
| --- | --- | --- | --- |
| U1 | 高层搜索的收益来自设计空间变大，还是来自更多候选/修复成本 | 决定是否值得从固定框架升级 | 同模型、同 evaluator、同真实预算下的固定函数/optimizer/solver 三路对照 |
| U2 | 哪类历史证据会改变下一次生成 | 决定 TraceAAD 的轨迹是否是有效机制 | 固定当前程序、算子和预算的 context micro-benchmark |
| U3 | 哪条路线值得获得下一次机会 | 决定预算分配是否应使用 continuation value | 同上下文下比较质量贪心、探索配额和未来前沿收益 |
| U4 | 何时应信任固定框架，何时应打破框架 | 决定是否需要自适应搜索粒度 | 强模板、弱模板和无模板条件下的粒度切换实验 |
| U5 | 完整 solver 的开放性如何与可执行性平衡 | 决定程序级 AAD 是否能稳定运行 | 相同生成预算下比较自由代码、结构化程序和合约化程序 |
| U6 | 搜索经验能否摊销到可复用 solver | 决定是否值得做模型训练或 RL 内化 | frozen best-of-k、compile-once 和训练后模型的 held-out 比较 |

U1–U3 是当前 TraceAAD 最接近、成本最低、最能减少主线不确定性的方向；U4–U6 是在前面证据成立后的扩展。

## 2. 优先方向 A：决策相关证据条件化的高层 AAD

### 2.1 核心问题

现有工作普遍保存精英、谱系、反思或代码差分，但“历史被保存”不等于“历史改变了生成”。需要在相同搜索状态下回答：

> 给定相同当前程序、相同设计算子和相同生成预算，哪类历史证据会改变候选条件分布，并把单步变化转化为后续前沿收益？

### 2.2 可证伪假设

**H-A1：** 在固定状态 `s` 和算子 `o` 下，与当前决策匹配的证据 `c` 能提高相对父代的即时改进量 `Delta1`，相对于无历史或随机历史基线有稳定正向效应。

**H-A2：** 只有同时提高即时改进和固定后续窗口内的 frontier gain，证据才具有可持续价值；仅改善 parent score 的上下文不一定值得继续使用。

**H-A3：** 证据类型与收益形成结构存在交互：连续协调任务更可能受形成谱系帮助，跨分支组合更可能受机制卡帮助，排序/边界任务更可能受实际决策变化帮助。

用可测量的差值表示：

```text
tau_gen(s, o, c)   = E[Delta1 | s, o, c] - E[Delta1 | s, o, c0]
tau_front(s, o, c) = E[frontier_gain_h | s, o, c]
                       - E[frontier_gain_h | s, o, c0]
```

`c0` 是无历史或长度匹配的随机证据，`h` 是固定的后续开发窗口。`tau_gen` 只证明候选立即变好，`tau_front` 才说明证据支持后续路线。

### 2.3 方法设计

建立一个可回放的 context registry，每条证据必须带 provenance：

```text
evidence = {
  source_node,
  parent_code_or_diff,
  design_idea,
  actual_decision_change,
  fitness_before_after,
  failure_or_constraint,
  applicability,
  later_development_count
}
```

候选证据至少分为五组：

1. **无历史**：只给当前程序和任务契约；
2. **短形成轨迹**：父代到当前程序的最近若干改动和评价变化；
3. **随机长度匹配档案卡**：控制 token 数量，但不匹配决策相关性；
4. **机制卡**：明确写出已验证的代码机制、实际决策变化、前后评价和约束；
5. **行为卡**：在固定 probe 上记录求解行为变化，不提供完整形成路线。

生成时固定算子、temperature、输出格式和最大 token；只替换证据组。上下文路由器在第一阶段不能读取任务名称到证据组的人工映射，只能读取当前代码结构、评价状态、形成关系、失败和行为摘要。

### 2.4 最小实验

第一阶段只做候选级 micro-benchmark，不修改在线预算分配：

- 任务：TSP、CVRP、OBP、VRPTW 各选一个已完成搜索的任务规模；
- 状态：每个任务随机抽取 12 个冻结父代状态，覆盖高分/中分、连续改进/停滞、不同深度；
- 条件：5 种上下文 × 4 个候选样本 × 3 个重复，共 `4 × 12 × 5 × 4 × 3 = 720` 次真实候选评价；
- 输入成本：五组上下文的 prompt token 设上限并单独计账；
- 生成状态：父代、算子、LLM、温度、任务契约和候选数全部固定；
- 输出：即时质量、可执行率、失败类型、代码 diff、关键决策是否改变、候选是否进入后续开发。

第二阶段只选择第一阶段 `tau_gen` 显著为正的两种证据，在每个任务每种证据选 8 个状态，使用固定的 3 步后续开发窗口。额外预算控制在 192 次候选评价，估计 `tau_front`。

### 2.5 主要指标与停止条件

主要指标：

- `tau_gen`：相对父代的即时改进差；
- `tau_front`：固定后续窗口中的 frontier gain；
- 有效率、可行率、失败类型分布；
- 机制落地率：参考机制是否进入代码并改变实际决策；
- 代码复杂度和输入 token；
- held-out 实例表现。

停止条件：

- 若所有证据组在四个任务中均没有稳定正向 `tau_gen`，停止把轨迹/上下文作为主机制；
- 若 `tau_gen` 正向但 `tau_front` 不正向，结论收缩为“局部生成帮助”，不称为持续经验利用；
- 若只有单一任务支持，改写为任务条件效应，不训练通用路由器；
- 若机制卡优于短轨迹，主线从“trajectory-conditioned”改为“decision-evidence-conditioned”。

### 2.6 创新点与边界

潜在创新不是“首次使用历史”，而是：

1. 将高层 AAD 的经验利用定义为固定状态下的反事实条件生成效应；
2. 区分展示证据、进入代码、改变实际决策和带来后续前沿收益四个事件；
3. 把形成谱系、机制卡和行为卡放到同一匹配实验中；
4. 为后续高层控制器提供可估计的 `tau_gen` 与 `tau_front`，而不是凭终局分数手工路由。

这条方向的边界是：它先研究证据是否有效，不直接宣称提出了新的完整 solver 或通用 meta-optimizer。

## 3. 优先方向 B：机会分配与生成上下文的分离

### 3.1 核心问题

高层 AAD 同时做两件事：

- 决定哪一个节点/路线获得下一次真实评价；
- 决定该节点看到什么材料来生成候选。

V11 的精英锁定说明，两者混在一起会导致“参考材料很丰富，但只有极少数路线继续发展”。需要研究机会分配，而不是继续加更多 prompt 内容。

### 3.2 可证伪假设

**H-B1：** 当前 fitness 不能充分预测路线的未来 frontier gain；路线级改进率、结构变化、证据兑现率和开发覆盖可以补充当前分数。

**H-B2：** 在相同上下文下，带最低探索配额的机会策略比纯质量贪心更能提高长期前沿，而不会显著损失早期收敛。

**H-B3：** parent improvement 和 frontier improvement 是不同目标；只优化前者会造成精英锁定。

### 3.3 候选机会策略

对每个路线或节点维护：

```text
quality                 当前质量
parent_gain             最近相对父代改进
frontier_gain           对全局前沿的增量
attempts                被选择开发次数
route_coverage          路线/结构区域覆盖
evidence_realization    历史机制进入代码的比例
failure_rate            近期执行失败率
```

比较四种策略：

1. V10.11 式质量分布抽样；
2. V11 式直接最高分选择，作为精英锁定对照；
3. UCB/Thompson 式路线级 continuation-value 估计；
4. 带固定最低探索额度的质量—覆盖混合策略。

任何策略都不能访问 held-out 结果，`frontier_gain` 只使用当前训练搜索中的真实评价。

### 3.4 最小实验

先做离线重放，再做小规模在线验证：

- 离线：从已完成日志中重放父代选择，比较策略在相同候选顺序下的路线覆盖和前沿轨迹；
- 在线：TSP、CVRP 各一个规模，四种策略 × 5 个重复；
- 每路预算 1000 次真实评价，报告 E100/E250/E500/E750/E1000；
- 上下文、算子、LLM、候选数和修复规则冻结；
- 只改变机会分配，不改变生成 prompt。

### 3.5 指标与停止条件

主要指标：

- 相同预算下的 frontier quality；
- 低分但后来突破的路线首次开发延迟；
- 路线/结构簇覆盖率；
- parent gain 与 frontier gain 的相关性；
- 有效率、重复率、LLM token 和真实 evaluator 数；
- 与离线 oracle continuation value 的 regret。

停止条件：

- 若所有策略在 E1000 的前沿和 held-out 均无差异，停止增加预算控制复杂度；
- 若探索策略只提高覆盖、不提高前沿，保留覆盖作为诊断，不称为质量收益；
- 若 V11 只在特定任务上退化，结论限定为该实现的精英锁定，不泛化为所有质量抽样失败；
- 若路线级统计不能预测后续收益，放弃 learned continuation value，回到固定最低探索额度。

### 3.6 创新点与边界

潜在创新是把高层 AAD 中的“机会分配”从生成器中独立出来，并用未来前沿而非一次 parent improvement 评价路线价值。它可以解释为什么一个看似更强的生成器仍然搜索失败，也能与 MoH/A2DEPT 的结构搜索接口组合。

边界是：机会策略本身不是高层 solver synthesis；它只能说明有限评价预算如何分配，不能证明结构搜索有用。

## 4. 优先方向 C：自适应搜索粒度与框架信任

### 4.1 核心问题

固定框架提供强先验和高可执行率，开放程序搜索提供结构跳变机会。现有论文通常在实验开始前决定“只改函数”或“开放完整程序”，缺少一个可学习决策：什么时候应该信任当前框架，什么时候应升级到更高层。

### 4.2 可证伪假设

**H-C1：** 搜索粒度应由当前框架先验、停滞状态、失败类型和结构冲突共同决定，而不是固定选择。

**H-C2：** 强模板任务适合局部精炼，弱模板或明显停滞任务更适合结构级改写；始终开放会浪费预算，始终固定会错过范式跳变。

**H-C3：** 一个有最低探索约束的粒度控制器，在相同真实评价预算下能取得更好的质量—可执行率折中。

### 4.3 设计动作

把设计动作分成三个粒度：

```text
L0: 函数内局部精炼 / 参数校准
L1: 组件替换 / 组件组合 / 算子重排
L2: solver 结构或控制流重写
```

控制器观察：当前质量分位、最近改进率、失败类型、结构变化量、历史证据兑现率、路线覆盖和剩余预算。动作完成后进入相同 evaluator 和日志协议。

对照策略：固定 L0、固定 L2、随机升级、停滞触发升级、学习型粒度控制器。

### 4.4 最小实验

- 任务条件：TSP/CVRP 各选一个强模板任务，另选一个弱模板或人为去掉关键结构先验的任务；
- 每个条件 5 个重复，每路 1000 次真实评价；
- 固定 LLM、上下文、输出 token、修复、候选数和 evaluator；
- 记录每次粒度切换的触发状态、候选有效率、切换后 50/100 次评价的 frontier gain；
- held-out 使用未见实例，另外保留一个未见规模测试。

### 4.5 指标与停止条件

- quality—validity Pareto 曲线；
- 粒度切换次数与切换成本；
- L0/L1/L2 的有效候选率和后续收益；
- 强/弱模板下的策略差异；
- 结构复杂度、依赖数和运行时间。

停止条件：

- 若学习型控制器不超过“停滞触发升级”，不再引入 RL；
- 若所有任务始终偏好 L0，结论是模板先验足够，不继续扩大搜索空间；
- 若 L2 只提高训练 best、不提高 held-out，停止结构升级主张；
- 若弱模板没有产生可测结构收益，先检查模板构造和 evaluator，不把失败归因给 LLM。

### 4.6 创新点与边界

潜在创新是把“是否打破框架”本身作为 AAD 决策变量，研究 algorithmic prior 的信任边界。这比一开始固定开放程度更接近真实自动算法设计，但必须先有方向 A/B 的证据，否则控制器只是又一层混杂。

## 5. 后续方向 D：合约驱动的完整 solver 合成

### 5.1 核心问题

完整程序搜索的主要瓶颈不是 LLM 是否能输出长代码，而是结构变化造成的依赖闭合、接口契约和失败归因。A2DEPT、BEAM 等方法已经使用修复环，但不同失败语义和修复成本尚未统一。

### 5.2 可证伪假设

**H-D1：** 明确的类型/形状/资源/可行性合约能够在不显著降低结构探索的情况下提高可执行率。

**H-D2：** 分阶段验证比只在最终 solver 上评分更能改善结构搜索的信用分配。

**H-D3：** 结构开放度与有效率之间存在可测量的 Pareto 前沿，而不是“越开放越好”。

### 5.3 设计方案

为程序树节点保存：

- immutable 接口和输入输出契约；
- 组件依赖图和类型/形状信息；
- 局部单元测试、阶段性指标和资源上限；
- 失败类型：解析、依赖、类型、可行性、超时、目标质量；
- 修复次数、修复 token 和最终去向。

候选按四级验证门推进：解析 → 依赖闭合 → 小规模行为测试 → 完整 evaluator。每一级都计入相应成本，不能把便宜预检查伪装成真实质量评价。

### 5.4 最小实验

同一任务、同一模型和同一总生成预算下比较：

1. 固定模板 + 函数槽位；
2. 无合约的完整代码搜索；
3. 合约驱动的完整程序搜索。

任务可先选 TSP/CVRP/OBP 三类，5 个重复。报告结构开放度、逐级通过率、最终可行率、修复成本、可行候选质量、代码复杂度、真实 evaluator 次数和 held-out 泛化。

### 5.5 创新点与边界

创新点是把完整 solver 搜索的评价目标从单一最终分数改成“开放度—可执行率—质量—成本”的联合曲线，并统一失败语义。边界是：合约化系统仍依赖人类设计接口，不能声称无先验的开放式发现。

## 6. 后续方向 E：portfolio 与完整 solver 的共设计

### 6.1 核心问题

EoH-S/InstSpecHH 说明不同实例可能需要不同算法，A2DEPT/BEAM 说明 solver 结构也可能需要变化。更实际的目标可能不是寻找一个万能 solver，而是共同设计候选 solver 集合和部署 router。

### 6.2 可证伪假设

**H-E1：** 在实例异质性足够高时，候选 solver portfolio 加选择器的真实部署收益超过单 solver。

**H-E2：** portfolio 的 oracle gain 只有在 router 误差和运行成本可控时才会转化为实际收益。

### 6.3 设计方案与对照

共同搜索候选 solver 集合和 router，但训练、验证和测试严格隔离。比较：

- 单一全局 solver；
- portfolio oracle；
- 特征/行为 router；
- 对所有成员运行后取最优；
- 随机 router。

router 不允许访问测试结果，只能使用预先定义的实例特征、初始 probe 行为或运行时诊断。

### 6.4 主要指标

- 质量、运行时间和总部署成本的 Pareto 曲线；
- router 准确率与误选损失；
- portfolio 成员边际覆盖和支配关系；
- 生成、选择和运行三阶段成本；
- unseen instance 和 unseen distribution 的表现。

若 oracle gain 很大但实际 router 不超过单 solver，结论应是“候选互补存在但部署不可行”，不能宣称 portfolio 方法有效。

## 7. 后续方向 F：从搜索经验到可复用 solver 的模型内化

### 7.1 核心问题

CALM、EvoTune 和 Hero 代表把搜索经验写进模型参数的路线。它的科学问题不是微调后分数是否更高，而是训练成本是否真的换来了未来搜索成本下降，以及能力是否迁移到未见任务。

### 7.2 可证伪假设

**H-F1：** 在固定总预算下，模型内化能降低未来实例的搜索调用，而不只是提高训练分布上的 pass@k。

**H-F2：** 只有固定 solver 跨 held-out 实例复用成功，才能称为可复用算法能力。

**H-F3：** 训练数据中的程序 lineage、失败和行为反馈比只用最终高分程序更能支持迁移。

### 7.3 最小实验

同一任务族比较：

1. frozen model + best-of-k；
2. frozen model + 进化搜索；
3. DPO/GRPO 模型 + 同样的搜索；
4. DPO/GRPO 模型一次生成后 compile-once；
5. 只用最终高分程序训练 vs 使用完整可回链轨迹训练。

必须单独报告训练 GPU 时间、训练 token、推理 token、真实 evaluator、固定 solver 执行时间、pass@k 和跨问题/跨分布结果。

### 7.4 停止条件与边界

若训练模型只在训练任务上提升，或 compile-once 不优于 frozen best-of-k，则停止“可复用 solver”表述；若训练收益来自更多筛选和重试，转而报告搜索摊销而不是模型能力内化。

## 8. 方向优先级和决策门

### P0：先做 A + B

原因：它们直接减少当前 TraceAAD 的主要不确定性，改动最小，能复用已有日志和 evaluator，不需要马上引入完整程序搜索或模型训练。

决策门：

- A 至少在 3/4 任务上有正向 `tau_gen`，并至少在 2/4 任务上有正向 `tau_front`；
- B 至少在 E500 或 E1000 的 frontier 上胜过 V11 argmax，且不以有效率和成本显著恶化为代价；
- 若任一门不通过，停止叠加 A+B，记录条件性或负结果。

### P1：再做 C

只有当 A/B 的单因素效应成立，才学习搜索粒度控制。否则粒度控制器会把上下文和机会分配的失败混在一起。

### P2：最后做 D/E/F

完整 solver 合成、portfolio 共设计和模型内化都需要更高预算、更严格的执行契约和更长的 held-out 评估。它们适合作为后续论文方向，不适合作为当前主线的第一步。

## 9. 一篇论文可以形成的最小贡献

最稳妥的第一篇高层 AAD 论文不应承诺“自动发现更好的完整算法”，而应形成以下闭环：

1. 提出决策相关证据的统一表示；
2. 在固定父代、固定算子和固定真实评价预算下，估计不同证据的 `tau_gen`；
3. 用固定后续窗口检验 `tau_front`，区分局部改进与路线价值；
4. 证明机会分配和生成上下文是两个可分离的控制层；
5. 在至少两个任务上把证据效应迁移到 held-out，而不是只在一批搜索轨迹上取得 best-of-run；
6. 明确写出失败条件：何时历史证据无效、何时模板先验更可靠、何时开放搜索只增加无效率。

这样的创新点是**机制辨识和可复核协议**，而不是把更多搜索组件堆成一个更大的框架。它与已有 MoH、A2DEPT、BEAM 和 agentic AAD 的关系是互补的：这些方法扩大设计对象，而本研究回答“扩大设计对象或使用历史证据的收益何时真实发生”。

## 10. 当前不应做的事情

- 不要在没有完成 context micro-benchmark 前训练 learned router；
- 不要同时修改预算、算子、上下文、程序表示和模型；
- 不要把 parent improvement 当作 frontier gain；
- 不要用 portfolio oracle 代替实际 router 结果；
- 不要用训练 best、best-of-run 或单路峰值代表泛化；
- 不要把代码相似度、轨迹距离、Idea 长度或算子标签直接当作算法质量；
- 不要在恢复一致性未修复前启动依赖断点续跑的正式批次；
- 不要把某个任务上的失败推广为整个高层 AAD 方向失败。

## 11. 最终研究判断

当前最有潜力的研究点不是“让 LLM 设计更多代码”，而是研究高层 AAD 中的**证据、机会和粒度三者如何分工**：

```text
历史证据       → 改变下一次生成
机会分配       → 决定哪条路线继续发展
搜索粒度       → 决定何时打破既有框架
合约与验证     → 决定开放搜索能否执行
held-out 复用  → 决定得到的是算法还是一次性候选
```

如果 A 和 B 的识别实验成功，TraceAAD 可以从“轨迹提示方法”提升为“决策相关经验利用与高层 AAD 控制”的机制研究；如果只有 B 成功，则应收缩为有限评价预算下的 opportunity allocation；如果只有 D/E/F 的系统方向显示收益，则应把 TraceAAD 的轨迹降为证据记录层。三种结果都能改变后续实验选择，只有在联合混杂下继续扩大系统才不会产生新的科研信息。
