# 演化轨迹能表征什么：字段组合、代码潜力与错位

我现在更倾向于把轨迹理解为：**当前算法具有什么实际能力，这些能力怎样形成，哪些改法已得到怎样的检验，以及下一步还有什么具体可做。** 精炼价值与拓展价值是依据这些信息作出的前瞻判断，不是直接存储在轨迹中的事实。

这次从既有审计定位候选，再回到原始代码与评价版本重新核读。我核对了 `20261030_base_compact_co6` 的六路冻结 state，SHA-256 全部与原 manifest 一致；提取26个程序，逐个确认归档代码等于末次评价代码。冻结时刻为北京时间2026-10-31 08:19:33，不能解释为当前运行状态。案例来自固定训练评价，适应度统一越小越好；没有运行候选、调用模型或补做 benchmark。原始条件、代码哈希、父子关系、评价编号、耗时与直接开发清单见[本次证据索引](../../experiments_result/analysis/trajectory_information_20261102/evidence.json)。26份程序全部核对记录，语义分析重点为下文分支，不表示对26份源码作了同等深度的审阅。

## 字段怎样组合才有含义

| 输入组合 | 可以表征的内容 | 对下一步判断的用途 |
| --- | --- | --- |
| 代码 + 任务接口及返回值用途 | 实际搜索对象、可用信息、决策规则、约束与输出路径 | 先确认算法真正会做什么；静态边先验不能被解释成读取蚂蚁当前状态的动态策略 |
| design / analysis + 实际代码 | 设计意图是否落实；哪里仍是死计算、错误实现或描述夸大 | 区分实现缺口与已经得到检验的设计 |
| 父子代码 + 修改说明 + 算子 | 改动究竟是调参、接入信息、改变搜索对象、删除机制，还是等价改写 | 算子说明生成意图；实际改动说明这份结果检验了什么 |
| 实际改动 + 父子评价 + 状态/错误 | 在这个起点和条件下，这种实现产生了什么响应 | 不把未执行、超时与有效但变差合并为同一种失败 |
| 祖先链 + 每步机制的保留/替换 + 评价 | 当前能力怎样形成，哪次修改改变了方向，哪些改进在后续仍保留 | 找到可保留的基础与需要撤回的具体改动；不能从沿链相关变化直接确定每项改动的独立效应 |
| 同父代子代 + 语义改动的异同 + 评价 | 哪些不同方向得到检验，哪些只是反复修改同一无效参数 | 区分尝试次数与有效检验的覆盖范围；同基比较仍可能混有多个同时改动 |
| 修复前后版本 + 错误 + 最终评价 | 最终结果属于原思想、降成本实现，还是替换后的另一个算法 | 避免把删除机制后的成功/失败归给原机制 |
| 实际循环/复杂度 + 耗时 + 评价限制 | 改进依赖更多计算，还是仍有可消除的冗余与可用预算 | 估计改法是否可兑现；区分生成预算与候选求解时间 |
| 参考代码 + 父代代码 + 子代代码 + reference_id | 新能力的来源、接入位置、互补性或功能重叠 | 融合价值需要针对具体对象判断；主父代树本身不足以归因参考贡献 |
| 出生时间 + 后续机会 + 已有尝试 | 未开发、未充分检验，还是多种有效改法均未奏效 | 没有子代表示缺证据，不等于高潜力；反复复制也不等于设计饱和 |

字段不必全部变成额外分数。最小的分析结果可以是四句话：**当前有效机制；已检验的改法；仍存在的具体障碍或机会；支持判断的节点/代码位置。**

## 案例一：同分可以是改动没有生效，而非精炼空间耗尽

CVRP seed2，P189→P193 是 Refine，唯一代码变化是 `beta=4` 改为 `beta=6`，两者适应度均为8.4772400744。关键计算为：

```python
excess = maximum(0, q_i + q_j - capacity)
capacity_factor = exp(-beta * excess / capacity)
feasible_mask = (q_i + q_j <= capacity)
eta = other_factors * capacity_factor * feasible_mask
```

可行边的 excess 为0，指数因子为1；不可行边又被 mask 置零。对该合法输入域，beta不改变返回矩阵。P193的design却说beta增强可行性约束。

因此，这条边说明的是“该参数在当前实现中无效”，不是“更强的容量惩罚已经试过但没有帮助”。给P189累加一次未改善，能描述这次生成没有收益，却不能据此判断该算法的其余精炼空间。下一步若研究容量因素，必须先明确有效因子如何在可行边之间产生差异；单纯删去冗余项只能简化程序，不能保证改善路线。

代码：[P189](../../experiments_result/analysis/trajectory_information_20261102/code/cvrp_aco/seed2/P189.py)、[P193](../../experiments_result/analysis/trajectory_information_20261102/code/cvrp_aco/seed2/P193.py)，L59–70。

## 案例二：较差的代码有明确可修复空间，多次退步未必说明父代饱和

JSSP seed2 的P120实际搜索作业优先级排列。`decode`在最早可开工操作中按排列位置选作业；50个排列经过30代选择、交叉和变异，返回历次最好排程。其适应度1853.875。P120的六个直接Refine子代均退步，但其中失败的含义不同。

P316保留种群，再增加局部扰动，适应度退至1993.5。代码在接受一次相对当前状态更好的移动时，无条件覆盖 `best_starts`；同时允许以5%概率进入较差状态。于是历史最好为100、当前退到120、再改善到110时，可以用110覆盖历史最好输出，而 `best_fit` 仍为100。这是控制流的反例，不是该批训练发生过的数值轨迹。

这给出一个具体精炼机会：将“当前搜索状态”和“历史最好输出”分开维护，仅在刷新历史最好时更新输出。对同一条搜索路径，这能恢复返回历史最好排程的保证。历史日志没有保存所有内部状态，所以尚不能给出修正后的训练分数，也不能保证超过P120。

更重要的是，这个判断来自代码，而不是P316的适应度、design或后代数量。P316没有直接子代，但“未开发”本身不是其价值依据；可定位、可修复且影响输出的缺陷才是。

另外，P140初稿超时，修复后直接删除种群，只剩按剩余工时派工，分数1911.75。其160秒超时与修复后约0.078秒成功对应的是两种不同算法。不能把该结果当成“保留种群进行精炼仍然失败”。P139、P188、P326也存在修复后的种群删除。

P120本身还有与分数无关的实现余量：每生成一个子代都调用返回50个父代的 `select(pop, fits)`，却只使用前两个。可以直接构造所需父代，避免其余选择开销；其确定性排列解码也适合检查重复排列缓存。这些改法有明确的计算依据，但运行收益未测，减少随机抽样还会改变固定种子下的后续随机序列，不能声称逐条轨迹不变。

代码：[P120](../../experiments_result/analysis/trajectory_information_20261102/code/jssp_construct/seed2/P120.py) L69–79、L127–146；[P316](../../experiments_result/analysis/trajectory_information_20261102/code/jssp_construct/seed2/P316.py) L155–184；[P140超时稿](../../experiments_result/analysis/trajectory_information_20261102/code/jssp_construct/seed2/P140_E172.py)与[修复稿](../../experiments_result/analysis/trajectory_information_20261102/code/jssp_construct/seed2/P140_E173.py)。

## 案例三：好成绩可以来自旧能力，新增机制实际上没有被检验

图着色seed0的P169达到40.8125，design说通过模拟退火接受冲突状态。实际调用是合法贪心着色→保持合法性的local_search→simulated_annealing。退火函数遇到 `current_conflicts == 0` 就退出，因此在这条入口路径上没有执行退火移动。

当前成绩不能作为退火有效的依据；增加温度或步数也不会解决这个问题。真正需要补的是“尝试降低目标颜色数→产生待修复冲突→进行搜索→保存合法最好解”的完整关系。这个缺口比P316的输出缓存错误更大，可能要求调整搜索状态和目标。不能因为代码里已有一个退火函数，就把它评为马上能兑现的高精炼价值。

另一条P185→P193的Refine更直接：设计声称加入新局部搜索，但源码逐字节相同，成绩同为40.5625。因此design、算子和高成绩都不能替代实现核对。

## 案例四：融合成功，不等于增加了互补能力

OP seed1，P504与参考P267生成P575，适应度从父代−15.050625改善到−15.15125。P575实际计算：

```text
sqrt(exp(-3*d/L) * exp(-2.5*d/L)) = exp(-2.75*d/L)
```

在正距离、正预算且未受数值地板影响的边上，其输出就是 `prize^5 / d^6 * exp(-2.75*d/L)`。父代已有平方衰减，参考已有1.8次幂衰减；子代没有保留两者不同的形状，而是回到单一线性指数，并改变密度幂。

这次生成有实际质量收益。但代码支持的解释是原有密度/衰减公式族内的调整与简化，不能直接记为新增互补机制。它也说明，算子名称和实际改动层次可能错位：融合调用可以完成精炼性质的开发，Refine也可能引入新的搜索能力。

若继续评估P575的拓展机会，我会问：当前评分只有终点奖赏、直接距离和预算尺度，是否值得接入终点后的可行奖赏信息？当前接口是否允许得到这项信息？这比“它是融合产生的，所以还应继续融合”更具体。该判断只提出有计算依据的机会，尚没有预测它能超过现有成绩。

代码：[P504](../../experiments_result/analysis/trajectory_information_20261102/code/op_aco/seed1/P504.py)、[P267](../../experiments_result/analysis/trajectory_information_20261102/code/op_aco/seed1/P267.py)、[P575](../../experiments_result/analysis/trajectory_information_20261102/code/op_aco/seed1/P575.py)，L10–21。

## 案例五：相同成绩也可能对应真实新增的可达状态

图着色seed1的P69→P146均为41.25。P146在原有颜色消减之外，确实遍历双色诱导子图的连通分量并交换颜色，之后回到消减循环。这类交换即使没有立即减少颜色数，也能改变顶点的合法换色条件；与CVRP的无效beta不同，它确实改变了内部状态及后续可尝试的移动。

P146在冻结后的剩余133次已完成尝试中没有被继续用作父代或参考。这个记录只说明该具体变体未进一步检验。我的代码判断是：它具有一个真实的中性移动入口，但任意接受第一个可交换分量，可能只在颜色对称状态间打转；应检查交换是否改变目标颜色类的消减机会，而不是仅增加循环次数。其潜力证据弱于P316的明确实现缺陷，不能因“有复杂邻域且未被选中”就断言高价值。

## 案例六：改善方向成立，也受求解时间约束

图着色seed0的P81→P96→P109→P115，对应50→100→150→200次随机构造，成绩41.375→41.0625→40.9375→40.8125。P96→P109的完整diff只有重启次数100→150。数字修改在这里改变了真实搜索量，具有实际收益，不能与无效beta调参混为一类。

同路P185使用1000次构造，最终评价耗时147.536秒，该批总时限160秒。这个时间是单次冻结记录，不能当稳定的安全余量，但足以提示：继续增加重启次数受到执行预算约束。它的拓展机会应来自新的搜索方式或更有效的单次构造；精炼仍可以来自减少重复计算。高成绩和长期开发均不自动意味着整个设计已饱和。

## 两种价值应怎样从这些事实推出来

**精炼价值**：当前机制仍有哪些具体可修正、可落实或可提高效率的环节，这些修改在可用预算内是否可能改善最终结果。依据是可定位的改进机会及相关尝试，而不是单纯的近期改善率。

**拓展价值**：当前机制受什么能力限制，什么新信息或新搜索方式能够针对该限制，与已有结构是否兼容，接入后是否仍有兑现的预算。依据是具体限制与可行的扩展方向，而不是“已经精炼很多次”或“需要新思想”。

两种价值可以同时高或同时低，也可以都未知。一个实现不完整且接入成本极高的算法，不会因为尚有许多缺口而自动值得投资。大量明确修复只能恢复到已有父代水平时，从现有父代继续可能更合算。价值最终仍需考虑与已有最好程序的差距及其他预算用途。

建议按场景作如下区分：

| 已观察到的状态 | 优先解释 | 对价值的影响 |
| --- | --- | --- |
| 多次同分，改动均为等价代码/无效参数 | 生成没有提供有效的新检验 | 这些改法应降权；整个机制的余量仍未知 |
| 多种已生效的改法均失败，且保留核心、评价正常 | 已覆盖方向出现负面证据 | 对这些精炼方向降低预期，再寻找具体拓展机会 |
| 新机制已接入，存在可定位实现缺陷 | 收益可能被实现遮蔽 | 为小范围精炼提供依据，尚不能预言最终领先 |
| 新机制只存在于说明、死分支或被修复删除 | 原机制尚未得到有效检验 | 不能给其成败信用；先估计落实成本 |
| 同分但改变合法状态/可达邻域 | 可能是中性移动与后续开发入口 | 给出机制性理由，仍需后续检验，不等同于收益 |
| 多次改善只来自增加计算量 | 质量收益与执行成本联动 | 结合时间余量判断是否还能继续兑现 |
| 两个机制使用相同信息且可代数合并 | 重叠或参数重组 | 可有精炼收益，互补拓展证据弱 |
| 两个机制处理互补限制、输入输出能接上 | 存在具体融合方案 | 是这一对程序的价值；单节点通用拓展值只能粗排 |
| 节点未开发或只做过很少尝试 | 缺少响应证据 | 结合代码提出假设，不能默认高价值或低价值 |
| 子代改善后又被继续改善 | 潜力在多步中兑现 | 需要读到实际后续路径；只看直接子代不能完整观察 |

## 对现有表述和表示的修正建议

我不再接受“精炼退步是负面，融合小退步是正面”作为一般规则。较小退步只能说明当前质量损失较小；还需验证新机制已实际接入、为何可能有用、剩余缺陷是否可修。精炼也可能经历多步开发，融合也可能立即获益。同算子比较能减少部分异质性，不能保证兑现时间相同或预测偏差共同。因此固定算子比例可以作为预算控制选择，但不能以这些保证作为已成立的推导。

当前定义中的“代码、设计、分数、算子、修改说明”提供基础材料；分析还必须能定位评价条件、修复过程与参考来源。原始字段与派生判断需要分开：operator是调用意图，code显示实际实现，design/analysis是待核验解释，fitness/status是观察结果。不要把模型对自己代码的解释再当一份独立证据。

局部轨迹的边界也要保留：父代P466的直接子代P664为1771.6875，P664的子代P680改善到1770.5625。P680属于P466的孙代，按当前定义不在P466的局部轨迹内。读取P680的祖先链可以看到这个过程，但不能假定P466的局部视图已包含它。融合参考也不是主父代；需要时通过reference_id补读参考实现，不必把整个主父代树改成多父代树。

此外，本次核对工作区 `traceaad_v19_4/prompts.py` L140–154，当前选择提示只展示design、形成过程及近期尝试的文字信息；`facts`中的analysis/design/reflection也未经代码语义核验。**档案保存源码，不等于选择器能利用源码判断潜力。** 这不要求把全部历史源码重新塞入生成提示；较小的选择是为价值分析提供经过代码核对的机制摘要和具体证据位置。是否自动生成、怎样验证、怎样呈现仍待设计，本文没有修改在线机制。

最值得先检验的一点是：在固定节点和局部轨迹下，加入代码核验后，能否区分“没有生效的尝试”“有明确可修复缺陷”“真实有效但未改善的改动”。P189/P193、P120/P316、P69/P146正好提供三种不同情形。先确认这个区分可靠，再讨论把它压成两个价值分数。
