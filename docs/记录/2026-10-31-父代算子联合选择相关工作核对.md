# 父代与算子联合选择：相关工作的一手核对

日期：2026-10-31，北京时间。本轮核对论文原文与作者官方源码，没有修改算法代码，没有运行实验。比较对象是 [V19](../机制设计/V19.md) 的实际实现。已在 [算子与交叉参考分配核对](2026-10-30-算子与交叉参考分配核对.md) 和 [轨迹预算分配文献核对](2026-10-30-轨迹预算分配文献核对.md) 中核对过的 RefineEvo、PathWise、ShinkaEvolve、OpenEvolve、ReEvo、MCTS-AHD、QUBE、Clade-AHD 不再重复，只在结论中引用。

## 1. 结论

**“父代价值依赖于对它施加的算子”这一认识已有直接先例。** 最接近的工作是 DGS（arXiv:2607.13911，2026-07）。DGS 把 `(算子, 父代集合)` 作为一个动作，用代理模型预测子代效用并加入不确定性项，再选择动作。它的受控实验显示：联合选择优于只选算子或只选父代。因此，TraceAAD 不能把“父代—算子联合分配”或“干预条件的父代价值”本身作为新认识。

**V19 实际上不是联合选择。** [selection.py:164–200](../../traceaad_v19/selection.py) 先按固定比例 0.45／0.30／0.25 抽算子，再在该算子内部按 `U_i,o` 抽父代。算子的边际比例不随证据变化。所以 V19 只估计了 `P(父代 | 算子)`，没有估计 `P(算子 | 父代)`，也没有估计联合分布。与 DGS 相比，V19 是更弱的一半。

**已有工作的空间可以按三个维度划分：**

| 维度 | 已有做法 | 代表来源 |
| --- | --- | --- |
| 先选父代，再按父代状态选算子 | 父代成绩、访问次数或失败类型决定算子概率 | Deliberate Evolution、DE-DDQN、Srinivas & Patnaik、DGM／HGM 的入口规则 |
| 先选算子，再在算子内选父代 | 算子决定父代抽样器 | TIDE、AdaEvolve、V19 |
| 直接对 `(父代, 算子)` 打分 | 代理模型或逐节点后验 | DGS、AB-MCTS 的 `stack` 模式 |

**V19 仍有可辨认的差异，但都是实现层面的选择，不是新问题。** 差异有三点：(1) 收益用子代在全库中的绝对质量，不用相对父代的改进；(2) 每个 `(父代, 算子)` 对使用非参数计数，不跨父代泛化；(3) 失败尝试按零质量计入开发次数。AB-MCTS 和 HGM 也用绝对分数；“非参数逐对计数”在 AB-MCTS `stack` 模式中已有贝叶斯版本。

**最值得做的检验：** 在 V19 中把逐算子统计合并为逐父代统计，其余不变。这直接对应 DGS 的 H4 与 H6 对照。若合并后结果不变，“干预条件”在 TraceAAD 中没有作用；若变差，才有证据支持它。

## 2. 逐项核对

### 2.1 DGS：对 `(算子, 父代集合)` 动作做代理模型选择

**来源。** Wang, Peng, Wu, Wu, Zhan. *How to Guide LLM Generation: Dual-Surrogate Guided Search for Automated Heuristic Design*. [arXiv:2607.13911v1](https://arxiv.org/abs/2607.13911)，2026-07-15，预印本。本轮在论文页与 GitHub 搜索中都没有找到官方代码。

**来源做法。**

- 动作 `x = (o, S)`。算子 `o ∈ {m1, m2, e1, e2}`，沿用 EoH 算子；`S` 是从前 K 名中选出的父代集合，大小由算子元数决定（式 18）。
- 用冻结的 ModernBERT 编码代码，得到隐表示 `z`。效用代理是一组集成头，按训练实例预测分数。转移代理以父代隐分布和学到的算子嵌入 `v_o` 为输入，预测子代隐表示的对角高斯分布。
- 获取函数（式 19）：子代期望效用 + β_u·效用不确定性 + β_u·λ_τ·转移不确定性，取 argmax。
- 无效程序的目标值设为该实例有效分数均值减 4 倍标准差（式 6）。

**真正支持的结论。** 表 2 是只在 TSP 上的受控对照，同一提示、预算和前 K 池。平均最佳训练分数（越高越好）：

| 配置 | 规则 | 分数 |
| --- | --- | --- |
| H1 | 轮转算子 + 排名父代 | −6.619 |
| H2 | 随机算子 + 排名父代 | −6.612 |
| H3 | 在线算子 bandit + 排名父代 | −6.449 |
| H4 | 联合算子—父代代理 | −6.406 |
| H5 | 只对算子用代理 | −6.802 |
| H6 | 只对父代用代理 | −6.701 |

这张表支持“联合动作优于单轴决策”。但 H4 只比 H3 高 0.043，任务只有一个，每组三次运行，没有方差或显著性。H5 比随机算子还差，这一点更有信息量：**只按算子学习，可能比不学习更差。** 消融表 3 中去掉转移不确定性 λ_τ 的下降最大（TSP −6.351 → −6.899）。注意 H4–H6 只用预测均值排序，没有使用完整获取函数，所以表 2 和完整 DGS 不是同一机制。

**与 TraceAAD 的差异。** DGS 跨父代泛化，依赖嵌入和神经代理；V19 逐对计数，不泛化。DGS 用 argmax；V19 按分数比例抽样。DGS 的算子由动作直接决定；V19 的算子比例固定。DGS 的父代只来自前 K 名；V19 的父代来自全部有效程序。

**可迁移经验。** 联合选择的收益主要来自“哪个算子作用于哪个父代”，单独调算子收益不稳定。若 TraceAAD 只想要这一收益，最简单的版本是让算子比例也由 `U_i,o` 决定，即对全部 `(i, o)` 一起抽样，而不是先固定抽算子。

**证据边界。** 无代码，不能核对实现。模型为 GPT-4o-mini，预算 200 次评价。超参数 K、β_u、λ_τ 等未在正文给出。

### 2.2 Deliberate Evolution：父代状态索引的算子权重

**来源。** Pang 等，*Deliberate Evolution: Agentic Reasoning for Sample-Efficient Symbolic Regression with LLMs*，ICML 2026，[arXiv:2606.04360](https://arxiv.org/abs/2606.04360)。官方仓库 [Xinyu-Pang/Deliberate-Evolution](https://github.com/Xinyu-Pang/Deliberate-Evolution) 在 commit `18ae1f1c33a0dfa3c81298bba035036d3b23ecaf`（2026-05-30）只有 README，写明代码“will be added soon”。

**来源做法（§3.1、算法 1、附录 C）。**

- 四个算子：Refine、Mutate、Crossover、Regenerate，从利用到探索排列。
- 先用 Boltzmann 选择抽父代（初始温度 0.5，指数降温 0.95，停滞时升到 2.0；表 8）。
- 父代决定状态：两个二值标志，即父代归一化排名是否 ≤ τ_r、访问次数是否 ≥ τ_v，共四个状态（式 7）。
- 每个状态保存一组算子权重，混合均匀下限 α/|O|（式 8）；附录给出 p_min 示例 0.05。
- 收益是相对父代的改进，截断到 [−0.5, 1.0]；无有效候选记 −0.5（式 9、附录 C.2）。只更新所选状态下所选算子的权重，乘以 max(δ, 1+ηr)，δ = 0.1（式 10）。

**真正支持的结论。** 表 4（物理子集，Qwen3-4B，单值无方差）：完整方法 NMSE 4.37e-4；固定 Refine 8.69e-3；均匀随机算子 1.02e-2。这证明“自适应选算子”优于“固定或随机”。它**没有**证明父代状态条件化有用，因为缺少“不分状态的全局自适应”这一对照。

**与 TraceAAD 的差异。** 方向相反：Deliberate Evolution 估计 `P(算子 | 父代状态)`，V19 估计 `P(父代 | 算子)`。它把父代压缩为四个状态，跨父代共享统计；V19 逐父代计数。它用相对父代的改进，V19 有意不用。

**可迁移经验。** “父代是否已被大量使用”这一个比特就能改变算子选择。这和 V19 的 `n_i,o` 承担的信号相同，但只用四个状态，统计量更稳定。均匀下限是所有自适应算子方案的共同保护。

**证据边界。** 无源码；正文未给 τ_r、τ_v、η 的数值；任务是符号回归，不是组合优化启发式。

### 2.3 TIDE：全局 UCB1 选提示算子，算子类型决定父代抽样器

**来源。** Chen, Zhong, Fan, Shi, Sun. *TIDE*，[arXiv:2601.21239v2](https://arxiv.org/abs/2601.21239)，预印本。正文未给代码链接；GitHub 搜索未找到。

**来源做法（§3.2.1，式 6）。** 五个算子臂：e1、e2、m1、m2、m3。标准 UCB1，C = 2√2（§4.1）。收益为“相对当前最优的适应度增益”，正文未定义归一化。选出算子后再选父代：交叉用锦标赛，变异优先当前精英。公式不含父代或岛屿输入，正文也没说统计是否按岛屿分开。

**真正支持的结论。** 表 3 中“去掉 UCB 改用随机算子”在 TSP、KP、OBP 上都变差，例如 TSP-200 相对差距 10.65% → 12.64%。这支持“全局算子 bandit 优于随机”，与 DGS 的 H3 > H2 一致。

**与 TraceAAD 的差异。** TIDE 学算子边际，父代规则固定；V19 固定算子边际，学父代条件。两者恰好互补。

**证据边界。** 无源码；收益归一化未定义；正文提到非平稳，但公式没有折扣或窗口。

### 2.4 AdaEvolve：岛屿 bandit 与“模式→父代”耦合，没有算子选择

**来源。** Cemri 等，*AdaEvolve*，[arXiv:2602.20133](https://arxiv.org/abs/2602.20133)；官方代码 [skydiscover-ai/skydiscover](https://github.com/skydiscover-ai/skydiscover)，commit `0d932b690670a7e544388ad362e9876c8bd256a0`（2026-09-13）。当前代码可能晚于论文版本。

**源码实际做法。**

- 岛屿选择：UCB，平均收益用衰减收益除以衰减访问数，探索项用原始访问数，C = 1.41（[adaptation.py:409–469](https://github.com/skydiscover-ai/skydiscover/blob/0d932b690670a7e544388ad362e9876c8bd256a0/skydiscover/optimize/search/adaevolve/adaptation.py#L409-L469)）。收益只在子代超过岛内最优时为正，并按全局最优归一化（[adaptation.py:324–378](https://github.com/skydiscover-ai/skydiscover/blob/0d932b690670a7e544388ad362e9876c8bd256a0/skydiscover/optimize/search/adaevolve/adaptation.py#L324-L378)）。
- 岛内强度 `I = I_min + (I_max − I_min)/(1 + √(G+ε))`，范围 [0.1, 0.7]，G 是衰减累积改进（[adaptation.py:153–172](https://github.com/skydiscover-ai/skydiscover/blob/0d932b690670a7e544388ad362e9876c8bd256a0/skydiscover/optimize/search/adaevolve/adaptation.py#L153-L172)）。
- 每次按强度抽模式：探索概率 I，利用 (1−I)·0.7，平衡 (1−I)·0.3。模式同时决定父代抽样器和提示标签（[database.py:556–600](https://github.com/skydiscover-ai/skydiscover/blob/0d932b690670a7e544388ad362e9876c8bd256a0/skydiscover/optimize/search/adaevolve/database.py#L556-L600)）。

**真正支持的结论。** 表 4 只有两个任务、三次运行：去掉自适应岛屿选择在信号处理任务上下降较大（0.7178 → 0.619）；去掉元指导下降最大。论文 Table 4 与 Table 1 的均值存在不一致（0.7178 与 0.698），该数字可能是最佳值。

**与 TraceAAD 的差异。** AdaEvolve 的“探索／利用模式”在功能上接近一个由岛屿状态决定比例的二元算子，再条件化父代抽样。这与 V19 的“先算子、后父代”顺序相同，但 AdaEvolve 的模式比例会随进展变化，V19 不变。

**可迁移经验。** 非平稳性用衰减收益和衰减访问数一起处理，避免平均值随访问增长趋于零。V19 每次按当前排名重算子代质量，也部分处理了非平稳，但开发次数从不衰减。

### 2.5 AB-MCTS／TreeQuest：逐节点贝叶斯后验，决定“扩宽还是加深”与动作

**来源。** Inoue 等，*Wider or Deeper? Scaling LLM Inference-Time Compute with Adaptive Branching Tree Search*，NeurIPS 2025，[arXiv:2503.04412](https://arxiv.org/abs/2503.04412)；官方库 [SakanaAI/treequest](https://github.com/SakanaAI/treequest)，commit `3fac4f8b07e14ed92742471492a59764993b9ab0`（2026-10-16）。当前库晚于论文，默认设置可能不同于论文实验。

**源码实际做法（AB-MCTS-A）。**

- 每个节点保存 GEN（从该节点生成新子代）与 CONT（进入已有子代）两个后验，以及每个已有子代的后验。默认 Gaussian–正态逆卡方共轭更新；也可选 Beta（[prob_state.py:118–176](https://github.com/SakanaAI/treequest/blob/3fac4f8b07e14ed92742471492a59764993b9ab0/src/treequest/algos/ab_mcts_a/prob_state.py#L118-L176)）。
- 观测是子代**绝对分数**，沿路径回传给祖先的 CONT 与子代后验（[algo.py:280–320](https://github.com/SakanaAI/treequest/blob/3fac4f8b07e14ed92742471492a59764993b9ab0/src/treequest/algos/ab_mcts_a/algo.py#L280-L320)）。
- “动作”是一组生成函数，论文多模型实验中是不同 LLM。两种模式：
  - 默认 `multiarm_bandit_thompson`：节点只决定 GEN／CONT；选 GEN 后用**全局**动作收益做 Thompson 或 UCB（[prob_state.py:361–420](https://github.com/SakanaAI/treequest/blob/3fac4f8b07e14ed92742471492a59764993b9ab0/src/treequest/algos/ab_mcts_a/prob_state.py#L361-L420)；默认值见 [algo.py:117–122](https://github.com/SakanaAI/treequest/blob/3fac4f8b07e14ed92742471492a59764993b9ab0/src/treequest/algos/ab_mcts_a/algo.py#L117-L122)）。
  - `stack`：每个节点为每个动作单独保存后验和 GEN／CONT 后验，先抽动作，再抽 GEN／CONT（[prob_state.py:337–359](https://github.com/SakanaAI/treequest/blob/3fac4f8b07e14ed92742471492a59764993b9ab0/src/treequest/algos/ab_mcts_a/prob_state.py#L337-L359)）。

**真正支持的结论。** 论文支持“在生成新候选与继续改进已有候选之间做自适应分配”优于重复采样和标准 MCTS。论文没有把 `stack` 与全局动作 bandit 作为核心对照，所以库中两种模式的相对价值没有证据。

**与 TraceAAD 的差异。** `stack` 模式在结构上最接近 V19：每个节点、每个动作一份统计，收益是绝对分数。差异是 V19 不回传到祖先，用 UCB 比例抽样而非 Thompson，且父代池是平铺的有效程序库而非树路径。

**可迁移经验。** 若要给 V19 的 `μ_i,o` 一个明确的模型名，它就是“以父代质量为先验均值、强度 κ 的逐对共轭均值”。AB-MCTS 已经用这种形式，并用后验抽样代替手调 λ。这说明 V19 的 κ 与 λ 可以换成一个 Thompson 规则，而不增加机制。

### 2.6 HGM 与 DGM：自我改进代理中的父代选择与规则化“入口”

**来源。** HGM：Wang, Piękos 等，ICLR 2026，[arXiv:2510.21614](https://arxiv.org/abs/2510.21614)，代码 [metauto-ai/HGM](https://github.com/metauto-ai/HGM) commit `013872d95da978483f5b540e531db063d23890da`。DGM：Zhang 等，[arXiv:2505.22954](https://arxiv.org/abs/2505.22954)，代码 [jennyzzt/dgm](https://github.com/jennyzzt/dgm) commit `a565fd2d1dca504ef5104a7cc0f3bdc4ab9b4fd2`。

**源码实际做法。**

- HGM 扩展：对每个节点，汇集本节点与全部后代的逐任务 0／1 评价，形成 Beta(1+成功, 1+失败)，Thompson 抽样选扩展节点（[hgm.py:360–404](https://github.com/metauto-ai/HGM/blob/013872d95da978483f5b540e531db063d23890da/hgm.py#L360-L404)；[tree.py:45–55](https://github.com/metauto-ai/HGM/blob/013872d95da978483f5b540e531db063d23890da/tree.py#L45-L55)）。默认 `cool_down: false`（[config.yaml:23](https://github.com/metauto-ai/HGM/blob/013872d95da978483f5b540e531db063d23890da/config.yaml#L23)）。
- HGM 扩展与评价的切换不是 bandit，而是确定性规则：`n_task_evals^0.6 ≥ 节点数` 时扩展（[hgm.py:406–420](https://github.com/metauto-ai/HGM/blob/013872d95da978483f5b540e531db063d23890da/hgm.py#L406-L420)）。
- DGM 父代：`sigmoid(10(score−0.5)) / (1 + 已入库子代数)` 比例抽样；子代数只计已进入存档的子代（[DGM_outer.py:50–100](https://github.com/jennyzzt/dgm/blob/a565fd2d1dca504ef5104a7cc0f3bdc4ab9b4fd2/DGM_outer.py#L50-L100)）。
- 两者的“算子”是自我改进入口（修空补丁、修随机性、修上下文长度、或某个未解决任务）。入口由父代的失败统计和固定概率 0.25 的规则决定，不学习（[DGM_outer.py:111–135](https://github.com/jennyzzt/dgm/blob/a565fd2d1dca504ef5104a7cc0f3bdc4ab9b4fd2/DGM_outer.py#L111-L135)；[hgm_utils.py:88–152](https://github.com/metauto-ai/HGM/blob/013872d95da978483f5b540e531db063d23890da/hgm_utils.py#L88-L152)）。

**真正支持的结论。** HGM 支持“用后代整体表现估计一个节点的改进潜力”优于只用节点自身成绩（与 DGM、SICA 的比较）。它没有检验入口选择。

**与 TraceAAD 的差异。** HGM 的信用覆盖整棵子树，V19 只看直接子代。DGM 的 `1/(1+子代数)` 与 V19 的 `n_i` 作用相同，但 DGM 不计失败尝试，V19 计入。

**可迁移经验。** “按父代失败类型选择修改方向”是一种零成本的父代条件算子规则，已在 DGM／HGM 中使用。V19 已在上下文中提供失败子代，但没有用失败类型影响算子选择。

### 2.7 CoEvo-AHD：两层 bandit，但无隔离证据

**来源。** Kuang, Deng 等，[arXiv:2606.00718](https://arxiv.org/abs/2606.00718)，预印本，正文无代码链接。

**做法与证据。** 交叉父代用全局 UCB1（式 9），每个组分种群用局部 Thompson 选算子；算子统计按算子保存，不按父代。表 3 的消融只比较单种群和去掉工具环境，**没有隔离任何选择机制**。它只能说明“已有人同时使用父代 bandit 与算子 bandit”，不能支持任何机制结论。

## 3. 横向认识

**收益定义是最一致的分歧点。** 自动算法设计中几乎所有算子 bandit 都用“改进”作收益：相对父代（Deliberate Evolution、DE-DDQN）、相对当前最优（TIDE、AdaEvolve）、或改进率（FRRMAB）。用绝对分数的是树搜索与自我改进方法（AB-MCTS、HGM）和 DGS 的效用代理。V19 选择绝对质量，与后一组一致。这个选择的理由已在 [父代选择定案](2026-10-30-父代选择定案.md) 中说明，本轮来源没有提供反对证据。

**失败记账各不相同。** Deliberate Evolution 记 −0.5（下限），DGS 记均值减 4 倍标准差，V19 记 0，DGM 不计入。在倒数排名质量下，V19 的 0 低于最差有效程序的质量 `1/M`，与 DGS 的做法方向一致：失败比任何有效结果都差，但不是无限差。

**均匀下限几乎是标配。** Deliberate Evolution 用 α/|O|，AdaEvolve 和 UCB 类方法用最少访问。V19 的算子比例固定，自然满足；若改为自适应算子，必须保留下限。

**联合选择的实测收益不大，且只有一个受控来源。** DGS 表 2 是唯一隔离“联合 vs 单轴”的证据，单任务、三次运行、无方差。Deliberate Evolution 和 TIDE 只证明“自适应优于随机或固定”。所以“联合选择有用”目前只是有一份弱证据支持的判断。

## 4. 对 TraceAAD 的含义

1. **定位。** “父代价值依赖算子”“预算分配给父代—算子对”都已有先例（DGS 直接，AB-MCTS `stack` 结构上）。TraceAAD 在这一点上的增量最多是：在 LLM-AAD 中，用逐对、绝对子代质量、计入失败的简单计数，替代 DGS 的神经代理。这是简化，不是新问题。
2. **V19 的“干预条件”需要先自证。** 建议唯一的下一检验是：V19 与“逐父代合并统计”的 V19 对照，其余全部相同。这对应 DGS 的 H4 vs H6，结果直接决定 `n_i,o` 是否值得保留。
3. **若条件化有用，下一步最简单的扩展**是对全部 `(i, o)` 一起按 `U_i,o` 抽样，使算子比例由证据决定，并为每个算子保留下限。这是 V19 现有统计量的直接推广，不新增模块。
4. **不建议现在引入**：代码嵌入代理（DGS）、子树回传（HGM、AB-MCTS）、状态化算子权重（Deliberate Evolution）。每项都对应不同问题；在第 2 点得到结果前，没有证据说明 TraceAAD 存在这些问题。
