## 本次修正

| 问题 | 修正与依据 |
| --- | --- |
| 空字段被下一行内容掩盖 | 按字段边界验证内容，拒绝空字段、重复字段和重复日志块。避免把不完整 delta 当作历史经验。 |
| 代码补全截取器可能丢掉模块初始化 | 补丁后直接解析完整模块，保留入口前后的初始化、辅助函数与文档字符串，再编译检查。父程序、评价程序和保存程序使用同一份模块。 |

| 评价中断后可能再次生成或重复扣预算 | 评价前保存待评价程序，评价后保存待 embedding 节点。恢复分别继续未完成阶段；生成预算用尽也可完成已有候选。另修正恢复后已消耗生成次数与历史年龄的对应。 |
| 长程序可能超过 embedding 输入上限 | 仅为 DeltaEvolve 增加完整代码分块和长度加权平均，单块最多 6000 UTF-8 字节。真实服务验证返回 1024 维向量，分块合计用量为 15012 tokens；各块内容和用量累加另有离线检查。 |
| 解析失败被计入评价次数 | 格式失败仍消耗生成预算，但不增加已完成的搜索评价次数。最终重评单独累加；恢复从候选记录还原计数。 |

我保留了原机制中的失败处理：生成程序若违反任务约束、执行报错或超时，只记录该次尝试，不加入种群，也不追加论文未定义的修复或反思调用。真实试跑曾出现 JSSP 的非法日程与索引错误、FSSP 对 NumPy API 的错误使用，以及图着色的慢候选。这些结果不能作为“接入失败”或“有效改进”处理。

## 固定的补充规则

默认 `w=10`，高分历史至多 3 个，多样性历史至多 2 个。3 个岛各保留至多 40 个占用格，全局保留成绩最好的 20 个程序。父程序按 0.1/0.2/0.7 进行精英、均匀探索与排名加权选择。embedding 使用固定种子 0 的两维随机投影和 10×10 网格；每 10 次返回生成结果做一次 0.1 比例的环形迁移。

历史层级遵循 Algorithm 1；历史反馈使用相对原父程序的定性变化。当前父程序显示负 raw objective，统一为提示中的最大化 FITNESS SCORE。模型的 HYPOTHESIS 仍是评价前的解释，不当作已验证的原因。默认使用本项目 DeepSeek 单模型；可显式设置副模型启用 0.8/0.2 混合。

## 验证条件与证据

全仓库 **126 项测试通过**。DeltaEvolve 专项覆盖完整模块、delta 字段、历史新旧层级、MAP-Elites 与迁移、预算和 token 记录、评价中断、embedding 故障恢复、Unicode 长程序分块，以及六任务的评价、最终选择、看板读取和配置重建。六任务命令行配置与 18 路排队计划也已检查。

真实验证使用 `deepseek-v4.1-flash`，关闭思考，temperature=0.7、top_p=0.95、输出上限 8192；embedding 使用 DashScope `text-embedding-v4`。每任务预算为 4：一次种子评价和三次生成。使用完整 16 个训练实例，按现有规则重评候选并固定最终程序，再评价 50 个同规模独立测试实例。每路使用两个实例 worker，不降低时间限制或合法性要求。

六任务均以 `finished` 结束，并完成独立测试。有效新候选数不包含种子：

| 任务 | 有效新候选 / 3 | 最终重评程序数 | 最终程序的独立测试 |
| --- | ---: | ---: | --- |
| TSP | 3 | 4 | 50/50 实例通过 |
| CVRP | 3 | 4 | 50/50 实例通过 |
| FSSP | 1 | 2 | 50/50 实例通过 |
| 图着色 | 0 | 1 | 50/50 实例通过，保留种子 |
| JSSP | 1 | 2 | 50/50 实例通过 |
| OP | 3 | 4 | 50/50 实例通过 |

图着色的两个候选分别用了平均 47.5498、56.7308 秒 CPU，超过 10 秒上限；第三个候选触及单实例 120 秒墙钟上限。因此，这一路只证明失败处理、保留有效种子和最终测试链路正常，没有得到有效的新程序。FSSP 另有一次运行错误和一次没有 SEARCH/REPLACE 补丁的回复。JSSP 另有一次平均 CPU 超限和一次非法日程。上述统计包含这些失败，没有只按成功候选计算。

六任务完成后，我逐一核对了看板读取的源码与固定程序一致，并重建配置、恢复检查点。各路均恢复为预算已用 4、剩余 0，随机状态可恢复；恢复得到的搜索评价次数与当时的 `delta_evaluated` 事件一致。

早期 `live/` 驱动曾误把按评价种子聚合的 `scores` 长度当作实例数，后来改为核对 `n_instances=50` 和实例评价状态；图着色的早期诊断运行也已主动停止。最终六任务结论只使用修正后的 `verified/` 记录。
