## TraceAAD 旧机制的一手核对

父代选择（`traceaad/v15/selection.py:1`，提交 e059e840）采用当前质量权重乘平滑的直接子代改善率：`exp(-beta*(fitness-best))*(improvements+3*pooled_rate)/(attempts+3)`。beta 按不同分数的有效样本量 8 设置，未尝试父代继承总体先验。计数来自程序记录，repair归给原生成；它估计的是局部改善概率，不是长期潜力，也没有按修复实际增加的模型调用成本折算。

谱系分配（`traceaad/v15/search.py:58`，提交 e059e840）在投入检查点比较各谱系与当前冠军谱系的历史最好成绩，优先投入最少的活跃挑战者；谱系内部才使用父代选择。投入是程序记录数，格式失败未建档时不计入该尺度。新 Base 已约定修复不另建个体，故不能直接沿用记录数作为成本。

配置（`traceaad/v15/config.py:10`，提交 e059e840）固定算子权重 Refine 0.45 / Explore 0.30 / Crossover 0.25；交叉参考（`traceaad/v15/selection.py:129`，提交 e059e840）从质量较好的半数候选中均匀选择，不等于识别互补机制。

[既有对齐前缀诊断](../../experiments_result/analysis/v18_frontier_20261029/README.md)显示 V18 TSP 的含偏差路径 219 次调用有 40 次改善父代却没有全局改善。两组父代与投入不同，不能视为 LDS 消融，但说明局部改善并不足以判断预算价值。旧版本同时改变生成提示、初始化与选择，不能从版本成绩给分配公式作因果背书。

## 后续综合需解决的问题

1. 轨迹结合有两种不同含义：用历史预测某个父代的下一次生成收益；或把预算给一条可继续发展的分支。祖先链在提示中出现，不要求选择也变成 MCTS。
2. 将全部后代成果回传给祖先可能奖励已被替代的旧程序；仅直接子代又可能忽略暂时退步后出现的改进。需核对文献如何定义实际获配对象。
3. 程序编号、独立尝试、模型调用与谱系成熟度必须分开。修复、无效格式与重复生成都耗费预算；重复程序不应因新编号刷新全部尝试经验。
4. 当前质量、改善幅度/概率、已获投入应保留各自含义。暂不把路径斜率直接当未来收益，更不把谱系距离当语义互补。
5. Base 的简洁性约束下，优先评估不新增规划器/思想审核的方案；具体推荐待两份文献核对完成后统一给出。

## 第一组文献核对后的认识

已复核轨迹预算文献记录。QUBE 的直接证据最接近当前父代选择问题：OBP 消融中，自身成绩选择、子代平均成绩选择、加入探索项的平均 excess ratio 分别为 3.07%、2.98%、2.89%；完整方法的 2.76% 还包含岛重置改动。奖励是子代绝对成绩，并非改善父代的幅度。MCTS-AHD 的子树最大值回传和 BaSE 的完整运行分配回答的是不同层级的问题，不能直接当成同一个父代收益估计。

我当前倾向先以直接子代的实际产出和成本支持父代选择，保留祖先轨迹指导生成，暂不将一个优质远代的成绩重复赋给所有祖先。这仍需与算子调度证据合并：不同算子产生不同分布，父代历史均值也受到曾经给它的算子影响。无新增模型调用。

## 综合推荐：质量与直接开发经验共同选择父代

**推荐 Base 采用“当前质量 × 平滑的单位调用成功产出”，三个算子固定配比，交叉参考在质量合格的去重候选中随机选择。** 祖先轨迹指导生成，直接开发轨迹更新父代的选择权重。暂不把远代成绩回传为祖先的繁殖收益，不新增谱系调度器、思想识别器或 LLM planner。用户已确认将该方案写入 Base 第 8 节；这是确定的默认设计，不是已验证最优策略。

### 为什么选择这一方案

QUBE 的分步消融直接支持观察子代产出而不只看父代自身成绩，但其绝对分数 UCB 存在无效/重复计分与尺度等尚需补充的细节。它不能直接证明下面的质量乘开发效率公式。Shinka 的质量乘欠探索权重是更简单的参照，但仅按投入惩罚会同时压低持续产生改进的程序。旧 TraceAAD 的平滑改进经验可作为一个可解释起点；这里明确补上调用成本、复制及交叉比较基准，不声称旧版本成绩验证了这些修订。

V15 18 路记录中，已被选中的父代 4060 个，尝试中位数 2，71.2% 至多被选 3 次。此时再为每个父代维护三个独立算子收益估计，数据过稀；为每个新节点强制依次试完三个算子，也会不断把预算花在冷启动。固定配比保留不同设计动作的机会，比凭少量观测判断某个父代只适合某个算子更稳妥。

### 具体父代规则

仅评价成功的程序可被选择；对规范化源码相同的程序，将其视为同一个选择候选并合并直接开发统计，档案仍保留各次记录。规范化只去除空白、注释与位置差异，不将同分视为同程序，也不宣称识别语义等价。选择一个确定代表（建议最早有效记录），后续上下文从这一代码身份关联的记录中按既定窗口取材；身份合并对父代历史展示的影响必须在实现前明确，不能仅合并权重却让重复程序获得空白历史。

设 q_p 为父代成绩，q_* 为候选最好成绩，C_p 为以它为主父代的普通生成及相应修复消耗的模型调用数，S_p 为这些尝试中产出“有效、此前未出现、超过输入最好成绩”程序的次数。一次尝试只记一次最终结果：

- Refine / Explore：最终子代严格优于父代。
- Crossover：最终子代严格优于父代与参考中较好者。
- 失败、格式错误、复制、持平与退步：调用计入 C_p，S_p 不增加。
- 修复成功：若满足上述条件，S_p 加一；生成和修复两次调用均计入 C_p。没有独立 Repair 算子收益。

每个完成的尝试都留存完整评价结果，选择奖励为零不代表丢弃有效退步个体或否定其后续价值。

建议权重为：

```text
r0 = (sum(S_p) + 1) / (sum(C_p) + 2)
e_p = (S_p + 3*r0) / (C_p + 3)
w_p = exp(-beta * (q_p - q_*)) * e_p
P(parent=p) = w_p / sum(w)
```

这里 e_p 是平滑的单位调用成功产出率，不是下一代成功概率的严格贝叶斯后验；3 是保留的先验强度，单位为等效调用，不是已证明最优值。未尝试程序的 e_p=r0，表示未知，不因零样本被判为无潜力。所有候选都有正权重，但这不保证每个新机制一定获得足够机会。

beta 沿用旧机制按不同成绩层级将质量权重有效样本量调至 min(8,层级数) 的规则，避免分数单位直接决定选择压力；层级数不超过8时 beta=0。8 同样只是初始默认，不等于最多开发8个程序。合并重复代码后，不合并同分不同程序。

相对于仅质量×投入倒数，这一规则让持续取得有用结果的父代保留机会；相对于仅局部改善率，质量项约束远离前沿的父代。它仍是启发式，不能声称最大化最终最好值的最优收益。

### 算子与参考

Refine / Explore / Crossover 默认 0.45 / 0.30 / 0.25，沿用旧设置以减少同时改动；没有证据支持这组数最优。先选父代，再按同一配比选算子。没有合格交叉参考时移除 Crossover 并归一化其余概率，记录实际执行算子。

参考从去重有效候选中，筛选成绩不劣于该池中位数者，再排除父代本身并均匀抽样一个。只把参考的 design 和成绩送给模型。这个规则保证参考质量并减少直接重复，不保证机制互补；不强制跨谱系，也不最大化祖先距离。一次交叉的调用成本与直接结果归主父代，参考身份保留用于分析，不重复发放两份收益。

V15 的 571 次交叉父代改进中，只有 375 次超过双方；因此判断交叉产出时必须避免把复现已有更强参考记成新的能力。但这些统计并不能证明必须超过双方的候选才值得继续开发，所有有效个体仍可进入普通选择。

### 轨迹在其中的准确作用

祖先的 design 与成绩用于理解算法形成过程；同父代的已有子代与失败信息用于指导下一次生成；所有实际调用及最终结果形成选择统计。提示 8/3/2 是展示窗口，统计不截成这13条。一个后代变强，首先增加的是其直接生成来源的开发证据；不能仅因它属于某条祖先链，就推断从每个祖先原代码重来都值得。

暂不增加“祖先连续改善奖励”或路径斜率：出生时的大改进不是未来改进率，经过选择留下的路径也缺少未展开分支的反事实。若后续证据显示关键突破反复经过先退步节点、且当前规则不给这些节点机会，再比较直接统计与分支预算，避免提前堆多层控制器。

### 最值得检验的一个问题

固定初始化、生成提示、8/3/2上下文、算子配比、参考与修复，仅比较“当前质量选择”和“质量×成本校正的开发经验”。按实际模型调用预算比较最终最好成绩与前沿推进，同时检查复制/失败和较弱父代的投入。此检验决定经验乘子是否值得保留；在此之前，不叠加自适应算子或整谱系回传。本轮未运行该实验。
