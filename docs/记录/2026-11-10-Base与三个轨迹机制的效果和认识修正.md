# Base 与三个轨迹机制：效果与认识修正

查询时间：2026-11-10 09:22，北京时间。只读正式实验；没有改动搜索、模型服务或运行条件。补做了一个不调用模型的代码行为探针。

我当前的判断是：同起点修改与结果对生成有直接帮助；新版机制1已有局部搜索收益，但形成轨迹的独立增量尚未分离；机制3已经能产生条件化笔记，却仍会把实现错误概括成算法原则。三者不能用同一个“轨迹有效”结论概括。

## 数据和比较边界

本次按固定主实验名单读取各路 `summary.json`、无 variant 的 `heldout.json`、`run_config.json` 和 `native/attempts.jsonl`。旧批次使用本地完成后的原始结果，新五组从 server4 只读抓取。共核对103份主测试：程序编号与训练赢家一致，测试源码SHA-256与 `best_program.py` 一致。所比较配对的共同配置字段无差异；输出schema的顺序属于机制2，比较时单列。逐路数据、配置核对与曲线更新保存在[证据目录](../../experiments_result/analysis/20261110_mechanism_assessment/)。

当前Base：5个有效初始算法，固定R/E/C概率0.45/0.30/0.25，按当前成绩做Boltzmann父代采样，同池随机交叉参考。演化生成只读当前算法；初始化和修复仍有共同反馈。预算1000次评价，包括失败与修复，使用Qwen3.8-27B，关闭思考。训练16例、主测试50例，分别共享160秒和500秒总时限。

11月5日的旧Base本来有祖先和子代上下文，而且采用旧父代分配规则。旧V21检验的是上下文组织、算子指令、参考和输出协议这一整套改变。新Base与旧Base不能直接拼接成一个对照。当前V21.1也取消了旧V21的参考结构分组。历史批次使用原冻结实现解释。

## 机制1：比较下一份预算的回报

旧实现的明确错误是把收益视为对称分布。原始诊断中Explore有82.4%退步，正残差中76.7%其实没有改善；接近冠军的父代上预测刷新概率27.5%，实际3.5%。下行造成的尺度膨胀被解释成上行机会。旧V22最终六任务均值都比V21差，与这个失败解释相容；最终分数本身不能证明全部损失都由该因素造成。

当前实现已改为真实冠军改善除以成本，并在近期、同算子、质量状态相近的记录间共享收益。出生算子、出生增益、路径动量和回撤参与相似度加权。固定状态重放已证明去掉轨迹权重会改变估计和分配；它尚未证明这种改变更准确。

新版TSP/CVRP及当前TSP/OP的正向结果说明不能再把机制1概括成无效。它最有希望发挥作用的位置是：在当前质量相近的程序与操作之间，利用已有开发响应改变下一份预算的机会成本判断。当前收益仍可能来自普通操作反馈或参考选择。

下一步优先保持当前模型与生成不变，分离同池随机参考下的“仅质量与普通历史收益”与“再加形成轨迹权重”。按时间前推检验实际收益排序，并做相同预算的接续比较。不要先加深前瞻。退步版本能恢复不是其值得投入的充分理由；必须与继续开发当前好版本比较。

当前Base的温度1.0使用各任务原始成绩单位，TSP差0.1对应权重比约0.90，FSSP差10对应约0.000045。这说明跨任务共享数值不等于共享选择压力。后续校准应在训练条件内预先固定各任务温度，并让各机制共用，不能按主测试结果挑温度。现有配对仍可解释为这些具体温度下的效果。

进一步核对已完成TSP、OP日志中真实评价编号101—1000的尝试：Base选择距冠军2%以内父代的比例分别仅3.23%、7.74%，V23.2为14.44%、19.20%；Base的TSP父代相对冠军差距中位数为14.98%。这支持“机制1部分补回质量集中”这一解释，尚不能分离它与轨迹独有信号、参考选择的贡献。原始计数见[父代位置](../../experiments_result/analysis/20261110_mechanism_assessment/parent_gap.json)。我因此把共同Base的温度校准提到价值特征继续扩展之前。

## 机制2：最直接的信息是同起点的修改与结果

我重新读取server4上11月5日的原始消融分析：17个固定提示、每臂3次采样，完整材料的子代改善率27.5%，去祖先仍为27.5%，去子代降至16.7%；去子代差值的按提示重采样区间为−20.6至−2.0个百分点。这个小实验直接支持同起点尝试的价值，未测出祖先段的一步增量。

旧V21在TSP主要减少较差运行，OP三路都超过旧Base最好一路。但当前V21.1的OP退步，提示整套机制的收益依赖搜索条件。源码也确认Explore根本不读祖先、子代、经验或当前成绩。因此，Explore发现新算法结构不能自动归功于轨迹阅读。

本次读取完成日志的第101—1000次评价：旧V21的OP Refine/Crossover有70.4%读到有效子代，新V21.1为59.0%；TSP从66.7%降至57.6%。新选择流程更分散，实际可供比较的同起点材料也变少。这只是机制交互的线索，参考规则、采样路径等也变化，不能将OP退步直接归因于材料覆盖下降。

下一步在固定父代、操作和生成协议下，只比较当前代码、增加少量相关同起点修改、再增加祖先。先保留有直接证据的同起点材料；祖先只在解释当前计算为何存在或某次修复丢了什么时加入。实际修改和结果要绑定，不能将模型自写分析当作已验证原因。当前Refine的“不要重复尝试过的修改”也应区分相同实现与相同思想：此前实现错误或支持条件已经改变时，重新实现可能有价值。

## 机制3：最新日志仍把实现退步提炼成算法禁令

最具体的新证据来自V24.1 TSP第1路。Program 73为6.03243，Crossover得到Program 145后为7.75975。反思把退步解释为“候选评价内部做2-opt会破坏几何结构”，继而要求只在选定候选之后修复。

但Program 145的2-opt允许反转包含首节点的片段。它按优化后的 `sequence[0]` 计算完整路径成本，却保存 `best_candidate = cand` 并返回原候选。这让评分对象与实际执行动作不一致。20个独立合成的12节点欧氏决策状态中，8个复现了所评分首节点与返回节点不同。该探针证明代码问题存在，没有测量修正后的任务收益，不能断言它解释全部退步。

反思同一窗口还看到了Program 85：它也在候选评价内做2-opt，并从6.89345改善到6.29808；它的实现固定了候选首节点。两个实现不能据此概括成“内部2-opt有害”。完整程序、原反思和探针结果见[案例证据](../../experiments_result/analysis/20261110_mechanism_assessment/reflection_case.json)。

这里真正值得迁移的认识是：如果候选动作靠模拟后续路径评分，局部优化必须保持候选首动作，或者返回与评分路径一致的动作。这个认识来自数据流核对，比“维持最近邻的几何纯净性”更有依据。它能否改善别的分支仍需检验。

当前机制3能保存带计算条件的认识，也能跨分支引用与修订，这是运行事实。CVRP已有按基础系数强弱修订空间衰减条件的条目。但更多条目不等于更多独立证据；TSP里反复出现关于纯最近邻和内部修复的相近禁令。相同来源的重复概括会强化同一个未经验证的解释。

我建议下一步先固定这个失败窗口、父代和后续修改机会，比较无经验、现有经验、纠正后的计算条件经验。看模型是否修复评分—动作不一致、是否还保留有价值的2-opt、实际收益是否改善。反思单元只需明确分开“观察到的改动和结果”“代码能支持的条件关系”“待检验的原因”，不要增加多层反思器。关键变化是先验证计算关系，再跨实现抽象；修复一个失败实现，不能自动推出整个算法思想不适用。

## 本轮优先级

我保留三个用途，但不再要求三者共享同一种轨迹表示：预算分配需要可比状态下的真实收益，生成需要与当前修改相关的局部比较，经验学习需要跨实现仍成立的计算关系。

近期先完成已在运行的同条件组，不新增堆叠机制。局部研究首先验证机制3的上述评分—动作案例，因为它能区分“轨迹不能产生知识”与“当前反思误读了实现”。随后分离机制1的形成轨迹增量；机制2用固定状态消融检验精简同起点证据能否在新Base下保持收益。本文中的改进方案是本轮建议，未写回WWH或改动机制实现。

下一批完整搜索应先固定合适的共同质量尺度，再比较轨迹增量；上述小型机制检验可独立进行。已有另一份[分配与算子审计](../../experiments_result/analysis/20261110_mechanism_effect_audit/)也显示Refine和Crossover的结果方向不同，支持按算子拆开验证。其跨批次合并统计是观察性证据，不能直接把参考代码呈现判为退步的原因。
