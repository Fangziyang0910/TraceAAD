相对比较基准 `[Task] description + score_definition（lower-is-better）`、`[Interface] signature + inputs + returns + execution constraints`：EoH 和 ReEvo 均向模型提供任务目标、目标函数接口及示例函数体。目标方向通常写在自然语言中，具体评估公式和资源限制并未统一作为提示字段展示。尤其要区分“装箱函数输出的优先级越高越好”与“完整算法的评估值越低越好”。EoH 的 ACO 示例还直接说明平均最优路径长度目标，不能笼统说所有任务都未说明评分含义。

## EoH

**任务、目标与接口。** 主查 `bp_online` 和 TSP 的 `aco_pheromone`，补查 `tsp_construct`。

1. **在线装箱 `bp_online`。** 任务明确要求设计箱子评分函数；每一步把当前物品放入评分最高的箱子，最终最小化使用的箱子数。原文为：

   > “In each step, the item will be assigned to the bin with the maximum score. The final goal is to minimize the number of used bins.”

   来源：[examples/bp_online/prob.py:32–36](/home/fang/code/LLM4AD/reference_code/EoH/examples/bp_online/prob.py:32)。实际放入提示的模板签名为：

   ```python
   def score(item: int, bins: np.ndarray) -> np.ndarray:
   ```

   模板 docstring 写明：`item` 是当前物品大小；`bins` 是**可行箱子的剩余容量**，且全部 `>= item size`；返回每个箱子的优先级分数，`Higher score = preferred bin`。因此，输入数组与输出分数逐箱对应；模板没有单独写 `(k,)` 这样的形状记号，也没有固定数组长度。示例函数体是 `return bins`。来源：[prob.py:20–31](/home/fang/code/LLM4AD/reference_code/EoH/examples/bp_online/prob.py:20)。

2. **TSP / ACO 信息素更新 `aco_pheromone`。** 这里让模型设计的是信息素更新规则（pheromone update rule）。任务明确点名蚁群优化（Ant Colony Optimisation, ACO），说明强化有潜力的边、蒸发其他边，并列举 Ant System、Elitist AS、MMAS、Rank-based AS 作为背景。目标原文为：

   > “The goal is to minimise the average best tour length found across TSP instances.”

   来源：[examples/aco_pheromone/prob.py:58–69](/home/fang/code/LLM4AD/reference_code/EoH/examples/aco_pheromone/prob.py:58)。模板签名完整给出：

   ```python
   def update_pheromone(pheromone: np.ndarray, ant_tours: list, tour_costs: np.ndarray,
                        best_tour: np.ndarray, best_cost: float,
                        rho: float, iteration: int, max_iterations: int) -> np.ndarray:
   ```

   模板逐项说明：`pheromone` 是当前对称信息素矩阵 `(n, n)`；`ant_tours` 是含 `m` 个 `(n,)` 城市访问序列的列表；`tour_costs` 为 `(m,)` 路径长度，明确 `lower = better`；`best_tour` 为历次迭代最优路径 `(n,)`，`best_cost` 为其长度；`rho` 是 `(0, 1)` 内的蒸发率；`iteration` 从 0 开始；`max_iterations` 是计划迭代总数。返回 `(n, n)` 信息素矩阵，值应非负。来源：[prob.py:28–46](/home/fang/code/LLM4AD/reference_code/EoH/examples/aco_pheromone/prob.py:28)。

   模板还提供完整的 **Ant System 更新函数**：先乘 `1-rho`，再按每只蚂蚁的 `1/cost` 给路径边及反向边增加信息素。它不是空函数或仅签名。来源：[prob.py:47–55](/home/fang/code/LLM4AD/reference_code/EoH/examples/aco_pheromone/prob.py:47)。

3. **补查构造式 TSP `tsp_construct`。** 任务要求访问每个节点一次并回到起点，寻找最短路径；明确逐步选择下一个节点。签名是 `select_next_node(current_node: int, destination_node: int, unvisited_nodes: np.ndarray, distance_matrix: np.ndarray) -> int`。docstring 将输入解释为当前节点 ID、返回节点 ID、未访问节点 ID 数组、所有节点之间的距离矩阵；返回下一个节点 ID。没有显式写 `(k,)` / `(n,n)` 或固定规模。模板函数体使用最近邻选择。来源：[examples/tsp_construct/prob.py:20–38](/home/fang/code/LLM4AD/reference_code/EoH/examples/tsp_construct/prob.py:20)。

**固定算法框架与完整程序骨架。** 上述提示都限定了要生成的局部函数，并给出该函数的可读实现；没有把完整 evaluator 或完整求解器程序放入提示。

- 在线装箱的逐项决策和最大分数选择已在任务文字中告知。实际循环由 evaluator 完成：筛选可行箱子，调用 `score_func(item, bins[valid])`，取 `argmax`，扣减容量。来源：[bp_online/prob.py:42–53](/home/fang/code/LLM4AD/reference_code/EoH/examples/bp_online/prob.py:42)。
- ACO 提示告知更新发生在迭代之间，但完整构造概率公式、蚂蚁数、具体迭代次数不在模板里。内部固定使用 `pheromone**alpha * eta**beta` 采样，`eta=1/distance`；每轮构造路径后才调用生成的更新函数，并将返回值截到至少 `1e-10`。来源：[aco_pheromone/prob.py:89–140](/home/fang/code/LLM4AD/reference_code/EoH/examples/aco_pheromone/prob.py:89)。`max_iterations` 的含义在提示中，运行时数值则作为函数实参传入，二者应区分。
- 构造式 TSP 的逐步选点已告知。内部从节点 0 出发，生成候选未访问节点，调用目标函数，最后补上剩余节点并计算回路长度。该循环源码没有进入提示。来源：[tsp_construct/prob.py:62–83](/home/fang/code/LLM4AD/reference_code/EoH/examples/tsp_construct/prob.py:62)。

**评分方向及执行限制：提示可见与内部执行。**

- **评分方向可见，具体公式随任务而异。** 装箱提示是“最少箱子”，内部实际返回各数据集相对下界超额 `(平均箱子数 - 下界) / 下界` 的均值；该公式没有放进提示。来源：[bp_online/prob.py:55–67](/home/fang/code/LLM4AD/reference_code/EoH/examples/bp_online/prob.py:55)。ACO 提示已经写明“平均最优路径长度”；内部还对每个实例的多次运行取均值，再跨实例取均值，重复次数和随机种子细节没有展示。来源：[aco_pheromone/prob.py:144–152](/home/fang/code/LLM4AD/reference_code/EoH/examples/aco_pheromone/prob.py:144)。构造式 TSP 返回平均回路长度，见上述 `tsp_construct/prob.py:62–83`。
- **没有独立注入统一的 `score_definition` / `lower-is-better` 字段。** `BaseProblem.evaluate_program` 的内部文档写有 `A float fitness value (lower is better)`，但该方法文档不属于提示模板。种群管理实际按 `objective` 取最小值。来源：[problem.py:115–125](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/problem.py:115)、[eoh.py:37–47](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/eoh/eoh.py:37)。父代提示块只放算法描述和代码，不附数值 fitness，见 [evolution.py:169–173](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/eoh/evolution.py:169)。
- **运行时间限制没有展示。** 装箱、构造式 TSP 示例使用 40 秒，ACO 示例使用 60 秒，均是评估配置；不是每次局部函数调用的独立预算。来源：[bp_online/runEoH.py:17](/home/fang/code/LLM4AD/reference_code/EoH/examples/bp_online/runEoH.py:17)、[tsp_construct/runEoH.py:17](/home/fang/code/LLM4AD/reference_code/EoH/examples/tsp_construct/runEoH.py:17)、[aco_pheromone/runEoH.py:18–28](/home/fang/code/LLM4AD/reference_code/EoH/examples/aco_pheromone/runEoH.py:18)。实际评估交给超时子进程，超时后结束进程树，见 [eoh.py:222–225](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/eoh/eoh.py:222)、[evolution.py:84–107](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/eoh/evolution.py:84)。LLM 请求自身的网络超时也未写入任务提示。
- **依赖与内存。** 提示要求 Python 函数，模板使用 `np.ndarray` / NumPy 操作，但没有依赖白名单、版本限制或内存上限。内部在执行生成代码前注入 `np`，并处理模板顶层 import；这不是向模型声明“只能使用 NumPy”。来源：[problem.py:92–110](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/problem.py:92)。在本次检查的通用执行链中，也未见显式内存上限或导入白名单检查。

## ReEvo

**任务、目标与接口。** 主查非 `black_box` 的 `bpp_online` 和 `tsp_aco`。

1. **在线装箱 `bpp_online`。** 配置中的 `description` 解释 BPP 是把物品装入最少数量的固定大小箱子；在线版本必须在收到物品时立即放置。来源：[cfg/problem/bpp_online.yaml:1–6](/home/fang/code/LLM4AD/reference_code/reevo/cfg/problem/bpp_online.yaml:1)。接口说明原文为：

   > “The priority function takes as input an item and an array of bins_remain_cap (containing the remaining capacity of each bin) and returns a priority score for each bin. The bin with the highest priority score will be selected for the item.”

   来源：[prompts/bpp_online/func_desc.txt:1](/home/fang/code/LLM4AD/reference_code/reevo/prompts/bpp_online/func_desc.txt:1)。签名是 `def priority_v{version}(item: float, bins_remain_cap: np.ndarray) -> np.ndarray:`，见 [func_signature.txt:1](/home/fang/code/LLM4AD/reference_code/reevo/prompts/bpp_online/func_signature.txt:1)。模型知道每个箱子对应一个输出分数；没有显式 `(k,)` 记号、固定长度或“传入数组已筛除不可行箱子”的声明。种子函数中的容量与 `item` 运算进一步展示了物品大小语义。

   **样例函数确实提供。** `seed_func.txt` 给出完整 `priority_v1`，包含以容量、当前物品大小计算分数、符号处理和相邻差分的 8 行代码；不是空白骨架。来源：[seed_func.txt:1–8](/home/fang/code/LLM4AD/reference_code/reevo/prompts/bpp_online/seed_func.txt:1)。

2. **TSP / ACO 启发式 `tsp_aco`。** 配置描述是：

   > “Solving Traveling Salesman Problem (TSP) via stochastic solution sampling following "heuristics". TSP requires finding the shortest path that visits all given nodes and returns to the starting node.”

   来源：[cfg/problem/tsp_aco.yaml:6](/home/fang/code/LLM4AD/reference_code/reevo/cfg/problem/tsp_aco.yaml:6)。接口说明将输入定义为距离矩阵，输出定义为每条边被纳入解的潜力先验，并明确 `The return is of the same shape as the input.` 来源：[prompts/tsp_aco/func_desc.txt:1](/home/fang/code/LLM4AD/reference_code/reevo/prompts/tsp_aco/func_desc.txt:1)。这里给出的是“同形状”关系，没有写具体节点数或 `(n,n)` 记号。

   签名模板为 `def heuristics_v{version}(distance_matrix: np.ndarray) -> np.ndarray:`，见 [func_signature.txt:1](/home/fang/code/LLM4AD/reference_code/reevo/prompts/tsp_aco/func_signature.txt:1)。实际初始化展示的完整种子函数是：

   ```python
   def heuristics_v1(distance_matrix: np.ndarray) -> np.ndarray:
       return 1 / distance_matrix
   ```

   来源：[seed_func.txt:1–2](/home/fang/code/LLM4AD/reference_code/reevo/prompts/tsp_aco/seed_func.txt:1)。初始化还附两条外部知识：组合多个因素评估边；把无潜力元素置零以稀疏化矩阵。来源：[external_knowledge.txt:1–2](/home/fang/code/LLM4AD/reference_code/reevo/prompts/tsp_aco/external_knowledge.txt:1)。

**固定算法框架与完整程序骨架。**

- 在线装箱提示已告知“物品到达即放置”和“选最高分箱子”。实际 evaluator 先筛可行箱子，再传入剩余容量子数组，按 `argmax` 选择并扣减容量。**可行性预筛选是内部行为，未在上述 ReEvo 任务提示中明确写出。** 来源：[problems/bpp_online/eval.py:12–35](/home/fang/code/LLM4AD/reference_code/reevo/problems/bpp_online/eval.py:12)。
- `tsp_aco` 的任务提示没有直接写 `ACO`、蚂蚁或信息素；模型得到的是“按启发式随机采样”和“边的潜力先验”。`problem_type: aco` 存在于配置，但没有插入 `user_generator`。这是与 EoH `aco_pheromone` 的实质区别：**ReEvo 生成边启发式矩阵，EoH 该示例生成信息素更新函数。** 不能仅因都用于 ACO 而把接口视为相同。
- 内部求解器才给出完整 ACO：先构造距离矩阵并将对角线设为 1；调用生成的启发式，加 `1e-9` 并截到至少 `1e-9`；以 30 只蚂蚁运行 100 次迭代。来源：[problems/tsp_aco/eval.py:19–30](/home/fang/code/LLM4AD/reference_code/reevo/problems/tsp_aco/eval.py:19)。选择权重为 `pheromone**alpha * heuristic**beta * mask`，按分类分布采样；信息素更新由固定代码完成。这些公式、参数和截断规则没有展示在任务提示中。来源：[aco.py:46–58](/home/fang/code/LLM4AD/reference_code/reevo/problems/tsp_aco/aco.py:46)、[同文件:105–117](/home/fang/code/LLM4AD/reference_code/reevo/problems/tsp_aco/aco.py:105)。输出的“潜力”语义可见，但数值如何转成采样概率、非负性如何处理没有作为接口约束明示。
- 两个任务都提供目标函数的样例实现；初始化不提供完整装箱循环、ACO 类或 evaluator 程序骨架。后续交叉和变异还展示父代函数体。

**评分方向及执行限制：提示可见与内部执行。**

- **自然语言目标可见，`obj_type: min` 不直接展示。** 两个任务配置都设为 `min`，但公共提示只插入函数名、任务描述和函数说明。反思/交叉另以 `[Worse code]`、`[Better code]` 告知相对优劣，不提供数值评估值或公式。来源：[reevo.py:51–95](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:51)、[同文件:325–349](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:325)、[prompts/common/crossover.txt:1–15](/home/fang/code/LLM4AD/reference_code/reevo/prompts/common/crossover.txt:1)。
- **装箱的最终评估值是百分比超额。** 辅助 `evaluate()` 返回负平均箱子数，但主程序再次取负，计算 `100 * (平均箱子数 - l1_bound) / l1_bound` 并输出；ReEvo 读入这一最终数值，按最小化比较。不能仅看辅助函数的负号就判断完整优化方向。来源：[bpp_online/eval.py:38–61](/home/fang/code/LLM4AD/reference_code/reevo/problems/bpp_online/eval.py:38)、[同文件:111–121](/home/fang/code/LLM4AD/reference_code/reevo/problems/bpp_online/eval.py:111)、[reevo.py:216–220](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:216)。该公式没有写入提示。
- **TSP 的最终评估值是 ACO 搜索所得最短回路长度的跨实例均值。** `ACO.run()` 维护并返回搜索中的 `lowest_cost`，训练 evaluator 对各实例结果取均值；这些聚合细节没有写入任务提示。来源：[aco.py:31–44](/home/fang/code/LLM4AD/reference_code/reevo/problems/tsp_aco/aco.py:31)、[eval.py:45–58](/home/fang/code/LLM4AD/reference_code/reevo/problems/tsp_aco/eval.py:45)。ReEvo 内部以 `min(objs)` 更新最优个体，见 [reevo.py:249–265](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:249)。
- **运行时间限制没有展示。** 默认配置为 `timeout: 20`，评估器启动独立 Python 程序后通过 `communicate(timeout=self.cfg.timeout)` 等待，超时则标记无效并杀掉进程。该限制作用于 evaluator 进程，不是提示中承诺给单次 `priority` / `heuristics` 调用的时间预算。来源：[cfg/config.yaml:27](/home/fang/code/LLM4AD/reference_code/reevo/cfg/config.yaml:27)、[reevo.py:197–207](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:197)、[同文件:230–245](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:230)。训练规模 `5000` / `50` 也作为运行参数使用，没有通过这条提示拼接路径展示。
- **依赖与内存。** system prompt 要求只输出 Python 代码，签名使用 NumPy 数组；未展示库白名单、版本、内存上限或复杂度要求。代码提取器会在文本包含 `np` / `torch` 时分别补 `import numpy as np` / `import torch`；这是生成后的处理，不能当作模型已知的依赖约束。来源：[prompts/common/system_generator.txt:1–2](/home/fang/code/LLM4AD/reference_code/reevo/prompts/common/system_generator.txt:1)、[utils/utils.py:78–104](/home/fang/code/LLM4AD/reference_code/reevo/utils/utils.py:78)。在本次检查的 evaluator 启动和执行链中，也未见显式内存上限或导入白名单检查。

## FunSearch：程序规格与模型所见提示需分别核对

FunSearch 的公开实现以 Python 程序规格定义任务：`@funsearch.evolve` 标记待设计函数，`@funsearch.run` 标记评价入口；示例规格还包含固定求解流程、类型注解、参数说明和返回值说明。[示例规格](/home/fang/code/LLM4AD/reference_code/funsearch/implementation/specification_nonsymmetric_admissible_set.txt:40)、[入口识别与初始化](/home/fang/code/LLM4AD/reference_code/funsearch/implementation/funsearch.py:30)。

实际生成提示并不自动包含整个规格程序：`_generate_prompt` 保留程序前缀，将函数列表替换为按成绩排序的历史目标函数和待续写的新版本函数头；第一份目标函数保留原文档说明，后续版本使用 “Improved version of …”。[提示构造](/home/fang/code/LLM4AD/reference_code/funsearch/implementation/programs_database.py:205)、[程序字符串表示](/home/fang/code/LLM4AD/reference_code/funsearch/implementation/code_manipulation.py:68)。

## 与核查时 TraceAAD Base 草案的区别

| 内容 | 已核对的相关实现 | 核查时 Base 草案 |
| --- | --- | --- |
| 任务与目标 | 任务配置或自然语言描述；FunSearch 也使用代码前缀及文档。 | 单列 `task.description` 和 `task.score_definition`。 |
| 待设计部分 | 常说明函数在固定求解框架中的角色，例如选下一节点、给箱子打优先级、给边生成启发值。 | `task.description` 可以承载，但当前模板未明确要求填写这部分。 |
| 输入输出 | 函数签名加自然语言说明，或代码文档；内容常合写。 | 拆成 `signature`、`inputs`、`returns`。 |
| 执行约束 | 部分写高效计算、所需库或导入要求；数值限额未必进入提示。 | 单列 `constraints`，拟明确时间、内存和依赖限制。 |
| 评分方向 | 常用任务目标说明；FunSearch 提示用好坏排序和 improved-version 组织历史。 | 明确写出评价指标与 lower-is-better。 |

上述差别主要是信息的组织方式和显式程度，不能从格式差异推出生成质量优势。我们应把这部分视为由具体任务及固定求解框架提供的任务规格；尤其要说明函数的使用位置、返回值如何被消费，以及评价指标的含义。若单列评价指标，建议使用 `Evaluation metric`，避免和启发函数返回的局部优先级混淆。

按后续讨论，Base 草案改为采用常见的 `task_description + template_program`，由对应基准任务提供任务说明与函数模板；未进行生成质量对照。
