# 轨迹行为信号与等预算接续

北京时间2026-11-03。完整条件、原始程序和复现脚本见[报告](../../experiments_result/analysis/trajectory_feature_probe_20261103/README.md)。本次新增独立分析模块和小接续实验，没有改在线Base/V19.4或方法正文。

用户同意先实现轨迹特征，在独立历史前缀上锁定案例，再用小预算接续补足原历史缺失的反馈。另一侧协作进一步要求测量同分/未改善子代中，未执行改动和相同输出的发生率。我将两件事分开：前者检验有限接续下的响应，后者检查“已经试过几次”究竟包含什么。

我实现了进展动态、尝试覆盖、实现变化及代价三组特征。选样只使用此前没有进入案例和预测分析的Base-schema六任务×三路前200次评价前缀。候选和规则冻结后才揭示后续；四个起点都没有再被直接开发。因此原历史仍然无法给出它们在相同预算下的收益。

完整批次11490个未改善子代中，185个规范化源码相同，2个被当前窄静态规则识别为不生效分支。这不是所有行为重复的比例。从前缀未改善子代按任务和算子随机抽取的144对中，18对在固定输入上输出相同。图着色精炼/探索/融合为3/8、2/8、2/8；JSSP为1/8、1/8、3/8；TSP为2/8、0/8、2/8。每格样本小，不能据此给算子排优劣。121对完成语句跟踪，零覆盖检出0；其余23对跟踪超时。新增条件判断执行过也不再算零覆盖，这个指标过严，不能用零检出否定未执行改动。

阅读源码并在全部16个训练实例上复查后，我确认三个不同原因：TSP P20→P21先归一化再取排名，决策顺序不变；OP P9→P10的预算惩罚在实际距离范围内恒为1；JSSP P59→P117新增第三层平局判据，排程不变。这些改动可以增加计算且确实执行，却没有改变输出。它们支持把行为变化补入表征，而不是只看AST距离或执行行数。

测量本身也改变了我的判断。TSP最初只取六个公共决策状态，17/24对看起来相同；在同一对程序上跑完两个实例的路线后，只有4/24对相同。另有7对探针输出相同但历史分数不同。少量输入一致不能直接记为无效尝试。跟踪也会改变墙钟停止算法的结果，因此我对跟踪失败和计时程序共32对做了无跟踪复测，覆盖缺失仍保留。完整历史还存在4对逐字相同代码分数不同，涉及无种子随机数或墙钟终止；程序差异与运行差异需要区分。

新接续共四起点×首步精炼/探索×两次重复，每条6次真实模型请求。96次请求全部计入预算，其中10次用于修复；96次评价为82成功、6错误、8超时，另有四次起点复评。12/16条改善起点，4条在第2次请求后继续改善，没有超过前缀全局最好。这个结果说明局部可修复空间和对全局最好值的收益是两种判断，不能只用相对差起点的改善量估值。

配对结果也不支持把粗特征直接当成排序规则。图着色P17是P16加未生效小图分支后的版本，执行部分相同，续跑差异可能来自描述、冗余代码、历史或生成随机性。JSSP结构大幅删减后退步的P127能被修好，但普通对照P29只需修改优先级就恢复得更好；“修复删掉很多”不自动表示更高恢复价值。两例都保留预先锁定的候选，没有看结果后换案例。

我现在建议保留真实尝试数、行为重复/改动覆盖、结果三类输入，暂不合成确定的有效尝试数。价值仍估计固定接续预算下突破当前最好的概率乘以突破条件下的期望幅度。首步算子、后续接续规则和预算必须明确；本次Explore接续不代表Crossover。LLM可独立定位实现缺陷，不能与反思合并，也不能把诊断直接当成已验证收益。

当前证据支持继续研究行为与过程信号，尚未证明新共享预测器或完整选择策略有效。最影响下一步的未知量是：在相同fitness与当前代码表征之外，这些过程信息能否帮助选中固定多步预算下更好的起点。
