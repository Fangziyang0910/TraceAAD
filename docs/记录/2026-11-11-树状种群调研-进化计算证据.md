# 树状种群调研：进化计算、GP、人工生命与 QD 的一手证据

核验时间：2026-11-11，北京时间。开始时真实 clock 为 `2026-11-11 02:02:27 UTC`，即北京时间 10:02:27；主要来源核验截至 10:12。本文只处理更广泛的进化计算，不覆盖父代理负责的 AAD 文献。

## 结论

我找到的最接近先例是 **Phylotrack/Empirical 的在线谱系维护**。它不仅删除绝灭旁支；当前官方代码还明确实现了**删除无存活成员、只有一个子节点的中间节点，并将其子节点接回父节点**。因此，“保存个体演化来源、剪枝、压缩路径并重连”已有直接实现先例。[2024 年论文，Lineage Recording](https://arxiv.org/pdf/2405.09389v2#page=4)、[官方压缩实现](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L1472)。

**谱系参与搜索也有明确先例。** Fry 与 Tyrrell 在 2003 年用祖先关系影响配偶选择；Lalejini 等在 2023—2024 年用祖先及近亲的评价记录补充当前评价，并影响选择和评价分配。不能把“在线利用谱系”整体作为新的机制。[Fry 与 Tyrrell，§1](https://www.cs.york.ac.uk/rts/docs/GECCO_2003/papers/2724/27241804.pdf)、[Lalejini 等，2023，§2—2.1](https://arxiv.org/pdf/2306.03970v1#page=5)、[2024 年后续工作，§2](https://arxiv.org/pdf/2402.01610v1#page=2)。

现有证据对应了构想中的不同部件，但这些部件的责任不同：**谱系维护解决历史表示与存储；树状种群拓扑限制交流与选择；谱系驱动策略决定后续搜索。** 当前构想可继续推进的具体问题是：在预算限制下，怎样保留对后续选择、LLM 算子上下文和经验学习有用的代表节点与发展关系。是否形成新方法，要由具体保留规则、重连语义和搜索收益决定。本轮没有核实到下述七项中的某一项同时实现了这整套组合。

## 先区分树表示什么

| 树的类型 | 节点与边的含义 | 剪枝或重排实际改变什么 |
| --- | --- | --- |
| 程序树 / 抽象语法树（AST） | 节点是表达式、语句或算子 | 改变单个程序，通常涉及复杂度或 bloat 控制 |
| 种群拓扑（population topology） | 节点是 agent、解的存放位置或子种群；边限定交流、配偶或迁移 | 改变谁能与谁交互；通常不表示真实祖先 |
| 个体谱系树（phylogeny / ancestry tree） | 节点是完整个体或其基因型等分类单元；边表示演化来源 | 删除历史、压缩发展路径，或改变可用的祖先信息 |

这是本文的比较口径。下面分别给出实际算法，避免仅凭标题中的 tree 或 pruning 判断相同。

## 最接近的七项

### 1. Phylotrack / Empirical：在线谱系剪枝与单子节点压缩

**来源与年份。** Emily Dolson、Santiago Rodriguez-Papa、Matthew Andres Moreno，*Phylotrack: C++ and Python libraries for in silico phylogenetic tracking*，2024。论文核验至 arXiv v2；代码核验为 Empirical 提交 `56d1679efa31bb27e013e7910afdd7b94b1587cc`。**2024 是论文年份，不表示下述每个当前 API 都已在 2024 年版本中出现。** [论文](https://arxiv.org/abs/2405.09389)、[官方源码](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp)。

**准确做法。** 模拟程序在线报告出生、父 taxon 和死亡。taxon 可以按个体、基因型或表型等定义；后代与父代的分类特征相同时可以共用 taxon，否则新建后代节点。默认删除没有存活成员、也没有存活后代的绝灭分支。它维护的是实际来源关系，不是事后从相似性推断的树。[论文 Methods / Lineage Recording，PDF 第 4—5 页](https://arxiv.org/pdf/2405.09389v2#page=4)。

当前代码有三个需要分开的操作：

- `Prune` / `RemoveOffspring`：移除无成员、无后代节点，并在必要时递归清理祖先。[实现 L1431 起](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L1431)。
- `SetCollapseUnifurcations(true)`：启用单子节点压缩（unifurcation collapse）。压缩对象没有存活成员、只有一个直接后代。`CollapseUnifurcation` 将后代的 `parent` 改成被删节点的父节点，更新连接，再删除中间节点。该选项默认关闭。[开关](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L404)、[触发与重连实现](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L1460)。
- `RemoveBefore(ud)`：删除早于给定时间、且祖先也符合时间条件的历史节点；实现会把保留下来的后代父指针置空。**这是截断历史，不是把后代接到某个相似代表节点。** [实现及说明 L1750 起](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L1750)。

**相同与不同。** 这是“在线长树—清理旁支—删除中间节点—重连”的直接先例。但库本身提供谱系基础设施，不规定按搜索前景淘汰仍然活跃的分支，也不规定深度、分支数和总节点数三个硬限制。taxon 还可能合并多个相同类型个体，不能默认一节点就是一个完整算法版本。

**可借鉴。** 直接借用“绝灭旁支清理”和“非活跃单子节点压缩”的区分。代码提供 `OnPrune` 与 `OnCollapseUnifurcation` 回调，可以在删除前转存需要的摘要；这为压缩后保留经验提供了现成接口，但摘要内容仍需自己定义。[回调 L913 起](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L913)。

### 2. Phylogeny-informed fitness estimation：带评价信息的谱系在线参与搜索

**来源与年份。** Alexander Lalejini、Matthew Andres Moreno、Jose Guadalupe Hernandez、Emily Dolson，*Phylogeny-informed fitness estimation*，2023 年预印本。后续为 Lalejini、Marcos Sanson、Jack Garbus、Moreno、Dolson，*Runtime phylogenetic analysis enables extreme subsampling for test-based problems*，2024。[2023 原文](https://arxiv.org/abs/2306.03970)、[2024 原文](https://arxiv.org/abs/2402.01610)。

**准确做法。** 2023 年方法为谱系节点记录各训练用例的实测结果。当前个体没有测过的用例，用最近已测祖先的结果估计；另一版本通过广度优先搜索寻找最近已测近亲。估计结果补齐 lexicase selection 使用的评价向量。搜索距离可以设上限。论文还明确建议剪掉绝灭分支：这不改变祖先估计，却可能删除近亲估计本来可用的信息源。[§2—2.1，PDF 第 5—7 页](https://arxiv.org/pdf/2306.03970v1#page=5)。

2024 年的祖先驱动子采样进一步根据谱系决定**当前应测哪些用例**，优先测该个体祖先最久没有测过的用例。它不只是为选择提供统计，还改变评价预算的分配。[§2.1—2.2.2](https://arxiv.org/pdf/2402.01610v1#page=2)。

**相同与不同。** 相同点是保留发展过程中的评价信息，让历史在搜索期间继续发挥作用。区别是其核心是逐用例评价估计与子采样；没有把压缩后的代表个体树用作 LLM 上下文，也没有给出按代码嵌入重接谱系的策略。

**可借鉴。** 先确定谱系服务的查询，再决定能删什么。该文已经给出一个具体例子：同一次旁支剪枝，对只查祖先和同时查近亲的策略影响不同。另一个简化点是，论文指出祖先估计可通过父代向后代传递所需评价记录实现，不一定要维护整棵树。[2023，§2—2.1](https://arxiv.org/pdf/2306.03970v1#page=5)。

### 3. Fry 与 Tyrrell：祖先树直接影响配偶选择

**来源与年份。** Rodney Fry、Andy Tyrrell，*Enhancing the Performance of GP Using an Ancestry-Based Mate Selection Scheme*，GECCO 2003，LNCS 2724，pp. 1804–1805。[作者所在大学提供的全文](https://www.cs.york.ac.uk/rts/docs/GECCO_2003/papers/2724/27241804.pdf)。

**准确做法。** 每个 GP 个体关联一棵二叉祖先树。树保存哪些前代个体参与了当前个体的生成，以及各亲本提供的比例，即亲本贡献比例（Parental Contribution Fraction，PCF）。第一个亲本按普通锦标赛选；选第二个亲本时，根据它与第一个亲本的祖先差异调整候选适应度，再做锦标赛。[§1，pp. 1804–1805](https://www.cs.york.ac.uk/rts/docs/GECCO_2003/papers/2724/27241804.pdf)。

**相同与不同。** 这是实际来源信息在线影响搜索的明确先例，目标是减少近亲交配、保持多样性。它关联的是每个个体的向上祖先树，不是将整个活跃种群组织成一棵向下生长、统一剪枝的树；这篇两页论文没有交代中间节点压缩、重连或全局树容量控制。

**可借鉴。** 交叉生成不能只记录“有两个亲本”，还可以区分贡献。对于 LLM 融合，能确认的通常是输入来源，不能直接照搬 GP 片段占比来声称实际代码贡献。

### 4. ETGP：按程序结构相似性反复分裂子种群

**来源与年份。** Ján Antolík、William H. Hsu，*Evolutionary Tree Genetic Programming*，GECCO 2005，pp. 1789–1790；另有 2004 年详细版本。[2005 原文](https://gpbib.pmacs.upenn.edu/gecco2005/docs/p1789.pdf)、[2004 会议原文，印刷页 27–37](https://itat.ics.upjs.sk/proceedings/itat2004-proceedings.pdf)、[作者实验室出版记录](https://www.kddresearch.org/page/publications-posters)。

**准确做法。** 从一个大子种群出发，每隔若干代，对满足大小条件的子种群按 GP 程序结构距离聚类，再用新的子种群替代旧的子种群。采用修改后的层次凝聚聚类（Hierarchical Agglomerative Clustering，HAC）；子种群大小按平均适应度分配。树状发展发生在**子种群 / 物种分裂层面**。[2005，§3.1 与 §5](https://gpbib.pmacs.upenn.edu/gecco2005/docs/p1789.pdf)。

**必须辨明。** 该文的 `Starting depth`、`End depth` 和随代数变化的最大深度，限制的是**单个 GP 程序树**。这些参数不能作为“限制个体谱系深度”的证据。[2005，§4.2，p. 1790](https://gpbib.pmacs.upenn.edu/gecco2005/docs/p1789.pdf)。

**相同与不同。** 相同点是持续分化、结构相似性参与组织种群、资源向不同分支分配。不同点是树记录群体分裂，节点并非完整算法个体；已核验的方法段落没有给出代表个体之间的谱系压缩重连。

**可借鉴。** 可以把代码结构或嵌入用于判断一组后代是否值得分成不同搜索方向。但这是一种分组决策，不能据此把相似个体自动认作真实祖先。

### 5. 树状 memetic algorithm：固定树拓扑、精英记忆与向上传播

**来源与年份。** Luciana Buriol、Paulo M. França、Pablo Moscato，*A New Memetic Algorithm for the Asymmetric Traveling Salesman Problem*，*Journal of Heuristics* 10，483–506，2004。[出版社记录](https://doi.org/10.1023/B:HEUR.0000045321.59202.52)、[作者 França 上传的正式全文](https://www.researchgate.net/publication/2541063_A_New_Memetic_Algorithm_for_the_Asymmetric_Traveling_Salesman_Problem)。

**准确做法。** 用三层、13 个 agent 的完整三叉树组织种群。每个 agent 保存两个完整可行解：`Current` 和 `Pocket`。`Current` 用于继续优化；`Pocket` 保存较好解。中间层 agent 同时属于上下两个重叠子种群。`UpdatePocket` 更新本地记忆；`PocketPropagation` 在下层 pocket 优于上层时交换两者，使好解向根传播。[正式论文 §2.2—2.3，pp. 487–488；作者全文](https://www.researchgate.net/publication/2541063_A_New_Memetic_Algorithm_for_the_Asymmetric_Traveling_Salesman_Problem)。

**相同与不同。** 这是真正参与选择和重组的树状种群，不是程序 AST，也不是仅画图。但节点是持续存在的 agent / 存放位置，且每个节点有两个解；树边表示组织关系，不能读成“下层个体由上层个体演化而来”。所谓重组树主要是交换存放的解，不是压缩真实出生历史。

**可借鉴。** 它展示了用固定分支数、固定层数和有限存储组织持续搜索，以及把可继续发展的当前解与精英记忆区分开。若采用这类位置交换，就需要单独保留真实来源，不能让交换改写历史。

### 6. Minimum Spanning Trees of Patches：节点对应个体的在线压缩存储与重连

**来源与年份。** Maxim Buzdalov，*Improving Time and Memory Efficiency of Genetic Algorithms by Storing Populations as Minimum Spanning Trees of Patches*，GECCO 2023 EvoSoft workshop，pp. 1873–1881。[作者预印本](https://arxiv.org/abs/2306.16686)、[全文 §3](https://arxiv.org/html/2306.16686v1#S3)。

**准确做法。** 节点对应候选个体，边保存两个个体的差分（patch）。只将一个个体的完整基因组实际展开，其余可沿路径应用差分恢复。生成后代时更新最小生成树，使差分存储的总规模较小。个体被淘汰后先标为 discarded；若该节点度为 1，则删除，并递归检查邻居。已淘汰个体可以暂时留作内部连接点。[§1、§3，Operations](https://arxiv.org/html/2306.16686v1#S3)。

**相同与不同。** 很接近“完整个体的可恢复表示—在线加入—删除无用节点—重连”。但边的含义是存储差分，不是实际演化来源。一个新后代可以通过更短的差分接到其他个体；这种重连不能用来解释它由谁产生。论文也没有把度为 2 的历史节点自动收缩作为上述删除规则。[§3](https://arxiv.org/html/2306.16686v1#S3)。

**可借鉴。** “保留一个算法个体”不必等于每份代码都完整常驻内存。但存储树和来源谱系承担不同事实；若同时采用，不能用最小差分连接覆盖真实 parent。

### 7. QD 中的谱系选择信号：能预测后代留存，不等于能改进选择

**来源与年份。** Corrado Calamita、Matteo Mendicini、Luca Ferrari、Riccardo Bertamini，*From Admission to Retention: Predicting Durable Offspring in Quality-Diversity Search*，2026-11-04 预印本。[一手全文](https://arxiv.org/html/2611.06522v1)。

**准确做法。** 在无结构的质量多样性（Quality-Diversity，QD）档案、Dominated Novelty Search（DNS）中，记录谱系深度、祖先适应度统计等信号。深度定义为从 founder 沿 base-parent 链到当前个体的繁殖步数。随后用按信号排名的 softmax 替换均匀亲本采样。[§2，Signal availability / Selection rule](https://arxiv.org/html/2611.06522v1#S2)。

**关键结果。** 论文在三个任务的观测分析中报告：浅谱系更易即时入档，深谱系更关联长期留存。但在 Omnidirectional Ant 的深度选择干预中，偏好深谱系、减弱偏好或反转偏好，都没有在 QD-score 和覆盖率上超出均匀选择，差异处于种子间波动范围内。[§3，尤其 Neither signal converts into a selection rule](https://arxiv.org/html/2611.06522v1#S3)。

**相同与不同。** 这是“谱系信息作为在线选择信号”的直接近邻；它使用有限容量档案，并没有在线维护、压缩或重连树状种群。可借鉴的是分清后代入档、后代留存与最终搜索质量。该实验也不支持把谱系深度本身直接设为更高的扩展优先级。

## 其他重点线索核验

- **谱系距离与廉价多样性标记。** Gabor、Belzner，*Genealogical Distance as a Diversity Estimate in Evolutionary Algorithms*，2017：既研究显式祖先关系，也给个体附加不参与任务解码的 bit vector，随变异和交叉更新，用 Hamming 距离估计亲缘差异。实验将多样性加入用于选择的适应度 `f′(x,P)=f(x)+λd(x,P)`。这是搜索中利用谱系多样性的先例，但其廉价版本正是为了避免维护越来越大的显式祖先图。[§4—6](https://arxiv.org/html/1704.08774v1#S4)。
- **HFC 不是祖先树。** Hu、Goodman、Seo、Fan、Rosenberg，*The Hierarchical Fair Competition Framework for Sustainable Evolutionary Algorithms*，2005：按适应度区间组织多层子种群，通过 admission / export 阈值向上迁移，并持续向底层引入随机个体。层级保护新个体发展，边不表示出生关系。它适合借鉴分层竞争与持续补充新方向，不能作为谱系压缩先例。[作者全文，§3.2.1—3.2.3、Figure 4](https://cse.sc.edu/~jianjunh/paper/ecj_hfc.pdf)。
- **Spector / Helmuth 线索主要是祖先分析。** McPhee、Casale、Helmuth、Spector，*Visualizing genetic programming ancestries using graph databases*，2017：将实际亲子关系存进图数据库，抽出成功或最终个体的祖先子图，再比较成功、失败和不同选择法。该文报告的是分析和可视化，不提供以图的剪枝规则控制搜索的算法。[原文 §1—2](https://www.cs.hamilton.edu/~thelmuth/Pubs/2017-GECCO-poster-ancestries.pdf)。
- **QD 中的祖先图也可能是分析工具。** Nordmoen 等，*MAP-Elites Enables Powerful Stepping Stones and Diversity for Modular Robotics*，2021：§3.3 对个体祖先图进行统计，并把祖先投影回形态 niche，解释 stepping stones。这里的祖先图统计用于分析搜索行为。[§3.3、Figures 10—12](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2021.639173/full)。
- **phylogenetic diversity 研究不能直接替代策略证据。** Hernandez、Lalejini、Dolson，*What can phylogenetic metrics tell us about useful diversity in evolutionary algorithms?*，2021 预印本，研究谱系指标与传统多样性指标、未来搜索表现的关系。它支持“谱系包含值得测量的信息”，不是“最大化这个指标或按它剪枝必然更好”的证据。[原文与摘要](https://arxiv.org/abs/2108.12586)。

## 对当前构想最有用的操作与判断

**可以直接借用的操作是：先清理绝灭旁支，再考虑压缩非活跃单子节点。** 两者都能删除历史存储，但无需把仍在发展的后代一起淘汰。保留祖先发展路线的办法已有实现，是否还要保留被压缩节点的评价转折、算子记录或代码差异，则由后续查询需要决定。上面的 Phylotrack 回调和运行时评价估计分别给出了实现接口与信息需求的实例。

**一个与容量限制有关的推导。** 假设维护单亲树，保留 `A≥1` 个活跃个体；递归删除所有非活跃叶子，并压缩所有非活跃单子节点。剩余非活跃节点都至少有两个孩子，因此它们至多有 `A−1` 个，整棵树至多有 `2A−1` 个节点。这是我根据树结构作出的推导，不是论文报告的保证；它要求不额外保留非活跃单子历史检查点。它也不保证浅树：深度仍可随 `A` 增长。由此，总节点数与最大深度是不同约束，不必一开始把所有限制都做成独立启发式。

**重连后必须保持关系含义。** 压掉 `a→b→c` 中的 `b` 后，`a→c` 表示跨过中间版本的祖先关系，不能继续当作一次真实算子调用。若后续选择使用演化步数，应保留被跨过的步数；若使用路径经验，应保留需要的摘要。按代码或嵌入相似性重接到非祖先，则改成了相似性组织，不能仍称真实谱系。Buzdalov 的存储树正好说明这种区别。

**交叉使谱系天然可能成为有向无环图（DAG）。** 两个亲本都影响一个后代时，严格来源不再是单亲树。Fry 的 PCF 以及 McPhee 等的双入边图都明确处理多亲本。当前若要保留便于调度的树，可以指定 base parent，同时记录其他输入来源；这是可选实现取舍，不是完整出生谱系本来就是树。

我的创新判断是：**“树状维护 + 谱系剪枝 + 中间节点重连”本身已有先例；“谱系参与选择”也已有先例。** 值得继续具体化的是，怎样让一个受预算约束的代表个体结构保留后续生成真正需要的发展信息，以及这种保留是否比同预算的普通种群更有效。这轮证据没有替该问题给出答案，也没有证明这一整套组合在全部文献中从未出现。
