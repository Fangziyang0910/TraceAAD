# 轨迹价值：现有记录能提供什么线索

我按用户要求先分析有偏的历史结果，寻找可核查的现象，不把旧机制的结果当成拟议机制的检验。此次核对Base六任务三种子的18份冻结快照，提取12,312条生成前开发状态，按独立运行验证三组输入，并导出45份程序与评价版本核对源码。没有新增LLM调用、算法评价或在线实验。

我找到两条值得继续研究的线索。

第一，JSSP seed1的P51为1951.75，Explore生成P77的初稿因未推进状态的循环超时，修复后为2083.375。修复保留了新的候选筛选结构，但用短工时排序替换了剩余工作量等信息。随后P84保留这一结构、加入剩余工作量，达到1861.25，成为当时新最好。这说明“修复后的坏成绩”可以与“有具体接续机会”同时成立。轨迹让我们看见丢掉了什么，代码让我们判断它能否接回新结构。它是已兑现的历史例子，不是事前预测成功率。

第二，图着色seed0的P81→P96从41.375改善至41.0625，但P96的两个直接子代P100/P106均同分。两份新增逻辑分别受n≤100、n≤20保护，冻结评价为300点图；移除这些不可达入口和专用函数后，剩余AST都与P96相同。后来P109仅把随机构造100改为150，改善到40.9375。上升的主链趋势与无效旁支不矛盾：旁支没有检验此前有效的改进方向。这个区分需要趋势、代码和评价条件一起读，不能单凭两次同分降低整个节点的潜力。

筛查也出现了会误导支持性叙事的候选。TSP的P255增加了regret公式，其后代确实改善；但公式可化为对原评分的正仿射变换，在精确算术下不改变选择。不能据此说新增regret机制已经生效。我保留这个对照，避免把结果串成想要的故事。

批量预测没有给出稳定优势。用适应度与共同条件、再加当前AST/词项、再加轨迹三组输入，留一路验证的“超过父代”平均AP分别为0.4458、0.4182、0.4219，“新全局最好”为0.1110、0.1006、0.0814。这个结果应如实保存；它检验的是粗表征对旧策略已选动作下一步结果的预测，没有检验多步接续，也没有自动表达两个案例中的关键代码语义。因此当前进展是找到了表征应区分的具体情况，尚未证明自动排序和预算分配有效，也没有理由用此结果否定未检验的设计。
