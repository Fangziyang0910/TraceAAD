# 动态反思简化实现与验证

我将自洽性审查后的最小方案落实到工作区EvoTrace V2。主线保持为树状种群的持续生长、个体选择、结构简化与经验利用：一次保留集合同时决定候选算法、必要分叉、路径收缩和旁支整理，再把经验交给后续生成。

## 实际改动

- 默认冷却窗口为40次评价。当前前半候选中的质量与差异代表、近期出生或实际用作父代/参考的可行节点共同决定保留集合。冠军保留，同一维护中只选择一次。删除宽度、长度、提前等待阈值，不增加反思积累队列。
- `topology.py`在维护前树上完成LCA闭包与唯一分区，同时支持剪枝和路径收缩。质量选择只检查满足质量门槛的候选，结构锚点不反过来排斥算法代表。
- 新增真实使用时钟与历史统计。节点直接开发、参考次数仍是自身统计；移除节点和旧经验的投入沿同一分区进入`selection_history`或`variation_history`。虚拟根承接已淘汰方向，方向累计评价不因最后一个显式节点消失而清零。
- 反思输入给出直接开发与承接历史的实际次数，区分观察和解释，允许材料少时更简短。收缩边明确表示发展阶段，不冒充一次真实算子调用。仍按每个最终区域一次调用，调用失败沿用已有回退并保留统计。
- 已完成尝试继续作为唯一恢复来源，嵌套历史统计随树恢复。CLI与搜索接口拒绝旧宽度/长度配置；旧实验必须使用其原冻结源码。

当前完整规则见[V2设计](../EvoTrace-v2设计草案.md)。V1包、分配公式、三算子生成策略和在线冻结批次未修改。

检查期间出现的两处历史校验失败属于检查器假设错误，均已修正后重跑全部历史状态：最初用原始源码字符串匹配已清理注释/文档字符串的上下文，改为按现有清理契约比较AST；最初计算区域目标时遗漏了补回的LCA节点，改为对全部原节点计算祖先关系。没有删除失败状态或跳过检查。

## 自行审查

我对照修改前源码检查了选择、统计、反思、恢复和入口。确认同轮排名不会随删除改变；历史投入不进入当前算法的`children_count`；计数与文字经验按同一分区交接；统计聚合不刷新使用时钟；整方向消失不丢累计评价；恢复不重放已提交的反思。审查补充了CLI旧配置的明确拒绝，避免以参数构造异常代替可理解的恢复边界。

当前没有发现阻塞实施的问题。仍需用真实搜索回答的事项是：冷却与相对质量选择的反馈是否过早压掉有潜力的新方向，以及每区域一次反思的收益是否值得成本。当前没有为这些未知量新增容量控制器、开发配额或复合评分。确定性回退仍是有限长度摘要，统计守恒不等于全部旧文字逐字保留。

## 原始证据

证据目录：[evotrace_dynamic_implementation_20261113](../../experiments_result/analysis/evotrace_dynamic_implementation_20261113/)。

- `before/`保存修改前包、测试和本轮修改前的相关文档；包和测试的初始哈希位于`before/manifest.json`。
- `full_tests_final.txt`为最终全仓输出，`historical_verification.json`为144个历史状态的逐项结果。
- `verify_history.py`为历史检查脚本；`history_stdout.txt`为最终汇总。
- `source_hashes.json`记录交付时实现、测试与历史检查脚本的哈希。

执行命令：

```bash
.venv/bin/pytest -q tests/evotrace_v2
.venv/bin/pytest -q
.venv/bin/python experiments_result/analysis/evotrace_dynamic_implementation_20261113/verify_history.py
```
