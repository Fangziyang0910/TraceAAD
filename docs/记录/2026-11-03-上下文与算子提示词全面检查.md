## 判断

当前提示具备任务、父代、轨迹、经验、三算子和结构化输出，基础完整。主要缺口在于：**部分设计原则只存在于中文论述，没有进入实际英文指令；输入中的自述、观察和建议缺少清楚的阅读关系；三种算子的计算目标还可以写得更明确。** 继续增加检索复杂度不能替代这三处交接。

好提示应让模型清楚知道：本次设计什么函数、当前实现怎样产生结果、历史试过什么、哪些经验可能有用、本次算子要求怎样改变计算，以及最终交付什么。它不必要求模型逐项解释所有材料，也不应要求模型证明历史没有提供的因果关系。

## 1. 哪些需要写，哪些应交给系统

| 必须传达的内容 | 在本项目中的具体作用 | 不应扩张成什么 |
| --- | --- | --- |
| 任务与函数的设计范围 | 区分下一节点函数、边先验、扰动函数与完整求解器；返回值在外层过程中的角色明确 | 每个算子都重述任务，或把可修改范围扩大到固定框架 |
| 当前实现与本次操作 | 当前代码是实际起点，说明延续、替换或接入哪项计算 | 把代码等同于优良机制；把所有历史组件都设为必须保留 |
| 历史关系与客观结果 | 形成路径、同起点尝试、相对父代反馈、可见窗口不是全部历史 | 按成绩排序形成模仿榜单；把连续成绩变化写成因果贡献 |
| 文字来源的性质 | 原始analysis/design是生成意图，review是代码解释，Result是实测反馈 | 把review升级为已验证事实，或声称代码能证明质量原因 |
| 经验的使用方式 | 寻找当前条件或能通过本次改动建立的条件，说明适配 | 必须执行经验、逐条辩论经验，或只许借已有结构内的建议 |
| 操作后的计算联系 | 改动怎样影响构造、选择、更新或返回结果 | 必须删所有看似无用代码、只能改一行、禁止调参或新增评分项 |
| 三字段输出 | analysis讲修改理由；design讲完整新方法；code完整实现 | 增加长篇诊断、证据表、逐步内心推理或第四个字段 |

检索方法、AST特征、RRF名次、评价器内部设置、成本记账、恢复逻辑不属于算法生成的推理任务。系统负责筛选、数值比较、编号、schema、裁剪和记录，提示负责使用筛选后的材料。经验选择器可以看召回线索，但无需把所有排名传播到最终生成。

## 3. 明确保留与删除

保留：Base任务说明、函数模板、analysis/design/code三字段和原schema；父代完整代码；最终参考完整代码；同起点好坏反馈；空历史自然退化；失败只描述本次实现；有依据的调参、增加评分信息、改变内部表示和合理多过程组合。

删除或不加入：

- “必须优于父代”“证明每项改动有效”“找出导致提升的原因”。当前结果不能提供这些证明。
- “所有历史设计必须保留”“所有失败方向都不要再试”。这会把参考变成搜索禁令。
- “一定要全新／完全不同”“只能做一处编辑”“禁止修改常数／增加评分项”。这些限制没有对应真实算子目标。
- 每轮强制引用多个经验、逐条说明不采用理由、输出长诊断表。它们争夺短analysis的空间。
- 在最终生成里解释检索分数、反思维护、预算估值、静态分析细则。它们属于宿主机制。
- 通用的“你是世界顶级专家”“深刻思考”“全面充分分析”等角色和程度修饰。没有交代具体动作，不能替代任务信息。

不因“期望效果”删去所有假设。模型应提出值得试的理由，但把它当预期，而非报告未发生的提升。也不加入“每个运算必须直接影响返回值”：辅助验证、可行性检查、候选生成和间接更新也可有用。

## 4. 建议的生成指令替换稿

以下文本只填Base的Instruction，不重写task_description、function_template或Output，也不增加字段。顺序为公共要求、选中算子、只在对应材料存在时追加的上下文提示、短输出职责。每段只承担一种作用。

### 4.1 公共要求

```text
Develop a candidate to improve solution quality for the stated task. Design the required function for its stated role in the surrounding procedure, using the available inputs and preserving its output contract. Internal helper computations are allowed.
Read the current code as the implementation being modified. Historical designs, reviews, experience notes, and suggested transfers are interpretations or proposals; evaluated results report outcomes, not the cause of those outcomes.
```

这里没有复述所有数据合法性、规模或评价设置。函数的具体边界由原task和template给出；不能写成“只许局部简单规则”，否则会误禁函数内部的有用求解计算。

### 4.2 Refine

```text
Refine the current decision mechanism. Identify a specific limitation or opportunity and change the computation that addresses it, keeping the main mechanism as the basis of the new method. Make coordinated changes where the improvement requires them, and implement the complete function.
```

“main mechanism”仍需通过analysis指出实际计算，不以相同名称认定延续。不要求证明限制已经成立；它可以是任务结构或历史启发的候选判断。删除单项编辑的暗示，保留一次有明确目标的改进。

### 4.3 Explore

```text
Develop an alternative decision mechanism for the required function. Introduce or reorganize a computation that changes how the method uses the available information to make its decisions, and explain that difference from the current method. Use the history to inform the alternative without requiring it to retain the current representation or computation pattern. Implement the complete function.
```

这里允许新信息、不同组织或新组合，不指定最近邻／前瞻／某类搜索等示例。是否构成不同机制要回到代码判断；仅换名称、公式重写或源码结构并不能由自述变成探索。无需再写一长串语法禁令。

### 4.4 Crossover

```text
Adapt a useful computation from the reference to work with the current method. Identify the decision it will change and how the two sources contribute to the resulting procedure, adjusting their representations or order of computation where needed. Implement the complete function with that interaction in its actual decision process.
If the full reference code does not offer a coherent adaptation, say that the reference was not used and implement your proposed candidate without claiming a fusion.
```

保留合法协作和两套过程配合，不规定只能逐组件拼接。诚实退出仍是现有机制允许的行为；不能因这句话就把退出当融合成功。若大量融合请求均绕开参考，应核对参考质量／可接入性和模型理解，再决定机制如何回退，不无限追加“必须融合”。

### 4.5 有材料才加的提示

```text
ANCESTORS:
Use the formation path to understand earlier changes to the current computation. Respect the recorded parent links and omitted intervals.

OFFSPRING:
Compare the modifications already tried from this parent and their outcomes. A useful next proposal may extend an improvement, revise an unsuccessful implementation, or test a different combination.

FAILURES:
Use execution feedback to address the reported implementation issue; it does not establish that every realization of the idea is unsuitable.

EXPERIENCE:
Use a note when its conditions hold or when your proposed change can establish them. Adapt the idea to the current computation; leave it unused when it adds no useful guidance. A note can also inform further development of a computation already present.
```

不要把四个标签和四段指令无条件全部发送。没有祖先但有经验时，只追加经验段；只有执行失败时不要伪造性能比较。

### 4.6 在原Output前补一次职责说明

```text
In analysis, briefly identify the computation you will change and why the change is worth trying. Cite an Algorithm or Experience id only when a specific observation informed that choice; a proposal may also follow from the task and current code without a historical precedent. Describe expected benefits as expectations, not measured improvements.
Use design to describe the whole proposed function as a self-contained procedure, including how it determines its returned result. Implement that procedure in code.
```

不要求输出逐步内心推理。analysis是可复查的修改理由，design是可实现的方法说明，两者不是同一段话的长短版本。不追加保留／删除／加入三个强制列表，也不要求全部引用；2—3句可以围绕一次具体改变展开。

## 5. 上下文应怎样呈现

建议记录格式如下，字段取舍仍需单独验证：

```text
[Evaluated Offspring: selected direct attempts from Current Algorithm P]
Showing selected records; other attempts are omitted.

Algorithm C | Parent P | Operator Refine
Result relative to P: {parent_fitness} -> {child_fitness}; {improved/tied/regressed}
Design: {self-contained method description}
Reviewed change: {review, when available}
OR Proposed change: {original analysis, when review is unavailable}
Changed computation: {optional complete local before/after units}
```

review存在时不再同时重复整段原Analysis；后台仍保存全部原文。Reviewed change明确是评价后模型解释，不叫Verified change。父代自身的原analysis也标成Origin proposal，不能被误认为本轮已选修改指令。

失败记录显示执行状态和去敏错误，不填性能增益。祖先变化点卡显示真实父节点与省略区间。经验卡保留条件与关键正反观察，不用“已证明”“最佳策略”等权威标签。选择器的Possible transfer在最终生成中标为Tentative transfer，完整参考代码允许生成器调整先前建议。

保持当前完整代码位于靠近Instruction的位置是合理候选，不因文献就宣称该位置最优。不要再复制一份当前代码或反复在首尾重述完整任务来补注意力。应先删除重复自述，再比较位置。

## 6. 选择器提示的必要修正

当前选择器应判断材料是否有用，不提前替生成器形成整套算法。建议核心要求为：

```text
Select context that can inform the requested modification of the current function.
For each selected note, identify a condition that already holds or a specific change that would establish it, then explain how the lesson could inform this proposal. Keep the observed outcome distinct from the proposed application. Select zero to three notes and omit redundant guidance.
For Crossover, first identify a plausible computation to adapt from a reference, then choose notes relevant to that combination or to a reference-independent part of the proposal. Retrieval tags identify matches, not established applicability. Base implementation claims on visible code; mark an interpretation drawn only from a description as tentative.
```

匹配条件不必每次都是“已经满足”；否则经验只能在原有表示内部流动。若建议的计算已存在，应明确经验还能帮助什么，不能机械剔除相近代码。

**需要同时处理的合同问题。** 当前schema强制Crossover有reference对象；即使短卡不足以识别有用计算，也没有拒绝状态。单靠“不要编造”不能消除被迫填写。推荐候选是允许reference=null表示未找到有依据的接入；宿主记录requested Crossover／executed Explore，保持原拓展父代、不重选，不加第二次选择请求。该修改须连同schema、调用条件、空结果处理和记录一起进入规格，不能只改提示中的一句话。它与“没看完整代码所以暂定选择”是两个可比较方案，本轮不隐式更改现有执行合同。

## 7. 证据与验证边界

本地[案例核对](2026-11-03-轨迹双机制调研-本地案例.md)证明出现过自述与实际计算不同、低分被解释为质量恢复、反例随经验修订消失。它不证明这些失败全由当前候选提示造成：案例来自旧运行，当前规格尚未上线。Base的FAILURES和实际客户端也已核对，当前请求把整份prompt放在一个user消息中，不能声称系统消息已隔离或提升某些指令优先级。

[EoH本地生成提示](/home/fang/code/LLM4AD/reference_code/EoH/eoh/src/eoh/eoh/evolution.py:180)按探索、修改和调参区分要求；[ReEvo变异提示](/home/fang/code/LLM4AD/reference_code/reevo/prompts/common/mutation.txt)将代码与反思直接交给生成。可借鉴的是操作与交付具体，不把它们的全部措辞当最佳范本。例如EoH的different form不能保证决策机制不同；ReEvo的according to reflection也不保证反思适用。

[Lost in the Middle](https://arxiv.org/html/2307.03172v3)在问答／键值检索中发现位置和长度影响，不能证明本模型在AAD中的某种布局一定更好。[Self-planning §4.3](https://arxiv.org/html/2303.06689v3)的HumanEval变体表显示短计划和单阶段可行，叠加解释层未稳定优于计划。借鉴的是不无条件堆分析层，不由此取消本项目短analysis或宣称其必需。

最先做两项分开的对照：固定同一批父代、算子、轨迹和经验，只改Instruction；再固定Instruction，只改“原Analysis＋Design＋Review”与“Design＋一份修改说明”的卡片。评价实际计算接续、有效率、重复率、改进及成本，而非分析是否更长、更像专家。融合另记录实际采用参考与否，探索以代码中的决策差异人工复核，不能只看自报算子。语法、schema与空历史组合可静态检查，行为收益需要真实调用和评价。本轮未执行这些模型实验。
