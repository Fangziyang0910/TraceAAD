# TraceAAD 三个演化算子的上下文与指令：设计记录

用户确认将算子的适用场景、上下文与指令纳入机制文档，完整设计已统一到 [TraceAAD Base 轨迹与算子设计](../TraceAAD-Base.md#5-轨迹上下文与演化算子)。

当前方案共用最近 8 个祖先、当前父代、最多 3 个有效子代及 2 个失败子代；三类历史分别受 token 上限约束。仅父代提供完整代码，其他个体提供设计说明与评价，交叉参考也只提供设计与成绩。祖先按形成顺序展示，有效子代优先保留最好结果再补近期尝试。下文保留此前设计与修订过程。

适用场景与调用结果为后续预算分配提供依据。具体概率与分配规则仍需确定，提示效果尚未进行模型对照。

自审时，我核对了父代尚无历史、已有更优变体、近期只有退步或失败、以及双源组合四种情形。上一版只要求改善父代，直接复制已展示的更优变体也能满足该目标；共同历史指令现要求在已有结果上形成进一步的计算改动。有效变体由单纯取最近三条改为优先保留最好结果，再补充近期尝试，减少有用结果被近几次退步挤出的情况。Refine 改为正面发展原机制，避免强求从汇总成绩中诊断出确定的弱点；Explore 引导模型从原问题的求解方法考虑目标函数；Crossover 将双方计算的贡献落实到函数输出，`design` 也明确说明计算如何决定输出。

这些修订改善的是目标与信息的一致性。历史已显示，修改保留措辞可以减少部分设置下的复制，却未必改善成绩；因此，文字审查不能替代固定输入下对不同有效实现、重复与求解质量的比较。本轮未增加模型调用。[已有生成端对照](../../experiments_result/analysis/v18_mechanism_20261029/README.md)

设计依据见[相关工作核对](2026-10-30-AAD算子参考核对.md)与[历史代码核对](2026-10-30-TraceAAD算子历史核对.md)。

进一步修改时，我将 Refine 的边界直接写入指令：保留核心决策机制，在其中改进计算、辅助步骤或参数。Explore 明确改变主要决策规则或产生决策信息的机制，并将所选方法适配到函数输入输出。Crossover 要求双方计算共同参与输出，同时协调输入输出与必要的数值尺度，避免将公式并列视为已经完成整合。历史指令分别利用有效变体的代码与成绩、失败实现与反馈；后者只指导与新设计有关的实现问题。有效变体要求进一步计算改动，历史不覆盖本次算子的目标。成绩仍只支持完整实现的比较，不据此断言单项改动的因果作用。这轮继续只修改设计文本。

用户确认恢复祖先链，并以语言记录提供历史指导后，我将 8/3/2 的数量上限、各类历史的选择顺序与 token 约束写入 Base。历史源码不再进入演化提示，交叉指令同步改为将参考设计中的计算落实到父代代码；失败历史缩至两条并只呈现设计与关键反馈，初始化沿用此失败窗口。修复仍使用失败个体完整代码。本轮不把这一上下文方案宣称为已有实验验证的最优设置。
