## 结论

我核对了分配、计数与时钟、质量代表、区域划分、反思材料、上下文读取及恢复链路。当前核心实现与极简规格一致，未发现需要退回机制修复的实证偏差。验证支持实现语义和结构不变量；没有在本轮调用真实模型或启动搜索，不据此判断反思质量与搜索收益。

## 逐项核对

| 规格 | 最新实现与检查结果 |
| --- | --- |
| 全体保留可行节点参与同一权重计算；路线取最大值，内部归一化 | `allocation.py`实现全局中位数与稳健尺度、对数权重、路线最大权重与内部权重分配；没有Open/Closed或超越排除。独立公式复算一致。 |
| 本路线开发计数与诚实时钟 | `models.py`只由Refine/Crossover主父代增加`children_count`并刷新`last_used`；Explore与参考不刷新原节点。一次失败加修复仍只增加一次开发次数，实际评价数单独累计。 |
| 同路线活跃继承与严格超越 | `topology.py`只继承同路线父代时刻；超越要求相同路线且适应度严格更好。代表选择之后再并入近期节点并补必要分叉。 |
| 初稿接棒与路线身份 | 跨路线收缩边保留Explore标记，后代保留原`direction_id`；虚拟根入边保持根连接约定。 |
| 中间基点的同轮旁支进入同一边 | `PathContraction.side_ids`携带旁支；规划在原拓扑上将其唯一分配给中间节点所属的收缩边，未重复进入祖先S。 |
| 反思材料保留转向与实际比较 | 路径和旁支提示都包含Explore初稿说明；收缩后的Explore仍显示转向标签；路径提示读取侧枝实际父代及差分、错误和旧经验。旁支的独立最优对照不替代真实父代。 |
| 多尺度读取与恢复 | Refine/Crossover读取沿途S和V，Explore读取方向经验；既有测试检查经验交接及展示开关。提交日志恢复测试通过；新`route_max_weighted`选择标识使旧平坦采样配置不能直接恢复到新语义。 |

## 文档纠正与数值边界

我同步了正式设计、研究主线、极简规格、包README及中英文论文中的以下旧表述：平坦节点分配、Explore计入本路线开发、只读参考刷新时钟、跨路线超越，以及收缩基点的同轮旁支进入祖先S。正式设计不再把更优后代出现解释成开发价值已经结案。

三张旧图有明确冲突：`01-main-framework.png`和`04-reflective-simplification.png`将B下的X送入A的S；`03-v2-selection.png`的近期条件只显示节点自身时钟。我移除了这些图在当前V2设计与论文中的嵌入及旧图注，正文保留准确规则。原图文件与历史V1引用保留。论文文献与既有实验记录未重写。当前六份机制文档及新增审校记录的本地链接检查通过；周记录的历史段落有一个既存启动证据链接缺失，已在[链接检查结果](../../experiments_result/analysis/evotrace_v2_doc_audit_20261113_225955/doc_link_check.json)中单列，未用另一批次材料替换。

数值检查还纠正了上一轮由我写入规格的过强承诺。五个独立路线的分数为`[1, 1, 1.001, 1.002, 100]`时，最后一个节点在最终浮点输出中概率为零。实现已使用对数权重，仍不能表示任意小的最终概率。这不等于按路线或超越状态硬排除节点；文档应承诺候选资格和理论权重，而不保证每个机器概率严格为正。本轮没有新增概率下限、配额或超参数。
