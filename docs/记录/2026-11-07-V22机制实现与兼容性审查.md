# V22机制实现与兼容性审查

日期：2026年11月7日（北京时间）。状态：主审与Opus 5.5独立复查完成，主审已复核独立重算与模型边界复现。仅审查与本地验证，未修改实现或启动真实模型实验。

## 范围与依据

审查对象为当前工作区的`traceaad_v22/`、继承的V21上下文与提示、Base的执行与恢复流程，以及共享实验入口。HEAD为`ccff42e23d19429165ad185f45bcf91dbecca041`；V22仍是未提交新增文件，因此HEAD本身不代表本次实现。审查起点13份核心代码与机制规格的SHA-256保存在[证据目录](../../experiments_result/analysis/v22_mechanism_review_20261107/source_hashes.json)，合并结论前已核对全部一致。

依据是[机制1](../机制设计/机制1-轨迹节点价值评估与预算分配.md)、[机制2](../机制设计/机制2-轨迹引导的上下文与算子.md)、[V21](../机制设计/V21.md)、[V22](../机制设计/V22.md)及用户已确认的取舍：保留等成本近似、固定第二步短名单、16点积分与九维模型；虚拟分支重选融合参考。上述近似不作为实现错误重复提出。

## 合并结论

未发现已证明的正常流程实现错误。机制1的主体计算和执行链与规格一致；机制2的材料组织、指令和输出协议直接复用V21。两者接口兼容，融合参考由机制1明确接管，已经替换V21的中位数参考池、computation分组筛选和均匀抽取。这是政策变化，不是漏接机制2。固定候选的盲区属于已接受近似；恢复配置不一致属于防误用缺口，同配置恢复正常。

最值得继续关注的是Opus新增、主审已经复现的模型现象：一次大幅负收益可能抬高该操作的预测上尾，进而提高I和Q并影响真实动作选择。它来自当前统计模型本身，不是代码偏离公式；是否使真实搜索持续偏向缺乏正向收益的操作，尚待验证。

### 1. 融合参考的family条件替换了机制2的不同计算条件

机制1要求取其他family中fitness最小的节点；`traceaad_v22/selection.py:183`的`actions_for`按此实现。机制2则要求排除与当前算法只差常数、没有不同计算的参考；V21在`traceaad_v21/context.py:63`通过`computation`分组执行这个条件。

复现：两个Init分别为`return x + 1`与`return x + 2`，成绩分别为100和110。两者是不同AST、不同family，但`computation`相同。冷启动选择器在`random.Random(0)`、剩余4次评价时选中`(parent=1, Crossover, reference=2)`，实际提示含该参考；V21的参考选择对此返回None。

因此，代码遵守机制1，也确实把同一动作交给机制2的上下文；但它不再保留机制2原来的“参考提供不同计算”筛选条件。V22版本文档已经说明参考选择被替换，这不是遗漏调用V21参考选择。需要统一的是组合后的规格和对Crossover的解释，不能把family当作计算差异的证据。

独立复查将此项降为已确认的政策边界。另一个直接推论是：取“其他family中最好”时，任一真实状态的参考只能来自全局最优family及排除它后的次优family，最多两个不同参考节点。这符合机制1，但材料来源比V21的均匀抽取更集中。

若保留不同计算作为硬条件，还需处理虚拟子代没有代码、无法直接计算`computation`的问题；不能只给真实选择加筛选，却仍声称虚拟分支执行相同合法性规则。若以family为首版代理，应明确这一筛选已由机制1接管。这里不擅自更改已确认规则。

### 2. 首次出现其他family时，旧父代新开放的C不进入第二步短名单

`traceaad_v22/selection.py:206`只重建短名单中已有的父代与操作，再加虚拟子代动作。真实池原来只有一个family时，没有已有C动作；Explore产生新family后，旧父代的C首次变得合法，但不会被补进短名单。

复现：真实池只有父代1，虚拟Explore子代2出现。第二步包括`1/R、1/E、2/R、2/E、2/C(ref=1)`，而真实下一轮还会有`1/C(ref=2)`。已有C的参考更新正确，问题只在原来不存在、现在新开放的旧父代C。

这符合当前“保留基础候选父代与操作”的字面规则，因此先归为固定候选近似的具体边界，不认定为代码偏离规格。它说明首版无法覆盖新版本作为融合材料的全部后续机会。是否补入这类动作，应与最多28个候选的约束一起决定。

### 3. 改变初始化数量恢复时，固定参照值可能静默改变

`traceaad_v22/search.py:43`按本次Config的`initial_size`决定何时冻结尺度；恢复没有核对原始配置，也不从已记录的`f0/s0`恢复这两个固定值。共享入口`experiments/traceaad_v20/run.py:159`先由当前命令行建立Config，后续读回旧metadata时未替换实际Config。

复现：以`initial_size=3`产生初始成绩99、98、97，再完成一次演化后保存；改用`initial_size=2`恢复，程序没有拒绝，`f0`从97变成98。历史演化仍使用原记录特征，之后预测则使用新参照，特征口径会混用。

同配置恢复已验证一致；原操作说明要求用原参数恢复，所以这项限定为防误用缺口。最小修正是恢复前核对关键配置并明确拒绝不一致参数，或以保存配置重建真实运行状态。不能只保留旧metadata、实际按新配置运行。

### 4. 大幅负收益可能抬高同一操作的预测上尾

这是独立复查新增的模型问题。`selection.py:101`按残差平方更新B，`selection.py:82`用B/A构造预测scale，`selection.py:113`据此计算上行期望改善。因此，大的负残差既会拉低均值，也会扩大预测波动；后者可能使预测的上行收益反而增加。虽然预测分布是Student-t，当前递推仍然包含平方残差，不能把它理解成已经采用了抗异常值的Student-t观测噪声。

主审独立条件复现：每次重置初始池为100、110、120，固定s₀=10，只改变父代1的一次可用Explore结果。继续在旧节点3上计算Explore的I，并在完整两步选择中比较全部动作。

| 该次归一化收益y | 旧节点3的Explore I | 旧节点1的Refine I | 完整两步选择 |
| --- | ---: | ---: | --- |
| 0 | 0.04569 | 0.32476 | 新节点4的Explore |
| −10 | 0.18652 | 0.32476 | 父代1的Crossover |
| −100 | 3.17298 | 0.32476 | 旧节点2的Explore |
| −1000 | 33.93754 | 0.32476 | 旧节点3的Explore |

这证明大幅退步可以提高预测价值，且影响两步动作选择。它没有证明这种反馈必然错误：模型将大残差解释为更大的结果波动，风险在于真实收益分布可能并不具有相应的正尾。当前现象也不能泛化为“任何失败都会被奖励”；无结果、无效和重复源码不进入连续收益回归，以上结果针对有效且不重复、成绩大幅退步的子代。

Opus还基于V21日志的成绩差进行了选择器重采样模拟，观察到部分运行集中到Explore或Crossover。该模拟把结果差值独立于当前父代重采样，不能代表真实LLM响应，也可能产生不符合任务含义的虚拟成绩。因此，模拟只提示应检查这条反馈方向，不能据此宣称真实V22已经失控。对负收益做压缩的临时干预同时改变均值与方差，也不能单独证明方差是唯一原因，更不能直接作为修正方案。

当前不改收益模型。下一项最能改变判断的证据是：在真实V22前期轨迹中，大幅负收益引起的B跳变，是否随后带来缺乏实际正收益支撑的算子集中。需要同时看s₀、预测上尾、实际收益和父代相对冠军的差距；只看算子份额不能区分合理集中与模型误判。
