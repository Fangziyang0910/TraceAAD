# 树状种群管理：规则与 CVRP 例子核对

2026-11-11（北京时间）。问题是当前“先选保留节点，再划分路径收缩与旁支剪除”的机制是否合理。

我认为这个组织顺序合理。保留算法、补齐分叉及方向边界后，移除区域由树的位置确定，便于统一整理经历。32 应作为容量预算，而非预先存在的恰好32个“必须节点”。当前最需要调整的选择规则，是仅因同方向后代成绩更好就排除祖先；成绩提高没有证明计算方式已被替代。建议仅对质量更差且计算方式接近的祖先做这种预过滤，其余进入共同选择。该建议尚未修改实现。

## 首轮输出与用户示意的区别

首轮总计保留29个节点。用户示意列出的13个节点中，实际保留的是：

`3, 9, 13, 18, 24, 36, 38`

其中局部前沿为 `24, 36, 38`；`3, 9, 13, 18, 36, 38` 在完整64节点树中为 LCA 锚点，角色允许重合。没有该局部的额外里程碑。对应路径收缩为：

- `9 → 12 → 13` 收缩为 `9 → 13`。
- `3 → 15 → 18` 收缩为 `3 → 18`。
- `13 → 20 → 36` 收缩为 `13 → 36`。

`7,8` 归入3的旁支区域，22归入9的旁支区域。示意省略了其他节点，不能据此推出完整树中的分叉角色；这份五节点示意不是当前首轮的逐项输出。第二轮需按其具体回放与重连规则另行定位。

原始记录还显示：8的主父代是7；7、8、22、24的fitness依次约为10.2204、13.8574、13.6735、9.3380，与示意中的数值不同。20是以13为主父代、16为参考的Crossover；其代码用K近邻倍增替换了此前的高斯邻近权重，不是只调整系数。实测 `code_distance(13,20)` 为约0.2997。

## 会影响机制判断的细节

**AST 距离是结构代理。** 当前指纹忽略变量引用身份与常数值。直接调用当前距离函数，`x/y` 与 `y/x` 得到0，`1/d**2` 与 `1/d**3` 也得到0。因此距离0不能解释为算法相同，固定的0.3也不能充当计算方式变化的通用分界。

**里程碑规则没有检测代码继承。** 当前实现检查中间节点相对起点的质量，并计算它到两端距离的最小值。它没有检查某个计算组件是否完整保留到终点，也不是到替代线段的几何误差。把删除12解释为“其平方反比已被13继承”，需要实际代码核对，不能当成该选择器的判断过程。

**探索保护计数需要跨压缩保持含义。** 当前 `subtree_visits` 是现存子树节点数，包含方向起点及嵌套方向；它不是累计评价次数。压缩后重新计数会失去已移除尝试。若规则要保证若干次实际探索机会，应从评价记录累计，明确起点是否计入；按深度衰减的贡献也应区分原始修改步数与压缩后跳数。

**经验要记录修改与结果。** 纯拓扑过程只产出保留集合与待凝练区域。对于路径3→13，下一步需要整理各阶段修改、对应结果及最终保留内容；一个最终分数差不能替代这些材料。旁支挂入保留祖先后，还应保留其真实发起版本。交叉参考属于形成过程，也需要参与区域经验整理。
