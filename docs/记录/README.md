## 2. 已核实的机制边界与证伪记录（防重复试错）

以下条目仅记录经数学构造或真实运行快照重算确认的客观现象：

1. **局部宽深裁剪不等于全局有界：** 仅限制单父代保留子数与无分叉链长时，完全分叉树仍随深度指数增长；在简化规则中混入父子适应度淘汰会与全局抽样职责重叠，并在移除叶节点后连锁暴露冷父代、破坏单轮简化幂等性。
2. **代码相似度硬过滤的固有折中：** AST 结构二元组特征忽略数值常数变化（常数调优的距离为 `0.0`），硬阈值去重会拦截有效参数改进；不设相似度过滤时，离散或平台型任务（如 FSSP）上同分改写会在活跃窗口内并存并挤占个体排名。
3. **跨路径同分合并与峰值分级排名的副作用：**
   - 直接将“同标量分数”当作同一个体去重，会在 FSSP 等离散目标任务上合并删除结构显著不同的实现（真实轨迹同分组内最大 AST 距离中位数约 `0.40–0.43`）。
   - 仅按路径峰值分数集合计名次并跨路径合并精确同分投入，在真实树扰动下对 `1e-16` 浮点末位差异存在超过 `50%` 的总变差跳变；峰值层数较少时会将后半段差节点采样份额从约 `6%` 抬升至 `26%–32%`。
4. **分层或分组分配对深挖锐度的影响：** 在真实树快照上，先按 `lineage_peak` 分组再组内分配或从根沿树逐层递归选择，均大幅压低连续改进任务（如 TSP）前排个体的抽样份额。
5. **Explore 全局概览不能仅展示路径峰值：** 节点经验可挂在非峰值分叉节点上，边经验可进入非峰值保留节点，且绝大多数保留的 `Explore` 尝试并非路径峰值；仅展示峰值在真实快照上会遗漏近半数经验载体（如 FSSP seed1 中 `13/25`）及 `98%` 已尝试的非峰值探索草稿。
6. **路径收缩与峰值计费的耦合边界：** 路径收缩保持存活节点的 `subtree_evaluations` 原值不变；但当非全局最优的路径峰值因超出活跃窗口且非分叉点而被收缩移除后，其未改进后代会在当前保留树上重新计算路径最优祖先。
7. **首个 V4 批次的 TSP 候选频繁复现最近邻。** 该批只输出 `code → design`，Refine 还要求保持核心计算。TSP 三路在约 100 评内都停在模板最近邻的 6.823969（同分程序中有 768/768 步决策与最近邻相同），前 120 评有 353/360 个程序是加权局部打分。V1–V3 的输出顺序为 `analysis → code → design`，同一时段约一半程序是模拟补全、外圈优先、2-opt 等结构性方法，并在 5–30 评内越过最近邻。V1/V2 的 Explore 同样读取父代源码，也能从最近邻父代生成 NN rollout。第二批 V4 恢复了写代码前的分析，并放宽精化与探索指令。种子 1 和 2 在停跑前均优于最近邻。两项改动各自的作用仍待单独检验。
8. **V3/V4 的 TSP 前期变慢，来自生成侧失去换思路的来源，不来自预算分配。** V1–V3 前 90 评中，TSP 低于 6.5 的程序都是全路线模拟一类的结构性方法，局部加权打分最好只到 6.52。V1/V2 的 Explore 指令含 “estimate downstream consequences, construct and improve a tentative solution, or solve useful subproblems”，按设计简述归类，模拟类占 58–73%；V1 前 40 次尝试的 30 次 Explore 回复中 29 次提到模拟或补全。V3 删去该句，靠只读设计概览的根部探索保持约 20%，前 100 评 20 次非初始化新最优中 10 次来自根部探索。aad 批 V4 的探索读取父代源码与逐次尝试，模拟类约 7%，且没有真正的贪心补全；另有约 43% 是“局部打分 + 末段穷举”。同期 V4 选中的父代离最优更近（差距中位数 3.8%，V3 为 10.7%），子代优于父代的比例与 V3 相同（精化均为 35%）。CVRP、OP 第 80 评在 V1–V3 范围内。V1/V2 约九成调用走 AWQ 端点，V3/V4 走 FP8 端点。layered 批据此让探索只读概念层并恢复该句，后因该句可能是任务相关先验、上下文组织也未从各算子所需的信息推出而停止。`20261118_195758_evotrace_v4_cards_co4` 改为让探索读取种群中不同算法的完整卡片（设计、经验与源码），指令只要求主要计算与它们都不同。cards 批前 60–92 评中，TSP 只有种子 1 在第 28 评由探索找到模拟补全余程的算法（后续精化与交叉做到 5.985），另两个种子停在 6.51 与 6.97；`20261118_204342_evotrace_v4_methods_co4` 因此在探索指令中加回计算方式示例。
9. **旧反思提示的结果行只相对直接父节点，模型会把不如起点的尝试写成改进。** 按 aad 与 cards 两批重建 208 次反思提示，并与写出的经验逐一对照：107 次子树区反思中有 91 次没有任何尝试优于起点算法，经验写明这一点的只有 7 次；有 52 个尝试优于自己的已剪父节点、却仍不如起点算法，其中 46 个在经验中被写成改进。101 次路径区反思没有统一的比较基准：42 次起点是虚拟根；其余 59 次中有 18 次终点不如起点；32 次有路径步骤或侧枝优于终点，若统一与终点比较，会把造就终点的步骤都标成更差。`20261118_215520_evotrace_v4_reflect_co4` 因此让子树区的结果行另与起点比较，路径区只给每一步相对自身起点的变化。
10. **被淘汰尝试凝练出的经验，直接促成了新的最优算法。** revised 批中有四个经原始记录核实的案例（CVRP rep3 #569、TSP rep2 #308、OP rep2 #208、CVRP rep3 #424）。经验的来源节点在子代生成时都已移除，经验原文都出现在子代提示中；子代的分析引用了这段经验，按它改动设计，并刷新了这一路的最优（8.145 → 8.010、5.747 → 5.722、−14.429 → −14.584、8.207 → 8.153）。四个案例覆盖边经验与节点经验，以及精化、交叉、探索三个算子。CVRP 三个种子中各有一次探索推翻了由一两次失败推广出的局部经验（rep3 #338、rep2 #372、rep1 #357），rep3 的经验随后被反思改写。150 评之后探索刷新最优的比例降到 0.2%–1.3%，12 路仅 7 次。[机制作用的证据](2026-11-19-机制作用的证据.md#四个经验使用案例)，复算脚本见 `experiments_result/analysis/20261119_reflection_cases/reproduce.py`。
11. **三个算子分工明确：探索开新路，精化走深并修正退步，交叉汇合分支。** 探索子代与此前所有程序的结构距离中位数为 0.26（精化 0.11、交叉 0.10）。最优谱系上 30% 的步骤不如父代，其中 46 次下一步即超过退步前成绩。交叉参考 84% 来自其他分支，交叉在最优谱系上的占比是先验的 1.5 倍。243 次刷新最优中，沿主父代被最终最优继承的有 37%，加上交叉参考为 84%。CVRP rep3 的最终最优 #641 集合了两次探索、一次精化和三次交叉的贡献。[机制作用的证据](2026-11-19-机制作用的证据.md#二三个算子的分工)，统计脚本见 `experiments_result/analysis/20261119_reflection_cases/operators.py`。
12. **反思式淘汰让树保持小而多样且信息不丢，预算分配的两个因子对应真实产出差异。** 12 路各 457–865 次尝试，存活节点峰值 80–99，共删除 7114 个节点；1598 次反思中 30% 修订了已有经验；150 评后 96% 以上的提示带经验，提示 token 中位数从 3,211 增到 5,749，最大 19,588。150 评后父代刷新最优的比例随名次单调下降（6.2% → 0.45%），随 $n_p$ 下降（名次前三的父代中 7.0% → 0%）；$1/(1+n_p)$ 把未扩展节点的份额从 14.5% 提到 38.6%，这些节点产出 49% 的刷新最优。[机制作用的证据](2026-11-19-机制作用的证据.md#一反思式淘汰树小而多样被删的尝试变成经验)，重放脚本见 `experiments_result/analysis/20261119_reflection_cases/tree_budget.py`。
13. **提示中的源码经 `ast.unparse` 重排后，较弱的生成模型照抄时会漏写右括号。** `ast.unparse` 把 `min(x for x in y)` 写成 `min((x for x in y))`（Python 3.14 仍如此）。Eco 批 583 次回复中有 35 次语法错误，其中 19 次正是提示里的某一行少了一个右括号；TSP 的精确 DP 收尾行 `return float(min((… for i in range(m))))` 被照抄 54 次，11 次漏写，而模型自己写的单括号形式 42 次无一出错。TSP 前 156 评中有 24 评（15%）因语法错误失败。同期 Qwen 批 3202 次回复只有 16 次语法错误，没有一次属于这一类。`20261119_154209_evotrace_v4_rawcode_co4` 与 `20261119_154209_evotrace_v4_eco_rawcode_co4` 因此改为只去掉文档字符串与注释、保留原写法；在 11,995 个已有程序上，展示源码的 AST 与去掉文档字符串的原程序完全一致，字符数多约 3%。同一类问题还有修复反馈：修复提示原先展示重排后的源码，而报错行号指向原程序；固定评测器以 `exec` 运行源码，报错帧只有 `File "<string>", line 55`，没有那一行；异常信息里的数字也被统一换成 `N`（如 `shape (N,)`、`on line N`）。这两批同时改为展示执行原文、保留数字，并从原文补出出错行；在上述两批 75 次非超时失败上重放，12 次 `<string>` 帧全部补出正确的行，反馈最长 338 字符。
