# EvoTrace V3：反思只记事实，上下文只讲设计

日期：2026-11-17（北京时间）

状态：事实反思初版已随 `190fe372` 合入主线；第7节定型清理在工作区未提交。定型版冻结批次 `20261117_181830_evotrace_v3_clean_co4` 已在 server4 启动（替代停于 253–321 评的 `20261117_153134_evotrace_v3_factual_co4`）。论文第2节与附录E尚未按本版改写。

**目标：机制只做两件事。** 反思回答“这些尝试留下了什么可以传承的经验”；生成上下文回答“根据现有材料，怎样设计出新算法”。两类提示都不混入工程表述、规则或与任务不符的引导。

## 1. 问题

精简版批次 `evotrace_v3_lean` 的反思与上下文仍有三类问题：

- **反思写成了规则。** 旧模板要求“为后来的设计者写笔记”“说明代码为什么导致结果”“保留仍然重要的旧笔记”。模型据此写出因果故事和禁令，并逐轮复制。36 个真实区域中，64% 的旧经验含规定性用语（avoid、should、most robust、key insight 等）。
- **Explore 挂在被抽到的父代下。** Explore 的程序换了主要计算，却记成父代的一次修改。父代的投入计数 $n_r$ 因此被 Explore 计费，反思也把它读成“从父代修改而来”。
- **根经验进入所有算子。** 每路约 55 次根反思把“从零设计的失败尝试”压成一段话，再送进 Refine 和 Crossover，形成一致的失败偏见。

## 2. 改动

| 项目 | 精简版 | 本版 |
| --- | --- | --- |
| 反思任务 | 为设计者写笔记，解释原因，保留旧笔记 | 记录事实：每个有信息量的尝试实际计算了什么（若是修改，相对起始计算改了什么），测得的适应度或失败；不写规则、建议或推测的原因 |
| 反思中的编号 | 允许写算法编号 | 只写计算，不写编号（这些算法以后不再出现） |
| 根区域 | 附“目前最好的保留算法适应度”一句 | 删去该句；从零设计的算法按适应度从好到差排列 |
| Explore 挂接 | 挂在被抽到的父代下 | 挂在根下，开始一条新谱系；抽到的代表只决定提示展示哪些已有做法 |
| 根经验 | 所有算子可见 | 只给 Explore（同样是从零设计） |
| 上下文用语 | Algorithm 编号、操作名、工程标签 | 设计语言：“First version / Step k”“modified / combined with another algorithm / designed from scratch” |
| `design` 字段 | 无长度要求 | 约 60 词，描述代码的主要计算和关键参数，不写预期效果 |

不变：代表集、区域、分配公式、算子比例、采样参数、输出字段。

## 3. 评审意见

- **Astra**：同意 Explore 挂根与上下文清理。指出“说明代码为什么导致结果”会诱发因果故事，“保留旧笔记”会延续错误；建议把观察与解释分开。
- **Carbon**：根经验只给 Explore；删去最佳适应度比较句；反思只记事实；“decision”改为“computation/result”；`design` 限约 60 词。Carbon 认为定义句导致伪向量化设计，核对后不成立（精简版提示中没有该句），定义句保留。

## 4. 对照

### 4.1 反思模板（36 个真实区域：12 个根区域 + 24 个随机区域；温度 0.3）

| 模板 | 规定性用语 | 含算法编号 |
| --- | --- | --- |
| 精简版（记录值） | 64% | 6% |
| 为设计者写笔记（v1） | 92% | 44% |
| 精简版任务句去掉存储句（v0） | 72% | 3% |
| 每条发现一行（v2） | 72% | 0% |
| Astra：观察与解释分开（v3） | 89% | 3% |
| 解释写成可能（v4） | 64% | 0% |
| v4 加“不把单次结果写成规则” | 58% | 0% |
| Carbon：只记事实（v6） | 25% | 3% |

| **本版（v8）** | **22%** | **0%** |

结论：“写给设计者”的框架会增加建议；禁令句只降低约 8 个百分点；只记事实的任务句效果最大。输出句必须明确“写计算，不写编号”，否则编号回到 64%。v8 的输出记录具体计算和数值，例如“Evaluating top-15 candidates via two-step lookahead yielded 8.149 … refining by shrinking the candidate window from 20 to 10 … improved fitness to 7.363”。

- **TSP 上旧根经验压制完整路线类设计**：旧根经验写着“多步前瞻、MST 估计常常增加路线长度”。去掉根经验（D）后完整路线类设计从 3/8 升到 6/8，最好值 6.458，但 3/8 无效。
- **OP 上 C 显著差于 B（p=0.04）**，追查出一个读数错误，见 4.3。

### 4.3 负分数任务的方向读反

OP 的分数是负的平均奖赏，越低越好。根区域里从零设计的算法只有绝对适应度，没有父代可比。删去“最佳适应度”一句后，新模板把 −13.21 读成“退化”，把 −8.82 读成“最好”。C 臂的根经验因此把有效的增量代价衰减写成失败，Explore 随之退回简单的奖赏/距离比。

修复：根区域按适应度从好到差排列记录，情境句写明“listed from best to worst fitness”。复测 OP 两个根区域各 4 次：rep1 区域 4/4 读对（修复前读反）；rep3 区域仍有约一半读反，在情境句再加 “(lower is better)” 没有改善，因此不加。rep3 的错误同时涉及把组合子代误当起点，属于模型对负分数的先验，残留风险在正式批次中观察。

## 7. 第 200 次评价复盘、去工程化清理与定型批次重开

  1. **OP 根经验仍读反负分数**：三路 `root_experience` 把淘汰的模拟类设计（`-6.05 / -6.22 / -7.32`）读为最优，导致 OP 上 `Explore` 89.5%（136/152）生成模拟算法、中位适应度跌至 `-8.55`、0 次破纪录（总分上升全靠 `Refine` 与 `Crossover` 被根经验隔离保护）。原因是根下淘汰记录缺少存活基准锚点。

  3. **`Explore` 假父代与 `Crossover` 补丁状态**：先抽 `parent_id` 再掷算子使 `Explore` 携带假父代（`Attempt/Program.parent_id` 与 `Edge.parent_id=0` 不一致）；`Crossover` 使用独立 `0.30` 线性排名硬阈值、确定性最远选择与 `TreePopulation.used_crossover_pairs` 历史黑名单。
