# V24 与 V24.1 对比审查（Opus 5.5）

审查时间为北京时间2026年11月9日13:00–13:40。对象是共享工作区：HEAD `07aaa99c` 加上一轮未提交修改，`traceaad_v24_1/` 与 `tests/v24_1/` 未跟踪。本次只读代码、运行离线测试与离线探针，没有调用模型，没有启动搜索，没有操作远端。

## 结论

**推荐 V24.1 的设计作为机制三的后续主线，但当前实现不能直接开正式批次。旧 V24 跑完正式批次作参照，不再在它上面迭代。两版都还没有“搜索更好”的证据。**

1. **V24.1 的方向更值得继续。** V24 的反思看不到父代代码；大幅改写只剩一句“多数代码被替换”；失败没有代码；笔记没有条件和来源，每轮整版重写。这些缺口由代码确认。经验要写清“在什么计算条件下成立”，反思先要看到计算本身。V24.1 补的正是这一层：实际实现、同起点对照、计算条件、稳定编号、代表来源和局部修订。
2. **当前 V24.1 的材料装入会让机制失效（发现1）。** 真实入口没有 token 计数，按 UTF-8 字节装材料。32256字节只相当于7–8K token，而一个完整片段中位15–20KB。离线重放六任务的真实档案：不写经验时，每轮只读3–4个新事件，搜索结束时未读积压510–620个，后期反思读的是约440–550次尝试之前的事件。经验达到5–6条、每条1个来源后，五个任务在第55–165次尝试之后不再发出反思请求，经验冻结到搜索结束。照此开批次，检验的是“早期冻结的经验”，不是设计中的可修订经验。
3. **V24.1 在没有经验时已改了 Refine 与 Crossover 指令（发现2）。** 它与 V21、V24 的差异不再只来自经验。在发现1之下，差异可能主要来自指令。
4. **V24 正式批次的早期笔记在五个任务上写成以现任程序为中心的跨结构排序（发现3）。** 在图着色、JSSP、OP 上，被否定的方向正是 V21 正式批次最终最好程序使用的计算。这支持换掉 V24 的笔记形式；它是否拉低最终成绩，由批次结果回答。
5. **推荐依赖的修正与证据。** 删去字节上限、延后与未读积压，每轮读本周期新事件的一跳材料，加每条经验1个代表来源；反思使用单独的小输出预留；越窗请求如实失败并记录；只在展示经验时替换算子指令。随后用本报告的离线探针确认每轮都能读到新事件，再做“最先做的检验”中的反思回放，然后开 V24.1 对 V21 的正式批次。

## 两版比较

| 项目 | V24 | V24.1 |
| --- | --- | --- |
| 反思材料 | 最近10次尝试的 V21 卡片：父子差分；改写只有摘要；失败只有报错摘要；没有父代代码 | 新事件的父代完整代码、完整差分或子代源码、失败代码与报错；父代形成一步；同起点最好与最近不同尝试；活跃经验的代表来源 |
| 经验形式 | `idea`/`lesson`，每轮整版替换 | `id`/`idea`/`when`/`lesson`/`evidence_ids`，局部更新与归档，累计来源 |

| 生成端 | Refine/Crossover 读笔记；指令同 V21 | Refine/Crossover 读三字段经验；指令改写（无经验时也改） |
| 实际运行 | 正式批次215次反思全部成功；提示中位5.1K token，p90 6.6K，最大10.5K；反思提示 token 为生成提示的17.6% | 没有真实模型运行 |

**V24 的实质优点**是简单、稳定、便宜：约190行，反思从不失败，成本可控。**它的问题在机制层面**：反思只能按结果写结论，因为它看不到计算；冒烟和正式批次都写成以现任程序为中心的排序（发现3）。笔记对最终成绩的影响未知，由 `20261109_v24_co6` 对 V21 回答。

**V24.1 的实质优点**在设计上：反思能区分“计算没有进入决策”“执行失败”“有效执行后变差”，这三种情况必须看代码才分得开；`when` 给条件一个固定位置；局部更新让未受新证据影响的经验保持原样，并留下修订记录。选择、评价预算、生成与修复和 V21 一致（`tests/v24_1/test_search.py:182`）。**可确认的问题**是发现1与发现2。**尚未验证的机制收益**有三项：完整代码与条件位置能否让反思不再做跨结构排序；来源回读能否触发修订，而局部更新不把早期条目固化；生成器能否按条件判断经验是否适用。

V24.1 仍有一处会产生跨结构结论的结构。Explore 事件的片段中，父子比较本身就是“新主计算对现任程序”，V24.1 照旧标注 `regressed`；它的同起点最好通常是现任结构的 Refine 子代。V24 冒烟中“一步前瞻不如贪心”正来自这样一次 Explore（7.38→8.21）。V24.1 现在给出两份完整代码，`when` 也提供了写条件的位置；结论能否写成“这份前瞻实现在什么条件下受限”，而不是“前瞻不如贪心”，取决于模型。这是 V24.1 核心假设中未检验的一环，也决定下面检验的窗口。

## 发现

### 发现1（严重，V24.1 实现）：字节上限、先旧后新和来源必装，使反思积压并永久停摆

**位置。** `traceaad_v24_1/search.py:33` 把输入上限设为 49152 − `Config.max_tokens`(16384) − 512；`search.py:36–37` 在模型没有 `count_prompt_tokens` 时按 UTF-8 字节计量。`traceaad_v24_1/evidence.py:157–183` 先装全部活跃经验的代表来源（159–171，超限即 `experience_sources_exceed_input_limit`），再从最早未读事件起装整片段（172–178），一个都装不下即延后（182）。`traceaad_v24_1/notes.py:10–12` 规定每条最多4个代表来源。`search.py:118–120` 延后时不发请求。真实入口 `experiments/traceaad_v20/run.py:197` 不传 `reflection_context_tokens`，`experiments/traceaad_v20/scheduling.py:97–117` 的 `ScheduledModel` 没有 `count_prompt_tokens`，所以正式批次一定走字节计量。

**触发。** 真实程序长度。按 V21 正式批次每任务前600次生成调用校准，提示每 token 3.95–4.60字节（1%分位3.49–4.16）。32256字节约等于7.0–8.2K token，只用到32256 token 输入预算的约四分之一。材料方面：固定部分3.8–4.8KB；一个新事件单独装入时提示9.0–11.7KB；一个完整片段（本事件、父代形成一步、同起点最好与最近不同尝试）的提示中位15.3–20.4KB，p90 19.3–27.2KB。图着色有8个、JSSP 有5个片段单独就超过上限。

**后果。** 离线重放运行 V24.1 真实的 `finish`/`_reflect`/`build`，只把反思回复换成固定策略。不写经验时：

TSP 在 cite1 下仍发请求，但每轮中位只读1个事件，后期滞后681次尝试。

**机理。** 每轮装得下的事件少于新到的10个；先旧后新又从不丢弃，未读事件成了只进不出的队列，反思越读越旧。来源每轮必装：去掉固定部分后证据空间约2.7–2.8万字节，每个来源事件带父代完整代码，约4.6–7.8KB。经验达到5–6条、每条1个来源后，再也装不下任何新片段。经验也无法再被修订或归档，所以没有出口。V24.1 文档把延后写成“保留材料”，在真实吞吐下它等于停摆。

**对机制的含义。** 经验冻结在搜索前55–165次尝试形成的版本。这正是 V24 冒烟和正式批次中笔记写成跨结构排序的阶段。V24 的笔记至少每轮重写，回放显示突破后会转向；冻结的 V24.1 经验不会。照当前实现运行，V24.1 在它要解决的问题上可能比 V24 更差。

**测试为什么没发现。** `tests/v24_1/test_search.py:37–43` 的生成器只写两行程序，装入上限从不起作用。延后测试（`test_search.py:118`、`:137`）人为把上限设到一个片段或1字节。来源超限只在 `tests/v24_1/test_evidence.py:105` 测了单次 `build`，没有测多轮之后能否恢复。

**最小修正（推荐）。** 让材料按构造有界，越窗就让请求失败并显露：

1. 删去字节计量、装入循环、延后与未读积压。每10次已评价尝试，反思读这10个新事件的一跳材料，加每条活跃经验1个代表来源（`REPRESENTATIVES = 1`）。请求、解析或越窗失败都如实记录，本周期不补读。
2. 反思请求使用单独的输出预留，例如4096 token。它的输出是不超过6条的短 JSON，不需要生成的16384。输入空间从约3.2万变为约4.45万 token。
3. 父代形成一步改用“祖父→父代”的差分，不再完整展示祖父代码。单个片段可省约两成。

按探针估计（全部10个新事件、每条经验1个来源、不展示祖父完整代码，按4.3字节/token换算），每次反思中位20.6–33.9K token，p90 24.7–40.8K。图着色最大约48K，少数周期会越窗失败；其余任务都在预算内。若按代码最多的 Crossover 提示比例（3.6–4.5字节/token）换算，JSSP、OP 的最大值约43K，也接近上限。

如果仍要保留装入逻辑，就要同时改三处：用校准的 token 估计（字节/3.5），新事件先新后旧，来源排在新事件之后、能装多少装多少。探针中这三项让各任务每个周期都发请求，后期滞后降到约4–50次尝试（cite1/cite2）。但每条4个来源时，图着色、JSSP、OP 仍分别在第76、235、335次之后停摆。所以无论选哪条路，来源数都要降。

**成本。** 修正后每次反思约20–34K token（中位），V24 正式批次为5.1K。V21 每路生成提示约2.5–3.2M token；V24.1 的反思约为其62%–91%，V24 为17.6%。这不是停用理由，但要单列，并在比较收益时计入。

**复现。** 见附录的 `probe_packing.py` 与命令。

### 发现2（高，V24.1 实现与归因）：没有经验时，Refine 与 Crossover 指令已不同于 V21

**位置。** `traceaad_v24_1/context.py:26–34`。第31行无条件替换指令，第32行才判断有没有经验。

**触发。** 从第一次 Refine/Crossover 起，包括第一次反思之前、反思失败和经验为空的全部时间。

**后果。** Refine 去掉 V21 的 “Do not repeat a modification already tried”，改为同起点同条件不重复、条件改变可重试，并要求先指出当前计算问题、不要只凭其他结构的比较改主机制。Crossover 增加先命名参考计算、用经验处理表示与尺度的要求。V24.1 相对 V21 的差异因此是“指令改写＋经验”。在发现1之下经验大多冻结或缺席，差异可能主要来自指令。V24 的指令与 V21 相同，所以 V24 与 V24.1 的比较也混入这一项。

**最小修正。** 只在展示经验时替换指令：把第31行移入 `if notes:`。这样 V24.1 在有经验之前与 V21 完全相同，差异只来自机制三。若新指令本身应成为生成端的一部分，就另设“V21＋新指令”对照。

**复现。** 在同一档案上调用 `traceaad_v21.context.context` 与 `traceaad_v24_1.context.context(..., notes=[])`：Refine 与 Crossover 的上下文相同、指令不同；Explore 两者相同。`tests/v24_1/test_search.py:195` 只核对了材料相同，没有核对无经验时的指令。

### 发现3（中高，V24 机制，正式批次观察）：V24 笔记重现跨结构排序，并否定了 V21 最终使用的计算方向

**位置。** `traceaad_v24/notes.py:14–42`：反思只读最近10张简略卡片，笔记只有 `idea`/`lesson`，没有条件位置。`traceaad_v24/search.py:43–60`：每轮整版替换。

**触发。** 搜索早期出现现任程序，新计算的初次实现相对父代退步。

**观察**（18路共215次反思，全部成功）：

- 图着色第1路，第85次尝试后：“Randomized DSATUR … is the strongest baseline”，“… as well as adding post-hoc local search phases, regress performance”，“structured heuristics like DSATUR outperform stochastic or simple local improvements”。V21 三路最终最好程序都在 DSATUR 之后做局部改进：消去最高颜色、类移动模拟退火、Kempe 链交换。
- JSSP 第1路，第136次后：“adding priority signals like Remaining Processing Time (RPT), Critical Path estimates … does not improve results and often causes regression”，“Simulated Annealing, Large Neighborhood Search, and Genetic Algorithms provide no advantage”。V21 三路最好程序分别用 RPT/LPT 复合打分、动态关键路径派工、机器序列局部搜索。
- OP 第3路，第245次后：用贪心路线构造或动态规划的前瞻模拟 “cause severe performance regressions … ill-suited”。V21 三路最好程序中，两路用贪心模拟或随机贪心路线加 2-opt，一路用 Dijkstra 最短路。
- TSP 第2路（第215次后）与 CVRP 第1路（第85次后）同样写成 “is optimal”“consistently outperforms”。TSP 的现任已是完整路线模拟，笔记随之把束搜索、精确排列与动态规划写成不如贪心模拟。

**解释边界。** 这些是第69–258次尝试的早期笔记；V21 的上述程序出现在第237–938次。Explore 不读笔记，笔记也可能在突破后转向。它说明 V24 的笔记形式在多任务上产生跨结构结论，不说明最终成绩已受影响。

**含义。** V24 的问题不在某句措辞。材料没有代码、笔记没有条件，结论只能按结果写。继续在 V24 上调提示不划算，跑完批次作参照即可。

### 其余核查：没有发现改变判断的问题

- 修复后的最终版本只算一个事件；格式失败不计入；搜索结束不再反思（`traceaad_v24_1/search.py:82–102`，`evidence.py:30–34`，测试 `test_search.py:148`、`:163`）。
- 恢复按 `attempts.jsonl` 重放事件，用反思记录中的快照覆盖状态；设置不一致时在修补日志之前拒绝（`search.py:49–50`、`58–67`）。中途恢复与延后后恢复都有测试。
- 重复观察只在规范化父子代码、父代评价、子代状态与反馈都相同时合并，常数差异保留；父代与中间程序的完整代码在一份材料中只出现一次（`evidence.py:20–27`、`75–96`；`test_evidence.py:37`、`:62`）。
- 反思请求不进入 `attempt.calls`，不计入 `model_calls` 与评价预算；状态与用量记在 `record["aux"]`，完整提示与回复写入 `calls.jsonl`（`search.py:122–126`）。
- 反思 schema 与生成 schema 分离：`ScheduledModel.for_role` 复制客户端并换 `response_format`（`scheduling.py:111–117`），直接客户端时复制后再换（`search.py:25–31`）。
- 事件编号是尝试编号，提示中同时出现算法编号。V21 正式档案中两者在五个任务完全相同，FSSP 只差0或1。混淆不会造成实质错误；直接用子代算法编号会更简单，但不影响判断。
- 整组更新原子校验：一个非法编号会使整轮作废。它让失败可见，与局部更新的数据接口一致；真实模型的作废率未知，批次中需单列。

## 复杂度与成本：保留什么，删什么

| V24.1 的新增设计 | 判断 | 理由 |
| --- | --- | --- |
| 父代完整代码、完整差分、改写给源码、失败给实际代码与报错 | 保留 | 区分“没有进入决策”“执行失败”“有效执行后变差”必须看代码；这是 V24 已确认的缺口 |
| 同起点最好与最近不同尝试 | 保留 | 同一起点上的干预对照，结论天然限定在同一结构内 |
| 父代形成一步（完整展示祖父代码） | 改为差分 | 单个片段多一份完整程序，约占两成 |
| 重复观察合并 | 保留 | 代价小，避免把重复当独立支持 |
| `when`、稳定编号、局部更新与归档、累计来源 | 保留 | 数据层代价小；`when` 的作用待检验 |
| 每条最多4个代表来源，且每轮必装 | 改为1个，且不得阻挡新事件 | 停摆的直接原因 |
| 字节计量、整片段装入、延后、未读积压及相应的恢复校验 | 删去 | 在真实吞吐下造成积压与停摆；V24 正式批次215次反思无一失败，失败保留处理的是罕见情况 |
| Refine/Crossover 新指令 | 只在展示经验时使用 | 让差异只来自机制三 |
| 整组原子校验 | 保留 | 失败可见 |

修正后 V24.1 的代码会比现在短，也更接近 V24 的生命周期：一个待读列表、每10次一轮、失败即本轮作废。复杂度主要留在材料组织与经验数据结构上，这两部分对应明确的机制需要。

- 窗口：图着色第1路（局部搜索被否定，第85次）、JSSP 第1路（优先级信号与 SA/LNS 被否定，第136次）、OP 第3路（前瞻模拟被否定，第245次）。用这些运行的本地档案构造 V24.1 材料，从头逐周期重放到目标窗口（每周期1次），在目标窗口采样3次。V24 一侧直接用已记录的笔记，不再请求。合计约50次反思请求。

```python
"""Replay a finished V21 archive through V24.1's real finish()/_reflect()/build(); no model is called.

usage: probe_packing.py RUN_DIR POLICY MEASURE [ORDER]
  POLICY  none | cite1 | cite2 | cite4  (experience written by a fixed stub reflector)
  MEASURE bytes (V24.1 default) | tok35 (count_prompt_tokens = ceil(bytes/3.5)) | unlimited
  ORDER   oldest (V24.1) | newest (unread events packed newest first)
"""
import json, math, re, statistics, sys
from pathlib import Path

sys.path.insert(0, "/home/fang/code/LLM4AD/TraceAAD")
from traceaad_base import Config, Task
from traceaad_base.models import Attempt, Program
from traceaad_v24_1 import TraceAAD


class Generator:
    model = "offline"

    def complete(self, prompt, **_):
        raise AssertionError("generation is replayed, never requested")


class Reflector:
    def __init__(self, policy, measure):
        self.policy, self.prompts = policy, []
        if measure == "tok35":
            self.count_prompt_tokens = lambda text: math.ceil(len(text.encode()) / 3.5)

    def complete(self, prompt, **_):
        self.prompts.append(prompt)
        new = json.loads(re.search(r"New events: (\[[^\n]*\])", prompt)[1])
        shown = sorted({int(x) for x in re.findall(r"^Event (\d+):", prompt, re.M)})
        active = re.search(r"\[Current Experience\]\n(.*?)\n\n\[Trajectory Evidence\]", prompt, re.S)[1]
        notes = [] if active.startswith("No experience") else json.loads(active)
        ids, updates = [n["id"] for n in notes], []
        if self.policy == "cite1" and new:
            updates.append(self.entry(None if len(ids) < 6 else ids[len(self.prompts) % 6], new[:1]))
        elif self.policy == "cite2" and new:
            for k in range(2):
                if new[2 * k:2 * k + 2]:
                    updates.append(self.entry(None if len(ids) + k < 6 else ids[k], new[2 * k:2 * k + 2]))
        elif self.policy == "cite4" and shown:
            for k in range(6):
                chosen = shown[-4 * (k + 1):len(shown) - 4 * k] or shown[-4:]
                updates.append(self.entry(ids[k] if k < len(ids) else None, chosen))
        return json.dumps({"analysis": "probe", "updates": updates, "archive_ids": []})

    @staticmethod
    def entry(target, evidence):
        return {"id": target, "idea": "Probe computation title of moderate length for sizing",
                "when": "A computational condition written in one or two short sentences, as requested.",
                "lesson": "A lesson and its design implication written in one or two short sentences.",
                "evidence_ids": list(dict.fromkeys(evidence))[:4]}


def task_from(config):
    t = config["task"]
    return Task(t["task_description"], t["template_program"], lambda *_: None, t["time_limit"],
                entrypoint=t["entrypoint"], example_code=t["example_code"], example_design=t["example_design"],
                score_definition=t["score_definition"], evaluation_seed=t["evaluation_seed"],
                executes_source=t["executes_source"], metadata=t["metadata"])


def main(run_dir, policy, measure, order="oldest"):
    if order == "newest":
        import traceaad_v24_1.search as lifecycle
        original = lifecycle.build
        lifecycle.build = lambda events, unread, *rest: original(events, list(reversed(unread)), *rest)
    native = Path(run_dir) / "native"
    config = json.loads((native / "run_config.json").read_text())
    reflector = Reflector(policy, measure)
    run = TraceAAD(task_from(config), Generator(), config=Config(**config["config"]),
                   reflection_model=reflector)
    if measure == "unlimited":
        run.input_limit = 10 ** 12
    for line in (native / "attempts.jsonl").read_text().splitlines():
        row = json.loads(line)
        attempt = Attempt(**row["attempt"])
        if attempt.operator != "Init":
            attempt.record["best_before"] = run.best.evaluation.fitness
        if row["program"] is not None:
            program = Program.from_dict(row["program"])
            run.archive[program.id] = program
        run.attempts.append(attempt)
        run.finish(attempt)
    reflections = [(a.id, a.record["reflection"]) for a in run.attempts if "reflection" in a.record]
    ok = [(i, r) for i, r in reflections if r["status"] == "success"]
    lag = [i - statistics.mean(r["reviewed_event_ids"]) for i, r in ok if r["reviewed_event_ids"]]
    quarter = max(1, len(lag) // 4)
    print(json.dumps({
        "run": Path(run_dir).name, "policy": policy, "measure": measure, "order": order,
        "cycles": len(reflections), "requests": len(reflector.prompts),
        "statuses": sorted({r["status"] + ":" + r.get("reason", "") for _, r in reflections}),
        "read_per_success_median": statistics.median(len(r["reviewed_event_ids"]) for _, r in ok) if ok else None,
        "read_total": sum(len(r["reviewed_event_ids"]) for _, r in ok),
        "input_size_median": statistics.median(r["input_size"] for _, r in ok) if ok else None,
        "final_unreviewed": len(run.unreviewed_events),
        "lag_first_last_quarter": [statistics.median(lag[:quarter]), statistics.median(lag[-quarter:])] if lag else None,
        "last_success_attempt": max((i for i, _ in ok), default=None),
    }))


if __name__ == "__main__":
    main(*sys.argv[1:5])
```

片段大小探针对每个计数事件分别渲染“单个事件”“完整片段”“去掉形成一步的片段”三种提示，并量 UTF-8 字节（使用 `traceaad_v24_1.evidence.fragment/render` 与 `notes.reflection_prompt`，经验为空）。字节/token 校准读取 `native/calls.jsonl` 前600行的 `prompt` 与 `usage.prompt_tokens`。
