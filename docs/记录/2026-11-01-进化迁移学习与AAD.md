# 进化迁移学习与 AAD：已有先例和可借的结构

日期：2026-11-01（北京时间）。本轮核对原始论文、作者稿和本地论文源码，没有运行搜索实验或修改算法。独立意见见[Claude 的进化迁移分析](../../experiments_result/analysis/aad_transfer_20261101/claude_ec_transfer.md)。下文是我的交叉核对与取舍，不直接继承独立意见的全部判断。

## 认识变化

迁移学习可以帮助理解 AAD，但“把迁移引入 AAD”已经不是空白。传统遗传编程超启发式已有跨任务程序迁移；LLM-AAD 已有共享程序后适配、跨问题经验复用、跨分支记忆，以及语义改动迁移。因此，上一轮提出的“保存前后变化，再用于另一实现”仍只是机制候选。尤其 DeltaEvolve 已将不同节点的语义改动用于当前父代生成，RefineEvo 已检索带适用条件的父子改动经验，不能把它们概括成只保存完整精英或无条件文字建议。

更值得研究的区分是：程序的整体成绩、某次改动在源程序上的效果、这次改动对当前目标程序的适用性，是三个不同的量。我们希望让已经出现的设计变化帮助新的实现，同时保留模型提出其他改法的自由。是否确有大量改进经验因缺少适配而未被利用，仍需直接证据，不能由历史上观察到的全部失败反推。

## 先区分迁移边界

| 情形 | 例子 | 合适的称谓 |
| --- | --- | --- |
| 不同设计任务之间 | TSP 到 CVRP；同类调度的不同目标、分布或约束 | 跨任务迁移、进化多任务优化 |
| 同一设计任务的不同实现之间 | 将一个构造算法中的前瞻改法用于另一种构造算法 | 任务内知识迁移、跨实现的类比适配 |
| 已发现算法用于新实例 | 同一程序在更大规模或新测试集上运行 | 泛化；若无目标侧学习，不自动等于迁移学习 |

同一类问题可以包含多个相关设计任务；也可以始终只有一个固定任务。不能仅因程序或谱系不同，就把每个节点重新命名为一个任务。借用迁移的思想不要求微调模型参数，源经验也可以通过上下文参与生成。

## 直接先例

| 一手来源 | 已经实现的迁移 | 与当前讨论的关系 |
| --- | --- | --- |
| [Multitask GP Generative Hyperheuristics](https://doi.org/10.1109/TCYB.2021.3065340)，2021 在线、2022 卷期；[作者论文目录](https://fangfang-zhang.github.io/publications/) | 多个动态调度任务共同演化 GP 调度规则，通过程序交叉共享信息 | 传统进化迁移早已进入启发式设计空间，不限于数值解 |
| [Task Relatedness Based Multitask GP](https://fangfang-zhang.github.io/files/2022-Task_Relatedness_Based_Multitask_Genetic_Programming_for_Dynamic_Flexible_Job_Shop_Scheduling.pdf)，2022 在线、2023 卷期 | 在共同决策情境下构造程序行为表征，用种群行为分布估计任务关系并选择辅助任务 | 可借“迁移要看目标关系”；它依赖共享决策接口，不能直接推广到任意完整程序 |
| [EMO-STA](https://arxiv.org/html/2605.22613v2)，2026 | 先演化跨任务共享的可执行程序档案，再为目标任务选择起点并继续适配 | 直接将进化多任务用于 LLM 程序发现；采用统一程序接口，预算比较是演化迭代数，不应改写成所有成本均相同 |
| [MTHS](https://openreview.net/pdf/5943a2ea1a6b035dd3938f1efb50142c928ed0b4.pdf) | 同时演化任务无关的元启发式与任务专属实现，并利用其他任务的精英程序 | 已有“算法思想跨问题迁移”的直接研究。本轮核对到原始摘要；全文打开遇到验证页，不依据它断言细部实现或正式录用信息 |
| [MECo](https://arxiv.org/html/2610.03316v1)，2026 | 维护任务条件种群，用跨任务表现形成 transfer gap，引导程序迁移和任务组合 | 已经针对目标兼容性选择跨任务交互，不是无差别混合；其目标还包括未知问题上的直接应用 |
| [RefineEvo](https://arxiv.org/html/2607.11358v1)，2026，§3.3、E.4、G.3 | 比较父子变化，提取修改、建议和适用条件；检索正负经验；以另一问题的经验库热启动 | 与我们的候选很近。其跨问题实验也包含负迁移，不能将“有适用条件”或“经验迁移”独立声称为新增机制 |
| [DeltaEvolve](https://arxiv.org/html/2602.02919v1)，2026，§4 | 当前父代保留源码，其他节点提供改动前后的逻辑及假设；以精英和多样来源提供改进材料 | “迁移变化而非仅迁移成品”已有直接先例。其 L2 已包含旧逻辑、新逻辑和假设，不能把它简化成只有最终算法摘要 |
| [MEMOIR](https://arxiv.org/html/2605.17539v1)，2026，§3.2.3 | 分支内保留执行反馈；分支结束后压缩为算法设计、失败模式与避免建议，供后续分支生成使用 | 同一任务内跨分支知识迁移已被明确命名和实现 |
| [Back to the Beginning of Heuristic Design](https://arxiv.org/html/2605.06123v1)，2026，§4.2 | 比较最终代码与知识产物的迁移；包括构造式 TSP 到 ACO TSP，以及 TSP 到 VRP 变体 | 同一问题的不同求解框架之间也已有迁移实验；作者明确报告迁移不总胜过从零搜索 |

另有 [2409.04270](https://arxiv.org/abs/2409.04270) 用 LLM 设计进化多任务的迁移算子。它属于用自动算法设计改善迁移算法，不能直接算作“让 AAD 的设计经验发生迁移”的证据。

## 成熟技术中值得借的部分

[MFEA-II 原始作者稿](https://memetic-computing.org/publication/journal/FinalSub.pdf)将跨任务交配概率扩展为在线估计的矩阵，以各任务种群模型的混合似然估计交互强度。[AMTEA 原始作者稿](https://dr.ntu.edu.sg/server/api/core/bitstreams/88dc6485-f16c-441d-b273-51654aaacc8e/content)将已有源分布与目标分布混合，并由目标种群数据拟合权重。共同启示是：源任务取得好成绩，不足以确定它对当前目标有帮助。

我会借用两个原则：先建立源与目标的对应关系；允许迁移只发生在适合当前目标的部分。不会直接给每个算法对建立 RMP 矩阵。程序不断新增、每对观测极少，与少数固定任务反复形成种群样本的条件不同。稀疏性不是迁移不可能，而是应利用共享的语义和结构，避免为每个新组合重新估计一个独立参数。

AAD 的具体适配难点有三项：

1. **计算角色没有公共坐标。** 两份程序都输出一条路线，不代表内部状态、候选评分、邻域或停止条件可互换。传统 GP 常用固定原语和决策情境；任意 Python 求解器的边界更开放。
2. **改动价值依赖周围计算。** 增加前瞻可能弥补短视，也可能重复目标已有的估计或耗尽其运行时间。源案例中的成绩变化不是目标中的收益保证，也不自动分离了多个同时改动的因果贡献。
3. **迁移材料可能改变生成偏好。** 它可能帮助模型建立新的组合，也可能诱导模仿或增加上下文负担。负迁移可以表现为低质量、无效或过慢的后代，不应预先断言其主要形态必然是趋同。

Claude 建议借差分进化的“基底与变化分离”。我保留这个结构类比，但不把代码差当作可相加的向量，也不把文本 diff 自动视为可迁移计算。只给局部 diff 可能丢掉依赖；模型口头拒绝不适合的案例也不等价于已学到正确的迁移概率。这两项应作为材料组织的选择，不增加硬性规则。

## 一个足够小的机制候选

当前算法仍按质量选择。另取一段与目标计算相关的历史变化，提供修改前后所需源码、变化说明以及对应评价，不要求源程序在全库排名靠前。生成模型在同一次调用中理解对应关系，将改动适配为目标实现；它也可以重组、简化或不用该案例。常规自主生成继续保留，评价后的候选按原有质量规则参与搜索。

最小形式为：

\[
e=(a,a',f(a),f(a')),\qquad
x'\sim G_\theta(\text{任务},x,e).
\]

其中源变化是 \(a\to a'\)，目标变化是 \(x\to x'\)。材料的作用是支持二者计算关系的类比，不是要求把 \(a'\) 复制到 \(x\)。相关案例的检索可以先用已有设计说明作粗筛；真正是否适用仍需结合源码理解，不能把嵌入相似度等同于功能对应。

例如，源程序从单步贪心改为评估候选选择后的剩余路径代价。目标采用插入构造，模型可以借鉴“评估选择的后续影响”，实现适合插入状态的估计，而无须继承源程序的整个构造顺序。这是机制例子，不是已经观察到的成功迁移。

## 贡献应落在哪里

当前值得检验的认识是：**经验复用的效果取决于设计变化在目标实现中的适配，而程序总分和源端改进量都不足以代替这种适配。** 对应候选是“基于具体前后变化的类比迁移”，将新增设计集中到源变化与目标计算之间的对应关系。

相较 RefineEvo 和 DeltaEvolve，可能的增量是：保留源变化所依赖的实际计算，并在目标中重新建立对应关系，减少仅根据源端说明使用经验时的错配。它们本身已经表达修改及情境，因此不能只靠多给源码、换名字或写一个更长提示宣称方法成立。

最能改变下一步决策的检验，是固定当前算法与源案例，比较三种材料：源端最终程序、文字化改动经验、带必要源码的前后关系。在可比的生成与上下文成本下，观察第三种是否更常产生真正适配目标且有竞争力的计算。检验关注材料是否带来额外帮助，不要求证明每次创新必然成功。若有帮助，再将这一个机制接入完整搜索；若没有，就不为经验迁移继续追加信用层、保护额度或配对潜力模型。
