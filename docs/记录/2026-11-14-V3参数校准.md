# V3参数校准：稳定名次之间的选择强度

我先检查了参数的实际含义，而不是直接搜索一组看起来最好的数值。固定质量倍率10在种群扩大后会使相邻名次越来越接近。按旧式，第一次评价导致的权重减半，相当于`(种群大小 - 1) × log(2) / log(10)`个名次：80个体时约23.8位。这个变化来自公式，与任务实际变难或开发价值下降无关。

## 本次采用的改动

我保留个体全局抽样和历史子树投入折扣，将质量参数替换为`rank_half_life=10`。平均名次从0开始，并列使用平均位置。个体权重为：

```text
2 ** (-平均名次 / rank_half_life) / (1 + 历史子树评价数)
```

它只有一个质量强度参数。以下折扣比较均固定当时的排名。默认每落后10位，质量权重减半；第一次开发的成本折扣也恰好对应10位，之后每次投入的边际折扣渐小。加入更差个体时，既有个体的质量权重比不变，但绝对概率仍会受新竞争者影响。它不是独立于种群数量的总预算份额，也不消除近同版本的数量效应。

这个变化等价于让原来的全体质量倍率按种群大小变化：无并列时，倍率为`2 ** ((种群大小 - 1) / rank_half_life)`。这是规模校准，不是根据改进率学习的控制器。排名仍不包含原始分差，所以不能声称自动适配了任务难度或算法潜力。

## 公式校准支持什么

[可复查脚本](../../experiments_result/analysis/v3_selection_calibration_20261114/analyze.py)比较固定倍率10、100、1000与名次跨度5、10、20，覆盖5、20、40、80、160个体和等投入、冠军投入1次、冠军投入9次、全部同分四种状态，共120个分布。[原始结果与源码哈希](../../experiments_result/analysis/v3_selection_calibration_20261114/results.json)和[对比图](../../experiments_result/analysis/v3_selection_calibration_20261114/comparison.html)保留在同一目录。没有生成新程序，也没有使用测试集选择参数。

无并列且投入相同的80个体中：

| 质量规则 | 前10名总概率 | 后40名总概率 |
| --- | ---: | ---: |
| 固定倍率10 | 28.0% | 23.8% |
| 名次减半跨度5 | 75.0% | 0.4% |
| 名次减半跨度10 | 50.2% | 5.9% |
| 名次减半跨度20 | 31.2% | 20.0% |

我选择10作为较温和的初始取舍。5对较低名次的压制更强，20在同一状态更分散。这里的“前10名约一半”只来自无并列、等投入的几何级数，不是实际运行的配额或保证；真实成本、并列和保留变化都会改变分配。固定倍率10从20个体扩大到160个体时，前10名总概率从77.1%降到15.0%；跨度10对应从66.7%到50.0%。这些结果确认规模变化的行为，不证明最终搜索质量提高。

## 其他参数的取舍

| 参数 | 本次取舍 | 理由 |
| --- | --- | --- |
| `rank_half_life` | 默认10，重点校准5、10、20 | 直接控制质量偏好；使用名次单位，避免种群扩大使相邻名次差变平。 |
| 子树折扣`1 + 历史评价数` | 保留，不另加耗竭尺度或指数 | 保持实际评价为单位。它是预算偏好，不把成本当成成功/失败观测。 |
| Refine/Explore/Crossover | 保留0.45/0.30/0.25 | 暂不按单步刷新率自适应；弱初稿可能需要后续开发，立即奖励容易混淆算子产出和后续选择。 |
| `cold_evaluations=40` | 保留 | 它控制近期状态的保留，不保证每个节点得到开发。不能用延长寿命代替合理分配。 |
| `quality_floor=0.5`、`clone_distance=0.08` | 保留 | 这两个量决定质量/代码差异代表；改动它们会同时改变候选集合与上下文，不能混在本次质量强度校准中解释。 |
| `reference_quality_floor=0.3` | 保留 | 它控制交叉参考，不直接控制主父代的探索与利用。 |

剩余预算退火、停滞触发和成功率驱动的在线控制都没有加入。它们需要额外确定信号、更新速度及目标；目前的明确问题是种群规模改变了选择强度，名次尺度已能直接处理它。

## 实现与证据边界

独立CLI、统一实验入口和批次计划均支持`--rank-half-life`，实际值写入配置并传到搜索，未指定的恢复读取原生保存值。旧固定倍率记录需用旧源码恢复，不能混用。计数所有权、收缩、算子和经验交接保持上一轮定义。

当前校准不利用历史日志反推一种未实际发生的搜索结果，也未启动付费模型调用或完整搜索批次。下一步能改变参数选择的证据，是在相同任务、训练条件和评价预算下比较5、10、20的完整搜索，而不是追求某个父代份额指标。协议中的独立测试只用于最后评价，不用于调参。最终是否保留10仍待这种比较。

检查结果：78项核心、入口及队列检查通过；新增参数传递和恢复断言所在的45项检查也通过（两组有重叠，不相加）。覆盖不同种群规模的相对权重、同分、极端跨度、成本账目、旧规则拒绝恢复和自定义跨度的原生恢复。图表HTML已呈现；宿主AppArmor阻止了浏览器预检，未完成图表外观自动验收。
