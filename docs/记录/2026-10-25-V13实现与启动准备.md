# V13 实现与启动准备

10月25日开始实现，10月26日完成检查与启动准备。

V13 已把[设计方案](../TraceAAD：从设计轨迹中学习可复用的算法变换.md)接成可执行搜索器。实现与参数见 [V13 README](../../traceaad/v13/README.md)。这次的目的，是把机制运行起来并检查实际模型接口；预试结果不用于判断完整搜索的收益。

## 已实现的范围

共享谱系 DAG 保存双亲、旁支和失败程序；父代轨迹在读取时汇总，晚到的祖先旁支失败可立即进入后代视图。变换库包含适用结构、修改操作、依赖、参数、保留条件、检查项及使用记录。新父代先匹配和绑定，再做受约束的局部编辑，最后独立核对实际差分。

使用结果区分不适用、实施失败、正确实施但无改进、正确实施且改进。前两类不计入变换的性能失败率。反馈可细化条件、拆分或组合操作，并保存旧版本。Open/Transform/Crossover 与算法路线按实际观察到的收益分配机会，保留 Open 和路线最低份额。所有模型阶段均记账，支持阶段恢复、同任务变换库导出与导入、训练最优程序冻结和公共独立测试入口。

预算沿用仓库协议：每路 1000 次**候选尝试**，另设全部模型请求上限 8000。初始化、不匹配、失败编辑及辅助调用都有明确记账；这不是相同有效评价次数或相同 token 预算。路线、检索、保底比例等文档未指定的数值已在配置和 README 中明确，后续可在固定条件下检验。

## 实际运行检查改变了哪些实现

最初两轮 TSP 搜索分别完成 8 和 12 次候选尝试、20 和 28 次模型调用，并通过独立的 50 实例主测试。但当时没有形成变换库。读取实际回复后发现，不能把“没有变换”直接解释为没有可复用修改：

- 模型把不同编辑归为同一个算法家族；现在明确区分编辑操作的类别和算法路线。
- 模型以“不够新颖、未证明泛化”为由拒绝已观察到的改进；现在一个有改进的样本就足以提出候选操作，适用范围由后续使用决定。
- 归纳时，模型把子代代码抄作父代绑定；来源锚点改由实际代码差分直接提取，新父代仍须模型独立绑定。
- 模型用文本列表表达依赖、参数和检查项；现在将这类明确结构规范化为逐行文本，仍拒绝空字段和未知嵌套结构。
- 变换规格有时描述整个结果算法，而没有说明怎么修改父代；现在明确要求“把哪个原计算替换成什么、加入或删除什么”，匹配针对修改前结构。

这些调整解决的是表示与实施接口，不要求每个变换都产生收益，也不把格式或执行失败算成算法思想无效。

## 冻结版本的验证

全仓库 **286 项测试通过**，其中 V13 专项检查为 35 项。覆盖所有模型阶段的中断恢复、不同规模变换库下的稳定上下文、评价回执、请求预算、局部编辑边界、失败分类、规格版本/拆分/组合/前提、库导入、六任务入口、公共结果读取和预算前缀选择。

真实模型正控制使用同一份实际父子修改，将来源父代的局部变量重命名，再重新评价确认成绩不变。它检查实施链条，**不是跨算法背景的迁移收益实验**。

| 冻结版本检查 | 实际结果 |
| --- | --- |
| DeepSeek 正控制 | 6 次请求完成归纳、匹配、编辑、核对、摘要和修订；核对全部通过，训练评价复现改进，无阶段错误。 |
| 共享 Qwen 池正控制 | 4 次请求完成归纳、匹配、编辑尝试和修订尝试；编辑超出已绑定区间，被拒绝并记为实施失败。修订回复缺少完整规格字段，保留原规格。 |
| 完成后的恢复 | DeepSeek 同一运行再次执行，调用日志、事件、检查点、最终选择和变换库文件的校验值保持不变，没有新增模型请求。 |

这一个正控制说明整条机制可以执行，也说明模型实施能力仍会影响有效尝试的比例。它不能估计模型总体差异，更不能证明完整搜索的收益。正式实验应分开报告“正确实施率”和“正确实施后的改进率”。早期单步失败不应直接上升为对机制的否定。

正式 18 路**尚未启动**。启动脚本只启动搜索；各路冻结后使用公共 `experiments.infra.evaluate --primary` 完成独立测试。当前预览采用共享 Qwen 池以衔接已有比较条件；正控制中的实施失败需要在小批量校准中计量，不能凭一次成功或失败给出总体判断。

最初两轮搜索、归纳绑定诊断、格式诊断、未见父代不适用记录、库导入正控制，以及最终两种模型的正控制均保留在 `preflight/` 对应子目录。它们来自不同的实现检查阶段，应按各自源码与配置解释，不应合并成一组方法性能结果。
