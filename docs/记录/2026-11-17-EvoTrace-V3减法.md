# EvoTrace V3：按奥卡姆剃刀删减反思与工程封装

日期：2026-11-17（北京时间）

状态：已提交 `1e6552b3`，经 Astra 与 Carbon 评审修订。论文第2节与附录E已按本版改写。精确规则见 [V3设计](../EvoTrace-v3设计.md) 第1–5节。

**目标：流程只保留服务核心贡献的部分。** 核心贡献是三件事：反思式淘汰（淘汰的区域凝练为边经验或节点经验）、代表集上的选择与预算、按树渲染的上下文。上一轮已精简生成上下文（见[演化轨迹上下文设计](2026-11-17-EvoTrace演化轨迹上下文设计.md)）；本轮主要删减反思，它是核心贡献本身，却是最工程化的部分。

## 1. 反思

旧批次 `evotrace_v3_rep_cover` 的 1890 次反思中，回退 0 次。按字符计，边反思提示中代码差分占 49%、完整代码占 38%；节点反思中差分占 69%、代码占 19%；提示里没有 `design`。

| 项目 | 原 V3 | 本版 |
| --- | --- | --- |
| 证据 | 起点代码、中间代码、分支差分、终点代码、净差分 | 每个算法一条记录：来源与结果 → `design` → 失败原因 → 已有经验 → 源码（只出现一次）；区域外保留的算法作基准 |
| 附加段落 | `[Related Results]`（区域外兄弟）、`[Comparison Catalog]`（重复列出步骤结果） | 删除 |
| 编号 | Step、Branch Trial、Trial、Additional parent 四套 | 统一为 `Algorithm i` |
| 模板 | 边、节点各一个，三句自我限定 | 一个模板；一条范围要求：写明起点、改动与结果，不把单次结果写成通用规则或禁令 |
| 回退 | 比较记录的确定性摘要，960 字符截断 | 沿用提示中已有经验的去重拼接 |
| 比较账本 | `Node/Edge.observations`、`root_observations` | 删除；原始记录在 `attempts.jsonl` |

保留源码的理由：反思是唯一消化实现证据的地方，复杂度缺陷与实现错误只能在这里进入经验。加入 `design` 的理由：经验写在概念层，后续在上下文中与 `design` 一起读。

## 2. 选择

- **父代权重**直接按 $2^{-\text{rank}/H}/(1+n_r)$ 计算，并列取平均名次；删去 quality 与 rank 的往返换算、`ulp` 下限和未调用的 `champion`。
- **精确去重**只保留在 `distinct_individuals` 一处（`cover_distance = 0` 的消融仍不会被克隆占满名额）；allocation 中三处 `identity` 检查删除。
- **保留 `used_crossover_pairs`。** 原方案想改为从树上推出，Carbon 用数据反对：`rep_cover` 最终树中 541 对已用组合有 386 对（71.3%）的交叉子代已被剪枝或收缩。从树上推出会让父代每次剪枝后重新选中同一个最远参考。它与确定性最远选择配套，实现无放回轮换，属于选择机制。

## 3. 生成提示

- 删去方向性暗示：Explore 中“例如估计下游后果、构造并改进暂定解、求解子问题”一句，以及 Explore、Crossover、初始化提示中 “rather than another weighting of the same local features”“rather than simply add another scoring term”。基线提示没有这类句子；代表卡片已给出本任务上真实存在的不同做法。
- 删除“尝试”列表中的同码子代合并，它会藏起挂着不同经验的子代。
- 当前算法卡片与初始化提示统一写作 `fitness =`。

这一项是唯一可能影响性能、又不属于机制的改动，不做预测试，在正式批次中观察。

**正式批次观察与修订（北京时间11-17 约14:10）。** `evotrace_v3_lean` 各路跑到48–75次评价时，CVRP、FSSP、OP与旧批次同次评价相当或更好，TSP明显落后（第60次评价三种子均值6.893；`rep_cover` 6.020，`full` 5.982，V1 5.980）。原因如下：

- 旧批次TSP的跃升都来自Explore生成的“为每个候选构造完整暂定路线（加MST估计或2-opt）”的算法。
- 本批TSP的Explore子代塌缩为局部特征加权和：设计文本含 composite/weighted score 的占40/52，`rep_cover` 只有4/54。用到路线补全思路的子代，本批13/52，`rep_cover` 53/53。
- 初始种群全是加权打分时，按AST距离选出的代表卡片仍属同一种计算方式。AST距离上的差异不等于计算方式上的差异，“代表卡片已给出不同做法”这一前提不成立。

两句的性质不同，处理也不同：

- **恢复定义句。** Explore的 “Develop a new way to compute the decision, rather than another weighting of the same local features.” 与初始化的 “Seek a different way to compute the decision, …” 已恢复。这两句定义“主要计算不同”的含义，不含领域思路，与EoH、RefineEvo探索算子的 “a totally different form from the given ones” 同类。
- **不恢复示例句。** “估计下游后果、构造并改进暂定解、求解子问题”属于策略先验。其前身清单（结构信息、前瞻、迭代、分解、小规模精确求解）来自对基准任务上有效程序的观察，基线没有对应句子。模型会照抄它：`rep_cover` 的TSP Explore设计中有9/54直接出现 “tentative”，OP与FSSP分别有14/54、12/54出现 “downstream”。若只恢复定义句后TSP仍停在加权和，再把示例句作为公开消融处理。

Crossover的 “rather than simply add another scoring term” 仍不恢复。

## 4. 工程封装

删除：`reflection_model="same"` 与 `reflection_enabled`（反思用生成模型），两个同构 schema 合一，`reflective_simplify` 与 `_call_structured_model` 的多分支，`prompt_chars` 与 `used_fallback`（失败看 `error`），`simplifications_count` 与 `reflection_calls_count`，`plan.triggers`（代表与分叉直接记入简化日志），`ContextConfig.include_reference_code`，`TreePopulation.add` 的内部检查，`reference_rule` 与 `reflection_representation` 标签，未调用的 `initialization.py`。生成与反思设置输出格式统一为 `with_output_format`。

保留：配置的取值范围检查（参数来自命令行）；实验入口读取的 `selection_rule`、`mechanisms`、`generation_protocol`；`aux` 成本记录；与基线共用的协议（一次修复、`max_unevaluated`、`failure_count`、`analysis` 字段）；评价沙箱、模型客户端、存储与断点恢复。

## 6. 兼容性

旧运行不能用新代码续跑（树快照含 `observations`，`run_config` 标签不同），需用各自冻结快照。`paper/collect_*.py` 读取 `used_fallback` 与 `triggers`，它们绑定旧批次；用于新批次时改读 `error`、`representative_ids` 与 `fork_ids`。
