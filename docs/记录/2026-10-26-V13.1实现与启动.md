# V13.1 实现与启动

我按[修订主稿](../TraceAAD：从设计轨迹中学习何时重用修改.md)实现了独立的 [V13.1](../../traceaad/v13_1/README.md)。用户授权停止 V13 并启动替代批次。V13 的十八个会话及子进程已停止，结果与源码保留；公共调度器和其他批次继续运行。

## 这次真正改变了什么

V13.1 将发现与验证分开。规格的操作、语义参数、绑定策略与收益条件冻结；发现样本不进入重放信用。全局、单条件与谱系模型用后续结果的预测概率竞争，Thompson 选择以期望正增益为目标。诊断只看新增执行的预测分歧，条件变化不是入口门槛；带符号 D 记录实际局部交互或背景收益差异，不充当额外样本。历史失败不形成谱系禁令。

匹配与条件按不可变程序和规格缓存。自由修改只携带近期轨迹与旁支的必要证据；规格分批匹配，超限时先缩小目录和可选上下文，保留当前源码与操作约束。运行时条件没有实测依据时记未知，本次未装配通用运行时探针。静态条件采用执行前源码及可定位的源码证据求值。

三个不同父代上的合规实例能被同一角色化 token 规则复现时，才启用确定性模板；切换执行器创建新版本，旧记录留存，信用与权重重新开始。完整训练评价仍使用公共任务接口、种子、约束与资源池。

## 真实模型检查改变了什么

第一轮来源正控制中，模型将固定参数写成 JSON 对象，原文本字段校验拒绝了它。现在对命名语义参数做无损规范化，并保留非有限值检查。

后续检查发现，归纳可能只提取复合修改中的一个有吸引力的部分，匹配又可能将“同类算法”误判为“完整操作已存在”。现在来源归纳要求覆盖全部实际语义差分，入库前做独立来源核对，漏项最多重写一次。匹配提供去掉注释后的实际来源差分，明确区分旧参数与冻结的目标参数，不能把相同算法家族作为拒绝理由。

冻结版本的正控制使用既有真实父子修改及重命名后的来源程序，共五次模型请求：归纳、来源核对、匹配、局部编辑和执行核对。全部核对通过，无阶段错误，训练评价复现改进。它验证实施链条，不证明跨算法背景迁移有效。最初三个未通过的检查保存在预试目录，不并入正式实验。

另一个从零开始的 TSP 小搜索完成八次候选机会、十七次模型请求，形成两个变换，达到预算后正常冻结；实际配对观察为零。这说明搜索流程可以结束，不能说明有限预算内的对照机会足够。

## 冻结验证与正式启动

全仓库 **308 项测试通过**。V13.1 的十七项测试覆盖每个模型阶段恢复、来源规格漏项重写、缓存非独立性、发现记录排除、后验与预测评分、未知条件、AST 位置映射、同条件配对入口、单次修复、执行器版本切换、库导入与配置保护、评价回执恢复及入口预览。六任务配置与十八路计划另做了核对。

正式批次为 `20261026_v13_1_co6`，六任务各运行种子 0、1、2，空库启动；每路 1000 次候选机会、最多 8000 次全部模型请求。源码冻结在 server4 的 `TraceAAD_runs/20261026_traceaad_v13_1_frozen`，启动前核对 374 个文件的 SHA-256。各路按三秒间隔启动，搜索冻结后自动执行公共独立主测试。

首轮跟进确认十八个会话均存活、十八路都已收到模型回复，十五路已有有效程序，接口错误为零。图着色第一路有一次未返回完整代码的生成失败，已记账并继续；其余尚无有效程序的路次仍在生成或评价。这里报告的是启动时点状态，不是最终成功率。

主看板已将当前 TraceAAD 切换至 V13.1，十二个基线名单不变。本机每分钟同步搜索与主测试结果，保留远端数据。原始依据位于 `experiments_result/traceaad_v13_1/preflight/` 和 `launch_20261026/`；正式清单为 `experiments_result/traceaad_v13_1/batch_20261026_v13_1_co6.json`。接下来最值得观察的是合格对照频率、前瞻重放与背景覆盖，以及这些开销是否换来同预算下的改进。
