# 轨迹双机制调研：AAD 之外的上下文与提示形式

日期：2026-11-03，北京时间。范围：独立研究；仅撰写本报告，未运行搜索算法、模型调用或实验，未改实现。下文的网络检索用于核对原论文与作者代码。

## 结论

我建议先采用一个最小候选：**当前父代提供完整代码；历史提供按关系组织的设计与修改记录；同一起点的不同结果并列呈现；生成输出保留短分析、候选设计与完整代码。** 祖先路径和全部直接子代均保留。历史文字首先用于理解已有尝试，不写成必须沿用的处方。

这五项研究改变的是具体呈现决策，而非证明整套轨迹机制有效：

1. 正负对照有理由保留，但“某实现成绩较差”与“某思想错误”需要分开。
2. 历史顺序和段落位置都是实际变量，不能把同一批信息的任意排列视为等价输入。
3. 增加历史可能同时增加线索与干扰。“窗口容得下”不代表模型会准确比较。
4. 简短、可执行的设计步骤值得先保留。没有依据要求长篇分析，也没有依据为此增加独立规划调用。
5. **历史文字优于历史代码、同父代对照优于其他历史、显式分析在当前模型上是否必要，均未被这些研究直接验证。** 它们应作为候选取舍，而非现成定论。

## 五项一手研究

### 1. Contrastive Chain-of-Thought：负例需要可辨认的对照关系

**作者机制。** Chia 等在同一道示例题中同时放入正确与错误解释、答案。负例由正确解释中的实体或数字错置构造。作者代码明确拼接 `Explanation`、`Answer`、`Wrong explanation`、`Wrong Answer`，不是只把错误回答混入示例。[论文 §2–3、表1–2](https://arxiv.org/html/2311.09277v1)；[作者 demo.py，ContrastiveChainThoughtPrompter，第132–142行](https://github.com/DAMO-NLP-SG/contrastive-cot/blob/main/demo.py#L132-L142)。

**实验真正证明。** GPT-3.5-Turbo-0301、4-shot 条件下，作者比较了五种错误构造。各类正负对照均优于其普通 CoT 基线；主实验覆盖算术与事实问答。它检验了带明确标签的对照示例，未隔离额外 token 的作用，也未检验程序演化中低适应度但仍正确的实现。

**作者解释。** 正确与错误解释的对照帮助模型减少推理错误。

**我的迁移判断。** 把同一父代的不同修改并列，呈现“改了什么、结果怎样”，值得采用。但我们的低分子代没有正确答案意义上的 `Wrong` 标签。它可能实现不充分、改动组合不当，也可能需要后续精炼。因此用“本次实现未改善”，而非“禁止这种思想”。代价是仍需模型解释差异；这项研究不能替我们完成因果归因。

### 2. Fantastically Ordered Prompts：同一批实例，次序也会改变输出

**作者机制与提示。** Lu 等把分类实例按固定模板串接，改变样例顺序。四个实例产生24种排列；另以生成的探测集合及熵统计挑选排列。[ACL 2022 原论文 §2、§3、图1/4、表1/2](https://aclanthology.org/2022.acl-long.556.pdf)。

**实验真正证明。** 固定样例集合时，排列可造成很大性能差异；在多组样例与不同 GPT 模型中复现。一种排列在某模型上表现好，不保证换模型仍好。论文没有比较演化历史按时间、成绩、算子排列。

**作者解释。** 差排列常使预测标签分布失衡；探测分布可帮助找出好排列。

**我的迁移判断。** 默认保留祖先的演化顺序，避免丢失修改先后。直接子代按同父代并列，内部用生成次序，不先按成绩排序。这是保持关系与避免额外选择偏差的工程候选，**不是论文证明了时间顺序最好**。代价是相关记录可能落在不利位置；换模型后不能沿用旧的顺序效果判断。暂不引入排列搜索和熵排序模块。

### 3. Lost in the Middle：提供信息与模型使用信息是两件事

**作者机制与提示。** Liu 等在多文档问答与键值检索中移动答案所在记录，同时改变上下文长度。提示包含文档或键值集合及查询。另比较查询置于材料前后两处的形式。[论文 §2–4，尤其 §4.2、附录B/C](https://arxiv.org/html/2307.03172v3)。

**实验真正证明。** 多个受测模型在相关信息位于开头或结尾时表现较好，中间较差。查询前后重复显著改善键值检索，却只轻微改变多文档问答的趋势。附录更换干扰文档与打乱干扰文档顺序，检验了部分替代解释。

**作者解释。** 模型未稳定利用长上下文；扩充窗口并不自动解决信息访问问题。

**我的迁移判断。** 在开头写清任务与本次算子，在历史之后放当前父代完整代码，最后以短句提出本次修改要求，是合理起点。不要再复制一遍全部历史或完整代码来“增强注意”。这是从检索迁移到代码编辑的假设；论文没有验证我们的段落布局，也没有证明尾部代码不会增加保守复制。代价是历史中的关键变化仍可能被忽略，需要检查生成是否实际引用并落实了它。

### 4. GSM-IC：相关词汇也会携带无关信息

**作者机制与提示。** Shi 等给算术题加入不改变答案的句子，并改变话题、角色重叠与数字范围。比较普通提示、带干扰的示例，以及允许忽略无关信息的一句指令。[ICML 2023 原论文 §3–5、表3/4/14](https://proceedings.mlr.press/v202/shi23a/shi23a.pdf)。

**实验真正证明。** 同话题干扰可比异话题干扰更难处理。针对性的忽略指令能改善表现；泛泛写“解数学题”没有同样效果。原实验中该指令只是部分缓解干扰，不能保证模型识别所有无关材料。

**作者解释。** 模型会错误使用干扰句中的内容；示例与指令可改善筛选。

**我的迁移判断。** 经验条目不应只因术语接近就被写成建议。最小条目写“在哪种结构上尝试、观察到什么、借鉴时需改变什么”，并允许本次不采用。不要强制逐条讨论所有经验。代价是可能漏用一条远距离但有价值的经验。算术中的已知无关句，不等于演化历史中价值尚不清楚的失败尝试，不能据此删掉全部低分子代。

### 5. Self-planning Code Generation：短步骤有依据，长分析没有必然优势

**作者机制与实际提示。** Jiang 等先用意图—计划示例生成编号步骤，再把计划接到任务后生成代码。步骤使用动作动词、保持较高抽象层级。PDF 附录C的加密函数示例采用建立字母表、遍历输入、返回结果的步骤；附录E展示逐语句解释和极简计划。[论文 §2、§4.3、表4与附录C/E](https://arxiv.org/pdf/2303.06689v3)。

**实验真正证明。** HumanEval 消融中，编号计划优于改为连续叙述的计划；极简计划未变差，Plan2CoT 加一层解释反而低于原计划。一步生成计划和代码也未低于两阶段。直接代码基线为零样例，计划方法带示例，不能把其全部差异归于“写分析”。这些结果不是等 token、等计算的隔离实验。

**作者解释。** 子问题分解降低实现难度；额外抽象可能增加错误。

**我的迁移判断。** 先保留一小段证据比较和具体设计步骤，再一次输出完整代码。没有必要强制长篇历史复述或另加规划调用。代价是短设计可能遗漏约束，生成仍可能偏离设计。函数级正确性任务不能直接回答复杂启发式优化中显式分析是否提高成绩。

## 候选取舍：问题、最小机制与代价

以下是我基于上述证据形成的方案判断，尚非 EvoTrace 的实验结论。

| 决策 | 明确问题 | 最小候选 | 潜在代价与替代 |
| --- | --- | --- | --- |
| 历史文字或代码 | 多份完整旧程序占据输入，并可能牵引模型复制旧结构 | 当前父代全文；历史默认使用设计、修改说明、成绩及必要代码差异 | 文字可能遗漏真实计算。若修改无法用文字准确区分，在该记录内加相关代码片段；不另建摘要模型 |
| 同起点好坏结果 | 只看好结果容易重复已失败实现，直接标错又可能提前排除思想 | 全部子代共享父代标识、评价条件、算子、改动、结果；好坏并列 | 多处同时修改仍混杂，不能从成绩差直接推出哪个改动有效 |
| 历史顺序 | 时间关系丢失，或高分排列额外强化模仿 | 祖先按演化顺序；子代按生成顺序，固定布局 | 不保证模型最易使用；顺序敏感性留作未来单变量核对 |
| 上下文位置 | 当前任务或代码被大量历史夹在中间 | 任务与算子在前；历史与经验在中；父代全文及本次要求在后 | 当前父代靠后也可能增加保守；无须重复全文 |
| 累积经验 | 同一结果被摘要、经验、历史重复转述，形成虚假多数 | 每条经验保留源事件编号，明确适用结构；相同事件仍算一次观察 | 编号不是因果鉴别器；不能将不同编号自动当作独立样本 |
| 分析输出 | 长分析消耗预算并把猜测写成原因；纯代码又难追踪接续依据 | 短分析引用关键记录，随后给设计与完整代码 | 分析可审查不等于因果真实；最终仍需看实现与评价 |

我暂不采用“从每条经验推导一条禁令”“强制选择一成功一失败”“先让模型全面总结历史，再让另一个模型写代码”。前两项会把稀疏反馈变成处方，第三项增加成本与摘要失真，当前没有对应证据要求这些模块。

同父代记录还需保留两个区分：

- **不可运行**是实现状态；**有效但退步**是评价结果。两者不能合并成思想失败。
- **同父代**消除了起点代码差异，但没有自动消除任务实例、随机性、运行预算或复合修改差异。条件不同就分别标记；没有重复评价时也不编造显著性。

这两点是解释评价记录所需的逻辑约束，并非上述五篇论文在 AAD 中完成的验证。

## 可直接采用的最小上下文格式

以下是提示结构候选，不新增生成阶段。`[待填]` 仅表示从既有记录取值，不要求新增评分、自动思想分类或新模型。记录仍覆盖既定祖先路径和全部直接子代。

```text
任务与本次操作
目标、接口、约束、成绩方向：[待填]
已选算子：[精炼 / 探索 / 融合]
精炼：改进现有设计的实现与细节。
探索：在当前算法上引入新的算法思想。
融合：借鉴所给另一算法的思想，与当前设计结合。

祖先路径（按演化顺序）
每条：事件ID；起点→终点；算子；设计变化；修改说明；评价结果。
历史设计是已尝试方案，成绩仅描述记录中的实现与评价。

当前父代上的全部尝试（共享父代ID；按生成顺序）
评价条件：[任务实例/评价预算等既有条件；未知处明示未知]
每条：事件ID；算子；子代设计；实际修改；有效性；成绩与相对父代变化。
必要时附能区分改法的代码片段。

累积经验
每条：经验内容；源事件ID；原先算法结构及观察；借鉴时的适用前提。
经验与本次结构无关时可以不采用；重复转述不增加观察次数。

融合参考（仅融合时）
参考算法设计、完整代码与已知评价结果：[待填]

当前父代
设计、成绩与评价条件：[待填]
完整代码：[待填]

本次请求
结合形成过程和同起点尝试，提出本次算子下值得实现的候选。
区分记录中的结果与你对原因的解释；一次退步不排除整个思想。
若更简单的机制足够，可以采用它。
输出：短分析、候选设计、完整代码。
```

若已有融合提示必须将参考与父代按其他顺序组织，可先保持原顺序。当前证据不足以要求为末尾位置调整整个模板。上述段落布局是一种完整候选，不应拆成越来越多的强制提示规则。

### 最小输出格式

```text
分析：引用最影响本次修改的历史事件，比较其中的修改与反馈，
说明本次要解决的具体问题。原因不清楚时，直接说明哪个原因尚不清楚。

设计：写出候选的主要决策规则，以及准备怎样实现。
说明它与当前设计的变化；借鉴经验或融合对象时写清借鉴哪一部分。

代码：给出满足原接口的完整实现。
```

我保留短分析，是因为用户需要专家式接续开发和可核查的修改依据。论文尚未证明它对当前模型不可缺少。无需要求固定数量的引文、假设、替代方案、检查项；没有相应记录时也不应填充模板。历史中的设计说明应叫“候选设计”或“当时设计”，不要称为“已验证最佳策略”。

## 尚未检验、最可能改变下一步的关键点

**最优先的问题是：历史文字是否留下足够的实现差异，让模型正确比较同起点尝试。** 如果它只会复述“加了某机制后下降”，却看不到代码没有实现该机制，那么继续压缩或增加反思规则都解决不了问题。可先人工复查现有轨迹：文字是否准确描述真正修改、结论是否超出了记录。此处没有运行该复查或生成实验。

若之后授权模型比较，我会先固定父代、算子、历史事件、结果与经验，比较“文字修改记录”和“同样记录加必要代码差异”。需要同时记输入长度和成本，不能把额外源码带来的收益归于呈现形式本身。只有确认文字没有丢掉关键实现信息，才值得进一步比较纯代码、设计加代码、短分析加设计加代码。这里列的是后续可区分解释的候选检验，本次未执行。

另外两项未知量直接影响方案：

- 若模型把低分尝试反复解释为思想错误，问题在结果标签与归因；应修正记录措辞，先不增加失败经验禁令。
- 若模型能准确分析历史，却持续生成旧算法，问题更接近生成牵引；仅靠把分析写得更长未必改变行为。

这些研究尚未直接比较演化轨迹中的祖先与子代来源，也未验证全局经验是否会随复用而自我强化。为此，我只建议保留事件来源与适用结构；不据此新增全局置信度、经验投票或自动剔除机制。
