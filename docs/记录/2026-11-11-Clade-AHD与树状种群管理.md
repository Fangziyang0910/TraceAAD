# Clade-AHD 与树状种群管理

我认为可借鉴的是：用后代结果判断分支是否值得继续投入，并给新分支探索机会。它没有提供从60节点压至约30的结构压缩规则。

**事实。** [论文](https://arxiv.org/html/2602.00549v2)的动态冻结（IV-D）规则是：访问数达到下限，且子树期望表现低于全局最佳表现的一定比例，便停止扩展该分支。[作者固定提交源码](https://github.com/Mriya0306/Clade-AHD/tree/ffd566b70070331dbd2759a2cb828543e43da2ac)对应[本地 README](../../baselines/clade_ahd/README.md)；本地补了冻结递归中计数变量的作用域错误，以下按修复后的路径核对。

选择时，`get_clade_scores` 将各后代的信念均值按 `visits` 加权，再加入当前节点均值的伪观测，构成 Beta 分布并做汤普森采样（Thompson Sampling）；评价证据沿祖先路径衰减回传。因此节点自身成绩一般，仍可能因后代表现获得选择机会。`visits` 含回传与重复更新，不能当作独立评价次数。

冻结时，`prune_tree` 去掉伪观测，以后代的加权均值作比较；它排除节点自身，叶节点不会单独触发冻结，但会随祖先冻结。这是影响迁移的实现细节：依据并非子树最优成绩。冻结只递归设置 `is_frozen`，`select_clade_thompson` 过滤这些候选；节点、父子边和统计仍在，全候选冻结时还会回退选首项。它不删除、重连或压缩路径。

**对我们的建议。** 我会借用两条原则：按分支后续产出判断去留；积累一定探索机会后再淘汰，避免新方向刚出现便被旧方向压掉。实现可先用分支最佳后代、近期改进和实际尝试数，不必引入 Beta。均值可能掩盖少数优秀后代，因此淘汰前应检查是否仍含有要保留的活跃前沿。

分支去留与中间节点保留需分开决定。分叉锚点可按存活分支的最近共同祖先确定；里程碑仍要核对计算结构变化及其后续作用。子树表现只提供线索，不能指出哪次修改构成关键台阶。60→约30还需我们自己的锚点保留、路径收缩与经验整理规则。
