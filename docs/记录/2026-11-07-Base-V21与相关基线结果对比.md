# Base、V21 与六个相关基线的结果对比

读取时间：2026-11-07T11:42:35+08:00（北京时间）。本次只读取已有结果，没有启动搜索或重新评价。

## 问题与口径

我要比较当前正式 Base、V21 与方法理念相关的六个基线。运行只取 `experiments_result/primary_runs.json` 中的名单，六任务×三个独立搜索种子，共144路。Base 固定为 `20261105_base_co6`，V21固定为 `20261105c_v21_co6`。统计单位是独立搜索，不把50个测试实例当作50次搜索。

成绩取训练最优程序的原主测试，即 `heldout.json` 中 variant 为空的记录。所有目标越小越好，OP使用负奖励。均值只聚合成功测试，部分成功单元格明确标注有效路数，不用放宽时限补测替代失败，也不对部分成功结果计算总排名。143份已有主测试通过当前读取器 `heldout_identity` 的程序身份核验；另1路没有主测试。

## 失败与缺失

所有144路搜索的status均为finished，budget_used均为1000。主测试137成功、6超时、1缺失。

- DeltaEvolve：JSSP种子2平均函数CPU 10.7899秒，超过10秒；其余17路成功。
- RefineEvo：图着色种子0平均函数CPU 10.2118秒，超过10秒；其余17路成功。
- MCTS-AHD：图着色种子0、2分别11.116秒、12.3083秒，超过10秒；16路成功。

- Base、V21、PathWise、Clade-AHD：各18路主测试成功。

## 比较条件与判断边界

18对Base与V21配置的budget、method_params、task_definition、task_eval、evaluation_execution以及共同采样字段逐项一致。Schema输出顺序为方法差异。二者每路1000次评价，训练16实例共享160秒墙钟，测试50实例共享500秒墙钟；temperature=1.0，max_tokens=16384。这个对照支持整套上下文、算子指令与输出顺序的效果，不能单独分离祖先信息的因果贡献。

历史基线每路1000次生成回复，解析失败等同样消耗生成预算；实际评价次数不等于1000。基线采用每实例120秒墙钟，并约束平均函数CPU（TSP/CVRP/FSSP/OP 2秒，图着色/JSSP 10秒）；temperature=0.7，max_tokens为8192或16384。模型配置包含AWQ和GGUF等不同部署记录。ReEvo的JSSP种子1原主记录另采用11秒平均函数CPU限制，不能默认为全体统一10秒。这些是实际条件差异，不能把跨方法成绩差距全部解释为机制效果。

本次为每任务三路的描述性比较，报告均值、样本标准差与单路结果，没有进行显著性检验。

## 认识

目前最清楚的优势是V21在TSP上减少差运行，并在OP上得到更高、波动更小的平均奖励。FSSP已与最好的相关基线非常接近。CVRP和JSSP分别存在MCTS-AHD、Clade-AHD的更好均值，因此不能把当前结果概括为上下文方法普遍优于树选择方法。基线与本方法的执行条件尚未对齐，不能据此判定轨迹上下文与预算分配哪个机制更有效。
