# 从轨迹表征到未来搜索收益预测

北京时间2026年11月3日。研究讨论与原文核对；没有修改在线算法、训练预测器或启动新实验。

## 我修正了什么

用户明确要求：价值判断与反思分开。即使需要LLM判断，也不放进反思调用；更应充分利用可以程序计算的数值、结构和文本特征。轨迹的斜率、波动、极值、代码变化、设计相似性都可以作为预测输入，不必先给每个特征一个确定的机制解释。

我此前把“单个指标不能证明未来潜力”过多地转成了“只使用能直接解释的指标”。这限制了表示。更合理的问题是：**在给定算子、后续开发方式和预算下，什么轨迹表示能预测后续搜索收益？** 指标负责描述状态，统计模型负责组合证据，价值函数负责将预测转成选择依据。

主线是：轨迹 → 可计算表示 → 条件结果分布 → 预算内价值。反思继续提炼算法经验，不增加评分任务。现有design/analysis可以由独立编码器处理，编码器前向计算和统计模型预测不需要新增生成式LLM判断。

## 先确定预测对象

我建议预测：从节点p出发，以某种方式o启动后续开发，在额外预算b内获得的最好结果。节点价值不等于当前程序的静态性能，也不等于平均子代性能。

统一fitness越小越好。设当前全局最好为f*，额外预算内有效程序的最好fitness为Z；没有有效新结果时令Z=f*。一个可检验的价值定义是：

\[
V(p,o;b)=\frac{1}{b}\mathbb E[(f^*-Z_{p,o,b}^{\pi})_+\mid \phi(\tau_t(p)),o,b,\pi],
\]

其中π规定第一步之后如何继续开发，b必须使用固定的成本单位。若所有节点比较同一个b，分母可以省略。这是期望改进（expected improvement, EI）思想在开发过程上的应用建议，不是已经证明最优的预算分配公式。标准EI以未知候选超过已知最好的期望增益作为采集值，见[Frazier，§4.1](https://arxiv.org/html/1807.02811)。

精炼价值对应以Refine开始的开发；拓展价值对应以Explore或Crossover开始、之后允许精炼的开发。两者可以使用同一预算尺度，区别由操作条件与数据体现，不预设“精炼只看一步、拓展看多步”。融合还要条件化参考对象，或明确参考选择策略；单节点通用拓展值只能对该策略取平均。

把未来结果建成分布，才能同时得到：超过当前最好的概率、超过的幅度、兑现需要的预算、预测的不确定性。只预测平均子代分数，会压低偶尔产生优秀算法的分支。单步收益分布也不能直接当作多步最好收益分布；后续程序和生成条件会变化，不能未经验证就按独立同分布重复抽样外推。

## 轨迹需要两个视角

祖先链记录连续变换；同父代子代记录从相同起点出发的不同结果。两者分别提取序列特征与响应分布特征，再合并。兄弟节点不能当成前后相继的优化步骤。

祖先链以局部代数表示结构变化；单位成本趋势需要额外连接实际调用/评价记录，包含失败和修复。全局Program ID间隔、墙钟等待时间都不能替代这条方向实际得到的开发量。主链只有最多8个祖先时，不为每个节点单独拟合高自由度时间序列；用全局历史共享预测规律。

同时保留原始质量序列和局部best-so-far序列：前者显示退步、波动与恢复，后者显示已获得的最好结果。best-so-far单调并不代表程序质量单调，更不保证收益递减。

## 可计算特征：先建立候选库，再按预测贡献压缩

为避免跨任务量纲与动态排名混淆，可使用同一评价条件内、仅从过去数据获得的固定尺度s>0，定义q=-f/s；也保留原始fitness。不能把历史排名随档案变化的漂移解释为程序改善。

| 维度 | 可计算特征 | 联合使用时回答的问题 |
| --- | --- | --- |
| 当前水平 | 当前q、与当前全局最好的差距、与自身路径最好的差距 | 值得预测的改进还需跨过多大距离？ |
| 趋势 | 2/4/8步窗口的稳健斜率、短长窗口斜率差、改善符号序列、连续持平长度 | 最近还在改善、减速，还是转向？ |
| 波动与退步 | 去趋势残差的MAD、上下行半方差、极差、最大回撤、回到前高所需步数 | 改进平稳，还是频繁破坏后再恢复？ |
| 突破节奏 | 距上次有效突破的开发次数、突破间隔、少数跃升占总收益的比例、局部变点分数 | 收益来自持续小步还是偶发跳跃？ |
| 子代响应 | 按算子的有效率、重复率、正增益概率、增益分位数、上尾增益、失败类型 | 哪种修改有机会产生好结果，代价多大？ |
| 代码结构 | AST节点类型分布、深度、循环/分支/调用结构、圈复杂度、返回值反向依赖范围 | 当前结构属于什么区域，修改会影响哪里？ |
| 代码变化 | 规范化AST重复、保留常数与抽象常数的两层比较、树编辑动作、数据流变化、祖先回退 | 改的是参数、结构、输出依赖，还是重复旧程序？ |
| 文本语义 | design/analysis分别嵌入；相邻距离、到祖先/已有子代/历史档案的距离、方向变化 | 设计在延续、转向还是复述已有尝试？ |
| 探索覆盖 | 子代修改的相似度矩阵、聚类占比熵、核矩阵有效秩、历史近邻密度 | 已尝试的是许多不同改法，还是同一方向的重复？ |
| 跨字段关系 | 文本变化与代码变化的组合；代码距离与收益的关系；结构变化与超时的关系 | 何种幅度和类型的改动，在这类起点上更有用？ |
| 成本与版本 | 生成/修复调用成本、评价耗时、超时比例、模型/提示/评价条件版本 | 收益是否可兑现，哪些历史样本可借鉴？ |

这些是候选预测特征，不是为每项指定一个“越大越好”的价值分量。极值与上尾统计需同时提供样本数；失败不以无穷差分数加入均值或方差，单独保留状态和成本。子代差异反映生成结果的离散性，不能直接当成模型对价值估计的认知不确定性。

### 几个比均值更有用、仍可直接计算的构造

**多尺度稳健趋势。** 对窗口w内的有效观测，以局部代数或明确的累计开发成本a为横轴：

\[
\beta_w=\operatorname{median}_{i<j}\frac{q_j-q_i}{a_j-a_i}.
\]

这是成对斜率的稳健汇总。短长窗口斜率差提供近期速度变化的信息；不把它解释成已识别的真实二阶动力学。窗口不足时保留缺失标志和长度，而非填成零趋势。

**表征空间里的有效多样性。** 对已有子代改动表示u构造归一化、半正定的相似度核矩阵K，例如固定带宽的RBF核：

\[
D_{\mathrm{eff}}=\frac{(\operatorname{tr}K)^2}{\operatorname{tr}(K^2)}.
\]

所有表示相同时为1；相互近乎不相似时接近子代数。它衡量在所选表示下的有效方向数，不是独立统计样本数。可用它区分“十次近似重复”与“十次不同结构改动”，再结合结果判断探索覆盖。带宽和表示必须固定或仅用过去数据选择。

**联合变化。** 对每条已观察边保留向量(代码距离，设计距离，分析距离，归一化增益，状态，成本)，而非先合并成一个相似度。模型可以学习“结构小改＋持续改善”“文字大改＋源码不变”“结构大改＋频繁失效”等关系。跨字段变化不一致只是待解释特征，不能自动判定描述错误。

**局部响应面。** 在相似开发状态间共享样本，估计算子、历史编辑幅度与收益分布的关系。它比“某算子过去平均收益”更接近当前问题。选择时尚不知道未来子代的源码距离，所以只能使用历史编辑分布；实际新子代的距离用于事后训练，不能泄漏进生成前预测。

## 文本与代码相似度怎样使用

[Sentence-BERT](https://aclanthology.org/D19-1410/)提供可用余弦比较的句向量。对我们，可分别编码design与analysis，计算相邻相似度、到历史优质/失败尝试的距离、局部密度与语义转向。这些量表征文本所描述的设计关系，不等于真实执行行为，也不自动表明设计正确。将相似性用于寻找可借鉴的历史结果，比直接把“不相似”奖励为高价值更合理。

代码比较可以分层：

1. 规范化token与AST：便宜地识别复制、改名、常数修改、结构变化。语义敏感的常数和比较运算必须保留在至少一个视图中。
2. 树编辑与子树模式：[GumTree](https://github.com/GumTreeDiff/gumtree)可识别与语法对齐的插入、删除、更新和移动；[Weisfeiler–Lehman图核](https://www.jmlr.org/papers/v12/shervashidze11a.html)提供比较局部结构模式的方法。图核本身不是程序语义判定器。
3. 数据流与返回依赖：[CodeBLEU](https://arxiv.org/html/2009.10297v2)将token、AST与数据流匹配分开；我们更适合保留这些分量，再由未来收益任务学习如何使用它们。静态切片可强调与返回值相关的变化；动态语言别名、库函数与反射会限制静态覆盖，需要保留未知，而非声称所有死计算都能检出。
4. 预训练代码表示：[GraphCodeBERT](https://arxiv.org/abs/2009.08366)通过数据流学习代码表示，可作为额外语义视图。其相似性仍需用我们的后续收益校准。

[BehaveSim](https://arxiv.org/html/2603.02787v1)比较的是执行时的中间解轨迹，不是本项目的程序演化树。它需要相应运行记录，不能由AST静态还原；这不妨碍先使用静态结构与文本作为预测代理。

## 最值得借鉴的方法，以及我们实际借什么

| 原工作 | 原方法实际做什么 | 我们可迁移的部分 |
| --- | --- | --- |
| [Freeze-Thaw BO](https://arxiv.org/abs/1406.3896) | 用部分训练曲线决定暂停、恢复或启动训练 | 将继续投入视为可比较的预测问题，而非按当前分数淘汰 |
| [DyHPO，§3.2–3.3](https://arxiv.org/html/2202.09774) | GP的深核联合输入配置、已有曲线和预算，预测下一预算处结果 | 当前算法表示＋历史动态＋未来预算共同建模；其原实验是HPO，不是程序树 |
| [ifBO](https://proceedings.mlr.press/v235/rakotoarison24a.html) | 使用预训练的FT-PFN作为freeze-thaw代理 | 跨曲线共享预测规律可降低逐节点拟合需求；训练曲线先验需适配AAD |
| [catch22](https://link.springer.com/article/10.1007/s10618-019-00647-x) | 从大量时间序列统计中筛选有预测力、较少冗余的特征 | 建立丰富候选库后按目标筛选；不把其22项照搬到8步短链 |
| [LLaMEA-SAGE，§3](https://arxiv.org/html/2601.21511) | 从AST及复杂度提取特征，用梯度提升树预测性能并产生结构修改提示 | 静态代码特征可以参与统计预测；其目标是当前性能/生成指导，我们改为后续收益 |
| [DGS，§3](https://arxiv.org/html/2607.13911v1) | 在生成前预测算子—父代动作引起的子代表示分布，再估计效用 | 预测对象应是后续生成结果，而非仅当前程序；不必直接照搬双代理结构 |
| [Quantile Regression Forests](https://www.jmlr.org/papers/v7/meinshausen06a.html) | 从高维特征估计条件分布与分位数 | 学习非线性交互与上尾机会，避免只拟合平均分 |
| [Extreme Bandits，§2–3](https://misovalko.github.io/publications/carpentier2014extreme.pdf) | 以预算内最大观测值为目标分配采样，而非最大化平均奖励 | 借鉴“最好结果”的目标；不能移植独立同分布和Pareto重尾假设 |

这些文献分别提供表示、预测与选择的方法依据；它们没有直接验证本项目提出的联合轨迹价值。上述迁移都是本次设计建议。

尤其要区分两个问题：学习曲线外推关心继续投入的结果；代码距离和可演化性描述当前起点周围的结果分布。程序演化会发生机制跳变，固定节点也可能受生成上下文变化影响，所以不能默认每条曲线平滑、单调或凹。变点检测/状态空间模型可用来处理阶段变化，但短链需要全局共享；它们是候选方法，不是必须增加的模块。

## 我建议首先收敛到的模型

第一版考虑“多尺度过程特征＋静态代码/文本关系＋算子/预算条件”的共享分布预测器。分位数森林或支持分位数损失的提升树是直接候选；多视图核GP是强调相似状态共享与概率建模的竞争方案。它们都独立于反思调用。

森林擅长非线性交互，但未经过校准的分位数不等于可信置信区间，经验分布也不擅长外推从未见过的极端收益。GP/曲线模型提供另一种外推先验，但先验不匹配会偏。应围绕同一个未来收益目标比较，而非因模型更复杂就认定更好。高不确定性是否值得探索属于分配策略；不能把结果波动直接当成探索奖励。

数据组织为“当时已知的轨迹前缀→随后真实观察到的结果”。固定评价条件与生成策略，按整路/时间划分，防止重叠祖先、同一后续结果或近重复代码泄漏。未继续开发是反馈缺失，不是零收益；只有已花费预算且未改进才是零。较长预测期限需要有实际接续的样本，不能把无关后代或任意子树最好值当成同一政策下的结果。

先回答一个最小问题：在相同前缀和预测期限上，演化过程是否在当前程序信息之外，额外帮助预测未来突破概率和幅度。比较需要三层输入：当前fitness；当前fitness加当前code/design；再增加祖先与已有子代的过程特征。只与fitness比较，不能区分静态代码表征和轨迹各自的作用。模型选型与特征压缩由这一结果决定，再检验在线预算分配。若要估计新策略相对旧策略的收益，历史选择造成的反馈缺失还需要另外处理，不能由预测拟合成绩替代。

本地已有[V15斜率投影脚本](../../experiments_result/analysis/v15_20261027/slope_projection.py)与[V19.4早期共享状态预测记录](../../experiments_result/analysis/v19_4_design_20261101/README.md)。本次只读其计算对象与验证边界，没有复跑、引用旧数值作当前结论，也没有把旧原型直接复用为定案。

并行原文检索补充了可演化性、自适应算子选择、共享情境模型与反馈缺失的相关依据，见[文献补充](2026-11-03-轨迹价值预测文献补充.md)。我另外核对了Extreme Bandits原文§2–3：有限预算中的最好值与平均奖励确实是不同目标，其尾部算法的分布假设也明确不适合直接移植到当前分支演化。

## 讨论推进：信用归属、预测目标与下一项检验

用户进一步问下一步及尚未考虑的问题。我认为当前最重要的未知量是：过程信息是否在当前代码与fitness之外提供了可用于选择的增量。存在候选算法与理论借鉴，仍不等于本项目的轨迹表示已经有效。以下是待检验的判断，不是已确认的新机制；不据此修改方法正文或WWH。

第一，预测未来收益与追溯历史贡献是两件事。第一版可以把固定预算接续的结果关联到起始的节点、首步算子及其上下文，用于学习这种开发动作的价值。它不证明某个祖先对成功有多少因果贡献。一个终点结果可以为多个前缀提供有关未来的信息，但不能将其作为多份独立成功，重复扩大同一谱系的预算权重。融合应记录双方及参考选择规则；单节点拓展价值取决于具体的融合对象分布，不能自动把探索和融合的收益看作同一分布。

第二，兑现期限尚未确定。只预测下一次评价超过全局最好，可能再次淘汰需要先实现、再精炼的设计。相同续跑设置短、长两个预算检查点，可以检查候选排序是否随期限变化；短期无法突破不能作为长程价值为零的标签。短期与长期排名不一致也是[DyHPO](https://arxiv.org/html/2202.09774)处理的原问题之一，但这里是否存在可预测的排序变化需要新证据。

第三，程序树本身不是完整的开发账本。解析失败、无效程序、重复源码、修复与接口失败可能不产生新节点，仍需连接尝试记录，按所选预算单位保留成本和状态。祖先链经过选择，不是所有尝试的时间顺序；链上的上升趋势不能直接解释成同一个起点越来越容易改进。历史分支获得的机会也不同，多子代和高极值可能只是更多投入的结果。[Dudík等](https://icml.cc/2011/papers/554_icmlpaper.pdf)讨论的部分反馈与策略差异提示了历史评估的这一困难；其单步估计不能直接校正整树演化。

第四，价值依赖生成条件。模型、提示、经验池、融合参考和后续接续规则都可能改变同一程序的后续结果。第一项检验固定起始生成条件与后续更新规则，并保存实际上下文；如果经验池在接续中更新，各重复使用独立副本，不能相互污染。先在同一任务与同一条件内学习，检验成立后再问跨任务、跨生成器共享是否有效。

第五，期望改进还没有给出完整分配策略。在此处按局部分支终点定义的收益，尚未完整计入一次试验对其他分支判断和全局经验的帮助。结果波动也不等于预测不确定性。初版可保持算子固定比例，在每个算子内比较节点，保留少量随机探索以获得新节点反馈；暂不追加人工新颖性奖励或祖先折扣规则。当前方法将两种价值的时间尺度写得过于确定，尤其“同一种价值下兑现时间相同”不能由算子标签保证，应当作为待修正表述，不先行改成另一套机制。

我建议下一项工作是小规模等预算续跑检验：从相同任务的冻结搜索快照中取当前成绩接近、演化经历不同的候选；固定生成条件、接续规则与融合对象选择规则，对每个候选重复续跑，成本包含该预算定义下的失败和修复，并观察短、长两个检查点。用上述三层输入分别预测，训练与验证按独立运行隔离。首先看轨迹模型选出的前列节点在相同后续预算下是否得到更好的程序，以及相对当前状态模型是否有增量。总体拟合误差只是辅助指标。历史数据可用于整理特征与预训练，不能用未经对齐的历史子树最好值充当这项检验的可比结果。

本轮只补充研究记录；尚未采样新接续、训练预测器或启动在线实验。
