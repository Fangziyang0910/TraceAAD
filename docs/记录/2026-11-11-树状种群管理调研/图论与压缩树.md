# 图论与压缩树

2026-11-11（北京时间）。依据两份当前设计文档与本次任务约束核对；60→约30、30–50范围及具体选择算法均作为候选。

**最值得借用的是虚树（virtual tree）的保拓扑压缩，其次是带局部约束的树背包（tree knapsack）动态规划（dynamic programming，DP）。** 核心问题是：在保留节点的容量内，选择有后续搜索价值的算法，同时支付分叉与方向边界的结构开销。固定端点后的连接并不难；价值选择、结构开销与经验损失才是难点。活跃前沿只是优先保留集合，内部可行节点仍可作父代。以下适配推导是本次分析，不是原论文对自动算法设计（Automated Algorithm Design，AAD）的结论。

斯坦纳树（Steiner tree）在给定图中连接指定终端，并最小化连接代价；有根版本（rooted）要求指定根出现，不能把“有根”直接等同于“有向图”。带奖惩版本（prize-collecting）允许放弃节点，最小化连接成本加未覆盖节点的罚值；预算版本（budgeted）则在成本上限内最大化所获奖励。[Bateni等，§1–2](https://arxiv.org/pdf/1304.7530)

**给定树且端点固定时，最小连接子树就是端点间唯一路径的并集。** 反复删除非端点叶节点，每条边至多处理一次，即可在线性时间得到；要求保留根时，把根也作为端点。这是树上路径唯一性的直接推导。[Diestel，Theorem 1.5.1](https://www.math.uni-hamburg.de/home/diestel/books/graph.theory/preview/Ch1.pdf) 无须调用一般图的Steiner近似算法。这里仍包含路径上全部节点。我们允许删除中间祖先并重连，因此计费对象变成压缩后节点，原路径长度不再等于容量成本。

最直接对应的是虚树：对选定节点集加入最近共同祖先（lowest common ancestor，LCA），形成LCA闭包（LCA closure），再压掉其余路径内部节点。KTH官方库的实现按深度优先遍历顺序排序，仅加入相邻端点的LCA，去重后重连；常数时间LCA查询的预处理完成后，构造耗时为O(k log k)。它处理的是给定端点后的结构，不判断哪些算法值得保留。[Lindholm，CompressTree.h](https://github.com/kth-competitive-programming/kactl/blob/main/content/graph/CompressTree.h)

令前沿F有k≥1个节点，A是闭包中新加入、原先不在F中的LCA，则|A|≤k−1，总节点数≤2k−1。[同一源码](https://github.com/kth-competitive-programming/kactl/blob/main/content/graph/CompressTree.h) 这个界不要求F是叶集或互不为祖先：若u是v的祖先，LCA(u,v)=u，无须新增锚点。更紧的计数解释是：压缩树的叶子都来自F；若叶数为ℓ，每个新增锚点至少有两个存活子分支，因此新增数≤ℓ−1≤k−1。额外强制保留的原根、里程碑与方向边界不属于这项新增LCA界；虚拟根若不占容量，应单独扣除。

**Explore边界可能比LCA消耗更多容量。** 若“不跨Explore”要求保留原单步边界，那么保留后代通往根的路径上，每条Explore边的两个端点都必须保留。例如A→B为Refine，B→C为Explore，C→D为Refine；只保留A、D不能直接重连，B、C仍须留下。即使F只有一个节点，连续Explore链也可能保留很多节点，开销无法仅用k限制。若允许迁移边界或把多次方向变化写成一条边，则是另一种语义，不能默认允许。

因此，设S包含价值选择产生的前沿和里程碑，B(S)为其根路径上Explore边的端点，r为虚拟根，实际保留集合应按候选规则计算为：

K = LCA闭包(S ∪ B(S) ∪ {r})，容量 = |K \ {r}|。

各角色重合时只计一次。新增候选可能共享已有锚点，也可能触发新锚点和边界开销。应在选择过程中核算这个增量；“先选一半容量的前沿”本身不保证闭包、边界、里程碑合起来装得下。交叉参考另存，不作为第二条树边加入此计算；上述性质针对主父代树。

带预算的节点加权（node-weighted）Steiner提供了“价值与成本一起选择”的目标，但原方法仍为所用连接节点付费；其有根近似算法还允许一定预算超限，不能直接继承为我们的硬容量保证。奖惩形式中的罚系数也不自动对应某个准确节点数。[Bateni等，§3.1，Lemma 3与Theorem 3](https://arxiv.org/pdf/1304.7530) 我们可借它区分价值、容量、删除损失的方式，不能直接套用原算法保证。

经典树背包要求选中节点时也选中它到根的全部祖先，Cho与Shaw给出Θ(nH)的伪多项式（pseudo-polynomial）算法，成本与容量H取整数。这个祖先闭包条件与允许跳过中间节点不同。[原论文摘要](https://pubsonline.informs.org/doi/10.1287/ijoc.9.4.431) 更有用的是按子树合并容量的DP方法；Kumabe等研究可由树自动机（tree automaton）表达的约束，明确使用可加节点奖励、可加成本，并分析状态转移复杂度。[§2.1–3](https://arxiv.org/pdf/1807.04942)

据此可推导一个适配起点：先仅考虑LCA与Explore约束，按“子树空／根保留／根跳过”及已用容量存状态。若跳过u，u的原始子节点中，最多一个的子树含保留节点，否则u应是保留的分叉锚点；若Explore边下方仍有保留节点，就强制留下两端。节点成本取1，子树逐个合并预算，可得到常数种状态下O(nH²)的候选递推。这里奖励应覆盖所有保留算法，锚点同样可作父代。

这项推导要求节点分数在本轮固定且可加，约束能局部表达。跨分支代码互补、多样性，以及凝练经验的效果若依赖整个集合，就不能直接相加。把同一后代收益重复计入多个祖先也会夸大价值。加入这些因素后，简单DP不再保证完整设计的最优；节点数有限并不能弥补目标失真。

重链剖分（heavy-light decomposition，HLD）按子树规模划分路径，使根路径只经过O(log n)段；它保留整棵树，用于加速操作，不选择有价值的算法。[Sleator与Tarjan，§3 Lemma 1及§5](https://www.cs.cmu.edu/~sleator/papers/dynamic-trees.pdf) Kumabe等也把它用于加速已定义目标下的DP，价值来自奖励函数。当前几十个节点的批量重构中，它的优先级低于直接遍历。

**优先建议两项：先借虚树维护精确分叉关系，并显式计入Explore边界；再在价值可加的简化模型中借树DP联合选择节点与结构。** 前者直接匹配路径收缩，后者用于检验容量分配，均不预设当前参数已定。

最能判别第一项适配是否成立的问题是：**Crossover需要原树中精确的LCA及该节点经验，还是可追溯的分化摘要就足够？** 前者支持支付LCA锚点开销；后者意味着闭包可能保留了不必要的算法节点，应先明确这项信息需求。
