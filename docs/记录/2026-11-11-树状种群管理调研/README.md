# 树状种群管理：可借鉴的方法与问题定义

调研日期：2026-11-11（北京时间）。本文记录文献核验与机制建议；具体取舍留在后续机制讨论中确定。

**最贴近当前任务的问题是：在有限容量下，持续选择有代表性的算法，并压缩它们的演化树，使后续搜索仍能使用关键的发展关系与试错经验。** 图论负责保留必要关系，种群选择负责保留有用算法，摘要方法负责处理被移除的信息。这三部分共同占用容量，也共同影响下一轮搜索。

## 1. 先把要解决的问题分清

当前树保存算法代码、评价结果、主父代关系与经验。达到容量上限后，重构需要回答三个问题：

| 问题 | 决定什么 | 可借鉴的方法 |
| --- | --- | --- |
| 哪些算法继续保留？ | 质量、多样性与有限的新方向机会 | 小生境、局部竞争、代表性覆盖 |
| 怎样连接保留的算法？ | 祖先关系、共同分叉与方向边界 | 虚树、LCA 闭包、谱系剪枝与单链收缩 |
| 哪些中间版本和经历值得留下？ | 阶段里程碑、路径经验与分支经验 | 树摘要、分段近似、按删点损失保留代表 |

前沿、分叉锚点与里程碑是保留理由，允许重叠。内部节点只要可行，仍可以被选为父代。因此，“前沿”不能直接写成叶节点，“内部节点”也不能直接写成历史遗迹。

这里有两个相互依赖的动作：选择保留算法会决定需要多少连接节点；连接节点的容量开销又会影响能保留多少算法。最合适的总体理解是**带容量约束的在线树摘要（online tree summarization）**。其中，“在线”表示树随搜索持续更新；每次重构仍可对当时几十个节点做一次完整计算。

## 2. Steiner Tree、LCA 闭包与轻重链剖分分别能做什么

斯坦纳树（Steiner Tree）研究连接指定终端的低成本网络。在一棵已有树上，节点间路径唯一。给定必须连接的节点，连接它们的最小子树就是这些路径的并；加入虚拟根后，也可以取根到各保留节点的路径并。这里无需在一般图中搜索其他连接路线。[树上唯一路径性质，Diestel §1.5](https://www.math.uni-hamburg.de/home/diestel/books/graph.theory/preview/Ch1.pdf)

接下来才是我们需要的压缩：保留指定节点与必要分叉，把中间没有保留理由的单链节点消去。这对应**虚树（virtual tree）或压缩的诱导子树**。最近共同祖先（lowest common ancestor, LCA）闭包让共同分叉显式留下；新边连接最近的保留祖先与后代，并代表原树中的一段路径。[KACTL 作者实现](https://github.com/kth-competitive-programming/kactl/blob/main/content/graph/CompressTree.h)

轻重链剖分（heavy-light decomposition, HLD）用于加速路径查询和更新。它按子树规模划分链，不判断算法质量，也不识别设计里程碑。[Sleator–Tarjan 原文，§3、§5](https://www.cs.cmu.edu/~sleator/papers/dynamic-trees.pdf) 当前几十个节点的规模，可以直接沿父指针求祖先并重构；需要的是虚树的结构规则。

**用户提出的图论方向很贴合，但最直接可迁移的是虚树与 LCA 闭包。** Steiner 的价值在于帮助看清“终端与连接节点”的分工；我们还需要决定终端是谁，以及哪些中间版本本身有价值。

### 容量应计算完整保留集合

令 $F$ 为希望继续开发的算法，$M$ 为额外保留的里程碑。令 $\operatorname{cl}_T(F\cup M)$ 表示加入虚拟根、必要 LCA 与必须显式保留的方向边界后的集合。实际约束应为：

$$
\left|\operatorname{cl}_T(F\cup M)\setminus\{r\}\right|\le B.
$$

这里 $r$ 是虚拟根，$B$ 是重构后的算法节点容量。这是对当前机制的形式化建议。

对 $k$ 个标记节点，额外 LCA 节点至多 $k-1$，标记节点互为祖先和后代时也成立；这个界帮助估计分叉开销，却不能替代总容量检查。[构造及数量界](https://github.com/kth-competitive-programming/kactl/blob/main/content/graph/CompressTree.h) 方向边界和额外里程碑还会占名额。选择一个新前沿时，应计算它实际增加了哪些节点；两个前沿也可能共享同一个锚点。前沿约占一半容量可以作为初始设置，最终数量应服从完整集合的预算。

例如 `A —Refine→ B —Explore→ C —Refine→ D`：若要求保留原来的单步方向边界，即使只想留下 A、D，也必须留下 B、C。连续的 Explore 边会产生额外开销，不能只按前沿数量估算。允许把方向变化改记到一条阶段边上，是另一种规则，需要单独确定。

## 3. 最值得优先借鉴的三组方法

### 3.1 数字进化中的谱系维护：操作与我们的树最接近

Phylotrack 记录出生、父代和死亡事件。其 Empirical 实现可剪除没有存活成员及存活后代的分支；开启单子节点压缩后，会删除无存活成员且只有一个孩子的中间节点，把孩子接到祖父上，删除前提供回调。[原论文](https://arxiv.org/pdf/2405.09389v2)、[作者实现](https://github.com/devosoft/Empirical/blob/56d1679efa31bb27e013e7910afdd7b94b1587cc/include/emp/Evolve/Systematics.hpp#L1431)

迁移到 EvoTrace 的顺序很明确：先决定淘汰哪些个体，再剪掉不含保留后代的旁支，压缩连接保留节点的单链，并在删除前整理经历。这里的适配是让压缩后的节点和边携带可供后续生成使用的经验。

这组方法直接提供结构操作。分叉由保留后代决定；里程碑由我们额外标记。没有必要再给每个中间节点设计一个复杂的拓扑重要性分数。

### 3.2 小生境与代表性选择：解决名额被相似算法占满的问题

PartEvo 用代码相似度或设计描述嵌入构造特征，再通过聚类建立小生境，使不同区域保有搜索机会。其代码相似度结合 CodeBLEU 的语法与数据流匹配；它没有用谱系距离充当计算差异。[NeurIPS 原论文，§3.2、附录 E](https://proceedings.neurips.cc/paper_files/paper/2025/file/e389b15166cf98966ba058965a8c17e3-Paper-Conference.pdf)

对我们最有用的是“相近算法局部竞争，不同算法保留机会”。可以使用局部分组，也可以直接用代表性覆盖选择前沿。先从一种简单规则开始即可。

需要分开三个概念：树的分支记录**来源**；代码或行为特征描述**当前差异**；阶段保留依据衡量**删去版本会损失什么**。两个不同来源的分支可能已经生成相似算法，同一分支也可能发生明显的计算变化。用于竞争的分组因此无需改写主父代关系。

新方向获得有限评价机会，可以借鉴年龄分层种群 ALPS 对年轻遗传材料的保护原则。我们的 `Explore` 仍来源于既有父代，把它视为全新起点是另需定义的规则。第一版可以只设置有上限的尝试保护，不必引入完整年龄分层。[ALPS 原论文](https://www.cs.york.ac.uk/rts/docs/GECCO_2006/docs/p815.pdf)

### 3.3 树摘要与分段近似：决定哪些内容值得占一个名额

加权树摘要 kWTS 直接研究：从带权层次树中选取少量代表节点，覆盖重要内容。论文用每个目标节点获得的最大代表作用构造总覆盖分数，给出贪心与动态规划算法。[原论文，§III、V–VI](https://arxiv.org/html/2008.03053v2)

它提供的启发是：**评价一组节点对整体内容的代表能力，而非只把单节点分数排一次序。** 但原论文的树是概念层次树，祖先表示更一般的概念。我们的祖先是较早的算法版本，未必能代表后代的计算方式。因此应迁移选择框架，重新定义代表关系。

沿单条路径，折线简化与序列分段也提供相同的思路：给定保留点数，最小化近似损失；或者给定损失上限，尽量少留点。CGAL 将删点代价、拓扑约束与停止条件分开实现，用户可以自定义代价。[Imai–Iri 原作摘要](https://doi.org/10.1016/B978-0-444-70467-2.50011-4)、[CGAL 官方手册](https://doc.cgal.org/latest/Polyline_simplification_2/index.html)

这使阶段压缩问题变得具体：删去某个中间版本后，两端算法和阶段经验是否足以交代关键修改、评价与失败条件？先明确这类损失，再决定按损失排序保留，还是用区间代价的动态规划。

最新[机制文档](../../树状种群与反思简化.md)进一步把里程碑的代码保留理由收束为“仍值得作为出发点”。据此，经验摘要与完整算法节点应分别判断：记录一项重要修改，可以由经验承担；若要从该版本继续生成、重组或作为阶段比较基准，才需要为其完整代码保留名额。几何转折只适合提出候选。

## 4. 对当前机制最有影响的两项修正

**“质量加最小差异”的贪心规则，应按启发式描述。** 子模覆盖（submodular coverage）需要一个明确的集合目标及边际收益。固定非负权重与相似度时，例如设施选址式覆盖

$$
G(S)=\sum_{x\in U}w_x\max_{v\in S}s(x,v),\qquad w_x\ge0,\;s(x,v)\ge0,
$$

具有边际收益递减的性质：相似内容已有较好代表，再加一个相近代表的作用会减小。空集的覆盖约定为零；$U$ 表示待代表的对象，$s$ 表示候选的代表程度。覆盖关注候选补充了什么，单纯远离已选算法却可能只保留一个孤立异常程序。原论文将设施选址用于摘要覆盖，并提出达到阈值后不再增加奖励的饱和覆盖，后者也适合启发经历去重。[Lin–Bilmes，§4](https://aclanthology.org/P11-1052.pdf)

单纯按“候选质量 × 与已选集合的最小距离”排序，尚不能自动获得上述性质。即使采用覆盖目标，加入 LCA 开销和方向限制后，也需要重新分析约束，不能直接沿用纯节点数量约束下的近似保证。覆盖对象也要明确：如果直接按历史节点数量计权，一个方向反复生成近似算法，会仅凭数量获得过高权重。

**“离两端都远”与“阶段发生转折”需要区分。** 一条直线上的中点也可以离两端很远。Douglas–Peucker 类几何方法关心被原路径偏离替代线段的程度；算法里程碑则还需要对应有意义的计算变化。当前 AST 结构距离可以作为候选差异特征，但数值常数被忽略时，一个改变决策阈值或搜索强度的修改也可能得到很小的距离。需要检验的是特征是否保留了当前任务关心的变化。

调研期间，[管理文档](../../树状种群管理.md)已新增拓扑实现与 Base 日志回放记录。我读取了当前 [topology.py](../../../evotrace_v1/topology.py)：前沿使用质量与最小 AST 距离的乘法规则；里程碑使用到两端的距离最小值。上述两项修正针对这些规则的解释与待检验含义，本轮没有修改它们。

## 5. 树动态规划放在什么位置

树背包（tree knapsack）提供按子树分配容量的办法。经典祖先闭包版本要求选中节点时保留整条祖先链，与我们的路径收缩不同。更一般的树约束动态规划允许局部状态表达保留与连接规则，前提是本轮节点奖励、成本可加，约束可由这些状态判断。[Kumabe 等原论文](https://arxiv.org/abs/1807.04942)

它适合在一个简化目标下联合选择算法与锚点，检查手工配额是否损失了较好的组合。如果质量、多样性和经验价值依赖跨分支的整个选集，就需要扩充模型，不能直接沿用简单树 DP。当前优先明确目标与保留规则，DP 可作为之后求解该目标的工具。

## 6. 建议收敛到的最小方案

1. 在双水位线触发时，依据质量与一种明确的差异表示，选择希望保留的算法；新方向只获得有限保护。
2. 补齐 LCA 和必须保留的方向边界，按完整集合核算容量；超额时调整前沿，而非删除仍必需的连接节点。
3. 在剩余名额内保留少量代码仍有使用价值的里程碑；修改的重要性同时用于确定经验内容。暂时无法定义可靠删点损失时，不必强行使用几何拐点算法。
4. 对被移除区域做路径收缩与旁支剪除，并把相关经历凝练到新的边和保留节点上。原有经验也作为整理材料。

优先顺序是：**虚树与谱系压缩先确定结构规则；局部竞争或代表性覆盖确定算法选择；里程碑方法围绕代码使用价值与删点损失逐步设计。** 当前最值得继续确定的变量是“哪些计算差异必须留下”，它会同时影响前沿多样性和阶段划分。

节点容量与经验长度分别计费。节点数受限以后，长期重复凝练仍可能使经验文本增长；需要控制的是保留下来的事实及其表达长度。饱和覆盖可帮助定义重复内容的边际价值，不能单靠摘要文本变短判断信息已得到保留。具体模型见下面的代表性选择报告。

## 7. 进一步统一的候选更新规则

用户进一步要求减少独立规则，使流程更统一。我建议把每次更新收敛为：**所有可行算法共用一次质量与差异选择，树结构确定必要连接和移除区域，反思将这些区域的经历写回更新后的树。** 以下为候选调整，尚未替换当前实现。

### 合并算法选择

内部算法与叶节点进入同一个候选池。保留依据相同：算法质量，以及它相对已保留集合补充了什么计算方式。可以先沿用当前质量—差异启发式；进一步使用明确的集合目标时，可采用前文的代表性覆盖。评分的具体形式与“只进行一次算法选择”是两个可分别检验的决定。

| 现有环节 | 建议调整 |
| --- | --- |
| 先按衰减后代分数淘汰整个方向 | 让各方向中的算法直接参与选择，优质后代不受上游方向筛选阻挡 |
| 仅因后代成绩更好就排除祖先 | 祖先与后代一起按质量和差异竞争 |
| 前沿与里程碑使用不同评分、分别分配名额 | 合并为一次算法选择；内部版本被选中后可以充当阶段代表 |
| 固定前沿比例与同父兄弟名额 | 第一版不单独设置，用共同选择规则与总容量控制重复占位 |
| LCA 与方向边界保留 | 作为结构约束；它们也是可继续使用的算法节点 |
| 新生方向保护 | 保留为有限的探索约束，按累计实际尝试计数，不加入另一套潜力分数 |

### 把结构成本纳入同一次选择

尝试加入一个算法时，先计算它连同必要 LCA 与方向边界会新增多少节点，再判断是否符合总容量。已因结构原因留下的节点，也参与下一步质量与差异比较，避免把它们当作没有算法价值的空连接点。每次新增候选都更新整个保留集合，不预先划分“前沿占几成、里程碑占几成”。探索保护同样需要计入完整结构成本。

最终集合确定后，仍按原来的两种操作更新：路径中间的移除节点收缩成边，经历进入变异经验；没有保留后代的旁支被剪除，经历进入承接节点的选择经验。新增算法继续挂到这棵树上。

这种统一主要通过合并选择过程、减少独立筛选步骤实现。分叉锚点由连接关系决定；阶段代表由算法价值选择产生。结构保持与探索机会属于约束，不必全部揉进一个加权总分。
