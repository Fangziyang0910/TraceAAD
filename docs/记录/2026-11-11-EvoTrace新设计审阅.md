# EvoTrace 新设计审阅

**最新结果：Explore 的方向内经验截断已移除，两项回归测试及相关测试共61项通过。** 以下保留首轮审阅和复检依据，最终修复见文末。

我支持保留当前骨架：统一选择决定保留哪些算法与连接；父代采样决定下一次评价投向哪里；三个算子从同一棵树读取不同范围的信息。新增规则都有明确职责。当前最需要打通的是经验写入位置与算子读取范围，其次是交叉参考的硬过滤、消融定义和恢复协议。

本次审阅对照[机制文档](../树状种群与反思简化.md)、[反思设计](../反思简化设计.md)及 `evotrace_v1/` 当前实现。定向复现使用小型构造树、脚本模型与本地玩具评价函数，没有发起模型服务调用或基准任务搜索。

## 1. Explore 读不到部分已经保存的探索经验

当前 `context.py:_directions_overview_block` 读取虚拟根与 Init/Explore 起点的选择经验。旁支整理则将经验写给最近的保留祖先，该祖先可能是普通 Refine 节点。

我构造 `Init #1 → Refine #2 → Explore #3`，保留 #1、#2，剪除 #3。实际调用 `reflect_and_apply` 后，#3 的方向及评价记录进入 #2 的选择经验。随后生成的 Refine 上下文能读到它，Explore 上下文不能。这个缺口来自读取位置，与反思模型是否能写出好摘要无关。

因此，当前 Explore 能概览活跃方向，但不能完整利用被淘汰方向的经验。应让方向概览读取方向内部节点承接的相关经验；若这些节点随后被收缩，还要考虑转存到边上的经验。可以先补读取规则，继续复用已有两种经验。

## 2. AST 距离不适合作为交叉资格的硬判断

`allocation.py:select_crossover_reference` 会排除 AST 距离为零的参考。如果全部为零，抽中的 Crossover 会回退为 Refine。

我用 `return x / y` 与 `return y / x` 复现：两者的当前指纹距离为 0，参考选择返回空；即使算子先验全部设为 Crossover，实际仍执行 Refine。这两个公式的计算行为不同，问题来自指纹忽略了变量身份及其使用关系。

最大 AST 距离可以继续作为偏好，帮助选择结构不同的参考；距离为零不能据此判定参考没有可迁移的计算内容。最小修改是分开参考资格与距离排序，只在确实没有其他合格参考时回退。最大距离能否提升交叉效果，再由后续生成结果判断。

## 3. 当前经验开关比较了两种上下文表示

`context.py:_step_card` 在经验开启时展示边经验及后代设计；经验关闭时展示端点代码差分及评价变化。我用同一棵树、同一个父代渲染，确认关闭经验后新增了端点 diff，同时移除了 `Resulting design`。`search.py:finish` 还会停止调用反思模型，改用确定性摘要。

所以当前开关实际比较的是“凝练经验”和“端点差分”，与机制文档中的“两种经验留空”不同。若要检验经验的增量，应固定共同的端点信息、设计与评价，只切换经验文本。若要比较这两种表示，则可以保留当前规则，并将实验问题写清楚。自由运行后，两组生成结果不同，树也会随之不同；“相同树”的严格比较适合固定状态下的下一步生成实验。

## 4. 恢复配置和重构日志需要补齐

正常保存并恢复的构造运行中，完整树序列化结果相同，按下一次尝试编号生成随机流后的分配结果也相同。Base 已按每次尝试重新设定随机流。

我另外复现了两处缺陷：

- `evotrace_settings.json` 只在新建运行时写入，恢复时不校验。原运行使用 `lambda=10`、经验开启；恢复传入 `lambda=0`、经验关闭仍被接受，文件继续记录旧配置。`run_config.json` 同时仍记录 Base 的 `boltzmann_fitness_v1`，与实际 Shinka 式采样不符。应在重放前校验 EvoTrace 配置，并记录实际采样规则。
- `consolidations.jsonl` 没有沿用 Base 日志的半行修复。末尾残留半个 JSON 时，第一次恢复会忽略它；下一轮重构追加数据后，新记录会与半行粘连，随后恢复报 `JSONDecodeError`。应在读取和继续追加前处理不完整尾行。

## 修复后复检（2026-11-11）

我按用户要求重新检查四项发现。`uv run pytest -q tests/evotrace_v1 tests/experiments/test_traceaad_entry.py` 的59项测试通过。独立复现得到以下结论：

- **Explore 读取部分修复。** 首轮“只有一个普通节点承接淘汰经验”的例子已能读取。新实现按节点编号取方向内前两份选择经验；我让同一方向的 #1、#2、#3 分别承接一个被剪 Explore 子树，三份账本都存在，提示只展示 #1、#2，漏掉当前父代 #3 的新试错。对应 `context.py` 第297行的 `branch_ledgers[:2]`。只要前两个节点持续保留且有账本，后续节点的经验就可能长期进不了 Explore 上下文。
- **边经验仍有相同的读取边界。** `stage_notes[-1][:260]` 只展示编号最大节点入边经验的前260字符。我在同一方向的两条收缩边分别放置独立记录，较早边的记录没有进入提示。此前的经验没有自动汇总进后一条边，不能将最后一条边当作整个方向的经验摘要。
- **AST 零距离误拒已修复。** `x/y` 与 `y/x` 仍然距离为0，但已可互为参考，Crossover 不再因此回退。资格使用标准化源码判重，距离仅用于排序。
- **经验消融原问题已修复。** 经验开关两侧保持相同端点评价与后代设计，不再替换成另一套端点 diff。关闭展示后，反思策略仍执行；`Edge.contracted` 保留阶段边身份。
- **恢复协议原问题已修复。** 分别更改分配参数、上下文、容量、反思温度、反思开关、参考源码开关，均在重放前被拒绝，运行文件保持不变。日志半行在恢复时被清除；继续触发一次重构、再恢复，完整树一致。`run_config.json` 现在记录 `shinka_weighted_v1`。

当前需要继续处理的是 Explore 的经验取舍：最早两份账本与最后一条边并不代表整个方向的试错。可以保持已有两种经验，调整读取范围或按当前决策分配文本预算。该复检没有修改正式实现。

## 最终修复：完整读取展示方向内的经验

按用户要求，我采用最小修改：去掉 `branch_ledgers[:2]`、`stage_notes[-1]` 和260字符截断，逐条展示每个选中方向内的节点选择经验与内部边变异经验。节点经验标明节点编号，边经验标明父子端点。直接复用树上已凝练的文本，长度仍由原有反思阶段控制；展示方向数量沿用 `max_directions`。

我在[上下文测试](../../tests/evotrace_v1/test_context_and_search.py)中加入两项回归：同一方向三个节点各承接一份淘汰经验；两条阶段边各自保存超过260字符的经验。两个测试在修复前均失败，修复后通过，并检查经验关闭时不展示这些文本。`uv run pytest -q tests/evotrace_v1 tests/experiments/test_traceaad_entry.py` 共61项通过。

机制文档与模块说明已同步为“读取展示方向内全部节点与内部边经验”。
