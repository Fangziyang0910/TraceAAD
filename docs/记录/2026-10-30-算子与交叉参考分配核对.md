## 1. 我的判断

**当前最适合 Base 的起点是：有效父代上的质量×平滑直接改进经验，固定 Refine／Explore／Crossover 配比，以及质量门槛内去重、随机选择一个参考。暂不加入 LLM planner、思想分类器、每父代算子 bandit 或谱系距离最大化。** 固定配比沿用现有 0.45／0.30／0.25 即可；这些数不是已证明的最优值。先把成本和信用记对，比再增加一个控制器更有证据基础。

如果主任务确实要增加自适应，优先试**同一任务、同一独立运行内共享的三算子统计**，保留固定配比作为先验和探索保底。不要跨任务混合，不为每个父代／谱系分别建三臂统计。交叉参考首先解决“参考重复与档案数量偏置”，不要宣称已经识别机制互补。

本记录按给定目标接口讨论：每次生成返回 design 与完整 code；交叉参考仅展示 design／fitness；普通父代必须有效；历史窗口为 8 个祖先、3 个有效子代、2 个失败；全部模型调用计预算，每次生成最多一次 repair。**这属于本次设计约束，不是对当前磁盘代码已满足约束的断言。** 核对时 Base 的 `_reference` 仍输出参考代码，`attempts_shown` 与 `progress_shown` 默认均为 8，repair 可继承 design；本轮不改这些文件。[Base 提示:383–389](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/prompts.py:383)、[配置:10–28](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/config.py:10)、[生成:77–122](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/traceaad.py:77)。

## 2. 一手来源究竟实现了什么

以下“全局”均指一次搜索内部共享，**不是跨任务通用统计**。论文表述、作者解释和实际实现分开列。

### RefineEvo：全局算子摘要＋LLM 决策，不是父代条件 bandit

- **机制。** Planner 读取种群状态及各算子的历史，选择算子子集，并可重写算子提示。代码只用 `operator_id` 索引 `history['operator_performance']`，没有父代或谱系键。每次算子批量生成后汇总有效 offspring 的 mean／best／worst／std、有效率与数量。有效率的分母是返回的 offspring 数，不是所有内部模型请求数。[历史定义:43–47](/home/fang/code/LLM4AD/reference_code/RefineEvo/planner_interface.py:43)、[更新:474–512](/home/fang/code/LLM4AD/reference_code/RefineEvo/planner_interface.py:474)、[调用点:324–331](/home/fang/code/LLM4AD/reference_code/RefineEvo/evo_agent.py:324)。
- **论文／代码差异。** 论文称算子效用包含“超过父代的成功率”；所核代码 `success_rate=len(valid_objs)/len(offsprings)`，实际是**有效率**。绝对 offspring 均值还会受到父代质量和搜索阶段变化影响，不能等同算子净增益。这里不存在一个明确的标量 bandit reward。[方法:27–38](/home/fang/code/LLM4AD/papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/03_method.tex:27)。
- **冷启动与成本。** 算子提示是否需要改写至少需 3 条历史记录；随后默认再调用 LLM 判断，必要时另调用 LLM 改写。策略选择本身也调用 LLM，另有 Reflector／embedding。`get_offspring` 对解析错误、重复代码内部重试：解析失败分支检查第 5 次生成，重复另允许 3 次重试；不要误读为所有情况统一最多 5 次。最终只返回一个 offspring。失败和复制消耗调用，但不是逐请求进入算子有效率分母。[冷启动:618–646](/home/fang/code/LLM4AD/reference_code/RefineEvo/planner_interface.py:618)、[改写:320–334](/home/fang/code/LLM4AD/reference_code/RefineEvo/planner_interface.py:320)、[重试:854–951](/home/fang/code/LLM4AD/reference_code/RefineEvo/evo_interface.py:854)。
- **参考选择。** 父代按配置的 rank／equal／roulette／tournament 等选择，并非按互补性选配；rank 与 equal 实现用有放回 `random.choices`。算子调用统一经 `self.select` 取所需父代。[选择:25–84](/home/fang/code/LLM4AD/reference_code/RefineEvo/evo_interface.py:25)、[调用:834–844](/home/fang/code/LLM4AD/reference_code/RefineEvo/evo_interface.py:834)。
- **隔离消融。** 表中 RefineEvo／Select All 的 TSPLIB gap 为 11.54%／11.63%，但 TSP100 为 8.541／8.496，Select All 更好；作者报告 token 约 511k／965k。固定选 4 个算子时 Planner 优于 Random；去掉提示 refinement 也变差。这支持“在该系统中调度与提示改写有用”，没有比较简单数值 bandit，也没有证明在全调用等预算下额外 planner 优于 Base。作者关于“识别协同算子子集”的解释，不是对协同性的单独测量。[表及解释:229–266](/home/fang/code/LLM4AD/papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/04_experiment.tex:229)、[评价预算说明:339](/home/fang/code/LLM4AD/papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/06_appendix.tex:339)。

### PathWise：对本轮“父代集合＋修改指令”的 rollout 评价，不是累计算子成功率

- **机制。** Policy LLM 选择父代集合与自然语言指令 κ；World Model 为每个 action 生成多个候选。父代 metadata 是 design 与 performance。Policy critic 用 action 下 rollout 的平均性能作排名信号，生成文字反思供下一步使用；没有固定三算子的全局／父代／谱系成功率表。[论文:215–258、328–352](/home/fang/code/LLM4AD/papers/PathWise/example_paper.tex:215)、[reward 公式:328](/home/fang/code/LLM4AD/papers/PathWise/example_paper.tex:328)、[实现入口:1230–1280](/home/fang/code/LLM4AD/reference_code/PathWise/pathwise.py:1230)。
- **reward／失败／冷启动。** reward 是候选绝对性能均值，不是相对父代的增益或每调用收益。实现统一转为最小化，失败为 `inf`，一个失败便能使 action 均值变为 `inf`。代码计算了 inf 数量作为并列排序补充，但送往 critic 的调用仍传简单 `action_scores`；不能把注释当成所有路径都实际使用的排序规则。无区分性得分时复用旧 reflection，没有历史则不注入。新父代无需单独 bandit 冷启动，但每轮要支付 policy、多个 rollout、critic 成本。[均值与调用:1483–1518](/home/fang/code/LLM4AD/reference_code/PathWise/pathwise.py:1483)、[冷启动:915–923](/home/fang/code/LLM4AD/reference_code/PathWise/pathwise.py:915)。
- **隔离消融。** TSP constructive、GPT-5-nano(low)、5 次运行，去掉 Policy Critic 后训练 gap 从 8.79% 到 10.21%；去掉 World Model Critic 到 9.63%。支持这些组件在原架构中的价值，不能将其归因为无需 LLM 的参考选择规则。主比较用 500 次 heuristic evaluations，而非 500 次全部 LLM calls。[消融:832–856](/home/fang/code/LLM4AD/papers/PathWise/example_paper.tex:832)、[预算:1254](/home/fang/code/LLM4AD/papers/PathWise/example_paper.tex:1254)。
- **可迁移认识。** design／fitness 足以作为选择上下文，是接口设计参考；它不证明 design 文本相似度能判断互补，也不证明新增 policy 的调用成本在本任务值得支付。

### ShinkaEvolve：自适应的是 LLM 模型，变异类型仍按概率抽样

- **机制／统计粒度。** 论文 UCB 的 arm 是 LLM，运行内跨父代累计；父代只是 reward baseline。代码 `llm_selection.update(arm=model_name, reward=..., baseline=parent_score)` 可直接核实。`diff/full/cross` 则用 `np.random.choice(..., p=patch_type_probs)`；没有 inspirations 时去掉 cross 并重新归一化。[模型归因:4485–4498](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/core/async_runner.py:4485)、[算子抽样:89–115](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/core/sampler.py:89)。
- **reward。** 论文最大化 score 下为 `exp(max(score_child−max(score_parent,score_initial),0))−1`，再做尺度处理；不是超过当前全局最好。源码 AsymmetricUCB 支持基线、父代平移、非负截断、指数变换、衰减及可选成本项；默认 `cost_aware_coef=0`，不能把支持成本感知说成默认按调用成本分配。无效程序传 reward=None，默认非对称路径最终为零收益并计一次完成。[论文方法:74](/home/fang/code/LLM4AD/papers/ShinkaEvolve/sections/03_method.tex:74)、[参数:295–343](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/llm/prioritization.py:295)、[更新:427–509](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/llm/prioritization.py:427)。
- **冷启动／成本。** 未试 arm 优先均匀抽样，然后 UCB＋探索项。这里每个新程序不新建 arm。一次最终程序可能经历 patch 重试、novelty rejection、embedding、LLM novelty judge；模型成功统计按最终程序更新，不能直接当作每次请求的成功率。[冷启动:603–627](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/llm/prioritization.py:603)、[论文重试与 novelty:27–47](/home/fang/code/LLM4AD/papers/ShinkaEvolve/sections/03_method.tex:27)。
- **参考与父代。** inspiration 是 best／elite／随机程序，通常限制在父代岛内；不是成对互补优化。论文 weighted parent sampling 为 fitness sigmoid 乘 `1/(1+offspring_count)`；这里的“novelty”是少生过后代，不是机制新颖性。[参考实现:39–110](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/database/inspirations.py:39)、[论文:9–16](/home/fang/code/LLM4AD/papers/ShinkaEvolve/sections/03_method.tex:9)。
- **隔离消融。** 展示 weighted parent selection、模型 ensemble bandit、novelty rejection 的组件比较。图注明确为 Circle Packing，bandit 相对固定 ensemble 是 “slightly improves”；正文措辞更强，不能替代效应大小。embedding filtering 有改善，额外 LLM novelty judge 仅边际改善。这是生成后去重证据，不是生成前交叉配对的证据。[分析:1–23](/home/fang/code/LLM4AD/papers/ShinkaEvolve/sections/05_analysis.tex:1)。

### OpenEvolve：质量与特征覆盖的 inspiration；不是无 LLM 互补识别器

- **机制。** 父代选择混合 exploration／exploitation／random；inspiration 先包括岛内最好、elite，再从父代附近特征格取样，不足时随机补齐。源码是“附近格”，不是最大语义距离。特征的含义取决于配置，岛和 feature cell 都不能自动解释为思想。[父代入口:1445](/home/fang/code/LLM4AD/reference_code/OpenEvolve/openevolve/database.py:1445)、[参考选择:1729–1850](/home/fang/code/LLM4AD/reference_code/OpenEvolve/openevolve/database.py:1729)。
- **统计／reward／冷启动。** 本次查到的标准选择路径没有 Refine／Explore／Crossover 的自适应 reward 表；模型 ensemble 按配置权重抽样，没有根据 offspring reward 更新权重。档案不足时走已有候选／随机补齐，无需每父代三臂冷启动。[ensemble:54–63、107–112](/home/fang/code/LLM4AD/reference_code/OpenEvolve/openevolve/llm/ensemble.py:54)。
- **失败成本。** 请求层可 retry，迭代数不等于实际模型调用数；该框架的工程能力不应被记为对成本校正算子分配的消融证据。[API retry:185–212](/home/fang/code/LLM4AD/reference_code/OpenEvolve/openevolve/llm/openai.py:185)。本次未找到对“参考互补选择”独立收益的受控结果。

### ReEvo：固定交叉＋变异流程，差异配对主要依赖成绩

- **机制。** 当前 `evolve` 实际调用 `random_select`，不是旁边虽定义但未在该入口使用的 `rank_select`。从有效种群随机选两人，要求 objective 不相等；随后短期反思→交叉→评价，再长期反思→变异→评价。没有自适应算子概率，也没有父代或谱系成功率表。[实际流程:460–486](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:460)、[配对:302–323](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:302)。
- **代价／冷启动。** 少于两个有效候选时无法配对；同分过多时最多尝试 1000 次配对后返回失败，此循环是本地抽样，不是 1000 次模型请求。短期和长期反思另外消耗模型调用，而 `max_fe` 是 function evaluations。不同分只是让反思有优劣可比，不证明机制不同；同分也不证明算法相同。
- **隔离消融。** TSP100-ACO 的 white-box gap/目标表中，完整方法 8.40±0.02，去掉 crossover 8.45±0.02；black-box 8.96±0.82 对 9.47±1.40。支持保留交叉作为候选生成工具，不支持特定参考距离或自适应配额。作者“verbal gradients 改善景观”的解释来自另一项固定配对随机游走分析，不能替代选配互补性实验。[消融:62–89](/home/fang/code/LLM4AD/papers/ReEvo/sections/06_ablation.tex:62)、[随机游走条件:40–60](/home/fang/code/LLM4AD/papers/ReEvo/sections/06_ablation.tex:40)。

## 4. Base 的最小机制与准确记账

### 父代：保留当前简单权重，不叠加谱系／算子层控制器

当前实现为 `exp(−β(q_p−q_min)) × (k_p+3r)/(n_p+3)`；`r` 来自本次运行的平滑总体改进率。它是**父代自身的直接经验＋全局先验**，不是算子自适应。repair 结果归给原生成尝试，失败不能做普通父代。[权重与归因:59–86](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/selection.py:59)。β 按不同 score 值的有效样本量（effective sample size, ESS）求解；score 层级≤8 时 β=0，不能称始终强烈偏向最好父代。[温度:33–55](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/selection.py:33)。

保留它的理由是避免只爬当前冠军，也避免无条件平均开发所有程序；历史 V18 对照更支持先保住质量位置，而非新增树遍历。**现有证据没有单独证明经验乘子优于质量单项**，因此不再叠加 UCB、永久关闭、谱系保护作为同一轮改动。

注意当前 `n_p` 数的是尝试，repair 不增加 `n_p`。真实总预算必须另外按调用消耗扣除。若日后把权重语义改为“单位调用的成功产出”，才把分母改为对应调用成本，并重新命名；不要无说明地把现有二项成功率替换成成本率。

### 算子：固定概率是默认；若自适应，只共享三臂并保留探索

当前普通算子独立于父代按配置抽样；无参考的 Crossover 回退 Refine。[实际路径:154–178](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/traceaad.py:154)。建议先保留。理由不是“自适应无效”，而是本地收益没有形成明确赢家、父代质量是强混杂因素、文献中的自适应多为额外 LLM 或模型选择。

如主任务需要一个可直接实现的低成本候选，采用以下**建议方案，尚未经隔离验证**：

1. 一次 task×seed 运行维护三组 `N_o`（尝试）、`C_o`（实际调用）、`S_o`（有用新候选成功数）。父代先按统一规则选，随后选算子，避免人为让好父代只配某算子。
2. 普通非交叉成功要求最终有效、未命中此前有效代码的规范化精确重复、严格超过原父代。交叉要求严格超过 `min(q_parent,q_reference)`，且同样是新候选。此处最小化；其它方向先统一符号。这估计“超过本次已知输入最好解”的即时产出，不是长期探索价值，也不是参考的因果贡献。
3. repair 的成本与最终成功归原算子一次；不设 Repair arm。无效、复制、持平、退化都使成本增加，成功数不增加。无参考而回退 Refine 的结果记到**实际执行的 Refine**，同时保留 sampled_action 作审计。初始化不更新三算子成功表。
4. 使用平滑成本率 `u_o=(S_o+λu_0)/(C_o+λ)`，`u_0=(ΣS_o+1)/(ΣC_o+2)`；`λ` 是共同先验的等效调用量。取 `P(o)=εp0(o)+(1−ε)·p0(o)u_o/Σ[p0(j)u_j]`，`p0=(.45,.30,.25)`。λ 和 ε 必须预先固定并注明是设计参数，不是本次数据已估计的最优值。全零／空历史自然退回 p0；不可执行的 Crossover 先移除并归一化。
5. 该自适应仍可能压低短期不赢、但后续可开发的 Explore。探索保底不能宣称解决延迟信用问题。先保留固定概率作为可证伪的对照；不追加衰减窗、contextual bandit、远代回报反传等层次，除非出现明确的新证据。

这套定义用成功总数除以总调用成本，避免把“每次尝试收益÷该次成本”再平均误当吞吐率。例如一个修复后成功、一个直接失败，总产出是 1/3，而非 `(1/2+0)/2=1/4`。参数越多，越难在当前轨迹稀疏度下稳定估计。

### 信用的三个边界

- **成本单位：** 一个生成尝试通常 1 次调用，带一次 repair 通常 2 次；网络/API 重试仍须按实际调用另计。只剩 1 次调用额度时可生成，但不能再 repair；额度为零立即结束。duplicate 不能触发不扣费的自动重抽。提示里的 8／3／2 是展示窗口，绝不能用作算子统计窗口。
- **参考信用：** 一次交叉的效果同时受父代、参考、提示、模型影响。没有“同一父代不加该参考”的对照，不能把成功全部归参考，更不能同时给父代、参考、谱系各发一份完整收益。普通生成尝试只记原父代与原算子，参考记录 exposure／结果供诊断即可。
- **即时与长期：** 超过双方比超过父代更能排除“拿已有好解替换差解”，但仍不保证新机制、全局改进或未来潜力。全局最好改进另报，不能作为唯一 reward（太稀疏）；不要用“新增 design 标签”补探索奖励。

## 5. 交叉互补：无需额外 LLM 能做什么

**最稳妥的是先控制质量与冗余；仅有 design＋一个总 fitness 时，没有可靠的通用机制互补判定。** design 是生成器自述。不同谱系可以独立复现同一公式，同谱系也能经历真正的结构变化。增大谱系距离、代码距离或文本距离，都不能保证两者可结合。

### 默认参考选择

沿用当前“有效档案中不劣于中位数”的质量门槛；排除父代本身、规范化代码完全相同的候选，再随机选一个。不要把父代历史改进率也乘给参考：某程序适合被继续编辑，不等于它适合提供参考。[当前门槛:122–126](/home/fang/code/LLM4AD/TraceAAD/traceaad/base/selection.py:122)。

去重优先用语法树（abstract syntax tree, AST）规范化来忽略空白、注释和位置，不删除数值常量、不交换运算、不宣称识别语义等价。代码可在调度端做免费本地比较，**不因此把参考代码放进提示**。若要求选择器也只能访问 design／fitness，就只做规范化 design 的精确重复排除，并明确去重能力更弱。

先不加“必须跨谱系”硬门槛。若本轮档案出现已观察到的根数量主导，可加一个单独可关的修正：在满足质量门槛的参考池中先均匀抽根，再在根内均匀抽程序；仍允许同根。这只是在纠正展示机会随谱系体量膨胀，不是思想均衡或互补保证。没有可用参考时直接重归一化 Refine／Explore 概率，不花模型调用寻找参考。

### 两种可操作但应有边界的增强

**已有逐实例结果时，用互补表现做轻量候选排序。** 不额外评价程序。设最小化损失为 `ℓ_pj,ℓ_rj`，在固定训练实例上用 `mean_j max((ℓ_pj−ℓ_rj)/s_j,0)` 衡量参考弥补父代短板的幅度；`s_j>0` 由固定基线尺度预先确定，避免大尺度实例支配。若要区分“互补”与“全面更强”，还检查双方各自在部分实例上有优势。可在质量门槛内先随机抽少量候选，再用这一统计择优；不必再加分类器。它测的是**表现互补**，不是代码可组合性；贪心最大化还可能偏向高噪声和特殊实例，不能直接作为已验证默认。

**无逐实例结果时，词法／AST 距离只能作为去冗余的弱辅助。** TF–IDF 或 token 重叠无需模型，可从合格小池中避免几乎同描述的参考；不要选择“距离最大”的程序。命名差异、描述遗漏和代码重排都能把同机制变远，参数变化也可能改变实际行为。RefineEvo 的 semantic retrieval 消融检验的是经验检索，不是两个程序的融合；不能移植成“文本距离越大交叉越好”的证据。[经验检索比较:336–338](/home/fang/code/LLM4AD/papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/04_experiment.tex:336)。

### 我反对现在加入的设计及具体原因

- **LLM planner／思想分类器：** 原文有系统内收益，但没有在本任务“每次调用都收费”条件下胜过简单规则的证据；还改变预算、提示与信用路径。
- **每父代×算子 UCB：** 71.2% 已被选父代至多 3 次尝试，三臂尚未形成经验就耗尽开发机会；每个新 code 重启冷启动尤其浪费。
- **谱系×算子统计与远代回报：** 谱系内状态不平稳，远代收益要跨多次父代／参考选择反传，容易把同一次改进重复记账。
- **最大谱系距离／强制异谱系：** 根是来源记录，非机制标签；本地数据换成“超过双方”后跨根优势明显缩小。
- **同分即去重、最大 design 距离即互补：** 一个聚合 fitness 丢失实例差异，design 又不是行为真值；两条规则都会误删有价值候选。
- **默认新增 novelty judge 或拒绝后免费重采样：** 生成后才拒绝并不能追回已花的调用；Shinka 的 novelty 结果不等于等总调用预算下同样占优。

最会改变下一步决策的检验只有一个：在目标 Base 接口、父代规则和参考规则固定后，比较固定三算子概率与上面运行内共享、含 repair 成本的三臂统计，按同一总调用预算看前沿进展及最终成绩。本轮不执行。参考分配的更复杂增强留到“参考冗余本身仍是主要损耗”被直接证实之后。
