## 后续修正：已有嵌入服务改变了选型依据

用户指出 server3 已部署嵌入模型。我核对 AGENT_OPERATIONS 的第139行和既有嵌入客户端后，撤回“为避免新增部署而默认 BM25”的判断。之前没有检查已有资源，过早将实现便利写成最终选择。当前默认改为复用 qwen3-embedding-4b-fp8，对经验适用条件与设计启发进行语义检索；文档向量按内容缓存，查询加入明确检索指令，按余弦相似度取至多3条。BM25 留作精确词项检索对照，AST 继续用于源码身份与修改结构分析，不将 AST 距离混作经验适用分数。下表保留上一轮形成过程，其中 BM25 相关定案已由本节及当前两份规格替代。本次没有探测远端健康或调用嵌入模型测效果。

## 辅助来源与协调者核对

本轮三个专项分别来自 OpenCode 哈基米 `o10/gemini-4-argon-high`、`muse-wonder-full-1.0` 和 `claude-opus-5-5`。报告如下：

- Gemini：有限历史与经验检索。
- Muse：融合参考与机制交接。
- Opus：Base 对齐与英文提示。

我逐项核对了 Base 的 prompts、config、selection、llm、models、search 与 evaluation。Base 实际使用8／3／2窗口、三字段 JSON、构造时可覆盖 request_options；选择成本来自 Attempt.model_calls，超时失败原文确实含具体时限。因此文档同时写清历史去敏、反思角色客户端、独立成本账本与恢复时不重复应用更新。

## 采纳与修正

| 专项建议 | 协调者处理与理由 |
| --- | --- |
| 复用 Base 模板与输出 | 采纳，公共模板逐字一致，新增机制只填 Context 与 Instruction |
| 恢复8／3／2，完整存储与可见范围分离 | 采纳；参数理由是延续基线，不写成已证明最优。去重保留最新代表，避免最早代表抹掉近期信息 |
| 固定条数已经保证长度，典型输入只需10—15K tokens | 不采纳。代码、失败文本与经验长度可变；这些长度估计没有本轮测量。保留真实 tokenizer 检查和确定性裁剪 |
| 全量历史溢出即停整路 | 撤销。优先裁剪经验、旧失败、远祖先和子代。只有必需任务／代码本身无法容纳，才按宿主未评价输入错误处理 |
| BM25 只召回，模型判断适用性 | 采纳，不加嵌入服务。索引含 lesson 与条件，查询不用全部旧分析；同分按编号，不按版本或使用次数提高权威 |
| Jaccard≥0.85 自动将新条目转 revise | 不采纳。少数否定词和条件差异可能改变含义；仅完全相同正文安全合并，其余交给有原记录的联合反思 |
| 同源码参考只占一票，质量门为空时放宽 | 采纳。中位数也在不同源码代表上计算，避免复制数量改变门槛；明确这是对 Base 参考规则的增量 |
| 无参考时按0.6／0.4在 Refine／Explore 改抽 | 不采纳。新框架先按算子价值选父代，拓展父代不能无条件转精炼。只转 Explore，仍保持拓展价值口径，并记录请求与实际算子 |
| 规范化相同则直接替代数值反馈 | 不采纳。源码身份与实测成绩是两件事，分别展示；同代码但反馈不同仍需保留 |
| Refine 不能只改常数，Explore 不能新增评分项 | 不采纳这种语法边界。有依据的调参属于精炼，新评分项也可能引入新决策信息；提示围绕计算原理，不按编辑形式禁止 |
| 融合必须禁止并行运行两套算法 | 不设普遍禁令。模型需要解释两者如何共同影响结果，合法的协作或组合也可能包含两套过程 |
| 输出顺序 analysis→design→code 表示 Base 无法要求先形成完整算法 | 不采纳。先形成完整方案再实现，与先输出设计后输出代码并不矛盾。没有证据需要因此修改已用的公共 Output |
| review 由系统绑定版本，去掉模型返回版本号 | 采纳。反思统一输出 analysis、review、updates；局部代码分析独立保存，不要求必须产出经验 |
| 单独 polarity 标签 | 删除。正反反馈在 observation 中明确保留，避免极性与正文不一致；不影响双向经验的内容 |
| 旧来源只靠编号，当前修订不需见原记录 | 只允许沿用已存旧来源。要改写或撤回旧观察，相关原始事件必须可见；系统并集来源，不要求模型重写窗口外编号 |
| 必须扩展 Base Model.complete 以指定反思 schema | 不需要作为首版前提。已有 OpenAIClient 构造器可用 request_options 覆盖 response_format，单独建立反思角色客户端即可 |
| 反思请求不进入原生成／修复成本 | 采纳，并单列总请求与 tokens。跳过与修复使调用量可变，不预先声称总请求必然翻倍 |

三份报告中的数值耗时、典型输入长度和模型行为解释不自动成为实验事实，未导入最终规格作为实测保证。

## 关键边界核对

| 状态 | 应有行为 |
| --- | --- |
| 根节点无祖先、无子代、空经验 | 省略空段与对应指引，仍正常输出 Base JSON |
| 同父代很多复制子代 | 档案与实际投入保留；相同条件与反馈合并展示，复制不占满代表窗口 |
| 同一代码从不同父代产生 | 保留不同修改关系，不把两次父子比较并成一个观察 |
| 首版失败、修复后成功 | 一次尝试下保存两版和两次评价，只在流程结束后至多反思一次 |
| 只有一种有效源码 | 无法融合，当前父代执行 Explore，明确记请求与实际算子 |
| 两种源码，当前父代最好 | 中位数门后无参考时，放宽门选另一种，不让好父代永久失去融合机会 |
| 所有参考同分，或一个参考有很多复制 | 每种源码一票；质量门和抽样均不受复制数量扩大 |
| BM25空查询、空库或无正分 | 不展示经验，不要求生成器逐条解释空材料 |
| 旧经验来源在祖先窗口外 | 旧来源由系统保留；新事实只引用当前可见事件，修改旧观察前补来源卡 |
| review 有内容、经验 updates 为空 | 保存局部说明，不强制产生可迁移认识 |
| 历史正常增长导致输入变长 | 裁剪可选材料，不因历史条数触发整路终止 |
| 反思异常或恢复时结果缺失 | 记录跳过、不补发、不覆盖已评价程序，不重复应用旧更新 |

规则完整并不等于收益已证实。之后的实现和受控实验检验这些选择是否改善生成与经验迁移；它们不再用于补齐本稿尚未定义的执行规则。本次没有运行模型生成、评价或在线搜索。
