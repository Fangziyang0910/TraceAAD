## 判断

上一版确实把“容易实现”当成了部分设计的充分理由。BM25 是最明显的一处，但不是唯一一处：经验只看当前状态，参考只看自身质量，历史只取最好和最近，观察交给模型随经验正文改写。这些取舍没有充分利用问题中已有的信息。

本轮不把单个更复杂的分数当作替代，而把不同信息交给不同判断：语义与结构负责找候选，当前修改需求负责区分相关方向，评价负责描述已发生的结果，模型负责说明适用条件和计算接入。原始观察独立保存，经验解释可修订。每一处新增设计都对应具体失败方式。

## 混合决策为什么这样组合

经验侧有三个不同问题：当前算法具备什么条件，这次打算改什么，实际代码里有哪些计算。单个父代 design 向量不能同时准确回答三个问题。状态通道比较条件和来源父代；需求通道比较算子、近期尝试与修改经验；实现通道比较代码函数与来源结构。相关子路先在组内合并，再让每个信息类别只投一票，避免多建几个文本向量就压倒结构。

RRF 解决分数尺度不同，不解决相关性真假。三路各取前4、保留各路首项并补到8，是有界候选设计；最终再用一次模型请求判断适用和接入。该请求与融合参考选择共用，避免每个选择点都增加一个模型。新增最多一次生成前辅助请求，它是否值得必须单独对照，不用“多元”替代收益证据。

融合侧的差异回答“有没有别的资源”，逐实例余量回答“对方在哪些实例可补我”，模型接入判断回答“我能借哪项计算”。三者都不直接预测融合收益。质量优先池外保留一个候选名额，处理参考整体较差但局部计算有价值的情形；选择器仍可不用这一候选。

反思侧不采用反复重写整个长期池。系统保留源码、事件、评价和接续关系，模型改解释；同起点比较与后续结果提供重新解释的材料。不同频率学习可以减少仅凭一次实现定性的机会，但不能保证模型不泛化，因此账本和条件表达仍有必要。

## 独立意见、分歧与协调者裁决

独立报告为Muse程序结构与互补选择、Opus整套架构与哈基米Gemini检索复核。Gemini初次运行因反复发送无法解析的读取参数而取消；同一模型的窄范围复核已完成。三份报告存在分歧，当前主规格采用协调者逐项核验后的规则，不将意见数当作证据。

| 建议或争议 | 裁决与理由 |
| --- | --- |
| Muse：AST／数据流加入表示 | 接受结构、局部 def-use 与位置线索；不接受从普通 Python AST 就保证完整静态切片。别名、调用副作用、控制依赖须标未知，不能自动判死计算 |
| Muse：质量＋差异＋互补短名单，再 LLM 选择 | 接受级联，但把经验选择和参考选择合为一请求；实际只给短卡与局部完整函数，不假装读过每个候选的完整代码 |
| Opus：双通道状态／需求 | 接受区分，并补代码／AST 来源通道；不按算子硬分池，以保留跨算子迁移 |
| Opus：状态前一半作为适用性门 | 不接受。相对名次无论高低都会放进一定比例，N=1时仍全部通过；不能解决“不相关也展示”，也会排除有用跨结构类比 |
| Opus：曝光次数决定轮换 | 不作默认。频繁展示不是错误，强制轮换可能让最有用条目消失；近期尝试改变需求查询，选择器可以排除重复启发，曝光只记录 |
| Opus：局部与全局分两次调用 | 采纳不同写入频率与接续触发；合并到同一次评价后请求，学习片段与最新局部事件分区，不递归摘要旧反思 |
| Opus：只按逐实例余量取前3随机 | 作为融合对照，不作唯一默认。逐实例择优是组合上限，不能判断计算能否接入；无逐实例数组时也不能运行这一规则 |
| 两份：沿用硬中位数质量门 | 改为质量优先池＋池外一个候选出口，避免整体低分遮蔽局部可迁移机制 |
| Muse：AST／向量0.95阈值近重复分簇 | 不采纳为硬门。未标定，参数关键改变可在相似代码中出现；精确身份去重＋连续排名覆盖，不按近似度禁止参考 |
| 将旧反思合并方式整体当已证实 | 不接受。保留论文验证的组件边界，新的召回、触发和接入方式均为本项目待检验选择 |

## Gemini复核后的最终修正

复核指出的有效问题是匹配角色、参考覆盖与选择器负担；另有一些建议把代理信号说成确定事实。本轮只吸收能成立的部分：

| 建议 | 最终处理 |
| --- | --- |
| 代码检索把源父／子和helper都取max | 正向改为当前入口对源父代入口，明确匹配“修改前起点”；子代与helper保留为改后状态和借鉴材料。高子代相似不等于已经应用，不作自动抑制 |
| 融合多查询max丢掉参考身份 | 保留每个参考的首项及匹配编号，三通道首项加4参考首项最多7条，再补到8；选择器先判断接入，再选择适合该组合的经验。检索标签不是硬适用性标签 |
| State与Need都重复完整父代design | Need改为算子与近期修改反馈；没有尝试时只用算子。State仍负责当前状态。不同信息间仍可能相关，不声称字段分开就已统计正交 |
| 选择器输入完整轨迹与所有源卡 | 改为父代完整代码＋最近3条摘要＋精简经验卡，最终生成仍读完整8／3／2视图与所选经验观察；保留最多8候选，不按未测量的12—16K估计直接改成5 |
| RRF只累加单路前4可能惩罚专精经验 | 写明对全库先计完整名次，前4只决定准入；有效通道集对全库一致。候选分母相同，改成均值不改变排序，无需增加按候选归一化 |
| max多源改为0.7／0.3前二均值 | 不直接采用。该均值仍可能随源数出现极值偏差，也可能压低仅适用于其中一个来源的有效经验。先按源起点身份去重、限制4个代表，记录并分层检验误召回；不称已校正 |
| 退步源不匹配实际修改，只匹配lesson | 不采用。找到相近失败正是检索教训的一种用途，低分不等于错误药方；实际状态随卡片呈现，选择器据条件解释 |
| 子代相似比父代高0.02就判已采用 | 不采用。余弦差不能证明某项计算已经存在；改为选择器检查实际代码，若已存在则说明仍能指导什么，否则不选 |
| 代码／AST按0.7／0.3、内层k=10 | 不采用为已确定优选。没有本任务标定依据。保留统一k=60与分组融合，权重和k敏感性可以比较，不从“更复杂”推出更合适 |

原始报告提出的“误召回低于5%”“新经验提高15%”“条件一致率90%”也没有来自本项目的数据依据，不作为验收阈值。其用余弦相似>0.90定义“已经采用”同样不适合作真值。核验需人工读实际代码和条件。

我重新核对了[GraphCodeBERT §5.5／Fig.4](https://arxiv.org/html/2009.08366)：它在Ruby验证集比较了两种AST注入方式，报告短序列下会退化。这进一步限制迁移范围，但既不能证明手工AST计数有益，也不能证明本项目只取控制流节点就更好。[Qwen模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-4B)确实建议多语言检索的指令用英文，本版已固定英文指令、保留查询正文语言。

## 协调者核对发现的两处事实修正

**逐实例成绩并非当前 Base 的现成字段。** 旧组件 instance_evaluation.py:414（`traceaad/base/instance_evaluation.py:414`，提交 e059e840）计算均值并返回 evaluations，但当前 [traceaad_base/evaluation.py:43](../../traceaad_base/evaluation.py:43)只接受任务给出的有限实数。两份报告据旧接口提出“只需落盘、零成本可用”，缺少当前路径核对。主规格将它明确为可选评价适配能力；适配需验证原评分、随机顺序与计时不变，不增加评价或使用测试反馈。没有适配时结构与语义流程仍完整。

**Qwen 查询格式需要修正。** 模型卡给出 `Instruct: ...\nQuery: ...`，旧稿的尖括号格式不是该示例格式。本版按官方格式区分查询与文档。模型支持代码检索、项目有服务部署记录，都不等于本轮已经验证特定经验检索的效果或远端健康。

## 一手依据：能迁移什么，不能推出什么

- GraphCodeBERT Table 5：代码搜索消融中去数据流的 Overall MRR 为0.693，完整模型为0.713。它验证训练模型中的结构模态有帮助，不验证本项目手工 AST 计数或静态线索必然改善在线搜索。我们据此让结构成为可消融的补充通道。
- [UniXcoder §4.6](https://arxiv.org/html/2203.03850)：作者报告 AST 有助于受测代码理解任务，对受测生成任务未带来改善。它支持把结构先用于召回与理解，不支持把“增大结构差异”写成生成目标。
- [RRF原论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf)：名次融合不要求原分数同尺度，常数60来自其先导试验。我们借用合并方式，不称为无需参数或已解决信号相关性。
- Qwen模型卡：文本／代码检索和查询指令是现有服务的能力依据，不提供本任务适用性阈值。不能把其通用检索性能写成经验迁移收益。
- [MEMOIR §4.3](https://arxiv.org/html/2605.17539)：移除全局记忆、分支局部记忆、失败节点均有退化，支持这些材料值得区分。本文在线v2的消融列出这三项，未据此采用“扁平记忆下降8.5”数值，也未将触发频率视为已验证结论。
- [ACE §2.2](https://arxiv.org/html/2510.04618v3)：整体重写上下文后信息和表现坍缩是其具体案例。我们迁移增量维护，独立保留观察，不把该案例当成任何摘要都必然失败的证明。
- [ReasoningBank 附录C](https://arxiv.org/html/2509.25140v2)：特定WebArena设置的经验条数消融里，1条优于2—4条。它支持“不固定填满”，不决定本项目最优为1条。
- [BehaveSim Table 2](https://arxiv.org/html/2603.02787)：构造程序对上 AST、嵌入、结果相似与过程行为相似有分歧。我们据此限制各代理的命名和用途，不将语义或结构距离直接称为算法互补。

本轮重新打开原文并核对上述局部证据，没有把“整套方法优于基线”搬成单个模块的实验证明。报告中的更多来源保留为进一步线索，不都作为本轮已独立核验的结论。

## 具体流程与开销

```text
原有机制：抽算子 -> 按该算子价值选父代
  -> 取历史覆盖视图，建立多视角经验候选与融合参考短名单
  -> 必要时一次共用选择：经验0—3条、参考至多1个
  -> Base任务模板 + 轨迹 + 经验 + 算子 -> analysis / design / code
  -> 原有修复与评价，系统追加真实观察
  -> 最多一次反思：最新review；有学习片段才允许updates
  -> 更新经验解释、来源索引和后续轨迹；预算模块继续读取原始记录
```

嵌入、选择与反思都单列成本；不改变原 Attempt.calls 或父代选择用的生成／修复成本。历史、经验、参考卡有固定上界，发送前仍需 tokenizer 检查。模型异常、空库、无参考、缺向量和缺评价明细都有确定回退。Schema 和源码引用校验不声称自动证明语义正确。

## 最能改变取舍的验证

1. 先做事实健全性检查：AST 变化事实正确；真实来源与观察不丢；过去不可见材料不进入查询；逐实例适配不改原成绩。
2. 固定搜索状态比较单语义／多视角／多视角加选择，人工核对召回、误用与类比；固定父代和算子后再评价生成，避免把上下文“更分散”当收益。
3. 融合对比分开短名单和 LLM 末关，并比较固定后续精炼预算的结果。逐实例余量单独作一臂，不与结构和选择器同时更换后归因。
4. 同一事件流比较逐次凝练与片段凝练，以及自由重写观察与系统账本，再到未参与学习的父代上检验迁移。

当前最关键的未证实判断是：一次共用选择能否用足多视角召回提供的信息，使新增模型成本换来实际生成改善。若不能，去掉选择关；若结构通道只引入实现表面相似，也应删除该通道。裁决依据是这两项可区分的结果，不是预先偏好简单或复杂。
