# V3机制原则回顾与修订方向

本轮是机制讨论。以下区分已经核实的历史事实和建议，不改变V3正式规格、方法源码或运行中批次。

## 为什么类似问题反复出现

我认为不是只有沿用V2的具体设置才可避免失衡。V1、V2、V3持续面对相同的关系：当前适应度与未来开发收益不同；保留资格与实际开发机会不同；实际谱系与计算内容的连续性不同；个体退出与修改效果不同；经历的摘要与评价事实不同。重构改变了这些量的作用范围，但我没有把旧修正背后的约束完整继承下来。

三种情况不能混为一谈。子树投入压低祖先，是已经讨论过、在V3全局个体竞争里仍然存在的取舍；反思写反结果，是旧版并未彻底解决的缺陷，而非V3独有；将大量弱初稿未经开发退出直接解释为探索不足，是我的诊断又可能犯的错误。11月14日V2复查已经说明，弱初稿低概率与优秀实现跟进不足可以同时存在，仅凭前者不能决定放宽采样或增加保护。

依据：[V2问题收敛](2026-11-14-V2问题收敛与最小修复建议.md)、[V2最小修复与回放](2026-11-14-V2最小修复与回放.md)、[V3中段诊断](../../experiments_result/analysis/evotrace_v3_diagnosis_20261115/README.md)。这些材料不证明当前全部成绩差距都由同一问题造成。

## V3应保持的研究主线

V3延续V1/V2的研究问题，但更清楚地区分了种群成员更新和经验表示更新：**在有限评价预算下，以树状种群联合维护可继续开发的算法与关联的发展经验；个体淘汰通过局部结构简化和经验凝练完成，使过去的尝试继续参与后续设计。**

适应度用于竞争，树用于组织发展关系、整理区域与经验归属。选择规则负责使用这个种群。核心主张不要求路线划分、局部峰值保留或每个预算公式都出现祖先累计量。质量名额32、近期窗口40、名次跨度10是运行选择，均不是这条主张的组成部分。叙事清楚值得保留，但不替代搜索收益的证据。

## 从历史保留下来的约束

| 历史问题 | 应当继承的约束 |
| --- | --- |
| 较差结构锚点因相似性排除更好实现 | 个体代表选择与连接闭包分开；相似性不能推翻已有的质量改进 |
| 近期版本改变归一化分布，优秀个体被压平 | 存储了更多记录，不应被误解释为已有个体质量关系改变 |
| 后代投入和成绩被用来决定祖先自身的开发资格 | 直接开发个体与投入一个谱系区域是不同决策 |
| 低分初稿未获开发就被视作“没有潜力”，或据此要求全面加探索 | 个体当前分数、思想潜力和预算取舍分别陈述；未开发率不是优化目标 |
| 历史链和经验无差别展开 | 谱系保持真实来源；生成材料依当前计算任务组织相关信息 |
| 旁支、淘汰和失败被混为一谈 | 结构位置与退出原因不决定改进/退步标签 |
| 旧摘要逐轮改写，比较对象漂移 | 经验可迁移，原观察的比较对象、结果与条件不随承载位置改变 |
| 真实模型少量回放通过被解释为机制已经成熟 | 区分实现正确、事实忠实与实际搜索收益 |

## 预算侧的修订方向

我首先撤回把“68%的到期Explore个体未被开发”直接称为探索不足的判断。该观察说明近期保留不保证开发，不能说明这些个体值得更多预算。目标是既能跟进有竞争力的实现，也不使大量相近新版本仅因出生清零而持续挤占机会。

当前选择对象是一个具体个体。其适应度说明它作为实现的质量，直接开发次数说明从它本身出发尝试了多少。子树累计投入则回答另一个问题：相关谱系总共花了多少。后代不断繁殖，不能单独证明旧父代自身已经得到足够开发。

因此，我建议下一轮优先考察用直接开发投入替代个体权重中的子树投入，保留全局概率竞争与当前质量偏好。子树计数可以保留为发展记录。该建议纠正统计量与决策对象的错位，不预先宣称它会提高冠军份额或最终成绩。若坚持用子树折扣，应明确承认这是主动分散谱系投入的额外偏好，而不是个体自身开发充分的证据。

这也不解决近同新版本清零的问题。若确认它造成明显占位，应让相近实现竞争代表位置，而不是为“新颖性”另加奖金或让子代继承祖先的全部债务。实现应质量优先，再考虑冗余，最后补结构；不能重现V1的较差结构锚点排斥更好实现。AST和嵌入只是判断接近程度的工具，不能自动证明行为等价。现有AST距离统计不足以确定新的代表规则，因此这里保留为候选方向，不直接恢复旧距离阈值。

不新增弱初稿配额、停滞切换或路线屏障。统一的是质量、投入和发展关系的含义，不是让所有任务得到相同的父代份额或让所有新个体获一次保底。

## 经验侧的修订方向

反思整理的对象应是“从哪种计算出发，做了哪些改动，实际得到什么结果”，而不是“解释为什么这些节点被淘汰”。结构维护已经完成退出决策，不需要反思为该决策辩护。S与V体现经验的归属和发展范围，两者均可包含改进、退步、持平与失败。

一条有用经验可以简洁地写成：**在计算X上联合改变Y，观察到结果Z；可能解释为H。** 比较对象、实测结果属于观察；计算解释属于推断。应让程序负责提供和保留所选比较的结果，让模型聚焦于计算变化及其启发，不再要求模型重新决定性能方向。

这不是恢复逐条公式、分数、版本编号的淘汰台账。压缩仍然可以选择值得留下的比较、合并相近认识、删掉细节；但留下的主张必须有对应的真实比较。只保留improved/regressed孤立标签，也不足以防止比较对象错配。

递归凝练时，旧经验是带原有比较条件的观察记录和解释。它迁移到新节点或边，不意味着其中所有尝试都曾从新承接节点出发；更不能把旧推断当作新评价重复加强。最小修订应围绕这一比较关系做，而不是继续增加“不要犯错”的通用提示，或默认再引入一个自由文本裁判模型。

## 工作顺序

优先修复已确认的经验事实冲突，并单独复核多轮凝练后的比较对象。预算侧先明确直接投入与子树投入的选择含义，再用相同状态分析真实开发流向；不以某个前十名份额或未开发率作为目标。两项修改应分开识别作用，不再把一组同步变更的结果反推成某一条规则的收益。
