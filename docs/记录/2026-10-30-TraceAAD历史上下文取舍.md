# TraceAAD：祖先链与子代尝试的上下文取舍

## 当前判断

尚无依据认定子代历史优于祖先链，因此不能以子代窗口替代原有形成路径。祖先链提供到达当前算法的连续变化；同父代子代提供从当前位置已经尝试的其他修改。两者的作用不同，是否同时提供及如何限长需要结合收益与上下文成本决定。本记录不修改 Base 的机制约定。

## 已核对的一手材料

### TraceAAD 原有实现同时使用两类信息

[V15 生成提示](../../traceaad/v15/_prompts.py:332)的 `build`：Refine 同时提供 `_formation` 与 `_children_section`；Explore 提供子代尝试和全局最好成绩变化；Crossover 提供主父代与参考算法各自最近四步形成路径，以及主父代已有尝试。`_formation` 按形成顺序组织变化与评价，`_children_section` 列出同父代的其他尝试及结果。V14 同样通过其基类组织这些材料。

[V15 信息表示](../../traceaad/v15/prompts.py:7)在 `info=True` 时对历史提供 design 与评价，省略代码差分；不能将它与新 Base 的差分表示混同。[配置](../../traceaad/v15/config.py:20)默认形成历史深度与已有尝试窗口均为 8。这是实现事实，不是两类信息各自有效的消融证据。

### RefineEvo：支持记录修改关系与正负结果，不区分祖先和子代

[方法正文](/home/fang/code/LLM4AD/papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/03_method.tex:43)将父代到子代的变化总结成正负经验，再按算子与父代特征检索；不是把完整祖先链直接放进生成提示。

[经验消融](/home/fang/code/LLM4AD/papers/RefineEvo_Planning-Guided_Heuristic_Evolution_with_Bidirectional_Experience/04_experiment.tex:272)中，完整方法 TSPLIB 为 11.54%，把父子变化替换为种群两两比较（w/o trajectory）为 15.32%；去负经验为 13.94%，去正经验为 12.92%。三个测试列均以完整方法较好。这里 trajectory 指父子变化，不是多代祖先路径；负经验也包含成绩退步，不能等同于程序报错。结果支持有来源关系、同时含正负结果的经验，不证明祖先链或同父代子代窗口哪个更好。

### PathWise：规划上下文与生成上下文需要分开

[状态格式化](/home/fang/code/LLM4AD/reference_code/PathWise/utils/pathwise_helpers.py:244)向策略模型提供候选算法、来源父代信息、推导逻辑、代码与成绩；[生成器](/home/fang/code/LLM4AD/reference_code/PathWise/pathwise.py:747)使用动作选中的父代代码、描述、成绩、指令与反思。不能因名字包含 Path 或保存推导图，就认为生成器读取完整祖先链。已有 critic 消融不能区分祖先历史与子代历史的效果。

### ReEvo：比较候选并积累反思，不限定同一谱系

[短期反思](/home/fang/code/LLM4AD/reference_code/reevo/reevo.py:325)比较两个候选的实际代码，按成绩区分优劣；[长期反思](/home/fang/code/LLM4AD/reference_code/reevo/prompts/common/user_reflector_lt.txt)融合旧反思与新观察。候选不要求祖先或同父代关系，因此其反思消融不能用来支持同父代窗口优于祖先链。

## 机制推断

祖先路径尤其适合延续开发：新生成的父代没有子代记录，但其形成路径已经提供经验；还能展示某个组件在何时引入及整体成绩如何变化。只展示当前代码会丢失这些比较信息。不过，路径由搜索选择形成，未保留的失败分支不会自动出现，较早步骤也可能与当前机制不同。

同父代尝试适合再次开发同一个父代：它们共享起点，更直接回答哪些修改已尝试、哪些实现报错或超时。共享起点并不保证因果归因成立，一次变体仍可能同时改变多个组件。

若要区分两种解释，下一步可固定父代、模型、算子、输出格式与上下文预算，比较仅当前算法、加祖先链、加子代尝试、两者都加；分别覆盖刚形成和已多次开发的父代。本轮只调研，不启动模型调用。
