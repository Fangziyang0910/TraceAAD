# EvoTrace V3：演化轨迹上下文的设计

日期：2026-11-17（北京时间）

状态：已在工作区实现（未提交）。经两轮 Astra 与 Carbon 评审修订。精确规则见 [V3设计](../EvoTrace-v3设计.md) 第4–5节。

**树状种群能给下一次推理的有效信息，是“这个任务上哪些计算有效”的经验知识，以及支撑这些知识的演化证据。最有价值的是 design、经验与 fitness。** 因此，上下文由三部分组成：相关经验、被修改算法的形成轨迹、提供想法的算法卡片。源码只给被重写或被移植的算法，不给代码差分。

## 1. 下一次推理缺什么

LLM 有通用算法知识，能读写代码，但缺两样东西：

1. 它不能运行代码，不知道在这个任务的评价器上，哪些计算有效、哪些无效。
2. 它不知道已经试过什么。

任务描述和当前代码给不出这两样，只有搜索历史能给。上下文的作用是把这两样交给模型。

## 2. 树中的信息层次

| 层次 | 内容 | 对下一次推理的作用 |
| --- | --- | --- |
| 知识 | 根经验、边经验、节点经验 | 把多次评价凝练成结论，包括已被删除的历史；模型无法自行推出 |
| 概念 | 节点的 design | 说明算法计算什么；模型在这一层决定改什么 |
| 证据 | fitness 与父子关系 | 把概念变化与结果联系起来 |
| 实现 | code | 重写或移植时需要的细节 |

树的结构本身也是信息：路径说明算法怎样形成；与当前节点的距离说明相关程度。

## 3. 推论

1. **决策发生在概念层。** 模型先决定改变或引入哪种计算，再实现它。所以上下文的主体是知识、概念与证据。
2. **被修改的算法给形成轨迹，提供想法的算法给卡片。** 形成轨迹把这条谱系上的 design 变化与成绩变化放在一起，是下一次修改的直接证据。提供想法的算法只需说明它算什么、效果如何、关于它已知什么，即分数、design 与它发展路径上的经验。它的中间祖先已被最终 design 取代。
3. **源码只给被重写或被移植的算法。** Refine 给当前算法；Crossover 给当前算法与参考算法；Explore 不给。Explore 要的是不同的核心计算，函数接口已由任务模板给出；给出父代源码会让模型沿用它的流程与变量结构。
4. **不给代码差分。** 生成是整段重写，同一父代下子代的 diff 常有 100–300 行，没有可读的局部改动。“试过什么、结果如何”由子代 design 与分数给出。损失的是 design 未记录的实现差异，例如常数微调或实现错误。这一损失不需要替代机制：进入代表集的子代与父代的结构距离不小于覆盖阈值，design 可以区分；其余子代至多暂留 m−1 个，随后被剪枝，反思仍读取源码与 diff，并把结果凝练进节点经验。
5. **树的简化已经完成分层。** 仍然相关的近期历史保留为节点（design 与 fitness）；被淘汰的历史凝练为经验。上下文按树的层次渲染，不在渲染时另行截断。
6. **经验放在其来源位置，按来源去重。** 经验紧邻对应的节点或阶段，与对应的成绩变化一起出现。同一条经验只出现一次，并标明它来自哪个算法。
7. **不设长度裁剪。** 树的节点数有上界，但 design、经验与代码的长度只受软约束，所以这不是词元上界。提示超过服务端上限时，由服务端拒绝并记为调用错误。

## 4. 组织原则

- 整体顺序：从全局到局部，从过去到现在，从知识到操作对象。需要直接修改的代码放在最后，紧邻指令。
- 每条记录内部：结果 → design → 经验 →（代码）。
- 每段开头用一句话说明这段是什么，例如收缩阶段的经验来自已删除的算法。

## 5. 三个算子的上下文

**Refine**

1. 初始种群经验（根经验）。
2. 当前算法的形成轨迹，从根到父代，按从早到晚：每一步给出算子、成绩变化与 design；收缩阶段给出边经验；节点经验紧邻对应节点。父代的节点经验移到第 3 项。
3. 从当前算法出发的尝试：先给父代的节点经验（已凝练的尝试）；再给尚未凝练的直接子代，每条给出结果（失败时给失败原因）、design 与经验。
4. 当前算法：分数与代码。

**Crossover**

1. 至 3. 与 Refine 相同。参考算法若是父代的直接子代，不在尝试中重复。
4. 参考算法卡片：分数、design、它发展路径上前文未出现的经验、代码。
5. 当前算法：分数与代码。

参考算法与当前算法共有的路径经验已在第 2 项出现，卡片说明中写明“只列出前文未出现的经验”。不再计算共同祖先，也没有共同祖先为虚拟根、父代或参考算法时的特例。

**Explore**

1. 初始种群经验。
2. 父代与选出的代表个体，按适应度排序，每张卡片给出分数、design 与其发展路径上前文未出现的经验，不给代码。

发展路径上的经验，指从根到该个体路径上的边经验和节点经验。在第 7 节的 288 个状态上，只用个体自身附带的经验，平均覆盖树中 19% 的边经验与节点经验；加入路径经验后覆盖 53%。

选择规则：候选为代表集去掉父代与相同代码，不设质量下限，因为较弱的不同做法及其结果同样提供信息。先取适应度最好者，再逐个加入与父代及已选个体的最小 AST 距离最大者，至多 6 个。候选为空时仍执行 Explore，只展示父代卡片。

## 6. 与原 V3 的差别

| 项目 | 原 V3 | 本设计 |
| --- | --- | --- |
| 路径基准代码与收缩阶段之后的完整代码 | 展示 | 删除 |
| 代码差分 | 祖先步骤与同起点尝试均展示 unified diff | 删除 |
| 同起点尝试 | 结果、design、diff | 结果 → design → 经验 |
| Crossover | 共同祖先、两条分支、两份代码 | Refine 的轨迹与尝试，加一张参考算法卡片 |
| Explore | 全部可行个体平铺，附父代代码 | 父代与代表个体的卡片，不给代码 |
| 当前算法位置 | Refine/Crossover 中位于开头 | 移到最后 |
| 长度控制 | 30k token 超限时折半展示窗口；必要上下文超限时报错 | 不裁剪；实际长度见调用记录 |

| --- | --- | --- |

## 8. 评审与修订

第一轮（设计草案评审后）：

1. Explore 由“个体自身附带的经验”改为“发展路径上的经验，按来源去重”。
2. Explore 去掉 0.30 的质量下限。
3. Explore 的父代给出 design。
4. 补充收缩边子代的规则。
5. 措辞修正：经验“提供解释线索”，不写成“说明原因”；不再写“用旁边的 fitness 校验经验”。

第二轮（用户指出 design、经验与 fitness 最有价值，diff 冗杂，Crossover 过于复杂）：

1. 删除所有代码差分。
2. Crossover 改为 Refine 的轨迹与尝试，加一张参考算法卡片；删除共同祖先块、两条分支与相关特例。两位评审都建议不加“在 Algorithm X 之后分开”一行：它不改变组合决策，还会带回共同祖先的特例。
3. Explore 不给父代代码，父代改为普通卡片。Carbon 在真实样例中发现一个 Explore 子代沿用了父代的四段流程、参数结构与十余个变量名，只替换了一个打分项。
4. 删除长度机制（`max_input_tokens`、超限省略循环与每次生成前的分词器调用）。

两轮都保留的部分：Refine 路径上的中间 design（未收缩边通常没有边经验，删去后成绩变化失去对应的计算描述）；Crossover 中从父代出发的尝试与算子标记。

后续：反思有时把局部结论写成通用禁令，例如“以后避免替换核心评分机制”，可能限制 Explore。已在[V3 减法](2026-11-17-EvoTrace-V3减法.md)中处理：反思提示要求写明起点、改动与结果，不把单次结果写成通用规则或禁令。
