## 10月16日：凝练研究问题

我重新梳理了自动算法设计中的研究对象。目前采用的概括是：在有限试错预算下，系统怎样从自己的尝试中积累经验，改善后续的生成、修改与选择。

这次讨论使我分开理解当前程序质量、后续搜索收益和一次尝试提供的信息。我把需要辨清的问题归为三个角度：结果能支持什么判断，经验在什么条件下适用，下一次投入是否值得。它们帮助组织问题，具体机制仍由证据决定。

这是一项概念整理，依据是当日科研讨论及查阅的文献。此前讨论引用过历史诊断，但本次没有重新核对其原始轨迹。因此，我没有把旧数值和因果解释迁为新系统的实验结论。当前表述见[研究问题](../研究问题.md)与[当前认识](../当前认识.md)。

我还转换了活动结果与封存结果中的 18081 个文件。独立核对覆盖 2954 份源码文件，程序编号仍对应原来的源码，成绩与来源关系保持不变。活动结果中的 44 个已选定程序可由当前读取器正常读取。最终全量测试 627 项通过。转换原件临时保存在仓库外，运行代码不读取它们。

## 10月16日：精简八任务的评价实现

我保留了全部八任务，精简评价器中的重复实现和辅助代码。CVRP 与 OP 共用参数检查和进程池执行，求解算法仍各自保留。我删除了没有调用方的单实例包装、演示入口和装箱绘图函数。装箱评价不再保存评分未使用的逐箱物品明细。`benchmarks/` 的 Python 代码净减少 308 行。

TSP 改用布尔数组记录已访问节点，减少逐步构造时的集合检查。同时，我修复了一处校验漏洞：生成函数修改候选节点数组后，旧评价器可能接受重复访问起点的非法路线。新评价器按独立的访问记录检查返回节点。路线长度仍由原始坐标计算，不受生成函数修改距离矩阵影响。
