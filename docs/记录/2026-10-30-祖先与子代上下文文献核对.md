# 祖先与子代上下文：一手文献核对

核对日期：2026-10-30。重点检查 MCTS-AHD、CogMCTS、PhyloEvolve、DeltaEvolve；补查 HiFo-Prompt。只依据本地论文 LaTeX 源码及作者仓库，不采用二手综述的机制归类。DGA2D 本地只有 PDF，本轮按优先三四篇的要求未展开，不能据此对它作否定判断。TraceAAD、ReEvo、RefineEvo、PathWise 留给主线程。

## 结论

在本轮核对范围内，**未找到在同一生成器、同一父代和同等上下文预算下，直接比较祖先链与该父代已有子代尝试的实验**。现有证据能确认部分方法把历史放入提示，但不能回答两类上下文谁更有效。

- **MCTS-AHD：有可核验的祖先集合生成提示及删除整个路径操作的消融。** 实现按分数排序祖先，不能称为保留演化顺序的路径提示。
- **PhyloEvolve：方法明确将当前祖先路径、兄弟比较及跨谱系精英轨迹一起送给规划器，并从轨迹凝练可复用知识。** 后一项来自 2026-11-02 对 Summarizer 的补核，见 §2。没有找到祖先与兄弟的独立消融，也缺少本地作者实现可核验。
- **CogMCTS：当前选中节点与全局精英对比，再累积正负知识。** 不是已经证实的祖先路径提示，也不是同父代子代尝试汇总。
- **DeltaEvolve：父代代码加全局历史节点的语义修改摘要。** “历史”“动量”不意味着这些节点是当前父代的祖先。

术语界限：对将被修改的节点 p，祖先是 p 的前驱链；已有子代是从 p 出发已经试过的修改，新生成节点将与它们互为兄弟。p 自己的兄弟则来自 p 的父代，二者不是同一条件下的尝试。

## 2. PhyloEvolve：最明确的路径加兄弟联合上下文，缺少来源拆分实验

**作者方法。** `/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/4_method.tex:82–98` 明确规定 NextStepper 的上下文包括：当前根到焦点节点的修改与增量奖励路径；邻近兄弟分支的性能和修改比较；精英轨迹；精英修改；任务约束。`:60–71` 说明精英轨迹可跨树检索。`:102–104` 说明 ModifyAgent 接收 NextStepper 的详细修改规范来生成代码。

因此可以说**历史明确进入提案生成提示，并经提案影响代码生成**；不宜未经实现核验说所有历史原文直接进入代码编辑器提示。这里的 sibling comparisons 描述为 neighboring branches，未精确定义为“重新扩展同一 p 时读取 p 的全部既有子代”，不应直接替换成后者。

**证据强度。** 本地 `reference_code/` 未找到对应仓库；以上是方法规范，未验证实际 prompt builder。方法 `:12–23` 的 Algorithm Distillation / Decision Transformer / ICRL 表述属于作者解释，不能当作机制已被实验识别。

**2026-11-02 补核：轨迹并非只用于提案。** 我重新阅读完整方法后确认，[Summarizer](/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/4_method.tex:120) 明确分析完整演化路径，归纳有效修改序列、失败模式与可迁移原则，再将摘要用于后续上下文（120–128 行）。[节点采样](/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/4_method.tex:148) 使用绝对得分、近期增益和深度，树级采样还使用近期改进趋势与多样性（148–160 行）。因此，不能将区别写为“PhyloEvolve 不用轨迹凝练经验”或“选择完全不用历史”。可以准确区分的是，它所述节点采样依据数值统计；TraceAAD 的选择模型直接读取候选的具体修改及其反馈。其 neighboring branches 未明确规定为当前候选全部既有直接子代，这属于定义尚不明确，不能推断实现必然排除这些子代。首次核对集中于生成上下文，不应将核对范围解释成该方法的全部用途。

**实验。** `/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/5_experiments.tex:6–10` 比较完整系统与基线实现，在 LLG、LTSA、GraphWave 上测运行时间和正确性；结果说明位于 `:28–60`。该实验文件共 62 行，未报告去祖先、去兄弟、路径对兄弟或无历史版本。主文件 `/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/main.tex:123–150` 也未载入额外消融附录。

**能支持什么。** 完整系统能产出更快实现；不能从相对原实现的加速推断收益来自轨迹条件化而非其他组件。图注 `5_experiments.tex:28,60` 的“rather than random mutation”是作者归因，本地正文未给相应随机变异对照。

## 6. 2026-11-02 补核：PathWise 的候选移除不等于历史删除

我对照论文与作者代码确认，[Policy 提示](/home/fang/code/LLM4AD/papers/PathWise/example_paper.tex:1834) 将父代描述与性能、推导理由及反思用于父代选择和修改规划（1834–1874 行），不能将这些历史信息归为仅用于生成。[状态更新](/home/fang/code/LLM4AD/papers/PathWise/example_paper.tex:212) 将已用父代移出活动候选集，并保留全局最优。作者代码另外维护 `all_nodes_archive` 和 `node_history`，见 [历史保存](/home/fang/code/LLM4AD/reference_code/PathWise/pathwise.py:1403)；[移除逻辑](/home/fang/code/LLM4AD/reference_code/PathWise/pathwise.py:1450) 对唯一最优节点保留例外，同分并列最优时按默认规则移除。因此，“父代用后移除，所以同一起点上的多次尝试不会被保留”不是成立的推论。若要比较局部轨迹，应该直接核对提供给决策模型的上下文是否汇集当前候选的既有子代，而不能从活动集合的变化推断历史已被删除。

## 对当前问题最有用的证据边界

最接近的问题分成两块：MCTS-AHD 提供“祖先集合可以用于生成且整套操作有用”的代码与消融；PhyloEvolve 提供“路径与兄弟信息可以联合用于下一步提案”的明确方法先例，也已经从完整轨迹凝练经验。两者均未回答哪种上下文来源更有效。若要区分它们，关键缺失对照是：固定父代与生成动作，仅替换等预算的祖先记录或同父代已有子代记录，并同时控制成功/失败比例和表示形式；否则来源效应会与质量选择、顺序、压缩及动作改变混淆。对整体框架的比较，还应区分数值统计驱动的节点选择与直接读取修改语义及反馈的选择，并分别核实轨迹在生成、选择和经验学习中的实际用途。
