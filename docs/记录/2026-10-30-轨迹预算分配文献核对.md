# TraceAAD Base：父代、谱系与轨迹预算的一手文献核对

核对日期：2026-10-30，北京时间。范围：只读论文、参考源码和作者公开仓库，不运行模型。本记录只给证据与候选建议，不代表已确定或实施 Base 机制。

后续设计与 Clade-AHD 在线 v2 的补充比较见[父代选择定案](2026-10-30-父代选择定案.md)。Base 总预算后来定为 1,000 次评价，父代成本另按模型调用统计；下文保留调研时的条件。

## 1. 我目前最相信的判断

**先区分“这个程序现在好不好”“从它出发下一次生成值不值”“继续开发这条谱系值不值”。三者的统计单位不同，不能共用一个 visit 或一个 reward。** 对当前 Base，最值得先检验的是 QUBE 式的直接后代证据，而不是直接移植 Clade-AHD 的整棵树统计。理由是前者的归因对象清楚，且有“父代自身成绩→子代成绩→加入探索项”的分步消融。轨迹首先用于解释哪些修改有效、哪些重复或失败，随后才考虑是否需要延迟回报。

这不是认定直接子代收益已足够。它无法识别“先退步、再经多步产生突破”的路径。只有实际轨迹表明这种路径对最终结果有实质贡献，整谱系回传才对应一个明确问题。

本轮有三个需要纠正的常见概括：

- **MCTS-AHD 不只是按父代当前质量选节点。** 论文与代码都回传子树后代的最大质量；它不是平均奖励 UCT。
- **BaSE 不直接估计改进斜率。** 当前官方源码把每次推进后的 running-best fitness 当奖励，用历史均值做 UCB / Gaussian Thompson sampling。源码中的单臂是一个可暂停的完整演化运行。
- **Clade-AHD 本地源码不能按论文公式无差别移植。** 同一次结果既更新新节点又从该节点开始回传，选择时还再次聚合已包含后代证据的节点均值，存在重复与重叠证据；这是静态代码证据，不是对其论文实验失效的结论。

## 3. QUBE：最直接区分父代质量与产出能力的证据

**作者机制。** 同一个岛内，评估实例上结果完全相同的程序被合成一个 cluster。先均匀选岛，再选 UIQ 最高的两个 cluster，各取一个程序作 few-shot 父代。cluster 内偏向较短程序。岛重置也使用 UIQ，TSP 实验只有一个岛且取消重置。

对 cluster C，令 `P(c,t)` 为 c 作父代生成的直接子代集合：

\[
Q_t(C)=\frac{\sum_{c\in C}\sum_{a\in P(c,t)}s(a)}{\sum_{c\in C}|P(c,t)|},\qquad
UIQ_t(C)=Q_t(C)+k\sqrt{\log t/N_t(C)}.
\]

`N_t(C)` 是该 cluster 的程序被用作父代的次数。**奖励是直接子代绝对成绩，不是子代减父代的增量，也不是整个子树回报。** 相同评估结果并不保证相同语义或相同可改进性，这是 cluster 统计的近似。

证据：[QUBE main.tex](/home/fang/code/LLM4AD/papers/QUBE_Enhancing_Automatic_Heuristic_Design_via_Quality_Uncertainty_Balanced_Evolution/main.tex:265)，265–294；TSP 特例 308。

**消融实际支持。** OR3 online bin packing，10 次运行，excess ratio 越低越好：

| 变体 | 平均 excess ratio | 10 次中最好 |
|---|---:|---:|
| FunSearch*，自身成绩 s(C) | 3.07% | 3.02% |
| Quality Only，子代均值 Q(C) | 2.98% | 2.74% |
| Parent Selection Only，Q+探索项 | 2.89% | 2.65% |
| 完整 QUBE，再改变岛重置 | 2.76% | 1.79% |

这是支持“产出成绩比自身成绩更有用、探索项有额外作用”的相对直接证据；均值改善依次为 0.09、0.09、0.13 个百分点。不能将最后一行全部提升归给父代选择。原表标准差写作 `0.0008/0.0012/0.0018/0.0016`，与百分数均值混用表示，本文不擅自重标单位，也不由此宣称显著性。来源：[消融表和定义](/home/fang/code/LLM4AD/papers/QUBE_Enhancing_Automatic_Heuristic_Design_via_Quality_Uncertainty_Balanced_Evolution/main.tex:397)，397–430。

**预算与缺口。** OBP 总生成 80K 样本，每 prompt 4 个；cap set 2M 样本，每 prompt 4 个；TSP 2K 样本，每 prompt 1 个。样本数不能直接当成 Base 调用数。论文没有在上述公式处定义 `N=0` 初始化、无效子代奖励、重复子代是否计入 Q、双父代如何分配一次奖励、repair 成本；公开仓库本轮不能补足。不能把“无效程序不入库”推导成“它不计预算”或“它必记零奖励”。来源：[实现参数](/home/fang/code/LLM4AD/papers/QUBE_Enhancing_Automatic_Heuristic_Design_via_Quality_Uncertainty_Balanced_Evolution/main.tex:498)，498–517；有效性过滤 210。

**对 Base 的迁移判断。** 借鉴“用后代证据评估父代”，不直接照搬同成绩 cluster、top-2、岛重置或 UCB 常数。Refine / Explore / Crossover 的产出分布不同，父代历史成绩还依赖当时算子与轨迹上下文。作者称 Q 为无偏估计（425），但对 Base 的变化上下文和自适应选择，它只能估计被观察策略下的历史产出，不能无条件保证下一次生成期望无偏。

## 4. MCTS-AHD：访问次数是子树扩展量，价值是后代最大质量

**作者机制。** 程序节点保留自身代码和描述；沿树按 UCT 下降；progressive widening 允许再次展开内部节点；每个叶节点展开多种动作。论文式为：

\[
UCT(c)=\frac{Q(c)-q_{min}}{q_{max}-q_{min}}+\lambda\sqrt{\log(N(parent)+1)/N(c)},\quad
Q(v)\leftarrow\max_{c\in children(v)}Q(c).
\]

论文把内部 N 更新为子节点 N 之和；代码在每次有效新节点回传时，给其每个祖先 `visits += 1`。因此 N 不是“程序 v 直接作父代几次”，更不是“在 v 身上用了几次模型调用”。新节点自身以 visit=1 开始；代码内部节点保留自身初始计数，与论文求和式也不是逐点相同。

来源：[论文方法](/home/fang/code/LLM4AD/papers/MCTS-AHD/icml2025.tex:255)，255–274；[代码回传与 UCT](/home/fang/code/LLM4AD/reference_code/MCTS-AHD-master/source/mcts.py:51)，51–70。代码 discount_factor=1（38），回传的是当前子节点 Q 最大值，未显式与父节点原始自身质量再取 max，不能称为“所有历来访问奖励的均值”。

**成本与失败。** 论文主预算是 1,000 次性能评估，BPP 特例 2,000。`evolve_algorithm` 最多三次评估尝试，失败/复制可能消耗评估计数，但不插入树、不回传 visit。`get_offspring` 内部还会因重复/异常重新生成，调用次数超过评估次数；`_get_alg` 末尾另有 `post_thought`。因此直接拿 `visits` 或 `eval_times` 做 Base 调用成本会漏账。来源：[接口](/home/fang/code/LLM4AD/reference_code/MCTS-AHD-master/source/evolution_interface.py:129)，129–175；[有效节点插入](/home/fang/code/LLM4AD/reference_code/MCTS-AHD-master/source/mcts_ahd.py:99)，99–123；[论文预算](/home/fang/code/LLM4AD/papers/MCTS-AHD/icml2025.tex:632)。

**交叉关系。** e1 从不同 root 子树抽程序作输入，却将产物挂在虚根下；e2 借助 elite set，但新节点只有一个 `parent`。这里的搜索树是搜索控制结构，不是完整因果谱系 DAG。不能把树上的回传路径理解为所有代码贡献者。

**消融。** TSP50 / KP100 最优性差距，越低越好：原版 10.661% / 0.059%；去 progressive widening 为 12.132% / 0.064%；去 exploration decay 为 11.606% / 0.064%；去路径推理 s1 为 11.919% / 0.062%。这支持在原框架中保留内部节点再探索及路径动作；**没有直接隔离 max-backup 相比 mean-backup 或直接改进奖励的贡献**。s1 删除还改变生成动作，不能证明“给 Base 加祖先摘要必然提高预算效率”。来源：[消融表](/home/fang/code/LLM4AD/papers/MCTS-AHD/icml2025.tex:418)，418–442；正文说 3 runs，表注说 5 runs，原版行说 10 runs，重复次数有内部不一致，应保留该局限。

**迁移判断。** 可借鉴“暂差节点仍保留、内部节点可再展开”。不要把所有后代最好成绩解释成该祖先仍有很高的下一步边际产出。高分后代存在，只证明曾成功到达那里；是否应继续从祖先原代码生成，是另一个问题。

## 5. Clade-AHD：谱系证据有动机，但实现的归因不能直接使用

**作者机制。** clade 是节点及全部后代。归一化性能 r∈[0,1] 被作为 fractional success / failure evidence，Beta 参数加 r 与 1−r。深度距离按 λ 衰减，聚合 clade 证据，用 Thompson sampling 选子树；另加伪观测、预算退火、冻结。默认 λ=0.8、先验 Beta(1,1)、伪观测 10、最小访问 10。奖励主要是归一化绝对性能，不是父子差值。来源：[机制](/home/fang/code/LLM4AD/papers/Clade-AHD_Clade-level_Selection_for_MCTS_in_Automatic_Heuristic_Design/main.tex:299)，299–328；默认参数 384；评估预算 395。

连续成绩作为 Beta 的分数计数是一个建模选择；不能仅凭 Beta-Bernoulli 的名字认定对相关、变化中的程序收益给出了校准概率。深度衰减处理的是祖先距离，**不等于按时间遗忘旧样本**。

**本地实现核对，三处尤其重要。**

1. 叶节点自身结果重复更新。顺序展开先 `nownode.update_belief(r)`，再 `mcts.backpropagate(nownode,r)`；后者从新节点本身开始。所以同一评估在新节点 alpha/beta 中进入两次，visits 变为 2。并行结果路径先赋 visits=1，再做这两次更新，visits 变为 3。见 [顺序入口](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/mcts_ahd.py:554)，554–570；[并行结果入口](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/mcts_ahd.py:444)，444–465；[belief 更新](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/bayesian_node.py:170)，170–188。
2. 后代证据重叠聚合。回传已把后代 r 沿祖先链加进各节点 belief。选择又调用 `get_clade_scores`，加入自身均值的 10 个伪观测，并将每个后代的 `expected_performance` 重复 `descendant.visits` 次。不同后代 belief 已有共同的更深后代证据，不是互相独立的新观测。见 [回传](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/mcts.py:319)，319–338；[clade 聚合](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/bayesian_node.py:190)，190–221；[实际选择](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/mcts.py:161)，161–181；调用链 [主循环](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/mcts_ahd.py:717)，717–720。
3. 无效结果不进入上述 belief。并行路径在无效或特定重复情况下直接 return，计数在有效插入后才加。顺序路径另调用演化接口，不能混称所有路径均只计成功。归一化随着历史范围变化，而已累计 alpha/beta 不会同步重算，旧新 r 未必同尺度。见并行入口 418–465；[归一化](/home/fang/code/LLM4AD/reference_code/Clade-AHD/source/score_normalizer.py:103)，103–124。

这里需要区分：**同一个事件在各祖先的不同区域统计里各记一次，不天然错误；将这些包含关系的累计统计再当成独立证据加总才造成重复确信。** 代码结论只针对本地快照，未核实论文表格使用的精确版本。

**消融数值。** 三次运行，表中“去模块”项是相对完整模型的性能损失百分比，不是原始 objective，也不是百分点：

| 删除项 | TSP50 损失 | KP100 损失 |
|---|---:|---:|
| 伪观测 | 1.869% | 0.862% |
| 深度衰减回传 | 4.950% | 0.143% |
| clade 冻结 | 7.751% | 0.148% |
| 温度退火 | 6.657% | 0.416% |
| 自适应归一化 | 1.870% | 0.064% |

完整模型原始值为 6.269 / 40.576。来源：[消融](/home/fang/code/LLM4AD/papers/Clade-AHD_Clade-level_Selection_for_MCTS_in_Automatic_Heuristic_Design/main.tex:477)，477–508。这些删除消融支持完整包里的局部效用；TSP 与 KP 效应量明显不同，不能说明五个模块在 Base 都必需。该表没有拆开“clade 汇总 vs 单节点 Thompson”这一对照。附录 λ∈{0,0.5,0.8} 的 ACO-TSP 曲线支持该设置下 0.8 更好，但未给 λ=1 对照或可精确摘取的末值表；λ=0 也不能在上述实现里自动等同于完全不使用后代统计。来源：[λ 敏感性](/home/fang/code/LLM4AD/papers/Clade-AHD_Clade-level_Selection_for_MCTS_in_Automatic_Heuristic_Design/appendix.tex:180)，180–193。

**在线 v2 补充核对。** [当前论文 §IV-A](https://arxiv.org/html/2602.00549v2#S4.SS1)明确将连续成绩的分数更新解释为避免额外伯努利抽样噪声的建模选择；不能把信念形式自动等同于校准后验。[§VI-E](https://arxiv.org/html/2602.00549v2#S6.SS5)的表 VII 还比较 UCT 的三个探索常数，但没有固定证据范围与其余机制来单独隔离 Thompson 的作用。表 VI 的五项消融数值与上述摘录一致。该版本补充了说明与实验，不能将本地 TeX 的全部措辞视为在线 v2 原文。

**迁移判断。** 学习“有些差节点是 stepping stone”的问题意识。若测试 clade，直接从唯一评估/尝试事件集合聚合，不从已回传 belief 再求和；成本与奖励分别记账。第一版没有充分理由同时移植伪观测 10、λ=0.8、退火和冻结。

## 6. Compute Allocation / BaSE：最适合解释跨轨迹预算，不能冒充父代策略

**作者机制。** 固定 K 条可独立继续的运行，把预算分给下一条要推进的轨迹；不改变轨迹内部 parent sampling。论文算法按一次调用写，先初始化 K 条，再分配余下 C−K 次。来源：[算法](/home/fang/code/LLM4AD/papers/Compute_Allocation_in_Evolutionary_Search_From_Depth_Breadth_to_Multi_Armed_Bandits/bandit.tex:53)，53–78；与 parent sampling 正交的说明 587。

**官方源码补足奖励定义。** 当前实现 `Arm` 是完整 greedy run；一步生成 N 个子代、耗 N 次调用，总预算 C=T×N。运行从现成任务初始程序开始评估；其初始评估不计生成预算。每次回馈的是该运行的新历史最好成绩。UCB 和 Gaussian Thompson 都用这个值的历史均值；没有近期斜率预测或滑动窗口。UCB / Thompson 前 K 轮强制每臂一次；EXP3P 的 `select` 没有相同强制逻辑。

固定源码：[arms.py:1–6](https://github.com/keruiwu/self-evolving-allocation/blob/ae7b5da1db39c0fd826adda7893c99d5bda5ac1b/base/arms.py#L1)、[runner.py:4–16](https://github.com/keruiwu/self-evolving-allocation/blob/ae7b5da1db39c0fd826adda7893c99d5bda5ac1b/base/runner.py#L4)、[runner.py:106–119](https://github.com/keruiwu/self-evolving-allocation/blob/ae7b5da1db39c0fd826adda7893c99d5bda5ac1b/base/runner.py#L106)、[policies.py:89–124](https://github.com/keruiwu/self-evolving-allocation/blob/ae7b5da1db39c0fd826adda7893c99d5bda5ac1b/base/policies.py#L89)、[policies.py:184–204](https://github.com/keruiwu/self-evolving-allocation/blob/ae7b5da1db39c0fd826adda7893c99d5bda5ac1b/base/policies.py#L184)。

这是一种随拉动改善、未拉动则状态不变的 bandit（rested rising bandit）。单调的是 running best，不是每个子代的成绩，更不是边际改进。停滞臂仍会重复反馈已有高分，算法并不直接惩罚“本次没改进”。论文源码内有被注释掉的 predictive reward / frozen-pool 方案，不能当成当前方法。正文 `main.tex:460` 明确说 end-to-end 10 次独立 LLM seeds；因此本记录也不把整篇实验定性为仅离线 replay。

**数值与局限。** C=512，Qwen3-8B HT：Greedy 0.6780、Shinka 0.7379、BaSE UCB 0.8530、Thompson 0.8736。CP 接近饱和：Greedy 0.9985、Shinka 0.9986、Thompson 1.0003。MMD 最好的是 EXP3P 0.9658，非 Thompson。来源：[主表](/home/fang/code/LLM4AD/papers/Compute_Allocation_in_Evolutionary_Search_From_Depth_Breadth_to_Multi_Armed_Bandits/bandit.tex:399)，399–427。这里只复述点估计，不把小差异当显著优势。主表 CP Thompson 标作 ±0.0174 SE，而正文 584 给出很窄 CI [0.9980,1.0004]，不宜据此做精确显著性结论。

固定 T=512、N=1 的 K 消融：Qwen3-8B MMD UCB 在 K=2 时 0.7172，K=5/10/20 为 0.9603，K=50 为 0.8634；HT UCB 从 K=2/5 的 0.8104 降到 K=50 的 0.6347。Llama HT 所有 K 都为 0（这是该固定配置，不能与主表的其他配置混用）。来源：[K 消融](/home/fang/code/LLM4AD/papers/Compute_Allocation_in_Evolutionary_Search_From_Depth_Breadth_to_Multi_Armed_Bandits/bandit_appendix.tex:1174)，1174–1216。支持“过宽会稀释精炼预算”，不支持“Init5 一定最优”；Base 的 5 个不同有效程序也不同于作者从相同现成种子开始的独立运行。

**迁移判断。** 若 Base 要比较 5 个独立开发过程，BaSE 是合适参照；若共享失败经验或跨谱系 Crossover 会改变另一个谱系未来分布，独立 rested-arm 假设不再成立。可把它作为经验调度器，但不能继承标准平稳 UCB 保证，也不能把历史最好成绩等同于下一次调用价值。

## 7. PhyloEvolve：轨迹上下文与预算统计必须分开评价

**作者机制。** 节点选择：

\[
p(n_i)\propto\exp((\alpha r_i+\beta\Delta r_i+\gamma/d_i)/T).
\]

r 是节点绝对成绩，Δr 是近期改进信号，d 是深度。树级分数混合当前最好、recent improvement potential、diversity。上下文包含根到节点轨迹、兄弟比较、精英轨迹和修改经验。作者用 edge delta reward 解释修改收益。来源：[轨迹及边奖励](/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/4_method.tex:12)，12–23；上下文 84–86；[选择公式](/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/4_method.tex:148)，148–170。

**未被公式解决的问题。** Δr 是节点出生那次增量，还是窗口内从它继续开发的增量，公式说明不够可执行；树 potential/diversity 的计算及权重未在该段具体化。d=0 时需单独处理，深度也不等于投入预算。不能从一个节点出生时改善大，推导它将来仍容易改进。

**实验能支持什么。** 实验比较 LLG / LTSA / GraphWave 内核性能，使用 GPT-5 规划、Sonnet 4 修改、GPT-4.1 总结，失败最多 3 次 debug retries。已核对的完整实验文件只有 62 行，主要是应用结果及图；没有控制调用预算的“去轨迹”“去动量”“随机 vs 复合选择”消融表。因此这里不能引用具体的轨迹选择收益数值，也不能声称父代公式得到因果验证。来源：[实验全文](/home/fang/code/LLM4AD/papers/PhyloEvolve_LLM-Powered_Evolutionary_Code_Optimization_on_a_Phylogenetic_Tree/tex/5_experiments.tex:6)，6–62，尤其 10。

**迁移判断。** 最适合借鉴状态—修改—结果的轨迹表示和失败保留。Base 已限定 8+3+2 上下文，没有证据要求再加入全路径、额外规划器、总结器或完整精英代码；这些都会改变生成机制和调用成本。要检验预算分配，应先固定当前上下文规则。

## 8. ShinkaEvolve：父代欠探索权重与模型 bandit 是两件事

父代 weighted sampling 使用 `sigmoid(λ(F_i−median(F))) / (1+N(P_i))`，其中 N 是 offspring count。它结合当前质量与已开发程度，不估计子代改进期望。论文另一个 bandit 选择的是 **LLM 模型**，奖励为 `exp(max(r_i−max(r_parent,r_init),0))−1`，不是父代 bandit。来源：[方法](/home/fang/code/LLM4AD/papers/ShinkaEvolve/sections/03_method.tex:12)，12–16、74。

当前源码额外用 MAD 缩放成绩差；`children_count` 在带 parent_id 的程序入库时增加，不要求该程序在该段被标为正确。但生成后被拒绝、未入库或 repair 内部的调用，不因此自动计入孩子数。来源：[父代权重](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/database/parents.py:374)，374–397；[入库计数](/home/fang/code/LLM4AD/reference_code/ShinkaEvolve/shinka/database/dbase.py:905)，905–911。

消融图 Fig.7 是 circle packing；正文说 weighted 优于 best-of-N 和 hill climbing，未提供可摘取的精确末值表。图注称 model bandit “slightly improves”，正文称“significantly outperforms”，没有统计检验就不把后者译作统计显著。来源：[分析](/home/fang/code/LLM4AD/papers/ShinkaEvolve/sections/05_analysis.tex:1)，1–23。新颖性 judge、解析重试、meta-scratchpad 都可能额外调用模型，不能按 generation 数与 Base 等预算比较，见方法 38、42、76。

**迁移判断。** 这是便宜的质量×欠探索参照，适合与直接子代产出估计比较；不要把其模型 bandit 的效果归给父代选择，也不因它使用 judge 就给 Base 增加 judge。

## 9. Base 最少需要澄清的记账与归因

以下是建议的语义约束，不是新增模块清单。

| 对象 | 记录什么 | 不应替代它的量 |
|---|---|---|
| 模型调用 call | 唯一 call_id、用途、返回状态、所属生成尝试 | 有效子代数、树节点数 |
| 一次开发尝试 attempt | primary_parent、辅助父代、算子、上下文版本、全部 call_id、最终状态 | 单个树边或 repair 后才出现的有效程序 |
| 程序节点 | 代码身份、有效性、评估成绩、出生关系 | 一次复制结果的新身份 |
| 父代直接投入 | 以它为主父代的尝试及调用总数 | 后代整棵子树大小 |
| 谱系投入 | 归属该区域的唯一调用集合 | 把所有节点累计 visits 再相加 |

**复制、失败、repair。** 一次生成失败再 repair 成功通常花 2 次调用，不是 1 次成功样本成本；修复失败仍花 2 次。复制花 1 次但不提供新的程序探索证据。把“没有产生有效新程序”的调用排除，会系统性高估容易复制/失败的父代。Init5 是成功个体数；初始化失败及 repair 也必须从同一个全局调用预算扣除。如果预算耗尽仍不足 5 个有效程序，应如实记录未完成初始化，而不是免费补齐。

一次生成尝试最终只产生一次最终收益，repair 不作为独立父代进化成功再奖励一次。调用逐条扣账、尝试最终归因，可以同时做到失败不免费和不重复奖励。如果剩余预算只有一次调用，则 repair 是否发生由剩余预算约束，不超过总额。

**奖励至少同时记录三种，选择器只使用事先选定的那一种。** 令 F 越大越好，q 为新有效子代，p 为主父代，B 为生成前全局最好：

- 产出质量 `F(q)`：对应 QUBE；容易奖励高分复制，应另记是否有效新程序。
- 局部正改进 `max(F(q)−F(p),0)`：对应继续开发该父代的直接进展；会偏爱容易从低分提升但远离前沿的父代。
- 全局突破 `max(F(q)−B,0)`：最贴近最终 best objective，但信号稀疏，无法单独给暂差新方向充分学习信号。

失败/复制的“新增收益”记零；有效退步的实际 Δ 必须保留在日志中，即使调度奖励截断为零。对多个尝试的成本归一化应使用 `Σ收益/Σ调用数`；不能把 `平均(每次收益/每次成本)`不加区别地当成同一指标。涉及不同算子，应先分层诊断；稀疏数据下不急于为每个父代×算子增加独立 bandit。

**冷启动。** 出生评估只观测自身质量，并没有观测“以它为父代”能生成什么。不要将出生高分直接伪装为一次繁殖成功。新程序可以从父代/同算子的共享先验得到平滑，但不能凭每次复制重新获得未尝试保护。全新有效代码也不自动等于新思想；若给每个节点强制一次机会，增长中的节点池可能吞掉几乎全部预算。因此保护总额必须有限，具体比例此处不锁定。

**非平稳性。** Base 即使保留相同父代代码，其最近 3 个有效子代、2 个失败会改变下一次提示；其他谱系又会改变 Crossover 输入。收益分布随上下文变化。历史均值和访问数不是严格的平稳置信区间。先记录 context 的实际内容/版本，再决定是否需要最近窗口或遗忘；不要用树深 λ 衰减冒充时间遗忘，也不在稀疏观测上贸然外推学习曲线斜率。

**交叉 DAG。** 保存主父代与所有辅助来源，形成来源 DAG；调度成本默认只归给发动该操作的主父代/主谱系是一种最简单、可审计的候选约定，辅助父代作为上下文贡献保留，不自动获得同额奖励。这是行政归属，不是因果贡献结论。如果采用双亲拆分，权重总和必须为 1，调用仍只消费一次；沿祖先回溯要按 event_id 去重，菱形路径不能让同一事件到同一祖先两次。Base 只展示主父代完整代码，更不宜假设两个父代对结果对称贡献。

## 10. 最小推荐与最值得区分的解释

**推荐优先级：先建立精确的 attempt/call 账本，再检验直接子代证据是否比质量×欠探索更有效；暂不默认整谱系 Thompson、冻结或多层 bandit。** 这既吸收 QUBE 最强的证据，也保留 Shinka 风格的简单参照。

如果必须提出一个首选候选方向，我会选“有效父代上的直接产出统计，含失败/复制与 repair 成本，有限冷启动；轨迹仍按现有 8+3+2 供生成器使用”。奖励先比较绝对产出与局部正改进，不把后者偷偷称为 QUBE 原算法；当前质量可保留为先验或参照，但不要在没有证据时再堆质量、动量、深度、clade、diversity 五种权重。

**唯一优先检验的问题：当前高质量父代与历史直接开发效率，哪个更能预测下一段调用带来的有效新进展？** 固定初始化、算子、上下文、repair、预算，比较简单质量×欠探索参照与直接子代证据选择；不同时改提示。评估最终 best 与按实际调用对齐的改进，另看复制/失败/repair 份额，避免把“抽到了更容易成功的程序”误报为“思想潜力被识别”。这是未来实验建议，本轮未运行。

轨迹只需回答一个会改变后续机制的补充问题：**关键改进是否经常来自先退步的有效节点，并且这些节点在直接收益规则下会被饿死？** 若答案有实质证据，再做同一生成机制下的直接归因 vs 唯一事件 clade 归因；否则先不加全谱系奖励。历史日志能揭示这种路径是否存在，但不能反事实证明换一种分配后会生成同样后代；不能把删减旧日志当新策略的真实运行。

## 11. 结论的证据强度

较强、可直接使用的是：QUBE 对自身质量与后代产出的区分；MCTS 的 max-backup 和 visits 实际语义；BaSE 的运行级分配与 running-best 奖励；Clade 本地代码的重复证据路径；所有方法的预算口径差异。

尚不能从这些论文推出的是：Base 最佳探索比例、固定窗口长度、λ=0.8 最优、5 个初始个体最优、谱系必对应思想、跨谱系交叉的因果信用、或长期潜力已可由一次出生改进识别。当前最小建议是一个可检验方向，不是已验证最适合 Base 的定案。
