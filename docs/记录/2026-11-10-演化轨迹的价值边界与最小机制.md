# 演化轨迹的价值边界与三个机制的最小职责

日期：2026年11月10日，北京时间。

本文综合前两轮的[效果核对](2026-11-10-Base与三个轨迹机制的效果和认识修正.md)与[信息增量分析](2026-11-10-演化轨迹的信息增量与三个机制的作用位置.md)，进一步回答：轨迹何时值得使用，何时产生负作用；三个机制如何保留必要部分；还有哪些用途值得研究。

本文的主实验判断沿用11月10日09:22的冻结截面，不是实时进度报告。历史实验使用各自源码、模型与评价条件。本文提出的是我的研究判断与候选改进，没有修改机制、运行实验或将建议写成已确认的WWH设计。

## 1. 我目前最相信的判断

**轨迹最有用的部分，是把起点、实际修改、实现条件、结果和成本联系起来。** 最终程序和成绩只能说明现在是什么；这些关系还能说明此前试了什么、哪些变化没有真正被检验、哪些经验有反例。

这不要求每次消费整条祖先链。当前最直接的正向证据来自同起点的少量修改与结果。完整路径更适合回答形成过程、计算丢失、配套依赖与延迟收益等具体问题；它不是所有决策的默认输入。

我的总体建议有四点：

1. **机制2优先服务精炼（Refine）。** 把已尝试修改作为比较材料，帮助生成新的有效修改。不要把历史赢家变成反复照抄的答案。
2. **机制1优先学习可比动作的实际回报。** 当前质量相近时，历史开发响应可能改变预算判断。形成路径特征与最远轨迹参考的独立增量尚未证明。
3. **机制3优先纠正和迁移带条件的计算认识。** 只有本地材料不足、其他分支能提供补充或反例时，独立反思才有明确职责。更多笔记和更抽象的措辞不是收益。
4. **不要求三个机制都成为固定开启的在线模块。** 三种用途都成立为研究问题，但证据强弱不同。最简单的充分方案可以是局部轨迹生成，加上轻量反馈分配和按需跨分支反思。

我尤其撤回一个容易从“轨迹有价值”推出的过强建议：**看见退步中的新想法，不应自动增加修复预算。** 已有四臂实验没有证明这比直接改进较好祖先更划算。

## 2. 轨迹究竟多提供了什么

### 2.1 增量来自关系，不来自记录长度

| 信息 | 只有静态代码与成绩时缺少什么 | 最直接的用途 |
| --- | --- | --- |
| 实际父子转换 | 不知道从哪个起点改了哪些计算、修复又改变了什么 | 定位变化，区分设计意图与实际实现 |
| 同起点的多次尝试 | 不知道相近条件下哪些改法已试、成功失败如何分布 | 选择下一项修改，估计动作回报 |
| 连续接续 | 不知道某计算何时出现、丢失、恢复，是否依赖后续配套修改 | 查依赖、回退与多步发展过程 |
| 跨分支的相关转换 | 不知道同一改法在不同计算背景下是否仍成立 | 发现适用条件与反例 |
| 完整尝试与成本 | 最终赢家隐藏了失败、重复、修复与选择机会 | 判断实际搜索效率，避免幸存者偏差 |

其中，错误、耗时和单个程序的行为可以独立记录，不天然属于轨迹独有信息。轨迹额外把它们归属到具体起点、修改和接续过程。代码差异也不自动等于行为差异；有序记录更不自动等于因果识别。

两个同起点子代比任意两份好差程序更可比较，但仍可能同时改了多个部分、使用不同提示、受随机执行或墙钟停止影响。只有观察到`P → P+A → P+A+B`，不能证明A是必要条件；还缺少`P+B`等能区分解释的对照。

### 2.2 历史有两种不同作用

**第一种是更新判断。** 程序、提示、模型和采样分布不变时，多次尝试主要更新我们对该动作回报的估计。程序不会因为被抽取过几次就必然“耗尽”。观察到后期成功率下降，还可能来自冠军门槛上升、被保留节点不同或选择策略变化。

**第二种是改变生成。** 把历史放入提示，或用反思改变指令，会改变下一次生成的分布。这时旧提示下的回报不再天然适用于新提示。

这一区分直接影响三个机制的协作：机制1不能把机制2、3改变上下文前后的记录都当成完全同分布反馈；机制2、3也不能仅因加入了信息就假设生成只会变好。历史既能提示新修改，也能诱发模仿、保守化与错误禁令。

### 2.3 什么才算正增益

保存记录、解释现象、提高预测准确率、改善一次生成、提升最终搜索结果，是不同层次的成果。

在本文中，“有助于理解”指排除了错误解释或形成了可检验判断；“局部生成增益”指固定起点和生成条件下的产物改善；“搜索净增益”指在约定资源约束下，最终选定算法更好。不能从第一层直接跳到第三层。

当前正式比较固定评价次数，反思与嵌入另计。因此，等评价次数下更好不自动等于等总成本更好。新增诊断或检验应说明它省下或挤占了什么预算；没有共同成本口径时，分别报告评价、模型调用、token与时间，不把不同单位硬减成一个收益分数。

## 3. 现有证据支持哪些正负判断

| 问题 | 已观察到什么 | 当前判断与边界 |
| --- | --- | --- |
| 同起点材料能否帮助生成？ | 固定提示消融中，删除子代材料降低子代改善率；删除祖先段没有测出变化。[E1] | 有局部正向证据。支持优先保留相关尝试，不证明所有任务或最终搜索都获益，也不证明祖先无用。 |
| 机制2是否整体稳定有效？ | 旧V21在多数任务的测试均值更好；新共同Base下，TSP改善、OP退步。[E1] | 整体收益依赖选择、算子和提示条件。旧比较同时改变了不止轨迹内容。 |
| 历史材料是否也会诱发浪费？ | 近冠军父代的Refine日志中，机制2会生成与已有同起点子代规范化源码相同的程序，多数复制对象是已知最好子代。[E2] | 重现已知程序是实际失败模式。跨批次比例尚不能独立归因于某一展示方式。 |
| 机制1是否已经证明形成路径有用？ | 新V23.2在已完成TSP、OP有正向结果，并把更多预算移向近冠军父代；关闭路径权重会改变选择。[E1] | 整套机制已有局部收益；路径特征的额外预测力、收益分配与参考选择各自贡献未分离。 |
| 退步后修复是否值得优先？ | 四臂实验中，诊断后从退步子代修复没有胜过直接精炼较好祖先。[E3] | 不支持因“可解释、可恢复”就提高优先级；也没有证明所有定向修复都无效。 |
| 是否有跨越退步后获得更好算法的真实路径？ | JSSP存在新候选结构经修复退步、再补充计算后刷新冠军的路径；小型等预算接续却未取得全局突破。[E4、E5] | 这类机会存在；能否事前识别并优于其他预算用途仍未证明。 |
| 轨迹反思是否产生可靠经验？ | TSP反思将特定实现退步概括成内部2-opt禁令；实际代码有评分与返回动作不一致，窗口内另有内部2-opt改善的反例。[E1] | 已证明解释和泛化可能出错。修正后的条件经验是否改善其他分支仍待验证。 |
| 多一些轨迹特征是否必然提高价值预测？ | 历史整路留出预测未给出稳定增益；部分看似新结构的改动实际上不改变决策。[E4、E5] | 不支持继续堆叠趋势、AST距离和“有效次数”代理，需先核实它们代表什么。 |

**四臂实验是必须保留的反向证据。** 120个案例中，119个有可比较的重评祖先。每臂两次生成与评价，诊断修复B超过祖先的案例为12个，直接精炼祖先A为19个；B−A的区间跨过零，不能据此断言B确定有害。从较好祖先移植同一新想法的D也没有确认胜过A。实验使用历史Base/V19.1案例和DeepSeek，不能直接当作当前Qwen机制的效应量。[E3]

更值得警惕的是诊断质量：所有案例都被模型判为定位到问题；盲读20例源码，仅3例可确认具体计算或搜索损失，5例只是性能假设，12例不成立或含关键错误。**输出了清楚的解释，不代表解释正确；解释正确，也不代表修复值得。** 本实验没有单独识别诊断错误对收益的因果贡献。[E3]

另一处需要收窄的表述是“相同代码成绩确定相同”。E2核查的复制案例确实同分；但历史FSSP存在无种子`default_rng()`，图着色存在墙钟停止，同源码也出现不同成绩。因此，重复识别与评价缓存必须保留运行条件，不能从这些局部记录推到所有任务。[E5]

## 4. 哪些用法更可能正增益，哪些更可能负增益

下表区分的是具体用法，不是给“祖先”“失败”“反思”本身贴正负标签。“可能正向”中未被独立验证的部分仍是设计假设。

| 同一种轨迹材料 | 更可能产生正作用的用法 | 更可能产生负作用的用法 | 决定方向的变量 |
| --- | --- | --- | --- |
| 失败修改 | 说明哪个具体实现、什么条件下失败；允许换实现或补条件后再试 | 把一次失败概括成算法思想禁令 | 是否真正实现目标计算，是否有相关反例 |
| 成功修改 | 看清实际改动，保留有效计算并尝试进一步改进 | 抄回已知最好子代，把赢家所有组件都解释成必要 | 是否带来新行为，改动是否混杂 |
| 同起点多次尝试 | 比较可比动作的响应，识别真正重复或未被检验的方向 | 用尝试总数机械惩罚节点，把“试过”当作“试尽” | 算子、提示、实际修改与结果是否可比 |
| 祖先路径 | 按需追查一项计算何时丢失、何时需要配套调整 | 每次输入整段谱系，鼓励沿原结构继续堆补丁 | 当前问题是否需要形成过程 |
| 退步与恢复 | 检查恢复后保留了什么新能力，再与好起点的接续比较 | 把回到已有水平算成新收益，为沉没成本继续投入 | 相对现有最好和替代预算用途的回报 |
| 跨分支案例 | 用一致计算关系和反例限定适用条件 | 用代码或文本相似代替机制相同 | 相关计算背景、接口和尺度是否一致 |
| 形成路径差异 | 在质量可比时检验是否补充开发响应信息 | 把出生增益、回撤或趋势当作固有潜力 | 是否增加留出预测及实际分配收益 |
| 交叉参考经历 | 查清可移植计算依赖什么、接收方缺什么 | 默认轨迹距离越远越互补 | 可接入性与实际交叉回报 |
| 经验笔记 | 保留来源，出现反例就收窄或撤回，按问题读取 | 同一失败反复总结成多条“证据”，让旧结论压制新尝试 | 独立来源、计算真实性和当前相关性 |
| 行为探针 | 验证具体怀疑，知道探针覆盖了什么 | 少量输入同输出就宣布算法等价或没有潜力 | 输入覆盖、随机性、外层调用方式 |

这些用法解释了一个表面矛盾：**同起点历史可以同时提高部分修改的有效性，又增加复制已有子代的次数。** 因此，保留这类材料与改进其呈现方式并不矛盾；不能因复制而删除全部历史，也不能因局部改善而忽略浪费。

### 最影响判断的五个认知误区

1. **把发生顺序当成原因。** “加入A后退步”只定位到一次转换。若同时改变B、修复删除C或测量条件变化，就不能只怪A。轨迹应帮助提出区分解释的检验。
2. **把相对弱起点的改善当成预算价值。** 容易修好的坏程序可能很快改善，却一直低于已有好程序。恢复、新发现和最终突破需要分开。
3. **把历史数量当成证据强度。** 同一来源的多次反思不是独立重复；相同节点的不同提示也不是同分布采样；没有被继续开发的分支不能标成零潜力。
4. **把“高层经验”等同于更宽泛的结论。** 有用的抽象应抓住跨实现保持的计算关系，并说明边界。比如“模拟评分对应的首动作必须与返回动作一致”，比“保持几何纯净”更可执行。
5. **把一切系统改善归功于轨迹。** 合理的质量温度、清楚的任务说明、输出格式、代码检查和普通参考多样性都可以独立改好。轨迹增量必须在这些共同能力之上判断。

其中最该先纠正的是第一项与第二项：它们分别让机制3产生过强禁令，让机制1高估容易恢复的差起点。机制2则最需要解决“使用证据”与“模仿例子”之间的混淆。

### 对“轨迹只有排除性价值”的进一步判断

同期[另一份价值审计](2026-11-10-演化轨迹的价值边界.md)提出，轨迹目前主要用于排除重复与低产出尝试。我同意把这些用途优先做实，但不采用“排除性可靠、生成性不可靠”的整体划分。这会影响机制是否被过早删掉。

首先，同起点材料已有生成改善证据，但尚未分离它究竟通过避开失败、沿有效方向继续修改，还是其他方式起作用。不能把未知的内部过程全部归为排除。反过来，多次未改善只能降低某动作值得继续的估计，不能可靠证明节点已经耗尽。即使提示完全相同，容易改善的冠军被替换、难改善的冠军留下，也会产生随尝试数下降的群体曲线。

其次，`replay.py`用“相同新增代码行集合”识别跨节点重放，未对删除行、顺序、数据流和适用条件作等价检查。它发现大量重建旧程序，足以提醒机械复制无效；但不是条件经验迁移的受控检验，不能据此断言机制3所有可能形式都无价值。`failures.py`中的重复错误也是归一化报错信息重复；同样的超时或异常文字可能对应不同原因，不能直接复用一次修复结论。[E2]

最后，程序去重和结果缓存需要静态代码存档，不需要演化关系；只有评价条件可比且随机性得到处理时，复用结果才合适。它可能是很值得做的工程优化，却不能被计作父子关系、路径或经验推理的独立收益。

因此，我保留更窄的结论：**目前最值得利用的是可以核查的局部事实；排除、生成、分配和迁移，都应分别证明它们怎样使用这些事实。** 不确定的推广应收窄，不必先按用途名称一概肯定或否定。

### 保守性能够解释多少

用户进一步问，以上正负作用能否归纳为模型的保守性。我认为，向已有方案收缩是机制2、3值得检验的一条解释，但不能概括全部作用，更不能直接认定是模型固有属性。这里至少要分开两个变量：模型缩小了多少修改范围，以及它是否根据可靠证据缩小了正确的范围。

如果“保守”指保留已验证计算、减少无依据的大改，它可能帮助Refine；如果连实现错误导致的失败也被推广为整个思想不能用，就会压制仍有价值的方向。与日志相符、尚未隔离验证的一条解释链是：现任程序已被筛选，多数新修改不如它；反思将这种结果误读为现任结构普遍优越，后续提示进一步收窄修改，再缺少反例来修正原解释。

但复制一个并不优于父代的历史子代，更接近示例模仿；把2-opt实现错误推广为算法禁令，包含错误归因；旧机制1把下行波动估成上行机会，则是收益模型过度乐观。它们不能都用“不愿冒险”解释。轨迹中的反例还可能解除禁令、支持结构改变，因此轨迹并非只能让模型更保守。外部锚定研究显示影响依赖上下文进入方式，可作为这种区分的参照，不能替代本项目检验。[AnchorBench](https://arxiv.org/abs/2608.14320)

最有判别力的对照，是固定父代、算子和预算，比较轨迹材料与无轨迹但明确要求保留主要结构的提示。先检查实际修改幅度与多样性是否接近，再比较修改指向和收益。若一般保守提示就能复现收益，轨迹的信息增量较弱；若在相近修改幅度下轨迹仍能更准确地选择修改对象，才支持它提供了超出普通保守约束的信息。仅凭平均改动小或复用率高，无法区分这两个解释。

## 5. 按奥卡姆剃刀保留三个机制的最小职责

### 5.1 机制1：同等机会下，哪些动作已有更好的开发响应

**保留的职责：** 在共同质量偏好之上，利用可比的真实尝试与成本，小幅修正父代—算子的投入；交叉参考选择单独检验。

最先利用同起点、同算子的反馈。记录稀疏时可以借用其他起点的反馈，但当前质量、生成方式和评价条件要可比。当前实现已经使用近期窗口、真实冠军改善、共享反馈收缩与修正封顶；无需因本轮讨论再加一个LLM价值评审器。

形成路径的出生算子、出生增益、动量与回撤，只能作为待验证的额外信息。当前它们改变选择，尚未证明比普通反馈更准确。**若去掉它们不损失实际分配收益，就应删掉这层权重，而不是再加更多轨迹特征。** 同理，最远轨迹嵌入参考若不优于同池随机参考，就不必保留。

需要先处理的共同背景是质量尺度。默认`tau=1`使用原始fitness单位，在任务间形成不同选择压力。当前机制1可能部分补回了Base在某些任务上过弱的质量集中；这是一种有用行为，却不能证明轨迹看到了额外潜力。后续完整比较应在训练条件内预先固定共同温度，再分离普通反馈、形成路径权重和参考选择。

我不建议恢复机械次数折扣，也不建议现在增加多步前瞻、按祖先身份加分或保护所有退步分支。历史接续能证明机会存在，但既有修复与接续实验没有证明广泛保护它们的净收益。是否要学习延迟收益，应由可比接续结果决定；把后来冠军的收益重复记给所有祖先会夸大证据。

**继续保留的判据：** 质量、参考和生成条件固定后，历史反馈确实使下一份预算更有效；形成路径只有在此基础上仍有增量才保留。

### 5.2 机制2：用少量相关比较帮助下一次Refine

**保留的职责：** 当前完整代码，加上与本次修改相关的少量“实际改动—实测结果”对照。优先回答：什么已经有效尝试、什么计算需要保留、下一步究竟改变哪里。

最小做法可以直接使用现有attempt记录，不新建一套经验模型：默认不铺满祖先和全部子代；保留足够理解改动的代码上下文，将结果紧邻对应差异。选择材料要按当前问题相关性，不能固定把“最好子代”当成答案模板。成功子代可以展示，但目标是继续改变它所揭示的计算关系；如果只是想采用它，应直接选已有程序，不再花生成预算复现。

对失败的提示应限定到具体实现。例如，“这次修改没有改变训练输入域中的候选排序”，比“这个方向已经试过，不要再试”更准确。没有检查行为时，只能写“这次实现未改善”，不能升级成整个思想无效。

祖先材料按问题调入：需要解释当前组件为何存在、某次修复丢了什么、某计算是否依赖前置变换时再读。长路径不是默认更好的Refine提示。

交叉（Crossover）只增加与接入有关的证据：参考计算依赖的表示或调用条件、接收方已有的接入失败。当前跨批次审计提示交叉与精炼方向不同，但同时存在参考呈现和算子指令差别，不能直接认定历史造成交叉退步。探索（Explore）当前不读轨迹；没有相关证据时维持简单输入，不为三个算子形式统一而强塞历史。

**继续保留的判据：** 固定起点、算子和生成协议，少量局部证据提高新的有效修改及突破机会，同时避免通过复制已有候选制造“改善”。

### 5.3 机制3：本地证据不足时，跨分支迁移或修正一个认识

**保留的职责：** 从当前节点之外带来能改变具体修改的计算关系，或用反例纠正已有认识。仅复述当前父代的子代历史时，不需要另建机制3。

这里也包括较早、已不在当前局部视图中的相关经历，不要求证据一定来自另一条分支。判断标准是增加局部材料之外的有效信息；若收益只是把同一局部材料表达得更简洁，可以直接作为机制2的组织方式。

当前固定每10次尝试反思，持续存储经验、每次最多展示6条。存储上限与展示上限不能混淆。真正需要收敛的是无新证据也重复产出结论，以及把具体实现失败推广为广泛规则。

我建议先试最小的按需方式：出现相关的新对照、反例，或明确的跨分支问题时，才更新对应认识。每条只需说清**适用计算条件、支持或反对它的来源、下一步具体改变什么**；证据不足时保留为问题。现有来源链接与笔记结构能够承担这些内容，不需要再加多层审查代理或一个不可校准的“经验置信分”。

TSP例子适合检验这一职责。待迁移的内容是：若用模拟后的路径评价候选首动作，路径优化需保持该首动作，或让返回动作与评分对象一致。静态代码检查也能发现这个不变量；轨迹额外提供发生退步的位置，并用另一实现的改善反驳“内部2-opt有害”的禁令。真正的机制3检验，是这条关系能否帮助另一个实现保留有价值的2-opt并避免同类错误，而不只是写出更漂亮的笔记。

**继续保留的判据：** 相对机制2的局部材料，跨分支经验改变了正确的计算并改善结果；若没有额外信息或收益，就不调用反思。尚不能把本例代码修正等同于已经证明整个任务的净收益。

### 5.4 三者协作不意味着三套记忆和三层模型

现有真实记录可以提供三种视图：机制1读取可比回报，机制2读取相关修改，机制3读取跨分支支持与反例。统计可以缓存，笔记可以压缩，但都应回到同一来源；不必把三份摘要当成三份事实。

选择决定哪些局部记录会积累，上下文决定下一次响应，反思又可能改变上下文。因此，**正向单模块效果不保证叠加后仍正向。** 机制1过早排除某类起点会让机制2缺少相关对照；机制3的禁令又可能让机制1误以为整个方向没有机会。

最简单的处理是保持模块开关与来源条件清楚，让各自承担一项可检验职责。没有证据时不增加一个总协调器。当前数据更支持“机制2作为主要生成用途，机制1轻量校正，机制3按需迁移”的研究优先级，不支持三个固定全开的对称设计。

## 6. 三个环节之外，什么用途真正适合轨迹

### 6.1 优先研究：用已有分歧决定下一次该检验什么

三个机制主要使用已经产生的结果。另一项不同职责是**改善后续证据的产生**：从轨迹中找出尚未被区分的解释，选择一个便宜、能改变判断的检验。

历史图着色案例中，父代增加的小图分支在当时输入域没有进入实际求解，连续无改善不代表原有重启方向失效。轨迹把此前有效的重启变化与后来没有检验该方向的修改联系起来。TSP的少量状态探针曾高估行为相同，改为完整路线后判断明显变化；这说明还需检验“探针是否覆盖真正的决策差异”。[E4、E5]

最小使用方式是：只对会改变下一步投入或经验结论的争议，做一次有针对性的代码检查、行为探针或受控替换。例如区分“2-opt这一思想有害”和“评分动作与返回动作错位”，应先保持其他计算不变检验首动作一致性，而不是再写一轮自由反思。

若要确认A与B的配套关系，就补足能区分“A有效”“B单独有效”“A需B才有效”的关键对照。这里轨迹的额外价值是指出缺哪一个对照；设计实验本身是已有能力。

这是我最看好的新增研究用途，因为现有失败多次暴露了证据解释和测试覆盖问题。**尚无本项目净收益证据。** 不建议给每个候选都加诊断或测试；只有检查成本低于它可能避免的错误投入时才值得。检查使用训练条件或独立合成状态，保留原始评价与固定主测试，不能用主测试反复指导设计。

### 6.2 明确适合：版本回退定位、回归测试与局部修复

“上一版通过，这一版失败，实际只改了这些部分”与轨迹天然匹配。它可以缩小检查范围、提取复现输入、分离引发失败的改动。差分调试（Delta Debugging）已有通过反复测试缩小失败输入和通过／失败差异的做法；这证明该操作可以具体实现，并不证明我们的自动修复会有收益。[Zeller与Hildebrandt，2002](https://www.st.cs.uni-saarland.de/papers/tse2002/)

在TraceAAD内部，这更适合作为机制2的专项用法，以及机制3的证据核查工具，不必命名为第四个在线机制。优先处理可复现的错误、接口不一致、确定未生效的计算或可定位的行为回退。

不能据此推广为“修复所有退步版本”。四臂实验已说明，仅凭分数下降和模型诊断来挑修复对象，没有证明优于精炼好祖先。[E3] 软件回归定位与算法性能修复的目标也不同：前者可能只需恢复必需功能，后者还要超过已有候选并抵偿机会成本。

### 6.3 适合离线积累：学习如何修改，而非只学习好程序长什么样

轨迹可形成`起点＋条件＋实际修改＋结果`的训练材料。相对只收集最终冠军，它保留了从不同起点如何变好、哪些实现错误重复出现，以及修复付出多少成本。适合研究修改器、失败诊断和条件化收益预测；训练方法本身不属于轨迹独有能力。

这项用途可能把多次在线反思的成本转成可复用的离线学习成本，但前提是数据量足够、任务或模型条件能迁移。当前没有验证，不宜作为近期主线替换。

数据整理要保留失败与重复，不把模型自写解释当真标签；训练和验证按整路搜索或来源分组，不能将同一谱系的近重复程序分到两侧。后代结果可以作为离线监督目标，但生成时特征只能使用当时可见的前缀。未被尝试的动作没有反事实标签，离线重放不能自动证明新策略的在线收益。

### 6.4 可迁移到哪些外部任务

| 领域 | 为什么适合轨迹 | 哪些条件使价值下降 |
| --- | --- | --- |
| 软件修改、编译优化与性能调优 | 能保存版本、差异、运行条件和复现测试；可检查变换顺序与组件交互 | 多项同时改动、环境漂移或性能测量噪声大；代码差异不足以独立解释性能 |
| 顺序实验与工程参数设计 | 同一对象上连续干预，结果可反馈到下一次条件选择 | 测量昂贵、条件不可回退、隐含环境变化；自然记录难以替代受控实验 |
| 有可验证状态的工具工作流 | 能记录实际动作、状态变化、错误与恢复，定位在哪一步失效 | 只保存语言理由或只有稀疏终局评分；外部状态不可观测、不可复现 |

这些是从信息结构推导的适用性判断，不是本项目已验证的跨领域效果。最适合的共同条件是：**修改可定位，反馈可比较，运行可复现，未来还会遇到相似的决策。** 若只有最终分数和一段事后叙述，轨迹学习很容易变成故事学习。

## 7. 哪些已有能力不应混入轨迹增量

调整质量温度、优化通用提示、改变输出顺序、静态代码检查、普通多样性维护、缓存重复程序、语义检索和保存笔记，都可以在没有演化关系时实现。

历史成功率、父子反思、条件经验和路径提示也已有方法使用。ReEvo比较算法并积累反思；RefineEvo有算子效用反馈、父子情境反思和带适用条件的正负经验；MCTS-AHD使用树上的结果和路径材料。[ReEvo §4](https://arxiv.org/html/2402.01145v3)、[RefineEvo §3.2–3.3](https://arxiv.org/html/2607.11358v1)、[MCTS-AHD §3](https://arxiv.org/html/2501.08603v1)

这意味着要分开两个问题：相对当前静态Base，多读实际转换能增加什么；相对已经使用历史的方法，更准确的比较与更合适的使用位置还能改善什么。本文集中回答前一个信息问题，并用后一个边界防止重复发明。已有论文提供功能参照，不替代我们自己的增量检验。

## 8. 下一步怎样用最少工作改变决策

我建议先集中验证一个问题：**少量可信的同起点证据，能否让模型提出新的有效修改，而不是复现已有代码？** 这既对应最直接的正向证据，也对应已经观察到的浪费。

固定生成前的真实状态、Refine指令和输出协议，比较仅当前程序、现有完整材料、精简的相关修改与结果。使用预先选定、具有真实历史的起点；结果同时看新程序、复制、有效改善与冠军突破，不能只看弱父代改善。若精简材料不损失收益且降低复制或成本，就没有必要默认读取更长历史。局部检验成立后，再验证整路收益。

其他机制各自只需要一个会改变保留决定的检验：

| 对象 | 最关键的区分 | 结果将改变什么 |
| --- | --- | --- |
| 机制1 | 共同质量尺度、随机参考与相同生成条件下，普通反馈之外的形成路径权重还有没有收益 | 决定保留路径特征，还是收敛为简单反馈分配；参考嵌入另做独立对照 |
| 机制3 | 在相关但不同实现上，无经验、现有经验、纠正后的条件经验是否产生不同且正确的修改 | 区分“不需要额外经验”与“当前经验内容错误”，决定是否保留独立反思 |
| 新增检验用途 | 一次定向检查能否排除错误解释，并比直接继续生成更有效地使用预算 | 决定是否按需接入检查，而不是建立普遍诊断流水线 |

不应先扩大诊断修复四臂实验、增加反思层级或加入更多形成轨迹特征。现有结果首先要求改进证据的真实性、相关性和使用方式。

我目前对三个机制的最终判断是：**都存在合理的轨迹作用位置，但没有理由保证三个都获得正净增益，更没有理由让三个都默认读完整轨迹。** 机制2有最直接的局部材料证据；机制1需要证明质量与普通反馈之外的增量；机制3需要证明跨分支迁移而非重复总结。能以更少信息完成同样决策时，就删掉多余材料和步骤。
