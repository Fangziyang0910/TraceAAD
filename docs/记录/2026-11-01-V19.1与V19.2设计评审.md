时间：2026-11-01，北京时间。状态：主审、三份独立评审、边界复现与分歧裁决均已完成。

## 我目前最相信的判断

我认为，问题有价值：有限预算下，当前程序的成绩不能直接代表继续开发它的价值；生成器还会重复熟悉机制，导致保存许多程序却没有持续开发不同方向。但当前证据尚不能把 V19.1/V19.2 写成已经解决这个问题的方法。

V19.1 是一个合理的选择器假设，不过当前默认配置几乎抹掉了质量信号。V19.2 更有意思的设计是以可观察的生成关系划分连续开发单元，并限制信用跨越设计转向。但它同时引入了质量映射、信用传播、局部收缩、两层探索项和三层分配。这些组件尚未形成证据充分的最小机制，而且存在可以复现的反例。

我不会把“公式更多”当作更深入地理解开发过程。当前最重要的工作是确认轨迹信息确实改变了有用的预算决策。

## 1. 到底在解决什么问题

我把三个问题分开：

1. **生成问题**：新机制是否真正进入返回决策，Refine/repair 是否保留有效计算。
2. **分配问题**：已经出现的候选是否得到值得投入的后续开发机会。
3. **识别问题**：两个程序是否代表不同算法思想。

已有 Base 轨迹能支持前两个问题确实出现过。某个有效候选后续机会少，并不能单独证明它值得更多机会；它可能被低估，也可能继续投入后仍然无效。第三个问题在 V19.2 中没有被解决，文档对此已有明确限定。

科学问题可以表述为：

> 在相同生成器与真实成本约束下，利用可观察的开发记录，能否比仅用当前成绩或访问次数，更有效地决定继续哪个候选、执行哪种操作，从而改善预算结束时找到的最好程序？

这里的最终目标是有限预算后的最好结果。后代平均质量只是一个代理量。高平均质量、持续改进、偶尔产生突破、最终找到最好程序，是四个不同变量。当前公式主要估计前者。

例如，一种动作总能得到质量 0.8 的程序；另一种动作有 10% 概率得到 1，其余得到 0.1。前者平均质量更高。如果当前最好质量已是 0.9，只有后者能改善前沿。这个例子说明估计对象的区别，不是建议直接改用单步改进率；单步改进率也可能排斥需要多步开发的起点。

## 2. 哪些设计值得保留

**父代价值具有算子条件。** 同一个程序的 Refine、Explore、Crossover 对应不同的生成分布。让条件统计参与决策有清楚的机制动机。但数学上，先选算子再选父代也定义联合分布；真正需要检验的是条件信息和自适应边际的价值，不是抽样顺序本身。

**固定含义的历史质量。** V19.2 不再因新候选入库而重写旧结果的质量。把最终结果冻结在 Attempt 中，也使修复与原动作的归属可审计。这个方向正确，具体的五点初始化尺度仍需修正。

**开发段的价值在于明确共享边界。** 同一条连续 Refine 链不必被当作彼此独立的方向；Explore/Crossover 则可能形成新开发任务。直接使用生成关系，避免先解决完整的语义思想识别，具有实际简洁性。

**记录、成本和修复归属清楚。** 不额外引入 LLM planner；一次生成和最多一次修复共属一次动作；请求、评价和失败分别留痕；保存联合与条件概率。这些使机制能够被证伪和简化。

## 3. 直接影响当前决策的问题

### 3.1 V19.1 的质量信息几乎不影响实际分布

位置：`traceaad_v19_1/selection.py:15–34, 193–238`。

**观察。** 各路最后 200 次已完成演化动作中，73.0%–82.5% 的选中组合此前没有被试过。探索项占总分的中位比例为 99.11%–99.59%。

我进一步在每路冻结末态上重新计算完整联合分布，将所有质量相关的均值项置零，只保留访问次数形成的探索项、算子先验和原有 5% 混合。18 路的总变差距离为 0.001677–0.003251，即只移动约 0.17%–0.33% 的概率质量。

**解释。** 动态倒数排名使多数程序的质量随库增长而接近零；新动作不断出现，未访问动作仍得到约 1.3 的加法奖励。比例归一化把这项大基线扩散到大量动作。当前机制主要近似于按访问次数分配的广泛采样。

这比“公式里有历史质量”更有解释力。它不证明删除质量后完整搜索结果一定不变，因为反事实选择会改变后续库。它已经足以否定“当前质量与轨迹信号明显主导这些决策”的解释。

**最小处理。** 先用现有日志检查质量项相对探索项的决策影响，再决定尺度与探索形式。不要立即为稀疏组合再加一层统计。

### 3.2 V19.2 的初始化尺度会饱和，也会被宽尺度压平

位置：`traceaad_v19_2/selection.py:40–64`。

**合成反例。** 五个初始化成绩都是 100 时，IQR 为零，尺度退化到约 `1e-7`。后续成绩 99 与 50 都映射为精确的 `q=1`，无法区分改进幅度。只得到一个有效初始程序的配置也会出现同一问题。

**实际候选上的压力检查。** 将当前 V19.2 映射离线应用于 V19.1 的既有候选，图着色 rep1 与 OP rep3 的初始化 IQR 为零，分别有 142、684 个有效候选映射为精确的 1。JSSP 有些批次的初始化又包含质量差异很大的程序；尺度过宽会把后续有意义的差别挤在很窄区间。

这是对映射的压力检查，不是 V19.2 的实验成绩。它表明退化输入确实会由当前生成过程产生。

**最小处理。** 保留稳定的历史语义；重新验证质量映射在本任务的分辨率和实际候选范围内能否保留差异。先处理零 IQR 与尾部压缩，不靠增加后续选择层弥补信号丢失。`MAD` 同样可能为零，换一个离散度名字并不足够。

### 3.3 段的探索奖励仍可由新叶子重置

位置：`traceaad_v19_2/selection.py:335–346`。

段值使用 `max V(p)`，而探索量是各程序自己的 `N_T(p)`。一个已经得到很多 Refine 子代的段，只要还有未开发的有效叶子，就仍有 `N_T=0` 的成员。

**合成反例。** 同一根产生 99 个代码和成绩完全相同的有效 Refine 子代。根的轨迹权重已达 49.5，新副本仍为 0；段的最大值继续含有完整的未开发奖励。

因此，取最大值可以移除“同值条目相加”的直接数量优势，却不能保证段的开发不确定性随累计投入下降。边界必须写清楚，不能把这个最大值直接称为段级证据汇聚。

**最小处理。** 若要表达段已被开发多少次，计数应落在段级尝试上，并在该段内共享；是否需要折扣祖先信用，应单独证明。先验证最简单的段级访问次数是否足够。

### 3.4 Explore/Crossover 的标签仍可制造新的竞争份额

位置：`traceaad_v19_2/selection.py:92–110, 341–351`。

**合成反例。** 关闭探索奖励以隔离归一化因素，根程序与另一个初始程序竞争时占 73.1%。若九次 Explore 返回与根完全相同的代码和成绩，它们全部成为新段，同一实现及其副本合计占 96.45%。

这是按算子标签划段的明确边界。Refine 可能实际改变机制，Explore/Crossover 也可能复制熟悉机制。跨段参考因此不保证借用了不同思想。

**最小处理。** 不要求立刻增加语义分类器。至少先阻止完全相同的有效源码通过不同入口反复获得独立份额，并将此规则对所有对照共同使用。语义上不同但代码近似的问题另行验证。若不做这一处理，叙事必须限定为操作关系上的分配，不能声称按不同思想保护机会。

### 3.5 段预算不被线性放大，不等于段内能持续开发关键候选

位置：`traceaad_v19_2/selection.py:353–360`。

**合成反例。** 关闭探索奖励，加入 99 个同值 Refine 副本，段总份额维持 73.1%，但指定程序的份额从 73.1% 降到 0.731%。

这不违反“段总量不随相同成员数相加”的窄性质，却说明该性质不足以保证有用的开发连续性。原来的“某个潜在有效程序只得到一次后续机会”不能仅凭段归一化宣称已解决。

### 3.6 同样的失败质量，因为是否产生节点而影响不同统计

位置：`traceaad_v19_2/selection.py:176–184, 277–290`；`search.py:200–211`。

**合成反例。** 同一父代的 50 次零质量 Refine 结果，如果都没有生成程序节点，`N_T=0`、`T≈0.731`、父代份额约 52.8%；如果都是产生节点的运行失败，`N_T=25`、`T≈0.0281`、父代份额约 14.3%。两种情况下局部组合次数都是 50。

不同失败阶段确实可能有不同含义和成本。但当前差别由是否存在节点隐式决定，文档又说失败不产生谱系信用。应明确其统计含义：运行/超时失败实际上产生了负面的零质量轨迹证据；格式/API 失败没有。

**最小处理。** 明确区分操作成本与有效的机制证据。段级投入可以按 Attempt 一致计入；是否把基础设施失败用作质量证据，单独规定。不能简单把 API 故障当成某算法思想无效。

### 3.7 截断信用是一项假设，也会丢掉发现入口的远期收益

位置：`traceaad_v19_2/selection.py:113–162`。

如果 A 的 Explore 产生较弱的 B，而 B 经数步 Refine 变强，A 的 Explore 统计始终只收到 B 出生时的质量。Crossover 的两个来源也只得到直接结果的一次等分。这个规则适合估计直接生成的产出；它不能同时被解释为估计发现后续高价值方向的长期能力。

同样，按照两来源各一半分配信用，是可审计的约定，不是已经识别出的因果贡献。生成模型可能只用了其中一个来源。

后代由谁获得、产生多少，也由当前选择策略决定。轨迹统计可以作为预测后续产出的特征，但不能直接解释为方向的固有潜力。需要在相同后续机会下验证其预测与决策价值，避免让已获投入较多的分支用自己的后代反过来自证。

数值信用的截断也不是模型信息的隔离。`PromptBuilder.histories` 仍沿父代链读取最多八个祖先，可能跨越 Explore/Crossover 段根。因此，共享边界属于统计约定，不能解释为更早来源对生成结果不再产生影响。

**最小处理。** 先确定要奖励的是一次产出，还是开启一个可持续开发的新任务。不要因为一次转向就把长期信用必然为零写成事实，也不要为了修正它立即恢复完整树回传。

## 4. 其他会改变解释的边界

| 情形 | 当前实际行为 | 对结论的影响 |
| --- | --- | --- |
| 动作空间随有效程序持续增长 | 多数组合只有零到一次结果；每个 Explore/Crossover 又增加一个段 | 局部收缩是合理保护，但不等于已经学到条件差异；算子下限也不保证某个具体段得到连续机会。 |
| 文本上下文随子代和失败窗口变化 | 固定父代和算子不对应恒定生成分布 | 历史均值是当前策略下的混合观测；探索项不能直接当作有校准保证的置信界。 |
| 直接子代同时进入轨迹均值和局部组合修正 | 同一观测影响共享先验与局部项 | 可作为启发式，但不能解释为独立证据相乘或严格后验。 |
| 参考个体随程序库改变 | `(parent, Crossover)` 混合了不同参考条件 | 三维统计太稀疏不必强建；也不能把该均值当作固定交叉操作的稳定性质。 |
| 一次动作最多包含两次评价和两次请求 | 选择器按一次 Attempt 更新，停止按评价预算 | 相同评价次数不等于相同模型成本，也不等于相同动作数；成本比较需要请求/token 与评价同时报告。 |
| `max_unevaluated` 达上限 | 代码在发生过评价时即重置计数，包括运行错误和超时 | 文档“连续未产生有效评价”应改为精确的“连续未进入评价”；当前不是连续无成功程序上限。 |
| 初始化数为一、重复成绩或预算不足 | 可能只初始化便终止；单点尺度退化；没有跨段候选时 Crossover 被关闭 | 最终返回最好有效程序有明确行为，但不能假设三算子始终存在。 |
| 检查点恢复 | schema 4 拒绝旧语义；未结束尝试保留已耗成本并结束 | 这有利于避免偷换统计语义；中断记为零结果仍应与普通算法失败区分。 |
| 全部有效程序都在同一段 | `reference_pool` 返回空，实际禁止段内 Crossover | 实现是硬性跨段限制，强于“优先跨段”的自然语言；应在规格中写清。 |

| --- | --- | --- |
| 当前成绩不等于后续开发潜力 | HGM 显式研究性能与自改进能力的差异 | 在当前 AAD 生成器和任务中识别具体失败模式，证明更简单的轨迹信号有预测和决策价值。 |
| 联合考虑父代和算子 | DGS 直接选择算子与父代集合；TreeQuest 为节点—动作维护状态 | 不用嵌入代理或额外模型，以可审计的小统计实现相近功能；需要证明简化没有丢失关键能力。 |
| 用后代表现汇聚分支价值 | HGM、AB-MCTS、Clade-AHD 均有相关设计 | 按生成操作约束共享范围，并处理双来源组合。 |
| 深度折扣回传 | Clade-AHD 式 5–6 已显式使用深度折扣 | 不能把折扣本身当作创新；边界选择及其效果才值得检验。 |
| 质量变换与开发次数共同分配父代机会 | ShinkaEvolve 的 weighted 采样已把 sigmoid 质量与子代次数结合 | 固定历史尺度与按段共享仍有区别；质量映射加次数保护本身不构成增量。 |
| 连续 Refine 段，转向时重建分配单元 | 本轮未找到与当前全部规则相同的直接实现 | 这是较有希望的候选设计主张。尚不能把有限检索中的未发现等同于不存在先例。 |

因此，V19.1 目前更像一个低成本、可审计的联合选择器实现。单凭“轨迹条件的设计干预”这个表述不能建立创新。

V19.2 较值得推进的主张是：**根据生成操作规定哪些开发结果可以共享，哪些应在转向处重新建立开发任务，从而在稀疏预算下改善延续与转向的分配。** 这个主张只有在共享边界优于无共享、完整祖先共享以及简单访问次数规则时才成立。

## 6. 科学叙事应该怎样收束

我建议围绕一个可被推翻的主张组织后续工作：

> 稀疏预算下，LLM-AAD 不仅需要选择当前成绩好的程序，还需要决定哪些连续开发结果可以共享。以可观察操作关系限定共享范围，可能比平铺程序竞争更有效地分配后续机会。

这比“管理不同算法思想”更贴合当前可观察变量，也比“我们同时利用当前质量、轨迹质量与干预适配性”更容易用实验回答。后三项目前是模型组成的描述，尚不是已经证明的科学解释。

V19.1 对比 V19 虽然只替换了选择器模块，但同时改变全局算子先验、联合归一化、探索项的总量与算子混合下限。它是选择器整体对照，不能被称为只隔离了联合决策这一数学因素。V19.2 又改变尺度、信用、分组与参考池，整体结果也不能直接归因于开发段。

## 7. 最值得先做的验证

我优先做一个问题：**加入真实轨迹结果，能否优于一个保留相同访问次数、但不使用结果的简单分配器？**

第一步已经完成：对冻结状态删除质量项，检查分布是否改变。V19.1 的答案是改变极小，足以要求先修正信号尺度与分配形式。

下一步应先做小规模、配对的在线验证，而不是再启动一整套复杂版本：

1. 选择相同的有效起点、生成提示、修复和重复处理规则，比较“只用当前质量和访问次数”与“额外用真实历史结果”两种分配。需要控制统一的质量映射与探索强度，避免把尺度调整当成轨迹收益。
2. 对预先选定的稀疏候选安排相同数量的后续开发，检查加入轨迹后的排序，是否更能预测未来固定预算内的最好结果；避免只看已被本选择器反复选中的后代形成自证。
3. 若真实历史结果确有用，再比较连续段共享、无共享、完整祖先共享，隔离共享边界的价值。此时才值得保留父代—算子的局部修正。

最小决策规则：如果真实轨迹不优于仅用访问次数的规则，就简化机制；如果有用但分段没有额外收益，就不保留开发段；只有二者都成立，才把有限预算的开发信用分配作为核心主张。最终仍看预算结束的独立测试结果，并单列真实请求、token 和评价成本。

## 8. 独立评审与裁决

三份独立评审均已完成：Claude Opus 5.5（high）、Muse Wonder Full 1.0（max）、Antigravity Gemini 3.8 Flash（high）。它们按独立提示启动，收到相同设计与代码范围，并被要求不读取本轮其他模型或主审意见。原文保存在[评审证据目录](../../experiments_result/analysis/v19_design_review_20261101/reviews/)。

我不按模型数量投票。已有意见的裁决如下：

| 独立意见 | 裁决与依据 |
| --- | --- |
| 探索项可能淹没质量信号 | 接受。主审用 18 路真实记录的完整分布重算验证；不依赖玩具树或任意困惑度阈值。 |
| 初始化尺度退化、新叶子重置奖励、失败节点处理不同 | 接受。已有可复现反例；失败的成本与质量证据仍需区分。 |
| Explore 对来源父代完全没有正反馈 | 驳回。`pair_stats` 已把直接 Explore 结果计入来源 `(parent, Explore)`；其均值随局部样本增加能克服轨迹先验。合成验证中，50 次高质量 Explore 将局部均值从 0.0103 提升到 0.8992，而轨迹均值保持不变。真正尚未回答的是新段后续开发的长期信用。见[裁决探针](../../experiments_result/analysis/v19_design_review_20261101/adjudication_results.json)。 |
| 跨段交叉保证异源思想 | 驳回。不同段由算子标签决定，相同源码可形成多个段；主审的重复 Explore 反例已否定该保证。 |
| 有进步的低分分支必须优先于没有进步的高分分支 | 不接受为通用要求。低分分支的改进可能仍不如高分分支有价值；应对齐最终预算收益，而不是把相对改进自动当作正确目标。 |
| ShinkaEvolve 的乘法分配优于当前加法探索 | 仅接受为简单竞争机制。源码先例已核对，尚无当前条件下的公平对照证明其端到端更优。 |
| 只保留叶节点即可解决问题 | 仅接受为待验基线。较旧但不同的起点可能仍有开发价值；不能凭年代或单次成绩证明未来生成能力被支配。 |
| 子代平均质量与最终最优目标不同 | 接受为核心估计对象问题。不能进一步断言改用单步改进或超越概率必然更好；这种替换也可能丢掉需要多步开发的起点。 |
| 同一结果进入多个统计量，因此机制在数学上无效 | 仅接受重复使用的代码事实。跨层收缩和树上的多节点回传本身并不必然错误；当前没有严格后验语义，不能要求它满足独立似然。真正需要核对的是每份证据的实际影响与探索强度是否匹配。 |
| repair 为失败动作提供未计账的额外预算 | 不接受“未计账”。请求与两次评价已完整保存并计入停止预算；接受动作均值未按异质成本调整的边界，因而不能直接宣称在优化每次评价或每单位模型成本的收益。 |
| 应新增参考编号与完整上下文版本才能追溯 | 参考编号和每次请求的完整提示已经保存。先使用现有记录分析上下文漂移，无需为追溯再增加一层状态。 |
| 三组消融中 `p<0.05` 就证明整条机制叙事 | 驳回。改变多个组件会混淆归因，三路重复的无显著差异也不等于等效。应优先控制实际质量尺度、参考池、成本与重复处理，再裁决轨迹及共享边界。 |

未核对的模型记忆、任意阈值和把局部行为推广为端到端优劣的断言不纳入确定结论。评审没有触发生产代码变更或正式实验。
