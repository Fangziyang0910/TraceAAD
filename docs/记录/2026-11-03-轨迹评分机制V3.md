# 轨迹评分机制 V3：两类精炼候选与预测落点

北京时间2026-11-03。本文是草案，在[V2](2026-11-03-轨迹评分机制V2.md)的基础上，吸收两侧的最新统计：我这边的遗传性、两步价值与接近程度检验（[分析目录](../../experiments_result/analysis/trajectory_value_mechanism_20261103/)），以及另一侧的失败内容检验（[报告](../../experiments_result/analysis/trajectory_failure_content_20261103/README.md)）。本文没有修改在线代码，也没有启动新实验。

## 结论

V3 改变了问题的提法。分数的任务只是决定下一笔改进预算给谁，不是预测每个节点的突破潜力。突破是创纪录事件，天然稀疏；单个节点自身的结果历史，分辨不出这种潜力。所以，区分节点的信息必须来自两处：跨节点汇总的状态规律，以及代码内容。

由此，精炼候选分成两类，各用不同的证据：

| 候选 | 例子 | 价值从哪里来 |
| --- | --- | --- |
| **已检验节点**：再从它出发试一次 | 当前较好、已有若干尝试的程序 | 状态规律：差距、已有尝试，按状态汇总估计 |
| **待修实现**：比路径上的好祖先差、还没被开发过的新实现 | 新思想的第一版、修复后丢了信息的版本 | 代码诊断：是否有可定位、可修复的损失或缺陷；修好后预计落在哪里 |

两类候选用同一个排序分比较：

\[
S(p)=\underbrace{P(\text{改进}\mid p)}_{\text{能否改进}}\times\underbrace{h\big(d(p)\big)}_{\text{落点离最好多远}}
\]

区别只在估计方式。已检验节点的落点就是它当前的位置；待修实现的落点是它的参照祖先附近，而不是它现在退步后的位置。决策用汤普森采样，后验按类别汇总，不按节点。

## 1 出发点

### 1.1 分数只需要排序

算子比例固定以后，分数只需要在同一种算子内部比较候选，所以不必是校准过的概率。它只需要满足两点：一是区分节点的部分要足够稠密，能从数据中学出来；二是方向与最终目标一致。最终目标是预算结束时的最好结果，所以机制好不好由完整搜索裁决，离线指标只用来检查排序是否合理。

### 1.2 稀疏性是首要约束

- 一次尝试突破全局最好的比例只有0.5%–2.5%。即使尝试独立同分布，1000次中预期也只有约 \(\ln 1000+0.58\approx7.5\) 次新纪录；搜索在进步，实际每路约20次。稀少是"纪录"这个定义决定的。
- 每个节点的直接子代，中位数是2个；90%分位数在 Base 是5，在 V19.1 是4。要分辨一个节点的突破率是2%还是4%，大约需要几百次尝试。
- 实测也是如此：在差距与尝试计数之外，加入已有子代的连续增益（包括离突破还差多远），预测突破的 AUC 在 V15、V17、V19.1 略降，只在 V18.1 精炼（.637→.676）与 Base 拓展（.647→.657）上升。
- "子代优于父代"在有效子代中占20%–50%，比突破稠密一个数量级以上，适合用来学习节点之间的差别。

**设计含义。** 不再为每个节点估计自己的潜力，所以去掉 V2 的节点随机效应。证据按状态和类别累积。

## 2 两类精炼候选

### 2.1 为什么要分开

另一侧把"失败之后"拆成了两种行动：再试原父代（108713次决策），和首次开发那个失败的子代（43979次决策）。两者对内容信息的反应不同。在一步"优于父代"的预测上，加入改动内容后：

- 再试原父代：同批留出时，只有1/9个完整批次的预测损失下降。
- 首次开发失败子代：5/9个批次下降。V15 最清楚：六个任务的损失都下降，整批迁移到未见过的批次时方向也相同，只在有效子代上拟合，增量仍然存在。

（条件：九个完整批次 C02/C03/C04/C06/C09/C12/C13/C15/C23；V15 为 qwen3.8-27b-awq、温度0.7、1000次生成回复、六任务×3个 seed。）

解释：再试原父代，只是从同一起点再抽一次样，内容说明不了下一次抽样的结果；开发失败子代，问的是"这个具体实现能不能修好"，答案就写在代码里。

### 2.2 待修实现的定义

满足以下三点的节点属于待修实现：

1. 它比自己祖先路径上最好的祖先（下称参照祖先）差；
2. 它还没有被开发过；
3. 它是一个新实现：由拓展产生，或经过了修复。

其余节点都属于已检验节点，包括还没被试过、但比参照祖先好的新节点。

### 2.3 为什么待修实现不能按当前差距打分

按当前差距打分，失败的第一版几乎总排在最后。但修好以后，它往往落在参照祖先附近，再加上新思想带来的增减：

- V15 TSP P93→P94→P100：P94 删掉了完整的贪心补全，退到8.08；P100 恢复后回到 P93 的6.32。
- V17 TSP P230→P231→P235：P231 把完整路线模拟换成距离惩罚，退到12.52；P235 恢复模拟，同时保留了新的候选限制，达到6.19，好于 P230 的6.26。
- V15 TSP P236→P297：P236 把两套前缀代价混在一起计价；P297 改为完整路线计价，并加入2-opt，达到5.94，超过当时的全局最好5.96。

这些案例是挑出来的，不能代表发生率。它们说明的是结构：待修实现的价值取决于修好后的落点，而落点的参照是它的祖先，不是它现在的位置。

### 2.4 旧策略几乎不开发待修实现

V15 中，退步且删除了结构的失败子代，有完整后续窗口的共1670个，其中只有112个在后续30条记录内被开发过；其余退步子代为983/7827。P236 出生后隔了61条记录才第一次被开发。所以历史数据回答不了"待修实现修好的比例有多高"。这一点必须在新搜索中在线学习（第4节）。

## 3 排序分的两个部分

### 3.1 能否改进：\(P(\text{改进}\mid p)\)

**已检验节点。** 用一个按算子区分的加性逻辑模型，以"子代优于 \(p\)"为标签。特征是差距、同类与异类的已有尝试数、近期尝试的结果计数，以及"\(p\) 是否优于它的父代"。最后这一项只是一个状态变量，它的负系数反映的是"从稀疏事件中做选择"带来的回归效应，不代表一种机制。

选择加性模型的理由：另一侧的结果中，V15 的线性基线（log loss .4862）优于加入内容的树模型（.5065）；九个完整批次里，线性模型加入内容后损失都没有下降。现有数据不支持非线性。

**待修实现。** 修好的概率按诊断类别估计：

| 诊断类别 | 含义 |
| --- | --- |
| 可定位的损失 | 相对参照祖先，删除或替换了有效的计算 |
| 可定位的缺陷 | 计价错误、代码未执行、输出被错误覆盖等 |
| 未检出 | 诊断没有找到可定位的问题 |
| 未诊断 | 尚未诊断 |

每个类别有自己的先验，先验来自历史中被开发过的同类节点；搜索中在线更新。

### 3.2 落点离最好多远：\(h(d)\)

\(h(d)\) 是改进落在距当前最好 \(d\) 处时，这次改进成为突破的概率。它从历史数据估计：在有改进的尝试中，看突破率随落点差距怎样变化，并按算子区分。第一版的数据显示：精炼的突破率随差距单调下降；拓展在差距超过1%后基本持平（五个版本一致，口径为有效子代）。

落点差距 \(d(p)\) 的定义：

- 已检验节点：\(d(p)\) 等于它当前的差距。
- 待修实现：\(d(p)\) 等于参照祖先的差距加上偏移 \(\delta\)。\(\delta\) 是"修好后相对参照祖先好多少"，先验均值为0，在线学习。

**理论依据。** 这是把强化学习中处理稀疏奖励的方法用到排序上：前一个因子用稠密、可学的信号区分候选，后一个因子把方向对齐到稀疏的最终目标。它也是对面所说"一步转移模型"中最有用的部分：只预测这一步改进会落在哪里，不做多步推演。

## 4 决策：按类别汇总的汤普森采样

每次选择时：

1. 按固定比例抽出算子。
2. 从各类别的后验中各抽一组参数，包括状态模型的系数、诊断类别的修复率、落点偏移 \(\delta\)。
3. 对所有候选计算 \(\tilde S(p)\)，选最大的那个。
4. 如果选中的是"未诊断"的待修实现，先做诊断，按诊断类别重算它的分数，再重新比较一次。诊断是一次模型调用，不消耗评价预算。

**为什么后验按类别而不按节点。** 节点层面的证据太少（每个节点约2次尝试）。类别层面能累积几十到几百次结果，汤普森采样可以真正学到东西。"可定位缺陷的待修实现"这一类，历史上几乎没被开发过，先验不确定性大。汤普森采样会先给它一些预算，再按结果收敛。这正是无限臂老虎机中"新类别值得一试"的行为，又不需要给每个新个体保留尝试次数。

**延迟价值怎样体现。** 拓展这一步本身不需要预判后果。它产出的第一版如果是待修实现，出生后会按落点被正确估值。延迟价值靠的是让第一版真正得到打磨，而不是靠前瞻计算。我这边的统计支持这种分工：只用状态特征时，两步排序与一步排序的相关系数为0.94–1.00；而两步内的突破中，有16%–38%来自第二步。

## 5 诊断

- **触发**：待修实现第一次被汤普森采样选中时。
- **输入**：节点与参照祖先的代码、design、analysis，以及两者之间的修改说明；如果经过修复，再加修复前后的版本。
- **输出**：诊断类别；如果有可定位的问题，给出位置，并用一句话说明它怎样影响输出。
- **用途**：一是确定类别，进入第4节的决策；二是选中后作为精炼材料。
- **独立性**：诊断是独立调用，不与反思合并。

为什么必须读代码：另一侧发现，两个真实的恢复案例中，失败版本的 AST 反而比参照祖先长（P94 长30.7%，P231 长11.4%），因为完整计算被换成了更复杂的近似。规模类代理会漏掉它们，只有指出"哪项计算消失、被什么替代"才能定位。

## 6 拓展

拓展沿用 V2 中基于状态的排序：\(P(\text{改进})\) 由状态模型估计，\(h\) 按拓展自己的曲线估计。融合对象保留现有选法。我这边的统计显示，拓展的子代如果"改进了父代但没突破"，下一步更容易突破（4/5个版本，例如 Base .034 对 .014）。这类子代属于已检验节点，状态模型会直接用到这个信息。

## 7 与 V2 的关系

| 部分 | V2 | V3 |
| --- | --- | --- |
| 分数的含义 | 校准的突破概率 | 只需排对的排序分 |
| 区分节点的证据 | 节点随机效应与特征 | 状态规律与代码诊断；去掉节点随机效应 |
| 候选 | 统一处理 | 已检验节点与待修实现分开估计 |
| 待修实现的距离项 | 当前差距 | 预测落点的差距 |
| 汤普森采样的后验 | 参数与节点 | 参数与类别 |
| 诊断 | 特征 | 决定类别，并作为精炼材料 |
| 模型形式 | 广义线性模型 | 加性逻辑模型（数据未显示非线性的必要） |

## 8 证据与条件

| 结论 | 证据 | 条件 |
| --- | --- | --- |
| 单个节点自身的结果历史，分辨不出突破潜力 | 子代中位数为2；接近程度特征不增加预测力 | V15、V17、V18.1、Base、V19.1；`near_miss.py` |
| 父代潜力的遗传性弱 | 加入父代改进率后，改进预测的 AUC 只提高0–0.02；新节点按父代改进率分组的结果，方向不一致 | 同上；`lookahead.py` |
| 只用状态特征时，前瞻不改变排序 | 两步与一步排序的相关系数为0.94–1.00（V19.1 精炼除外：0.59，突破样本很少） | 同上；只含后来被继续开发过的子代 |
| 内容对待修实现有用，对再试原父代无用 | 损失下降的批次：5/9 对 1/9；V15 六任务同向，整批迁移同向 | 另一侧报告第1节 |
| 不需要非线性 | 线性基线优于加入内容的树模型 | 同上 |
| 待修实现很少被开发 | V15 删除结构的失败子代中，112/1670 被开发 | 另一侧报告第2节 |
| 落点参照祖先 | P100、P235、P297 三个案例 | 人工选取，不代表发生率 |

所有统计都基于各版本自身策略选中的尝试。

## 9 关键未知量与检验

1. **待修实现修好的比例和落点。** 这一项历史数据回答不了，是 V3 最关键的未知量。检验方法是配对接续：从冻结的历史中按诊断类别抽取待修实现，同一预算下分为"有诊断材料的精炼"和"普通精炼"两组，比较修好的比例和落点相对参照祖先的偏移 \(\delta\)。这一步也能估计各诊断类别的先验。
2. **\(h\) 的形状。** 按完整尝试口径（生成失败也计入），重新估计各算子下突破率随落点差距的变化。
3. **诊断的准确性。** 抽查诊断给出的位置是否真实存在问题，只检查诊断这一步做得对不对。
4. **完整搜索。** 在固定协议下与现有机制和 V2 比较最终结果。机制好不好由这一步裁决。
