# MCTS-AHD 实现与生成次数预算核查

本次核查由“六项测试没有领先，是否存在实现错误”触发。结论是：核心树搜索与本地官方实现一致，但生成次数预算有两个可复现问题，其中一个已在本批发生。不能将当前实现称为完全无误，也不能据此把未领先归因于这两个问题。

## 核查依据

- 官方参考：`/home/fang/code/LLM4AD/reference_code/MCTS-AHD-master/source/` 的 `mcts.py`、`mcts_ahd.py`、`evolution_interface.py`。
- 本地实现：`baselines/mcts_ahd/`、共享采样器、`experiments/infra/resume_baseline.py`，以及六任务 `20261011_server3_deepseek_off_pilot` 档案。
- CVRP 两次恢复记录中保存的 MCTS 主循环、树、采样器、共享解析器和恢复入口哈希均与核查时源码一致。
- 现有测试：`uv run pytest -q tests/method/test_mcts_ahd_mechanics.py tests/method/test_baseline_fidelity.py tests/experiments/test_resume_baseline.py`，108 项通过。
- 差分探针：向本地与官方树插入同样的 200 个节点。回传 Q、访问数、Q 上下界一致，20,099 次非退化 UCT 比较一致。本地额外处理相同 Q 上下界，避免官方实现除零。

- 历史树回放：六任务分别重建至末段已记录的 selected_leaf 状态（CVRP 999、FSSP 993、图着色 998、JSSP 997、OP 998、TSP 996）。根 Q、访问数、Q 上下界及全部根分支摘要均与日志一致。

## 已确认的问题

### 1. 代码生成成功、思路重述失败时，程序被丢弃且预算未增加

`MASampler.get_thought_and_function` 先生成并解析程序，再调用模型重述思路。主循环仅在两步都返回后增加 `_tot_sample_nums`。因此第二次请求抛异常时，已生成的程序不计入预算。恢复入口也仅将成功重述或解析失败的生成计入消耗，遗漏了同一种情况。

最小复现：第一次模型调用返回合法 `heuristic`，第二次抛 `TimeoutError`。采样入口返回失败，生成次数统计仍为 0。按本项目“生成程序计预算”的规则，应在生成返回时记账。重述失败不能退回生成次数预算，恢复也应保持相同语义。

按 `transport_id` 去重压缩与未压缩请求档案后，本批观察如下：

| 任务 | 被复用的生成尝试编号 | 成功生成次数 | 记录预算 |
| --- | ---: | ---: | ---: |
| CVRP | 318 | 1001 | 1000 |
| FSSP | 392 | 1001 | 1000 |
| 图着色 | 224 | 1001 | 1000 |
| JSSP | 238 | 1001 | 1000 |
| TSP | 无 | 1000 | 1000 |
| OP | 无 | 1000 | 1000 |

上述四项第一次生成均解析成功且有思路，随后遭遇 429，恢复后在同一编号重新生成。这里统计成功返回的生成请求，不是模型调用总数，也不是有效评价数。四项各多生成一个程序，不足以直接解释六项均未领先。被丢弃程序的质量未评价。

### 2. 算子内部重试没有检查剩余预算

外层循环检查预算，但 `expand` 中每个算子最多重试三次，重试前未重新检查。最小复现：从 999/1000 开始，m1 连续三次生成后评价无效，退出时计数为 1002。应在公共采样入口或每次重试前阻止预算耗尽后的生成，并覆盖此边界。

本批六项最大生成尝试编号均为 1000，未发现本问题触发。它是后续运行前应修复的边界错误，不是已证实的本次性能原因。

## 核心机制与适配边界

UCT 最大化 `Q=-score`，渐进扩展条件为 `int(visits**0.5) > children`，探索系数随剩余预算衰减，Q 回传取最好子节点，主要算子顺序为 e2、m1、m1、m2、m2、s1。这些核心规则与本地官方参考一致。

本批每项有两次日志边界恢复，保存了树历史，但随机状态重新设种子、从新一轮继续，不能称为不中断运行的逐步等价复现。重述温度实际为 0 与官方客户端的温度回退行为不同，是此前已记录的适配差异。

本次只审查并记录，没有修改算法实现、重跑搜索或覆盖历史预算。修复后应补上上述两项边界测试。已有测试通过并未覆盖这两个错误。
