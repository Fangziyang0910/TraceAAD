# 七种基线与官方开源实现的忠实性审查

第2至6节记录审查时版本的问题与复现证据，第7节记录修复结果，第8节说明当前模型适配。实际实验设置集中在[规范与共识](../08-实验规范与共识/README.md)。

审查日期：2026-10-11。被审查版本：`c6224cdf7a798dcf642981e77add0a7c6d968c41`。

**状态更新：下文为修复前的审查记录。修复结果与验证范围见第7节。** 修复只约束后续使用该源码的批次；历史成绩需核对各批启动快照及受影响路径，既不自动获得忠实性保证，也不因此整体作废。

**结论：七种方法都保留了主要搜索结构，但不能统一称为忠实移植。EoH、MCTS-AHD、FunSearch较接近官方；ReEvo存在错误比较上下文；CALM的算子提示词保留得很好，但上下文数据和任务接入有缺口；PathWise、ShinkaEvolve的提示词经过明显重写。七种方法共同存在完整程序被截为单个函数的问题。**

本轮以**官方仓库固定版本的实际执行路径**为准。论文用于理解方法，不以论文描述否定官方实际做法。不把未调用的函数当作运行行为，也不将本地个人fork自动视为官方来源。本轮只审查和记录，没有修改基线算法、任务评价器或实验协议。

## 3. 必须先处理的共同问题

### 3.1 七种方法均丢失顶层辅助函数

输入完全合法的程序：

```python
def solve(x):
    return helper(x)

def helper(x):
    return x + 1
```

原程序 `solve(2)` 返回3。经过七种方法的当前解析／重建路径，均只剩 `solve`，运行均报 `NameError: name 'helper' is not defined`。EoH、ReEvo、MCTS-AHD走共用SampleTrimmer；CALM、PathWise、FunSearch、Shinka的各自入口也复现同一结果。Shinka本次探针检查的是full patch路径。

位置：[共用解析](../../baselines/shared/sampling.py)、[CALM转换](../../baselines/calm/calm.py)、[PathWise转换](../../baselines/pathwise/sampler.py)、[FunSearch转换](../../baselines/funsearch/funsearch.py)、[Shinka转换](../../baselines/shinka_evo/sampler.py)。这些路径还会丢弃候选新加的顶层import；写在目标函数内部的辅助函数不属于本次失败例。

**它直接违背当前图着色、JSSP允许完整solve及辅助函数的任务契约。** 不能据此说原始FunSearch等单函数设计“错误”；错误在于我们把完整求解器任务接入后，仍用旧的单函数转换器。官方当前EoH已支持多函数／类程序，Shinka也面向程序块编辑，当前移植反而收窄了它们的代码范围。

### 3.2 四种方法的system/user角色被压成单个user消息

ReEvo、PathWise、CALM、Shinka的当前提示最终都是字符串；[OpenAIAPI._build_messages](../../core/llm.py)把字符串包装成一个user消息。CALM甚至先构造了正确的消息列表，再由[CALMSampler](../../baselines/calm/sampler.py)转为带`[system]`、`[user]`字样的字符串。

官方ReEvo、PathWise、CALM API路径保留消息列表；Shinka采样器分别返回system与user文本供客户端发送。**文本中写了角色名称，不等于保留聊天角色。** 这不是更换统一模型所必需的改动，当前客户端已经支持消息列表。

离线探针检查四条提示构造路径，实际构造出的role均为`["user"]`。EoH和MCTS-AHD官方本来就使用单user，不能把这条问题套到它们身上。

## 4. 逐方法证据

### EoH：主要流程贴近官方，初始化预算需要单独说明

[当前提示](../../baselines/eoh/prompt.py)保留了官方e1的异构探索、e2的共同思路提取、m1的结构修改、m2的参数修改。父代给思路与代码，不额外提供成绩，与官方一致。编号、括号要求和模板呈现并非逐字相同，但没有发现算子意图被反转。

[当前演化](../../baselines/eoh/eoh.py)随机选择算子，候选完成后立即更新种群；官方当前`eoh.py`也如此，**不能依据论文中的代际描述将其判错**。rank权重形式也一致。

当前初始化生成`2 × pop_size`个候选，`count_sample=False`；之后再消耗1000次演化预算。六个主任务pop_size为10，正常完成时名义总候选为1020。离线探针缩到pop_size=2，实际产生4个初始化候选，计入预算0个。官方当前`_run_evolution`同样把`max_sample_nums`解释为演化阶段预算。这是**沿用官方口径与本项目总预算约定不一致**，不是EoH算法被错误重写。

### ReEvo：反思链保留，但同分上下文有明确错误

[当前流程](../../baselines/reevo/reevo.py)保留短期比较、交叉、长期总结、精英变异；[当前提示](../../baselines/reevo/prompt.py)保留主要原文和20/50词限制。初始化温度增加0.3也沿用官方做法。

但`_select_parent_pairs`在种群只有一种分数时启用`selection_tie_fallback`，随机选择同分父代。随后短期反思提示仍断言第二个版本更好，并标为Worse/Better。官方`random_select`明确要求两者分数不同，无法配对时退出。探针用分数均为1的两段不同代码，确认仍生成“第二个更好”的断言。**这里给模型提供了不存在的质量差异，会污染随后反思和交叉。**

另外，官方会读取任务的`external_knowledge.txt`，并把它作为初始长期反思；例如TSP提示look-ahead。当前长期反思直接置空，没有独立任务先验入口。这是任务上下文适配差异；应明确是否统一取消任务先验，而不是声称上下文完全相同。角色压平问题见3.2。

### MCTS-AHD：搜索结构和算子语义基本保留

[当前MCTS](../../baselines/mcts_ahd/mcts.py)与官方的渐进扩展、随剩余预算衰减的探索系数、最好子节点回传基本一致。`Q=-score`与统一最小化目标相容。init_size=4、精英规模10、α=0.5、λ₀=0.1来自官方设置。e1/e2/m1/m2/s1的父代思路、代码及适用的成绩材料仍在；生成后再依据代码重述思路的额外调用也保留。

两个具体差异在[采样器](../../baselines/mcts_ahd/sampler.py)：官方`_get_thought`显式使用temperature=0；当前重述调用与生成共用客户端默认采样设置，正式入口默认为0.7。另一个是大括号思路解析：官方使用`re.DOTALL`，当前没有；`{First line\nSecond line}`在当前返回None。后者是可复现解析缺陷，不是算法约束。

因此不需要另造MCTS规则。应保留现有结构，修正解析，并明确阶段采样设置是否遵循官方。

### FunSearch：核心保留，分数签名被任务适配压缩

[数据库](../../baselines/funsearch/programs_database.py)保留10个岛、最多两个版本函数入prompt、分数聚类、较短程序偏置及4小时弱岛重置；温度0.1、周期30000与官方默认一致。生成新版本后拒绝调用旧版本函数也保留。没有证据要求给它额外加反思或历史长上下文。

官方`_get_signature`接收各测试的成绩tuple；当前固定为`(score,)`。当前评价器只交付一个汇总分，故不同实例行为但均值相同的程序会落入同一cluster。官方本身允许只有一个测试，这属于**标量任务接口适配**；不是“FunSearch不能这样运行”，但它没有保留逐测试行为签名。completion改chat及增加输出约束也是明确适配。完整solver辅助代码问题仍需处理。

### PathWise：状态材料大体保留，提示词与失败反馈确有偏差

状态中仍包含节点ID、说明、父代信息、推导理由、代码、分数；world model仍收到所选父代、directive和反思。内外循环、每动作rollout、选取最好子节点等主干保留。

但[当前prompt.py](../../baselines/pathwise/prompt.py)不是直接移植官方`prompts/common/`：

- policy删去了官方明确要求考虑性能趋势、候选差异和推导历史的条目。
- policy critic的官方上限是60词，world-model critic是30词；当前两者均改成80词。
- 官方要求critic不要引用特定ID／标签，并要求比较父子变化；当前简化提示没有完整保留这些要求。
- 探索扰动短语改成两组各5条自写短语；角色也被压平。

更直接的问题在[策略反思](../../baselines/pathwise/pathwise.py)的`_policy_critic_reflection`：当前只对`node is not None`的rollout求平均和展示，失败样本被删掉；官方把全部rollout及其fitness（包括失败的inf）放进action bundle。例：动作A产生2和失败，动作B产生3和4；当前给A显示平均2，官方会保留A的失败。因此模型接收到的动作可靠性信息不同。当前是否触发反思还按所有有限rollout分数判断，官方按action平均分是否存在差异判断。

**已排除的误判：** 官方虽然定义`world_model_critic_reflections`逐动作函数，但主循环实际调用`single_world_model_critic_reflection`。我们目前的全局一次反思与实际官方路径一致，不应改成逐动作反思。官方policy state也包含完整代码，不应擅自删去。

### CALM：官方算子文本忠实，成绩上下文与任务接入有问题

从官方Trainer提取提示构造方法，以同一模板、随机种子和任务占位内容运行，与当前[PromptBuilder](../../baselines/calm/prompt.py)比较。九项构造结果逐字一致：system、creation、design strategy、local refinement guidance、simplification、injection、replacement、requirements、crossover。比较使用空父代列表以隔离算子文本；**不代表父代成绩上下文也一致**。

官方当前版本确实包含偏向局部细化的提示、数值字面量微调和profile gate。这些不能指认为本项目私加机制。官方也提供API与local no-GRPO执行分支；当前入口明确命名`CALM (w/o GRPO)`，不训练模型是所选变体，不是凭空造出的CALM。

实际问题：

1. [CALM._evaluate_code](../../baselines/calm/calm.py)把汇总分包装成`np.asarray([score])`。官方保存的是实例成绩向量，并在prompt中提供均值、标准差、最好／最差和代表值。当前profile因此恒为n=1、std=0，best=worst=mean；依赖逐实例比较的接受门槛和去重也退化。统一最小化方向本身没有问题，丢失实例维度才是问题。
2. [task_config.py](../../baselines/calm/task_config.py)与[seeds](../../baselines/calm/seeds/__init__.py)没有FSSP、图着色、JSSP。正式[write_run_config](../../experiments/calm/run.py)调用任务解析即抛ValueError；绕过它仍会在种子加载抛KeyError。六任务探针确认原有TSP/CVRP/OP通过，新增三项失败。
3. 消息列表被CALMSampler压为字符串，见3.2。

任务温度／top_p、数值微调等参数大多沿用官方task config；这与本项目协议中“所有方法同一采样设置”的文字不完全一致。应明确保留官方方法设置的例外，不能一边照官方运行，一边报告全部相同。

### ShinkaEvolve：保留结构，但明显简化了提示与配置

[当前采样器](../../baselines/shinka_evo/sampler.py)保留当前程序、成绩、archive/top-k inspiration以及diff/full/cross三类输出，meta信息也会注入下一次生成。不能说它“没有inspiration上下文”。

不过与官方`shinka/core/sampler.py`、`shinka/prompts/`相比，当前patch格式提示被重写；官方full会随机选择多个改写策略，当前只有一个FULL_FORMAT。官方NAME/DESCRIPTION/CODE约定也没有完整保留。三阶段meta虽然保留，但[当前三段提示](../../baselines/shinka_evo/shinka_evo.py)只是短指令：官方对成功／失败计算、具体成绩证据、当前最好程序、上轮建议的要求明显更完整；当前推荐阶段没有传入previous recommendations。

[正式入口](../../experiments/shinka_evo/run.py)显式设置`embedding_fn=None`和`novelty_llm=None`，所以novelty rejection不执行；官方当前默认有embedding与相似度阈值，并提供该机制。入口已如实记录这两个开关关闭，属于**配置裁剪**，不是隐藏崩溃。统一使用单模型也使多模型bandit退化为单臂，这是共同模型条件带来的适配。不要为“忠实”自行发明新的多模型组合；应明确比较的是哪个官方可配置变体。

## 5. 处理顺序

1. **先修任务接入和代码交付：** CALM新增三任务；完整solver的完整源码保留、执行及后续父代上下文。否则实验失败混有移植错误。
2. **再修模型看到的错误／缺失信息：** 四种方法的消息角色；ReEvo同分比较；CALM实例profile；PathWise失败rollout；MCTS多行思路解析。
3. **直接复用官方提示及其填充顺序：** 优先PathWise和Shinka；不要用自行写的“意思差不多”提示替代。任务名称、签名、目标方向按本项目任务替换即可。
4. **单列运行适配：** EoH总候选预算、FunSearch标量签名、CALM w/o GRPO、Shinka无novelty／单模型、方法特有温度。保留官方做法时也要同步写清实验口径。

这些问题的修复结果见第7节。

## 6. 复现与验证边界

本轮通过解析器、提示构造器与mock初始化进行离线核对，不调用模型、不运行任务评价。一次性探针已清理，后续回归由方法测试维护。

既有737项测试通过说明现有测试范围内没有回归，并不能证明与官方提示或完整新任务启动一致。本轮未重新跑正式搜索，也没有测量以上差异导致的收益变化。静态核对及离线探针足以确认列出的实现差异，但不据此断言它们一定让某方法成绩变好或变差。

## 8. 当前模型适配与明确差异

主比较采用DeepSeek-V4.1-Flash，关闭原生思考。提示中的reflection、analysis和世界模型调用仍按各方法保留。统一模型不意味着抹去方法的提示、上下文与阶段机制；实际采样参数逐次记录，完整设置见规范正文。

- ReEvo的DeepSeek初始化偏移设为0，使用temperature=1.0。此前1.3出现多语言混杂回复，1.0与0的单独复测正常；这是模型适配，原算法类默认+0.3保留。
- MCTS-AHD当前思路重述真实发送temperature=0；官方调用虽然传0，但[共享客户端](https://github.com/zz1358m/MCTS-AHD-master/blob/ee9c4f424503c65a5fd2b899e6620ce86079fedb/utils/llm_client/base.py#L27)的`temperature or self.temperature`会回退到默认值。两者实际行为不同，不能称逐项完全一致。
- PathWise当前保留初始化+0.3；其官方[GPT-5客户端](https://github.com/oguzhangungordu/PathWise/blob/9d014a368d920d46ef4538da4c484503549214cb/utils/llm_client/openai.py)会覆盖温度为1.0，因此跨模型移植需区分方法请求值与服务实际生效值。
- CALM采用w/o GRPO变体与任务采样配置；Shinka采用单生成模型及独立阿里云embedding。提示与机制来自上述固定官方版本，模型服务和统一任务接口属于本项目适配。

关闭思考的依据是36次配对生成与训练评价：12份EoH／ReEvo初始提示，各比较high、low与关闭思考，temperature=1.0、top_p=0.95，不设输出上限。

| 模式 | 平均生成token（含思考） | 平均耗时（秒） | 训练集有效代码 |
| --- | ---: | ---: | ---: |
| high | 20366.4 | 142.5 | 9/12 |
| low | 14189.8 | 99.7 | 8/12 |
| 关闭思考 | 1836.0 | 11.3 | 10/12 |

high／low开销较大，未稳定改善有效性或质量，效果存在任务差异。每提示每模式只生成一次，不能据此建立普遍质量排序。关闭思考的10份有效代码中，一份EoH CVRP未满足思路交付格式，因此方法实际可接收的有效候选为9份。一次性诊断脚本与原始输出已按清理要求删除，以上结论和现用实验设置保留。
