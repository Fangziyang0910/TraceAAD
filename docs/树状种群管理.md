# 树状种群管理

本文保留V1种群管理的细节与采用依据。完整机制见[V1正式设计](EvoTrace-v1设计.md)；动态选择与简化见[V2正式设计](EvoTrace-v2设计.md)。

**所有可行算法共用一次质量与差异选择。每次选入算法时，同时补齐必要分叉与初始根，并按完整集合计算容量。** 保留集合确定后，树上位置自动决定哪些节点形成路径收缩、哪些形成旁支剪除，反思再整理相应经历。

方法主线见[树状种群与反思简化](树状种群与反思简化.md)，数据字段与调用方式见 [EvoTrace-V1](../evotrace_v1/README.md)，实现见 [topology.py](../evotrace_v1/topology.py)。

## 1. 生长与更新

默认在树达到64个算法节点时重构，更新后最多保留32个可行算法。虚拟根单独表示，不计入容量；暂存的失败节点计入触发数量，并在重构时移除。若候选不足或剩余候选都过于相近，保留数量可以少于32。

两次重构之间，新算法经评价后接入父代之下。达到触发数量后，系统统一完成选择、重连与经验整理。32和64控制种群更新节奏。

## 2. 一次选择确定保留集合

所有可行节点进入同一个候选池，包括内部节点和叶节点。内部版本与后代可以同时保留；它们按当前质量与代码差异竞争。被选中的内部版本可以作为阶段代表。

### 质量与差异

按当前可行算法的适应度排序，成绩越小越好，同分按编号从早到晚排序。秩质量按下式计算：

$$
\text{秩质量}=1-\frac{\text{从0开始的排名}}{\max(1,\text{可行算法数}-1)}.
$$

代码差异使用抽象语法树（Abstract Syntax Tree, AST）结构指纹：统计父子节点类型与遍历序列二元组，计算多重集Jaccard距离。普通局部变量名与数值字面量被忽略，调用名、运算类型与控制流结构参与比较。

候选算法的选择分数为：

$$
\text{选择分数}=\text{秩质量}\times\left(0.65+0.35\times\text{与保留算法的最近AST距离}\right).
$$

常规候选要求秩质量不低于0.30，与已保留算法的最近AST距离不低于0.08，且与适应度相同的已保留算法距离不低于0.20，防止同分等价改写挤占容量。当前最优算法优先保留，新方向代表按下节获得有限保护。

### 结构与算法共同占用容量

每次尝试加入候选，同时补齐连接存活分支的最近共同祖先（Lowest Common Ancestor, LCA）与路径上的初始算法。完整集合不超过32个节点时，才接受本次加入。

补入的节点本身也是算法，会参与下一轮距离比较。共享分叉的候选可以少占新增名额。容量不够时跳过，继续检查其他候选。单独保留冠军时至多需要冠军与其初始根两个节点。

保留共同分叉、收缩其间单链，采用虚树（virtual tree）的结构思路。历史Explore起点也可随单链收缩，方向变化由边上的经验承接。结构成本随选集变化，因此每次选点都重新核算。

### 有限的新方向保护

Init和Explore创建方向，方向编号随算法保存在 `Node.direction_id`。同方向的Refine与Crossover评价计入该方向，嵌套Explore另起计数。计数包含起点本身、失败评价及修复重评；起点被压缩后，后代继续沿用原编号与累计计数。

默认从原始方向编号距最新已生成版本不超过16、累计评价少于4次的Explore方向中，按各方向最好算法的质量排序，暂缓淘汰至多2个代表。它们也须满足完整结构容量；容纳不下的代表记录在计划中。这是本轮保留资格，后续评价预算继续由统一父代采样分配。

方向累计评价数随重构保留，已淘汰版本的评价仍计入。最新节点编号也随树保留，因此删除近期节点不会延长旧方向的保护窗口。

### 选择顺序

1. 若可行算法不超过容量，保留全部可行算法，整理失败节点。
2. 选入当前最优，补齐必要结构。
3. 在容量内加入有限的新方向代表。
4. 按共同分数选择下一算法，每次补齐结构并更新距离，直到没有合适且容得下的候选。

分叉锚点由连接关系确定，阶段代表由算法选择产生。两者都属于最终保留集合，可以与主动入选的算法重合。

## 3. 保留集合决定简化区域

保留集合确定后，每个移除节点恰好归属以下一个区域：

| 区域 | 怎样确定 | 结构更新 | 经验位置 |
| --- | --- | --- | --- |
| 路径收缩 | 两个相邻保留端点之间的中间节点链 | 后代接到最近的保留祖先 | 新边的变异经验 |
| 旁支剪除 | 不通往任何保留后代的节点 | 删除相应旁支 | 最近保留祖先的选择经验 |

被剪旁支的原父节点也可能被收缩，其经验由最近的保留祖先承接。虚拟根承接被淘汰初始方向的经历。

收缩后两端属于不同方向时，新边标记为Explore；同方向内按是否包含Crossover标记为Crossover或Refine。只要收缩链包含Crossover，`reference_id` 就保留最后一次Crossover的实际参考编号，包括跨方向收缩和再次收缩。参考编号可以指向已移除算法，供原始记录追溯。反思输入保留路径各步的算子与参考来源。

反思读取移除区域、保留端点、实际差分、评价结果及原有经验，写回变异经验和选择经验。已有的中间节点经验一并整理。具体格式与递归合并见[反思简化设计](反思简化设计.md)。

## 4. 当前参数与接口

| 配置 | 默认值 | 含义 |
| --- | ---: | --- |
| `base_capacity` | 32 | 重构后的算法节点上限 |
| `trigger_capacity` | 64 | 触发重构的节点总数 |
| `quality_floor` | 0.30 | 常规候选的最低秩质量 |
| `clone_distance` | 0.08 | 常规候选与保留集合的最低AST距离 |
| `same_fitness_clone_distance` | 0.20 | 与已保留个体同分时的最低AST距离 |
| `min_protected_evaluations` | 4 | 新方向保护的累计评价门槛 |
| `protected_new_directions` | 2 | 一次重构最多保护的方向代表数 |
| `recent_node_window` | 16 | 新方向的编号窗口 |

接口与状态字段见[模块说明](../evotrace_v1/README.md)。

## 5. 采用依据

[Base离线配对实验](记录/2026-11-11-统一种群选择离线实验.md)比较了四任务各3路、共48个原树状态。当时的统一选择版本在全部状态满足容量与结构约束。首轮前10名算法保留总数为117/120，原规则为110/120；对齐实际保留数量后，结果仍为117对110。

首轮平均最近邻AST距离为统一规则0.2176、原规则0.2254、仅按质量0.1949。该结果支持合并选择过程并保留差异项。后续改进来源的保留没有一致变化，完整搜索收益将通过从重构后树继续生成的实验检验。冻结输入、原实现与逐路结果保存在[实验报告](../experiments_result/analysis/20261111_unified_population_selection/README.md)中。

随后放开历史方向边界的路径收缩，长路径容量、重复重构、方向计数与经验读取由当前回归测试验证。
