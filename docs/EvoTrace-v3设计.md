# EvoTrace V3：树状种群与反思简化

V3通过树状种群，使算法的优胜劣汰同时成为积累和复用算法设计经验的过程。选择规则确定保留节点，演化关系据此划分待简化的路径区域与子树区域。反思结合区域内的算法变化、评价结果与已有经验，形成边经验或节点经验；路径收缩和子树剪枝移除算法节点，将经验保存在重连边或保留节点上。后续反思继续整合已有经验，生成算子结合相关算法及其演化轨迹读取经验。

本文档给出该过程的精确规则，依次说明表示、种群简化、经验合成、预算分配与生成上下文。研究论证见[研究概述](树状种群与反思简化.md)，实验安排见[实验方案](EvoTrace-v3实验方案.md)。实现位于独立包 [`evotrace_v3/`](../evotrace_v3/README.md)，仅依赖Python标准库。

## 1. 演化树表示与评价记账

每次生成经过程序评价后，将该次生成最终得到的算法作为节点加入 `TreePopulation`：

- `Node` 保存源码 `code`、模型生成的计算描述 `design`、实测适应度 `fitness`（越小越优，`None` 表示未通过评价）或错误摘要 `failure`、节点经验 `experience`、原始比较记录 `observations`，以及以此个体为主父代直接消耗的评价次数 `direct_evaluations`。本文档中的可行程序指通过评价器检查并返回有限目标值的程序。
- `Edge` 保存主父代编号 `parent_id`、生成算子 `operator`、交叉参考编号 `reference_id`、收缩标记 `contracted`、边经验 `experience` 与原始比较记录 `observations`。虚拟根（`root_id = 0`）单独保存初始阶段归并的 `root_experience` 与 `root_observations`。

`Init` 生成的个体挂在虚拟根下（`operator = None`）；虚拟根没有算法实现或分数。`Refine`、`Explore` 与 `Crossover` 生成的子代挂在所选主父代下，`Crossover` 参考个体仅提供上下文而不建立结构边。未收缩边记录生成关系，收缩边记录跨越已移除节点的祖先关系。

每次包含程序评价的尝试完成时（含运行失败及修复后的再次评价），按实际执行的评价次数推进全局 `evaluations_used`，并将该次数累加到算法主父代的 `direct_evaluations`。新节点的 `direct_evaluations` 从 `0` 起计；初始化没有算法主父代。每次生成总共至多修复一次，格式修复与运行修复共用这个机会。最终被评价的程序作为一个节点入树，即使其评价失败；同次生成中的两次评价不会形成两个节点。未进入程序评价的请求错误、格式修复与反思调用不推进评价时钟，其调用与词元用量单列记录。

## 2. 算法选择与树简化

首先，`distinct_individuals` 对标准化源码（`identity(code)`）与实测适应度均相同的可行节点，仅保留最早编号节点作为代表候选，其 `direct_evaluations` 不变。随后，`representatives` 按 `(fitness, id)` 从优到劣贪心扫描去重后的可行个体：若候选 $i$ 与所有已入选代表 $r \in R$ 均满足 $\operatorname{code\_distance}(i, r) \ge \delta$（`cover_distance`，默认 `0.15`），则将 $i$ 加入代表集 $R$，直至 $|R| = K$（`max_representatives`，默认 `24`）。存在可行节点时，适应度最优且编号最早者排在 $R$ 首位。

`identity` 比较忽略排版、注释和文档字符串后的语法树。`code_distance` 使用AST父子标签对与深度优先遍历二元组的多重集Jaccard距离；标签保留节点类别、运算符类型与被调用的函数名或属性名，其余标识符名称和常数值不进入特征。因而距离为零不等于源码重复。

初始化集齐 `initial_size`（默认 `5`）个可行个体后，每次将经过评价的个体加入树中，均执行树简化检查（`TopologyConfig`：`max_representatives = 24`，`cover_distance = 0.15`，`region_size = 4`）：

1. **确定保留骨架：** 先选出代表集 $R$，再求代表两两之间的最近公共祖先。记额外的非代表分叉节点为 $F=\operatorname{LCA}_T(R)\setminus(R\cup\{v_0\})$，保留骨架为 $\mathcal H=\{v_0\}\cup R\cup F$。由于 $F$ 在 $R$ 选定之后补齐，其节点不会在贪心覆盖中阻挡候选，也不参与父代抽样。
2. **划分路径与子树区域：** 其余非骨架节点在树拓扑上唯一归入两类互不相交的区域：
   - **路径收缩（`PathContraction`）：** 连接两个保留骨架端点（或虚拟根与骨架端点）的中间链 `removed_ids`，连同挂载在该中间链上的未保留分支 `branch_ids`。
   - **子树剪枝（`SubtreePruning`）：** 其余未保留节点按最近保留骨架祖先（或虚拟根）归集为待剪除子树 `removed_ids`。
3. **成批简化与幂等性：** 仅当路径区域节点总数 `len(removed_ids) + len(branch_ids) >= region_size` 或子树区域节点数 `len(removed_ids) >= region_size` 时，执行拓扑简化并发起一次反思调用。未满阈值的区域暂留在树上，其节点位于 $R$ 之外，不参与父代抽样。简化保留 $R$ 和存活节点之间的祖先关系；在没有新增节点时，再次执行不会继续移除节点，证明见论文附录B。

简化重连边标记 `contracted = True`（`operator` 与 `reference_id` 置空），所有存活节点的 `direct_evaluations` 原样保留。

## 3. 节点经验与边经验合成

每个达到阈值的简化区域调用一次结构化反思模型（严格 JSON 模式输出单一 `"experience"` 字段，约 120 英文词）：

- **路径收缩区域**（`build_edge_reflection_prompt`）读取两端算法的代码及净差分、中间算法的代码与评价结果、沿途待剪分支中的代码差分、相关父节点下其他最优可行节点的设计描述与分数（`[Related Results]`）、已有经验及区域比较表（`[Comparison Catalog]`），生成**边经验**写入重连边的 `edge.experience`。起点为虚拟根时，不提供起始代码、分数或首尾相对表现。
- **子树剪枝区域**（`build_node_reflection_prompt`）读取区域所依附的保留节点代码、区域内各节点相对更新前树中父节点的代码差分与评价结果、相关父节点下其他最优可行节点的设计描述与分数、已有经验及区域比较表，生成**节点经验**写入该保留节点的 `node.experience`；依附于虚拟根的区域不提供起始算法代码，经验写入 `tree.root_experience`。

原始比较元数据保存在节点与边的 `observations` 列表中供核查与无模型回退使用；`[Comparison Catalog]` 仅向模型呈现当次区域的比较项；随经验保留的历史比较项继续存于 `observations`。若反思调用异常，系统根据比较记录与截断后的已有经验生成确定性摘要。`MAX_EXPERIENCE_CHARS = 960` 控制各部分的截断，不是完整摘要的总长度上限。自然语言经验遵循忠实记录与谨慎解释的提示要求，但属于有损总结。

## 4. 预算分配与算子选择

父代仅在代表集 $R$ 上抽样：

$$w_r = \frac{2^{-\operatorname{rank}_R(r) / H}}{1 + n_r}, \qquad p_r = \frac{w_r}{\sum_{u \in R} w_u},$$

其中 $\operatorname{rank}_R(r)$ 为代表 $r$ 在 $R$ 中相对最优并列组的平均适应度名次差，$H = \text{rank\_half\_life}$（默认 `10.0`）为适应度排名权重减半的名次跨度。$n_r$ 即 `tree.nodes[r].direct_evaluations`，统计以 $r$ 为主父代生成子代时消耗的实际评价次数，包括执行失败和修复后的再次评价：

- **未入选子代：** 与排序更早的已选代表结构距离小于 $\delta$ 的候选不进入 $R$；排序同时考虑适应度与节点编号。生成该子代消耗的评价次数已计入其主父代的 $n_r$。
- **新入选子代：** 新节点以 $n=0$ 进入代表竞争，不继承祖先节点的评价计数。适应度更优且距离小于 $\delta$ 的子代可以覆盖旧代表；与已选代表距离均不小于 $\delta$ 的子代在名额允许时加入 $R$。两种情况均保留其原有父子关系。
- **代表资格：** $n_r$ 只影响抽样权重，不决定是否淘汰。代表仅在被排序更早的代表覆盖，或代表名额已满时退出 $R$；退出后若不属于分叉骨架，则作为非骨架节点等待成批简化。

选定主父代后，按 `0.45 / 0.30 / 0.25` 抽取 `Refine`、`Explore` 或 `Crossover`。执行 `Crossover` 时，在 $R \setminus \{\text{parent}\}$ 中排除标准化源码相同的个体，保留归一化适应度排名得分不低于 `reference_quality_floor`（默认 `0.30`）的代表，优先挑选未配对过的 `(parent_id, reference_id)` 组合并取 AST 结构距离最大者；无合格参考时回退为 `Refine`。

## 5. 面向算子的树上下文读取

| 算子 | 树上下文内容 |
| --- | --- |
| `Refine` | 当前算法源码与分数、从根到当前节点的演化路径（未收缩边展示代码差分，收缩边展示边经验 `edge.experience`，沿途节点展示节点经验 `node.experience`）、虚拟根经验及当前树中连接至当前节点的分支记录。 |
| `Crossover` | 主父代与参考代表两份源码及分数、最近公共祖先的设计描述、分数与节点经验、其后的两条演化路径及沿途经验、主父代处的分支记录。若LCA为虚拟根，则提供可用的根经验与两条初始谱系各自的路径，不提供共同祖先算法。 |
| `Explore` | 按适应度排序的树上可行个体概览（`design`、分数、来源及附着的边/节点经验，含初始根经验），后附所选主父代源码作为一份现有实现对照。 |

生成提示默认输入上限为 `30,000` tokens。超限时折半缩减可选展示窗口，保留当前与参考算法源码及所展示差分的必要基准，因此提示可能只包含部分演化轨迹。必要上下文仍超限时，构造过程报错。将 `ContextConfig.include_experiences` 设为 `False` 可在固定树状态下隐藏提示中的节点与边经验，不直接修改该状态的父代抽样概率；自动缩减可能随文本长度改变展示范围。

`Crossover` 提示允许在无法形成有用组合时，根据比较结果改进主父代。`Explore` 提示要求构思不同的核心计算过程；实现没有独立检验是否达到这一要求。

## 6. 运行、恢复与边界

统一实验入口（`--method evotrace.v3` / `evotrace_v3`）与独立 CLI（`python -m evotrace_v3`）均支持 `--max-representatives`、`--cover-distance`、`--region-size` 与 `--rank-half-life`（将 `cover_distance` 设为 `0.0` 即退化为无结构覆盖的前 $K$ 个体对照）。`attempts.jsonl` 是唯一权威恢复日志，发生简化的步骤保存更新后的完整树快照，恢复时确定性重放而不重复调用反思；`run_config.json` 严格校验机制列表、选择规则（`representative_rank_direct_sampling`）、经验表示（`node_and_edge_experience`）及拓扑/分配配置，防止不同版本混跑。

已知边界：

- **AST 结构距离与覆盖非传递性：** `code_distance` 以语法结构二元组近似算法差异，结构相近但需连续退步改写才能突破的变体会被当前更优代表覆盖；覆盖关系不具传递性，且 `distinct_individuals` 仅在当前保留树内折叠精确重复（已被简化移除的程序若在后续搜索中重现，按新节点入树，不维护全局永久黑名单）。
- **反思归纳边界：** 单步自然语言反思是有损归纳，面对多处同时修改的代码仍可能出现归因偏差。当前对照批次与已验证边界见[实验与边界台账](记录/README.md)。
