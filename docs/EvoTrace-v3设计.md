# EvoTrace V3：在发展中竞争，在竞争中发展

V3以算法个体为种群成员，以主父代边记录发展脉络。个体凭当前质量参与竞争，树上的实际开发投入调节下一次尝试的位置。种群更新同时整理被移除的经历，使保留的实现继续携带相关经验。

实现位于独立包[`evotrace_v3/`](../evotrace_v3/README.md)。V1、V2及其冻结实验保留各自条件；V3使用新的运行目录和记录，不把旧树直接转换为V3运行。

## 1. 一个个体，两种预算信息

节点保存可执行代码、计算描述、适应度、选择经验S，以及：

- `development_evaluations`：以这个个体为主父代实际消耗的评价次数。
- `subtree_evaluations`：从这个个体及其后代出发实际消耗的历史评价次数，包含已被移除的后代开发。
- `last_used`：该个体出生或被直接开发时的评价时钟。

入边保存主父代关系、生成算子、交叉参考和变异经验V。累计投入属于节点，不随入边重连而转移。直接计数用于记录个体使用情况，子树计数参与预算分配。

Init从虚拟根产生初始个体。Refine、Explore、Crossover都从选中的个体产生后代。Explore描述生成任务的转向，不产生另一种种群成员或划分预算组。Crossover参考只提供信息，结构边仍只连接主父代。

每次完成一次带评价的尝试，按实际评价次数更新主父代的直接计数，以及主父代自身和所有保留祖先的子树计数。失败与修复重评均计入。只读参考不增加直接计数，也不刷新它的活动时钟。如果参考恰好是主父代的祖先，其子树计数会因真实后代开发增加，与参考读取无关。模型请求失败、格式修复及反思调用没有执行程序评价，不增加这些计数；调用成本单独记录。

子代的出生属于父代的一次直接开发。新子代自身的直接计数和子树计数从0开始。全局`evaluations_used`包含初始化和所有实际评价，用于总预算和个体活动时钟。

## 2. 一条规则选择开发起点

先在当前全部保留可行个体中按适应度从优到劣计算排名质量。最好为1，最差为0；同分使用平均名次，只有一个个体或全部同分时为0.5。这样不依赖任务分数的单位，也不因编号先后区分同分个体。排名质量每次选择前重算。

所有保留可行个体在同一个分布中直接抽样，包括内部祖先。每个个体只使用自身的排名质量和历史子树投入：

```text
质量权重 = quality_ratio ** 排名质量
个体权重 = 质量权重 / (1 + 该个体的 subtree_evaluations)
选择概率 = 个体权重 / 所有保留可行个体权重之和
```

`quality_ratio`默认10，且必须为有限数、至少为1。它表示**相同投入下，最好与最差个体的质量权重比**。同分个体使用相同质量权重；全部同分时，选择只由投入决定。即使排名为0，质量权重仍为1。实现按对数权重归一化，避免数值溢出。

这个参数统一表达质量偏好与投入的取舍：最好个体尚未开发时，其权重是未开发末位个体的10倍；其子树投入达到9次时，两者权重相同。增大倍率更偏向当前高质量个体，减小倍率让质量较低但投入较少的个体更容易获选。默认10是可解释的初始选择，不是由Clade伪观测数推导，也不是已验证的最优值。

树只决定实际投入向哪些祖先累计。开发`A → B → C`中的C，会增加C、B、A各自的子树投入；这些是嵌套的发展记录，不能相加当作总预算。A的累计投入只降低A自身的权重，不构成通往C的门槛。新个体C以自身质量和零开发投入直接参赛；C的成绩不改写A的质量。失败和修复消耗的真实评价同样计入。

质量偏好体现利用，随机抽样与投入折扣给其他个体留下探索机会。每次得到反馈后重算排名和概率，不设停滞开关、固定后续额度或探索/利用阶段。保留个体有正权重不等于在有限预算内必获开发。子树投入表达对已有发展投入的预算节制，不表示独立统计证据、未来收益预测或已耗尽的潜力。

该规则没有消除版本数量效应：持续出现近同的新个体仍会以零投入入场，近期保留也不会立即合并它们。保留与经验机制继续处理历史，但不能据此声称重复开发问题已经解决。排名消除目标值单位差异，也会忽略绝对分差；不同任务的搜索收益仍需在统一条件下评价。

选中个体后，Refine、Explore、Crossover按既有比例0.45、0.30、0.25抽取。父代选择决定在哪个个体上花预算，Explore算子决定怎样构思新计算，两者职责不同。交叉参考排除自身与相同源码，在剩余候选中按同一平均排名规则取质量不低于0.30者，再选AST结构距离最大的参考；优先尚未配对者。无参考时回到Refine。

日志保存实际选择的父代、该次选择概率、算子及参考。配置、尝试档案与维护快照共同支持重算当时的完整选择分布。

## 3. 一次种群选择，随后简化树

每次受评入树后，在同一快照上确定：

1. **质量与实现差异代表**：按适应度排序，保留最好个体；在排名质量至少0.50的个体中，依次保留尚未被更优或同分近似实现代表的个体。标准化源码相同或AST结构距离小于0.08视为已被代表。AST差异是代码结构启发式，不等同于算法语义差异。
2. **近期个体**：全局评价时钟距其自身`last_used`小于40。父代或邻居活跃不会连带刷新它。
3. **必要分叉**：补齐连接上述个体所需的最低共同祖先（lowest common ancestor, LCA）分叉。

合并这三个集合。其他节点成为本轮移除区域。后代更好不再单独取消祖先的质量代表资格；旧祖先是否保留同样由质量、代码差异、近期活动及连接需要决定。Explore边没有永久保留屏障。树没有固定容量上限。

保留端点之间的中间路径及其同轮移除旁支，共同凝练到重连边V；其他移除旁支归入最近保留祖先S。一个移除节点只进入一个区域。各区域从维护前快照读取代码、真实父代比较、执行错误和旧经验，再一起提交更新。

路径和旁支都可能包含改进、同分、退步与失败。比较标签由程序计算；反思区分观察与可能解释，不把初稿成绩解释为整个思想的潜力。收缩边标注为压缩发展，算子标签仅保留是否包含Explore或Crossover的信息，不冒充一次直接生成。

## 4. 简化同时保留历史投入

若`P → A → B → C`收缩为`P → C`，C自身的直接计数和子树计数均保持原值。A、B及其旁支经历交接到重连边V；它们的历史投入不转嫁给C。P的累计投入早已包含这些评价，继续保留。

例如A开发B花1评，B开发C花1评，A另一个失败旁支花2评，C尚未开发。收缩后C的两个计数仍为0。若P一直是A的祖先，P原有子树计数已经包含上述4评，无须再加一次。之后从C开发花2评，只给C直接计数加2，同时给C及当前保留祖先的子树计数各加2。

剪枝和重复收缩都不修改保留个体的已有计数，也不减少全局评价时钟。被删节点的原始投入仍可从尝试档案追溯。历史子树计数不能从当前可见节点重算；同一评价可属于多个祖先的子树，只有全局计数表示实际总预算。简化会改变候选集合和排名，因而仍可能改变采样概率。

## 5. 算子读取同一棵树

| 算子 | 读取内容 |
| --- | --- |
| Refine | 当前完整实现、从根到当前个体的保留形成路径、路径S/V及当前个体的尝试。Explore步骤显式标注转向。 |
| Crossover | 当前与参考实现、真实共同祖先、祖先之后的两段发展及相关经验。参考不增加结构父代。 |
| Explore | 当前种群各个体的设计、成绩、派生来源及其S/V，并提供所选个体作为一个现有实现。 |

不再按Init/Explore边界截断历史，不额外分组“路线代表”。Explore概览直接使用已经维护过的种群，按成绩排序；默认展示全部，只有输入超限时缩减完整条目。默认输入上限30000 tokens；有服务端tokenizer时按真实计数，否则按UTF-8字节保守限制并记录口径。展示缩减不改变种群、计数或经验归属。

## 6. 运行与恢复

V3独立持有搜索循环、任务、模型客户端、程序评价与存储，不导入V1/V2或其他方法包。仓库实验入口支持`--method evotrace.v3`与`evotrace_v3`，使用V3自己的任务、模型和评价器，训练最好程序固定后再做独立测试。

`attempts.jsonl`的已提交尝试是恢复依据；有简化的尝试保存完整更新后树，其他尝试按实际评价重新接入。恢复不会重新调用反思。`run_config.json`保存方法、选择规则及全部配置，方法或条件不一致则拒绝恢复。当前选择规则标识为`rank_subtree_sampling`；先前逐层选择的V3记录须用当时冻结源码恢复，不能混用计数语义。`tree_latest.json`仅是便捷视图。

实现核验及认识变化见[本周记录](记录/2026-W46.md)。本轮功能检查不替代完整搜索效果比较。
