# EvoTrace V3：在发展中竞争，在竞争中发展

V3以算法个体为种群成员，以主父代边记录发展脉络。个体凭当前质量参与竞争，树上的实际开发投入调节下一次尝试的位置。种群更新同时整理被移除的经历，使保留的实现继续携带相关经验。

实现位于独立包[`evotrace_v3/`](../evotrace_v3/README.md)。V1、V2及其冻结实验保留各自条件；V3使用新的运行目录和记录，不把旧树直接转换为V3运行。

## 1. 一个个体，两种预算信息

节点保存可执行代码、计算描述、适应度、选择经验S，以及：

- `development_evaluations`：以这个个体为主父代实际消耗的评价次数。
- `last_used`：该个体出生或被直接开发时的评价时钟。

入边保存主父代关系、生成算子、交叉参考、变异经验V，以及`subtree_evaluations`：进入这条分支后，已经从其中的个体出发消耗的评价次数。路径收缩后，它继续保存被折叠区域的投入。

Init从虚拟根产生初始个体。Refine、Explore、Crossover都从选中的个体产生后代。Explore描述生成任务的转向，不产生另一种种群成员或划分预算组。Crossover参考只提供信息，结构边仍只连接主父代。

每次完成一次带评价的尝试，按实际评价次数更新主父代的直接计数和所有祖先入边的分支计数。失败与修复重评均计入。只读参考不增加直接计数，也不刷新它的活动时钟。如果参考恰好是主父代的祖先，其分支计数会因真实后代开发增加，与参考读取无关。模型请求失败、格式修复及反思调用没有执行程序评价，不增加这些计数；调用成本单独记录。

子代的出生属于父代的一次直接开发。新子代自身的直接计数和入边计数从0开始。全局`evaluations_used`包含初始化和所有实际评价，是根节点使用的总时钟。

## 2. 一条规则选择开发起点

先在当前全部保留可行个体中按适应度从优到劣计算排名质量。最好为1，最差为0；同分使用平均名次，只有一个个体或全部同分时为0.5。这样不依赖任务分数的单位，也不因编号先后区分同分个体。排名质量每次选择前重算。

从虚拟根开始，逐层比较以下选项：

| 选项 | 质量依据 | 已投入评价 |
| --- | --- | --- |
| 直接开发当前个体 | 当前个体的排名质量 | 节点的`development_evaluations` |
| 进入一个直接子树 | 该子树中最好保留个体的排名质量 | 子树入边的`subtree_evaluations` |

两种选项使用同一个分数：

```text
选项分数 = 质量 + exploration_weight × sqrt(log(1 + 当前区域投入) / (1 + 选项投入))
```

“当前区域投入”在根处取全局评价次数，在算法节点处取其入边的分支计数。选择最高分选项；精确同分时使用该次尝试的随机种子打破平局。选择子树则继续向下比较；选择直接开发则返回该个体。虚拟根只有进入子树的选项。所有保留可行个体，包括内部祖先，都保留直接开发选项。

子树质量取最好个体，是因为目标是发现优质算法，普通后代的平均质量不能代表已有最好成果。这个最好成绩只支持进入该子树；走到内部节点后，直接开发祖先仍使用祖先自己的质量与直接计数。例如`A → B → C`中的C变好，不会把A的直接开发质量改成C的质量。

探索项让较少尝试的位置参与竞争。它不是新思想的语义评分，也不是对未来改进的预测。此规则借用上置信界（upper confidence bound, UCB）的形式；排名、候选集合和分支会变化，因此这里是分配启发式，不声称统计置信保证。默认`exploration_weight=1.0`，不随任务切换规则，也不声称有限预算下每个个体必获开发。

每次只决定一个开发起点，获得真实反馈后更新树并重新选择。不分配固定后续额度，不引入停滞阈值、路线配额或探索/利用阶段切换。

选中个体后，Refine、Explore、Crossover按既有比例0.45、0.30、0.25抽取。**选择中的探索项与Explore生成算子职责不同**：前者调节在哪个个体上花预算，后者要求怎样设计后代。交叉参考排除自身与相同源码，在剩余候选中按同一平均排名规则取质量不低于0.30者，再选AST结构距离最大的参考；优先尚未配对者。无参考时回到Refine。

日志保存每层选项的质量、已花评价、分数和最终选择，不再写父代采样概率。

## 3. 一次种群选择，随后简化树

每次受评入树后，在同一快照上确定：

1. **质量与实现差异代表**：按适应度排序，保留最好个体；在排名质量至少0.50的个体中，依次保留尚未被更优或同分近似实现代表的个体。标准化源码相同或AST结构距离小于0.08视为已被代表。AST差异是代码结构启发式，不等同于算法语义差异。
2. **近期个体**：全局评价时钟距其自身`last_used`小于40。父代或邻居活跃不会连带刷新它。
3. **必要分叉**：补齐连接上述个体所需的最低共同祖先（lowest common ancestor, LCA）分叉。

合并这三个集合。其他节点成为本轮移除区域。后代更好不再单独取消祖先的质量代表资格；旧祖先是否保留同样由质量、代码差异、近期活动及连接需要决定。Explore边没有永久保留屏障。树没有固定容量上限。

保留端点之间的中间路径及其同轮移除旁支，共同凝练到重连边V；其他移除旁支归入最近保留祖先S。一个移除节点只进入一个区域。各区域从维护前快照读取代码、真实父代比较、执行错误和旧经验，再一起提交更新。

路径和旁支都可能包含改进、同分、退步与失败。比较标签由程序计算；反思区分观察与可能解释，不把初稿成绩解释为整个思想的潜力。收缩边标注为压缩发展，算子标签仅保留是否包含Explore或Crossover的信息，不冒充一次直接生成。

## 4. 简化同时保留历史投入

若`P → A → B → C`收缩为`P → C`，新入边继承旧`P → A`的分支计数。该计数已经包含A、B、C及其移除旁支的开发投入，不能把嵌套计数相加。C自身的直接开发次数不变。

例如A开发B花1评，B开发C花1评，A另一个失败旁支花2评，C尚未开发。收缩后C的入边计数为4，C的直接计数仍为0。从P决定是否进入这片发展区域时，看见过去4评；到C决定是否直接开发它时，看见它还没有被尝试。

剪掉整条旁支时，祖先分支计数和全局时钟保留已经花掉的评价。简化后的分支计数不能用当前可见子节点数重新计算。重复收缩继续继承最外侧被折叠边的计数，避免预算清零和重复计费。

## 5. 算子读取同一棵树

| 算子 | 读取内容 |
| --- | --- |
| Refine | 当前完整实现、从根到当前个体的保留形成路径、路径S/V及当前个体的尝试。Explore步骤显式标注转向。 |
| Crossover | 当前与参考实现、真实共同祖先、祖先之后的两段发展及相关经验。参考不增加结构父代。 |
| Explore | 当前种群各个体的设计、成绩、派生来源及其S/V，并提供所选个体作为一个现有实现。 |

不再按Init/Explore边界截断历史，不额外分组“路线代表”。Explore概览直接使用已经维护过的种群，按成绩排序；默认展示全部，只有输入超限时缩减完整条目。默认输入上限30000 tokens；有服务端tokenizer时按真实计数，否则按UTF-8字节保守限制并记录口径。展示缩减不改变种群、计数或经验归属。

## 6. 运行与恢复

V3独立持有搜索循环、任务、模型客户端、程序评价与存储，不导入V1/V2或其他方法包。仓库实验入口支持`--method evotrace.v3`与`evotrace_v3`，使用V3自己的任务、模型和评价器，训练最好程序固定后再做独立测试。

`attempts.jsonl`的已提交尝试是恢复依据；有简化的尝试保存完整更新后树，其他尝试按实际评价重新接入。恢复不会重新调用反思。`run_config.json`保存方法、选择规则及全部配置，方法或条件不一致则拒绝恢复。`tree_latest.json`仅是便捷视图。

实现核验及认识变化见[本周记录](记录/2026-W46.md)。本轮功能检查不替代完整搜索效果比较。
