# EvoTrace 机制设计

三个机制围绕同一演化过程展开：用可比轨迹的真实收益分配下一次评价，按算子的设计问题组织局部材料，再把跨分支的认识凝练为可修订的条件经验。

## 方法正文

| 阅读入口 | 核心问题 |
| --- | --- |
| [方法总览](../method.md) | 轨迹怎样连接选择、生成与经验学习？ |
| [机制一：轨迹节点价值评估与预算分配](机制1-轨迹节点价值评估与预算分配.md) | 在当前质量与搜索阶段下，下一次评价投给哪个父代—算子组合？ |
| [机制二：轨迹引导的上下文与算子](机制2-轨迹引导的上下文与算子.md) | 当前修改需要哪些事实，模型具体要改变哪项计算？ |
| [机制三：轨迹反思与经验学习](机制3-轨迹反思与经验学习.md) | 哪些计算认识可以供其他分支借鉴，怎样保留条件并随新证据修订？ |

四张方法图及其中文图注集中在[机制示意图](../figures/mechanisms/README.md)，各图同时嵌入对应正文。

正文按设计问题、关键区分、机制定义和作用过程组织。[实现说明](实现说明.md)保存提示协议、日志字段、装入与恢复约定；日期化研究记录保存诊断、认识变化和实验结果。

文中适应度 `fitness` 均为越小越好的训练成绩。最终程序按训练成绩固定，独立测试只评价固定后的程序。

所有组合共用当前Base的评价、预算、修复公共实现和Boltzmann基础质量权重。未启用机制1时，交叉参考在共同质量池中均匀随机选择；机制2不再额外按计算结构筛选参考。V22.2与V23.2直接共用机制1；正式入口默认开启轨迹嵌入参考，显式使用`--no-trajectory-reference-embedding`才进行参考部分消融。V24.1直接继承V21.1，机制3保持当前的持久条件经验、展示选取与跨分支修订。

可直接形成以下对照：

- Base与V21.1：检验机制2。
- Base与V21.2：检验新版机制2；V21.2与`--reference-code`：检验参考是否给完整源码。
- Base与V23.2，以及V21.1与V22.2：分别在两种生成流程中检验机制1。
- V23.2与V22.2：在相同机制1下检验机制2。
- V21.1与V24.1：检验机制3。

比较时仍需使用相同任务、数据、种子、模型、选择温度和评价预算。版本名本身不证明条件相同。完整三机制组合尚未设为独立运行类。

[V21](V21.md)、[V22.1](V22.1.md)、[V23.1](V23.1.md)与[V24](V24.md)保留历史条件，当前入口不再启动这些实现。旧结果和冻结源码不迁移、不重命名。当前已进入四任务阶段，Base/V23.2/V21.1各12路运行，V22.2/V24.1各12路等待36路队列补位；具体条件见[记录](../记录/2026-11-09-四任务阶段与36路补位队列.md)。已运行批次继续按自己的冻结源码解释。运行入口见[实验说明](../../experiments/traceaad/README.md)。
