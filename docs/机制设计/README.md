# TraceAAD 机制设计

每份文档独立说明研究问题、核心认识与机制设计。已实现版本以实际代码为依据；设计规格明确标出尚未实现的状态，避免将候选机制当作已运行结果。代码、相关研究与分析在各文档中给出。

| 版本 | 研究问题 | 机制设计 |
| --- | --- | --- |
| [V14](V14.md) | 重复生成消耗预算，新设计缺少初期开发机会。 | 回访拒绝、无代码发散与定额发育。 |
| [V15](V15.md) | 当前成绩混合了设计质量与开发投入，提示中的其他实现又容易成为复制对象。 | 同投入竞争与设计层面的信息曝光。 |
| [V16](V16.md) | 阶段成绩可能低估仍在改进的方向，完整设计描述难以突出有效修改。 | 近期进步外推与修改轨迹上下文。 |
| [V17](V17.md) | 参考算法的整体质量不能指出哪些局部计算值得迁移。 | 同龄竞争与有来源证据的组件导入。 |
| [V18](V18.md) | 一次局部高分接续可能占据后续开发，父代的其他延伸缺少机会。 | 同龄竞赛与有限偏差接续搜索。 |
| [V18.1](V18.1.md) | 程序来源和源码变化不能准确表示思想出生，成熟程度不同的思想直接竞争。 | 出生审核、精炼年龄与有限同龄选择。 |
| [V19](V19.md) | 同一父代在不同设计操作下具有不同的开发状态，单一父代分数无法表示这种差异。 | 干预条件的轨迹预算分配。 |
| [V19.1](V19.1.md) | 固定算子比例无法利用父代—算子之间的条件关系，逐组合统计又容易冷启动。 | 共享先验下的轨迹条件父代—算子联合分配。 |
| [V19.2](V19.2.md) | 稀疏信用难以估计开发价值，零散生成也可能丢失可继续发展的计算。 | 当前修订为有界连续开发与源码反馈；已实现，尚无在线优势结论。 |
| [V19.3](V19.3.md) | 基于局部适应度比较的反思，如何学习算法演化中的改进策略并支持知识迁移？ | 评价后的轨迹级反思与全局正负经验池；已有独立实现，核心假设待实验检验。 |

文中 `fitness` 统一为越小越好的训练成绩。机制改变的是生成与开发机会的组织方式；最终程序由训练成绩确定，独立测试用于评价固定后的程序。
