# TraceAAD V14：抑制回访，支持新设计的初期开发

## 研究问题与核心认识

大语言模型驱动的自动算法设计（LLM-based automated algorithm design，LLM-AAD）依靠反复生成、评价和修改程序发现更优算法。有限预算下，搜索既需要精炼已有设计，也需要建立新的开发起点。然而，持续生成并不必然带来持续探索：模型可能返回已经评价过的代码，也可能围绕提示中的高分实现反复做小幅改写。

已有搜索轨迹揭示了两个相连的痛点。重复候选继续消耗生成与评价资源，却很少提供新的性能信息。即使生成了不同的设计，它的初版也往往尚未调优；直接按当前成绩分配后续机会，容易使它在完成必要修改之前就很少被选中。因而，探索不足同时涉及候选重复、代码锚定和新设计开发不足。

**核心认识是：有效探索需要让新尝试产生实际变化，让新起点减少对已有代码的依赖，并为其保留一段明确的初期开发。** 据此，TraceAAD V14 将回访拒绝、无代码发散与定额发育结合，分别作用于这三个位置。

## 回访拒绝：让重复回复成为生成反馈

回访拒绝（revisit rejection）以规范化抽象语法树（abstract syntax tree，AST）识别已经出现的程序。规范化移除注释、文档字符串与排版差异，因此仅改写说明文字不会获得新的有效程序身份。

重复回复保留记录，状态标为 `revisit`，并跳过执行评价。在预算允许时，同一生成请求最多重问一次，明确指出此前回复重复了当前程序、参考程序或其他已评价程序，要求落实实际改动。重问仍消耗生成预算。该机制节省重复评价，同时把已经识别的重复直接反馈给生成器。

## 无代码发散：用已有设计约束新的计算方向

无代码发散（code-free divergence）在搜索连续未刷新最好成绩时提供新的起点。提示展示已有算法的设计描述及近期新设计的开发结果，要求用不同的主决策计算重新构造算法。已有实现的完整代码不进入这一提示。

设计地图按成绩选择代表程序，并以代码距离减少相近实现的重复展示。距离采用数字归一化后的五词元片段 Jaccard 距离；默认地图最多包含八个程序，代表之间的距离至少为 0.3。这一距离用于组织提示中的实现覆盖，思想差异仍由生成出的实际决策规则体现。

默认停滞窗口为四十次候选生成。新最好成绩和一次发散期的结束都会重新确定停滞起点，使新建方向获得开发时间，也避免连续发散占据全部预算。

## 定额发育：先形成可竞争的实现

定额发育（reserved development）为有效新设计保留四次 `Mature` 修改。修改从该发散期目前最好的程序出发，围绕其主决策规则修补薄弱步骤、调整参数与完善辅助计算。每次修改都通过相同的训练评价检验。

这段机会独立于普通父代抽样，使粗糙初版不必立即与充分精炼的程序争取开发。发育结束后，有效成员进入常规候选集合，按当前质量与历史直接改进经验获得后续机会。若发散没有取得有效起点，至多再请求一次新设计。

三个机制共同组织停滞后的探索：回访拒绝减少已知实现的重复评价，无代码发散改变新起点的上下文，定额发育让新起点的价值经过实际修改后再参与常规竞争。其直接检验对象是新增有效候选和发育后的改进，最终算法质量仍由执行成绩衡量。
