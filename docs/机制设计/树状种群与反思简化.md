# 持续生长的树状种群与反思简化

**摘要。** 大语言模型（LLM）驱动的自动算法设计（Automated Algorithm Design，AAD）迭代地选择已有算法，并以它们为条件提示LLM生成新算法。在这一过程中，方法跨迭代维护的搜索状态同时承担两种角色：它是选择算子的候选集合，也是生成算子的条件上下文。现有方法只针对其中一种角色设计搜索状态。基于种群的方法维护有界的高适应度个体集合，个体被淘汰时，其形成过程携带的信息随之丢失。基于树的方法保留完整的派生关系，但结构随评价预算持续增长，其中的演化信息停留在单步修改的粒度。反思机制则把经验存入与搜索状态相分离的外部记忆。我们提出**树状种群**（tree-structured population）：一个受结构约束、持续生长的搜索状态，节点是算法个体，边是个体之间的发展关系及其经历记录。树状种群由生长、剪枝和**反思简化**（reflective simplification）三个算子交替更新。反思简化在收缩树的局部结构的同时，把被移除部分的演化经历凝练为保留结构上的记录，使个体选择与经验凝练在同一次更新中完成。更新后的树为预算分配和各生成算子提供统一的、多尺度的演化上下文。

## 1. 动机

### 1.1 搜索状态的两种角色

给定任务的评价函数 $f$（越小越好）和评价预算 $B$。在第 $t$ 次迭代，方法维护搜索状态 $S_t$，并执行四个步骤：

$$
(p,o)\sim\pi(\cdot\mid S_t),\qquad
a'\sim \mathrm{LLM}\big(\cdot\mid c_o(p,S_t)\big),\qquad
y=f(a'),\qquad
S_{t+1}=U(S_t,a',y).
$$

其中 $\pi$ 选择父代 $p$ 与算子 $o$，$c_o$ 从搜索状态中构造生成上下文，$U$ 是状态更新算子。

$S_t$ 以两种方式影响搜索。它通过 $\pi$ 决定搜索从何处继续，通过 $c_o$ 决定LLM以何为条件生成。在经典进化计算中，变异与交叉只作用于父代的基因型，谱系不进入变异算子，因而可以作为记录单独维护。在LLM驱动的AAD中，这一前提不再成立：祖先、同起点的其他尝试以及其他分支的发展，都可以经由 $c_o$ 进入生成，并改变生成的分布。我们的消融分析支持这一点：从上下文中移除同一父代的已有尝试后，子代优于父代的比例由27.5%降至16.7%（[记录](../记录/2026-W45.md)）。

因此，搜索状态中保留哪些演化信息、以何种粒度保留，是搜索算法自身的设计变量，而不是实现层面的存储选择。

### 1.2 现有搜索状态只为一种角色设计

**基于种群的方法**（EoH、FunSearch、ReEvo、PartEvo等）以有界的个体集合作为搜索状态，$U$ 按适应度执行淘汰。这一设计服务于选择。个体的形成过程，以及被淘汰个体所代表的尝试，不属于搜索状态，生成算子无法以它们为条件。

**基于树的方法**（MCTS-AHD、Clade-AHD、A2DEPT）保留全部已评价算法及其派生关系。树主要服务于选择，例如以后代的评价统计决定扩展位置。作为生成上下文，它有两个限制：结构规模随评价预算增长，没有容量约束；路径由单步修改构成，一种计算方式的引入、补全与调整分散在多个相邻步骤中。PhyloEvolve进一步对演化森林剪枝，其准则是成绩统计，保留的路径仍为单步粒度。

**基于反思的方法**（ReEvo的长短期反思、PathWise的路由反思、PhyloEvolve的总结模块）把演化经历凝练为文本经验。经验存放在与搜索状态分离的外部记忆中，按独立的时间表更新，并脱离了产生它的个体与位置。

三类方法的局限有共同的根源：**状态更新算子 $U$ 只被设计为个体的选择；演化经历的取舍或者没有发生，或者由一个独立的过程完成。** 由此，作为生成条件的演化信息缺少三项性质。

- **选择性**：保留的经历经过取舍，规模有界。
- **阶段粒度**：经历以算法发展的阶段为单位，而不是以单步修改为单位。
- **局部性**：经验保留在产生它的结构位置上，其适用条件随位置保留。

## 2. 树状种群

我们把搜索状态定义为一棵树 $T_t=(V_t,E_t)$。

- 节点 $v\in V_t$ 是一个已评价的算法个体 $v=(a_v,d_v,f_v)$，包含代码、设计描述（Design）和适应度。$V_t$ 即当前种群。
- 边 $e=(u\to v,\,r_e)\in E_t$ 表示 $v$ 由 $u$ 发展而来。$r_e$ 是这段发展的**阶段记录**。
- 具有多个子分支的节点 $u$ 另带一份**比较记录** $m_u$，描述从 $u$ 出发的不同方向及其结果。

树的形状由结构约束 $\Omega$ 控制。深度范围、分支数量范围与节点总数是 $\Omega$ 的候选维度。

搜索状态由三个算子交替更新：

$$
T_{t+1}=\mathcal{R}_\Omega\Big(\mathcal{P}_\Omega\big(\mathcal{G}_k(T_t)\big)\Big).
$$

生长算子 $\mathcal{G}_k$ 从当前树扩展并评价一批 $k$ 个候选。剪枝算子 $\mathcal{P}_\Omega$ 更新参与搜索的个体集合。反思简化算子 $\mathcal{R}_\Omega$ 收缩树的拓扑，并更新记录 $r$ 与 $m$。约束 $\Omega$ 与批量 $k$ 共同决定生长与整理的节奏。

图1给出一次更新的示意。节点A与D作为个体保留；B、C、E离开种群，它们的演化经历进入A与D之间的阶段记录。

```
G 之后                          P 与 R 之后

A ── B ── C ── D                A ══════ D
│                                   r
└── E                           r：A 到 D 这一阶段的发展经历
```

## 3. 更新算子

### 3.1 生长

$\mathcal{G}_k$ 依据当前树选择 $k$ 个扩展位置，由Refine、Crossover或Explore生成候选并评价，新个体作为节点接入树中。批量生长使随后的整理面对的是一片新扩展的区域，从而能够以阶段而非单步为单位处理演化经历。

### 3.2 剪枝

$\mathcal{P}_\Omega$ 移除节点或分支，使树满足 $\Omega$。种群的淘汰由此成为树上的结构操作。

剪枝的目标是在约束内保留执行不同计算的个体。适应度反映个体当前的性能；它不区分计算方式，适应度相同的两个程序可以执行不同的计算。因此剪枝同时使用代码结构比较与嵌入相似度，识别相近的实现、重复的修改和不同的计算方向。

### 3.3 反思简化

$\mathcal{R}_\Omega$ 作用于树的一个连通区域：以更少的节点和连接替换该区域，并把该区域的演化经历凝练为保留结构上的记录。它有两种形式，分别沿树的两个方向工作。

| 形式 | 拓扑操作 | 凝练得到的经验 |
| --- | --- | --- |
| 路径收缩 | 将路径 $u\to\cdots\to v$ 收缩为边 $u\to v$ | **阶段经验** $r_{u\to v}$：算法怎样从 $u$ 发展到 $v$ |
| 分支归并 | 整理节点 $u$ 之下的子分支 | **比较经验** $m_u$：从 $u$ 出发的不同方向各自达到了什么结果 |

跨分支的认识由此获得明确的结构位置，即相关分支的最近共同祖先。

反思简化可以递归作用于已简化的结构。较早的发展阶段随搜索推进被再次凝练，因此距当前节点较近的经历较细，较远的经历较粗。树状种群中的演化上下文由此具有多个尺度。

### 3.4 三个算子的必要性

移除任一算子，树状种群退化为一类已有的搜索状态。

| 更新算子 | 搜索状态 | 缺少的性质 |
| --- | --- | --- |
| $\mathcal{G}$ | 全历史树 | 选择性、阶段粒度 |
| $\mathcal{G}+\mathcal{P}$ | 有界种群 | 被淘汰个体的经历不再保留 |
| $\mathcal{G}$ 与独立的反思 | 全历史树加外部经验记忆 | 局部性；经验不随结构被选择 |
| $\mathcal{G}+\mathcal{P}+\mathcal{R}$ | 树状种群 | — |

剪枝与反思简化互为条件。结构收缩必然丢失信息，经验凝练决定丢失之后保留什么。反过来，结构约束为凝练提供了边界：经验只为保留下来的结构而写，并随该结构在后续更新中被继续选择。

## 4. 反思简化作为经验凝练

独立的反思模块需要回答三个设计问题：何时反思，以什么为材料，经验存于何处并如何检索。在树状种群中，这三个问题由结构回答。

| 设计问题 | 独立的反思模块 | 反思简化 |
| --- | --- | --- |
| 触发 | 固定的评价次数间隔 | 结构事件：一个区域被简化 |
| 材料 | 另行选取的尝试与待分析的问题 | 被简化的区域 |
| 存储与检索 | 外部经验库，另行选取与展示 | 边与节点上的记录；构造视图即检索 |

经验因此与个体受到同一选择过程的作用。一个方向被剪除时，它的经历归入分叉节点的比较经验。一个方向继续发展时，它的阶段经验保留在形成路径上。

## 5. 基于树状种群的选择与生成

选择算子与生成算子以同一棵树为依据。我们把各算子所需的上下文定义为树上的**视图**。

| 视图 | 定义 | 使用者 |
| --- | --- | --- |
| 局部视图 | 根到 $v$ 的路径及其阶段记录，$v$ 处的比较记录 | Refine：决定接下来修改哪一项计算 |
| 成对视图 | $v$ 与 $w$ 各自到最近共同祖先的路径，及该祖先的比较记录 | Crossover：决定迁移哪一项计算、怎样融合 |
| 全局视图 | 收缩到主要分叉节点与代表节点的树，及各分叉处的比较记录 | Explore：决定探索哪一个计算方向 |
| 结构状态 | 各分支的规模、适应度与发展经历 | 预算分配：决定下一批候选的扩展位置 |

历史个体以Design和记录的形式进入上下文，当前被修改的算法提供完整代码。三种视图取自同一结构的不同范围，不需要分别维护材料。

EvoTrace此前的三个机制在树状种群中的关系如下。轨迹反思与经验学习成为状态更新的一部分，即反思简化。轨迹节点价值评估与预算分配、轨迹引导的上下文与算子，分别对应树状种群上的选择算子 $\pi$ 与上下文构造 $c_o$。

## 6. 与已有工作的关系

谱系的在线维护在进化计算中已有成熟的方法，包括绝灭旁支的清理与单子节点的路径压缩（Phylotrack）。这些方法以无损地保留现存个体的祖先关系为目标，谱系本身不参与变异。在LLM驱动的AAD中，谱系经由上下文进入生成算子（§1.1）。维护准则因此需要从拓扑上的无损，转为对后续生成的有用性：收缩是有损的，保留的内容由经验凝练决定，个体的取舍需要区分计算方式而不只是成绩。树状种群的剪枝与反思简化依据这一准则设计。

在AAD及相近的LLM程序演化方法中，与树状种群最接近的工作如下，完整核对见[相关工作调研](../记录/2026-11-11-树状种群与剪枝简化的相关工作调研.md)。

| 工作 | 搜索状态及其更新 | 与树状种群的区别 |
| --- | --- | --- |
| MCTS-AHD、Clade-AHD、A2DEPT | 全历史树；Clade-AHD冻结低潜力子树 | 结构不收缩，路径为单步粒度 |
| PathWise | 内层派生图与外层种群；个体携带来源摘要 | 派生图在每轮外层更新后重新建立，拓扑不跨轮保留 |
| PhyloEvolve | 持续演化的森林；按成绩统计剪除节点、分支与整树 | 没有路径收缩；经验由独立的总结模块与精英池维护 |
| PACEvolve | 思想—假设层级池，限额、总结与删除 | 凝练的对象是思想，层级关系不是完整算法之间的发展关系 |

## 7. 贡献

1. **树状种群。** 我们指出LLM驱动的AAD中搜索状态同时是选择集合与生成条件，并据此提出树状种群：一个受结构约束、持续生长的搜索状态，联合维护算法个体与它们之间的发展经历。
2. **反思简化。** 我们提出与生长、剪枝交替执行的反思简化算子。它把拓扑收缩与经验凝练合并为一次状态更新，使保留的演化经历具有选择性、阶段粒度与局部性。
3. **基于树状种群的选择与生成。** 我们在同一结构上定义局部、成对与全局视图，为预算分配和Refine、Crossover、Explore提供统一的多尺度演化上下文。
