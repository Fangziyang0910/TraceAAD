# V19.3：基于轨迹级反思的算法改进经验累积与迁移

*已有独立实现，核心假设待实验检验。*

## 1. 研究问题：从适应度比较到算法演化经验

基于大语言模型的自动算法设计（LLM-based automated algorithm design，LLM-AAD）通过生成、评价与演化候选算法，在有限搜索预算内寻找高质量算法。演化反馈既用于选择候选，也可以形成指导后续生成的算法改进经验。如何从搜索过程学习这些经验，决定了已有探索能在多大程度上帮助后续算法发现。

现有方法已将反思与经验复用引入算法演化。ReEvo通过个体间的适应度（fitness）比较形成短期反思，再将新反思与既有长期反思整合，用于指导交叉与变异。[ReEvo，§4](https://arxiv.org/html/2402.01145)。RefineEvo根据一次演化操作的父子代描述、操作目标及适应度反馈，提取带适用条件的正负经验，并依据后续使用结果维护经验效用。[RefineEvo，§3.3、E.4](https://arxiv.org/html/2607.11358v1)。

这些方法主要以个体比较或单次演化操作为反思单元。算法思想的发展还包含连续修改之间的配合、失败后的适配，以及后续演化对早期经验的修正。基于局部适应度比较形成的经验，可能将一个需要继续发展的算法思想归为失败，也可能将依赖特定算法结构的改进概括为一般建议。这会影响后续搜索对改进策略的选择与迁移。

经验反思也有更广泛的基础：ExpeL从智能体成功与失败轨迹中提炼洞见，EvoPH在AAD中利用累计执行经验更新提示和演化策略。[ExpeL，§4.2](https://arxiv.org/html/2308.10144v3)、[EvoPH，§4.1–4.2](https://arxiv.org/html/2509.24509v1)。V19.3关注带真实修改关系、同父代对比与评价结果的算法演化记录，检验这些关联是否提高经验对其他实现的迁移价值。

以一个可能的演化过程为例：算法引入前瞻后超时，随后通过候选筛选使前瞻可行，再调整评价函数获得更好的解。单次比较分别反映每一步的局部收益；联合考察整段演化，则可以归纳前瞻、筛选与评价函数之间的适配关系，并据此判断另一算法应如何借鉴这一策略。

V19.3研究的问题是：

> **如何通过反思算法演化轨迹，累积可迁移的算法改进经验，进而提高后续算法发现的效率与质量？**

## 2. 核心思想：将演化轨迹作为经验学习单元

V19.3通过轨迹级反思（trajectory-level reflection），学习算法思想如何经过探索、精炼与适配形成有效算法。经验描述的是一类设计问题可以采用怎样的改进策略、这些策略怎样协同，以及它们依赖什么算法背景。后续演化提供新证据，使已有经验得到补充、修正或重新解释。

这一思路借鉴派生类比（derivational analogy）：利用既往求解过程及其成功、失败条件，指导新问题的求解。[Carbonell与Veloso，1988](https://www.cs.cmu.edu/~mmv/papers/CarVel88.pdf)。在AAD中，源算法与目标算法可以具有不同的表示和计算结构。轨迹级反思以自然语言归纳改进策略及其形成背景，生成模型再结合目标算法完成适配。

**核心假设是：与逐次累积局部反思相比，联合反思算法演化轨迹，更有利于学习具有适用条件的改进策略，并提高经验对其他算法实现的迁移价值。**

本设计的贡献集中于一种经验学习机制：以演化轨迹组织反思，以后续演化反馈修订经验，再根据目标算法的设计背景进行知识迁移（knowledge transfer）。本文聚焦同一问题类中不同算法实现之间的经验迁移。

## 3. 机制设计

### 3.1 全局正负经验池

V19.3在同一任务的一次搜索中使用所有候选算法共享的正负经验池\(\mathcal E_t^+\)与\(\mathcal E_t^-\)。正经验概括有效的改进策略及其适用条件；负经验概括失败模式、策略局限与相应建议。经验采用与RefineEvo一致的内容结构：

\[
e=(\text{summary},\text{recommendations},\text{applicable\_when}).
\]

`summary`概括轨迹支持的设计认识，`recommendations`给出具体改进建议，`applicable_when`说明适用的算法背景。系统关联其来源轨迹，供后续理解和比较。经验在不同算法实现之间共享，检索与适配依据目标算法的设计背景。

一段演化轨迹可以同时产生正经验与负经验。例如，候选筛选可能使前瞻可行，随后评价准则的调整才带来解质量改善；这段过程可以同时形成关于可行性、决策评价与无效计算的经验。

### 3.2 经验引导的算法生成

根据当前算法设计和近期演化反馈，从两个经验池分别检索相关经验：

\[
\mathcal R_p^\pm=\operatorname{Retrieve}(\mathcal E_t^\pm,q_p).
\]

生成模型读取任务、当前算法完整代码、相关演化记录及检索经验，提出候选：

\[
(c,a_c,d_c)\sim G_\theta(\mathcal T,p,\tau_p,\mathcal B_p,\mathcal R_p^+,\mathcal R_p^-).
\]

其中\(\tau_p\)为父代的形成轨迹，\(\mathcal B_p\)为相关旁支，\(a_c\)说明相对当前算法的实际修改，\(d_c\)概括候选的完整算法。模型根据目标表示与计算结构适配经验，形成可执行的新实现。

候选随后接受评价。必要的修复形成独立代码版本，与生成版本共同保留在该次演化尝试中。

### 3.3 评价后的轨迹级反思

反思在一次演化尝试完成评价及修复后独立进行。一次修改记为\((p,\Delta,c,y_c)\)，其中\(\Delta\)为实际代码变化，\(y_c\)为执行状态与适应度反馈。反思围绕候选的形成轨迹及相关旁支展开：

\[
\tau_c=\bigl(p_0,(\Delta_1,p_1,y_1),\ldots,(\Delta_\ell,c,y_c)\bigr).
\]

反思模型以本次新评价支持的新认识为中心，比较真实父子关系中的算法变化与评价结果，分析多步改进怎样配合，以及后续结果怎样限定早期建议。较早的修改及同父代旁支为解释新结果提供背景。生成候选时实际提供的经验一并呈现，帮助理解策略在目标算法中的适配结果。

\[
(\mathcal L_c^+,\mathcal L_c^-)\sim
R_\theta(\mathcal T,\tau_c,\mathcal B_p,\mathcal R_p^+,\mathcal R_p^-).
\]

反思输出可复用的策略与适用条件。它区分解质量、计算可行性与仍待检验的建议，使失败经验能够帮助算法思想继续发展。生成与反思使用同一基础模型的不同提示，各自承担算法实现与经验学习的任务。

### 3.4 经验累积与迁移

新经验加入相应的全局池，内容相同的经验合并来源记录。后续结果可以形成对早期建议的更新解释；池中的既有条目通过使用反馈维护效用。该规则沿用RefineEvo的实现：初始分数为0，实际提供过的经验在候选改善父代时加1，否则减1，分数小于0时移出检索池。正负类别描述经验内容本身。

\[
\mathcal E_{t+1}^\pm=\operatorname{Maintain}(\mathcal E_t^\pm,y_c)\cup\mathcal L_c^\pm.
\]

后续算法可以检索这些经验，并在自身表示与计算结构中重新实现相关策略。新的适配结果又进入轨迹级反思，形成具有新背景的经验。原算法、其后代与其他分支均通过同一经验池获得相关知识。

整体机制为：

\[
\text{全局正负经验}
\rightarrow\text{算法生成}
\rightarrow\text{评价反馈}
\rightarrow\text{轨迹级反思}
\rightarrow\text{全局经验累积}.
\]

## 4. 方法实例化

### 4.1 搜索与检索

有效算法按规范化源码去重，并根据训练适应度排序，fitness越小越好。设\(r\)为名次、\(n\)为有效非重复算法数，父代选择概率为：

\[
P(p_r)=0.95\frac{r^{-2}}{\sum_{j=1}^{n}j^{-2}}+\frac{0.05}{n}.
\]

同分算法平均分配对应名次的总权重。初始化顺序生成五份有效且规范化源码不同的算法；每次可以读取此前实际形成的初始设计及结果。随后通过上述选择与经验引导持续演化。重复候选仍接受真实评价并保留实际来源，但不增加选择权重。

经验检索采用BM25，参数为\(k_1=1.5,b=0.75\)，索引由经验的三项内容组成。查询使用当前及近期版本的`design`，两个池各取相关性最高的至多三条，零匹配不展示，同分随机。分词兼容英文词项与中文字符、相邻双字符。相同经验去重展示，来源与目标的谱系关系保存在运行记录中。

### 4.2 轨迹上下文

形成轨迹默认包含最近三次主链演化尝试及其生成、修复阶段；相关旁支取同一父代最近两次其他已完成尝试。生成与反思共用相同的版本关系和结果表示，反思材料包含本次刚完成的评价。

每条记录给出所选父代、代码修改起点、实际修改与评价结果。系统标明相对有效父代的改进、持平或退步；失败阶段提供执行状态。代码和差分按实际版本共享，相关经验提供完整建议及适用条件。

历史与经验材料默认共用8192 tokens，当前完整代码另行保留，并按模型窗口预留输出。优先保留本次已评价的修改、主链关系和相关经验；完整修改按实际token长度选择差分或尚需提供的版本。较早或较次要修改放不下时保留结果摘要。普通生成中的超时历史标为timed out，实际时限用于超时修复。

### 4.3 模型接口与成本

生成接口返回`code`、`analysis`与`design`三个字符串。反思接口返回`positive`和`negative`两个经验数组，每条包含`summary`、`recommendations`与`applicable_when`。一次反思可以只形成某一类经验，也可以同时形成两类经验。

初始化形成算法起点；有实际代码与评价反馈的演化尝试触发轨迹级反思。正常生成、最多一次共享修复及一次独立反思分别计入模型请求与token成本。经验提取失败时保留已有算法与评价结果，后续搜索继续使用已有经验池。

生成与修复保留独立代码版本。每次尝试以最后一个实际已评价版本对所选父代判定改进，经验效用只更新一次；实际评价失败记为未改进，未获算法评价的接口或解析故障不更新。只给生成时实际展示的经验更新效用。反思最多保存三条有效经验，超量与无效条目随原始回复保留。

历史材料与完整输入分别检查容量，完整输入还预留角色输出、schema及协议空间。检查点保存调用阶段、已返回的回复和经验提交状态；恢复继续处理已保存回复，在途但无回复的请求保留计数与未知用量。模型、任务、提示、tokenizer或源码不兼容时拒绝恢复。

完整输入定义、英文提示与例子见[上下文与提示词](V19.3-上下文与提示词.md)。

代码、运行方式与消融参数见[独立实现](../../traceaad_v19_3/README.md)及[实验入口](../../experiments/traceaad_v19_3/README.md)。

## 5. 验证方案

### 5.1 反思单元的作用

核心检验是：**在相同演化经历下，轨迹级反思能否比单次演化反思形成更有迁移价值的经验？**

固定源演化记录、适应度反馈与独立初始化的未见目标，比较：

| 条件 | 经验形成方式 | 检验目的 |
| --- | --- | --- |
| 单次演化反思 | 每次根据父子比较形成正负经验，累积到全局池 | 局部经验累积的迁移能力 |
| 同父代对比反思 | 本次尝试及同父代旁支 | 同一起点上的不同修改提供的作用 |
| 轨迹级反思 | 每次联合分析近期主链与旁支，形成正负经验 | 跨步骤关系对经验学习的价值 |
| 原始轨迹上下文 | 将对应源演化记录直接提供给目标生成 | 显式经验相对于原始历史的作用 |

前三组共用经验结构、检索、生成提示与反思调用次数，仅改变反思可见的演化范围。源—目标组合由共同的算法设计信息确定，源经验构建按冻结记录的顺序进行，适应度对应档案中的实际代码。冻结源阶段仅提取经验；目标阶段根据真正提供过的经验更新效用。源记录若包含当时实际提供的经验，各组读取同一份历史记录。迁移阶段统一目标生成预算、模型、评价条件与材料上限，经验形成成本计入总成本。

主要评价固定目标预算内得到的最好有效算法及其独立测试成绩，同时分析有效率、负迁移、实际呈现的演化步数与典型策略适配。按中间修改未改善、后续适配才改善的轨迹与单调改进链分层，判断跨步骤关系是否构成主要帮助。

### 5.2 完整算法发现

完整搜索比较不同反思范围在相同搜索与经验池配置下的表现，并考察经验共享对不同算法分支的作用。实验沿用[统一任务与评价约定](../../experiments/PROTOCOL.md)，具体配置确定评价接口与时限。

默认每路搜索为1000次实际评价，包含初始化、失败与修复评价。独立反思的请求、token与耗时另外计量。除评价次数对应的发现质量外，报告按实际模型成本对齐的最好训练成绩曲线。

搜索结束固定训练适应度最好的有效算法，同分取较早记录，再执行独立测试。分析报告正负经验实际进入生成的情况、经验来源与目标的设计差异，以及适配后的新经验，刻画全局经验共享的作用。
