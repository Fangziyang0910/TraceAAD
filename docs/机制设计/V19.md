# TraceAAD V19：干预条件的轨迹预算分配

## 研究问题与核心认识

程序个体的当前成绩同时受到设计质量和已经获得的开发投入影响。一个方向可能已经取得较好成绩但仍未充分检验，也可能经过大量尝试后仍没有形成有竞争力的后代。只按当前成绩选择父代，会让先占据优势的方向持续获得机会；只按新旧或出生时间分配机会，又无法判断一个新个体是否真的代表有价值的设计方向。

**V19 将父代选择表述为对设计方向分配下一次试验机会。** 当前个体的质量提供初始判断，直接子代的绝对质量反映继续围绕该方向生成的表现，已完成的开发次数反映仍有多少未知。开发程度调节选择机会，但不被解释为设计价值，也不把“超过父代”作为收益。

## 设计方向的隐式表示

V19 不增加显式的思想编号或设计簇。每个有效程序及其 `parent_id` 形成一个可追溯的局部设计轨迹；`analysis`、`design`、`code` 和评价结果共同描述该方向在一次试验中的实现与反馈。交叉仍然可以连接两个来源，参考个体只承担知识提供角色，不改变主要父代的开发计数。

## 开发统计与父代选择

先在当前有效程序库内按训练成绩计算倒数平均排名质量 `q_i`，成绩越小越好。V19 先按固定比例确定算子 `o`，再在该算子内部为每个候选父代 `i` 统计：

- `n_i,o`：该个体在算子 `o` 下作为主要父代完成的生成尝试次数；
- `r_i,o,j`：第 `j` 个直接子代的绝对质量，按当前程序库中的倒数排名计算；
- 失败的格式、运行和超时尝试记为一次开发机会，并令 `r_i,o,j = 0`。

一次生成及其最多一次修复只计为一次父代—算子尝试。修复后的有效程序使用最终评价结果；修复仍失败的尝试保留失败反馈，但不进入有效程序库的质量排序。

对每个父代—算子对计算平滑平均表现：

\[
\mu_{i,o}=\frac{\kappa q_i+\sum_j r_{i,o,j}}{\kappa+n_{i,o}}.
\]

再加入该算子下的开发不确定性：

\[
U_{i,o}=\mu_{i,o}+\lambda\sqrt{\frac{\log(1+N_o+M)}{1+n_{i,o}}},
\]

其中 `N_o` 是算子 `o` 已完成的开发尝试总数，`M` 是当前有效程序数，`kappa` 是当前质量的先验强度，`lambda` 是不确定性系数。V19 默认使用 `kappa = 3`、`lambda = 0.5`，按 `U_i,o` 抽样主要父代。

这个条件化很重要：一个父代可能已经充分进行 Refine，却几乎没有进行 Explore；总开发次数不能据此压低它在 Explore 下的价值。V19 因此不把父代视为单一的固定 arm，而把每个父代在不同算子下的局部轨迹分别估计。该分数不使用父子成绩差值，不设置搜索阶段，也不给每个新个体固定的额外进化次数。

## 与三个算子的关系

算子比例回答“本次试验属于哪种设计干预”，父代—算子选择回答“该干预应当作用于哪个设计方向”：

- **Refine**：在当前设计方向附近继续检验和改进；
- **Explore**：改变关键设计原则，检验替代方向；
- **Crossover**：组合两个已有方向，检验机制之间能否形成有效方案。

三个算子仍按固定比例调用。V19 不根据算子历史改变三者的全局比例，而是在每个算子内部使用自己的局部轨迹分配父代机会。

## 轨迹反馈

父代选择只使用压缩后的统计量；模型上下文继续使用完整的局部轨迹：当前父代提供完整 `analysis`、`design` 和 `code`，祖先、直接子代和少量失败子代提供分析、设计与评价结果，交叉参考个体提供完整设计信息和代码。这样，统计量负责分配试验机会，轨迹负责说明下一次试验应当怎样设计。

失败反馈分为两种作用。格式、运行和超时失败降低相应方向产生可用程序的统计表现，并把具体失败原因提供给后续修复或生成；合法运行但成绩较差的程序保留其设计与分析，用于提示后续精炼或转向。失败不会被解释为设计方向绝对无效。

## 方法核心叙事

V19 的核心不是提出一个新的质量排名公式，而是改变有限预算在自动算法设计中的含义。一次评价不是简单检验一个孤立程序，而是对某个设计方向施加一次具体干预；因此，预算应分配给带有干预历史的父代—算子轨迹。

TraceAAD 将这一机制概括为**面向主动算法设计的干预条件轨迹分配**（intervention-conditioned trajectory allocation for active algorithm design）：当前质量提供设计方向的初始判断，直接子代结果描述该方向对某类干预的响应，开发次数描述该响应仍有多少未知，轨迹上下文则把这些反馈转化为下一次设计。

这个观点把父代价值定义为条件价值：一个父代是否值得继续使用，取决于“对它执行哪种操作”以及该操作在此前轨迹中的表现。Refine、Explore 和 Crossover 因而不是同一分数下的标签，而是三种不同的设计干预。该机制同时连接了质量利用、欠开发探索和轨迹驱动的设计反馈。

## 实现与验证

V19 基于独立的 [`traceaad_v19`](../../traceaad_v19/README.md) 实现，只替换 Base 的父代机会分配，保留任务接口、JSON 输出、历史上下文、三算子、一次修复、评价预算和最终选择规则。[`selection.py`](../../traceaad_v19/selection.py) 先选择算子，再计算该算子下的质量先验、直接子代统计和不确定性选择分数；每次演化尝试在 `selection` 字段中保存实际统计量。

离线测试覆盖绝对子代质量、失败尝试记账、不确定性随开发程度变化、父代选择和完整 Base 流程。V19 的收益需要与相同提示、模型、种子和评价预算下的 Base 进行单变量对照。
