# V23.2：Boltzmann Base 加新版机制1

用户于2026年11月9日确认：基础预算分配与机制1交叉参考均已改变，当前组合改名为V23.2。旧V23.1的实验名称、结果与冻结源码保留，不能用新实现续跑旧日志。

代码位于[traceaad_v23_2](../../traceaad_v23_2/)。生成流程继承当前[Base](../TraceAAD-Base.md)，预算估计与交叉参考共用[机制1](机制1-轨迹节点价值评估与预算分配.md)的选择与运行实现。

Base按当前成绩做纯Boltzmann父代采样，温度由`Config.selection_temperature`设置；算子概率固定，交叉参考从共同质量候选池均匀随机选择。V23.2从相同的基础质量权重出发，用近期可比轨迹的真实冠军改善与实际评价成本修正预算分配。

当前统一实验入口默认开启轨迹嵌入参考，也可显式使用`--trajectory-reference-embedding`声明完整机制1。轨迹表示包含当前设计与代码、最近三步真实修改及观察结果；从与Base相同的合格池中选择余弦相似度最小的参考。没有合格参考时，两边均直接报错。显式使用`--no-trajectory-reference-embedding`时，V23.2使用同池随机参考，作为参考部分的消融，轨迹收益修正仍在运行。

生成侧只读当前算法的代码、设计与成绩，交叉增加所选参考的设计与成绩；不提供机制2的轨迹上下文，也不进行反思。初始化、修复和输出顺序沿用Base。

统一入口为`--method v23.2`或`v23_2`，默认结果目录为`traceaad_v23_2`。选择规则、温度、生成协议及参考模型设置均进入恢复核对。向量缓存和嵌入用量独立记录，失败不回退成随机参考。设计见[机制1](机制1-轨迹节点价值评估与预算分配.md)。

正式对照为同一冻结源码下的新Base与V23.2，六任务各种子0/1/2，每路1000次完整评价。两组生成、数据、评价预算和模型设置相同；Base使用纯Boltzmann与随机参考，V23.2使用轨迹收益修正与轨迹嵌入参考。旧V23.1条件见[历史规格](V23.1.md)。
