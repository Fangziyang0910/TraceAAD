# TraceAAD V18.1：识别思想出生，按精炼年龄补充分配机会

## 研究问题与核心认识

大语言模型驱动的自动算法设计（LLM-based automated algorithm design，LLM-AAD）中，当前成绩同时反映算法思想与实现的精炼程度。成熟设计可能仅因得到更多修改就占据优势，使刚出现的有效思想缺少继续发展的机会。要比较相近成熟程度下的表现，首先需要明确一个思想何时出生，以及哪些修改仍在精炼同一个思想。

程序来源不能直接回答这个问题。不同起点可能实现相同的决策规则，一个程序的后代也可能转向新的规则。源码变化同样不等于思想变化：调参、等价改写和重复生成都可能产生不同记录。若这些变化反复获得新的保护，有限预算就会继续流向已经充分开发的内容。

**核心认识是：同龄机会应绑定于实际决策机制的出生身份，并在精炼过程中共享有限额度。** TraceAAD V18.1 据此建立可审查的出生记录，用精炼年龄组织历史比较，再以有限同龄通道补充常规父代选择。

## 出生审核：从实际代码确定开发对象

思想出生（mechanism birth）定义为某个核心决策机制在本次搜索中的首次有效实现。核心机制指实际决定选择、优先级、构造、更新或接受的计算。参数调整、重命名和等价改写继续属于已有思想。

出生审核在程序通过执行评价后进行。独立审核请求读取候选、主父代、交叉参考及已有机制记录，根据实际代码判定它是新机制、已有机制还是无法确认。审核不读取成绩或生成者的设计自述；明确判断必须附上候选代码中的逐字片段和相应理由。登记表较大时，在输入额度内检索相关机制，并记录实际检查的对象。

规范化 AST 相同的程序直接继承首次记录的出生身份和年龄。其他不确定判断保守沿用有效父代的身份；无有效父代时建立未确认记录，不授予同龄额度。出生记录因此提供可回查的操作性身份，具体判断由所检查的代码与登记范围支撑。

## 精炼年龄：把思想变化与实现改进分开计量

确认的新思想年龄为零。同一思想的后代沿实际来源的精炼深度增加一；主父代与交叉参考都属于该思想时，使用两者较大年龄加一。已有思想在缺少同思想直接来源的情况下重现，在该思想已达到的最大年龄上加一。修复与原失败生成合为一次形成步骤，完全重复的程序保持原年龄。

这个年龄描述思想经历的精炼深度。实际请求数、token 数与执行评价成本另行记录，分别回答成熟程度和资源消耗的问题。

每个出生标识在各年龄首次到达时的成绩形成固定历史。后续重试不改写这份历史，每个标识在同一年龄最多贡献一个参照。因此，年轻程序比较的是其他思想在相同精炼位置留下的表现。

## 有限同龄选择：保留开发机会并约束重复保护

同龄通道只考虑已确认思想在当前最深年龄中的最好个体。将其与其他出生标识在该年龄首次记录的成绩比较，采用平滑胜率

\[
R=\frac{1+w+0.5t}{2+n},
\]

训练成绩越小越好。\(w\) 为胜出数，\(t\) 为持平数，\(n\) 为参照数；没有参照时 \(R=0.5\)。归一化排名得到同龄分布 \(P_{\mathrm{age}}\)。常规分布 \(P_{\mathrm{basic}}\) 综合当前训练质量与平滑后的直接子代改进率，最终父代分布为

\[
P(p)=0.75P_{\mathrm{basic}}(p)+0.25P_{\mathrm{age}}(p).
\]

每个确认思想共享十二次同龄通道选择额度；其任何版本达到精炼年龄八，或额度耗尽后，整个出生标识退出同龄通道，仍可通过常规通道获得机会。新版本和旧思想重现沿用已用额度。额度在请求发出前扣除，使失败、重复和中断无法重新获得保护。没有合格同龄对象时，全部机会交回常规分布。

同龄通道为尚未充分精炼的思想保留机会，常规通道继续利用当前质量与局部改进经验。初始化和修改通过 Refine、Explore、Crossover 生成程序，执行反馈与必要修复提供后续经验。方法改变的是父代机会分配，生成出的程序仍按真实训练表现参与最终选择。

出生审核会产生额外模型请求，其成本需要与生成成本一起衡量。该机制的关键检验是：有限同龄机会是否推进了原本开发不足的思想，并使其后续改进足以覆盖审核及机会分配的成本。
