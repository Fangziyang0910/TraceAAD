# V19.2：有界连续开发与源码反馈

修订：2026-11-01，北京时间。实现标识 `bounded_development_20261101`，检查点 schema 5。

这是经过离线验证的机制候选。尚未完成在线对照，不能宣称优于 V14、V15 或基线。旧版的固定质量尺度、折扣轨迹信用、父代—算子收缩和加法探索项全部移除。旧源码与文档保存在 `experiments_result/analysis/v19_2_rebuild_20261101/before/`，旧实验继续按其冻结源码解释。

## 1. 要解决的问题

搜索的目标是在有限成本内找到更好的有效算法。当前代码的成绩、一次生成是否正确落实了原理、以及这个实现经过有限开发后能达到的成绩，是三个不同的量。

旧选择器让每个新程序增加三个待估计动作。若 t 次生成产生约 ct 个有效新程序，A 个动作各自维护统计，则全部直接观测只有 t 份，每个动作的平均观测约为 1/(Ac)。增加总预算不会自动增加典型动作的观测量。同时，提示里的历史和交叉参考还在变化，同一父代—算子并非固定分布的独立重复。

因此，本版不再从几乎没有重复的组合上估计“潜力”。本版直接安排一个短开发过程，让实际源码、修改和结果构成后续生成可以使用的证据。现有病例证明了实现失真、修复丢失计算、接续不足都存在；尚不能证明其中任何一个是全领域的主要瓶颈。

## 2. 三个对象

| 对象 | 精确定义 | 用途 |
| --- | --- | --- |
| 开发段 segment | Init / Explore / Crossover 的有效新实现开段，连续 Refine 延续该段 | 给中间版本一个共同的竞争单位 |
| 段代表 frontier | 段内有效、非重复实现中训练 fitness 最小者；同分取较早 id | 段外竞争与保留成果 |
| 开发过程 episode | 一次选段后、最多 H 次实际模型请求的局部过程 | 限定接续成本，不逐步回到全库抽签 |

段不等同于算法思想。Refine 可以实际改换原理，Explore 也可能只是微调。当前实现不做语义分类，不把算子标签当作思想连续性的证明。

另外区分两个版本：固定的 `episode_anchor_id` 是本次开发起点；工作版本 tip 是最近一个同段有效实现。工作版本可以暂时比段代表差。档案中的最好结果不会被它覆盖。

## 3. 实现身份与档案

`source_key` 对源码的 Python AST 去掉位置信息后计算 SHA256。它忽略排版与注释，保留标识符、常量、字符串、docstring 及语句顺序。这是保守的语法身份，不是行为等价或思想去重。

首次出现的有效实现是 canonical owner。后续相同 AST：

- 仍然生成、评价、归档，并计入实际成本；
- `Attempt.duplicate_of` 指向首次有效 owner；
- 不增加段、竞争代表或新生保护额度；
- Refine 若复制本段的旧版本，工作版本回到该 owner；复制其他段的实现不改变当前段的工作版本；
- Explore / Crossover 若只是复制，不继续该出生 episode。

同源码多次评价仍分别存档；选择身份沿用首次有效记录，最终全局最好仍按全部有效记录取最小 fitness。本版假定固定评价协议使源码成绩可比较，不用重复评价的偶然较好值刷新该源码的选择身份。对含墙钟时间或随机噪声的任务，这种假定需要单独检查。

## 4. 段外分配

每段只有一个代表参加竞争，不让连续生成的中间版本叠加份额，也不让过时祖先稀释前沿。按代表的当前 fitness 从小到大排序，排名 r 从 1 开始：

\[
w_r=r^{-2},\qquad P(S)=(1-\epsilon)w_r/\sum_j w_j+\epsilon/K.
\]

K 是段数，默认 ε=0.05。相同 fitness 占据的各个排名权重取平均，确保同分对称。排名仅决定当前概率；原始历史结果不会重写。负目标、离散目标、相同初始化和异常宽尺度都不需要 sigmoid 定标。

平方排名与 5% 均匀项是透明的固定启发式，不是置信界，也不是创新主张。单个严格最好段在大量较差段增加后仍有非消失份额；很多同分或近似副本仍会分走份额。过强集中也可能遗漏后续才改善的方向，必须与更平缓的质量选择比较。

初始化不属于 episode。默认先让每个唯一 Init 段获得一次 Refine episode，不看其初始名次。该段出现任何已完成 Refine 尝试后便不再拥有这项优先权；API、格式、运行失败同样消耗它的实际请求额度。保护不因新叶子或复制而重置。`protect_new_segments=False` 关闭这项初始化保护；Explore / Crossover 的出生接续由下一节负责，不额外领第二份额度。

## 5. 开发过程与成本

默认 H=`development_calls`=4。每个新 episode：

1. 选一个段代表。初始化保护期只选 Refine；否则首个操作按 Refine / Explore / Crossover = 0.45 / 0.30 / 0.25 抽样。没有合法参考时去掉 Crossover 后重新归一化。
2. Refine episode 以所选代表为 anchor。Explore / Crossover 只有产生有效且非重复的新实现时，才以该子代作为新 anchor，并继续其剩余额度；出生失败或复制则立即结束。
3. 剩余额度内只做 Refine。有效同段子代成为工作版本，即使成绩暂时退步。失败保持原工作版本。返回旧版本不增加额度。
4. H 次请求耗尽后结束。下一轮只用各段代表竞争。全局评价预算或连续无评价停止规则可以提前截断 episode。

H 包含出生请求、格式修复、程序修复、API 错误和中断时已发出的请求。初始化生成及其最多一次修复单独计费。每次 attempt 最多共享一次修复；只有全局仍有评价额度、且 episode 仍有模型请求额度时才能修复运行错误。最后一个请求产生的格式/运行错误不会额外获得修复调用。H=1 时出生没有后续 Refine；H=2 且出生用完两次请求时同样没有接续，不另补额度。

这是按真实请求限制的开发过程，不是固定四个有效子代或固定四次评价。API 错误没有算法结果，不能赋值为质量 0。所有失败都记录真实状态与成本；`outcome_fitness=None`。有效结果记录原始 `outcome_fitness`。

全局仍默认 1000 次评价，repair 的再次评价也计入；连续 10 次没有启动评价则停止。记录 attempts、model_calls、evaluations 和实际 tokens，禁止把三者混成一个预算轴。

**算子比例改变**：0.45/0.30/0.25 是 episode 首步分布。若每次请求均成功且不修复，H=4 时长期原子操作比例约为 Refine 86.25%、Explore 7.5%、Crossover 6.25%，初始化另计。故必须做匹配 Refine 总量的对照，不能将任何收益直接归因于“接续”。

## 6. 源码反馈

默认 `local_history=True`：

- 当前工作版本完整代码始终展示；与工作版本不同的开发 anchor 也展示完整代码。
- 展示本段最近 3 个有效 Refine 结果与最近 2 个算法/格式失败。每条标明实际父代、原始分数、子代结果、是否修复、实际模型调用数。
- 父子变化由代码生成 unified diff；每条最多 60 行、2400 字符，截断明确标注。它不是可直接执行的补丁，也不用于要求模型生成补丁。
- 模型的 analysis/design 明确作为提议；要求以实际代码核对，检查关键计算是否影响返回决策。该提示不是自动正确性证明。
- API 服务错误不作为算法失败经验。无可解析代码的格式错误不宣称“该算法已被评价”。修复后的记录明确表示最终评价版本，修复前代码和每次评价仍在原始日志。
- 不跨 Explore / Crossover 边界继承旧祖先的修改结论。Crossover 显式展示两个来源的完整代码及成绩。

`local_history=False` 恢复原先的祖先/子代文字上下文，用于隔离整套反馈形式。它同时改变实际差分、anchor材料和相关指令，不能单独解释为diff效应；它不改变选择器。默认不额外调用规划器、反思器或语义分类器。

## 7. 交叉

优先从其他段的代表选择参考，保留其中成绩较好的半数（含分界同分项），均匀抽一个。只有一个段时，可从该段其他不同 AST 的有效实现中按同样规则选参考；没有不同实现才关闭 Crossover。

不同段不保证语义互补，同段也不保证没有互补信息。该规则只是限制明显的自复制与旧节点堆积。记录主父代、参考 id、参考池大小和参考条件概率；不向任何来源回传因果信用。

## 8. 记录、恢复和实现边界

`Attempt.selection` 保存 episode id、已消耗请求、anchor、工作父代、段与代表 id、阶段、候选组合数，以及实际父代边际、算子条件、联合概率。确定接续时这些选择概率为 1；Crossover 参考抽签概率另记。

episode 状态从已提交 attempts 重建，不依赖隐式内存队列。恢复保留随机状态、调用/评价计数、已完成结果。中断的 attempt 结束，不重发已计费请求；已占用的 episode 额度不返还。schema 4 及更早检查点拒绝在新语义下恢复，不静默迁移。

| 边界 | 当前处理 | 尚不能据此保证什么 |
| --- | --- | --- |
| 初始化全同分 / IQR=0 / 负分 / 极端量级 | 当前名次，无质量变换 | 相近分数的差异可靠 |
| Refine 中间节点大量增加 | 一个段代表参加竞争 | 所有语义变化都被正确分段 |
| Explore / Crossover 精确复制 | 原实现 owner，不新开段 | 近似副本不会增加段数 |
| 修复删去核心计算 | anchor、失败源码及修复提示要求保留计算；复制可识别 | 自动发现所有机制丢失 |
| 工作版本退步 | 有界继续，段代表与全局最好保留 | 深于 H 的损失谷能被跨越 |
| 所有新实现都差 | 保护成本有界，之后质量竞争 | 有界保护一定比额外探索划算 |
| 预算只剩一次评价 | 不做超预算修复，正常冻结赢家 | episode 能完整执行 |
| 评价含运行时间噪声 | 保留各次原始结果，不隐式重评 | 原始均值能鉴别微小进步 |
| 无有效程序 | 继续 Init，服从预算与连续失败上限 | 必然取得有效起点 |

## 9. 验证与贡献范围

首先检验接续是否有用，其次检验源码反馈是否有额外价值。需比较：简单质量与访问衰减选择；相同算子总量但每次重新选择父代；连续开发但保持旧反馈；完整候选。提示、模型、初始化、评价数据和成本轴分别固定。episode 末尾限制 repair 本身也会改变有效率，必须报告并隔离，不归功于信用机制。

可执行接续对照：`--reselect-parent` 保留H、episode首步分布、后续Refine和修复额度，只在非初始化episode的后续步骤重新按相同规则选择段代表；阶段记为 `reselect`，anchor设为本次选中的代表。初始化保护过程保持一致，可在两组共同使用 `--no-protect-new-segments` 另作检查。不同父代会改变成功/修复结果，因此实际操作总量仍须核账，不能声称两次随机搜索次数完全相同。它改变的是接续策略，避免了以H=1同时改额度和算子规则。

三个首步权重也可通过 `--refine-weight`、`--explore-weight`、`--crossover-weight` 明确配置。`--no-local-history` 是反馈形式的整体消融；要识别某一句指令或diff单独作用，需要进一步单变量实验。

核心终点是评价对齐与调用/token 对齐的最好成绩曲线、冻结训练赢家的独立测试成绩，以及新计算是否实际进入返回决策。不要只看开发深度、段数或全局改进事件数。先用小规模配对试验确定效应与方差，再决定重复数；三次重复不能自动保证统计显著或足够检验力。

可主张的候选增量是：在持续扩张、局部观测极稀疏的生成空间中，用一个有成本上限的开发过程产生可追溯证据，并把证据限定在实际源码和连续开发范围内。有限精炼、排名选择、段划分或源码差分各自都有先例，V14 已有四步发育，不能将它们单独包装为新发明。

端到端优势、各组件的独立收益，以及该问题在不同 AAD 系统中的普遍程度，均等待受控实验。若简单基线解释全部收益，就删除额外设计并收窄论文主张。
