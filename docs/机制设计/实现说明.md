# 机制实现说明

本文件保存复查代码和复现实验所需的接口、参数与运行约定。三个机制的设计动机、定义和作用过程见[方法正文](README.md#方法正文)，代码组合见[版本索引](README.md#实现与实验版本)。

## 机制一

### 动作、结果与统计接口

[selection.py](../../traceaad_v22_2/selection.py) 实现动作集合、历史匹配、收益率估计与概率修正；[runtime.py](../../traceaad_v22_2/runtime.py) 接入实际选择、首评冻结、完成反馈和恢复。V22.2 与 V23.2 共用这层实现，分别组合 V21.1 与当前 Base 生成流程。V23.2 的演化提示不读取轨迹，选择器仍读取轨迹分配预算；新运行保存生成协议标识，旧批次使用冻结源码恢复。

动作按父代编号与R/E/C顺序稳定枚举。同源码取最早有效代表。Base与机制1共用 `reference_candidates` 的当前质量筛选；机制1关闭轨迹参考时调用 `random_references` 均匀提出参考，开启时用轨迹嵌入选择最不相似者。family仅保留为来源记录，不再约束参考。所选参考同时用于生成提示与结果统计。

### 可选轨迹嵌入参考1.0

[references.py](../../traceaad_v22_2/references.py) 实现 `trajectory_embedding_diverse_v1`，归入机制1的交叉参考设计。V22.2和V23.2的实验入口默认注入现有嵌入客户端，启用轨迹参考选择；显式增加`--no-trajectory-reference-embedding`时使用同池随机参考，作为该部分消融。独立Python调用通过`reference_embedding=encoder`启用轨迹参考；传入`None`表示随机参考消融。encoder提供可调用接口、`settings`与`last_usage`。静态Base不启用该策略。

候选库按Base相同的有限成绩和AST规则去重，参考限于不劣于中位数且不同于父代的程序，选择轨迹向量余弦相似度最小者。相似度并列按候选成绩、编号顺序决定。没有合格参考时不创建C动作，并将其基础权重并入E，与Base的C转E一致。C权重为0时不请求参考嵌入。本版本不增加新的收益学习器或辅助LLM总结。

输入包含当前设计、去掉注释和文档字符串的源码，以及主父代链上最近三次修改，按旧到新排列。每步保留算子、实际代码差异（最多24行）、观察到的改善／退步／不变；C步骤补充当时参考设计。根节点只使用当前代码与设计，并标明没有形成步骤。当前成绩用于候选质量过滤，改善幅度与评价成本继续由原收益估计使用。

向量缓存保存在 `native/reference_embeddings/<hash>.json`，键包含输入与模型设置。`native/reference_embedding_calls.jsonl` 单独记录逻辑嵌入调用、用量与耗时；长文本由既有适配器分块并汇总用量，不把嵌入调用计作搜索评价或生成调用。服务或向量错误会停止该次选择，不自动改为随机参考。选择记录中的 `reference_selection` 保存实际C参考、相似度与缓存键；随机控制记录 `quality_pool_uniform_v1`。运行配置保存 `reference_settings`；恢复要求开关、模型与输入规则一致。统一参考与回退后的选择器更新规则为 `base_anchored_champion_yield_v3`，旧规则使用冻结源码恢复。

实验入口复用 `experiments.deltaevolve.embedding.CodeEmbedding` 的长文本适配，服务参数沿用 `SHINKA_EMBEDDING_BASE_URL`、`SHINKA_EMBEDDING_MODEL`、`SHINKA_EMBEDDING_API_KEY_ENV`；未另设时为已有DashScope客户端配置。六个既有TSP个体的真实服务冒烟见[结果](../../experiments_result/analysis/20261109_trajectory_reference_v1/result.json)和[复查脚本](../../experiments_result/analysis/20261109_trajectory_reference_v1/check.py)。它验证服务、缓存与选参考流程，不证明搜索收益。

### 公共选择与反馈接口

| 接口 | 行为 |
| --- | --- |
| `select` | 返回父代、算子、参考与本次选择记录。 |
| `_evaluate` | 在实际调用前检查预算，按第一次实际评价冻结首评结果。 |
| `finish` | 一次完整尝试反馈一次，保留有效且源码不同的最终子代，包括退步子代。 |
| `restore` | 按尝试顺序重建选择状态，每个 `attempt_id` 只处理一次。 |

收益只在结果有效、成绩有限、且相对尝试开始前的池不重复时计算。完整视图使用最终结果和实际评价次数；剩余一次评价时使用首评视图与单位成本。首评前可能已有格式修复，不能用 `repair_used` 判断哪次评价是首评。首评结束时冻结的可用性随后直接读取，避免子代入池后被误判为重复。

零评价尝试不进收益率估计，仍记录 `model_calls`，并受连续无评价停止规则约束；调用数不再降低基础选择权重。收益率不使用 `max(1, evaluations)` 伪造成本。

### 选择记录与恢复

非初始化尝试在 `attempt.record["selection"]` 保存：

```text
parent_id, operator, reference_id, action_group
parent_fitness, reference_fitness
champion_before_attempt, evaluations_used_before_attempt
parent_origin, parent_birth_change, parent_momentum, parent_ancestor_best
first_result, final_result, champion_gain, first_champion_gain
evaluations, model_calls
matching_radius, shared_weight, local_weight, value, eta
base_probability, selection_probability, mean_value
multiplier, uncapped_multiplier, window_breakthroughs
remaining_evaluations, valuation_view
```

恢复前核对方法、完整 Config、任务和 `selection_settings`。重放逐条核对决策时父代、参考、冠军、已用评价数和轨迹量，并重算冠军收益。不一致时拒绝恢复。早期固定尺度或父代改善版本的检查点不能直接续跑到当前选择器。

### 参数与计算

默认历史窗口为 `min(B,256)`，共享近邻为 32，共享等效样本上限与收缩常数均为 16，轨迹动量衰减为 0.5，相对收益率项封顶为 4。质量半径是近邻中正的两两状态距离中位数的两倍。无共享近邻时，以质量距离最近的至多 32 条本地记录确定半径。

基准质量与Base共用 `boltzmann_weights`，选择规则为 `boltzmann_fitness_v1`。`Config.selection_temperature` 默认为1.0，使用fitness单位，独立于模型温度；排名指数与调用衰减已移除。R/E/C 权重读取 Config，默认为 0.45/0.30/0.25。没有合法C时将其权重并入E。轨迹设置与基础选择规则进入 `selection_settings`，温度保存在完整Config中，恢复要求一致。旧批次仍使用原始源码快照。

实现对窗口内历史作精确近邻匹配，距离并列按尝试顺序处理。按算子预计算两两距离，并按所选集合缓存半径。沿用搜索的随机流。适应度作正比例缩放和平移时，采样温度也须按相同比例缩放；状态距离、半径和收益同步变化后，最终分配概率不变。

公式与变量定义见[机制一](机制1-轨迹节点价值评估与预算分配.md)，定向检查见[选择测试](../../tests/v22_2/test_v22_2_selection.py)与[搜索测试](../../tests/v22_2/test_v22_2_search.py)。

## 机制二

### 材料与参考接口

[context.py](../../traceaad_v21_1/context.py) 返回上下文文本、指令和实际展示编号；[representation.py](../../traceaad_v21_1/representation.py) 提供源码规范化与差分；[prompts.py](../../traceaad_v21_1/prompts.py) 定义完整提示和输出 schema。

机制二的选择直接继承Base：参考池保留成绩不劣于中位数、源码不同于父代的有效程序，按同一规则均匀随机抽取，不按计算结构或常量差异额外分组。没有合格参考时实际执行Explore。与机制一组合时，由共同选择层直接传入参考。轨迹视图中对重复观察的合并仍属于材料组织，不改变选择池。

| 材料设置 | 默认规则 |
| --- | --- |
| 祖先 | 最多 8 条；最近 3 条优先，其他按相对自身父代的绝对成绩变化选取，变化相同优先较近者。 |
| 有效子代 | 最多 3 条；先最好者，再最近者，最后按发生顺序展示。 |
| 失败记录 | 最多 2 条最近的不同观察。 |
| 差分 | AST 规范化后逐行比较，全部改动行各带一行上下文，分隔处用 `...`。 |
| 大幅替换 | `SequenceMatcher` ratio 小于 0.5 时，仅说明替换范围与未变行数。 |
| 当前代码 | 完整代码，去注释和文档字符串，不展示 `design`；Explore 还省略成绩。 |
| 参考代码 | 完整代码、成绩与描述；存在有效父代时附最后一步的结果和实际改动。 |

有效卡片依次给出父子关系、实际算子及参考、相对自身父代的结果、`design`、`analysis`，子代另附差分。`analysis` 以 `Proposed change` 标识；修复产生的说明沿用既有的 `Repair:` 记录。

失败卡不含成绩或代码差分。摘要包含异常类型、消息及候选源码位置，消息中的数字规范化为 N；超时摘要只说明评价未在允许时间内完成。R/C 的指令按事实与描述的公共说明、算子要求、必要时的失败指引依次组成。Explore 只使用其算子要求。

### 生成协议

一次请求返回三个字符串字段，顺序为 `analysis`、`code`、`design`，严格 schema 不允许额外字段。`analysis` 与 `design` 各为 2–3 句，最多 100 个英文词或 200 个汉字。前者说明计划，后者说明实际代码的表示、计算和输出关系。`code` 包含完整实现、必要导入和辅助定义，不含注释或文档字符串。完整文本直接见 [COMMON_TEMPLATE](../../traceaad_v21_1/prompts.py)。

初始化示例代码同样规范化。修复保留原始代码，使报错位置能对应源码行。生成提示包含任务、接口、成绩含义和算法材料，不暴露数据规模、划分、种子或评价器设置；超时修复反馈按实际约束说明总时限或单实例时限。

机制效果的独立比较条件见[V21.1](V21.1.md#比较口径)，实际材料与协议的检查见[测试](../../tests/v21_1/test_v21_1.py)。V21.1直接继承当前Base公共提示实现，只覆盖机制2的代码视图与输出协议；旧V21的冻结提示仅保留在历史快照中。

## 机制三

### 材料、经验与调用接口

| 文件 | 职责 |
| --- | --- |
| [evidence.py](../../traceaad_v24_1/evidence.py) | 已评价事件、相关计算问题、实现材料呈现与完整装入。 |
| [notes.py](../../traceaad_v24_1/notes.py) | 条件经验保存、内容匹配与轮换展示、反思提示、严格 schema、局部更新。 |
| [context.py](../../traceaad_v24_1/context.py) | V21材料、正面算子指令与生成格式；经验位于局部材料之前。 |
| [search.py](../../traceaad_v24_1/search.py) | 周期、未审阅事件、反思调用、提交快照与恢复。 |

事件编号使用 `attempt_id`，不是程序编号。一个事件对应一次尝试的最终已评价版本；初始化事件可以提供背景，但不计入 10 次反思周期。代码未改变或观察完全重复的尝试仍计入周期并留档，不重复进入待审阅集合。搜索结束时不额外反思。

当前工作区的材料组织规则为 `cross_branch_experience`。每次反思先选择一个计算问题：同一规范化父代码上的改动位置有交集，或事件通过直接父子链接相连。大幅改写读取完整实现。优先尝试含多次相关修改、且锚点较新的问题，超限时尝试下一个，源码与案例保持完整。

旧经验从全部有效条目中召回，入口包括结构连接、内容匹配，以及核心尝试的 `experience_ids` 展示记录。查询使用核心父子程序的代码、设计和分析，与经验的计算问题、条件和认识做IDF加权词项余弦比较。最多6条候选及其完整来源进入反思；逐条装入后才获得更新或归档权限。公开字段为 `id/idea/when/lesson/evidence_ids`，来源取1–3个完整案例，可来自独立分支；内部 `source_ids` 累计全部来源。共享计算条件由模型阅读实际实现与结果后判断。

`id=null` 表示新增，已有编号表示局部修订；`archive_ids` 归档已合并或替代的条目。整组更新检查非空内容、有效且不重复的编号、可见且观察各异的来源、更新与归档互斥，以及每轮最多6项更新和6项归档。经验持续保存，内部 `active` 标记仍参与选取的有效条目。新认识直接接纳，未涉及的经验、旧版本和累计来源保留。

生成展示预算为6条。有效条目超过预算时，本地选取5条与当前程序内容匹配的经验，Crossover查询增加已选参考程序；另1条按稳定编号轮换。轮换位置来自此前含经验的生成尝试数，按当前有效条目数取模。条目暂时退出展示后可经匹配、轮换或反思召回再次出现。

反思请求、解析或更新验证失败时，经验与未审阅事件保留，调用计数重新从零累计。成功反思标记实际展示的未读事件，其余继续保留。生成材料与算子职责沿用V21，V24.1的任务指令与输出说明使用正面行动表述。

### 上下文与记录

默认上下文为 49152 tokens，反思独立预留 4096 tokens 输出和 512 tokens 聊天格式余量，输入上限为 44544 tokens。生成仍使用 Config 自身的输出预算。统一客户端用服务端 tokenizer 与相同聊天模板计数；计数失败则保留材料，不退回字节估算。直接接入其他客户端需提供 `count_prompt_tokens` 或显式 `reflection_counter`。

`attempt.record["reflection"]` 保存所示、已审阅与延后事件、当前计算问题、候选经验编号、输入计量、更新和完整快照。`experience_ids` 与 `experience_from` 记录生成实际可见的经验及其成功反思来源；Explore 为空。事件从尝试记录恢复展示编号，供跨分支反馈召回使用。`native/calls.jsonl` 保存 `stage=reflect` 的提示、回复和用量。

恢复以已提交的 `attempts.jsonl` 为准，重放程序、展示记录与审阅状态；`experience.json` 是便读副本。先逐项核对方法、任务、配置、材料组织和反思设置，再读取日志。运行设置记录 `display_limit=6`、`update_limit=6`、`presentation=idf_overlap_with_rotation` 和 `prompts=positive_computational_guidance`。历史规则使用各自冻结源码恢复。反思调用与token单独计量，候选评价独立记账。

反思提示引导模型对应实际修改与结果、解释共同计算条件并形成设计认识。接口校验记录与更新规则，内容质量由真实模型案例检验。已有[小规模验证记录](../记录/2026-11-09-V24.1修正与小规模实验.md)按各自冻结源码解释。各批次条件与状态见[V24.1](V24.1.md)。
