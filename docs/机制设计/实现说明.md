# 机制实现说明

本文件保存复查代码和复现实验所需的接口、参数与运行约定。三个机制的设计动机、定义和作用过程见[方法正文](README.md#方法正文)，代码组合见[版本索引](README.md#实现与实验版本)。

## 机制一

### 动作、结果与统计接口

[selection.py](../../traceaad_v22_1/selection.py) 实现动作集合、历史匹配、收益率估计与概率修正；[runtime.py](../../traceaad_v22_1/runtime.py) 接入实际选择、首评冻结、完成反馈和恢复。V22.1 与 V23.1 共用这层实现，分别组合 V21 与当前 Base 生成流程。V23.1 的演化提示不读取轨迹，选择器仍读取轨迹分配预算；新运行保存生成协议标识，旧批次使用冻结源码恢复。

动作按父代编号、R/E/C 顺序及参考编号稳定枚举。同源码取最早有效代表，融合参考取异 family 中成绩最好者，同分取最小编号。family 是来源分组，不保证不同组具有不同计算。所选参考同时用于生成提示与结果统计。

| 接口 | 行为 |
| --- | --- |
| `select` | 返回父代、算子、参考与本次选择记录。 |
| `_evaluate` | 在实际调用前检查预算，按第一次实际评价冻结首评结果。 |
| `finish` | 一次完整尝试反馈一次，保留有效且源码不同的最终子代，包括退步子代。 |
| `restore` | 按尝试顺序重建选择状态，每个 `attempt_id` 只处理一次。 |

收益只在结果有效、成绩有限、且相对尝试开始前的池不重复时计算。完整视图使用最终结果和实际评价次数；剩余一次评价时使用首评视图与单位成本。首评前可能已有格式修复，不能用 `repair_used` 判断哪次评价是首评。首评结束时冻结的可用性随后直接读取，避免子代入池后被误判为重复。

零评价尝试不进收益率估计，仍累计父代的 `model_calls`，并受连续无评价停止规则约束。收益率不使用 `max(1, evaluations)` 伪造成本。

### 选择记录与恢复

非初始化尝试在 `attempt.record["selection"]` 保存：

```text
parent_id, operator, reference_id, action_group
parent_fitness, reference_fitness
champion_before_attempt, evaluations_used_before_attempt
parent_origin, parent_birth_change, parent_momentum, parent_ancestor_best
first_result, final_result, champion_gain, first_champion_gain
evaluations, model_calls
matching_radius, shared_weight, local_weight, value, eta
base_probability, selection_probability, mean_value
multiplier, uncapped_multiplier, window_breakthroughs
remaining_evaluations, valuation_view
```

恢复前核对方法、完整 Config、任务和 `selection_settings`。重放逐条核对决策时父代、参考、冠军、已用评价数和轨迹量，并重算冠军收益。不一致时拒绝恢复。早期固定尺度或父代改善版本的检查点不能直接续跑到当前选择器。

### 参数与计算

默认历史窗口为 `min(B,256)`，共享近邻为 32，共享等效样本上限与收缩常数均为 16，轨迹动量衰减为 0.5，相对收益率项封顶为 4。质量半径是近邻中正的两两状态距离中位数的两倍。无共享近邻时，以质量距离最近的至多 32 条本地记录确定半径。

基准排名指数为 1.5，调用衰减常数为 3，R/E/C 权重读取 Config，默认为 0.45/0.30/0.25。没有合法 C 时移除该动作并归一化，R/E 为 60%/40%。参数进入 `selection_settings`，恢复要求一致。

实现对窗口内历史作精确近邻匹配，距离并列按尝试顺序处理。按算子预计算两两距离，并按所选集合缓存半径。沿用搜索的随机流。适应度作正比例缩放和平移时，状态距离、半径和收益同步变化，最终分配概率不变。

公式与变量定义见[机制一](机制1-轨迹节点价值评估与预算分配.md)，定向检查见[选择测试](../../tests/v22_1/test_v22_1_selection.py)与[搜索测试](../../tests/v22_1/test_v22_1_search.py)。

## 机制二

### 材料与参考接口

[context.py](../../traceaad_v21/context.py) 返回上下文文本、指令和实际展示编号；[representation.py](../../traceaad_v21/representation.py) 提供源码规范化、代码分组与差分；[prompts.py](../../traceaad_v21/prompts.py) 定义完整提示和输出 schema。

单独使用机制二时，参考池取成绩不劣于中位数、源码不同于父代的有效程序。程序按忽略常量取值后的 AST 结构分组，每组取成绩最好者，排除父代所属组，再均匀抽取一组代表。这个筛选减少只改常量的近重复，不是程序语义等价或行为差异的证明。没有合格参考时实际执行 Explore，并记录实际算子。与机制一组合时，由选择层直接传入固定参考。

| 材料设置 | 默认规则 |
| --- | --- |
| 祖先 | 最多 8 条；最近 3 条优先，其他按相对自身父代的绝对成绩变化选取，变化相同优先较近者。 |
| 有效子代 | 最多 3 条；先最好者，再最近者，最后按发生顺序展示。 |
| 失败记录 | 最多 2 条最近的不同观察。 |
| 差分 | AST 规范化后逐行比较，全部改动行各带一行上下文，分隔处用 `...`。 |
| 大幅替换 | `SequenceMatcher` ratio 小于 0.5 时，仅说明替换范围与未变行数。 |
| 当前代码 | 完整代码，去注释和文档字符串，不展示 `design`；Explore 还省略成绩。 |
| 参考代码 | 完整代码、成绩与描述；存在有效父代时附最后一步的结果和实际改动。 |

有效卡片依次给出父子关系、实际算子及参考、相对自身父代的结果、`design`、`analysis`，子代另附差分。`analysis` 以 `Proposed change` 标识；修复产生的说明沿用既有的 `Repair:` 记录。

失败卡不含成绩或代码差分。摘要包含异常类型、消息及候选源码位置，消息中的数字规范化为 N；超时摘要只说明评价未在允许时间内完成。R/C 的指令按事实与描述的公共说明、算子要求、必要时的失败指引依次组成。Explore 只使用其算子要求。

### 生成协议

一次请求返回三个字符串字段，顺序为 `analysis`、`code`、`design`，严格 schema 不允许额外字段。`analysis` 与 `design` 各为 2–3 句，最多 100 个英文词或 200 个汉字。前者说明计划，后者说明实际代码的表示、计算和输出关系。`code` 包含完整实现、必要导入和辅助定义，不含注释或文档字符串。完整文本直接见 [COMMON_TEMPLATE](../../traceaad_v21/prompts.py)。

初始化示例代码同样规范化。修复保留原始代码，使报错位置能对应源码行。生成提示包含任务、接口、成绩含义和算法材料，不暴露数据规模、划分、种子或评价器设置；超时修复反馈按实际约束说明总时限或单实例时限。

机制效果的独立比较条件见[V21](V21.md#比较口径)，实际材料与协议的检查见[测试](../../tests/v21/test_v21.py)。V21 沿用冻结的旧 Base 提示层，不能用当前纯净 Base 的生成协议描述其历史条件。

## 机制三

### 材料、经验与调用接口

| 文件 | 职责 |
| --- | --- |
| [evidence.py](../../traceaad_v24_1/evidence.py) | 已评价事件、相关计算问题、实现材料呈现与完整装入。 |
| [notes.py](../../traceaad_v24_1/notes.py) | 条件经验状态、反思提示、严格 schema、局部更新与生成用短经验。 |
| [context.py](../../traceaad_v24_1/context.py) | 经验位于局部材料之前；有经验时调整 R/C 指令，Explore 不读经验。 |
| [search.py](../../traceaad_v24_1/search.py) | 周期、未审阅事件、反思调用、提交快照与恢复。 |

事件编号使用 `attempt_id`，不是程序编号。一个事件对应一次尝试的最终已评价版本；初始化事件可以提供背景，但不计入 10 次反思周期。代码未改变或观察完全重复的尝试仍计入周期并留档，不重复进入待审阅集合。搜索结束时不额外反思。

当前工作区的材料组织规则为 `focused_relations`。每次反思先选择一个计算问题：同一规范化父代码上的改动位置有交集，或事件通过直接父子链接相连。大幅改写不靠源码位置建立同起点问题。优先尝试含多次相关修改、且锚点较新的问题，超限时尝试下一个；选择的是完整关系，不裁剪源码。

反思只读与当前问题相连且能装入的旧经验及其来源，只有这些已展示条目可以修订或归档。其他条目保持原样。公开字段仍为 `id/idea/when/lesson/evidence_ids`，来源取 1–3 个相连事件；内部 `source_ids` 累计全部来源。这里的相连性按源码位置和父子关系检查，不等于自动确定科学上的因果关系。

`id=null` 表示新增，已有编号表示局部修订；`archive_ids` 归档条目。整组更新检查非空内容、有效且不重复的编号、可见且相连的来源、更新与归档互斥，以及最多 6 条活跃经验。未涉及的经验、旧版本和累计来源保留。容量满而没有可更新的相关条目时，可仅记录分析。

反思请求、解析或更新验证失败时，经验与未审阅事件不变，调用计数重新从零累计。成功反思仅移除实际展示的未读事件，其余继续保留。无经验时的生成提示完整沿用 V21。

### 上下文与记录

默认上下文为 49152 tokens，反思独立预留 4096 tokens 输出和 512 tokens 聊天格式余量，输入上限为 44544 tokens。生成仍使用 Config 自身的输出预算。统一客户端用服务端 tokenizer 与相同聊天模板计数；计数失败则保留材料，不退回字节估算。直接接入其他客户端需提供 `count_prompt_tokens` 或显式 `reflection_counter`。

`attempt.record["reflection"]` 保存所示、已审阅与延后事件、当前计算问题、相关经验编号、输入计量、更新和完整快照。`experience_ids` 与 `experience_from` 记录生成实际可见的经验及其成功反思来源；Explore 为空。`native/calls.jsonl` 保存 `stage=reflect` 的提示、回复和用量。

恢复以已提交的 `attempts.jsonl` 为准，重放程序与审阅状态，不重调反思模型；`experience.json` 是便读副本。方法、任务、配置、材料组织或反思设置不一致时，在修改日志前拒绝恢复。反思调用与 token 单独计量，不占候选评价预算。

反思要求模型保留计算条件并区分实现问题与性能比较；接口只验证数据合法性，不自动验证经验的科学正确性。已有[小规模验证记录](../记录/2026-11-09-V24.1修正与小规模实验.md)对应其各自冻结源码，不能直接视为并行修订后材料规则的验证。各批次条件与状态见[V24.1](V24.1.md)。
