# V20：轨迹评分、上下文与经验学习的完整实现

北京时间2026年11月3日。V20在Base上集成修正后的轨迹评分、[轨迹引导的上下文与算子](轨迹引导的上下文与算子.md)、[轨迹反思与经验学习](轨迹反思与经验学习.md)。本轮检验完整机制。评价、修复、评价预算和训练最好最终选择继续沿用Base。

## 问题与想法

一次改进既产生候选程序，也留下修改与结果之间的联系。祖先路径说明当前计算怎样形成，直接尝试说明同一起点已经试过什么。V20将这两类记录同时用于分配下一次改进机会、组织生成材料，以及形成可以在其他节点借鉴的经验。原始结果留档，模型解释以review和带适用条件的经验另存。

## 从结果学习评分

T(p)为当前程序及沿主parent_id最近8祖先的最好训练成绩，排除0号样例。目标越小越好。g=(T−f*)/|f*|，v=(f(p)−T)/|f*|。零目标值用max(|f*|,1e−12)作数值分母。

P预测最终程序严格击败T的概率。特征依次为截距、1{g>0}、log(1+g/0.01)、1{v>0}、log(1+v/0.01)、log(1+k_same)、log(1+k_other)、log(1+s)。X在截距后增加Crossover指示。差距为0时两项log特征都为0，随差距平滑增大。截距先验N(logit 0.1,1.5²)，所有斜率统一N(0,1²)。原先N(−1,0.5²)的失败先验把反复尝试的当前最好过早压低；这一理论尺度不适合成功率集中在基础率附近的节点。

系数方向由机制决定。T固定时，父代越差，子代需要越大的改进才能超过T；同一节点上的失败只会降低对它的成功率估计，成功只会提高。因此退步两项和两项失败系数取≤0，成功系数取≥0，抽样与后验均值都先按此截断再打分。轨迹差距和Crossover指示没有确定方向，不截断。没有这一约束时，搜索早期系数接近先验，退步极大的节点会因一次正向抽样获得接近1的P：TSP冒烟中成绩30.99的节点（当前最好7.148）在7次决策中被选4次。

h在g=0时等于1；g>0时logit h=α+b(log g−c)。先验α~N(0,1.5²)、b~N(−1,1²)。它只接收“击败T且g>0”的事件，标签为是否也击败当时f*。P和h分别用Newton与Laplace在线更新。每次从后验抽系数，h的抽样斜率取min(b,−0.05)，S=P×h，价值内取最大，同分随机。

Refine/Explore/Crossover固定按0.45/0.30/0.25抽样。Refine用R，Explore与Crossover共用X。融合没有不同源码参考时，实际执行Explore，仍计入X，并使用Explore的特征、提示和结果记录。评分始终读全量真实尝试，辅助请求不计入生成成本或评价预算。

[第四轮评分复查](../../experiments_result/analysis/v20_calibration_v4_20261103/README.md)在同90路冷启动回放上检验符号约束。两种价值、四个阶段中，当前最好的预测分都高于退步节点和其他节点。退步节点获配从48%降到22%，当前最好从29%升到34%。剩余偏差在h：0.1%–1%相对差距的转化率预测34%，实测15%，使轨迹落后于当前最好的节点获配43%。

## 将轨迹组织成生成材料

系统保存完整档案，每次生成提供最多8祖先、3有效直接子代和2失败记录。祖先保留最近3条，较远位置按结构变化与成绩变化的RRF取5个变化点。有效子代先保留最好；Refine再保留最近，其余名额按review/design向量距离与AST距离的最远优先补齐。失败记录先合并相同源码、状态及去敏错误，再选不同异常类别的近期代表。所有卡按真实parent_id呈现；省略区间单独标明。

当前程序与所选参考给完整代码。历史卡先给客观Result，再给Design和Reviewed change；没有review时标Proposed change。最多两个完整变更语句单元补充局部计算。每个段落只出现一个标题，子代与失败段标明总数与可见数。指令依次由公共要求、所选算子、随实际展示材料出现的段落指引和analysis职责组成。源码身份用去位置和说明字符串后的AST；结构用类型二元组、三元组及运算符计数。

参考按源码去重，质量优先池与差异RRF形成最多4个的短名单，池外保留1个名额，再均匀随机抽1个。先抽定参考，再构造唯一的融合Need查询。逐实例H当前记为unavailable：现有Base评价合同为标量，本次不改评价路径，也不额外评价或读取独立测试。

State、Need、Implementation各自形成完整排名，相关子路先在通道内融合，再做外层RRF。前3条直接进入生成；不足时全部展示，空库省略。没有相似度阈值。同分且至少一个通道可计算时按编号确定顺序；全部索引不可用时省略经验。经验展示完整系统观察视图，同时包含改善与未改善来源。生成器结合完整代码自行决定是否借鉴、怎样适配。

## 观察账本与两个学习频率

每个已评价的演化尝试保存一条事件：实际算子、参考、父子代码、原始评价与源码身份。最终结果只生成一条选择标签；修复前的评价保留在尝试记录中。局部review说明实际改了什么；经验正文与适用条件作为可修订解释，原始观察不由模型改写。

反思与评分用同一个成功标准：子代超过轨迹参照T才记为improved；好于父代但未超过T记为recovered。否则从坏节点修回原水平也会被当成改善，并写成经验。每次有算法评价的非初始化尝试至多一次反思。满足接续片段的2条新直接尝试、同父代3个不同实现/反馈、新最好，或10次尝试后的补处理时，使用学习模式。接续片段只取尚未进入学习片段的直接尝试。片段最多12个事件；超出时保留最新、最好、最差、最近失败和片段起点，其余由近到远补足。原生成曝光最多3条经验，学习时另召回最多3条。搜索终止后不补发只用于存档的反思。

create至少引用一个已有事件作来源；revise与retire只作用于本次反思可见的有效经验。revise并集旧来源。系统观察按最近改善、持平/退步及执行失败分别保留，经验正文修订不删除相反结果。无更新的学习回复仍消费实际可见片段；回复无法解析时不消费。review可以独立接受。

生成与反思都沿用生成请求的max_tokens、温度和超时设置。提示用short或brief，不设角色专用输出上限、字数检查或长度拒收。任务文本保持共同的任务、接口与分数。内部时间、实例、划分、随机数和评价设置不进入提示；普通失败卡只保留异常类型与候选位置。

## 配置、恢复与成本

四个开关默认全部开启：

| Config字段 | 关闭后的行为 |
| --- | --- |
| trajectory_scoring | 使用Base的父代权重 |
| trajectory_context | 使用Base的历史窗口取法 |
| reference_selection | 使用Base参考池 |
| experience_learning | 不反思、不更新或召回经验 |

生成与修复记在Attempt.calls中，计入模型调用。反思与嵌入记在`attempt.record['aux']`，按local_reflection、learning_reflection、embedding分列请求、tokens与失败，不占评价预算。嵌入向量只在进程内缓存。查询格式为`Instruct: ...\nQuery: ...`，文档编码不加指令。

运行目录只追加两类行：每个完成的尝试连同其程序写入`attempts.jsonl`，每次请求的提示与回复写入`calls.jsonl`。V20另写`decisions.jsonl`（每次选择的全部候选评分）和`experience.json`（每次尝试后的经验状态）。恢复时读回`attempts.jsonl`重建程序库，按顺序重放选择记录得到P/h后验，读入`experience.json`，然后继续。中断时未完成的尝试直接丢弃。每个尝试的随机数由种子与尝试序号确定，所以恢复后的抽样与不中断时一致。

输入不做长度检查，也不裁剪。材料超出模型窗口时，请求失败会直接记录在调用中。
