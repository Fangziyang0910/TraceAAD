# V21.2：轨迹引导的设计推理

V21.2在当前[Base](../TraceAAD-Base.md)上加入新版机制2。代码位于[traceaad_v21_2](../../traceaad_v21_2/)，入口为`--method v21.2`或`v21_2`。父代、算子和参考选择与Base和[V21.1](V21.1.md)相同。

## 要解决的问题

V21.1把轨迹组织得很细，但没有给模型一个使用轨迹的位置。它的`analysis`只要求说明“准备采用什么方案、为什么适合任务”，而关闭思考后，`analysis`是写代码前唯一的思考空间。轨迹读进来以后，模型直接给出方案。

V21.2的原则是：**不要求模型得出历史结论，而要求模型利用相关历史作出当前设计决定。** 仍是单次调用和`analysis → code → design`三个字段，不增加核对步骤或字段。

## 三项改变

### 1. `analysis`由算子指令定义

公共模板只规定形式，具体任务交给算子指令：

> "analysis": Before writing the code, briefly explain your design reasoning according to [Instruction], in 2–4 sentences and at most 120 words.

`design`保持不变，仍是代码生成后对实际计算的描述，供后续算法理解和轨迹使用。

三个算子共用一条推理逻辑：当前设计机会 → 相关轨迹给出的启发 → 新的计算决定。每段指令都要求`analysis`以一句修改决定结尾。不要求引用历史编号，也不要求模型从历史中找到支持；没有相关历史时，模型从当前计算和任务出发。

### 2. 每个算子读取支持其决定的材料

| 算子 | 设计推理 | 材料 |
| --- | --- | --- |
| Refine | 当前哪项计算值得改变，已有尝试说明了什么，这次怎么改 | 形成路径、同起点子代与失败（选取规则同V21.1）、当前完整代码 |
| Crossover | 借参考的哪项计算，它补充什么决策信息，怎样重新设计并接入 | 参考的设计描述与其计算的形成记录；当前父代的已有尝试，先取此前的Crossover；当前完整代码 |
| Explore | 当前代码依靠什么，哪种不同计算仍值得尝试，准备实现什么 | 本路此前的初始与Explore算法及其后续开发；当前代码，不给成绩 |

**Crossover的参考形成记录。** 我们想看到的是参考中值得借用的计算怎样产生和演变。最近几步和成绩变化最大的步骤都不一定对应这些计算。V21.2沿参考的真实父代链回溯到初始算法，对每一步取它新增、且参考现在仍在执行的代码行；按这类行数从多到少取最多4步，按发生顺序展示。成绩变化只在行数相同时排序。每步给出修改决定、实际差分和相对父代的结果。大幅改写的一步没有可读差分，改为列出该步引入、参考仍在执行的代码行。

参考默认不给完整源码，计算细节来自设计描述中的公式与参数，以及形成记录中的差分。`--reference-code`另给完整源码，作为对照条件，用来确定完整源码是在帮助正确实现，还是在诱导复制。两者的`generation_protocol`不同，恢复时互不接续。

**Explore的覆盖记录。** 程序取本路此前全部有效的初始与Explore算法，按规范化源码去重，不含当前父代。每条给出：设计描述、产生时的成绩与当时的搜索最好成绩、此后经Refine与Crossover形成的尝试数，以及其中的最好成绩。后续的Explore另起一条记录，不计入前者的开发。展示后续开发最多的3条和其余最近的3条。系统不给“已检验”“未充分检验”这类标签；开发次数少可能因为它确实差，也可能因为没有得到机会，判断留给模型。按源码去重只去掉重复程序，不合并相同思想，这一版不做思想聚类。

### 3. 子代卡片只保留修改决定

卡片顺序为：父代与算子 → 修改决定 → 实际改动 → 结果。修改决定取原始`analysis`的最后一句；修复过的程序取修复前的部分。完整推理和`design`留在原始记录，不进入后续生成上下文，以减少对前人推理的模仿和错误解释的传播。祖先卡片同样只给修改决定与结果。

## 算子指令

```
Refine
Improve the current algorithm by changing one computation in it. Identify a specific limitation or improvement opportunity in what the current code computes. If earlier attempts from this algorithm are shown, use their actual changes and results to judge what has been tried and what remains worth changing; otherwise reason from the current computation and the task. Make a targeted change that addresses it. The change may add, replace, or remove a computation, and it should differ in substance from the attempts shown. Keep the main mechanism where it serves the decision. In analysis, state the opportunity and, when attempts are shown, how they inform it; end with one sentence that states the change you make.

Crossover
Improve the current algorithm with decision information from the reference algorithm. Use the reference as shown and the formation records of its computations to judge which computation supplies information the current algorithm lacks, and what that computation depends on. If earlier attempts from the current algorithm are shown, use their changes and results. Redesign the chosen computation as needed, including a cheaper approximation of the same information. Align input representations and numerical scales, and combine its result with the current decision mechanism so both contribute to the returned result. In analysis, state what you take, what decision information it adds and how you integrate it; end with one sentence that states the change you make.

Explore
Develop an algorithm that reaches its result through a computation the current code does not perform. Options include decision rules on different information, estimating consequences before deciding, iteratively improving a complete solution, decomposition, solving small parts exactly, and population or restart search. If earlier explorations are shown, use their designs, results and later development to judge where a different computation is still worth trying. An unsuccessful or little-developed implementation does not rule out a different realization of the same idea. Implement the new computation in full; it does not need to beat the current code yet. In analysis, state what the current code relies on, the new computation you introduce and why it is worth trying; end with one sentence that states the change you make.
```

Refine与Crossover之前加一句材料说明：“Results and changed computations are measured facts. Designs and decisions are descriptions, and do not establish why a result occurred.”有执行失败时，沿用V21.1的失败说明。

## 比较口径

V21.2与V21.1的差别是`analysis`的任务、三个算子的指令、卡片内容、Crossover参考材料和Explore覆盖记录；与Base比较检验整套新版机制2。参考是否给完整源码，由`--reference-code`单独对照。

## 记录与恢复

`attempt.record["context"]`在V21.1字段之外增加`reference_steps`（展示的参考形成步骤）和`explorations`（展示的探索记录）。原生配置保存`method=traceaad_v21_2`和`generation_protocol=trajectory_design_reasoning_v1`，对照为`trajectory_design_reasoning_v1+reference_code`。测试位于[tests/v21_2](../../tests/v21_2/)。
