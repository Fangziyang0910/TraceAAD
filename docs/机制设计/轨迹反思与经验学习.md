# 轨迹反思与经验学习

日期：2026-11-03，北京时间。本文给出 EvoTrace 反思侧的多视角修订规格，与[轨迹引导的上下文与算子](轨迹引导的上下文与算子.md)配套。规则已在[V20](V20.md)中实现，正在正式批次中检验。

## 机制概述

EvoTrace 将演化轨迹分为原始经历与可迁移经验。系统保存实际程序、修改关系和评价；LLM 比较同起点尝试与连续修改，提出带适用条件的设计认识。后续生成同时按当前结构和本次修改需求检索经验，再结合实际代码选择可用的启发；适用条件可以已经满足，也可以由本次具体改动建立。

局部说明逐次写入，全局经验按包含比较关系的轨迹片段更新。两者使用同一个评价后请求，但不必同频更新。经验解释可以改变，原始观察由系统追加保存。这样既能及时交接本次计算变化，也能在出现接续结果后重新认识早先未改善的设计。

## 1. 保存什么，何时学习

### 1.1 原始经历与经验解释分开维护

一次开发尝试用一个 attempt_id，生成版、修复版和各次评价各有编号。修复结束后，以最后实际已评价版本填写最终状态和父子比较，较早错误仍附在同一尝试内。失败没有数值增益；同分新源码仍是新实现；相同源码从不同父代产生仍是不同修改关系。

系统维护不可由模型改写的观察账本：

| 字段 | 来源 |
| --- | --- |
| event_id、parent_id、child_id | 实际生成与评价记录 |
| operator、reference_id | 实际执行算子与参考，不只保存请求算子 |
| code identity、代码与完整差异位置 | 实际已评价源码，不使用生成器自述替代 |
| status、parent_fitness、child_fitness、reference_fitness、Result | 评价器；reference_fitness 是父代及其最近8个祖先的最好成绩，与评分的参照 T 相同。Result 按原始有限值比较：超过轨迹最好为 improved；好于父代但未超过轨迹最好为 recovered；与父代相同为 tied；差于父代为 regressed |
| analysis、design | 原生成说明，标为意图 |
| review | 评价后的模型代码分析；与评价事实分别标注 |

源码身份、AST 结构、代码及文字向量共用生成侧第1.4节的旁表。历史提示先展示客观 Result，再展示 Design 和一份修改说明：有 review 时用 Reviewed change，否则用 Proposed change。原始意图和解释在账本中完整保留。原始观察永不由经验更新覆盖。review 是模型分析，也可能出错；保留原始代码与后续复查版本，不把它当作外部实测事实。

经验在同一任务、同一路搜索内跨节点共享。不同独立运行、任务或评价条件不隐式混合。独立测试只评价冻结赢家，不写回经验。

### 1.2 两个时间尺度，在一次请求中交接

**局部记录**：每个有实际算法输出与评价的新尝试，评价后写一段 review，说明实际改变了哪项计算，以及设计与代码的关键差异。接口故障、无算法评价不反思。初始化无父子修改关系，不做本机制反思。

**全局凝练**：维护待处理事件和学习片段，满足以下条件之一才允许写经验：

1. 同一父代有至少3个尚未处理的不同最终实现／反馈，形成同起点比较。不同性按相同父代、最终源码身份、可比条件、状态与原始成绩判定，生成说明换词不增加计数。
2. 某次 Explore／Crossover 产生的子代，已积累至少2个尚未进入学习片段的最终直接尝试，形成首次设计与后续开发片段。这里按实际parent_id关系取片段，不把算子标签当成思想身份。
3. 新事件产生本路新的最好有效成绩，可以立即分析该事件及其形成路径。
4. 每10个最终尝试，若仍有未处理事件，补处理一个等待最久的父代片段，避免低频节点永远不能形成经验。

3／2／10是明确的调度起点，不是证据强度阈值，不表示三次经历即可证明通用规律。相同源码但不同反馈可形成比较，复制同一记录不凑次数。后续出现新结果时，同一主题仍可再次进入凝练。

每次评价后最多发送一次反思请求。优先处理尚未学习的接续片段，其次是达到3条的比较片段，再次是新最好，最后是补处理；同级按最早待处理事件排序。本次未处理的片段保留到下一次，不丢弃。本次最新事件无论是否属于被选片段，都只在局部区域出现一次；它的 review 职责与学习片段分开。没有学习片段时，updates 必须为空，系统忽略其中的更新。搜索结束后不为存档补发不会用于生成的模型请求。

局部与学习模式都沿用本路生成请求的max_tokens、模型、温度与服务超时设置，使用独立角色schema。提示用short或brief，不作字数检查或长度拒收。分层指信息的用途与写入频率，不是把旧短期反思反复摘要成长期反思。

## 2. 根据什么反思

### 2.1 实际修改与两类关系

所有模式沿用 Base 任务说明、function_template 和成绩定义，提供最新父代完整代码、最新子代 analysis／design、最终执行反馈及完整代码差异。默认统一差分保留前后3行；差分比完整子代更长时提供完整子代。失败按 error／timeout 区分，普通反思和生成均不显示具体超时时限与协议禁止的评价设置。

学习模式另提供选中片段父代的设计和代码、按生成侧规则选择的最多8祖先，以及该片段的同起点尝试或后续开发卡。最新修改若同时属于学习片段，仅引用一次实际材料。片段事件优先于无关历史。

一个学习片段最多展示12条事件：先保留本轮未学习事件中最新者、最好者、最差有效者、最新失败者（存在才保留并去重），接续片段另保留最初的 Explore／Crossover 事件；剩余位置由近到远补足，最后按事件顺序呈现。未展示事件保留为待学习，不能因进过候选集就标已处理。

待修订经验最多6条：生成时实际展示的至多3条，加针对学习片段额外召回的至多3条。条目附系统观察卡。

评价条件由系统核对可比性。完整条件只留元数据，提示中的适用条件描述算法结构与信息依赖，不包含实例数量、规模、数据切分、种子、预算、时限或评价器内部设置，见[协议](../../experiments/PROTOCOL.md)。

### 2.2 检查计算是否真正进入决策

反思检查设计声称的计算是否真正进入候选选择、更新、构造或返回过程。模型可以明确没有定位到作用，不自动判负。JSSP 中关键路径变量未控制邻域的案例说明该检查有价值，但不能据成绩单独归因。[案例核对](../记录/2026-11-03-轨迹双机制调研-本地案例.md)

### 2.3 输入边界

输入不做长度检查，也不裁剪。材料超出模型窗口时反思请求失败，记在该尝试的辅助记录中。完整档案不删，不因历史增长停搜索，不另发摘要请求。模型与嵌入成本都单列。

## 3. 从比较中形成什么认识

局部 review 回答“这次实际改变了什么”。经验凝练回答“结合相同起点和连续修改，哪些关于后续设计的认识发生了变化”。两者都把实测结果与原因解释分开。

单次退步只说明这次实现没有改善。若之后调整另一项计算才改善，可以提出二者需要配合的假设，保留完整片段与适用条件；多项改动同时发生时，不强分组件贡献。后续结果也不是早期思想的因果验证。经验应指出可借鉴的计算关系，而非复述某个程序的常数或将执行失败变成思想禁令。

全局经验不能只按单步分数把修改分为“好思想／坏思想”。比较首先考虑实际实现和组合，再讨论未解决的限制。一次新最好可以提供值得迁移的启发，但仍需保留起点和实现条件。

已有经验是可修订解释，不是新的观察。经验被展示、模型声称借鉴、代码实际采用和最终评价分别记录；不按一次子代成败给所有可见经验共同加减分。

## 4. 经验内容与更新

### 4.1 经验解释与系统观察

一条经验包含：

- lesson：一个简短的设计启发，写明机制、组合或实现限制。
- applicable_when：与启发有关的结构、信息和计算条件。
- source_event_ids：系统维护的完整来源集合。
- observation：由系统从源事件渲染的观察视图，模型不生成或重写此字段。

系统还存编号、活动状态与历史正文。没有独立的正负池、极性配额或可信度投票。正面和负面实现可以属于同一经验。

每次展示经验时，系统从来源中取最近2条 improved、最近2条 recovered／tied／regressed，以及最近1条 error／timeout，并去重；接续学习片段作为一个整体来源卡保留起点与后续结果，最多展示最近一个片段。其余来源只列总数与完整可追溯编号，不拿次数称为因果证据。观察卡写事件、具体修改的 review（缺失时标生成自述）和客观 Result，不用模型给出的 supports／contradicts 标签决定是否显示。

这样可以保证已登记的好坏结果不会被经验正文重写删除；它仍不能保证模型正确解释相反结果，也不能保证有限视图呈现所有语义反例。会改变某次修订的旧来源必须另行附入，不可只留后台编号。

### 4.2 更新协议

学习模式的 updates 是零条或少量 create／revise／retire：

- create：形成当前条目未覆盖的认识；至少引用一个已有源事件。
- revise：只修改本次实际展示的活动经验；模型返回完整的新 lesson 和条件，以及新增可见来源。系统自动并集旧来源，不能减去旧观察。
- retire：解释包含实质错误，或已被另一条经验覆盖。原始来源与旧正文继续保存。一次失败不自动撤下经验。
- 空更新：没有可迁移认识，或现有认识不需改变。

系统不自动合并经验。相同或近似的认识由模型通过 revise 与 retire 处理，否定词和适用条件可能改变含义。不用 Jaccard 或向量阈值决定“同一认识”。

系统只应用可执行的操作：create 的来源须是已有事件；revise 与 retire 的目标须是本次可见的活动经验。回复无法解析时不应用，也不消费片段。来源检查不证明解释正确。

## 5. 经验如何进入下一次生成

### 5.1 三类表示分别召回

复用 server3 的 qwen3-embedding-4b-fp8，端点为server4的`127.0.0.1:18002/v1`，见[操作说明](../../experiments/infra/AGENT_OPERATIONS.md#server4-入口)，不假定 Qwen3-Reranker 已部署。查询使用官方格式，文档侧不加指令：

```text
Instruct: {retrieval_instruction}
Query: {query_text}
```

三个检索 Instruct 固定使用英文，query_text 保留原文语言。向量按 L2 归一化，在进程内按查询文本缓存，正文改变即重算。代码按完整函数编码，不截断；编码失败时该向量缺失，相应路不参与排名。

经验不是代码，AST 必须匹配它的来源程序。每条经验从源事件中选最近2个改善事件与最近2个其他结果事件，不足则全部取；对其来源父代构造状态、入口代码与结构索引，来源父子关系另存修改内容与改后状态。接续来源包含起点及后续边，不把后代单独当成原始父代。有限源代表限制条目因引用很多程序而获得更多匹配机会；全量观察仍留档。

| 通道 | 当前查询 | 经验索引与排序 |
| --- | --- | --- |
| 状态 State | 当前父代 design＋已有 review | 条件文本及来源父代 design 分别算余弦排名，再在该通道内 RRF；多个源设计取最高匹配 |
| 需求 Need | 算子要求首句＋最近2条直接尝试的 review／design 和 Result 状态；无尝试则只用算子要求，不重复完整父代 design | lesson＋各源实际修改说明及状态；各源单独编码，取最高匹配。不按算子硬分池 |
| 实现 Implementation | 当前父代必需函数代码、AST 结构 | 当前入口与来源父代入口的代码余弦，以及当前与来源父代 AST 特征余弦；两条排名在该通道内 RRF |

融合时先按生成侧第2.4节抽定一个参考。Need只构造“融合要求＋最近尝试反馈＋已选参考design”的一份查询，不重复完整父代design。不存在不同源码参考时，先转Explore，再按实际算子检索。额外查询嵌入按实际次数记账。

固定查询指令分别为：

```text
State: Retrieve experience notes whose stated conditions or source algorithms match the current algorithm's representation and decision rules.
Need: Retrieve design lessons relevant to the requested modification and recent outcomes, including ways to revise an unsuccessful implementation or combine computations.
Implementation: Retrieve source computations relevant to the current function's implementation, even when their descriptions use different terminology.
```

实现通道的正向代码排名仅比较当前入口与来源父代入口，回答“修改前的起点是否相近”；不再把来源子代或任意 helper 的高相似分数当成同一种匹配。源子代与相关 helper 仍作为修改说明和可选代码材料保存。若当前代码更接近源子代，仅在经验来源中标注命中的改后状态，不能据此断言改法已经采用，更不能按未标定的相似度差阈值压低经验；已有计算也可能需要继续精炼或重新组合。

AST 用生成侧第1.4节的特征。没有可解析来源则缺该条结构特征，不把缺失当零相似；如果一个通道无法给所有活动条目生成可比排名，该通道本轮不参与融合。各条来源代表、匹配角色和客观 Result 留存。多源取最高匹配表达“任一来源情境相近即可召回”，可能带来候选数量的极值偏差；每条最多4个源代表并按来源父代源码去重，不声称这已消除偏差。是否影响实际适用率，按源数分层核对；不以任意0.7／0.3均值冒充已校正，也不按改善／失败给相关性加权。

非需求检索的成对覆盖向量（如 review 距离和函数间距离）统一用不加查询指令的文档编码，两端保持同一编码形式；查询检索才用上述任务指令，不能混用。

三个通道各先对全部活动且可比的条目形成完整排名，再做外层 RRF，常数60、同分和全同处理与生成侧一致。所有条目都用完整名次参与计分，不在单路截断后再融合。全库使用同一组有效通道，不能按候选各用不同的通道数；在此条件下除以通道数不会改变排序。相关子路先组内合并，不因多建几个相近向量就获得多票。

按完整外层 RRF 排名直接取前 `min(3, N)` 条，N为本轮可检索的活动经验数；同分按经验编号。至少有可计算通道但分数全同、没有区分信息时，按编号确定次序取最多3条，记录退化；空库或全部索引不可用时返回空。

经验带编号、条件与系统观察直接进入生成。排名不等于适用性判断，生成模型读取当前完整代码和任务要求时，可以借鉴、调整或不用。State不作为硬门，跨结构类比也可通过具体改动建立适用条件。

### 5.2 空库、缺特征与修订召回

空库时省略经验检索。嵌入服务失败但缓存仍有效时使用有效缓存和可用的结构路；只有结构可用也按其排名直接取最多3条，不偷偷改用 BM25。所有通道不可用时省略经验，继续用父代与轨迹。新条目缺向量则等待补建，旧向量不冒充新正文。每个通道的可用状态、候选与最终曝光落盘。

学习模式用选中片段父代作 State／Implementation 查询，用该片段的实际修改及反馈作 Need 查询；最新尚无 review 时用 design 与系统变更线索，不读取未来反思。额外召回在三通道候选融合后取前3条，排除本次生成已展示编号。反思本身可以不修改不适用条目。与原展示经验合计最多6条，均附来源卡。

检索不按展示次数增加可信度，不强制为轮换而舍弃相关条目，不把一次收益同时奖励所有经验。反复选同一父代时，需求查询会随最近尝试改变；仅有算子名不同并不保证结果必定不同，集合变化率只是检查项，实际适用与生成收益才是目标。

## 6. 最终提示、输出与调用规则

### 6.1 英文提示

````text
{task_description}

The function being designed:
```python
{function_template}
```

[Latest Evaluated Change]
{latest_parent_design_score_and_complete_code}
{latest_attempt_version_status_and_result}
{child_analysis_and_design}
{complete_diff_or_complete_child}

[Learning Segment, only in learning mode]
{segment_parent_and_formation_path}
{same_start_comparisons_and_or_followup_chain}
{experience_notes_with_system_observation_cards}

[Instruction]
For the latest evaluated change, describe the computation that actually changed and any important difference from the proposed design. Trace its role in construction, selection, updates, or the returned result.
{learning_instruction_only_when_a_segment_is_present}

[Output]
Return exactly one JSON object with "analysis", "review", and "updates".
"analysis": Briefly state what the visible comparison adds; an empty string is acceptable in local-only mode.
"review": Briefly describe the latest actual code change and any important design-code mismatch, or an empty string when no useful comparison is possible.
"updates": Zero or more operations using the supplied schema. In local-only mode, this must be an empty list.
Return only JSON, without Markdown fences or additional text.
````

学习模式才加入以下指令：

```text
Compare the learning segment's same-start alternatives and successive changes. Separate observed results from explanations, and examine whether a later implementation changes the interpretation of an earlier outcome.
Propose a reusable design idea or revise a shown experience only when the segment adds information; no update is valid. Describe the relevant computation and its applicability conditions, rather than turning a single implementation's outcome into a rule about every realization of an idea.
For mixed results, explain the conditions or leave the difference unresolved. The system preserves observations; do not rewrite them. Cite only visible source events for new observations. An old note is an interpretation, not new evidence.
Do not infer a component's contribution from a multi-change improvement. Keep internal evaluation settings out of lessons and applicability conditions.
```

### 6.2 严格输出协议

根对象仅有 analysis、review 两个字符串及 updates 数组。每项固定以下字段，不允许额外字段：

```json
{
  "analysis": "比较带来的认识变化",
  "review": "本次最新已评价程序的实际计算变化",
  "updates": [
    {
      "action": "create",
      "experience_id": null,
      "lesson": "一个简短的机制启发",
      "applicable_when": "有关结构、信息与计算条件",
      "new_source_event_ids": ["A17"]
    }
  ]
}
```

编号仅为格式示例，不进入真实库。action 为 create／revise／retire 枚举；experience_id 为整数或 null，其余为字符串及新增来源字符串数组。create 的编号为空；revise 返回完整 lesson 和条件；retire 的正文可空。事件编号即尝试编号。系统生成 observation，禁止模型写该字段。

局部模式可独立接受 review。含学习片段的回复即使 updates 为空，也把实际可见事件标已处理；新接续边或新反馈会重新触发片段。回复无法解析、接口失败、截断或拒绝输出时，不更新经验、不制造 review，待处理事件仍留队列。

### 6.3 客户端、成本与恢复

生成继续使用 Base CANDIDATE_RESPONSE_FORMAT。反思使用独立角色客户端，复用模型与端点，通过已有 OpenAIClient 构造器的 request_options 覆盖 response_format，不改 Model.complete 公共签名。反思回复不交给候选代码解析器。

嵌入、局部／学习模式反思各自记请求、tokens、延迟、失败及缺失用量，不追加到 Attempt.calls，不改变父代预算用的生成／修复成本定义。生成前仅有检索所需嵌入请求，每次评价结束后最多一次反思；无算法评价、空库与搜索终止会改变实际次数，不宣称总请求必然为某个倍数。完整比较既报告相同评价预算，也报告全部模型成本。

经验状态在每次尝试结束后写入 experience.json。恢复时读回该文件和已完成的尝试；中断时未完成的尝试连同其反思一起丢弃。

## 7. 依据与取舍

本轮裁决见[元评审综合](../记录/2026-11-03-轨迹机制元评审-综合裁决.md)。它替代旧版“单查询余弦前3、逐次自由重写 observation、每次立即更新全局经验”的规则。生成 Base 模板与父代预算机制保持其原有合同。

| 依据 | 可迁移的认识 | 本机制的取舍 |
| --- | --- | --- |
| [GraphCodeBERT](https://arxiv.org/html/2009.08366)、[UniXcoder](https://arxiv.org/html/2203.03850)的结构消融 | 结构信息可补充文本，对代码理解／检索有价值 | AST 加入召回与变化定位，不直接指导增加复杂度；不声称其收益已迁移到 AAD |
| [Qwen3官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-4B) | 支持文本／代码检索与查询指令 | 复用已有部署，纠正此前错误的尖括号查询格式；不假定 reranker 存在 |
| [RRF原论文](https://cormack.uwaterloo.ca/cormacksigir09-rrf.pdf) | 可在不直接相加原始分数的情况下合并名次 | 分组融合，防相关通道多票；不宣称等权和常数60已最优 |
| [RefineEvo](https://arxiv.org/abs/2607.11358)的情境检索与正负经验 | 来源情境与条件都有价值 | 同看来源状态和本次需求，不按算子硬分经验池 |
| [MEMOIR](https://arxiv.org/abs/2605.17539)的局部／全局分层 | 局部执行细节与不同节点间认识可以不同频率维护 | 保留逐次 review，以比较／接续片段凝练经验；原消融没有证明本触发频率最优 |
| [ACE](https://arxiv.org/html/2510.04618v3)的增量维护与重写坍缩案例 | 来源保留不能只依赖反复摘要 | 系统观察与可修订解释分离，不复制其 helpful／harmful 共同奖惩 |
| [ReasoningBank](https://arxiv.org/html/2509.25140v2)的经验条数消融 | 该任务中更多经验未必更好 | 排序前3条直接展示，不足3条全部展示；不把其 top-1 结论当成本任务最优值 |
| [BehaveSim](https://arxiv.org/abs/2603.02787)的静态与行为相似分歧 | 程序结构与语义近似不能充当行为／互补的真值 | 保留多视角，逐实例成绩仅作可选互补代理；本轮不要求六任务执行插桩 |

ReEvo、RefineEvo、ExpeL 与本地失败案例的原始核对分别保留在[AAD反思调研](../记录/2026-11-03-轨迹双机制调研-AAD反思.md)、[记忆借鉴](../记录/2026-11-03-轨迹双机制调研-记忆借鉴.md)及本地案例。文献的整套系统收益不归到本机制的单一模块。

## 8. 最有区分力的检验

先固定真实事件流与当时可见材料，比较旧的逐次自由改写和本版观察账本：已登记的相反结果是否仍显示、修订是否凭空增加事实、最新差异是否准确。人工读源码与评价作核对，不让模型自评充当真值。再比较逐次凝练与片段触发，控制源经历与总模型成本，检查获得接续反馈后的经验是否正确改变，而不是只数经验条数。

检索先做离线标注回放：单语义排序前3与多视角融合排序前3分别检验实际展示的适用率和漏掉的有用类比；按来源数量与修改前／后角色分层检查误召回，人工核对“改法已存在”与“仍有可改之处”，不拿余弦阈值自造真值；融合检查每个最终选定参考是否有对应的经验入口及实际生成的借鉴是否匹配。不以集合差异或向量距离当收益。随后在未参与经验形成的父代上比较相同生成／接续预算的效果，记录实际计算是否借鉴经验、有效率与改进结果。

完整搜索最后检验训练赢家与独立测试，按协议报告全部模型及评价成本。当前没有运行上述模型、评价或搜索实验。
