# TraceAAD V17：在同龄竞争中迁移有用的局部改动

## 研究问题与核心认识

大语言模型驱动的自动算法设计（LLM-based automated algorithm design，LLM-AAD）可以通过交叉借用其他算法的计算，但高分参考程序并没有直接说明哪些部分值得迁移。整体成绩来自多个计算及其相互作用。模型面对完整设计时，可能重建参考算法，也可能因缺少具体改动依据而无法有效借用其中的计算。

搜索历史提供了更具体的经验：一个程序在怎样的实现背景下，通过哪一步修改取得了改进。这类局部证据把可迁移的计算与实际效果连接起来。它也使知识共享能够围绕已有程序展开，而不必把整个参考算法变成新的开发对象。

**核心认识是：跨方向共享的基本单位可以是有来源证据的局部改动，开发机会由相同投入下的表现决定。** TraceAAD V17 据此结合组件导入（component import）与同龄竞争，让已观察到的有效修改成为其他谱系可尝试的计算。

## 组件：用来源轨迹筛选值得尝试的改动

一个谱系由无父代程序及其沿主父代关系产生的后代构成。组件来自同一谱系内两个有效程序之间的修改，并满足三个条件：新程序刷新该谱系的最好成绩；修改的新增与删除行数之和不超过六十；相对谱系原最好成绩的改进比例，不低于当前所有满足前两项条件的修改的中位数。

这三个条件分别提供性能依据、修改范围与筛选尺度。来源成绩说明该修改曾在具体背景中有效，局部差分指出它实际改变的计算；较小的修改范围使模型能够把共享对象集中在一个部件上。修复后的有效程序按原始修改的起点与操作识别组件。

组件保留来源程序、父代、修改说明、代码差分和评价结果。来源中的改进为迁移提供候选依据，目标程序中的实际收益则由适配后的执行评价确定。

## 导入：将来源中的计算适配到当前算法

当搜索选择交叉操作时，组件导入从其他谱系中寻找当前谱系尚未导入过的组件。多个组件可用时，优先选择来源程序成绩最好的一个，同成绩选择较新的记录。这样的排序关注组件所处实现的质量，避免只因粗糙设计的一次较大相对改善而反复偏向它。

导入提示提供当前算法的代码、形成轨迹与此前尝试，再展示组件的修改说明、局部代码差分及来源父子的评价结果。来源算法不作为完整参考程序单独展示。生成任务是在当前代码中适配组件的计算，并保持当前算法的主决策规则。

局部源码在这里承担明确的知识传递作用：它指出发生过什么改变，当前程序提供目标计算背景。一次导入无论是否改善，都计入目标谱系的尝试记录；同一组件不会再次向该谱系发起导入。没有可用组件时，交叉通过其他谱系的设计描述提供参考。

## 同龄竞争：让知识迁移服务于有限预算搜索

借用新组件并不意味着一个方向应持续获得预算。自身成绩仍在改善，也不足以说明继续投入比开发其他方向更有价值。因此，谱系的开发机会由相同年龄下的历史表现决定。

年龄为谱系已经建立的程序记录数，失败、修复和回访记录均计入。训练成绩越小越好，\(b_D(r)\) 表示前 \(r\) 条记录中的最好有效成绩。\(C\) 为持有全局最好程序的谱系，\(e_C\) 为其当前年龄。挑战谱系在五、十、二十……的检查点满足

\[
b_D(r)\leq b_C(\min(r,e_C))
\]

时保持活跃；首个检查点前保留初期开发机会。后续尝试优先给投入最少的活跃挑战者，没有合格挑战者时开发冠军。停滞后的无代码发散提供新的起点。

同龄竞争约束开发投入，组件导入提高不同谱系能够共享的信息粒度。方法关心的是来源中的局部改进能否在新的代码背景中产生实际收益，并使有限预算发现更好的算法。
