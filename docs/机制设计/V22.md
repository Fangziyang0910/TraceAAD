# V22 与 V22.1

**V22 系列 = Base＋机制1＋机制2 = V21＋机制1。** V21 保持为 Base 加机制 2 的最终版。

- **V22.1（当前机制 1）：** 代码位于 [traceaad_v22_1](../../traceaad_v22_1/)，实现[机制 1：以 Base 为基准的轨迹经验分配](机制1-轨迹节点价值评估与预算分配.md)。
- **V22（11月7日运行批次）：** 代码保留于 [traceaad_v22](../../traceaad_v22/)，对应正在运行的 `20261107_v22_co6`。

## V22.1：以 Base 为基准的轨迹经验分配（11月8日）

V22.1 复用 V21 的初始化、上下文、算子提示、`analysis → code → design` 输出、评价和一次修复流程，选择层为最新版[机制1](机制1-轨迹节点价值评估与预算分配.md)：

- **选择池与参考：** 有效、成绩有限、AST 去重选择池。family 为 Init 自立、R 继承、E/C 自立。每父代唯一 C 参考取异 family 最好节点。
- **真实冠军改善：** 每条反馈记 $Y_i=\max(f_i^*-f(c_i),0)$ 与真实评价成本。改善父代但未超当时冠军记 0。零评价 attempt 不进收益率估计。
- **可比借用：** 只借同算子、最近 $\min(B,256)$ 次评价内、已评价的历史。质量状态用真实成绩坐标与最大坐标差匹配，取最近 32 条共享记录并按匹配半径线性衰减。本地记录不做质量衰减。轨迹以出生操作、出生变化、符号动量与回撤深度做 $[0.5,1]$ 温和修正。
- **Base 锚定再分配：** 共享经验最多按 16 条等效尝试与本地反馈合成每评价收益率。最终概率按经验强度修正 Base 联合概率，单动作乘子封顶 4 倍。无正收益证据时完整回退 Base。无可比经验的晚出生节点保留 Base 机会。
- **预算边界与首评冻结：** 剩余评价至少 2 次时用完整 attempt 视图。剩余 1 次时用首评视图且成本为 1。首评按第一次实际 `_evaluate` 识别，并相对 attempt 开始前的池冻结可用性。

运行入口支持 `--method v22.1`（或 `v22_1`），测试位于 [tests/v22_1/](../../tests/v22_1/)。尚未启动正式批次。

## V22（11月7日批次规格）

V22复用V21的初始化、上下文、算子提示、`analysis → code → design`输出、评价和一次修复流程。新增[机制1](机制1-轨迹节点价值评估与预算分配.md)，联合选择父代、操作和融合参考。不包含机制3、反思、经验池、嵌入或额外LLM评分。

## 选择与反馈

- 选择池只保留有效、成绩有限且AST源码不同的版本，同源码取最早有效代表。原始程序库和尝试记录仍完整保留。可运行的退步版本可进入选择池。
- Init建立family；Refine继承主父代family；Explore和Crossover建立新family。融合参考取其他family中成绩最好者，同分取最小ID。这替换V21的中位数参考池、computation分组筛选和均匀抽取，提示直接使用选定参考。不同family不保证有不同计算；V22的参考合法性由机制1接管，机制2继续组织选定动作需要的材料。
- Refine、Explore、Crossover分别学习可用率，以及共享线性回归加局部随机截距的连续收益分布。输入为机制1约定的九维特征。连续收益反馈的残差裁剪到更新前预测尺度的±3倍，共享均值、B和局部收益和使用同一有效反馈。这是稳健近似更新，不是原始观测的精确共轭后验。
- 每轮对全部真实动作计算价值。剩余至少4次评价时，用16点积分计算两次attempt的前瞻；第二步使用每操作前8个基础候选、当前动作及虚拟子代动作，并补入当前父代以虚拟子代为最佳合法参考的C，去重后最多29个。虚拟分支会重新确定候选融合参考与局部组。
- 剩余1～3次评价时只用一步期望改善；无正尺度时均匀选可行动作。尺度首次可确定时冻结，并回放此前可用转移的连续收益，可用率不重复累计。
- 每个完整attempt反馈一次，包括一次修复的最终结果。无结果、最终失败和重复源码只更新可用率。可用新版本同时更新连续收益。

实际每轮只执行一个动作，取得结果后重新分配。评分保留attempt等成本近似；预算继续按真实evaluation计费，在实际评价调用前检查。调用次数与评价次数分别保存。

裁剪只限制学习的单次影响。真实与虚拟子代的成绩、冠军、保留和轨迹始终使用原始结果；真实与虚拟分支调用相同的稳健学习逻辑。

## 记录与恢复

统计和前瞻位于[selection.py](../../traceaad_v22/selection.py)，共享搜索接入位于[runtime.py](../../traceaad_v22/runtime.py)，[search.py](../../traceaad_v22/search.py)将它与V21组合。V23将同一接入与Base组合，统计状态在各自运行中独立建立。模型状态不单独落盘。

`native/attempts.jsonl`保存原始尝试及程序。`attempt.record.selection`保存动作三元组、决策时特征、父代成绩、固定尺度、冠军、I、Q、可用率和剩余评价；完成后增加可用结果标记及实际评价次数。尺度未确定时，特征和预测值为null。

进入选择池的节点在`attempt.record.node`保存来源操作、主父代、参考、family、出生变化、出生前祖先动量、当前动量和祖先最好值。`attempt.record.context`继续使用V21的材料记录。

`native/run_config.json`的`selection_settings`保存`update_rule=predictive_residual_clip_v1`、`residual_clip=3.0`和`scale_rule=positive_pairwise_median_v1`。Python接口可用`residual_clip`指定裁剪倍数，恢复必须使用同一值。各attempt的`record.selection_scale`保存其结束后的固定参照与尺度。

恢复前核对方法、完整Config、任务与评价设置及上述选择器设置，不一致时在日志修复与重放前拒绝。重放时核对决策前和更新后的f₀/s₀，按已记录动作和特征调用同一更新逻辑，每个attempt_id只处理一次。Init重建初始池与尺度；历史动作不重新选择。未完成尝试沿用Base的丢弃规则。缺少更新契约的旧V22检查点不能直接续跑到当前稳健更新，避免混用规则。

## 运行

复用[现有实验入口](../../experiments/traceaad_v20/README.md)，指定`--method v22`与独立结果目录。以下命令只展示配置，不调用LLM：

```bash
.venv/bin/python -m experiments.traceaad_v20.run \
  --method v22 --experiment traceaad_v22 \
  --task tsp_construct --run-name v22_dry --batch v22_dry \
  --scheduler-socket /tmp/traceaad-1003/scheduler.sock --dry-run
```

正式运行仍需可用的公共调度器，运行参数、冻结源码、主测试和恢复规则沿用实验入口。V22不需要嵌入服务。保留的Config算子权重用于共享配置格式，V22选择器不读取它们。
