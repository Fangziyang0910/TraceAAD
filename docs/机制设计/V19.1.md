# TraceAAD V19.1：轨迹条件下的父代—算子联合分配

## 1. 科学问题

在自动算法设计中，一次生成不是对一个孤立程序的无条件改写，而是对一个已有设计轨迹施加一次具体干预。相同父代接受 Refine、Explore 或 Crossover，可能产生完全不同的结果；同一个算子作用于不同设计方向，也可能有不同表现。

因此，下一次预算分配的对象应当是：

\[
\text{设计轨迹} + \text{设计干预}。
\]

只按父代质量选择，无法回答“应该对它做什么”；只按算子统计选择，无法回答“这个算子应该作用于谁”。V19.1 将二者合并为一个联合动作 `(parent, operator)`。

## 2. 科学叙事

V19.1 的核心认识是：**父代的可开发性是条件性的，它取决于对该父代施加的设计操作。**

轨迹在机制中承担两种作用：

- 数值轨迹记录父代质量、算子投入、子代质量与失败结果，用于决定下一次预算投向；
- 文本轨迹记录祖先、当前父代、有效子代和失败尝试，用于告诉模型如何执行选定的设计操作。

这使 TraceAAD 的选择对象从“程序”提升为“带有干预条件的设计方向”。V19.1 的价值不在于单独提出联合选择；DGS 已将算子和父代集合建模为联合动作，AB-MCTS 的 `stack` 模式也为节点—动作分别维护后验。V19.1 的区别在于：它把联合动作嵌入显式的算法设计轨迹中，用可审计的轨迹统计进行选择，并让同一条轨迹同时指导预算分配和模型生成。

这个表述比“给优秀父代更多机会”更准确，因为当前成绩只描述已有程序的质量，不能直接说明它在某一种后续干预下的潜力。

## 3. 状态与动作

对每个有效父代 `i`，数值状态由以下信息构成：

- `q_i`：父代在当前有效程序库中的倒数平均排名质量，成绩越好，`q_i` 越大；
- `n_i,o`：父代 `i` 接受算子 `o` 的已完成尝试次数；
- `r_i,o,j`：该组合产生的第 `j` 个直接子代的绝对质量；
- 失败尝试的质量为零，但仍计入一次开发机会；
- `N_o` 与 `g_o`：算子 `o` 在当前任务中的全局投入和平均产出，用于给稀疏组合提供共享先验。

一次演化动作是：

\[
a=(i,o), \qquad o\in\{\mathrm{Refine},\mathrm{Explore},\mathrm{Crossover}\}.
\]

Crossover 的第二个参考个体仍在确定 `(i, Crossover)` 后从质量合格的参考池中选择；V19.1 暂不把 `(主父代, 算子, 参考父代)` 建成三维独立统计，因为当前每个组合的样本本来就很少。

## 4. 共享先验下的联合分配

令 `\bar q` 为当前有效程序的平均质量，`s_o` 为算子 `o` 的直接子代质量总和，`N_o` 为该算子的尝试次数，则算子共享先验为：

\[
g_o=\frac{\kappa_o\bar q+s_o}{\kappa_o+N_o}.
\]

父代—算子组合的平滑平均表现为：

\[
\mu_{i,o}
=
\frac{\kappa_p q_i+\kappa_o g_o+\sum_j r_{i,o,j}}
{\kappa_p+\kappa_o+n_{i,o}}.
\]

其中，父代质量提供个体先验，算子全局表现提供共享先验，直接子代结果提供组合自身的轨迹更新；未充分尝试的组合不会因为样本太少而被立即判定为无价值。

组合的不确定性为：

\[
u_{i,o}=\lambda
\sqrt{\frac{\log(1+N+|\mathcal A|)}{1+n_{i,o}}},
\]

其中 `N` 是所有联合动作的已完成尝试数，`|A|` 是当前可用联合动作数。最终选择分数为：

\[
U_{i,o}=\mu_{i,o}+u_{i,o}.
\]

初始化阶段的算子比例 `(.45, .30, .25)` 只作为软先验，不再是固定配额。令 `p_o` 为该先验，联合动作的主要抽样概率为：

\[
P_0(i,o)=
\frac{p_oU_{i,o}}
{\sum_{(k,v)}p_vU_{k,v}}.
\]

为避免某个算子因早期偶然失败而消失，最终概率保留少量先验混合：

\[
P(i,o)=(1-\epsilon)P_0(i,o)
+\epsilon\frac{p_o}{|\mathcal I_o|},
\]

其中 `\mathcal I_o` 是当前可使用算子 `o` 的父代集合，V19.1 默认 `\epsilon=0.05`。因此算子比例可以随轨迹变化，但三个算子仍保留探索机会。

这等价于先按联合分布选择父代，再从该父代的条件分布中选择算子：

\[
P(i)=\sum_oP(i,o),
\qquad
P(o\mid i)=\frac{P(i,o)}{P(i)}.
\]

所以“先选父代，再看对它使用什么算子”是可以实现的，但父代的边际分数必须已经综合了所有可用算子；先只按父代质量选完，再临时挑算子，不属于联合选择。

## 5. 轨迹与模型上下文

V19.1 不增加额外的 LLM 决策器。选择器根据数值轨迹决定 `(parent, operator)`，模型根据文本轨迹执行该操作。

模型上下文沿用 V19 的组织：当前父代提供完整 `analysis`、`design` 和 `code`；祖先、有效子代与失败子代提供有限数量的分析、设计和评价信息；Crossover 参考个体提供完整 `analysis`、`design` 和 `code`。因此，选择器回答“给谁做什么”，生成器回答“具体怎样做”。

一次生成及其最多一次修复仍算作一次联合动作尝试。修复后的最终评价更新原 `(parent, operator)` 组合；格式错误、程序错误和评价超时计入该组合的开发次数，失败质量记为零。

## 7. 实现方案

V19.1 复制 V19 的独立实现，只替换选择器：

- `traceaad_v19_1/selection.py` 维护全局算子统计和父代—算子组合统计；
- `Config` 增加算子共享先验强度、联合探索系数和算子最低概率；
- `Attempt.selection` 保存联合概率、父代边际概率、算子边际概率、条件概率、组合投入、共享算子表现和不确定性；
- 初始化、提示词、JSON Schema、一次修复、评价预算、评价时限和最终训练集选择全部沿用 V19；
- 不增加 LLM planner，不增加自定义算子，不增加代码去重，不建立三维交叉统计。

该实现只需要遍历当前有效程序与三个算子形成的有限联合动作集合，并从已有尝试中重新计算统计量，因此不依赖嵌入模型、额外服务或不可复现的语义判断。

## 8. 可检验的主张

V19.1 不预先宣称联合分配一定提高最终成绩。它检验的是：

> 在相同任务、提示、模型、随机种子和评价预算下，使用轨迹条件的父代—算子联合分配，是否比 V19 的固定算子比例与条件父代选择更快找到高质量有效程序。

比较时同时记录最终独立测试成绩、评价次数对齐的最好成绩曲线、算子边际分布、父代—算子组合的投入、失败率、修复率和有效子代质量。若 V19.1 只改变算子比例但没有改善前沿曲线，不能把动态分配本身解释为成功；若组合统计始终稀疏且不稳定，则说明需要回到更强的共享算子先验，而不是继续增加组合层次。

V19.1 的科学贡献因此应表述为：**将 LLM 自动算法设计中的预算分配单位明确为轨迹条件下的设计干预，并给出一种具有共享先验和局部组合修正的可审计联合选择机制。** 其性能价值需要通过与 V19 的单变量对照确定。
