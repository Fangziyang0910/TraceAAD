# TraceAAD 演化轨迹价值估计与预算分配实现说明

## 1 设计意图

**根据一个算法版本的演化经历，判断接下来怎样开发它最有价值。**

机制使用三类信息：当前成绩、产生它的纵向轨迹，以及在它身上执行各类操作的历史结果。用这些信息预测每个“父代＋操作”的结果，再选择最值得投入下一次生成机会的组合。

价值同时包含当前改善与后续开发机会。例如，当前最好成绩为100，继续精炼预计得到99、98；探索可能先得到105，但新版本进一步精炼可到95。两步前瞻让第二条路径的潜力进入当前决策。**能运行的退步版本继续保留；每轮只执行当前动作，收到结果后重新选择。**

## 2 每轮怎样选择

### 确定候选动作

选择池保存所有有效、fitness有限、AST源码不重复的版本，同源码保留最早的有效代表。每个父代p有R精炼、E探索，以及条件允许时的C融合。

C的参考规则固定：选择不同family中fitness最小的节点，并列取最小ID。Init各自建立family；R继承主父代family；E和C建立新family。没有其他family时，C不可选。一次动作记录为a=(parent, operator, reference)，总动作数不超过节点数的3倍。

### 预测每个动作的结果

预测器返回两项：

- **可用率π**：完整attempt最终得到有效且不重复版本的概率。
- **质量变化分布**：如果结果可用，相对主父代会改善或退步多少。

R、E、C分别学习。新节点借用共享轨迹规律；尝试过的父代—操作组合还使用自己的局部反馈。连续收益保留正负号，例如110精炼到105记录为改善5，即使祖先已有100。

九维轨迹特征相同、尚无局部反馈的新节点会得到相同预测。轨迹先提供一类版本的开发倾向，后续局部反馈再区分具体版本。因此，特征的信息边界主要限制新节点的初始排序能力。首版保留现有预测模型，不增加代码嵌入；需要检验的是轨迹能否在当前成绩之外，帮助选出更值得先尝试的版本。

### 比较当前收益与后续机会

一步价值I，是本次生成超过当前冠军的期望幅度。两步价值为：

```math
Q(a)=I(a)+(1-\pi_a)J_0(a)+\pi_a\sum_{j=1}^{16}\omega_jJ_1(a,y_j).
```

- J₀：假设本次没有得到可用新版本，更新可用率后，下一步最大的I。
- J₁：假设得到质量变化y的新版本，执行稳健近似更新、加入新节点、更新冠军后，下一步最大的I。
- yⱼ与ωⱼ：预测分布上的16个积分点与权重，按附录计算。

第二步基础候选在当前真实状态下截取：当前I最高的每类操作前8个，加上正在评估的动作。前8名并列时按父代ID、参考ID排序。进入虚拟分支后，保留这些候选的父代与操作；有可用虚拟子代时，再加入它的R/E/C，C仍需满足family条件。另补入“本次动作的父代＋C＋虚拟子代”，前提是虚拟子代是该父代按既定规则选中的最佳合法参考。候选去重后最多29个，不扩展其他父代新开放的C。

**每个虚拟分支都按真实选择规则重新确定候选C动作的参考。** 可用分支的选择池是真实池加虚拟子代。对已有父代，只有虚拟子代属于不同family且按fitness、ID排序优于原参考时，才替换参考；虚拟子代自身的C参考从真实池选择。没有其他family时，C不可选。不可用分支的选择池不变，参考也不变。

参考变化后，重新计算特征x的第8项，并使用新的局部组g=(parent,C,reference)预测可用率与连续收益；该组没有历史时，其局部计数与统计量为0，共享C模型仍使用该分支更新后的状态。这样，新版本既能被继续开发，也能作为其他版本的融合材料。计算只需要虚拟子代的成绩、family及节点ID，无须提前生成代码。

第一步比较全部真实动作，取Q最大的组合；精确同分使用当前attempt的随机流。虚拟更新使用独立影子状态。实际只执行选中的第一步，下一轮重新对全部真实动作评分。

## 3 接入 TraceAAD

**V22 = V21＋机制1 = Base＋机制1＋机制2。一次完整attempt作为一条训练记录，包含现有的一次repair机会。预算继续按真实evaluation次数累计。** 初始化、`analysis → code → design`输出和上下文组织沿用V21，不加入经验模块。

| 接口 | 实现行为 |
| --- | --- |
| select | 联合返回parent、operator、reference和selection记录，用上述价值替换原来的算子概率与父代评分 |
| evolution_prompt | 使用select确定的实际reference；上下文模块围绕这个动作组织材料 |
| finish | 以attempt最终结果更新一次预测器；有效不同源码的子代加入选择池，包含退步子代 |
| restore | 按attempt顺序调用同一更新逻辑，每个attempt_id只处理一次 |

接入点位于[traceaad_v22/search.py](../../traceaad_v22/search.py)中的同名接口，继承V21；统计与选择逻辑位于独立的[selection模块](../../traceaad_v22/selection.py)。版本范围与记录方式见[V22](V22.md)。

**预算边界：** 剩余evaluation≥4时使用两步价值Q；剩余1～3时使用一步价值I；耗尽时返回真实冠军。两步指两次完整attempt，每次最多消耗两次评价。首次评价和repair后评价均在调用evaluator前检查剩余预算。最后一次evaluation复用一步预测，实际执行按预算截断。连续无评价attempt的停止规则沿用现有配置。

**首版成本近似：** I和Q按attempt收益比较，暂时将不同动作视为等成本；实际预算仍按evaluation次数扣除。上述预算边界保证执行不超额，但不表示已经比较了相同评价额度下的收益。每个attempt保留实际evaluation次数；格式repair可能增加模型调用，却不一定增加evaluation，二者分别记录。最后一次evaluation继续复用完整attempt的一步预测，保留repair机会被截断时的预测近似。

以后即使在分支中加入成本，若仍固定比较两次attempt、剩余预算又充足，动作排序也可能不变。真正修正成本偏差，需要比较相同评价额度下的收益，或计入额外消耗评价所放弃的后续机会。首版先观察实际评价成本差异，不增加成本预测模型，也不简单用I或Q除以平均成本。

反馈规则固定如下：

- 最终无效、无结果或源码重复：可用率记一次失败，不更新连续收益回归。
- 最终有效且不重复：可用率记一次成功，以主父代与最终子代的成绩差更新回归一次。
- repair前后的中间结果不拆成两条训练样本；全部实际评价仍由执行器计费。
- 产生子代的收益只记给原动作；新子代的局部尝试数从0开始。Init只建立初始池与尺度。

在attempt.record.selection保存：动作三元组、决策时特征x、父代fitness、f₀、s₀、当时冠军、I、Q、π和剩余evaluation。节点元数据在attempt.record.node保存来源操作、主父代、参考、family、出生变化、祖先动量和祖先最好值。每个attempt还在attempt.record.selection_scale保存更新完成后的f₀和s₀，初始化和尚无尺度的阶段同样记录。

恢复前核对native/run_config.json中的方法、完整Config、任务与评价设置，以及selection_settings中的尺度规则、更新规则和裁剪倍数。恢复过程中再逐条核对决策时与更新后的f₀/s₀。不一致时明确拒绝；恢复使用已记录动作和特征，不重新选择历史动作。缺少新更新契约的旧记录也拒绝直接续跑，不将原始共轭更新与稳健更新混用。

接入顺序（伪代码）：

```python
action, record = selector.choose(archive, remaining_evaluations, rng)
attempt = create_attempt(action, record={"selection": record})
execute_existing_attempt(attempt)  # 原生成、评价与repair流程
selector.observe(attempt.id, record, archive.get(attempt.program_id))
```

## 附录 计算接口

### A 输入特征与尺度

fitness越小越好。初始化完成后，f₀取初始选择池最好成绩；s₀取初始节点两两fitness差的绝对值中所有正值的中位数，保留配对重数。两者随后固定。

全部同分时先均匀选择可行动作；首次出现非零差值时，在当时真实池计算并冻结s₀，回放此前的有效转移一次。f₀仍保留初始最好值，可用率计数不重复回放。

```math
h(z)=\frac{z}{1+|z|},\qquad y=\frac{f(p)-f(c)}{s_0}.
```

对非根节点：δₚ=f(parent)−f(p)，Aₚ=M(parent)，M(p)=0.5h(δₚ/s₀)+0.5Aₚ。根节点这些量均为0。T(p)取自身fitness、主父代T、参考父代T的最小值；无参考则省略，根节点T=f。

特征x按以下顺序排列：

| 下标 | 数值 |
| --- | --- |
| 0 | 1 |
| 1 | h((f₀−f(p))/s₀) |
| 2 | h(δₚ/s₀) |
| 3 | Aₚ，出生前祖先动量 |
| 4 | h((f(p)−T(p))/s₀) |
| 5、6、7 | 来源分别为R、E、C的0/1指示，Init全0 |
| 8 | 当前操作为C时取h((f(p)−f(reference))/s₀)，否则0 |

### B 可用率

操作o的总尝试/可用数记为Nₒ、Uₒ；局部组g=(parent,operator,reference)的尝试/可用数为n_g、u_g。R/E的reference为None。

```math
\bar\pi_{o,-g}=\frac{1+U_o-u_g}{2+N_o-n_g},\qquad
\pi_g=\frac{4\bar\pi_{o,-g}+u_g}{4+n_g}.
```

未尝试时本地计数为0。虚拟分支也按同一规则增加一次成功或失败。C参考变化时形成新局部组，共享C模型仍使用全部C历史。

### C 连续收益预测与更新

每个操作使用“共享线性回归＋局部随机截距”：y=xᵀwₒ+ξ_g+ε。每操作保存m、V、A、B；每局部组保存可用数k、特征和sx、有效收益和sy，新组均为0。单次反馈的残差按更新前预测尺度裁剪，限制一个极端结果对共享规律的影响。

设原始残差e=y−μ，预测尺度为ℓ，则e_eff=clip(e,−3ℓ,3ℓ)，y_eff=μ+e_eff。共享均值使用e_eff，B使用e_eff²，局部收益和累加y_eff。以下公式给出完整递推，所有数组使用float64。

```python
# predict(x, group) -> mu, scale, df
c = 1.0 / (k + 1.0)
z = x - c * sx
mu = z @ m + c * sy
H = 1.0 + c + z @ V @ z
df = 2.0 * A
scale = sqrt((B / A) * H)
# 条件于可用：y ~ StudentT(df, loc=mu, scale=scale)

# observe_usable(x, y, group)，先使用旧状态计算所有右侧
e = y - mu
e_eff = clip(e, -3.0 * scale, 3.0 * scale)
y_eff = mu + e_eff
v = V @ z
m = m + v * e_eff / H
V = V - outer(v, v) / H
V = (V + V.T) / 2.0
A = A + 0.5
B = B + e_eff * e_eff / (2.0 * H)
k, sx, sy = k + 1, sx + x, sy + y_eff
```

每次仅更新生成该结果的操作模型与局部组。普通残差不受裁剪；极端正收益和极端负收益对称处理。预测仍使用Student-t分布，但这是对伪观测y_eff的稳健近似递推，不再称为原始观测下的精确共轭后验。

真实fitness、冠军、版本保留和轨迹特征始终使用真实结果，巨大正突破立即更新冠军，巨大退步的可用版本也继续保留。虚拟子代同样按原始采样y计算成绩、冠军、family与轨迹，仅其模型学习调用同一套稳健更新。虚拟更新复制小矩阵及被修改组，不修改真实状态。

### D 一步改善与两步积分

设当前冠军f*=min f(p)，G=(f(p)−f*)/s₀，d=(μ−G)/scale。tν为标准Student-t密度，Tν为CDF，ν=df。

```math
I(a)=\pi_g\left[(\mu-G)T_\nu(d)+\mathrm{scale}\frac{\nu+d^2}{\nu-1}t_\nu(d)\right].
```

I和Q均在归一化尺度上比较；日志展示原始fitness单位时乘s₀。用SciPy的stdtr和gammaln计算CDF与密度。

```python
v, w = numpy.polynomial.legendre.leggauss(16)
u, omega = (v + 1.0) / 2.0, w / 2.0
y_points = mu + scale * scipy.special.stdtrit(df, u)
```

对每个y点：门控加入成功，收益模型加入(x,y)，虚拟子代fitness=f(parent)−s₀y；由附录A计算其全部特征，新组计数为0，并更新冠军。随后按正文规则在加入虚拟子代的选择池中重新确定候选C动作的参考、特征及局部组，再求第二步最大I。不可用分支只更新门控，选择池不变。将这些值代入正文Q公式，选最大值即可。依赖NumPy和SciPy，虚拟计算不调用LLM。
