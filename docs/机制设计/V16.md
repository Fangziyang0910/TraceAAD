# TraceAAD V16：以近期进步与修改轨迹支持持续开发

## 研究问题与核心认识

有限预算下，大语言模型驱动的自动算法设计（LLM-based automated algorithm design，LLM-AAD）需要判断一个方向是否值得继续开发。即使在相同投入下比较，当前阶段成绩仍可能低估一个正在有效改进的方向：它暂时落后，却可能在下一阶段缩小差距。单看阶段水平，会忽略已经观察到的改善趋势。

开发机会的价值也取决于生成器如何利用历史。逐步重复完整设计描述，会把实际改动埋在大量相同信息中。交叉参考若集中在同一谱系的相近程序，又难以提供新的计算。有效经验因此需要同时回答：改了什么、结果怎样，以及哪些外部计算值得借用。

**核心认识是：后续投入应结合阶段表现与近期进步，生成上下文应围绕修改及其评价结果组织。** TraceAAD V16 以近期进步外推保留有希望的谱系，以修改轨迹和跨谱系参考支持进一步精炼。

## 近期进步外推：保留仍有追赶机会的方向

以无父代程序及其主父代后代构成谱系，年龄为其程序记录数。训练成绩越小越好，\(b_D(r)\) 表示谱系 \(D\) 在前 \(r\) 条记录中的最好有效成绩。\(C\) 为持有全局最好程序的谱系，\(e_C\) 为其当前年龄。检查点为五、十、二十……；尚未达到首个检查点的有效谱系获得初期开发机会。

挑战谱系首先按同龄表现竞争。对在检查点 \(r\) 暂时落后的谱系，取

\[
h=\max\!\left(a_D^{\mathrm{first}},\left\lceil r/2\right\rceil\right),
\qquad
s_D=\frac{b_D(h)-b_D(r)}{r-h},
\]

其中 \(a_D^{\mathrm{first}}\) 是首次取得有效程序的年龄；\(h=r\) 时令 \(s_D=0\)。再以

\[
\widehat b_D(2r)=b_D(r)-r s_D
\]

表示延续近期改善速度后的乐观成绩。以下两项满足任一项，该谱系便继续参与开发：

\[
b_D(r)\leq b_C(\min(r,e_C)),
\qquad
\widehat b_D(2r)\leq b_C(\min(2r,e_C)).
\]

后半窗口减少粗糙初版到早期修正的大幅跳变对外推的支配。该外推是对已有进步的确定性估计；它增加一次继续开发的理由，后续成绩仍由真实生成与评价决定。下一次机会优先给投入最少的活跃挑战谱系，缺少挑战者时开发冠军。

## 修改轨迹：让历史说明具体变化与结果

修改轨迹上下文（change-trajectory context）用 `Change` 描述每次改变了哪些计算或参数，并附上相应的执行结果。形成路径、当前程序此前的尝试，以及全局最好成绩的改进记录，都围绕这些改动组织。完整设计描述保留给当前程序、路径起点和参考设计，分别说明开发对象及其计算背景。

修改说明由生成回复提供，至多六十词，要求明确改前与改后。已尝试程序被标记为已经评价，使模型可以在已有改动和结果的基础上提出新的修改。这样，历史承担的是支持后续决策的经验，而不是反复展示一组相近算法。

## 跨谱系参考：为当前实现引入不同的计算

交叉参考优先来自其他谱系。在候选参考中，从成绩不劣于其中位数的程序均匀抽取；缺少其他谱系的有效程序时使用全档案。提示提供参考设计描述，要求保留当前算法的主决策规则，将借用的计算适配到当前代码。完整源码集中于被修改的程序。

近期进步外推决定哪些方向值得继续尝试，修改轨迹与跨谱系参考则提高这些尝试所能利用的信息。对方法的核心检验是：额外保留的开发是否带来足以补偿投入的改进，以及历史中的修改信息是否确实帮助后续生成。
