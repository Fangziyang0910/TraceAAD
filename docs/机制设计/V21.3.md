# V21.3：当前 Base 加当前机制2

V21.3在当前[Base](../TraceAAD-Base.md)上加入[三种算子各自的过程材料](机制2-轨迹引导的上下文与算子.md)，让修改、形成与迁移、探索与发展经历支持不同的设计决定。直接修改现有V21.3，没有新增版本。入口为`--method v21.3`或`v21_3`。

## 当前行为

| 算子 | 输入与规则 |
| --- | --- |
| Refine | 形成路径＋同父代尝试＋当前完整代码与成绩。形成路径默认最近8步；同父代尝试最近3条有效、2条失败，包含Refine、Crossover和Explore。 |
| Crossover | 参考形成路径＋历史接入＋参考Design与成绩＋当前完整代码。接入包括当前父代过去的融合、以当前参考为来源的迁移，不只限定同一参考。 |
| Explore | 最多6条近期方向及其发展记录，包括出生Design、成绩、开发次数、较好后代Design和真实算子路径，最后给当前完整代码。 |

形成路径包括形成目标算法的最后一步，以初始fitness和真实路径序号组织，每步给相对自身父代的完整差分与评价变化，省略区间明确标出。形成和尝试都使用最近窗口，不按成绩波动、代码留存或最好子代额外排序。不同父代、参考的接入保留各自比较条件。

历史不重复完整代码和长analysis，步骤以紧凑标签、差分和结果表达。参考、其他接收方及探索方向保留必要Design。三个算子分别决定改什么、借什么及怎样接入、探索什么，不强制总结、引用或解释历史原因。

所有演化生成保留单次`analysis → code → design`。analysis说明这次改变的计算，历史是设计依据，不是独立的推理流程。当前完整代码不附带Design；差分沿用3行上下文的完整unified diff，失败记录保留执行事实。`--reference-code`仍额外显示参考完整源码；默认形成diff也可能包含参考代码，该开关只比较额外的平铺源码。

初始化与修复提示、选择、评价和预算没有改变。V21.1、V21.2、V22.2、V23.2和V24.1的实现没有随本次修改迁移。

## 记录与恢复

原生配置保存`method=traceaad_v21_3`、`mechanisms=[2]`、`generation_protocol=operator_trajectory_context_v1`。启用参考源码时协议增加`+reference_code`，统一入口同时保存`reference_code`开关。

`attempt.record["context"]`在Refine中记录`formation_path`、`formation_steps`、`children`与`failed`；Crossover记录`reference_path`、`reference_steps`、`integrations`及`reference_code`；Explore记录每个起点`origin`、`development_count`、该分支最好实现`best`及`best_path`。真实程序编号留在记录中，便于核对实际路径与比较对象。

此前V21.3的分层卡片、只读局部尝试和只恢复Refine形成路径等协议均归属各自冻结源码。当前入口拒绝混用旧协议或不同参考源码设置恢复。

## 比较口径

Base与当前V21.3的直接比较检验整套生成变化。单独检验轨迹时，固定父代、算子、参考、指令和输出模板，分别改变相应过程材料。比较不同材料表示时也保持指令一致。`--reference-code`只改变Crossover额外的完整参考代码呈现。

测试位于[tests/v21_3](../../tests/v21_3/)。实现验证不等于生成或完整搜索收益，旧回放不作为新实现的效果证据。
