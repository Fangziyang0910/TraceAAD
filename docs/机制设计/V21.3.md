# V21.3：当前 Base 加当前机制2

V21.3在当前[Base](../TraceAAD-Base.md)上加入[同起点Refine修改证据](机制2-轨迹引导的上下文与算子.md)，不再要求每个算子使用轨迹。直接修改现有V21.3，没有新增版本。入口为`--method v21.3`或`v21_3`。

## 当前行为

| 算子 | 输入与规则 |
| --- | --- |
| Refine | 当前完整代码与成绩；最多3条有效、2条失败的同父代Refine记录，给实际差分和结果，不给祖先或历史Design/analysis。 |
| Crossover | 当前完整代码与成绩，参考Design与成绩；默认不提供参考源码或任何融合历史。`--reference-code`额外展示参考完整代码。 |
| Explore | 任务与当前完整代码，不展示历史探索或开发统计，也不展示当前成绩。 |

Refine先合并源码与反馈重复的记录，优先一个实际改善，再选最近不同记录；无改善时选最近记录。没有同父代Refine历史时使用相同的普通Refine指令。Crossover允许不采用不适合的参考，不要求双方必须参与，也不提示便宜近似。Refine和Explore复用Base的算子指令。

所有演化生成保留单次`analysis → code → design`。analysis只说明这次改变的计算，历史可以作为依据，不是必须完成的分析任务。当前完整代码不附带Design；参考默认通过Design描述。差分沿用3行上下文的完整unified diff，失败记录保留执行事实。

初始化与修复提示、选择、评价和预算没有改变。V21.1、V21.2、V22.2、V23.2和V24.1的实现没有随本次修改迁移。

## 记录与恢复

原生配置保存`method=traceaad_v21_3`、`mechanisms=[2]`、`generation_protocol=refine_local_evidence_v1`。启用参考源码时协议增加`+reference_code`，统一入口同时保存`reference_code`开关。

`attempt.record["context"]`在Refine中记录展示的`children`与`failed`编号；Crossover记录`reference_code`；Explore为空。祖先、融合和探索历史选择逻辑已删除，不保留空的旧字段。

简化前V21.3使用`trajectory_design_reasoning_layered_v1`；旧批次和11月10日已完成的回放继续归属原冻结源码。当前入口拒绝混用旧协议或不同参考源码设置恢复。

## 比较口径

Base与当前V21.3的直接比较检验整套生成变化。要单独检验轨迹，固定父代、Refine指令和输出模板，只改变是否提供同父代差分。与简化前材料比较时也保持指令一致，避免把材料与任务定义混在一起。`--reference-code`只改变Crossover的参考代码呈现。

测试位于[tests/v21_3](../../tests/v21_3/)。实现验证不等于生成或完整搜索收益，旧回放不作为新实现的效果证据。
