# V21.3：当前 Base 加当前机制2

V21.3在当前[Base](../TraceAAD-Base.md)上加入[形成路径与同起点尝试](机制2-轨迹引导的上下文与算子.md)，以紧凑的连续经历支持Refine，不再要求每个算子使用轨迹。直接修改现有V21.3，没有新增版本。入口为`--method v21.3`或`v21_3`。

## 当前行为

| 算子 | 输入与规则 |
| --- | --- |
| Refine | 形成路径＋同父代尝试＋当前完整代码与成绩。路径默认保留最近3步及更早成绩变化较大的步骤，最多8步；同父代尝试最多3条有效、2条失败，包含Refine、Crossover和Explore。 |
| Crossover | 当前完整代码与成绩，参考Design与成绩；默认不提供参考源码或任何融合历史。`--reference-code`额外展示参考完整代码。 |
| Explore | 任务与当前完整代码，不展示历史探索或开发统计，也不展示当前成绩。 |

形成路径包括形成当前算法的最后一步，以初始fitness和真实路径序号组织，每步给相对自身父代的完整差分与评价变化，省略区间明确标出。同父代尝试先合并源码与反馈重复的记录，优先一个实际改善，再选最近不同记录；无改善时选最近记录。

历史不重复Algorithm、Parent等卡片字段，不给完整代码、Design或analysis；Crossover步骤保留参考信息，同起点尝试保留实际算子。Refine使用简短的“保留有用计算、结合演化经历决定下一次修改”指令，不要求解释历史原因。Crossover允许不采用不适合的参考，不提示便宜近似；Explore沿用Base指令。

所有演化生成保留单次`analysis → code → design`。analysis只说明这次改变的计算，历史可以作为依据，不是必须完成的分析任务。当前完整代码不附带Design；参考默认通过Design描述。差分沿用3行上下文的完整unified diff，失败记录保留执行事实。

初始化与修复提示、选择、评价和预算没有改变。V21.1、V21.2、V22.2、V23.2和V24.1的实现没有随本次修改迁移。

## 记录与恢复

原生配置保存`method=traceaad_v21_3`、`mechanisms=[2]`、`generation_protocol=refine_evolution_history_v1`。启用参考源码时协议增加`+reference_code`，统一入口同时保存`reference_code`开关。

`attempt.record["context"]`在Refine中记录完整主父代路径`formation_path`、实际展示的形成步骤`formation_steps`、同父代有效尝试`children`与失败尝试`failed`。路径包含当前算法，步骤序号可对应原始程序编号。Crossover记录`reference_code`；Explore为空。

此前V21.3的`trajectory_design_reasoning_layered_v1`及只读同算子尝试的`refine_local_evidence_v1`均归属各自冻结源码。当前入口拒绝混用旧协议或不同参考源码设置恢复。

## 比较口径

Base与当前V21.3的直接比较检验整套生成变化。单独检验轨迹时，固定父代、Refine指令和输出模板，分别改变形成路径与同父代尝试。比较不同材料表示时也保持指令一致。`--reference-code`只改变Crossover的参考代码呈现。

测试位于[tests/v21_3](../../tests/v21_3/)。实现验证不等于生成或完整搜索收益，旧回放不作为新实现的效果证据。
