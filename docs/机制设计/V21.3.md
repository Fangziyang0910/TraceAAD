# V21.3：当前 Base 加当前机制2

V21.3在当前[Base](../TraceAAD-Base.md)上加入当前的[机制2](机制2-轨迹引导的上下文与算子.md)。代码位于[traceaad_v21_3](../../traceaad_v21_3/)，入口为`--method v21.3`或`v21_3`。父代、算子和参考选择与Base相同。

## 与V21.2的区别

设计推理协议、Refine与Explore指令、展示条数和选择规则不变，轨迹材料改为分层证据：

- 卡片不再显示从`analysis`抽取的修改决定；每条记录给出设计描述、相对父代的完整差分（按角色）和结果。
- 差分统一为3行上下文的unified diff，不设相似度阈值；失败子代也给差分，并给出抛出异常的候选源码行。
- 最近3条祖先给差分，更早的祖先只给设计描述。
- 融合参考只给成绩、设计描述和完整代码，不给形成步骤；没有`--reference-code`对照。
- 当前算法同时给设计描述和完整代码。
- 每张卡片先给结果，再给设计描述和差分。
- Crossover的历史只取此前以同一参考进行的融合（先取当前父代的，再取其他接收方最近的；最多3条有效、2条失败），不再展示当前父代的其他子代；没有这样的记录时不展示历史。
- 公共材料说明改为：代码差异和评价结果是观测事实，设计描述可能不准确，单凭成绩变化不能说明原因；差分标签为`Code change`。Crossover指令删去了“formation records”，并改为要求用此前以该参考的融合判断其计算怎样接入、暴露了什么问题。

## 比较口径

Base与V21.3检验当前机制2的整体增量；V21.2与V21.3检验轨迹材料从“决定＋局部差分＋参考形成步骤”改为分层证据的作用。

## 记录与恢复

原生配置保存`method=traceaad_v21_3`、`mechanisms=[2]`和`generation_protocol=trajectory_design_reasoning_layered_v1`。`attempt.record["context"]`保存实际展示的祖先路径、祖先、给出差分的祖先（`ancestor_changes`）、子代、失败、融合记录（`integrations`）和探索记录。测试位于[tests/v21_3](../../tests/v21_3/)。
