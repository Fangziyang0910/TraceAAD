# V24

**V24 = V21＋机制3。** V24 在 V21 上只加入[轨迹反思与经验累积](机制3-轨迹反思与经验学习.md)。代码位于 [traceaad_v24](../../traceaad_v24/)。

V24 要检验一个问题：**在机制2的局部视图之上，加入从干预事实凝练的全局设计笔记，搜索能否找到更好的算法？** 父代选择、算子比例、评价、修复和预算都与 V21 相同，所以与 V21 的差别只来自笔记和反思。对照为 V21 正式批次 `20261105c_v21_co6`。

## 与 V21 的差异

| 项目 | V21 | V24 |
| --- | --- | --- |
| 评价后 | 无 | 每10次有评价结果的非初始化尝试反思一次，修订最多6条设计笔记 |
| Refine、Crossover 的 `[Context]` | 机制2的段落 | 有笔记时以 `[Design Notes]` 开头，其后不变 |
| Explore | 只读当前代码 | 相同，不读笔记 |
| 模型请求 | 生成与修复 | 另加反思请求，使用独立 schema（`analysis`；`notes` 每项含 `idea`、`lesson`） |

指令文本、输出协议、材料选取和 Base 配置都不变。V24 的源码中，`traceaad_base`、`traceaad_v21`、`benchmarks` 与 `core` 与 V21 正式快照逐文件一致。

## 实现

| 文件 | 内容 |
| --- | --- |
| [notes.py](../../traceaad_v24/notes.py) | 反思提示、响应 schema、反思卡片（机制2卡片；刷新搜索最好的尝试另加 `This attempt set a new search best.`）、`idea`/`lesson` 笔记、解析与笔记段。 |
| [search.py](../../traceaad_v24/search.py) | 继承 V21；`evolution_prompt` 记录尝试开始前的最好成绩并插入笔记；`finish` 计数并触发反思；`restore` 重放笔记。 |

间隔 `INTERVAL = 10`、容量 `CAPACITY = 6` 是模块常量，不进入 `Config`，所以运行配置与 V21 相同。

## 记录

| 位置 | 内容 |
| --- | --- |
| `attempt.record["best_before"]` | 尝试开始前的搜索最好成绩，反思卡片据此标出刷新最好的尝试。 |
| `attempt.record["notes_from"]` | 本次生成所见笔记来自哪次尝试的反思；未展示时为 `null`。 |
| `attempt.record["reflection"]` | 触发反思的尝试上保存所读尝试编号、旧笔记、`analysis`、新笔记和状态。 |
| `attempt.record["aux"]` | 反思请求的状态与 token，汇总进 `summary.json` 的 `auxiliary.reflect`。 |
| `native/notes.json` | 最新一版笔记，便于直接查看。 |
| `native/calls.jsonl` | 反思的完整提示与回复，`stage` 为 `reflect`。 |

反思请求不计入 `model_calls`，也不消耗评价预算。恢复时按 `attempts.jsonl` 重放计数和笔记，不重新调用模型。
