# V24.1

**V24.1 = V21.1（V21.1版机制2）＋围绕具体计算问题形成、可由后续轨迹修订的条件经验。** 实现位于 [traceaad_v24_1](../../traceaad_v24_1/)，方法解释见[机制三](机制3-轨迹反思与经验学习.md)。旧[V24](V24.md)的运行记录与冻结源码保留，当前入口不再启动其早期机制3。

每10次已评价非初始化尝试触发反思，一次反思聚焦一个计算问题。经验持续保存，每次生成最多展示6条。Refine与Crossover借鉴经验，Explore沿用当前代码视图。选择、修复、评价和输出字段沿用V21.1；本版将反思与生成指令写成正面的计算任务。

## 反思围绕什么组织

以尚未审阅的实际修改为入口，按现有关系构造有界的问题片段：

- 同起点比较：规范化父代码相同，实际修改涉及的父代码行有交集。保留锚点和最近的不同实现，不按成绩挑出一个方向作为答案。
- 接续修改：保留形成当前父代的那一步，或直接接续的Refine/Crossover。修改先退步、配套调整后改善时，可以保留这段关系。
- 单个计算事实：一次修改可以用于识别恒零特征等问题，并独立形成经验。

优先选择有相关比较、且锚点较新的问题。小幅修改用源码位置匹配，大幅改写读取完整实现。源码位置和父子链接缩小材料范围，模型根据实际计算确定问题与关系。反思可以记录观察，或形成经验更新。

每个问题包含至多3个核心事件，必要时补父代形成背景。系统从全部有效经验中召回候选：代表来源结构相邻、经验内容与当前计算的词项相似，或经验曾在核心尝试的生成中展示。查询使用核心事件父子程序的代码、设计和分析，内容排序使用IDF加权词项余弦相似度。排序依次看来源与核心事件重合数、内容相似度、结构连接、展示记录和经验编号。

最多6条候选连同完整代表来源加入反思，输入上限内逐条装入。模型读取实际代码与结果后判断共享条件，再修订对应条目。每条经验保留1–3个案例，允许跨分支共同支持一条认识；每个案例保留自己的起点、修改与结果。累计来源另行保存。

## 代码、修改与结果直接对应

材料使用稳定的`Program`编号与`Attempt`编号。每段先展示同一起点的完整代码，随后紧接各次修改与其评价结果。取消临时的`Code N`总表。程序编号识别实现，尝试编号识别事件；经验的`evidence_ids`引用尝试。

小幅修改给出完整差分；大幅替换或差分更长时给完整子代代码；执行失败给实际评价代码和错误反馈。后续需要作为起点的中间实现完整展示一次，再按稳定程序编号引用。模型的`Design`和修改自述保留在原始档案中，不代替反思材料中的实际实现。

完全重复的父子代码及评价反馈合并展示，另记发生的尝试，不把重复次数当独立支持。常数不同或反馈不同不合并。代码未改变与完全重复的观察继续留档并计入十次周期，但不反复进入待审阅集合。

任务背景交代候选函数如何影响整体算法。OP中，函数每个实例只生成一次固定边先验，ACO每一步再结合信息素和动态可行性掩码采样。候选函数改变可行动作之间的相对权重，调用方通过掩码保证可行性。该作用分工同时进入生成和反思的任务背景。

## 经验与更新接口

公开字段仍为`id / idea / when / lesson / evidence_ids`。内容先保存可靠关系：具体改了什么、相关尝试出现什么结果，再说明类似计算中值得保留、调整或检查什么。经验可以表达计算事实、条件化性能取舍和配套设计认识。

反思输出仍为`analysis / updates / archive_ids`。简短分析先写清依据的尝试、变化与成绩方向，再说明认识与条件。每轮最多6项新增或修订，归档最多6个已展示条目。系统验证字段、编号、来源可见性、观察去重，以及更新与归档互斥；跨分支来源按同样规则验证。模型根据计算内容判断案例之间的关系。

旧经验的修订和归档针对本轮完整展示的候选，新经验独立接纳。经验库保留全部有效条目；内部`active`表示条目仍可用于选取。归档用于内容已被整合或替代的条目。请求、解析或事务验证失败时，经验与未读事件保留；成功后标记实际展示的待审阅事件。其他事实继续留档。

生成端保持算子分工：Refine先确定当前计算问题，Crossover先确定参考计算及接入位置，再借鉴短条件经验。Explore只读当前代码。指令直接说明理解实现、比较修改、对应条件与完成计算的动作。

## 保存与展示分别管理

有效经验超过6条时，生成选取5条内容匹配的经验，并按稳定编号轮换1条。匹配查询使用当前代码、设计和分析，Crossover增加已选参考程序的对应内容。少于或等于6条时全部展示。选取过程使用本地词项计算，经验本体与历史版本继续保存。

轮换位置取此前含经验的生成尝试数，对当前有效条目数取模。尝试记录是轮换恢复的依据。未展示的经验可经内容匹配或轮换重新入选，也可由反思直接召回。`experience_ids`记录当次展示的编号；反思沿实际计算检查经验与新结果的关系。

一次尝试修复后仍只贡献一个最终评价事件，全部实际评价照常计入预算。两个状态继续分开：`interval_count`决定触发，`unreviewed_events`记录未读修改。搜索结束不补做反思。

默认上下文仍为49152 tokens，反思输出独立预留4096 tokens，格式余量512 tokens，输入上限44544 tokens。先完整装入一个问题，再补能完整装入的候选经验来源。超限时尝试其他问题或下一条经验，源码与来源保持完整。计量使用服务端聊天tokenizer，计数或请求失败保留事件。

恢复重放已提交状态。方法、任务、配置、材料组织、展示与提示设置逐项匹配后再读取日志。历史`focused_relations`与批量反思运行使用各自冻结源码恢复。统一入口支持`--method v24.1`和`--method v24_1`，见[实验说明](../../experiments/traceaad/README.md)。
