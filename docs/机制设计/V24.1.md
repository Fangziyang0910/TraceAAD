# V24.1

**V24.1 = V21＋围绕具体计算问题形成、可由后续轨迹修订的条件经验。** 实现位于 [traceaad_v24_1](../../traceaad_v24_1/)，方法解释见[机制三](机制3-轨迹反思与经验学习.md)。旧 [V24](V24.md) 的代码、运行记录和实现说明保留。

保留每10次已评价非初始化尝试的触发周期、最多6条活跃经验、Explore不读经验，以及V21的选择、生成、修复与评价。十次是调用周期；一次反思优先解决一个计算问题，不再要求总结这批程序。此次不修改机制一，也不扩大上下文或增加生成前调用。

## 反思围绕什么组织

以尚未审阅的实际修改为入口，按现有关系构造有界的问题片段：

- 同起点比较：规范化父代码相同，实际修改涉及的父代码行有交集。保留锚点和最近的不同实现，不按成绩挑出一个方向作为答案。
- 接续修改：保留形成当前父代的那一步，或直接接续的Refine/Crossover。修改先退步、配套调整后改善时，可以保留这段关系。
- 单个计算事实：没有相关比较时，一次修改仍可用于识别恒零特征等问题，不要求每条经验都有多次成功。

优先选择有相关比较、且锚点较新的问题。大幅改写不靠源码位置建立同起点问题。源码位置和父子链接只是缩小材料范围，不能代替模型判断这些修改是否讨论同一项计算。模型若没有读出新关系，可以只记录观察。

每个问题包含至多3个核心事件，必要时补父代形成背景。只回读与核心事件相连的旧经验及其完整代表来源；无关经验不进入本轮反思，也不能被更新或归档。每条经验保留1–3个相连事件，数量由它表达的关系决定：一个事实、同起点取舍或必要的接续变化。累计来源另行保存。

## 代码、修改与结果直接对应

材料使用稳定的`Program`编号与`Attempt`编号。每段先展示同一起点的完整代码，随后紧接各次修改与其评价结果。取消临时的`Code N`总表。程序编号识别实现，尝试编号识别事件；经验的`evidence_ids`引用尝试。

小幅修改给出完整差分；大幅替换或差分更长时给完整子代代码；执行失败给实际评价代码和错误反馈。后续需要作为起点的中间实现完整展示一次，再按稳定程序编号引用。模型的`Design`和修改自述保留在原始档案中，不代替反思材料中的实际实现。

完全重复的父子代码及评价反馈合并展示，另记发生的尝试，不把重复次数当独立支持。常数不同或反馈不同不合并。代码未改变与完全重复的观察继续留档并计入十次周期，但不反复进入待审阅集合。

任务背景还要交代候选函数如何影响整体算法。OP中，函数每个实例只生成一次固定边先验，ACO每一步再结合信息素和动态可行性掩码采样。候选函数改变可行动作之间的相对权重，不能使被掩码的动作越过预算限制。该说明同时进入机制二的生成和机制三的反思，评价器保持原样。

## 经验与更新接口

公开字段仍为`id / idea / when / lesson / evidence_ids`。内容先保存可靠关系：具体改了什么、相关尝试出现什么结果，再说明类似计算中值得保留、调整或检查什么。性能差异可以形成条件化取舍，不要求补造完整原因。

反思输出仍为`analysis / updates / archive_ids`。简短分析先写清依据的具体尝试、变化与成绩方向，再说明它改变了哪项认识，不写程序的总体排名。未涉及的经验原样保留。系统检查来源是否可见、是否组成相连关系，以及更新、归档和容量是否有效；这些检查不自动证明经验内容正确。

只有本轮相关且来源完整装入的旧经验可被修订。满额而没有相关条目可更新时，允许保留分析而不新增条目。请求、解析或事务验证失败时，经验与未读事件不变；成功后只标记实际展示的待审阅事件。其余事实继续留档，不以全量审阅率作为经验质量目标。

生成端保持现有算子分工：Refine先确定当前计算问题，Crossover先确定参考计算及接入位置，再借鉴短条件经验；Explore不读经验。无经验时完整沿用V21提示，不增加输出字段或检索器。

## 运行状态与恢复

| 位置 | 内容 |
| --- | --- |
| [evidence.py](../../traceaad_v24_1/evidence.py) | 事件、问题片段、相邻呈现、相关来源与完整装入 |
| [notes.py](../../traceaad_v24_1/notes.py) | 五字段经验、最小来源关系、局部更新和短经验 |
| [context.py](../../traceaad_v24_1/context.py) | 保留V21材料和已有Refine/Crossover用法 |
| [search.py](../../traceaad_v24_1/search.py) | 周期、观察留档、未读状态、调用与恢复 |
| `attempt.record["reflection"]` | `focus`、相关经验编号、所示/审阅/延后事件、更新和完整快照 |
| `attempt.record["observation"]` | 未改变计算或完全重复的观察及对应尝试 |
| `native/calls.jsonl` | `stage=reflect`的完整提示、回复与用量 |
| `native/experience.json` | 状态便读副本；恢复以已提交的`attempts.jsonl`为准 |
| `native/run_config.json` | 方法、任务、配置和`organization=focused_relations`等反思设置 |

一次尝试修复后仍只贡献一个最终评价事件，全部实际评价照常计入预算。两个状态继续分开：`interval_count`决定触发，`unreviewed_events`记录未读修改。搜索结束不补做反思。

默认上下文仍为49152 tokens，反思输出独立预留4096 tokens，格式余量512 tokens，输入上限44544 tokens。先完整装入一个问题，再补能完整装入的相关经验来源。超限不裁剪关系或源码，尝试其他问题；计数或请求失败保留事件。计量使用服务端聊天tokenizer，不回退到字节估算。

恢复重放已提交状态，不调用模型。方法、任务、配置或材料组织设置不一致时，在修改日志前拒绝恢复。此前批量反思的V24.1目录不能直接按本版新规则续跑。统一入口仍支持`--method v24.1`和`--method v24_1`，见[实验说明](../../experiments/traceaad/README.md)。
