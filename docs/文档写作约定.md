# 文档写作约定

目标是让读者能够按顺序理解：算法怎样产生，怎样评价，过去的结果怎样改变下一次搜索。

中文表述采用 ASD-STE100 的短句、明确主语和稳定用词原则。“约 90%”表示写作要求，不是标准认证或自动评分。该标准的词典针对英文；中文按其表达原则执行。依据见[官方说明](https://www.asd-ste100.org/STE_faq.html)和[写作规则原文](https://www.asd-ste100.org/assets/files/ASD-STE100_ISSUE9.pdf)。

## 先写具体操作

一句主要说明一件事。每段围绕一个问题。先说结论，再给证据。条件先写，满足条件后做什么接着写。

写明动作的执行者：LLM 提出设计，程序执行计算，评价器返回成绩，选择规则分配下一次生成机会。机制说明按执行顺序展开。先解释一种记录保存什么，再解释它怎样参与计算。

首次出现的必要术语，要用具体操作解释。一个概念使用一个稳定名称。科研说明采用自动算法设计、进化计算和优化领域的术语。

## 按含义选择用词

| 要说明的内容 | 使用的说法 |
| --- | --- |
| 一次成功解析的程序生成结果 | 程序个体，对应 `Program` 对象；校验或执行失败保留为失败个体 |
| 请求模型产生一份实现，占用一次生成预算 | 一次生成尝试；回复失败、重复代码与修复按实际规则计数 |
| 下一次修改从哪份程序开始 | 父代程序；由它修改得到的程序称为子代程序 |
| 模型对算法计算方式的文字描述 | 算法设计说明；提示中的名称是 Design，程序字段是 `idea` |
| 决定代码是否执行了设计中的计算 | 检查程序是否实现设计 |
| 决定新程序是否删除原有计算 | 检查是否保留原有计算，并说明哪些计算允许替换 |
| 下一次生成参考同一设计的旧实现 | 复用相同设计的已有程序 |
| 运行后得到的数值 | 程序成绩或适应度，并说明计分方向 |
| 达到评价要求 | 有效程序，并写清有效条件；有效不表示成绩优秀 |
| 从模型回复取得代码失败 | 回复解析失败，并写明格式不符、截断或缺少内容 |
| 搜索结束后选定程序 | 确定最终程序 |
| TSP 每一步可访问的点 | 未访问城市或可选的下一城市 |
| 调度或着色中可执行的选择 | 具体作业、工序或着色操作 |
| 预算、随机种子、模型、数据等比较条件 | 实验设置，并逐项写明 |

程序个体、生成次数、模型请求与运行评价分别计数。当前 V12.1 的解析失败不创建个体，相同源码仍创建新个体并评价。说明预算时写出具体单位。修复、重复与失败是否计入，要按对应方法和批次的实际规则解释。

种群、父代、子代、变异、交叉、选择概率、适应度、随机种子、对照实验和消融实验保留领域含义。树搜索和图论中的节点也保留，并说明节点表示程序、搜索状态还是问题中的顶点。

## 区分机制、代码和证据

正文先解释算法操作。字段表再列实际代码名称与含义。运行命令、文件格式和服务设置写在实现或实验操作部分。

公式旁写明每个量的来源、计算条件和用途。数据结构旁写明记录何时产生、保存哪些信息、后续在哪里使用。条件分支写出成立和不成立时各做什么。

模型的设计说明、实际代码与运行结果分别说明。LLM 的代码检查结果按模型判断解释。程序总分与算法思想的潜力分别讨论。推断说明依据，假设说明需要怎样检验。

## 修改已有文档

改写句子时保留实验数值、计分方向、公式、来源链接和结论所需的条件。原始提示、代码、日志和直接引文保留原文。历史方案按当时设置说明，并写清是否实现。当前方法以当前实现为准。

修改标题时检查索引文字与文内定位链接。已有文件名用于定位，通常保留。写作检查包括术语含义、句子主语、执行顺序、计数单位和证据来源。
