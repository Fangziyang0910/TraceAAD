# TraceAAD：同龄竞赛与有限偏差搜索

*面向持续算法探索的接续决策搜索*

**英文工作标题：** TraceAAD: Age-Matched Racing with Limited-Discrepancy Development Search

**文档版本：** 机制设计稿 v1.0

**整理日期：** 2026 年 10 月 29 日

**适用接口：** 普通外部聊天 API；模型每次返回完整算法函数，评价器执行并返回成绩。

核心机制：为不同起点保留开发时间，为早期接续选择保留修正空间。

TraceAAD 在外层通过同龄竞赛分配开发机会，在内层通过有限偏差搜索组织后续生成。每次产生子代后，搜索保留“沿子代继续”和“从父代另试”两种接续方式。当前成绩决定优先顺序，有限偏差调度则使少量非贪婪选择得到实际开发。所有有效候选按真实成绩进入全局档案，最终返回其中表现最好的完整算法。

## 文档依据与规格范围

本文整理上一轮确定的“同龄竞赛＋有限偏差搜索”方案。问题依据来自用户提供的[《TraceAAD：脱离、脱轨与以思想为臂的递增收益老虎机》](TraceAAD：脱离、脱轨与以思想为臂的递增收益老虎机.md)中的运行观察 [E1]；机制来源为经典有限偏差搜索与递增收益老虎机研究 [1, 2]。本文采用的是以具体程序为起点的开发搜索这一统计单位。

上一轮已经确定两层搜索、父子双向接续和路径上下文。本次进一步指定接续树遍历顺序、同龄参考缺失时的处理、失败与重复处理、初始化、停滞发散及预算记账。这些内容是本版的实现规格，不是文献中已有的 AAD 算法，也不是原始实验记录的结论。

本稿以用户提供的详细设计 [E2] 为默认规格，并结合前轮讨论补充第 1.3 节的统计单位与证据边界，以及第 13.3 节的对照解释；这些补充不改变下文的默认调度规则。

本文给出一套可直接据此实现的默认规则。真实模型上的搜索收益由正式实验评价；默认参数是起始配置。

## 1. 研究问题与核心认识

### 1.1 问题：开发机会可能被早期接续选择吸收

LLM-AAD 的一次生成得到一个完整候选程序，执行评价给出当前性能。搜索随后决定：下一次从哪个程序出发。

现有讨论中的关键观察是，部分新设计在最初一两次开发中转向了熟悉的做法，后续提示又沿用这些子代。用户记录追查了五条最终换回初始做法的冠军谱系，其中的方向变化均发生在 Diverge 后的第 1–2 次开发尝试。OP 案例中，后一条提示直接包含已经改变方向的前一子代 [E1，§2.3]。

这说明需要同时处理两个位置：

| 搜索位置 | 需要解决的问题 | 本文对应机制 |
| --- | --- | --- |
| 起点之间的投入分配 | 新起点尚未充分开发，就因当前成绩落后而失去机会 | 同龄竞赛 |
| 一个起点内部的后续生成 | 一次早期高分接续，使后续投入长期集中在同一条路径 | 有限偏差搜索 |

沿用项目中的问题表述，前者对应“脱离”，后者对应“脱轨被后续接续放大”。本文将后一问题具体化为早期接续过度集中，直接作用于父代选择和后续调用顺序。

### 1.2 洞察：好程序值得保存，早期选择也值得重新考虑

子代 B 优于父代 A，说明 B 值得保存并优先开发。同时，从 A 再生成一个不同子代，仍可能形成更好的后续路径。

因此，一次生成评价应产生两类信息：一是候选本身的成绩；二是一个新的接续分岔。前者用于保存结果，后者进入后续搜索。

算法质量负责指导搜索，接续分岔负责保留搜索选择。

本文最终优化的对象仍是完整算法在任务上的真实表现。每次模型调用都生成或修改出一个完整算法函数，每次新候选都通过任务评价器评价。

### 1.3 与前一版方案的关系及证据边界

相较于[行为小生境方案](TraceAAD：同龄竞赛与行为小生境.md)，本版将统计单位改为“从具体程序出发的开发搜索”。同一任务承担其全部分支的请求消耗，也获得这些分支产生的候选成绩；不再需要先按行为归类思想，或将外来成果记入未增加年龄的接收小生境。

机制保护的是重新考虑早期接续的机会。返回父代后，模型仍可能再次生成熟悉的设计；因此，接续路径保持可探索，不等于算法思想必然保持不变。低分子代也可以通过替代接续继续开发，搜索不以维持原设计为硬约束。

既有记录中的 5 个切换案例来自 13 个 Diverge 起源的最终冠军谱系 [E1]。它们支持“谱系延续不等于原方向延续”的观察，不能单独证明切换有害，也不能用于估计所有生成请求的脱轨率。当前待验证的解释是：某些早期高分接续是否遮蔽了更有价值的替代路径；其价值最终取决于同预算下发现的算法质量。

## 2. 跨领域来源与 AAD 适配

### 2.1 有限偏差搜索：系统性尝试少量非贪婪选择

Harvey 与 Ginsberg 提出的有限偏差搜索（Limited Discrepancy Search，LDS）利用启发式对子分支排序，优先探索只在少量决策点偏离启发式的路径。其出发点是：启发式通常有用，但少数早期选择可能把后续搜索带入不理想的区域 [1]。

在本文中，启发式来自父子程序的当前成绩。一次“偏差”具有明确含义：在一个接续分岔处，选择即时成绩排序中的第二个接续方向。

| 经典搜索概念 | 本文中的具体对象 |
| --- | --- |
| 搜索状态 | 当前父代、对应路径上下文和本地尝试记录 |
| 启发式顺序 | 父代与子代的真实成绩顺序 |
| 首选分支 | 从当前成绩较好的程序继续生成 |
| 替代分支 | 从另一个程序继续生成 |
| 一次偏差 | 选择替代分支一次 |
| 节点展开 | 一次普通 API 调用，生成完整函数并评价 |

经典 LDS 面向有限搜索树。AAD 的候选按调用逐步产生，因此本文采用逐步增加深度上限的有限偏差调度，并保存已展开节点的实际结果。

### 2.2 同龄竞赛：按照相近开发投入比较搜索表现

递增收益老虎机研究考虑选项随投入而改善的决策问题，并研究固定预算下的最优臂识别。Mussi 等提出了 R-UCBE 与分阶段拒绝方法 R-SR [2]。

本文据此采用同龄比较原则：比较两个开发任务获得相同次数调用时已经找到的最好成绩，再决定后续投入。具体的冠军参考、检查点和暂停规则由第 6 节定义。

### 2.3 两层机制如何配合

外层回答：哪个起点值得继续投入？

内层回答：这个起点拿到下一次机会后，应该从哪一个已有程序继续生成？

两层共同构成一个完整搜索过程：外层为新起点留下开发时间，内层把这段时间分配给少量不同接续路径。路径经验随后用于对应位置的下一次生成。

## 3. 搜索对象与记录单位

### 3.1 程序、开发状态和开发任务

三个对象分别承担不同职责。

程序（Program）。 一份完整源码及其评价记录。程序具有唯一记录编号、源码、有效性、原始成绩和统一方向的质量值。本文统一以质量值越大越好描述算法；最小化任务使用原始目标值的相反数。

开发状态（Development State）。 一次待执行的生成请求所依赖的状态，包括当前程序、当前路径上的已选接续，以及在该位置已发生的尝试。每个开发状态最多执行一次模型请求。

开发任务（Development Task）。 从一个有效起点出发形成的完整搜索，包括接续决策树、已消耗调用数、历史最好成绩曲线和当前遍历位置。外层同龄竞赛以开发任务为单位。

例如，程序 A 可以出现在两个不同开发状态中：初次开发 A；以及生成 B 后选择仍从 A 另试。两者使用相同父代源码，但后者具有不同的尝试记录和接续位置，需要一次新的模型调用。

### 3.2 两种路径记录

系统保存两种关系，生成时各有用途。

接续决策路径记录每个分岔处选择了首选还是替代接续，用于计算偏差次数和调度顺序。

程序开发路径只记录当前真正选作父代的程序序列，用于生成上下文。

例如：

```text
生成事件：A 生成 B；随后选择仍从 A 另试；得到 A1。

接续决策路径：在第一次分岔处选择 RETRY。
程序开发路径：A → A1。
全局程序档案：A、B、A1 均保留。
```

B 的生成事件完整保存。A1 的形成路径则由 A 出发，以保证下一次上下文对应当前实际开发位置。

### 3.3 开发年龄与成绩曲线

任务年龄为该任务实际消耗的开发请求次数。解析失败、无效程序、超时和重复生成均计入年龄。创建起点的调用计入全局预算，并单列为建起点成本；有效起点创建完成时，任务年龄为 0。

任务在年龄 n 的成绩为：

起点及该任务前 n 次开发请求产生的全部有效候选中的最好质量值。

它评价的是“从这个起点进行搜索，已经找到了什么”。任务中的所有分岔共享这一条外层成绩曲线。历史快照在请求完成后写入，后续结果不回填到较早年龄。

## 4. 接续分岔：内层搜索的决策单位

### 4.1 一次展开的输入与输出

输入为一个尚未展开的开发状态，当前程序记为 A。

外围程序组织任务、接口、A 的完整代码、A 的成绩及对应路径材料。模型返回完整候选 B。系统解析代码，执行评价，保存该次生成记录。

B 有效且与 A 源码不同，就建立两种接续：

| 接续动作 | 后续状态的当前程序 | 程序开发路径怎样更新 |
| --- | --- | --- |
| FOLLOW：沿子代继续 | B | 在当前路径后接入 B |
| RETRY：从父代另试 | A | 保留当前路径，增加一次本地尝试记录 |

这两条边只是建立待探索状态。只有调度器选择展开其中一个状态时，才发生下一次 API 调用。

### 4.2 用即时成绩确定首选与替代

| 候选情况 | 首选接续，记为 0 | 替代接续，记为 1 |
| --- | --- | --- |
| B 的质量高于 A | FOLLOW(B) | RETRY(A) |
| B 的质量低于 A | RETRY(A) | FOLLOW(B) |
| B 与 A 同分，但源码不同 | RETRY(A) | FOLLOW(B) |
| B 无效或请求失败 | RETRY(A) | 无 |
| B 与 A 的规范化源码完全相同 | RETRY(A) | 无 |

同分时保留父代优先，使规则确定。源码完全相同仅通过统一换行和文件首尾空白后的源码比较确定。

这里的“偏差”是选择标记为 1 的边。它可能表示暂不采用一个高分子代，也可能表示继续开发一个当前较差的子代。

### 4.3 状态保持独立，结果共享保存

两个状态即使使用同一份父代代码，也分别保存自己的路径材料和本地尝试记录。展开其中一个状态，不会改写另一个状态已经确定的输入材料。

程序存储与状态存储分开。相同源码可以共享存储，接续状态仍按其位置区分。全局档案保存全部生成记录和有效程序，最终结果按真实质量选择。

### 4.4 失败与重复如何继续

失败状态只产生 RETRY 接续。下一次仍从有效父代生成，并获得简短错误反馈。该反馈可以包含异常类型、执行限制和返回格式问题。

首版不安排独立的隐藏修复调用。任何后续修复或重新生成都占用下一次明确的开发请求。

完全相同的源码只保留一条接续边，避免为同一个起点建立两条内容相同的选择。重复请求本身仍然计入预算，并写入日志。

## 5. 内层机制：有限偏差开发搜索

### 5.1 深度与偏差次数

深度是当前状态之前经历的生成决策层数。根状态深度为 0。即使某一步继续使用相同父代，新的生成状态也进入下一层。

偏差次数是从根到该状态的接续路径上，选择替代边的次数。

深度控制连续搜索展开到哪里；偏差次数控制一条路径允许重新考虑多少次即时成绩选择。

### 5.2 默认调度窗口

每个任务从深度上限 H＝2 开始。窗口允许展开深度为 0 到 H−1 的状态。

最大偏差次数设为：

`D(H) = min(H − 1, floor(log2(H)))`

| 深度上限 H | 最大偏差次数 D(H) | 搜索侧重点 |
| --- | --- | --- |
| 2–3 | 1 | 很早尝试另一种接续 |
| 4–7 | 2 | 在较长开发中重新考虑少数选择 |
| 8–15 | 3 | 进一步组合替代接续 |
| 16–31 | 4 | 随投入扩大可搜索的接续组合 |

当前窗口中的可达状态完成后，H 增加 1。此前已展开状态继续使用已有结果，新增状态才调用模型。

这条深度—偏差关系是本版提出的默认调度规则。

### 5.3 一个窗口中的遍历顺序

首先遍历零偏差路径，然后遍历一次偏差、两次偏差，直到 D(H)。在相同偏差次数下，优先把替代选择放在靠近根的位置。

在所有父子候选都有效且源码不同时：

```text
H = 2：依次展开 ε、0、1。
H = 3：已有状态跳过，新增 00、10、01。
H = 4：已有状态跳过，新增 000、100、010、001、11、110、101、011。
```

其中 ε 表示根状态；每个数字表示上一个分岔处选择首选边或替代边。

这一顺序意味着，先做一次短的成绩优先开发，然后就重新考虑早期接续。随着深度扩大，搜索逐步结合更长的开发和更多替代选择。

### 5.4 在实际树上遍历

遍历器直接检查已经存在的接续边。无效候选只有首选边，遍历器直接跳过不存在的替代边。

实现时使用显式栈，保留“当前节点、深度、剩余偏差次数”。不枚举所有理论上的二进制序列，也不为不存在的分支创建占位调用。

每次外层只请求一个尚未展开的状态。完成一次生成评价后即可暂停，下一次获配预算时继续相同遍历。

### 5.5 早期替代选择会获得实际调用

当首次候选有效且与父代源码不同时，H＝2 的调度会展开根状态、首选状态和替代状态。因此，在该任务获得前三次开发请求时，第一次接续的两个方向均已得到后续生成机会。

首次候选更好时，第三次调用从原父代重新生成。首次候选更差时，第三次调用从该较差候选继续生成。这是调度规则直接带来的行为，见第 10 节示例。

外层默认第一次检查在第 5 次请求，因此，最早的替代接续发生在首次同龄竞争之前。

## 6. 外层机制：同龄竞赛

### 6.1 参考对象

当前冠军任务，是拥有全局最好程序的开发任务。同分保留最早取得该质量的记录及其所属任务。

检查点为第 5、10、20、40……次开发请求。设任务最近完成的检查点为 r，则将它在年龄 r 的历史最好质量，与冠军任务在年龄 r 的历史最好质量比较。

相同或更好则继续开放，较差则暂停。检查点之间继续使用最近一个已完成检查点。

### 6.2 任务状态

| 状态 | 判定 | 是否可以获得下一次调用 |
| --- | --- | --- |
| YOUNG | 年龄小于 5 | 是 |
| CHAMPION | 当前冠军任务 | 是 |
| ACTIVE | 最近同龄检查点不差于参考 | 是 |
| WAIT_REFERENCE | 已到检查点，但冠军尚未达到该年龄 | 暂时等待 |
| PAUSED | 最近同龄检查点落后于参考 | 暂停 |

候选任务中，优先选择年龄最小者；同龄时按任务创建顺序选择。冠军也参加这一排序。只有冠军可继续时，就将下一次机会给冠军任务。

WAIT_REFERENCE 时读取的参考值尚不存在，因此先由其他符合条件的任务推进。冠军一旦达到该年龄，再进行真实的同龄比较。

### 6.3 冠军更换与任务恢复

每次新评价完成后，更新冠军并重新计算各任务状态。原来暂停的任务如果通过新冠军的同龄参考，可以恢复；恢复后保留原年龄、接续树和遍历位置。

所有历史成绩快照保持原值。已经取得的完整程序不因任务暂停而丢弃。

### 6.4 谁获得信用与谁承担成本

一次开发请求属于哪个任务，其请求消耗与有效候选成绩就进入该任务的记录。候选在该任务的任意接续分支产生，都属于从该起点出发取得的成果。

因此，本版的曲线统计与价值定义一致：比较具体开发搜索的产出，调度该搜索内部的替代路径。

建立新起点的请求单列为全局建起点成本。若起点有效，创建年龄为 0 的新任务，并以起点成绩作为其初始质量。

## 7. 完整搜索流程

### 7.1 初始化

默认目标为 5 个有效起点，最多发出 16 次初始化请求。每次请求使用任务描述、函数接口、输入输出约束和评价目标，生成完整算法函数。

每个有效起点创建一个开发任务。初始化失败计入全局请求预算。达到有效起点数、初始化请求上限或总预算后结束初始化；已有有效起点即可进入开发。全部初始化失败时，返回明确的初始化失败状态与日志。

调用方可以提供已评价的初始程序作为起点。其获得方式及评价成本在运行配置中单列；比较实验采用相同的起点条件。

### 7.2 常规开发

每轮顺序固定：

1. 检查是否满足发散条件。

2. 否则更新冠军与同龄状态，选择一个任务。

3. 从该任务的有限偏差调度器取得下一个未展开状态。

4. 组织该状态的路径上下文，调用普通聊天 API。

5. 解析完整候选，执行评价。

6. 更新全局档案、任务年龄和成绩曲线。

7. 建立首选与替代接续，等待下一次分配。

每次循环最多执行一次生成请求。主版本在单次搜索运行内部按顺序执行，多个独立实验运行可以并行。

### 7.3 停滞后的新起点

默认停滞窗口为 40 次全局请求。距离最近一次全局严格改进和最近一次发散请求均至少 40 次，且剩余请求预算不少于 6 时，发起一次 Diverge。

Diverge 的输入为任务、接口及当前最好完整程序，要求尝试不同的计算方式并返回完整函数。有效结果创建新的开发任务；无效结果只记录成本，并从本次请求重新计算发散间隔。

新任务年龄从 0 开始，首轮同龄检查仍为第 5 次开发。Diverge 属于已有搜索循环中的起点扩展操作，有限偏差搜索负责此后如何开发。

### 7.4 结束与最终算法

总请求预算耗尽或外部时间预算达到上限时停止。已完成评价的有效程序均保留，输出全局训练评价最好的完整算法。同分采用最早取得该成绩的程序。

最终程序确定后，使用独立测试集执行一次既定测试协议。测试结果用于报告，不进入搜索与同龄比较。

## 8. 路径上下文与普通 API 调用

### 8.1 固定输入结构

每次开发提示包含五部分：

实现修订（`v18-context-2`）：生成提示按[公共实验协议](../experiments/PROTOCOL.md)提供问题、接口和实际反馈；实例数量、规模、种子及时间预算留在执行配置中。运行限制由评价器执行，不预先展示给生成模型。

| 提示部分 | 内容来源 |
| --- | --- |
| 任务与接口 | 任务适配器提供的问题说明、函数签名、数据类型和返回值约束 |
| 当前父代 | 当前开发状态中的完整代码 |
| 评价信息 | 父代真实成绩、目标方向及已有实际评价反馈 |
| 路径经验 | 当前程序开发路径上最近的实际程序变化与结果 |
| 本地尝试反馈 | 该接续路径在当前父代位置已尝试的次数、成绩与失败状态 |

路径经验默认保留最近 4 次程序接续。本地尝试反馈默认保留最近 3 条，包含尝试序号、成绩变化和错误信息，不展示未选子代的完整实现。

路径材料可以由外围程序计算源码差分并配上成绩。模型仍然输出完整函数，不增加计划、思想标签或反思字段。

### 8.2 不同接续对应不同经验

沿 B 继续时，B 进入当前程序开发路径，相关父子评价记录可以展示。

从 A 另试时，完整父代仍是 A。上次候选的成绩可以作为尝试反馈，但其代码不作为当前已经采纳的实现展示。若随后采用 A1，则路径更新为 A→A1。

这种组织方式使得有限偏差搜索不仅改变调用位置，也改变该位置真正用于下一次生成的经验。

### 8.3 模型请求示例

```text
[Task and Interface]
任务、函数签名、输入输出语义。

[Current Program]
当前父代的完整代码。

[Evaluation]
当前成绩与优化方向。

[Selected Development Path]
最近若干次实际选取的程序变化及其评价结果。

[Previous Attempts at This Position]
本路径在当前父代上的尝试次数、结果和必要错误反馈。

[Request]
从当前程序出发，生成一个更好的完整算法函数。
根据实际评价与路径经验选择改进方式，满足接口和运行限制。
这是从当前程序出发的第 N 次尝试，请给出另一种有针对性的实现。
仅返回完整代码。
```

任务说明提供必要接口和语义，开发提示中的实现代码以当前父代为准。历史超出上下文预算时，先移除最旧的本地反馈，再移除最旧的路径片段；保留任务、接口、当前代码和当前成绩。

温度、输出上限和 API 超时采用统一的运行配置。API 支持随机种子时可记录独立请求种子；否则记录请求序号与完整输入输出。

## 9. 预算、评价与异常处理

### 9.1 三种成本分别记录

| 成本 | 记账规则 |
| --- | --- |
| 生成请求 | 每次实际发出的请求计一次，包含初始化、Diverge、失败与重复 |
| 模型使用成本 | 记录可获得的输入/输出 token、费用及响应时间；缺失则标记不可用 |
| 程序评价成本 | 记录评价次数、CPU/墙钟时间、超时和失败类别 |

任务年龄只统计该任务发起的开发请求。全局预算包含全部请求。读取树中已有结果与选择接续边不消耗新的模型请求。

首版不自动追加未记账的修复、反思或候选选择调用。

### 9.2 评价协议

父子比较和同龄比较使用同一任务内固定的训练实例、随机种子设置及计算限制。有效候选的评价由任务适配器完成。

对于最大化任务，质量等于原始评价；对于最小化任务，质量取原始评价的相反数。NaN、无穷值、接口错误及评价超时均记为无效。

评价器返回的质量决定接续排序。当前默认规则使用直接数值比较，同分按第 4 节处理。

### 9.3 异常分支

| 事件 | 本轮记录 | 下一接续 |
| --- | --- | --- |
| API 错误或超时 | 计一次请求；保存错误类型 | 从原有效父代重新生成 |
| 文本无法解析为函数 | 计一次请求；保存解析失败 | 从原父代重新生成 |
| 编译、执行或接口失败 | 计一次请求和实际评价成本 | 从原父代重新生成 |
| 候选有效但较差 | 保存质量与完整代码 | 首选父代，替代为该子代 |
| 候选有效且更好 | 更新档案和任务成绩 | 首选子代，替代为父代 |
| 同分但源码不同 | 保存两个程序 | 首选父代，替代为子代 |
| 与父代源码相同 | 记录重复和评价 | 只建立父代继续状态 |

当前父代始终是一个有效程序，所以失败后仍有明确生成起点。

## 10. 完整例子：从一次高分接替到另一条改进路径

以下是合成示例，质量越大越好。候选结果仅用于解释调度。

初始程序 A 的质量为 60。

| 任务内调用 | 深度上限 | 状态地址 | 本次父代 | 新候选及质量 | 本次输入中的程序路径 |
| --- | --- | --- | --- | --- | --- |
| 1 | 2 | ε | A：60 | B：90 | A |
| 2 | 2 | 0 | B：90 | B1：91 | A→B |
| 3 | 2 | 1 | A：60 | A1：65 | A |
| 4 | 3 | 00 | B1：91 | B2：92 | A→B→B1 |
| 5 | 3 | 10 | A1：65 | A2：98 | A→A1 |
| 6 | 3 | 01 | B：90 | B3：93 | A→B |

第一轮先使用 B 的即时优势。第三次调用明确从 A 另试，而不是继续让 B 的后代占用所有机会。第五次调用进一步开发 A1，得到更好的 A2。

任务在年龄 5 的最好质量为 98，进入外层同龄比较。B、B1、B2 的结果也全部保留。

另一种情况是 A 生成质量为 50 的有效 W。此时首选仍从 A 另试，替代接续是开发 W。H＝2 中的第三次请求会从 W 出发。这使暂时退化的实现也有一次实际发展机会。

两种情况由同一个父子成绩排序与有限偏差调度处理。

## 11. 机制如何落实到六类任务

搜索层依赖三个任务能力：提供函数接口、执行完整候选、返回质量。各任务继续使用自身评价器。

| 任务 | 候选评价方式 | 搜索层实际读取 |
| --- | --- | --- |
| TSP | 将生成函数放入既定求解流程并评价路线质量 | 有效性、路线目标汇总、成本 |
| CVRP | 使用生成的启发式函数运行既定评价流程 | 有效性、路线目标汇总、成本 |
| OP | 使用生成的启发式函数运行既定评价流程 | 有效性、收集奖励汇总、成本 |
| FSSP | 执行生成的算法函数或既定求解器组件 | 有效性、调度目标汇总、成本 |
| JSSP | 执行完整算法或任务约定的生成接口 | 有效性、调度目标汇总、成本 |
| 图着色 | 执行生成算法并检查解的合法性 | 有效性、颜色数或既定目标、成本 |

候选函数输出矩阵、优先级、扰动操作或完整解，均由任务适配器完成原有评价。父子比较与有限偏差调度读取统一质量值，因此采用相同的搜索规则。

具体输入签名与运行限制以实验任务协议为准；本文不改变评价任务的定义。

## 12. 算法伪代码

### 算法 1：完整搜索

```text
initialize valid root tasks under the initialization budget
archive = all generation records and valid programs

while global request budget remains:
    champion = owner_of_global_best(archive)

    if divergence_due() and enough_budget_for_new_root():
        result = generate_and_evaluate_new_root(champion)
        charge_global_setup_request(result)
        if result.valid:
            create_task(root=result.program, age=0)
        continue

    status = classify_tasks_by_same_age(champion)
    eligible = tasks with status in {YOUNG, CHAMPION, ACTIVE}
    task = min(eligible, key=(age, creation_id))

    state = next_unexpanded_state(task)
    prompt = build_path_context(state)
    result = chat_api_generate_and_evaluate(prompt)

    charge_global_development_request(result)
    append_global_record(result)
    task.age += 1
    task.best_curve.append(max(task.best_curve[-1],
                               result.quality if result.valid else -infinity))
    expand_continuations(state, result)

return best_valid_program(archive)
```

### 算法 2：同龄状态

```text
def status(task, champion):
    if task is champion:
        return CHAMPION
    if task.age < 5:
        return YOUNG

    r = largest value in {5, 10, 20, 40, ...} not exceeding task.age
    if champion.age < r:
        return WAIT_REFERENCE
    if task.best_curve[r] >= champion.best_curve[r]:
        return ACTIVE
    return PAUSED
```

### 算法 3：寻找下一个未展开状态

```text
def next_unexpanded_state(task):
    while True:
        H = task.depth_limit
        D = min(H - 1, floor(log2(H)))

        for k in range(D + 1):
            # 状态、当前深度、剩余偏差次数
            stack = [(task.root_state, 0, k)]

            while stack:
                state, depth, remaining = stack.pop()

                # 剩余接续位置不足以容纳所要求的偏差次数
                if remaining < 0 or remaining > H - depth - 1:
                    continue

                if not state.expanded:
                    return state

                if depth == H - 1:
                    continue

                # 栈后进先出：同一偏差轮次先访问较早的替代接续
                if state.preferred_child exists:
                    stack.push((state.preferred_child,
                                depth + 1, remaining))
                if remaining > 0 and state.alternative_child exists:
                    stack.push((state.alternative_child,
                                depth + 1, remaining - 1))

        task.depth_limit += 1
```

伪代码通过已保存状态重建遍历。实际实现可持久保存当前窗口和遍历栈，减少重复访问已有节点；生成顺序保持相同。

### 算法 4：建立接续

```text
def expand_continuations(state, result):
    parent = state.current_program
    state.expanded = True
    state.generation_record = result

    if not result.valid or same_source(result.program, parent):
        state.preferred_child = new_retry_state(state, result)
        state.alternative_child = None
        return

    follow = new_follow_state(state, result.program)
    retry = new_retry_state(state, result)

    if result.quality > parent.quality:
        state.preferred_child = follow
        state.alternative_child = retry
    else:
        state.preferred_child = retry
        state.alternative_child = follow
```

new_follow_state 把子代接入当前程序路径，清空当前位置的本地重试记录。new_retry_state 保留当前父代与程序路径，并追加此次尝试的状态和成绩。两者均具有新的状态编号。

## 13. 预期作用、计算代价与关键检验

### 13.1 核心研究假设

本机制的研究假设是：对于一部分起点，少量早期非贪婪接续能够找到即时成绩优先开发尚未覆盖的高质量算法；同龄竞赛则为这些接续提供足够的开发机会。

机制直接改变后续调用位置、低分程序的开发机会和生成上下文。对算法思想变化的影响，可通过运行案例进一步分析。

### 13.2 计算代价

一次新状态展开对应一次生成请求和一次候选评价。模型输出格式与普通生成相同，没有额外规划或反思调用。

新增开销来自接续状态、调度和历史记录。每次展开最多产生两个后续状态，状态数量随实际调用数线性增长；源码与历史片段通过引用共享。已有节点的遍历发生在外围，不消耗模型请求。

更丰富的接续搜索会占用原本可用于深挖当前优胜路径的预算。这是本机制的核心资源取舍，需通过最终质量和搜索曲线评价。

### 13.3 正式实验

主比较采用相同任务协议、初始条件、模型采样设置和总请求预算，报告训练搜索曲线及最终独立测试质量。同时报告 token、评价耗时与总运行时间。

最关键的四组实验为：

| 实验组 | 外层分配 | 内层接续 |
| --- | --- | --- |
| 基础组 | 按当前最好质量优先 | 零偏差接续 |
| 同龄组 | 同龄竞赛 | 零偏差接续 |
| LDS 组 | 按当前最好质量优先 | 有限偏差搜索 |
| 完整组 | 同龄竞赛 | 有限偏差搜索 |

四组共用初始化、Diverge、生成提示和评价协议。零偏差版本将 D(H) 设为 0，始终采用首选接续；其他状态与记账保持一致。

再加入一个接续顺序对照：相同深度与偏差上限下，将“早期替代优先”改为“晚期替代优先”。它用于判断效果来自重新考虑早期选择，还是仅来自增加了非贪婪开发。

结合前轮讨论，顺序对照要区分“允许非贪婪开发”与“优先重新考虑早期选择”的作用。除固定外层分配、总请求预算和深度—偏差上限外，还应核对实际替代展开次数及其后续开发长度；若这些量随顺序变化，应一并报告，避免将全部收益单独归因于分岔位置。

### 13.4 运行中记录的机制指标

| 指标 | 计算方式 | 回答的问题 |
| --- | --- | --- |
| 早期替代展开次数 | 统计前两层替代接续获得的新请求 | 早期选择是否真的被重新考虑 |
| 替代接续产出 | 统计含至少一次替代选择的状态所产生的改进 | 非贪婪开发是否产生有用结果 |
| 低分子代后续产出 | 跟踪选择低分子代后产生的有效候选和最好成绩 | 是否发现延迟收益 |
| 原父代另试产出 | 跟踪暂不采用高分子代后产生的结果 | 早期接替是否遮蔽其他机会 |
| 分支深度与重复率 | 记录状态深度、程序深度、源码重复比例 | 是否把预算过多花在浅层重复 |
| 同龄存活与冠军变化 | 读取检查点状态及最佳记录 | 分配是否支持有产出的开发任务 |
| 各类请求与评价成本 | 由日志直接汇总 | 性能收益对应多少真实资源 |

这些指标直接来自控制流和评价记录。脱轨的语义判断另以具体程序案例分析，不由替代边数量代替。

## 14. 学术定位与方法表述

MCTS-AHD 已将树搜索引入自动启发式设计，通过组织已有候选来继续开发暂时较差的程序 [3]。本文进一步聚焦早期接续的搜索顺序：父子比较产生接续分岔，再按照有限偏差规则实际分配调用。

建议将方法概述写为：

我们提出 TraceAAD，一种结合同龄竞赛与有限偏差搜索的 LLM 自动算法设计方法。同龄竞赛按照相近的开发投入比较不同起点的搜索表现，有限偏差搜索则将父子程序之间的接续选择纳入搜索。在优先利用高质量候选的同时，该方法系统性地探索少量偏离即时成绩排序的路径，并优先重新考虑早期接续。路径相关的程序与评价记录进一步指导后续完整算法生成，使有限预算同时支持持续开发与替代路径探索。

英文对应表述：

We propose TraceAAD, an LLM-based algorithm design method that combines age-matched racing with limited discrepancy search. Age-matched racing compares development searches at comparable levels of effort. Within each search, limited discrepancy search treats the choice between continuing from a child and generating another candidate from its parent as a branching decision. The method prioritizes high-quality candidates while systematically exploring paths that depart from immediate-fitness preferences at a small number of decisions, with priority given to early alternatives. Path-specific program histories and evaluation feedback guide subsequent generation of complete algorithms.

本文的设计重点是两层决策的衔接及 LDS 在开放式程序生成中的具体适配。方法来源与预期作用应分别描述；贡献强度最终由机制比较和算法质量结果支撑。

## 附录 D. 本次补充的实现决定

为便于后续讨论追溯，以下列出从上一轮方案到本文详细规格的新增决定：

| 原方案中需要具体化的事项 | 本版决定 |
| --- | --- |
| 树节点表示什么 | 开发状态；完整程序单独保存 |
| 相同偏差数怎样排序 | 优先改变较早接续，使用真实边上的栈式遍历 |
| 深度如何推进 | 从 2 开始，每个窗口结束增加 1 |
| 失败后如何继续 | 只建立父代重试接续，消耗一次请求 |
| 同分如何排序 | 父代优先，源码不同的子代保留为替代 |
| 冠军参考年龄不足 | 标为等待参考，待真实快照形成后比较 |
| 冠军改变后是否重算资格 | 每次完成评价后重新判定，允许恢复 |
| 新起点成本如何计 | 全局预算单列，起点有效后开发年龄从 0 开始 |
| 重新从父代生成时展示什么 | 保留父代与本路径经验；未选候选仅提供简短尝试反馈 |
| 最终选择的范围 | 全部有效程序，不受接续选择或任务暂停影响 |

这些决定构成 v1.0 的完整默认规格。后续更改应同时更新调度、日志定义与实验配置。
