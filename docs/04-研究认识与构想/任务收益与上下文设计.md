# 任务收益与上下文设计

历史信息的价值取决于当前算法需要怎样改进。五任务分析给出四种有用的理解：发现有效骨架、组合互补信号、协调连续修改、校准实际决策边界。上下文可以围绕这些需求组织。

## 五任务带来的启发

| 任务 | 已观察到的优势结构与变化 | 上下文假设 |
|---|---|---|
| TSP | 从 1-Tree、残余路径估计发展到 2-opt、向量化与候选池协调 | 短形成链帮助维持骨架后的连续开发 |
| VRPTW | savings、等待、slack、容量和返仓规则相互协调 | 最近修改及前后结果帮助处理规则间依赖 |
| CVRP-ACO | 距离、Clarke-Wright 节约、极角、容量衰减和车场锚定组合 | 跨分支精英代码提供互补计算 |
| OP-ACO | 奖励、距离、预算可行性与空间结构的收益随规模变化 | 形成链与参考程序的适合比例随状态变化 |
| OBP | 可复用孔洞与容量交互改变选箱排序 | 关键计算与排序变化比抽象思想更直接 |

这些是从已有轨迹提出的任务解释。同一任务也会从骨架发现转向参数协调，因此更有价值的研究对象是当前程序的改进需求。

## 四类改进需要什么信息

**骨架发现。** 当当前路线的计算方式存在瓶颈，模型需要可执行的替代结构、任务约束和运行反馈。给少量有区别的算法骨架，可能比延长同一路径的历史更有效。

**互补组合。** 多个评分信号往往各有盲区。参考程序的完整计算、输入输出和实测质量，可以帮助模型判断哪些信号值得迁入当前程序。Fuse 的关键问题是组合后是否形成连贯决策。

**连续协调。** 已有算法包含相互依赖的阈值、评分项和约束时，形成关系可以说明哪些变化已经配合起来。短历史及最近局部试验有助于保持整体逻辑，并避免重复走过的退步方向。

**边界校准。** 公式变化只有改变排序、采样或可行性，才改变下游决策。OBP 的一个具体例子是把 `residual-myopic` 诊断落实为 `reusable = r >= sz` 和复用加分，从而改变 `argmax`。严格单调变换则可能改了数值而保留全部选择。

## 从固定上下文走向按需组织

可以先用少量可观察状态来选择材料：最近连续退步时给局部试验；结构已经稳定时给短形成链；缺少互补计算时给一个高质量 donor；长期同分时检查实际返回决策。局部失败可能帮助避免重复尝试，成功形成边可能帮助保留已协调的组件，跨分支代码可能提供互补计算。这些作用还只是待区分的解释；还需分清是缺少相关知识、没有检索到，还是模型看到材料后未落实到代码。先在离线状态上比较材料，再决定是否值得引入在线分类器。

一个最小对照是在同一父代、算子和生成模型下，分别提供当前代码、短形成链、局部试验或跨分支参考。记录是否产生不同计算、是否超过父代、在固定后续开发窗口里是否继续改善，以及未见实例上的表现。Refine、Tune、Pivot、Fuse 的动作名称也要对照实际排序、采样或构造决策；尤其需要排除 Tune 只重标定分数、Fuse 只拼接互相覆盖的信号。这样可以区分“材料进入了提示”和“材料帮助了算法设计”。

失败反馈也值得按作用拆开：解析失败先检查接口接受范围，运行失败可尝试一次有界修复，合法退步则保留父子代码差异供后续开发。完整代码与局部编辑、短 Idea 与按需说明可分别做配对比较；离线解析能检验合法候选是否被拒收，但不能替代真实评价来判断算法质量。
