# TraceAAD：贡献主张与机制精炼

> 历史构想：`v1025-trajectories-2` 已废弃。后续实现见[V10.25](../01-搜索方法/轨迹条件化的算法改进-V10.25.md)。

## 1. 从算法设计到 LLM 算法设计，再到 TraceAAD

**算法设计中的改动具有条件依赖。** 同一个语义改动，放进不同计算组合，可能改变可行性、搜索范围、排序强度和时间代价。设评分越低越好，一次可执行改动的收益为：

\[
g(\delta;p)=F(p)-F(\operatorname{Apply}(p,\delta)).
\]

不能把它直接简化成与原程序无关的 `g(δ)`。例如补全一条剩余路径是否有用，取决于路径如何初始化、哪些候选接受补全、如何比较补全结果。一个单独看似无效的部件，也可能是后续改动成立的条件。该式说明收益的定义，不提供可计算的收益预测；执行失败另记错误，不任意转换成质量增益。

**LLM 把读到的材料转化为提案分布。** 固定评价条件下，程序表现由可执行计算决定，不会因为来时路不同而改变。因此不能声称目标函数对同一程序存在“路径依赖”。真正依赖路径的是设计者掌握的信息，以及冻结 LLM 在不同上下文下提出什么代码。

**TraceAAD 的切入点，是向模型提供可核对的变换条件。** 当前源码提供结果状态，真实父子差异提供改了什么，两端评价与错误提供这个整体改动发生后怎样。形成路径把这些材料接起来，使模型有机会解释连续变化和依赖。它不自动构成因果识别，更不是已经学到的长期价值函数。

当时从以下案例提出了“计算积累”这一候选方向，它不构成当前主线：TSP 的完整路径补全与 2-opt 需要共同发挥作用；CVRP 的最后一处权重修正建立在已有几何容量组合上；修复也可能删除新计算。固定父代实验支持形成历史有生成价值，但完整搜索的收益不一致。因此最值得研究的问题是：**保留变换发生的程序条件，何时能帮助下一次改进，何时反而把生成限制在旧做法中？**

## 2. 与最近工作的真实关系

| 工作 | 实际做法 | 对我们主张的约束 |
| --- | --- | --- |
| ReEvo | 比较两个程序的表现，生成短期反思，并累积长期反思用于交叉和变异 | “用经验指导生成”已经存在。[原文 §4](https://arxiv.org/html/2402.01145v3) |
| DeltaEvolve | 将语义修改组织成多层记录，与代码一同生成；选择精英及差异来源，按层次展示历史 | “从程序转向修改记录”也已存在。它使用语义 delta，我们当前核心材料由宿主从实际源码计算。[原文 §4](https://arxiv.org/html/2602.02919v1) |
| PathWise | 推导图保存代码、描述、来源与表现；policy、生成器和 critic 共同推进 | “状态化路径规划”和“记录来源”不能直接算我们的新贡献。[原文 §2–3](https://arxiv.org/html/2601.20539v1) |
| PhyloEvolve | 用树组织修改及奖励，读取演化路径，并通过代理与精英记忆复用 | “沿完整谱系学习怎样改进”已有直接先例。[原文 §4](https://arxiv.org/html/2601.14523v1) |

相对这些具体设计，TraceAAD 当前值得检验的差异是：**直接使用实际代码变化与对应评价，沿当前程序的形成关系组织材料；区分作者解释与实际变化；按当前操作决定是否需要形成历史。** 它采用一次候选生成与真实反馈的循环，不要求另外调用规划器、反思器或摘要器。

这组差异定义了一个可检验的方法，尚不能仅凭定义宣布算法创新已被证明。尤其不能把“原始 diff 比语义摘要一定更好”当作前提；原始记录更可核对，却也更长，可能包含大量无关实现细节。

## 3. Contribution 应如何收束

建议围绕一个核心主张组织论文：

> TraceAAD 研究如何把实际程序变换及其评价条件保留在生成上下文中，使多轮算法改进能够积累；方法用真实形成轨迹支持精炼和迁移，并为结构探索保留不受形成链示范约束的入口。

可以用三条相互支撑的内容展开，而不是列三套独立新算法：

1. **认识**：刻画历史在算法设计中的双重作用——帮助解释和保留已有计算，也可能强化已有改法。单步成绩、算法思想、修改关系需要区分。已有材料支持提出这一认识；算子间的稳定差异仍需直接证据。
2. **方法**：以宿主生成的代码差异、明确来源和完整评价事件构造形成上下文；保留退步与修复变化，按精炼、替换、迁移和修错分别提供材料。形成记录与代码交付共用唯一、明确的程序来源。
3. **实证**：在相同生成与评价条件下检验这些关系信息是否改变实际代码、能否累积收益，并用固定预算的冻结测试衡量全局效果。这是待完成的论证，不把测试通过或旧版本成绩写成新结果。

不把以下内容拆成贡献：三个算子的名字、倒数排名公式、`1/8 × 3` 续写、原子 SEARCH/REPLACE、保存全部档案。这些是实现主张所需的运行设计或已有技术。

## 4. 公式精炼：一条选父规则即可

上一稿的 softmax 用温度拟合 `ESS≈0.1N`。它确实控制集中度，但不能由此推导“弱首版拥有实际开发机会”。性质检查中，八个分数 `[0,0,0,1,2,3,4,5]` 的 ESS 为 3，最差程序的概率约 1.8×10⁻⁷⁹。这个例子暴露的是我们对 ESS 的解释过强，不是评价程序存在错误。

候选选择公式：

\[
P(i)=\frac{1/r_i}{\sum_j1/r_j},\qquad
r_i=\frac{a_i+b_i}{2}.
\]

`[a_i,b_i]` 是并列程序占据的名次区间，没有并列时为通常名次。这样同分同权，任意保序分数变换不改概率；无并列时首尾概率比为 N。上面的八程序例子中，末位概率约为 0.0524。100 个不同名次的末位概率约为 0.00193。

这条规则去掉了质量归一化、ESS 目标、并列下界和在线温度求解。它仍有明确选择偏好：固定采用倒数排名，而不是说不存在设计选择。它忽略绝对成绩差，不能识别行为重复或开发潜力；尾部机会也不是最优预算分配的证明。是否比首版 ESS 更有效，要靠搜索比较。

不再增加任何 `质量 + 祖先增益 + 新颖度 + 不确定性 − 成本` 的综合分数。各项尺度、信用对象和未来收益尚未校准，拼接公式只会隐藏这些未知量。

## 5. 参数只保留有明确职责的部分

| 项目 | 当前决定 | 理由与解释边界 |
| --- | --- | --- |
| 质量选择 | 固定倒数排名，同分平均名次 | 不再拟合温度；不是潜力模型 |
| 普通 Refine / Explore / Crossover | 保留 0.45 / 0.30 / 0.25 | 控制三类提案的份额；沿用已有配置，没有最优比例证据，不为数字整齐而改动 |
| 续写概率 q | 保留 1/8 | 控制多少新 Explore 得到短程机会，不按首版质量决定 |
| 续写步数 h | 保留 3 | 控制被选中的探索连续改写多深；与 q 不是同一个作用，不能只用 qh 代替二者 |
| 形成历史 H | 保留 8 个事件组 | 已有历史长度起点；Crossover 两边分享 H，默认 4+4，不另设第二组独立长度 |
| Explore 历史 | 不显示形成链 | 防止用整段调参轨迹示范结构替换；这是待检验的操作配合，不宣称探索不需要任何经验 |
| Repair 历史 | 产生失败的最新事件组 | 修复的直接对象已经给定，不需要八步路径来重新规划 |
| 当前代码的其他尝试 | 保留最近 2 次 | 避免重复交付或重做同状态尝试；真实差异与错误单独标明，不能混成形成链 |
| 根数、初始化上限 | 保留 8 / 16 | 沿用实验入口，当前没有改变初始化预算的依据 |
| 上下文与输出上限、最终候选数 | 保留协议与既有值 | 属于执行约束和冻结条件，不解释为研究创新 |
| Crossover 参考筛选 | 沿用质量中位数与代码相似度规则 | 本轮聚焦历史表示与操作配合；代码差异不等于思想差异，先看实际迁移，再决定是否值得动这条支撑规则 |

无失败、无修复且所有 Explore 有效时，普通步骤对应的期望续写数为 `0.30×(1/8)×3=0.1125`，占总生成约 10.1%。这只是简化条件下的成本解释；实际有修复和无效提案，不能把它当成 10% 的硬预算保证。

奥卡姆剃刀不是把所有数字改成 1 或把三类操作合成一句“请改进”。要删除的是没有明确职责或未获得依据的自由度；有不同作用的控制量可以保留，但不把默认值说成理论结论。

## 6. 上下文与算子一起定义提案

| 操作 | 需要解决的决定 | 上下文 |
| --- | --- | --- |
| Refine | 现有计算里哪些部分应保留，哪些部分一起修改 | 当前完整代码 + 形成轨迹 + 同起点近期尝试 |
| Explore | 当前的重要决策计算可以怎样替换 | 当前完整代码 + 同起点近期尝试；不显示形成链 |
| Crossover | 参考中的哪段计算可以适配到当前程序 | 两份代码 + 两边各自的形成轨迹 + 当前程序近期尝试 |
| Repair | 当前失败由什么改动造成，怎样保持意图修好 | 失败完整代码 + 错误 + 最近形成事件 |

所有材料都来自当前时刻的档案。Refine 的历史包含实际退步，失败和修复分开展示；Crossover 的来源互不混淆。Design 保留为作者描述，不把它改名成“已验证知识”。

目标句：

**Refine**

```text
Improve the bound algorithm within its current approach. Use the observed changes to choose
what to revise and what to retain. Apply connected changes together.
```

**Explore**

```text
Replace an important decision computation in the bound algorithm, beyond adjusting its parameters.
Implement the replacement and any connected changes, retaining useful parts it does not replace.
```

**Crossover**

```text
Improve the bound algorithm by adapting a computation from the reference algorithm.
Use the available code and observed changes to identify its required dependencies and how it
fits the bound algorithm. Do not copy the reference wholesale.
```

**Repair**

```text
Fix the bound program's execution failure. Use the error and the change that produced it.
Preserve the intended computation where possible; explain any necessary replacement in Analysis.
```

删去了“回顾轨迹以证明某个部件有贡献”“首版不必胜全局最好”等反复说理。目标句规定做哪类计算修改，Analysis 用几句说明本轮选择；交付契约单独规定 edit 或 Code。差异初始化也删除了“立即胜过全部已有根”的额外要求。

继续保留完整编辑基底及原子应用。语义上想保留什么是模型的决定；未编辑源码保持不变是宿主能够兑现的性质。两者不能混成“已经保证算法思想继承”。

## 7. 什么证据最能改变判断

第一项主检验固定父代、操作和当时可见的历史事件，比较无历史、这些事件的语义摘要、实际形成差异。摘要须忠实，不人为去掉对照臂必要的任务信息。比较实际代码修改、首版及等总预算续写后的收益，并单独记录 token 开销。这样才能判断原始关系信息是否比总结经验提供增量，不能只凭模型措辞判定它“理解了依赖”。

第二项直接检查本次按算子配材料的判断：相同 Explore 起点有无形成链，是否改变结构替换及后续收益。若去掉历史只增加失败或无用重写，应修正 Explore 的材料，而非坚持“探索必须无历史”的先验。

随后用相同候选预算、模型与冻结测试比较整体方法。完整版本胜出不能单独证明排名选择、三步开发或原始 diff 各自有效。相反，如果轨迹的关系信息没有增量，就应收缩主张，不再靠增加高层模块维持故事。
