# 生成上下文：决策相关的历史证据

## 核心判断

生成上下文的作用不是提供尽可能完整的搜索档案，而是让模型在一次具体修改中看到能够改变决策的证据。上下文应由当前程序、设计操作和任务收益形成结构共同决定。

## 三类有效证据

### 形成关系

形成轨迹记录当前程序如何从父代演化而来，包括最近修改、算子、Idea 和评价变化。它适合已经出现有效骨架、需要继续协调多个机制的候选。TSP 的残余路径估计、2-opt、候选池和计算成本协调，以及 VRPTW 的 savings、等待、slack、容量和返仓规则，都体现了形成关系的连续价值。

### 跨分支机制

档案参考提供当前谱系之外的计算视角。它适合当前候选缺少互补信号，或任务收益来自多个机制组合的场景。CVRP-ACO 中距离、节约、极角、容量衰减和车场锚定的算法族传播，说明档案的关键价值是可执行机制进入新代码。

### 行为与边界

当任务收益由排序、采样或可行性边界决定时，应该展示代码变化和行为变化。OBP 的 `residual-myopic` 诊断进入 `reusable = r >= sz` 逻辑后改变箱子选择 `argmax`，说明行为证据能够把 Idea 连接到真实算法差异。

## 算子与上下文

| 算子 | 设计意图 | 优先证据 |
|---|---|---|
| Pivot | 寻找替代结构或新的决策边界 | 多样化骨架、当前路线的限制、行为变化 |
| Fuse | 组合当前程序与跨分支机制 | 代表程序、互补计算、实测质量 |
| Refine | 保持骨架并协调组件 | 形成关系、最近修改、前后评价 |
| Tune | 校准公式、阈值和参数 | 局部代码、排序变化、行为反馈 |

算子名称表达生成意图，不能决定上下文内容。任务和算法状态决定参考证据来自形成链、档案还是行为摘要。

## 最小上下文骨架

每次生成至少需要：任务契约、当前程序、当前操作和明确的输出契约。根据设计意图追加一种主要证据：

- 连续协调：最近形成关系与评价增量；
- 互补组合：少量跨分支代表代码与机制摘要；
- 边界校准：影响排序或可行性的局部代码和行为信号；
- 替代结构：不同骨架及其运行约束。

证据按决策相关性排序，保留足够解释机制的内容即可。更长的历史只有在它改变当前设计选择时才值得进入提示。

## 机制评价

上下文实验必须同时观察生成质量和搜索质量。固定当前程序、任务和算子，对比无历史、随机历史、匹配形成历史和跨分支档案；再检查代码是否实现参考机制、下游决策是否改变、候选是否超过父代、是否获得持续开发，以及 held-out 结果是否保持收益。

解析率、Idea 长度和代码相似度可作为生成诊断，但不能替代算法质量。上下文只有在实际设计行为和真实评价中产生增量，才构成方法机制。
