# V10.24 的设计取舍

首版采用计划准入、分槽预算和前沿续投。后续实现改为共同开发资格与单一预算池。

| 问题 | 实现选择 |
| --- | --- |
| 首版分数不足以判断后续开发价值 | Refine、Crossover、Explore 均可获得最多两段开发 |
| 文本计划不证明预算价值 | 新开与续投交替，不使用 Plan 授权或预留 |
| 已有源码仍可能是有效回退 | 缓存复用评价，有效结果更新工作版；新发现另计 |
| 失败与修复不能抹掉开发对象 | 保存失败源码、真实差异和全部尝试 |
| 历史完整保存不等于完整复读 | 保留完整编辑基底，按决策用途选取证据 |
| 相同成绩不应因标识获得不同机会 | 同分质量同权，边界并列保留 |

## 待检验的问题

共同开发能否补偿独立提出数量的减少？历史材料能否帮助模型修正具体计算？这些问题用固定预算的完整搜索和同状态开发对照回答，代码正确性检查不代替效果检验。
