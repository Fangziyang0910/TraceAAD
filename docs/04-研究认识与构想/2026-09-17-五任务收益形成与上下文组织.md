# 五任务收益形成与上下文组织

## 核心认识

自动算法设计中的高质量收益不是由单一搜索动作产生，而是由任务特定的发现、组合、协调和边界校准共同形成。TraceAAD V10.11 四组对照和 V11.0 五任务实验表明：历史上下文的价值取决于当前算法需要完成哪一种改进。

因此，历史组织的目标不是增加记忆量，而是把与当前设计决策相关的证据放在模型面前。短形成轨迹、跨分支精英档案、完整代码和行为摘要分别服务于不同的收益形成方式。

## 五任务对应关系

| 任务 | 优势算法的形成方式 | 主要改进模式 | 优先上下文 |
|---|---|---|---|
| TSP | 从基础构造骨架发展到残余路径估计，再协调 2-opt、候选池和计算成本 | 骨架发现、连续协调、参数校准 | 短形成轨迹 |
| VRPTW | 协调 savings、等待、slack、容量和返仓判定 | 互补组合、连续协调 | 短形成轨迹与最近变化 |
| CVRP-ACO | 组合距离、节约、极角、容量衰减和车场锚定信号 | 互补组合、精炼和精英传播 | 跨分支高质量档案 |
| OP-ACO | 组合奖励、距离、预算可行性与空间结构并按规模校准 | 互补组合、参数校准 | 形成历史与精英档案的受控组合 |
| OBP | 通过可复用孔洞和容量交互改变箱子选择排序 | 决策边界塑形、骨架替换 | 行为摘要、排序变化和可执行机制 |

这张表给出上下文组织的研究假设，也给出机制验证的自变量。它不是固定的任务标签：同一任务在不同阶段可以从骨架发现转向连续协调，搜索系统需要识别当前改进需求。

## 四类收益形成机制

### 有效实现骨架

在搜索初期或低效路线中，收益来自改变数据结构、控制流程或核心求解方式。此时上下文应提供多样化算法骨架、运行约束和可继续开发的机制线索，帮助模型摆脱局部实现的固定形式。

### 互补信号组合

单一启发式指标会形成评价盲区。收益来自从不同候选中提取互补计算并形成综合决策。此时跨分支代表算法和实际代码机制比单条祖先链更有价值。

### 连续协调改进

当算法已经拥有有效骨架，收益来自多个相互依赖的评分项、阈值和约束之间的协调。形成关系、最近修改和前后评价变化能够说明当前结构怎样演变，并帮助模型保持整体机制而推进局部改进。

### 决策边界校准

局部公式变化只有在改变下游排序、采样或可行性时才产生算法差异。例如 `argmax` 下的严格单调变换不改变选择，容量与物品尺寸交互或候选间差分项才会改变实际边界。此时最有价值的上下文是代码变化与行为变化，而不是更长的解释文本。

## V10.11 对照的机制证据

### TSP：形成关系支持骨架后的持续开发

优势谱系呈现出“1-Tree → 残余路径估计 → 2-opt → 向量化 → 候选池和参数协调”的连续链条。短形成轨迹把这些已经验证的决策变化呈现给后续生成，使模型能够围绕高阶骨架继续改进。

### VRPTW：形成历史维持多规则协调

优势程序持续组合并协调 savings、时间窗、剩余容量和返仓逻辑。短形成轨迹在训练预算点和 held-out 规模上保持优势，说明其主要作用是维持跨组件的协调关系。

### CVRP-ACO：档案传播高质量算法族

高质量程序集中包含距离矩阵、Clarke-Wright 节约值、极角连续性、容量衰减和车场锚定。跨分支档案把这些机制带到新的父代，形成精英算法族的传播、比较和参数精炼。这里的关键是高质量机制的可执行传播，而不是档案规模本身。

### OP-ACO：上下文价值随规模变化

完整代码轨迹在训练后段支持继续改善，held-out 优势随规模分化。该现象把 OP 定位为上下文敏感任务：形成历史提供连续改进线索，跨分支参考提供替代机制，两者的比例需要由规模和当前状态决定。

### OBP：思想进入代码并改变排序

档案中的 `residual-myopic` 诊断在新节点中落实为 `reusable = r >= sz` 与强复用加分，改变了箱子选择的 `argmax` 边界。这个个例与跨重复结果共同说明：参考上下文的价值由可执行机制和真实决策变化决定。

## 任务条件化的上下文映射

| 当前设计需求 | 需要回答的问题 | 组织证据 |
|---|---|---|
| 延续和协调 | 当前结构如何形成，哪些改动已经改变整体行为 | 形成关系、最近修改、评价变化 |
| 引入互补机制 | 哪个跨分支候选提供了当前缺失的计算信号 | 代表代码、机制摘要、实测质量 |
| 校准公式和参数 | 变化是否真正改变排序或采样 | 局部代码、行为探针、相邻候选 |
| 寻找替代实现 | 当前路线有哪些可执行的不同骨架 | 多样化骨架、约束、运行结果 |
| 开发新方向 | 新结构是否获得连续修改机会并兑现收益 | 形成来源、后续开发、累积结果 |

## 机制成功的判定链

历史上下文只有在以下链条闭合时才构成机制证据：

1. 相关证据进入当前提示；
2. 生成代码实现对应机制；
3. 机制改变下游决策；
4. 候选超过父代或参考程序；
5. 候选获得后续开发或在 held-out 实例上保持收益。

这一判定链把“发现—融合—精炼”从叙事标签转化为可观测事件。Idea 说明设计意图，代码展示实现事实，评测结果衡量算法质量，三者需要在同一证据链中连接。

## 研究结论

五任务实验支持一个明确的设计原则：**上下文应服务于当前收益形成机制。** 短轨迹擅长维持协调，精英档案擅长传播互补机制，行为证据擅长确认决策边界变化。TraceAAD 的后续方法应从任务和算法状态诊断改进需求，再选择历史证据，而不是把全档案、完整代码或固定轨迹作为普适模板。
