# 从搜索经验到模型学习

搜索经验可以同时改善即时上下文和生成器参数。TraceAAD 可以并行推进固定模型的搜索研究与离线生成器训练，先分别测量收益，再研究两者怎样配合。

## 学习什么

第一阶段训练条件改写策略：`πθ(code | current code, operator, structured experience)`。经验包括形成关系、代码差分、执行失败、前后质量和后续开发结果。控制器继续选择父代与算子，模型学习在给定状态下提出更有价值的候选。

相比模仿全局 best，这种学习保留了“从哪里改起、为什么这样改”的条件。它可能提高可执行率、父代改进率和跨状态的改写能力；外部记忆和参数学习也由此可以放在同一个问题下比较：哪些经验值得反复读取，哪些值得固化。

## 第一轮：固定搜索器的离线训练

| 组别 | 训练材料 | 回答的问题 |
|---|---|---|
| Base | 原始生成模型 | 基线 |
| DPO-generic | 程序质量与可执行性构成的一般偏好对 | 一般任务适配有多少收益 |
| DPO-structured | 同状态、同父代与同算子下的条件偏好对 | 结构化改进经验增加什么能力 |

从已完成搜索中整理几百到几千个偏好对，优先覆盖 TSP、CVRP、OBP 和 VRPTW。每条样本保存任务契约、父代、算子、上下文、候选、解析与运行状态、真实质量、代码变化及已有的后续结果。训练/验证/测试按程序族和状态集合隔离，held-out 实例独立保留。

组内比较保持父代和算子一致。Refine 与 Pivot 的即时质量分布不同，分别成组更容易保留各自目标；对暂时退步但后续有收益的候选，可先单列样本，比较即时标签与固定窗口标签。解析失败、运行失败、重复程序和合法退步分别记录，便于分析模型学到了什么。

检查同状态候选收益、可执行率、行为变化、后续窗口收益和 held-out，同时记录训练与推理成本。在至少两个任务、两个未见状态集合上同时改善候选收益和 held-out，才扩大训练规模；只改善可执行率就把结果定位为接口适配；仅在相邻程序族上改善则先处理数据与泛化问题。

## 第二条线：固定模型研究搜索

使用相同上下文比较质量抽样、高分集中开发和带最低探索配额的分配。观察 E100/E250/E500/E750/E1000 前沿、路线覆盖、新结构首次开发延迟、父代收益和重复间方差。任务、种子、评价上限和 held-out 沿用既有协议。

两条线出现独立增量后，做 `Base/Fine-tuned × Base search/Improved search` 四组实验。观察微调是否提高探索候选的可开发性，以及新的机会分配是否缓解生成模式集中。

## 在线学习放在后续

离线实验先确定数据单位和收益定义，再比较在线更新与固定模型。在线 rollout 的评价与搜索评价共同消耗总评价预算；GPU 训练时间与推理时间另外记录。例如每 50 步搜索追加 8 个状态、每状态 4 次评价，1000 步搜索将额外产生 640 次训练评价。

下一步先整理可用状态与程序族划分，估算能构成多少同条件偏好对，再据覆盖情况确定训练规模、重复数和停止条件。相关方法及其分工见[搜索经验与模型学习](../05-相关工作/搜索经验与模型学习.md)。
