# 当前问题与认识：LLM 怎样改进算法

TraceAAD 优先理解 LLM 怎样进行算法改进，再据此设计更有效的方法。我们研究提示中的信息与目标如何改变模型的选择，生成代码怎样改变计算，以及这些改动为什么有效或失败。完整搜索提供真实轨迹，局部对照帮助区分解释。当前最值得辨清的是：少量继续改写的收益究竟怎样产生，模型读到试验结果后又改变了什么。

## 已经看清的现象

**强结果依靠具体的计算结构。** 所分析的任务与搜索方法中，TSP 在逐步选点接口内部构造并优化剩余路径；CVRP 持续协调几何与容量规则；OBP 通过保结构的数值修改与新项注入改进；VRPTW 经跨程序迁移获得前瞻，再修正局部评价。接口、生成方式和搜索方法共同决定了这些开发过程。[形成路径](../03-现象与检验/2026-09-09-强结果形成路径.md)

**形成历史与代码前分析提供两种帮助。** 固定父代的历史配对中，72 个锚点有 58 个平均改写表现更好。格式实验则发现，简短而针对当前修改的 Analysis 改善 Refine，Design 的长度影响较小。前者提供过去的改动与结果，后者帮助模型作出本次决策；完整搜索中的收益随任务变化。[历史对照](../03-现象与检验/2026-08-21-父代形成历史.md)、[格式配对](../03-现象与检验/2026-10-01-写代码前的决策与Design格式.md)

**后期超时与时间、质量的权衡相关。** 加入尝试经验后，TSP 从接近时限的父代出发少了一半（483 对 940 次），总超时率随之下降。同类父代上的子代超时率大体接近。减少候选或搜索遍数能提速，但常使质量变差；需要解释的是计算怎样产生质量收益。

加入逐行耗时剖析的配对重放也没有提高改进率：在时限内超过父代的比例为 9.3% 对 7.4%，配对差为 −2.0 个百分点，95% 区间为 −7.8 到 +2.9。模型更多提到提速，实际仍主要减少候选和搜索遍数。这使我把重点从补充代价信息转向模型能够提出并实现哪些计算方式。[耗时剖析重放](../../experiments/diagnosis_v1016_profile/README.md)

**初次生成的成绩与继续改写后的成绩相差明显。** 同等开发实验给十路搜索的最好程序及每路两个后期 Explore 程序各 12 次 Refine；后者按与最好程序的代码相似度 ≤0.5 选取。20 组中 17 组改善，中位数 +1.44%；多数从落后 1%–25% 追到约 1%，主要改进发生在前 3–5 次生成。2 组在训练上超过原最好程序。改写让这些程序达到更高质量，收益可能来自保留新计算、修正实现或吸收已有程序的部件。[同等开发](../../experiments/diagnosis_v1016_develop/README.md)

**开发机会本身影响我们能得到什么证据。** 按当前分数选择起点，容易让较弱的首版没有机会修正。V10.17 的 CVRP 第 3 路提供了一个具体例子：首版构造忽略容量的最近邻回路，首次短程改写补上容量可行路线，分数从 9.9977 到 9.2848，之后持续开发到 8.4076。当前机制已有持续精炼的能力，但新计算进入这个过程仍依赖首版质量或随机短程机会。下一步考虑让一次探索拥有连续的开发记录与初步机会，再根据实际进展决定投入；同时检查新计算是否保留，避免把恢复旧程序误读为新设计成熟。[开发机制与同日讨论](2026-10-04-算法改进机制与开发闭环.md)

**改动要在它所针对的原算法上检验。** V10.18 让每个新设计从首版开始单独开发，开发看不到原程序，只与自己的上一版比较。首版落后于原程序的探索，3 步内超过原程序的只有 4.6%；V10.17 的改写能看到原程序，为 21.6%，但多数是回到原程序再调参数。Explore 首版与原程序的代码相似度中位数只有 0.62，首版分数混合了想法的价值与丢掉的成熟细节。V10.19 把 Explore 当作对原算法的受控改动：保留不替换的部分，在原程序可见的上下文中开发至多 3 步，以超过原程序为成立标准。[诊断](../03-现象与检验/2026-10-06-新设计开发诊断与改动检验.md)、[规则](../01-搜索方法/对原算法的改动检验.md)

## 当前要辨清什么

**少量继续改写的收益怎样产生？** 从已有同等开发样本入手，沿代码改动检查最初计算的保留、实现错误的修正、旧部件的重新加入和关键计算的替换。结合执行行为与逐步评价，定位每次改善解决了什么限制，以及质量何时趋稳。

**展示试验结果后，模型改变了什么？** 比较同一程序在不同信息条件下的修改：是否识别了已有失败，是否改变计算方式，还是只减少候选和遍数。形成历史、尝试记录和耗时信息服务的决定可能不同，需要结合实际改动解释。代码前分析的配对也提示我们，信息供后续读取与本次作出修改决定是两个不同作用。

理解这些变化之后，再问它们能否帮助判断继续投入。最好程序的形成路径提供线索，还要比较决策当时具有相似信号、后来停滞的程序，以及把同样预算用于其他程序的收益。

同一套正增益续投规则的对照中，CVRP 的收益最一致，TSP 训练侧与 OP 的结果随重复变化。近期改善、排名、连续失败和结构变化，可能在不同计算过程中表达不同信息。先按任务、计算结构与已有开发检查这些关系，再判断哪些认识可以共享。[续投对照](../03-现象与检验/2026-08-24-自适应调度.md)

眼下先使用同等开发已有的逐步记录，对照初次程序、首个明显改善、开发后的最好程序及无改善样本。逐处说明改动怎样影响计算与结果。若收益主要来自实现修复，下一步区分修复提示与开放改写；若来自吸收旧部件，检查参考材料的作用；若保留了新计算并持续改善，再检验相同材料下继续改写与独立提出的收益。按最影响解释的差异选择局部对照，完整搜索随后检查连续生成中的效果。

LLM 也可以依据当前代码、限制与尝试结果，决定精炼、换结构或借用其他程序。值得观察的是它识别了什么具体问题、选择了什么计算改动，以及这些选择的后续收益。简单选择规则与 LLM 判断都围绕同一个问题比较：有限预算用在哪里更有价值。

路线和思想可以帮助概括这些过程。一次生成可能保留多个程序的部件，也可能在同一形成链上替换关键计算。研究结论应具体落到这些变化，概括方式由当前问题决定。

## 怎样记录进展

研究主线按问题、证据与认识变化组织。进展应写清哪个解释改变了、哪个变量起作用、发现了什么限制，以及这如何影响下一步。辨清一种失败原因或撤回一个解释，也能推动研究。方法说明保存实际规则，实验记录说明对照与结果，实现标识用于定位代码。一次整体原型比较回答整套配置的表现；针对关键解释的实验回答变化来自哪里。下一次研究从当前未知量继续。
