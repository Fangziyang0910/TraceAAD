# 研究目标与当前问题

更新于2026-10-14。

**有效利用搜索过程中获得的经验，发现有优势的算法思想，持续精炼其实现，并促进不同算法思想的融合，最终找到更好的算法。**

这一目标不能缩成判断某个改动是否值得继续投入。LLM 描述的算法改动与实际代码改动可能不一致。程序成绩（fitness）反馈的是具体代码在给定实例和评价条件下的表现，不直接代表算法思想的表现或潜力。讨论方法时，分别说明研究目标、具体问题与已有机制的作用，不把目标当成已经实现的能力。介绍机制时逐步说明为什么这样做、实际怎样做。

一次搜索不仅产生算法，也产生关于怎样设计和改进算法的过程经验。TraceAAD研究如何让算法搜索利用自己走过的路。

## 搜索轨迹是什么

搜索轨迹是多轮算法设计的过程：尝试发生的顺序、程序的来源与参考关系、评价和失败、机会分配、持续开发、停止与转向。成功、停滞、失败和未被采用的尝试共同构成搜索过程。

| 视角 | 关心什么 |
| --- | --- |
| 搜索时间线（Search History） | 整场搜索先后尝试了什么，何时改进、失败或停滞，投入与最好成绩怎样变化。 |
| 算法演化路径（Evolution Path） | 程序从哪里来，经历了哪些修改，不同程序之间有哪些生成与参考关系。 |
| 探索与竞争过程（Search Dynamics） | 哪些程序或路线获得机会，何时继续、停止或转向，哪些方向尚未充分尝试。 |

这是理解同一搜索过程的三个角度。程序来源不能直接代表算法类别。同一初始程序可以发展出不同计算，不同初始程序也可以发展出同类算法。

这里的搜索轨迹不同于LLM单次生成中的推理文本，也不同于算法在一个实例上的求解轨迹。后两者可以帮助解释搜索中的具体尝试，但不代替多轮搜索过程。

## 当前要辨清的问题

**搜索已经走过的路，能给后续决定提供什么当前程序本身没有表达的信息？** 从整场搜索出发，先看哪些经验已有记录、实际用了哪些，以及它们影响了什么决定。

- 搜索为什么持续沿某些路线发展，另一些路线停止？过去的投入和响应能否帮助判断下一步在哪里搜索？
- 哪些探索经历值得影响其他程序的生成或参考选择？它们的适用条件与来源关系是什么？
- 轨迹以什么方式进入修改、起点、算子、参考、续投、停止或转向，怎样改变后续搜索过程？

这些是开放问题，当前工作只需推进其中最影响判断的一项。

**当前实现：** [V12.1](../01-搜索方法/设计核验-V12.1.md)在 Explore 提出设计后，匹配同一主要计算的已有程序供实现参考。生成输出解析成功后创建独立的 `Program` 个体，保存分析、设计、代码、来源和实测结果。代码检查判断是否实现设计、是否保留起点中未被替换的计算；指出缺失且程序未优于起点时，按规则补写。检查结果还影响后续设计匹配与提示中的描述。程序不按源码合并，相同代码也独立评价。检查准确性、补写对后续改进及最终成绩的作用，需要分别检验。具体记录与用途见[轨迹索引](../01-搜索方法/搜索轨迹的记录与使用.md)。

## 怎样选择下一次检验

先确定轨迹中的具体问题与要改善的决定，再选择观察范围。固定父代对照适合隔离生成材料的作用。多步窗口适合观察继续投入的后续响应。完整搜索适合检验机会分配和固定预算的最终收益。局部对照、轨迹回放和完整搜索按当前问题使用，不预先固定为一种检验。

成功路径用于解释结果如何形成，同时查看同类失败、停滞和未获机会的尝试。单次超父、恢复幅度和最终搜索收益分别回答不同问题。调参、修复、恢复、重用、组合和重新设计都按后续结果与成本判断。探索的价值不由改动大小预定。
