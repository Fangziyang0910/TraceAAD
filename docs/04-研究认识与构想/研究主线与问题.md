# 研究目标与当前问题

更新于 2026-10-11。

**利用自动算法设计搜索中获得的轨迹与反馈经验，改善后续决策，提高有限预算下发现和改进优质算法的效率。**

轨迹是经验的来源和组织方式，反馈是其中的内容，后续决策是用途。代码改动、评价结果、失败与修复、重复尝试和投入成本，都可能提供经验。经验如何表示、选择和进入决定，是需要检验的问题。

## 当前最值得辨清的问题

**已有搜索经验怎样改变下一步决定，并带来可用的收益？** 先明确要改进的决定，以及决策当时可见的材料。例如，同一程序和评价条件下，提供相关历史是否改变下一次生成；同一剩余预算下，尝试反馈是否帮助选择起点或决定续投。

下一次检验应固定一个决策对象，比较使用相关经验与不使用、或使用另一种组织方式的结果。先核对实际选择和代码，再评价质量、有效性与成本。若决定改变而收益没有改善，下一步应查经验的解释和用途；若决定没有改变，应查材料是否被读懂和使用。检验对象随当前问题选择，不预设必须通过真实 diff、计算保留、增加模拟或特定开发流程实现。

## 工作底座与实验身份

原V10.17是此前选择保留的工作底座，不是已确定的最优机制或最终论文版本。V10.24完整搜索、V10.25停止批次及其他旧本地模型结果均作为历史材料查阅。实际批次和执行入口见[实验入口](../../experiments/README.md)，不在这里维护实时状态。

[当前规范](../08-实验规范与共识/README.md)约束新实验。历史比较须绑定批次、源码、模型、任务接口、数据、计分方向、预算和终选方式。未知项明确留空；不能因新版基线修复而自动更新旧成绩，也不能把历史结果整体作废。
