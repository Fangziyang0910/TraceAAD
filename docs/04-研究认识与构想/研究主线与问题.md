# 研究主线：利用已有试验改进算法搜索

TraceAAD 研究如何利用已经做过的算法试验，在有限预算下找到更好的算法。每次搜索都要决定两件事：下一次怎样写算法，以及把这次尝试用在哪个已有程序上。过去的代码、修改和评价结果，能否帮助做好这两个决定，是本项目要回答的问题。

## 一、希望从已有试验中学到什么

**帮助生成更好的算法。** 模型看到当前程序是怎样改出来的、哪些尝试效果较好，能否据此保留有效部分、避免重复失败，或者从其他程序中找到可用的方法？这里关心的是，提供这些信息后，模型实际写出的算法是否更好。

**帮助安排后续尝试。** 搜索预算有限，继续修改一个程序，就少了一次尝试其他程序的机会。除了当前成绩，过去的开发结果能否帮助判断下一次应继续改哪个程序，或者转向其他程序？这里关心的是，同样的预算能否找到更好的结果。

两个问题并重，但需要分别检查。历史材料有助于改写，不代表它也能帮助选择开发对象；一种选择规则有效，也不代表模型已经用好了历史。最终要比较的是，在相同预算下找到的算法在独立测试中表现如何，同时考虑生成、评价和算法运行的成本。

## 二、已有试验带来的认识

[强结果的形成过程](../03-机制探索与验证/2026-09-09-强结果形成路径.md)表明，算法改进可以有不同来源。TSP 的关键变化是在选点函数内构造并优化剩余路径，CVRP 的进展更多来自持续调整已有规则。这些例子提示，尝试不同计算方法和继续改进已有方法都可能有价值。不过，这些成功案例还不能告诉我们，应当怎样提前选择或分配尝试；TSP 的改进还增加了算法运行时的计算量。

在生成方面，历史材料已有一些正向证据。在[V9.8 的配对研究](../01-主线机制设计/V1-V9.13-搜索单位与形成历史.md)的 72 个固定起点中，有 58 个在提供形成历史后，平均改写表现更好。但[完整搜索对照](../03-机制探索与验证/2026-08-21-父代形成历史.md)存在任务差异。这说明历史值得研究，怎样提供、模型怎样使用，以及局部改进能否积累成最终收益，仍需确认。

在安排尝试方面，已有结果同样依赖条件。[自适应延长开发](../03-机制探索与验证/2026-08-24-自适应调度.md)在 CVRP 上表现较好，其他任务和设置的结果并不一致。[Pivot 两步实验](../03-机制探索与验证/2026-09-07-Pivot两步价值.md)在 18 个起点上，没有发现先退步、再经一次 Refine 超过起点的案例；一些大幅回升只是恢复之前的退化。因此，继续开发是否划算，要与同预算的其他做法比较，不能只看某一步改进了多少。这也不排除其他起点或更长开发时间下的收益。

目前更明确的认识是：已有试验可以提供有用线索，但还不足以支持一套通用的使用规则。需要解释的是，哪些信息在什么条件下帮助了下一次尝试。

## 三、接下来怎样推进

生成方面，先在同一程序、同一生成要求下比较有无形成历史，观察代码实际改了什么，以及改写结果是否更好。需要区分保留有效部分、产生新改进和重复返回旧程序，避免把更少修改直接当作更好设计。

安排尝试方面，先比较只按当前成绩选择，与同时参考已有开发结果的做法。在相同预算下，检查选择是否发生变化、最终结果是否改善。某个规则失败，就检查它利用的信息和适用条件；不能由此断言经验对选择没有帮助，也不能因为一次成功就认定规则普遍有效。

先把这两个问题分别检验清楚，再看它们能否共同改善完整搜索。研究主张应随证据逐步明确，方法的复杂性也应由实际收益来支持。
