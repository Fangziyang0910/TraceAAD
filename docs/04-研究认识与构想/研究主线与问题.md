# 研究主线：经验何时真的帮助设计

TraceAAD 想利用过去的算法试验改善下一次设计。已有工作更清楚地说明了一个障碍：**保存了历史、展示了差异、安排了更多开发机会，都不保证模型因此做出更好的算法决策。**

## 一、先分清“发现结构”与“开发结构”

[五任务强结果的形成路径](../03-机制探索与验证/2026-09-09-强结果形成路径.md)显示，TSP 的关键变化是在选点接口内构造并优化剩余路径，改变了求解结构；CVRP 的进展更多是长期调整距离、节约、角度与容量信号；VRPTW 的强程序则在引入前瞻模拟后继续修正等待和提前终止的评价。这些案例说明，强结果可以来自新骨架，也可以来自保留骨架后的细致协调。它们是已发生的成功路径，不能单凭胜者轨迹推断哪种预算分配更好。

## 二、退步后的回升不是新方向的价值

[Pivot 两步干预](../03-机制探索与验证/2026-09-07-Pivot两步价值.md)比较同一锚点上的两次 Refine 与 Pivot 后接一次 Refine。18 个锚点里，没有观察到 Pivot 先退步、再经一次 Refine 超越起点的案例。OBP 中第二步的大幅增益主要是从严重退化恢复，最终仍不及原锚点。因此，子代相对父代的回升会夸大“垫脚石”的价值；要看给定额外机会后是否超过原起点或已有前沿。这不排除其他起点和更长开发窗口，但目前没有理由把大位移本身当成续投信号。

## 三、相似性可以帮助观察，却还不会替我们选方向

[行为距离分析](../03-机制探索与验证/2026-09-07-BehaveSim全档案行为距离.md)发现，多数任务中行为近邻的训练分也更接近；[探针校准](../03-机制探索与验证/2026-09-07-BehaveSim群体距离校准.md)却显示 CVRP 的距离排序不稳。[初始化对照](../03-机制探索与验证/2026-09-25-初始化方式对照.md)进一步表明，代码不同可以产生几乎相同的行为，而更大的根间距离未稳定改善短程成绩。距离描述的是“做得像不像”，并不直接回答“哪个程序值得继续开发”。

## 四、历史材料和调度规则都必须落实到实际行为

[提示组件配对实验](../03-机制探索与验证/2026-09-03-提示组件与上下文.md)没有找到跨任务一致有益的文本改动；少数均值差受极端样本影响。[机会评分消融](../03-机制探索与验证/2026-08-25-边界机会评分.md)在 TSP200 和可比较的 OP200 重复中反而退步；OBP 上规则数学等价，出现的成绩差也不能归功于机会评分。[自适应调度对照](../03-机制探索与验证/2026-08-24-自适应调度.md)在 CVRP 上有较一致的收益，在其他任务上却有相反或混合结果。更多上下文、更复杂的选父分数、更长的开发，都不能代替对生成代码和后续结果的检查。

这些经历把“利用搜索经验”落到了两个具体难点：怎样让过去的试验改变模型实际写出的计算，怎样识别值得继续开发的程序。V10.14 偶有强候选，但跨路波动仍大，[现有结果](../03-机制探索与验证/2026-09-29-V10.14-正式实验结果与分析.md)还没有改变这两个认识。
