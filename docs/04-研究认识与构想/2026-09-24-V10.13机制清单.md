# V10.13 机制清单

按评价预算、初始化、预算分配、算子设计、输出与解析、错误处理六部分逐项审查。保留原有 M 编号，合并后不重新编号。

## A. 进化搜索评价预算

- **M1 预算额度与计数规则**：每次独立搜索的评价预算为 1000 次，由初始化和后续进化共同使用，耗尽后结束搜索。候选程序每实际评价一次计一次，包括运行失败、超时、重复代码的再次评价及修复后的评价；解析失败且未评价不计，确认的基础设施故障不计入预算。完整定义见[评价预算规范](../02-实验结果/00-评价预算与成本口径.md)。

## B. 初始化

- **M2 初始个体数量**：初始化 8 个评价有效的个体，加入档案。
- **M12 初始化输入**：任务契约与证据说明，以及此前已评价的初始个体；每个个体展示完整代码、分数和说明文字。
- **M13 初始化生成指令**：提出另一个有潜力的决策原则，明确“避免只换公式而保持相同选择”。
- **M14 初始化上下文裁剪**：超过输入上限时，从最旧的初始个体开始整份移除，并记录裁剪；不截断代码。输入上限见 M28。

## C. 预算分配与个体选择

- **M4 算子选择概率**：Refine / Tune / Pivot / Fuse 各为 25%，不随运行状态调整。
- **M5 个体质量分布**：对档案内全部个体的分数构造 softmax 分布 q，数值求解 β，使有效样本数 ESS≈min(8, 档案大小)；最高分并列个体超过 8 个时，目标提高到并列数。softmax 使用“分数−最高分”；重新求解 β 后，分数的正比例缩放或平移不改变分布。
- **M7 父代选择**：所有算子共用分布 p = 0.875·q + 0.125·均匀分布，每次开发抽一个父代。被选个体的 attempts 加 1，仅作记录，不参与质量计算或抽样权重；失败后的机会沿用见 M38。
- **M10 重复个体保留**：相同代码、相同分数的个体仍作为独立节点保留，各自拥有抽样概率，不合并。Fuse 参考池的去重另见 M19。

## D. 算子设计

### 四种开发动作

- **M15 Refine**：把当前程序当作可用的设计，改进其剩余问题表示、候选比较或组件协调；保留仍然有效的计算；聚焦小改或整体重写均可。
- **M16 Tune**：保持主决策方法，校准有影响的参数、阈值、权重、调度及其交互与状态依赖；提示明确“argmax 分数的严格递增重标定不改变选择”。
- **M17 Pivot**：重新考虑当前方法的一个核心假设，从模型知识提出替代的问题表示、决策规则或搜索组织；有用组件可以保留，不以新颖为目标。使用公共上下文，不附加形成轨迹、局部试验或参考程序。
- **M18 Fuse**：用参考程序中能弥补当前程序弱点的计算改进当前程序，调准其尺度、假设和交互，目标是超过两者；允许不融合而直接改进当前程序，明确“不要机械拼接”。

### Refine / Tune 的经验材料

- **M25 形成轨迹**：沿当前父代的父链向上取至多 3 条形成边，按旧→新排列；每条包含算子名、前后整体分数和子代说明文字（显示上限 480 字符），不含代码或 diff。
- **M22 局部试验选择**：从当前父代已评价的直接子代中取至多两条——超过父代的最优一条，以及未超过父代的最新一条；无子代时不展示。Tune 若存在由 Tune 产生的子代，则只在这些子代中选择。

### Fuse 的参考程序

- **M19 参考池去重**：排除与当前程序 AST 相同的个体；参考池内精确重复代码取最新已评价节点作为代表。
- **M20 参考选择与呈现**：每次选择一份参考，50% 概率按质量分布抽样、50% 概率均匀抽样；将完整代码、一行分数和说明文字直接提供给模型。

### 公共上下文与容量

- **M24 上下文组成与顺序**：任务契约 → 证据说明 → 当前完整代码 → 形成轨迹 → 局部试验 → 参考程序 → 算子指令 → 输出格式。其中证据说明明确“分数评价整个程序，说明文字表达设计意图”；按算子提供相应材料，没有的部分省略。
- **M28 上下文容量与裁剪**：输入上限为 24,320 token，输出上限为 8,192 token。开发上下文超限时，依次整项移除最旧形成边、局部试验、整份参考；仍放不下则明确失败，不截断代码。保留裁剪记录；初始化的裁剪顺序见 M14。

当前设计范围：没有算法语义分类、行为距离或行为签名、多样性门控及多种群；没有持续无父代生成、按近期候选分配机会或强制后续开发；没有逐实例评价反馈进入生成、数值校准层或参数提取器。

## E. 输出协议与解析

- **M30 完整程序输出**：默认输出一个完整 Python 代码块，前面可附一句说明；不要求 JSON 或多字段。兼容“说明+代码块”和纯代码；说明缺失、超长或类型异常不影响代码接受，只在展示时截断。
- **M31 局部修改输出与校验**：使用 JSON `{"mode":"edit","edits":[{"search":"原文","replacement":"替换文本"}]}`，1–32 项顺序应用，每个 search 必须非空且在当前程序中精确匹配一次。应用修改后检查目标函数、接口、语法和模块编译，再送评价。
- **M35 解析优先级与边界**：响应中有单个完整 Python 代码块则直接采用；否则从外围文字中读取唯一明确的 JSON 对象，多个冲突对象拒绝。不修补代码字符串、不猜测转义；缺少结束围栏但完整可解析的 Python 可以接收。

## F. 错误处理

### 候选失败与修复

- **M38 一次修复与机会沿用**：解析失败，或候选出现代码报错、运行时错误、超时、非法返回、非有限分数时，把原输出与错误反馈给模型，最多修复一次；修复后仍失败则放弃该候选。沿用原算子和父代机会，不重新抽父代。评价计数统一按 M1。

### 运行保障与研究记录

以下用于保证评价可信、证据完整和恢复安全，不作为独立的进化搜索策略。

- **M40 故障阻断**：评测基础设施故障或来源未明的异常阻断运行，不用候选修复掩盖；有评价预约但缺回执时保留预约，禁止自动重评，等待核定。连续 50 次无效输出也阻断。分类、计数和核定入口见[评价预算规范](../02-实验结果/00-评价预算与成本口径.md)。
- **M42 阶段保存与评价回执**：候选依次经历 scheduled→generated→parsed→evaluating→evaluated→committing→clear，各阶段先落盘再推进。调用评测器前保存唯一评价号与预算预约，结果追加写入独立回执；评价号与预算计数分离。
- **M44 恢复与日志一致性**：节点和事件随检查点保存，再按唯一 ID 写入日志，恢复时不重不漏。
- **M45 写入保护**：每路使用独占写锁；损坏的日志尾部另存为证据，不覆盖。
- **M46 恢复兼容性**：检查点记录机制配置；配置不同的版本使用独立运行目录。
- **M47 研究记录**：节点保存完整代码、说明、分数、父指针、算子、参考 ID 和评价号；事件保存选择统计、预算、耗时、token 和超父代/超前沿标记。区分展示的参考、实际提供完整实现的参考和模型声明采用的参考；每次模型请求与响应全文留档，含 token 与耗时。
