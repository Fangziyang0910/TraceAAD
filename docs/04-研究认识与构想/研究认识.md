# 自动算法设计与 TraceAAD：核心研究认识

> **核心定位**
>
> 本项目研究在**真实 evaluator 调用次数有限**的条件下，如何利用搜索过程中已经产生的证据，控制大语言模型在程序空间中的后续生成，使有限次算法设计实验产生尽可能好的最终算法。
>
> 核心科学问题：
>
> $$\boxed{\textbf{算法设计是一个不断试错、积累经验、再据此行动的连续决策过程。怎样让已经付出的试错成本，转化为后续更好的设计决策？}}$$
>
> 核心准则：**不是让模型记住哪种算法最好，而是让它学会依据已经发生的设计实验，决定接下来怎样继续设计。**
>
> 💡 **纲领性总览与最新定位**：详见专题文档 [主线研究定位与科学问题](主线研究定位与科学问题.md) 与 [AAD 领域的五个前沿方向与研究定位](AAD领域的五个前沿方向.md)。

## 怎样从实验结果形成研究认识（2026-09-09）

**实验既用于判断方法是否有效，也用于理解它怎样起作用。我们应当形成有依据、可修正的判断，并让下一轮实验逐步提高判断的可信度。** 分数、搜索过程和重复之间的差异共同构成证据；结论的力度与证据相匹配。

### 1. 把随机性纳入研究对象

算法搜索中的突破往往依赖少数关键生成。一次运行较好，可能来自机制提高了发现与开发好算法的机会，也可能来自这次恰好生成了好候选。机制的价值可以体现为更容易找到好算法、更快兑现收益、减少差的终点，或提高稀有突破的概率。应比较这些结果在重复运行中的分布，而不是要求每次搜索都复现相同路径。

同一机制的运行波动，为判断版本差异提供参照。评价本身的波动、搜索路径的随机性和执行条件的变化需要分别观察：前者可通过固定程序与评价条件检查，搜索随机性需要独立完整运行，资源争用等执行问题则应定位和处理。大量相关节点和连续预算点，能够丰富过程分析，却不能替代独立搜索重复。

### 2. 联合解释表现与实验过程

分析沿着“设计意图与可见上下文 → 实际生成的修改 → 算法决策行为 → 求解表现 → 后续开发与终局”展开。终局与预算曲线回答是否取得收益，过程证据帮助辨认收益从哪里来、在哪一步受阻，以及下一步值得改变什么。

成功、同分和退步的尝试都值得观察。例如，一条新规则经过多次开发最终带来突破，可以提示延续开发的重要性；结合其他新规则获得的机会与结局，再判断这是否是可重复的模式。最终分数相近的两组，也可能在生成有效性、开发效率和行为变化上出现有价值的差异。这些差异可以支持下一轮假设，其终局价值继续由实验检验。

### 3. 让证据支持相应层次的判断

一条真实成功链能够说明一种改进路径如何发生；多条一致的过程观察能够支持机制解释和实验候选；同预算的独立重复与有针对性的消融，则进一步检验某项改动是否提高搜索效果。每一层证据都有用途，研究可以在有限证据下作出暂定选择，并写清选择依据和什么新结果会改变判断。

对小样本的领先，保留它作为候选的价值，同时检查是否由某一次突出结果驱动。对暂时分不清的比较，结论可以是“现有运行尚未识别出稳定优势”；再根据差异大小、过程证据和研究重要性，决定补重复、缩小问题，或优先推进其他方向。未知实例与跨规模评价用于检查生成算法的泛化，独立搜索重复用于检查设计方法的稳定性，两者各自回答不同的问题。

### 4. 用不确定性安排下一步，而不是取消研究判断

每次分析都应落到三个问题：**目前最值得相信的解释是什么？它影响哪个研究选择？哪一个小实验最能区分关键解释？** 少量重复适合筛选方向；候选出现后，优先用新的独立重复确认，再决定是否扩展机制。提前明确主要比较与指标，有助于避免反复从多个版本、时点和指标中挑选偶然的赢家。

“存在随机性”本身不能解释某个机制为何有效或失败，也不应成为否定所有观察的通用理由。我们仍应提炼具体经验、提出机制假设、作出行动选择；对性能优势的判断则随着重复和对照逐步加强。正确看待实验结果，最终是让实验持续帮助我们理解问题和改进方法，而不是把分析写成一串防御性限定。



## 核心判断：从领域难题到 TraceAAD 的研究主线（2026-09-09）

> [!NOTE]
> 关于 AAD 领域全局前沿方向划分（五大前沿维度、背后的科学问题剖析、代表工作脉络）以及 TraceAAD 明确的研究定位与主战场，详见专题文档：[AAD 领域的五个前沿方向与研究定位](AAD领域的五个前沿方向.md)。

本节凝练当前研究判断；后文保留机制分解、历史实验依据与适用边界。以下定位不代表最终实验结论，也不预设轨迹机制必然有效。

### 1. 这个领域究竟在追求什么：发现更好的算法，还是获得更好的设计能力？

需要首先清晰区分两个层次：
- **第一层是被设计的算法（Designed Algorithms）**：例如最终获得一个更好的装箱决策规则、路径构造启发式或局部搜索算子。
- **第二层是自动设计器（Automated Designer）**：它如何提出候选、利用反馈、组织搜索，以及从多个设计任务中学习经验。

TraceAAD 的核心研究客体是第二层。TSP、CVRP、OBP 等组合优化任务是用来检验设计器的标准实验基准环境（testbeds），并不要求分别发明这些问题的人类未知数学理论。

在此区分下，领域内存在四类不同的研究立场与成功标准：

| 研究立场 | 最关心的问题 | 什么结果最有说服力 | 代表工作 |
| --- | --- | --- | --- |
| **算法发现** | 能否得到此前未知、超过现有纪录的方法或结构？ | 新算法、新构造、新纪录，以及可验证的数学/算法改进 | [FunSearch](https://www.nature.com/articles/s41586-023-06924-6)、[AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)（科学发现） |
| **任务适配与工程优化** | 能否针对具体工作负载，低成本地产生更合适的算法？ | 部署收益、运行可靠性、开发与维护成本降低 | [AlphaEvolve](https://deepmind.google/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)（系统优化） |
| **搜索方法研究** | 在相同模型与预算下，怎样更有效地找到好算法？ | 搜索效率、最终质量、稳定性，以及清晰的机制归因 | [EoH](https://arxiv.org/abs/2401.02051)、[ReEvo](https://arxiv.org/abs/2402.01145)、[MCTS-AHD](https://arxiv.org/abs/2501.08603) |
| **设计能力学习** | 能否把试错经验沉淀为可复用的设计策略？ | 训练后搜索能力提升，并能迁移到未见任务 | [EvoTune](https://arxiv.org/abs/2504.05108)、[CALM](https://ar5iv.labs.arxiv.org/html/2505.12285)、[AHD Agent](https://arxiv.org/html/2605.08756v1)、[SimpleTES](https://arxiv.org/abs/2604.19341) |

TraceAAD 选择聚焦于 **“搜索方法研究 + 设计能力学习”**，不把发现人类未知的数学结构作为必要目标。方法贡献不要求产出的算法思想前所未见，即便最终产生的是已有思想的有效重组，只要能在严格受控条件下更高效、更稳定地完成设计并解释能力来源，就是扎实的研究。底线要求是：产出的程序必须具备真实的算法效用，而非仅代码表面形式不同。

### 2. 真正的领域难题：不是“代码空间很大”，而是“试过之后，究竟学到了什么”

在自动算法设计中，最深层的挑战是：**在反馈昂贵、不充分、难以归因的情况下，如何把一连串局部试验，组织成能够持续积累收益的设计过程。** 具体体现在四个根本瓶颈：

1. **提出一个合理的修改 $\neq$ 提出一个有价值的实验**：
   模型一次修改往往同时变动归一化、非线性权重与边界处理等多处逻辑。即便分数提升，客观反馈也只能说明“整份程序在本次评价下表现更好”，无法直接归因于哪项改动、是否存在互相抵消，以及换规模后是否成立。EoH 引入自然语言思想演化、ReEvo 引入相对性能反思，均是在弥补“盲目生成代码与标量分数”之间缺失的设计指导。
2. **评价告诉你结果，未必告诉你原因**：
   一次退步可能是核心思想不合适，也可能是局部参数未调优、实现瑕疵或实例采样的偶然波动。最难的不是记录分数，而是避免把有限观察过度解释为普遍规律。因此，轨迹应优先记录**真实程序、修改关系和执行反馈等事实证据**，而非模型自述的“成败经验总结”（前者是客观事实，后者是主观解释）。
3. **局部收益与长期收益不一致**：
   一次修改可能暂时降低分数，却打开了更容易进一步改进的代码结构；一次连续微调虽然带来小幅提升，却可能使搜索在单一局部极值处耗尽预算。MCTS-AHD 关注暂时落后的候选是否被过早淘汰；但**处理长期收益并不等同于必须先准确预测每个节点的潜力**，它完全可以通过合理的搜索结构、经验条件化生成或策略学习来隐式处理，而不必堆砌脆弱的显式价值估计器。
4. **最终提升是否真实，以及代价是否值得**：
   必须同时检验双重泛化：一是**生成算法的泛化**（在训练实例上发现的程序，在未见规模、未知分布上能否保持优势）；二是**自动设计器的泛化**（在某类任务上学到的经验使用策略，能否迁移到新任务）。此外，评价成本不能只看 evaluator 次数，还需综合计入输入 token 开销、模型调用次数以及训练前置成本。

### 3. TraceAAD 的立足点：当前算法不足以表达设计状态

关于“为什么要引入历史轨迹”，最坚实的第一性原理论证并非“人类专家也是这样做的”，而是：

$$\boxed{\textbf{同一份当前算法，在不同的试错历史下，合理的下一步决策应当截然不同。}}$$

例如两次独立搜索当前停在完全相同的 CVRP 启发式（代码与得分相同）：
- 搜索 A 从未尝试过需求归一化；
- 搜索 B 已经尝试过多种归一化方案，并确认它们均显著损害了高需求实例的表现，因而回退到当前版本。

只有当前代码与标量分数的设计器无法区分这两种状态；而能够感知历史的设计器，显然应当采取不同的下一步决策。**这里缺失的关键信息是：围绕当前算法，已经提出过哪些假设、做过哪些实验、得到了什么反馈。**

对此，必须对“过程知识”确立三条严格边界：
- **轨迹是经验的记录，不是知识正确性的保证**：它可能包含错误归因、实现缺陷与偶然波动。机制的职责是从记录中提取可操作的证据，而非默认历史中的每句总结都成立。
- **历史的价值是高度条件化的，不是越长越好**：Refine 最需要的可能是单步成败对比，Fuse 最需要的可能是另一方案的关键机制。无节制堆砌全局历史只会稀释模型的局部注意力。
- **真实轨迹不必限定为单一祖先链**：形成谱系、失败尝试、跨分支参照均可作为证据来源，但不能把任意程序按分数排列后伪造成真实的演化历史。

由此得出 TraceAAD 的核心假说：
> **与当前设计任务相关的试错经历，能够提供当前程序及其评分之外的信息；利用这些信息，有望改善下一次设计决策，并提升有限预算下的最终设计质量。**

### 4. 统一架构：历史上下文与预算分配统一于“下一次设计实验”

历史上下文与预算分配并非两个互不相干的目标，它们统一于**“如何组织下一次设计实验”**：

$$H_t \;\overset{\text{选择实验（预算分配：做什么实验）}}{\longrightarrow}\; a_t \;\overset{\text{组织证据（历史上下文：看什么经验）}}{\longrightarrow}\; C_t \;\overset{\text{条件化生成}}{\longrightarrow}\; x_t \;\overset{\text{评价与更新}}{\longrightarrow}\; H_{t+1}$$

- **预算分配（Search Control）**：依据历史，决定下一次把探索机会给哪个程序、执行何种意图；
- **历史上下文（Context Construction）**：为了做好这次实验，为模型装配哪些具体证据。

**概念上相容，实现上严格解耦**：为了获得可归因的科研证据，必须先固定其中一端来验证另一端（如 V10.7R 先在固定预算分配下，严格检验具体任务设计证据对生成端的纯增量）。
- **主张边界**：若目前仅验证了历史上下文改善候选生成质量，就主张“轨迹条件化生成”；只有进一步验证历史改变了长程搜索决策并带来系统性增益，才主张完整的“轨迹引导搜索控制”。
- **MDP/RL 概念澄清**：更准确的表述不是“算法设计非马尔可夫因此引入轨迹”，而是**“轨迹帮助构建更充分的设计决策状态，RL 进一步学习如何基于该状态行动”**。必须注意：代码的静态祖先链 $\neq$ RL 的交互轨迹，策略训练必须记录当时真正可见的信息与采取的动作，不能事后抽取高分链路充当真实策略 rollout。

### 5. 文献先例与原创性边界纠偏

不能将“首次把轨迹、多步回报或 RL 用于算法设计”或“现有方法不利用历史”作为贡献点，该路线上已有非常直接的前序工作：
- **[EvoTune (2025)](https://arxiv.org/abs/2504.05108)**：利用进化搜索产生的反馈微调 LLM，使搜索算子本身具备学习能力；
- **[CALM (2025)](https://ar5iv.labs.arxiv.org/html/2505.12285)**：将进化搜索与 RL 微调结合，将生成候选相对提示中基准程序的改进作为奖励；
- **[AHD Agent (2026.05)](https://arxiv.org/html/2605.08756v1)**：将启发式设计表述为多轮交互 MDP，依据历史反馈生成代码并调用诊断工具，以终局启发式质量为回报采用 GRPO 训练；
- **[SimpleTES (2026.07)](https://arxiv.org/abs/2604.19341)**：联合组织搜索深度/宽度与历史复用，按最终最优结果筛选高质量轨迹进行加权似然迭代微调。

TraceAAD 的真正增量与切入点不在于宽泛的概念框架，而在于实证回答具体机制问题：
**如何以低额外成本，将真实设计转移中的成功与失败证据组织为紧凑有效的设计状态；使优化目标与整个搜索过程的最终收益对齐（而非仅仅奖励立即超父的局部微调）；并检验模型是否真正内化了可跨任务迁移的“经验使用方式”。**

### 6. 多步奖励与信用分配的思考逻辑

1. **终局回报与增量增益的望远镜恒等**：
   若以搜索结束时的最优提升为终局回报 $R(\tau) = F_B - F_0$，而在无折扣（$\gamma=1$）下采用最优值增量奖励 $r_t = F_t - F_{t-1}$，二者满足望远镜求和：
   $$\sum_{t=1}^B r_t = F_B - F_0$$
   这表明终局奖励与增量奖励在总体目标上是一致的。单纯把终局奖励切分为单步增量不构成实质创新，关键在于训练如何反传长期收益。
2. **避免单步即时近视，但不盲目奖励失败**：
   必须克服“只根据当前步是否超过父代”独立奖惩的近视性，使能够打开后续改进空间的早期结构探索得到肯定。但这绝不等于无差别奖励失败——失败的价值必须由它是否促成了后续成功来兑现；**系统要学习的是“如何利用试错反馈继续改进”，而不是“盲目承担失败”**。
3. **警惕搜索树的标签偏倚**：
   不能直接将搜索树中后代达到的最好成绩作为当前动作的无偏价值标签。各节点分配到的后续计算资源与选父频率不同，混杂了调度选择的系统性偏差。
4. **内化经验使用方式（元学习视角）**：
   模型最终学到的不应是对特定任务的高分代码记忆，而应是**“遇到新任务后，如何根据新产生的试错反馈决定下一步设计行动”**（与 [RL²](https://arxiv.org/abs/1611.02779) 的元强化学习思想契合）。在此架构下：
   $$\text{上下文提供当前任务的新经验} \quad \times \quad \text{模型参数决定如何理解与利用这些经验}$$

### 7. TraceAAD 的三个递进验证命题

TraceAAD 的完整路线分解为三个递进的科学命题（不必在一篇论文内全部完成，但构成了清晰的推进阶梯）：

- **命题一（证据增量）**：证明“真实设计经历”提供了超越纯代码堆砌的增量。在控制底座、参考质量与 Token 开销的前提下，严格对比“无历史”、“纯代码对照样例”与“保留真实演化关系的历史证据”，验证过程关系本身是关键解释变量（V10.7R 是此命题的极简基座）。
- **命题二（搜索兑现）**：证明历史上下文不仅能改善单次输出的局部超父率，还能转化为有限预算完整搜索下的全局求解质量提升与未知测试实例上的泛化优势。
- **命题三（策略泛化）**：证明多步强化学习训练使模型掌握了通用的设计策略与经验利用能力，而非仅仅记住了训练任务的高分算法模板（通过未见起点、未见历史状态以及跨任务测试检验）。

## 1. 研究对象与目标

假设给定：
1. 一个权重固定（frozen）的预训练大语言模型 $\phi$；
2. 一个待设计的算法任务 $\mathcal{T}_{\mathrm{AD}} = (d_{\mathcal{T}}, K, \mathcal{E})$，包含问题描述 $d_{\mathcal{T}}$、程序模板与接口契约 $K$、可执行评估器 $\mathcal{E}$；
3. 一个由可执行函数构成的开放代码候选空间 $\mathcal{R}$；
4. 严格受限的真实评价预算 $B$（如 1,000 次 evaluator 调用）。

系统整体优化目标为：

$$\max \; \mathbb{E}\left[\max_{t \le B} f(r_t)\right]$$

其中 $f(r_t) = \mathcal{E}(K[r_t]; S_{\mathrm{train}})$ 为候选函数在训练实例集上的客观评估得分。最终产出的算法 $r^\star$ 必须在独立、未见的测试集 $S_{\mathrm{test}}$（跨规模、跨分布实例）上进行一次性盲测检验泛化能力。

本质上，**表层优化对象是算法代码，科学研究客体是“有限预算下序贯产生算法的搜索过程”本身**。TSP、CVRP、OBP 等经典组合优化问题是检验自动设计器性能的标准实验基准环境（testbeds）。

## 2. 系统机制分解

设第 $t$ 步时累积的全部搜索历史为 $H_t$（包含生成的程序、客观得分、父子关系、模型声明的 Idea、代码 diff 与执行反馈）。搜索闭环严格分解为四步：

$$\boxed{H_t \overset{\mu}{\longrightarrow} a_t \overset{g}{\longrightarrow} C_t \overset{K_\phi}{\longrightarrow} x_t \overset{\mathcal{E}}{\longrightarrow} y_t \longrightarrow H_{t+1}}$$

### 2.1 第一步：决定下一次实验做什么（Search Action）
$$a_t = (n_t, o_t, r_t) \sim \mu(a \mid H_t)$$
- $n_t$：从哪个已有算法节点出发；
- $o_t$：执行何种设计意图（如局部精炼 Refine、思路跳变 Pivot、机制融合 Fuse）；
- $r_t$：若需要跨分支借鉴，选择哪个参照/donor 节点。

这属于**计算与预算分配问题（Search Control）**。在此必须解耦决策对象、资源单位与重决策频率。节点本身并非孤立的价值实体，合理的价值概念是动作条件化的 $Q(n, o \mid H_t)$。

### 2.2 第二步：决定给模型看什么（Context Construction）
$$C_t = g(H_t, a_t)$$
映射 $g$ 负责将庞大的搜索历史事实有损投影为本次决策高度相关的上下文。

**明确区分完整历史、控制状态与生成上下文**：
- 完整历史 $H_t$ 保存全部可重放事实；
- 控制器状态（如访问计数、未见区域、失败标记）用于引导资源分配 $\mu$；
- 生成上下文 $C_t$ 仅提取与本次动作 $a_t$ 相关的证据输入模型。历史不仅通过上下文直接塑造候选，也通过控制逻辑决定搜索重心。

### 2.3 第三步：模型在条件约束下生成候选（Conditioned Proposal）
$$x_t \sim K_\phi(x \mid C_t, o_t)$$
预训练语言模型不是黑盒单点优化器，其实质是**由上下文与设计意图共同调控的候选生成核（Proposal Kernel）**。核心洞见在于：

$$K_\phi(x \mid C_t, \text{Refine}) \neq K_\phi(x \mid C_t, \text{Pivot}) \neq K_\phi(x \mid C_t, \text{Fuse})$$

不同设计行为不仅指令不同，所需要的上下文证据结构也不同。目标是系统性提高：

$$P(\text{生成高质量有效算法} \mid C_t, o_t)$$

### 2.4 第四步：购买真实环境反馈并更新（Evaluation & Update）
$$y_t = \mathcal{E}(x_t), \quad H_{t+1} = U(H_t, a_t, x_t, y_t)$$
消耗一次真实评价预算，将客观执行结果与代码写回历史，进入下一步循环。

## 3. 轨迹及其他信息的含义

在程序演化与算法设计中，**代码文本变化 $\neq$ 算法行为变化 $\neq$ 搜索路线变化**。

### 3.1 轨迹内容的三类性质解耦
给定演化步骤 $(x_i, o_i, \Delta_i) \to x_{i+1}$，必须严格区分：
1. **形成事实（Formative Facts）**：客观发生的父子关系、代码 diff $\Delta_i$、evaluator 得分与报错信息；
2. **模型陈述（Model's Self-Reports）**：模型生成的 Idea 描述与自述成败归因（属于文本表征，不等于客观因果）；
3. **研究者推论（Mechanistic Inferences）**：关于机制生效机理的假设（如推测轨迹有助于约束搜索空间）。

引入形成历史改善候选质量，能支持“该上下文配置有效”，但**不能直接等同于“模型完全理解了代码与性能间的因果律”**。

### 3.2 四类不同轨迹的严格辨析
1. **形成谱系（Ancestral Lineage）**：算法由哪些父代代码演化而来（代码变更、算子类型、历史评分），用于**组织生成上下文与信用溯源**；
2. **搜索几何轨迹（Search Geometry）**：群体在解空间或代码嵌入流形上的宏观移动分布，用于分析探索与收敛状态；
3. **求解执行轨迹（Problem-Solving Trajectory, PSTraj）**：单一算法在探针实例上逐步求解时的微观决策动作（BehaveSim 的观测对象），用于**识别运行时实际行为的重访与失真**；
4. **求解器内部 Pipeline 拓扑（Pipeline Topology，如 DGA²D）**：单次运行中算法内部各模块的前后依赖图。DGA²D 讨论的是内部组件依赖，既非外层进化谱系，亦非 prompt 上下文长度。

### 3.3 行为度量的群体定位与个体边界
在固定探针上度量 PSTraj 行为距离能透视实际执行行为。8 月 27 日的 landscape 结果和 9 月 7 日的校准复验共同支持一个有限命题：在 TSP、OBP、VRPTW 的算法群体中，行为距离越小，fitness 差在统计上往往也越小。这说明算法空间从行为视角看并非完全无结构。

该关系不可逆。相近行为可能对应相近 fitness，但相近 fitness 不能推出相近行为。多个机制完全不同的算法可以分别位于不同的高质量行为区域，因此 fitness 不能替代行为距离，也不能作为行为归区依据。

这个群体命题不能外推成个体反事实。自动算法设计的单次生成方差大、突破稀疏；“某类近邻平均更相似”不等于“某个邻居下一次更值得 Refine”。E1-A/A.1 已经表明，控制 fitness 后行为近邻没有提供稳定的 Refine 响应增量。因此**行为距离是群体几何与条件性诊断信号，不能直接作为节点潜力分数或自动排他的硬性分配规则**：
- 行为距离大但当前未改善：不能立即武断判为“无效漂移”（可能正在跨越低谷或构建全新结构）；
- 行为距离小且当前未改善：也不能直接武断判为“绝对停滞”（可能正在进行关键参数或局部核心逻辑的有效精炼）；
- 行为距离主要用于离线分析、重访排查与失真检验；引入在线决策必须有明确的前瞻收益支持。

### 3.4 从个体潜力坐标转向离线群体几何传感器

E1-A/A.1 的严格时间回放没有支持“行为近邻共享 Refine 响应”：控制fitness后的联合核增量接近零，first-parent-use也未改善。因此不再把BehaveSim定义为Refine evolvability的直接泛化坐标。核心认识是：

$$
\text{algorithm execution phenotype similarity}
\neq
\text{LLM variation-response similarity}.
$$

LLM proposal还由代码结构、实现摘要、形成路径和可修改空间决定。对TraceAAD更真实的邻域是算子与上下文诱导的proposal neighborhood。BehaveSim更适合观测整个 archive 的覆盖、拥挤、高质量行为岛、窗口扩散/收缩，以及在转移发生后测量`parent→child`实际移动和对历史区域的重访程度。

9 月 7 日的[群体几何校准](../03-机制验证/03-算法行为几何/2026-09-07-BehaveSim群体几何校准/README.md)进一步固定了任务边界：OBP 的 256-item probe 与 1000/5000-item 正式规模几何不够一致，后续切换到 scale-matched；OP 四随机流明显改善但严格稳定门槛略未通过；CVRP 四随机流仍不稳定。该轮 landscape 样本受旧 E1 画像覆盖限制，严格适用于历史 Refine-parent 子群体。

后续[全 Archive 群体验证](../03-机制验证/03-算法行为几何/2026-09-07-BehaveSim全Archive验证/README.md)直接从全部有效节点按评价时间等间隔抽样，不看 fitness，也不要求节点被 Refine。TSP、scale-matched OBP、VRPTW 的三个重复仍全部通过 distance–fitness-gap、kNN 对随机 pair 和远近距离档门槛。因此在当前 V10.6 和校准 probe 下，可以把 BehaveSim 视为这三个任务 archive 的有效群体几何坐标。OP 的 32 节点时间样本也全部同向，但测量稳定性仍待确认；CVRP 重复失败，继续停用。

“有效群体坐标”不等于“适合在线维护”。[在线可行性复审](../03-机制验证/03-算法行为几何/2026-09-07-BehaveSim在线可行性复审/结论.md)确认，V9.19 后期已经实现五任务评价内轨迹采集、节点轨迹缓存和新旧节点增量距离更新。它消除了额外画像执行和旧距离重算，却没有消除完整轨迹的成对比较：OBP 的四条 1000/5000-item 训练轨迹约需处理 5200 万个编辑距离单元/算法对，1000 个节点有 499,500 对；ACO 若要稳定又可能需要正式评价之外的多个随机流。V9.21 因而已经让 BehaveSim 退出在线控制。

当前职责据此分开：TraceAAD 的通用在线状态来自形成历史、代码、评价结果和真实搜索事件；BehaveSim 在校准任务上用于代表性样本的离线覆盖、区域和算子移动分析。未来的轻量在线行为传感器是一条可选支线，必须先通过明确成本上限、测量稳定性、压缩保真、增量信息和等成本终局收益门槛。

控制器研究也必须区分三层证据：

$$
\text{sensor validity}
\rightarrow\text{outcome predictability}
\rightarrow\text{policy utility}.
$$

Brier改善只说明概率预测或校准更好，不能直接推出预算分配有效。E1中Q_kernel的优势在E1之后539次未见Refine suffix上没有复制：其Brier、AP、lift和top组收益均弱于M1，因此不再把quality kernel保留为选父候选。

E2-A进一步把行为用作轨迹状态传感器，并借V10.6已知operator propensity比较停滞状态下Pivot与Refine。三任务suffix虽然有424个overlap动作，但没有任何frontier event，主目标不可识别；更根本的问题是，它以parent的祖先形成状态近似“局部已被搜尽”，没有纳入parent出生后接受过多少开发。它识别的是ancestral formation state，不是真正的development exhaustion。

因此控制状态还需要显式区分：

$$
S_t(n)=[
FormationState(n),
DevelopmentExperience(n,t),
GeometryState(n,t)
].
$$

Formation trajectory负责告诉生成模型当前代码如何形成；development experience记录该位置出生后被试过多少次、近期是否成功以及children是否重访；behavior transition用于测量一次实际动作走了多远。失败sibling可以不进入Prompt，但必须允许其聚合结果进入controller state。

E2-B'随后以18个固定锚点做了36条随机配对路径，直接比较Refine→Refine与Pivot→Refine。9个experienced锚点上相对两步价值差为+0.000201，95%区间[0,0.000602]，只有1个Pivot路径更好、8个平局，且只有TSP为正，未过预注册门槛。最关键的是，没有一个Pivot的第二步Refine提高第一步已经达到的best：唯一的experienced正例来自第一步立即改善。大行为移动虽然与$c_2-c_1$正相关，但它主要表示灾难性Pivot后返回anchor附近，与两步$Q_2$几乎不相关。因此当前没有证据支持一步horizon内的Pivot stepping-stone value，也不能用“大移动后易恢复”给Pivot记正信用。

个体动作控制的主逻辑仍可写作：

$$
\boxed{
Trajectory\rightarrow Transition\ Observables\rightarrow Search\ State
\rightarrow Operator/Continuation\ Decision
}
$$

这些结果促使几何路线退回群体层，考虑用覆盖、区域质量和扩散/收缩研究搜索分布。但在线可行性复审之后，群体几何也不再是通用在线控制的默认前提；当前推进顺序见下节。行为距离本身不决定某个节点 Refine/Pivot，也不让“远距离”自动获得正信用。若重新研究个体 Pivot，应单独识别其宽 parent routing 或更长 horizon 价值。

### 3.5 最新认识：先补充搜索决策依据，再选择观测工具（2026-09-07）

我当前最需要解决的是：**搜索器主要依据当前 fitness 与节点访问次数分配预算，尚未充分利用已经发生的设计实验。** 相似性只有在能低成本地补充这些决策依据时才值得引入。方法应适用于已有标量 evaluator，不依赖逐任务编写行为探针，也不以重建完整算法景观为前提。

因此，下一步优先组织三类证据：**改写产生了什么响应，候选是否重访已有实现，以及预算实际测试过哪些生成条件。** 代码、父子与 donor 关系、实际提示、评价结果、执行状态和资源消耗都已在通用接口内；把它们按形成条件关联起来，可以恢复单个 fitness 丢掉的信息，但不能凭聚合分数恢复真实行为等价类。

形成历史回答“当前代码怎样形成”，开发记录回答“它出生后已接受哪些尝试”。同一程序配上不同历史和参考，可能诱导不同生成分布；同一份提示重复采样，也可能产生新结果。应保留完整形成树，同时按程序身份与实际生成条件统计覆盖，不能用节点数代替方向数，也不能把重复提示直接标为浪费。

对一次改写，分别保留相对父代、较强双亲和当时全局 best 的响应。改善弱父代、追上强 donor、推进前沿具有不同含义。逐次前沿改善幅度之和等于最终 best 的提高，因而与终局目标一致；但这个恒等式没有解决中间步骤的后续投入与信用问题。尚未开发、已开发但未恢复、已经恢复必须分开，恢复到旧起点也不等于创造了新价值。

当前顺序是：**改写响应 → 重复与两级覆盖 → 投入和恢复的轨迹分析 → 有证据支持时，采用轻量表征改进参考选择。** AOS 借鉴响应与信用的组织方式，代码指纹补充跨分支实现关系，STN 借鉴对实际访问和转移的分析。逐节点潜力拟合、完整景观重建和行为新颖性奖励暂缓。进入策略实验时只改变一个决策位置，最终仍由同评价预算下的 best、未知实例表现与额外成本决定是否保留。

[本轮调研与只读回放](../03-机制验证/02-搜索调度与预算分配/2026-09-07-搜索观测与预算分配/2026-09-07-从搜索观测到预算分配-调研与分析.md)进一步限制了判断：V10.6 的共同前 350 次评价中，严格 AST 重访只占有效节点的 1.44%，尚不支持把完全重复视为主要瓶颈；早期退化 Pivot 缺少直接后续评价更明显。前者不排除近似或行为重复，后者也不证明续投有收益。接下来应辨识哪些观测足以区分可干预的原因，而非先给停滞统一增加探索。

## 4. 当前假设与已有证据

TraceAAD 建立在两层明确的假说及其已有实证基础之上：

### 假设 1：状态表示假设（State Representation Hypothesis）
> **算法的局部形成轨迹包含了对下一步设计至关重要的状态信息，单纯依赖当前算法代码与其单点 fitness 无法充分表示当前搜索状态。**

- **已有实证支持**：固定锚点实验（4 任务、72 锚点、648 次生成）显示，在当前代码基础上加入父代来时路（parent-path）后，四任务配对增益区间均为正，72 个锚点中 58 个更好。其最主要且稳定的作用是**显著降低灾难性偏离与代码逻辑崩溃**，帮助模型保留已有可用结构。
- **边界说明**：形成轨迹的单步 proposal 改善并不等于无条件改善所有任务的 1,000-eval 终局搜索（终局受分配与任务特性共同制约）；在父代来时路之外进一步堆砌直接子代尝试，未见稳定额外收益。

### 假设 2：动作条件化生成假设（Action-Conditional Generation Hypothesis）
> **轨迹证据的价值并非全局静态，而是强依赖于下一步所执行的设计行为；不同搜索意图需要差异化的证据投影。**

- **已有实证支持**：在相同父节点上对比不同算子，Refine 呈现较高小步超父率与紧凑改写；Pivot 呈现较低即时超父率与较大退化尾部，但少数成功 Pivot 能打开全新机制拓扑；Fuse 能在父代间产生互补合成或吸收优势特性。提示词与上下文成分（原理说明、去注释、算子指引）确实显著改变了 proposal kernel 的分布形态。
- **边界说明**：算子超父率强依赖于父节点成熟度与选父分布，非算子的固有静态属性；提示技巧的影响方向高度依赖具体任务，不存在跨任务绝对普适的单一最佳 Prompt。

## 5. 尚未解决的核心问题

当前研究与实践仍面临四个深层科学瓶颈：

1. **跨步信用归因的模糊性**：一次代码修改往往同时变动多处逻辑或超参数，无法轻易隔离究竟是哪一行代码、哪种机制设计导致了得分变化；多步演化后，后代突破对早期祖先的真实依赖难以无偏估计；
2. **认知不确定性与质量信号的混杂**：新方向/未充分访问节点的“探索潜力”来自信息不足（epistemic uncertainty），而高分节点的“利用价值”来自已兑现表现。现阶段缺乏跨任务自适应平衡这两者的稳健机制，容易在加权公式中退化为对任务尺度敏感的经验调参；
3. **探索算子的有效性塌缩与代价控制**：跳出既有模式的大步修改（Pivot）极易落入语法错误或性能崩溃的无效空间，而收敛到微调（Refine）又容易导致骨架收敛与局部停滞；
4. **单步提议改善向完整搜索终局的跨越**：单步 proposal 分布上的方差收窄或配对增益，在有限预算的复杂非线性演化动力学中，如何稳定转化为全搜索周期的解质量突破，目前仍缺乏充分的理论与实验因果链条。

## 6. 当前阶段范围与研究选择

围绕上述认识与瓶颈，本项目在当前阶段作出明确的方法论取舍：

1. **优先在固定预训练模型下开展推断端搜索研究**：保持模型权重固定，聚焦上下文组织、历史证据呈现与算子语义对生成分布的调控机理；模型参数微调与强化学习作为远期条件性扩展，不作为当前研究成立的前提；
2. **机理辨识优先于复杂的自适应动态分配**：保持清晰透明的基准分配策略，优先识别 prompt、lineage 与不同算子的因果效应，避免在机制尚未摸清前引入过多超参数和复杂控制器导致变量混杂；
3. **坚持单向科学信息流与证据边界**：
   $$\text{原文事实} \longrightarrow \text{单篇笔记} \longrightarrow \text{跨文献比较} \longrightarrow \text{TraceAAD 条件性认识}$$
   整系统在基准上的胜出直接支持整法方案的工程有效性，但断言具体内部组件的独立贡献必须依靠严格受控的单变量消融；
4. **改变判断的潜在证据标准**：
   - 若出现跨任务稳健的无偏历史价值估计器，将重新评估动态预算分配器的引入；
   - 若观察到特定信息块在不引起注意力稀释的前提下显著提升了长程搜索终局，将扩展默认生成上下文；
   - 若发现行为距离与未来改进潜力存在可靠的前瞻性因果预测关系，方考虑将其纳入在线决策系统。
