# 自动算法设计与 TraceAAD：核心研究认识

## 核心判断

TraceAAD 研究在真实评价调用有限的条件下，如何利用搜索过程中已经产生的证据，控制大语言模型在程序空间中的后续生成，使有限次设计实验产生更高质量、更可迁移的算法。

算法设计不是一次生成，而是连续的发现、组合和精炼。模型需要依据当前程序、已有修改及其真实反馈决定下一步动作。历史上下文的价值不在于让模型记住一个最优答案，而在于让它理解当前算法已经形成了什么、哪些机制值得保留、哪些方向能够继续发展。

## 四类收益形成结构

高质量算法的收益主要来自四种相互交织的机制：

1. **有效骨架发现**：改变数据结构、控制流程或核心求解方式，找到可以继续开发的算法基座。
2. **互补信号组合**：从不同候选中提取互补计算特征，形成综合决策机制。
3. **连续协调改进**：围绕已有骨架协调多个相互作用的评分项、阈值和约束。
4. **决策边界校准**：确认局部公式变化是否真正改变排序、采样或可行性决策。

这四类机制解释了为什么同一份历史在不同任务上产生不同价值：任务的收益来源不同，设计者需要的证据也不同。

## 历史上下文的决策相关性

“记录更多”不等于“设计更好”。与当前程序和操作无关的历史会分散生成注意力，过短的历史则无法说明机制如何形成。有效上下文应回答当前一次设计的具体问题：

- 继续开发时，哪些形成关系和评价变化值得保留；
- 组合机制时，哪个跨分支候选提供了互补计算；
- 校准参数时，局部变化是否改变了实际决策；
- 寻找替代结构时，哪些路线提供了可执行的不同骨架。

因此，历史组织应以设计意图和当前算法状态为条件，而不是以固定长度或统一采样规则为目标。

## 机制证据的最低闭环

一个机制只有同时满足以下链条，才构成论文中的有效解释：

1. 上下文中出现与当前设计相关的证据；
2. 生成代码实现了对应的计算或结构变化；
3. 该变化改变了排序、采样、可行性或其他下游决策；
4. 候选在真实评价中超过父代或参考程序；
5. 改进方向获得后续开发或在 held-out 实例上保持收益。

Idea、算子标签、代码长度和结构距离只能描述生成过程，不能替代这条证据链。

## 任务层面的研究认识

当前五任务证据支持以下对应关系：

| 任务 | 主要收益形成方式 | 有效历史组织 |
|---|---|---|
| TSP | 骨架发现后持续协调 | 短形成轨迹 |
| VRPTW | 多规则组合与协调 | 短形成轨迹，强调最近变化 |
| CVRP-ACO | 多信号组合与精英传播 | 跨分支高质量档案 |
| OP-ACO | 组合与参数校准随规模变化 | 形成历史与精英档案的受控组合 |
| OBP | 改变实际 `argmax` 边界 | 决策变化和行为证据 |

这不是静态任务分类，而是对“当前候选需要怎样改进”的诊断框架。一个任务可以在不同搜索阶段切换收益形成方式，历史组织也应随设计需求变化。

## 研究评价口径

机制效果必须在相同真实评价预算下比较，并同时报告训练曲线、重复均值、held-out 泛化和跨规模结果。局部父代改进率用于说明生成行为，全局 best 和 held-out 结果用于说明算法质量；二者不能互换。

研究记录只保留能够改变主张或后续实验选择的事实。运行状态、失败类型和执行成本在它们能够解释搜索行为或可执行性时进入分析；纯粹的步骤日志不进入论文主线。

## 当前主线

TraceAAD 的核心命题是：**与当前程序和设计意图匹配的改进历史，能够改善下一步算法生成；当这种生成改善改变实际决策并获得持续开发时，它会转化为有限预算下的搜索收益。**

后续工作围绕两个可分离问题展开：一是历史证据怎样改善机会给定后的生成质量，二是搜索调度怎样决定哪些路线获得机会。先建立生成端的机制证据，再研究二者的协同。
