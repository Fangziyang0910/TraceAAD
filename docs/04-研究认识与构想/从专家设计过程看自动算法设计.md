# 经验怎样进入下一次算法设计

算法专家会把改动及其实测结果用于下一次判断：哪些结构有效，计算代价在哪里，哪里出错，一个设计继续开发后达到什么水平。TraceAAD 的形成历史提供了这类信息的一部分。本页记录经验缺失假设怎样形成，以及后续实验怎样改变了它。

## 观察从哪里来

在只保存有效程序的搜索中，失败、重复生成和修复过程留在日志里，后续生成主要读取当前代码与通向它的形成路径。2026 年 10 月 2 日的轨迹分析发现：

| 观察 | 数据 |
| --- | --- |
| TSP 超时率随搜索上升 | 每 250 次尝试分段，依次为 2%、8%、13%、16% |
| 分析已讨论时间，子代仍超时 | 父代耗时至少 20 秒的 220 次 Refine 中，89 次超时 |
| 同一程序被反复尝试 | 单个程序最多展开 45–90 次 |
| 多次失败后的下一次改进率更低 | 首次约 18–21%，15 次以上失败后约 1%；后一类尝试占预算 10–15% |
| Explore 后期刷新更少 | 每千次 Explore，前 300 次与之后：TSP 25 对 6，CVRP 12 对 0，OP 16 对 0 |

这些观察促成了一个假设：把已做过的尝试展示给后续决策，可能减少重复失败并改善搜索。实验因此同时检查经验是否改变生成起点，以及模型读到经验后怎样修改代码。实现见[尝试记录与经验使用](../01-搜索方法/尝试记录与经验使用.md)。

## 检验改变了什么认识

补上尝试记录后，失败率没有随搜索下降。TSP 的总超时率降低主要对应少选了接近时限的父代；相近耗时父代上的子代超时率大体接近。这把选择变化与生成变化分开了。

进一步加入逐行耗时剖析，模型更多讨论提速，但时限内的改进率没有提高。它主要减少候选和搜索遍数，仍使用路径补全、2-opt、小规模精确求解等已有组件。当前瓶颈更可能涉及模型的设计空间，以及时间与质量的权衡。[耗时剖析重放](../../experiments/diagnosis_v1016_profile/README.md)

同等开发实验又揭示了另一类经验：一个新思想的第一版，与少量开发后的水平相差很大。20 组新设计中 17 组改善，多数在 3–5 次生成内完成主要提升。这让研究重点转向怎样用少量试验判断设计潜力。[同等开发](../../experiments/diagnosis_v1016_develop/README.md)

## 可以迁移的认识

经验的价值取决于它服务的决定。形成路径帮助理解当前结构；直接尝试揭示同一起点上的改动效果；开发曲线帮助判断设计潜力。哪种信息值得展示，应从当前决策缺什么、模型实际改变什么来判断。

程序按规范代码识别，形成关系记录来源，训练分记录评价结果。把这三种信息分清，可以同时观察代码变化、计算行为与质量变化。运行中的记录方式见[方法说明](../01-搜索方法/尝试记录与经验使用.md)，当前问题见[研究主线](研究主线与问题.md)。
