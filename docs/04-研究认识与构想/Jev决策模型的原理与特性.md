# Jev 决策模型的原理与特性

Jev 是 TypeSafe 的决策模型。它读一份材料和一个明确的问题，返回答案与概率，不生成文字。适合它的问题，是行家看一眼材料、几秒内能判断的问题。复杂决策要拆成多个这样的判断，再由代码组合。

前两节依据官方文档（docs.typesafe.ai 的 Introduction、AI Primer、System One、Confidence 等页）。第三节是我们在搜索记录上的实测，详见[Jev 父代与算子决策探索](../03-现象与检验/2026-10-15-Jev父代与算子决策探索.md)。

## 原理

**训练目标是校准的决策。** Jev 从预训练语言模型出发，用 RLCD（reinforcement learning for calibrated decisions）训练。三种后训练方式的目标不同：

| 方式 | 训练目标 | 产物 |
| --- | --- | --- |
| RLHF | 人更喜欢的回答 | 聊天模型 |
| RLVR | 可验证的正确答案 | 推理模型 |
| RLCD | 概率与实际结果一致 | 决策模型（Jev） |

**校准的含义。** 在大量判断中，Jev 给 0.8 的那些答案，应有约 80% 正确。这是对一批判断的统计性质，不保证单个判断正确。校准只对它训练时见过的那类问题成立。

**System One。** 名称来自卡尼曼的"快思考"。Jev 做直觉式的快判断，不做多步推理，也不输出理由。

**独立评估。** 一次请求含一份材料（state）和多个问题。每个问题并行、独立地对同一份材料评估。增加问题几乎不增加响应时间，问题之间也不互相干扰。

## 特性

**三种题型。**

| 题型 | 问什么 | 返回 |
| --- | --- | --- |
| Choice | 从给定选项中选一个 | 选项、各选项概率、置信度 |
| Score | 按评分表打分 | 分数、各档概率、置信度 |
| Noul | 一个陈述是否为真 | 0–1 的概率 |

**一题一事。** 文档建议每个问题只问一件具体的事。涉及多个独立因素的问题要拆开问，用代码加权组合。权重改变时改代码系数，不改问题。

**避免讨好与模式丢失。** RLHF 奖励人喜欢的回答，会带来迎合与自信的编造，也会让输出只剩一种风格。RLCD 的目标是判断与结果一致，不是让提问者满意。

**输入与成本。** 只接受文本（字符串、JSON、数组）。实测单个问题上限约 32k token，超出返回 400 `max_tokens_exceeded`。按输入计费，`jev-1.13.0` 为每百万 token 0.042 美元。接口为 `POST https://api.typesafe.ai/v1/systemone`，密钥在项目 `.env` 的 `TYPESAFE_API_KEY`。

**适合与不适合。**

| 适合 | 不适合 |
| --- | --- |
| 分类与分流 | 多步推理 |
| 按明确标准评分 | 计数与算术 |
| 核实一个陈述 | 在多个独立因素之间权衡的综合判断 |
| 两段文本之间的语义比较 | 生成代码或解释 |

## 在搜索记录上的实测

以下现象都能用上述原理解释：

| 现象 | 对应的原理 |
| --- | --- |
| 换问法后，最好程序得到的概率从 11% 变到 88%；"改进空间"被读成"分数低" | 快思考，按字面回答被问的那件事 |
| 最好程序失败 0 次与 40 次，概率只从 66% 降到 58% | 不做计数 |
| 在几个思想之间比较"哪个已给够尝试"，能选出尝试最多的一个 | 比较是一眼可做的判断，绝对的是非题要权衡多个因素 |
| 判断两个程序是否同一思想，正反顺序差 0.03–0.11 | 读两段代码的语义比较，正是它擅长的问题 |
| 直接问"选哪个父代"，结果接近按分数和成功记录挑选 | 这是综合问题，按文档应拆开问 |
| 12 个选项时，选项顺序最多改变 0.35；含整份代码的选项顺序差更大 | 选项多、选项长时判断不稳，需要两个顺序取平均 |

## 使用原则

1. 不问"把预算给谁"这类综合问题。把决策拆成原子判断，例如：两个程序是否同一思想、本次改动是否与以前某次相同、代码中是否有某个计算、失败是否因为超时。
2. 结构与计数留在代码中。代码负责记录、计数与组合规则，Jev 负责语义判断。
3. 优先用比较。需要负面证据（例如尝试过多）时，在几个对象之间比较，不对单个对象问绝对的是非题。
4. 问法就是标准。每个问题的措辞决定了判断标准，要按想要的标准写问题。
5. 选项多或选项长时，用两个顺序取平均。
6. "哪个改动会让分数更好"这类预测不在它的训练范围内，其概率是否校准没有保证。评价 Jev 参与的决策，要看实际运行的搜索结果，而不是与记录中单次尝试的结果是否一致。
