# EvoTrace提示词简化计划

反思压缩算法设计经验，Explore获得新鲜的算法思想。修订围绕这两个目的展开，减少逐项登记和排除规则，让模型直接处理算法问题。

本文保留早期修订依据与方案。当前统一实现与两模型回放见[上下文系统核对](../experiments_result/analysis/evotrace_context_system_20261112/README.md)。下文的单字段反思等仍属早期建议，不是当前接口；当前反思允许准确描述经历，不强制提炼规律。以下历史样本不作为新提示词的生成结果。

## 核对范围

实验材料来自北京时间2026-11-12 11:21封存的[审计数据](../experiments_result/analysis/evotrace_audit_20261112_1120/audit.json)。批次为`20261112_095126_evotrace_v1_v4_co4`。`reflection_records`保存实际反思输入、响应与最终经验，`operator_cases`保存生成案例。

该批[反思源码](../experiments_result/evotrace_v1/launch_20261112_095126_evotrace_v1_v4_co4/source/evotrace_v1/reflection.py)和[上下文源码](../experiments_result/evotrace_v1/launch_20261112_095126_evotrace_v1_v4_co4/source/evotrace_v1/context.py)是解释已有输出的依据。独立迁移后的[当前反思](../evotrace_v1/reflection.py)与[当前上下文](../evotrace_v1/context.py)用于确定尚需修改什么。

## 具体问题与修订方向

| 项 | 实验使用的要求及影响 | 工作区现状与后续建议 |
| --- | --- | --- |
| 1. 反思目标偏向登记 | `Write a compact experimental record`、`Update ... record of eliminated trials`要求整理实验记录。模型列齐计算与结果就完成任务，没有必要压缩出设计认识。 | 当前已改为压缩算法设计经验。保留这个方向，并缩短补充规则。 |
| 2. 压缩单位过细 | 路径反思逐项登记新增、替换、移除的公式；旁支反思要求`ONLY`记录相对父代改变的计算。输出容易停留在改动层，难以连接几次尝试中的算法思想。 | 当前任务段已放宽。后续让输出自然描述计算思路及尝试之间的关系；实际代码和差分继续作为输入。 |
| 3. 旧经验只能累加 | 要求保留每个旧方向的最好分数和每个旧错误，同时限制125词。模型需要解决的是旧条目怎样塞进去。多轮反思会不断传递早期台账。 | 当前已允许选择有信息的旧经验。后续删除文档里的逐项保留口径，允许重组、合并和省略不再提供认识的细节。 |
| 4. 输出结构继续拆账 | `analysis`要求检查保留/替换关系，随后分填`retained_changes`、`intermediate_attempts`；旁支填`pruned_attempts`。格式固定了思考对象和叙述结构。 | 当前分析任务已改，但旧字段仍在；路径输出仍拼成`Development ... | Experience ...`。建议两类反思均只返回一个`experience`字符串，不再生成单独的反思核对稿。 |
| 5. 淘汰标签暗示思想结论 | `[Eliminated]`、`Eliminated initial directions`和`Eliminated attempts along this direction`反复进入后续上下文。版本管理事件因此容易获得算法判断的语气。 | 当前已改为经验标签。继续使用中性名称即可，不必再叠加一段“淘汰不意味着什么”的解释。 |
| 6. Explore背负排除任务 | `genuinely different`后列举结构信息、前瞻、迭代、分解、小规模精确求解，又要求避免重加权与已覆盖机制。方法清单可能产生锚定，避重复要求可能把既有经验读成排除列表。 | 当前已改为发展新思想并实现主要计算。保留简短的正向任务，不增加新颖性论证或方向筛选字段。 |
| 7. 方向概览混入实现与管理细节 | 入口`design`直接成为`Core mechanism`；生成模板要求表示、计算、输出以及必要公式和参数。方向概览再附评价次数和多份经验，模型可能花精力比较公式和开发状态。 | 已简化`design`为核心思想与实际计算，删除固定句数和分栏字数要求。累计次数与结构筛选信息留在记录中；Explore展示核心思路与自然分段的经验，不增加全局总结调用。 |
| 8. 文档仍会把台账要求带回来 | `反思简化设计.md`仍把按公式配分数、参数合并区间和分栏词数写成当前约定。以后按文档维护，可能重新加回已经删去的要求。 | 实现方案确定后同步反思设计与方法正文，写清经验压缩的目的、实际材料和最终输出即可。 |

前四项直接决定了现有反思为何像台账。第五至七项说明台账怎样继续影响后续设计。提示词是否因此降低最终搜索收益，还需要保持其他机制一致的比较。

Refine与Crossover的主指令已经较短，分别要求改进当前算法、借用互补计算。现有证据不足以要求同时重写它们。任务接口、完整实现、合法JSON和真实评价材料继续保留。

## 三个真实输出与预期表达

下列“预期表达”由本次讨论手工改写，用于说明期望的经验层次，未调用模型验证。它们不是今后强制套用的模板。

### TSP：路径经验保存参数，遗漏局部规划的设计思路

定位：`kind=variation, task=tsp_construct, seed=0, cycle=1, attempt=64, target_id=25`。

实际经验节选：

> Replaced fixed K=min(8,n) with dynamic K=n if n<=12 else 8; added destination distance penalty term -alpha*dest_dist[end_node] ... alpha=0.6/(1+0.3*n).

随后又登记旧alpha公式和固定K的分数。这段内容能恢复改动，但读者仍需自己从参数中提取“局部路径求解怎样考虑后续连接”。

预期表达：

> 这段演化在局部路径求解中逐步引入终点信息，并在剩余节点较少时扩大求解范围。算法开始同时考虑眼前的局部路径和它与终点的衔接，这一组版本的成绩由约6.50改善到6.36。留下的主要经验是局部求解与整条路线连接之间的关系，具体权重是这一思路的实现选择。

这里保留算法变化及实测结果，把精确参数留在原始代码中；没有把多项共同变化解释成某个单独参数的已证实贡献。

### CVRP：旁支经验列五个名字，没有连接建模视角

定位：`kind=selection, task=cvrp_aco, seed=0, cycle=1, attempt=64, target_id=0`。

实际经验：

> [Eliminated] Inverse distance heuristic: score 13.096; Centroid angle penalty heuristic: score 18.6464; Threshold-filtered inverse squared distance: score 13.5068; Randomized nearest-neighbor edge frequency: score 16.287; Demand-weighted inverse distance scaling: score 14.6471.

预期表达：

> 这些尝试从两种视角构造边先验：用距离、需求或几何方向直接评价边，以及先构造路线、再用边的出现频率表达路线经验。本组距离倒数版本约13.10，路线频率版本约16.29。后者这次表现较差，但它提供了从完整路线反推边先验的另一种建模思路，使后续设计可以同时思考局部边偏好和整体路线结构。

这段经验连接了不同尝试的计算思想，并用少数结果保留实际经历。它没有要求后续避开路线构造，也没有将一次评价升级为整个方向的结论。

### FSSP：公式清单没有形成关于扰动对象的认识

定位：`kind=selection, task=fssp_gls, seed=1, cycle=1, attempt=64, target_id=25`。

实际经验：

> [Eliminated] delay_in scoring (C[i,k]-C[i-1,k]) in job selection: score 3909.19-3904.06; static totals+variance scoring replacing critical path: score 3941.31; tail/head criticality with positive-only noise [0, 0.8*base]: score 3912.69

预期表达：

> 这组尝试围绕怎样识别值得扰动的作业展开：一类利用当前排程中的完工时间关系，一类利用作业自身的总加工量和方差，另一类追踪关键路径。当前排程相关的几个版本约3904—3913，静态统计版本约3941。这些经历把关注点带到作业在当前排程中的作用，也留下了选择扰动对象与设计扰动方式相结合的思路。

输入代码中的`C[i,k]-C[i-1,k]`是相邻作业在同一机器上的完工时间差，不能仅凭变量名把它直接称为等待时间。改写保留准确的计算含义，也不将同时发生的评分与噪声变化拆成独立因果结论。

## 拟用的短提示

共同的任务说明、函数接口、真实代码与结果继续由程序提供。以下只替换任务段和反思输出约定。

路径反思：

> Compress this evolution path into useful algorithm-design experience. Read the implementations, experimental outcomes, and earlier experience together. Explain how the algorithmic idea developed and distill the insights that can inform further design. Return one JSON object with an "experience" string containing a concise, coherent paragraph.

旁支反思：

> Distill useful algorithm-design experience from these alternative attempts, their outcomes, and earlier experience. Connect the computational ideas and synthesize what was learned in a concise, coherent paragraph that can inform further design. Return one JSON object with an "experience" string.

Explore：

> Develop a fresh algorithmic idea for this problem and implement it. Draw inspiration from the current algorithm, the other approaches, and accumulated experience.

生成后的design：

> Briefly describe the core algorithmic idea and how the implemented computation produces the output.

这些提示明确任务和输出即可。算法经验由具体材料产生，不再增加“必须总结几个洞见”“逐项说明什么该做或不该做”等要求。经验长度沿用现有总体上下文上限，不再分配多栏固定词数。

## 实施顺序与检查

1. **先贯通反思输出。** 将两类反思任务、JSON schema、解析和格式化一起简化为`experience`，沿用现有树上存储位置。更新现有相关测试。工作区已经修订的任务语义直接沿用，不叠加新的规矩。
2. **再整理后续输入，生成侧已落实。** Explore围绕新鲜思想构思，初始化沿用同一方向；简化analysis与design，方向概览展示思想和经验，累计计数保留在元数据中。代码差分独立成块，共同祖先只展示一次。生成侧方法说明已同步，反思设计由并行线程维护。
3. **用相同真实切片检查内容。** 固定代码、评价和模型条件，比较新旧提示生成的经验是否从登记条目变成准确且有用的算法认识。重点读取上述三个案例及已有反复合并旧经验的案例。宏观表述仍要能回到实际代码和结果。
4. **再看后续生成。** 将新旧经验分别放回相同树状态的生成上下文，检查模型提出并实现了什么算法思路。短回放能暴露语义或代码问题；完整收益还需跨越反思与后续开发的搜索比较。

父代选择、算子比例、种群管理、评价预算和运行中的冻结实验均不在这次提示词修订范围内。生成侧的离线检查不等于实际模型质量或完整搜索收益验证。

生成侧已在原冻结批次的28个真实重构状态上检查84组三算子上下文，另检查经验关闭和交叉参考源码开启的展示。任务与函数接口、当前完整实现、所选方向的入口思想与经验均保留，渲染不改变树状态。检查清单、源码哈希和12份四任务样例见[生成上下文核对](../experiments_result/analysis/evotrace_generation_context_review/manifest.json)。这些样例沿用历史快照中的旧经验，未重新调用反思模型。全仓493项测试通过；本线程没有调用真实模型或干预运行中的实验。
