## 2026-09-18：V10.11—V11 历史上下文与预算调度复盘

- **研究问题**：V10.11 的任务/阶段/算子上下文差异是否足以支持 V11 的算子条件化设计，以及 V11 退化主要来自预算分配、上下文内容还是提示措辞。
- **证据**：在相同每路 1000 次真实评价下重算 V10.11 四组 E100/E250/E500/E750/E1000 曲线、算子 `parent_improved`/`frontier_improved`、关键节点形成链和 held-out；审计 V11 五重复的父代质量百分位、形成深度、参考节点、提示长度、失败类型和算子改进率。产物见 `V10.11-实验结果.md`、`V11.0-实验结果.md`、`TraceAAD-V11.0-机制设计.md` 及两批 `events.jsonl`。
- **结论强度**：高：V10.11 证明的是任务/阶段相关的证据需求，不是固定的任务×算子偏好；V11 的总体退化首先对应统一精英父代调度，Pivot 父代改进率由 V10 的约 9%–16% 降至 V11 的约 1.5%–3.2%，同时形成链显著变深。中高：Pivot/Fuse 只接收 Idea+fitness、缺少可执行代码和时序关系，倒数排名抽样还扩大了长尾噪声，这解释了任务分化和部分运行失败，但与调度联合变化，不能单独归因。中低：提示措辞不是首因；V11 提示较短、格式失败率低，尚无同调度下的提示孤立对照。
- **关键边界**：V11 并非全面失败，CVRP 五重复补齐后 held-out 相对 V10.11 generic 在 50/100/200 分别改善 3.70%/4.46%/3.75%；TSP、OP、VRPTW 退化，OBP 接近不变。V10 的“算子偏好”需区分局部父代改进和全局前沿推进，Pivot 局部改进高但几乎不产出最终前沿。
- **下一步**：先做预算分配×上下文的受控拆分，至少比较 V10 ESS/随机 Pivot 与 V11 最高分选父，在同一上下文下记录阶段曲线、父代/前沿改进、低质量分支获得开发的延迟、参考实际进入代码的证据和 held-out；在此之前不把静态任务×算子映射升级为动态控制器。

## 2026-09-19：V11 机制修正方向

- **预算分配的实现缺陷**：V11 在 `traceaad_v11_0/traceaad.py` 中对每个 distinct AST code 计算百分位和尝试次数，并在 `select_parent()` 中直接选择最高分 code；探索计数不是谱系、分支或结构簇的覆盖计数。V11 五任务运行中 `num_codes` 通常接近 `num_nodes`，因此 `attempts` 几乎不能表达分支探索，`q + exploration_bonus` 实际退化为精英贪心。
- **建议的最小修正**：恢复 V10.11 的 ESS 校准 softmax 作为父代采样基础，保留非零的 Pivot/ donor 均匀质量，新增谱系/结构簇覆盖、parent/frontier 改进率和最近开发时间；按算子使用条件化父代分布，禁止所有算子共享同一最高分父代选择器。
- **上下文融合方向**：Refine/Tune 先使用 TSP/VRPTW 已验证的短形成轨迹；Pivot/Fuse 使用 CVRP/OBP 方向的精英参考，但参考卡必须包含短代码机制摘要、实际决策变化、前后 fitness 和约束，而不是只有 Idea+fitness；OP 保留形成链与紧凑代码的阶段性组合。当前证据支持任务×上下文先验，不足以直接宣称每个算子已有独立最优上下文，因此需要记录并更新 task×operator×context 的实际收益。
- **耦合结构**：预算选择、算子选择和上下文路由应组成一个受限 portfolio：Refine/Tune 偏向高质量连续开发，Pivot 保留最低探索配额，Fuse 选择行为或机制互补的跨谱系 donor；每个预算块保留探索下限，不能只靠分数上的小 bonus 获得探索。
- **验证顺序**：先做“调度修正、V10 generic 上下文”和“V10 ESS 调度、上下文路由修正”两个单因素对照，再测试组合机制；统一记录 parent/frontier 改进、谱系覆盖、参考机制进入代码、代码复杂度、LLM/评测成本和 held-out，避免再次把预算与上下文的联合变化归到单一因素。

## 2026-09-20：V11.0 与 V10.11 四组控制的局部平台回查

- **研究问题**：V11.1 的路径方差、TSP 退化和“parent improvement 不转成 frontier improvement”是否已经存在于 V11.0，以及 V10.11 的 generic、no_traj、idea_code、rand_ctx 是否也有同一问题。
- **证据**：复核 V11.0 机制/结果报告、V10.11 四批完整训练与 held-out 报告，并从两版本各批次 `events.jsonl` 重算 parent-improved、frontier-improved、连续无 frontier 的平台长度和选择信息。
- **判断**：V11.0 确实已有该问题，而且预算机制更硬：从 V10.11 的 ESS-8 质量抽样改成唯一 AST code 的最高百分位选择，取消 Pivot 的 50% 均匀混合；报告记录的高百分位开发集中、best 谱系更深和 Pivot parent 改进率下降，与精英锁定解释一致。V11.0 的 TSP/OP/VRPTW held-out 退化也与此方向相符。
- **控制组边界**：V10.11 四组都出现局部平台信号。原始日志中 parent improvement 之后没有 frontier improvement 的比例大致处在 70%–90% 区间，且各组各任务都能看到持续上百次评价无新 frontier 的片段；但四组共享 ESS-8 质量分配、Pivot 均匀混合和相同预算，没有 V11.0 那种最高分确定性父代锁定证据。因此应称为搜索共有的局部改良/前沿脱钩，不应把四组都归因于 V11.0 式机会分配退化。
- **任务分化**：generic 的短形成轨迹在 TSP/VRPTW 最稳；no_traj 的 TSP 方差增大但 OBP 更好；idea_code 的 TSP 退化、VRPTW 方差与上下文溢出明显；rand_ctx 的 TSP/VRPTW 不能替代形成关系，OP 方差最大，CVRP/OBP 反而受益。四组更像上下文与任务结构失配，而非同一局部最优机制。
- **下一步**：用固定父代、固定算子和固定上下文做候选级匹配实验，分别估计即时 parent 改进和后续窗口 frontier 改进；再单独比较 ESS 抽样、V11 argmax 与最低探索配额。当前不要用四组训练 best 或 V11.1 partial 结果直接宣称因果。

## 2026-09-20：V11.1 当前失败信号与改进优先级

- **当前边界**：`20260920_v111_manual` 仍有运行中的 tmux/run 进程，不能把本批当作最终质量或 held-out 结果。以下使用当前事件日志作机制诊断。
- **首要机制信号**：在共同 E500 截面，五任务各路的 parent improvement 中约 88%–97% 没有转成 frontier improvement；四算子合计的 frontier/parent 比例仅约 8%–10%。这比早期快照更强，说明问题不是单个 TSP 路线的偶然平台。
- **第二个机制信号**：固定 `tau=0.2` 的节点 softmax 仍按质量百分位分配机会，低次数奖励只有 0.1 权重，没有最低探索质量或 frontier 潜力估计。当前 E500 选中父代的平均 percentile 约 0.79，低于 0.5 的父代约 8%，说明探索样本比例偏低且尚未稳定转化为前沿收益；新节点和同一行为族仍被当作独立节点。
- **第三个机制信号**：上下文与算子/任务的匹配仍不充分。TSP 当前 Pivot 有效率约 72%、frontier/parent 约 4%；Fuse 提示中位长度约 3836 tokens，TSP 的 Fuse frontier/parent 约 7%。TSP、VRPTW 需要形成关系，Idea+fitness 档案卡不能稳定替代；Fuse 的第二完整代码又增加了提示和程序复杂度。
- **工程事实**：当前手工批的 TSP 事件中约 4288 个候选有 791 个无有效节点，其中约 372 次 runtime error、307 次 timeout；各 task 的有效率不同。端点统一按同一个 Qwen3.8-27B 模型记录，后续应把这些失败归入候选可靠性和有效预算问题，不能归因于“本地模型与远程模型不同”。
- **改进顺序**：先让当前批次完成；下一批固定模型/端点和真实评价预算，单独比较 `tau=0.2`、ESS-8 和带 10%–20% 均匀质量下限的抽样。若 frontier 改善回升，再单独测试 Pivot 的可执行参考代码/机制 delta 与短形成轨迹，Fuse 减少档案卡并限制第二代码复杂度；最后才考虑行为簇、复杂度惩罚或 task router。
