## 2026-09-18：V10.11—V11 历史上下文与预算调度复盘

- **研究问题**：V10.11 的任务/阶段/算子上下文差异是否足以支持 V11 的算子条件化设计，以及 V11 退化主要来自预算分配、上下文内容还是提示措辞。
- **证据**：在相同每路 1000 次真实评价下重算 V10.11 四组 E100/E250/E500/E750/E1000 曲线、算子 `parent_improved`/`frontier_improved`、关键节点形成链和 held-out；审计 V11 五重复的父代质量百分位、形成深度、参考节点、提示长度、失败类型和算子改进率。产物见 `V10.11-实验结果.md`、`V11.0-实验结果.md`、`TraceAAD-V11.0-机制设计.md` 及两批 `events.jsonl`。
- **结论强度**：高：V10.11 证明的是任务/阶段相关的证据需求，不是固定的任务×算子偏好；V11 的总体退化首先对应统一精英父代调度，Pivot 父代改进率由 V10 的约 9%–16% 降至 V11 的约 1.5%–3.2%，同时形成链显著变深。中高：Pivot/Fuse 只接收 Idea+fitness、缺少可执行代码和时序关系，倒数排名抽样还扩大了长尾噪声，这解释了任务分化和部分运行失败，但与调度联合变化，不能单独归因。中低：提示措辞不是首因；V11 提示较短、格式失败率低，尚无同调度下的提示孤立对照。
- **关键边界**：V11 并非全面失败，CVRP 五重复补齐后 held-out 相对 V10.11 generic 在 50/100/200 分别改善 3.70%/4.46%/3.75%；TSP、OP、VRPTW 退化，OBP 接近不变。V10 的“算子偏好”需区分局部父代改进和全局前沿推进，Pivot 局部改进高但几乎不产出最终前沿。
- **下一步**：先做预算分配×上下文的受控拆分，至少比较 V10 ESS/随机 Pivot 与 V11 最高分选父，在同一上下文下记录阶段曲线、父代/前沿改进、低质量分支获得开发的延迟、参考实际进入代码的证据和 held-out；在此之前不把静态任务×算子映射升级为动态控制器。

### 2026-09-19：V11.1 节点级预算机制进一步简化

## 2026-09-19：V11 机制修正方向

- **预算分配的实现缺陷**：V11 在 `traceaad_v11_0/traceaad.py` 中对每个 distinct AST code 计算百分位和尝试次数，并在 `select_parent()` 中直接选择最高分 code；探索计数不是谱系、分支或结构簇的覆盖计数。V11 五任务运行中 `num_codes` 通常接近 `num_nodes`，因此 `attempts` 几乎不能表达分支探索，`q + exploration_bonus` 实际退化为精英贪心。
- **建议的最小修正**：恢复 V10.11 的 ESS 校准 softmax 作为父代采样基础，保留非零的 Pivot/ donor 均匀质量，新增谱系/结构簇覆盖、parent/frontier 改进率和最近开发时间；按算子使用条件化父代分布，禁止所有算子共享同一最高分父代选择器。
- **上下文融合方向**：Refine/Tune 先使用 TSP/VRPTW 已验证的短形成轨迹；Pivot/Fuse 使用 CVRP/OBP 方向的精英参考，但参考卡必须包含短代码机制摘要、实际决策变化、前后 fitness 和约束，而不是只有 Idea+fitness；OP 保留形成链与紧凑代码的阶段性组合。当前证据支持任务×上下文先验，不足以直接宣称每个算子已有独立最优上下文，因此需要记录并更新 task×operator×context 的实际收益。
- **耦合结构**：预算选择、算子选择和上下文路由应组成一个受限 portfolio：Refine/Tune 偏向高质量连续开发，Pivot 保留最低探索配额，Fuse 选择行为或机制互补的跨谱系 donor；每个预算块保留探索下限，不能只靠分数上的小 bonus 获得探索。
- **验证顺序**：先做“调度修正、V10 generic 上下文”和“V10 ESS 调度、上下文路由修正”两个单因素对照，再测试组合机制；统一记录 parent/frontier 改进、谱系覆盖、参考机制进入代码、代码复杂度、LLM/评测成本和 held-out，避免再次把预算与上下文的联合变化归到单一因素。
