## 2026-09-21：V10.12 最小融合方案建议

- **建议版本**：以 V10.11 generic 为唯一基线，只改生成上下文；保留 ESS-8 质量分配、Pivot 1:1 均匀混合、Fuse donor、四算子比例、一次修复、任务契约、模型与每路 1000 次真实评价。
- **混合上下文**：所有算子继续看到当前程序与最近 8 条短形成轨迹；每次额外加入 2 张档案 profile card；每张卡只包含一个算法节点的 Idea 与实测 fitness，按现有 rand_ctx 的 rank-softmax tau=8 无放回抽样，排除当前父代。档案卡只作为补充证据，不替换形成顺序；Fuse 保留原 donor 完整代码。
- **机制假设**：短轨迹保留 TSP/VRPTW 所需的连续关系，档案卡提供 CVRP/OBP 所需的跨分支机制；低数量档案卡限制提示负担和随机噪声。该假设不预设 task router，也不假设算子标签已经证明了最优历史匹配。
- **检验**：V10.12 与 V10.11 generic、V10.11 rand_ctx 同时比较，五任务×三重复×E1000；训练 best、E500/E1000 frontier、parent-to-frontier 转化、有效率、提示 token 与运行错误分别记录，并做同规模测试。
- **停止门**：若 TSP/VRPTW 任一任务相对 generic 的同规模测试恶化超过 1%，或提示超限/有效率明显恶化，停止扩大档案卡数量；若 CVRP/OBP 没有改善且构造型任务受损，回退为 V10.11 generic。只有在至少一个档案受益任务改善且 TSP/VRPTW 不受实质损害后，才考虑算子条件化或动态路由。
