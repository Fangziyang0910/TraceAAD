# 初始化机制比较与通用方案

2026-09-09。状态：历史档案核查完成，感知已有方法的初始化已纳入 V10.9（1091），研究收益待验证；原 1090 批次单独归档。研究目标是改善有限总预算下的最终算法质量，初始化分数只是一项中间指标。

## 哪些版本初始化成绩最好

核查范围是 V9.7、V9.14、V9.19 fixed、V10.1—V10.8（V10.7 与 V10.7R 分开）的12组版本配置，共177路、1416个根。V9.7 的 VRPTW 档案不在本次可用组中。每路均有8个根，以“每路最好根的 fitness，再对三个重复取平均”比较；不把 bootstrap 子代算作根。各路路径、评分与初始化边界见统计摘要。可在仓库根目录运行核查脚本重算 TraceAAD 表。

| 任务 | 本次核查中根节点成绩最好的版本 | 三次最好根的均值 | V10.8 对应均值 |
| --- | --- | ---: | ---: |
| TSP ↓ | V10.3 | 6.8696 | 6.9599 |
| CVRP ↓ | V10.5 | 11.9048 | 13.0660 |
| OP ↑ | V10.3 | 13.6620 | 12.8867 |
| OBP ↓ | 全部并列 | 744.5000 | 744.5000 |
| VRPTW ↓ | V9.19 fixed | 21.0867 | 21.8333 |

这不是同条件初始化消融。历史模型服务、输出预算、种子等不同，例如 V9.19 为 Qwen3.6、8K输出，V10系列为 Qwen3.8、16K输出；三个重复也不足以证明排名稳定。V10.3、V10.5 的初始化仍主要是固定提示独立采样，不能把它们的数值领先解释成已经找到更优的初始化机制。

“根节点起点最高”与“后续最好算法从哪里长出来”也不同：历史 TSP 最强的 V9.14，三个最好根均值为6.9873，并非此表最好；最终却形成5.74左右的强程序。V9.7 CVRP 初始最好根均值15.0049，也不是最好初始化分数。

## 真正值得借鉴的机制

### V9.7：先给每个根一次开发机会

根生成完后，V9.7 对每个根执行一次 bootstrap Refine，再进入正常分配。代码见 `llm4ad/method/traceaad_v9_7/traceaad.py:_initialize`；每个根获得一次生成机会，不保证子代有效或改善。

CVRP rep1、rep2 的最终最好主父链都起于根1，初始成绩18.8405，首次 bootstrap 后为11.8381，最终分别到8.6873、8.7609。rep1 另一个初始根已达到13.9598：若只看根分数，这个后来成功的方向很容易被低估。rep3 最好链起于初始13.9598的根3，其首次 bootstrap 退步到14.6774；一次开发失败也不能否定整个结构。

值得继承的是低成本试开发后再判断，而不是每个根永远均分预算，或按一次改进量直接预测终局。

### MCTS-AHD：初始集合逐步形成，并参考已有程序

当前实现和20260824批次实际调用均显示：第一个根用 i1，后续使用 e1，提供已有算法的代码和思想，要求形成不同结构。它试图获得互补起点，较重复空白提示更接近有意识地扩展搜索方向。

但其同评分排除规则不宜照搬：同分可能来自不同执行行为或不同可开发结构。实际 OP 三路进入正常搜索前的最好分仅9.486、8.924、12.826，明显不是历史最高的起点，最终却都超过14.8。OBP 三路初始化边界对应样本位置4、20、23，初始最好仍均为744.5。它说明“要求不同”与“过滤同分”既不保证找到好结构，也可能多花预算。其初始根目标数和TraceAAD也不同，这段对照用于机制分析，不能当作同预算胜负。样本位置和生成调用数分别记录，不能把所有生成调用都解释成真实评价。

值得继承的是利用已有实码寻找未覆盖的假设；不要继承按分数去重或为了新颖强迫彻底抛弃有效部件。

### CALM：初始化中已经包含数值开发

OBP seed 成绩759.25，低于普通 Best Fit 的744.5，但首次 LLM 编辑前，24次初始数值试验已将三路最好推进到726.25、740.5、739.25。这是初始开发价值的强过程证据，并不证明任意数值丰富的程序都值得开发。

这一实现使用任务专属 seed 和任务参数，不能作为本方案的通用初始化直接照搬。seed 的实际评价也未计入原 CALM 的 evaluation_budget，因此这段初始化包含24次数值试验加1次seed评价。归档候选只有17/17/16个，不能据此缩减其预算。

值得继承的是检查一个结构经少量校准后是否能兑现价值；初始程序由同一通用生成机制产生，不手工注入任务答案或历史赢家。

## 原 V10.9（1090）的初始化问题

22:32快照：同一路每次 Init 提示哈希相同，无先前根节点或试验上下文。V10.9 的 Init AST 去重只对父代/donor生效，而 Init 没有两者；近期开发池又要求存在父代，根节点不进入该池。

OBP rep1 的8个根 AST 各不同，但实码分别是负剩余量、其等价表达、倒数剩余量，以及不改变排序的小项。实际物品为正整数、输入为可行箱容量；这些规则均偏好容量最小的可行箱。1000个随机可行状态探针中，8个程序都与 Best Fit 一致。TSP rep1 的根2/4/5在1000个随机欧氏状态中都与最小化 `d(current,j)+d(j,destination)` 一致；根4多除以一个对所有候选相同的距离，常规非退化情况下不改变主排序，特殊并列处理仍可能不同。

因此“8个不同代码的有效根”不足以证明覆盖了8种方法。另一方面，同一行为的不同代码也可能包含有用组件或提供不同开发空间，探针相似不能直接作为永久删除依据。

V10.9 初始化结束恰有8个候选，质量 ESS 目标也是8，首次非 Pivot 分布实际为均匀。后续档案增长才逐步集中；这仍不等于每个根都获得了明确的一次试开发。当前继承的初始化入口应视为后续值得改进的模块，不能把代码审查通过解释成它的研究机制已充分优化。

## 当前方案：后续起点感知已有方法

用户明确去掉初始化中每根一次开发的安排。当前方案只改变根生成所依据的上下文：第一个起点从零生成，后续起点知道已经有哪些方法，并据此提出有竞争理由的新起点。V9.7 与 CALM 的历史案例保留为研究证据，不作为本方案的 bootstrap 要求。

初始化的目标是形成一组有竞争潜力、能提供互补部件的起点。当前独立重复提示没有利用已经花预算获得的程序与成绩；将这些事实用于下一次生成，是直接针对这一缺口的改动。

1. **第一个起点独立生成。** 只提供任务接口、目标、执行限制与统一输出要求，不注入任务专属种子程序。
2. **后续起点看到已有实码。** 在完整上下文容量内展示已有根的代码与实测成绩；放不下时使用有明确来源的少量代表，不能截断程序，也不应只按分数保留最高者。实现依次尝试最新、最早、次新、次早根，整块纳入或跳过；这是时间覆盖，不引入未经验证的思想相似度模型。
3. **提示要求有依据地提出另一种方法。** 先理解已有方法的主要决策假设，再提出可能改善求解表现的不同假设。有效组件可以复用和重新组织；不强迫所有公式、辅助计算都不同。仅改变名称、分数尺度或不改变选择的单调变换，不算新的决策方法。输出仍为一次生成的自包含 Idea 与完整代码，不额外增加分析调用。
4. **开发交回正常搜索。** 根生成完成后，仍由后续 Refine、Tune、Fuse、Pivot 分配开发机会；不插入每根一次的强制开发阶段。

保留当前8个有效根目标及真实评价记账，优先只比较上下文这一因素。严格输入代码复制可在评价前过滤；同评分不直接排除，避免为了凑齐不同分数而不断重试，也避免丢失不同组件或开发空间。生成失败和评价失败继续按已有规则记录，任何额外初始化预算上限应单独说明，不能隐含改变对照条件。

这里的关键要求是“理解已有什么，再提出值得增加什么”。已有程序是比较材料，不是必须围绕它们修改的宿主，也不是禁止再次使用其部件的清单。参照可能造成锚定，因此应检查实际主决策是否发生变化，不能用提示中出现“不同”或代码数量增加宣布机制有效。

所有任务共用这一流程与提示结构。模型依据各自接口和实码理解任务，不手工规定不同任务的算法菜单。初始化之后仍持续探索，不把探索限定在前期。

## 如何尽快验证

只比较两个初始化版本：原有独立生成与感知已有方法的顺序生成。两组保持8个有效根目标、相同生成模型、输出上限、真实评价记账和1000次总预算；后续搜索机制完全相同，均不增加 bootstrap。

先看新上下文是否减少重复决策方法，同时记录初始化评价次数、失败/复制次数与输入tokens，防止把更高成本误认为更高效率。随后比较预算50/100/1000处最好值、根作为宿主及donor产生的延迟收益，最终用完整搜索与泛化判断价值。初始分数或方向数量只能帮助解释结果。

方案已按上述边界实现为 1091，见机制设计；新批从零开始，既有 1090 实验保持独立，不构成完整的同预算消融。当前主要借鉴 MCTS-AHD 的参照生成机制；V9.7 和 CALM 的开发证据用于提醒我们不要按根的初始分数判断其全部价值。
