# 父代来时路完整搜索消融（V9.7-PP vs V9.7-CO）

## 1. 实验目标与协议

在 V9.7 完整搜索框架下，检验生成上下文从 code-only（无形成历史）扩展为包含父代来时路（形成历史），在 1000 次评价预算下的 search best 与测试集泛化表现。

- **对照臂**：
  - **CO (Code-Only)**：任务说明 + 当前 Fitness + 完整代码 + 意图指令 + 输出契约，不含任何历史事件区。
  - **PP (Parent Path)**：标准上下文，包含至多 8 条父代形成事件与操作记录。
- **实验规模**：4 任务（Online Bin Packing、TSP Construct、OP-ACO、CVRP-ACO）× 3 随机种子 × 2 实验臂 = 24 个 1000-eval 完整搜索运行；同任务同 seed 严格配对。

## 3. 机制分析与决策

### 3.1 跨任务表现汇总

train best 均值（3 seed）与测试集均值的臂间方向，逐 seed 配对方向以 train best 计：

| 任务 | train best 均值（PP vs CO） | seed 方向 | 测试列方向 |
| --- | --- | --- | --- |
| TSP | 5.7840 vs 5.7534（CO 优） | CO 2–1 | TSP50：CO 优 |
| CVRP | 8.9703 vs 8.8801（PP 优） | PP 2–1 | CVRP50：CO 优 |
| OP | 14.7733 vs 14.4393（PP 优） | PP 2–1 | OP50：PP 优 |
| OBP | −726.58 vs −726.58（平局） | PP 2–1 | 四测试设置中 CO 3 个更优，PP 在 1k_100 更优 |

### 3.2 决策结论

1. **机制事实**：四任务结果呈现明显方向分裂（OP 倾向支持形成历史 PP，TSP 偏向无历史纯代码 CO，CVRP 与 OBP 处于随机噪声范围）。
2. **设计决策**：父代形成历史在完整搜索中不存在跨任务一致的普遍增益，因此**不作为全局默认上下文**；后续版本转为按算子特性条件化精简提供。
