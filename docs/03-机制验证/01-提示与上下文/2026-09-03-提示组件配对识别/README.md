# V10.1/V10.2 提示与上下文配对识别

## 1. 实验目标与配对协议

本实验识别从 V10.1 到 V10.2 的提示词与代码上下文改动是否对单步提议（proposal）质量产生显著影响。

- **实验设计**：固定同一任务、父节点、父代来时路、Fuse 算子与 donor，对 Qwen3.8-27B 后端使用相同采样种子，依次比较五个累积文本条件：
  1. 正式运行基线：`V10.1`
  2. `+ Implementation Principle`
  3. `+ Current/Donor 代码去注释`
  4. `+ V10.2 Fuse instruction`
  5. 完整 `V10.2`（补入剩余来时路序号、Idea 标签与输出契约变化）
- **锚点与采样**：
  - 来自 V10.1 与 V10.2 完成 1000 次评价的搜索状态。五任务分别从两个版本各抽 6 个 Fuse 状态（按父节点适应度分低、中、高三层均衡抽样），共 60 个状态、300 次生成。
  - 另对五任务运行 20 个 `Init` 配对 block（40 次生成），合计 340 次生成。
- **评价响应指标**：
  - $\Delta f = f_{child} - f_{parent}$（仅在有效候选上统计）；
  - 无条件改善率（有效且严格超父比例）；
  - 运行时无效（invalid）率。

## 3. 机制分析与决策

1. **文本成分的效果具有任务差异**：各文本细分成分（原则说明、去注释、算子描述）未呈现跨任务通赢的单一开关。OBP 的局部极端退化减少是值得复核的信号，不能据此判定某一成分普遍降低尾部风险。
2. **当时的 Prompt 选择**：
   - 坚持“精简与契约优先”原则，突出代码接口和输出约束，避免堆砌自然语言解释。
   - 单步细微修饰收益有限，后续关于上下文机制的研究直接转向跨代际宏观组织范式对比。
