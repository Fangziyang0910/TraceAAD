# 机制验证总览

机制验证围绕一个问题展开：搜索中观察到的收益来自哪类历史证据、生成行为和预算决策。每组实验把设计假设连接到代码行为和真实评价，服务于 TraceAAD 的论文主张。

## 提示与上下文

固定当前程序、任务和生成操作，比较形成轨迹、无历史、随机历史和提示组件，测量历史证据对候选质量、代码行为和后续开发的影响。现有证据显示：形成轨迹在 TSP 与 VRPTW 的连续协调中有效，跨分支精英档案在 CVRP 的多信号组合中有效，OBP 需要进一步观察排序边界的真实变化。

## 搜索调度与预算分配

预算实验把父代质量、开发次数、谱系覆盖和新方向机会分开测量。连续改进的价值取决于任务结构：CVRP 的高质量算法族适合持续开发，TSP、OP 和 OBP 需要保留替代路线机会。调度研究因此从全局固定规则转向任务和状态条件化。

## 算子动力学与两步价值

算子实验检验形成状态、开发经验与 Pivot、Fuse、Refine、Tune 之间的关系。结果把机制分析的重点放在“哪类证据改变哪类代码行为”：形成关系用于连续协调，跨分支机制用于组合，行为和排序证据用于边界校准。

## 统一证据链

每个机制结论按以下顺序建立：

1. 上下文提供与当前设计相关的证据；
2. 模型生成对应的代码变化；
3. 代码变化改变下游决策或执行行为；
4. 候选超过父代或参考程序；
5. 改进在后续开发或 held-out 实例中保持。

解析率、结构距离、算子标签和单次峰值用于定位生成过程，不直接作为算法质量。机制验证的最终职责是把历史证据和搜索收益连接起来。
