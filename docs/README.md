# TraceAAD：从算法试验中学到了什么

搜索会留下程序、分数和修改记录。要用这些记录改进算法设计，需要检查代码实际改变了什么，以及这些改动能否帮助后续开发。

- **好结构的发现与精炼是两种不同的能力。** TSP 的强结果来自在选点函数内部求解剩余路径；CVRP 的强结果主要来自持续协调已有的几何与容量规则。只看最好程序的祖先链，无法判断应当增加结构探索还是继续精炼。[五任务形成路径](03-机制探索与验证/2026-09-09-强结果形成路径.md)
- **大幅改写是否值得继续开发，要看后续结果。** 18 个固定锚点的两步干预中，没有出现 Pivot 第一步退步、接一次 Refine 后超越起点的案例。若只看第二步相对第一步的增益，会把从严重退化中恢复误认成突破。[Pivot 两步实验](03-机制探索与验证/2026-09-07-Pivot两步价值.md)
- **代码不同，实际决策仍可能相同。** 初始化对照中，OBP 独立生成的根代码彼此不同，但 112 对中有 98 对在两组行为探针上零距；扩大根的行为距离也没有带来稳定的短程收益。[初始化对照](03-机制探索与验证/2026-09-25-初始化方式对照.md)
- **一次改进未必意味着继续开发有收益。** 自适应延长开发在 CVRP 上表现较好，在其他任务上却有相反或混合结果；单次局部增益不能稳定预测继续开发是否划算。[调度对照](03-机制探索与验证/2026-08-24-自适应调度.md)
- **保存尝试及其结果，才能积累可用的经验。** 专家依靠关于改动的经验（效果、代价、失败方式、后续开发结果）设计算法；搜索目前只保存评价成功的程序，超时、错误和重复生成都没有进入数据结构。V10.15-6 中 TSP 超时率随搜索从 2% 升到 16%，错误率也没有下降。[从专家设计过程看自动算法设计](04-研究认识与构想/从专家设计过程看自动算法设计.md)
