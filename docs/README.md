# TraceAAD 研究文档

TraceAAD 研究大语言模型驱动的自动算法设计：在真实评价预算有限的条件下，如何利用已经发生的设计试验，改善下一次算法生成，并把局部改进累积为可迁移的高质量算法。

## 当前主张

TraceAAD 的核心贡献是**算法改进轨迹驱动的经验利用**。系统把候选算法的形成关系、真实评价反馈和跨分支机制组织成与当前设计决策匹配的上下文，使模型能够围绕已有算法继续精炼、吸收互补机制或改变决策边界。

实验表明，历史信息的价值由任务的收益形成结构决定：TSP 与 VRPTW 更依赖短形成轨迹维持机制协调，CVRP 从跨分支精英经验传播中获益，OBP 的关键证据是参考思想进入代码并改变实际 `argmax` 决策，OP 则体现了上下文价值随规模变化的边界。由此，历史上下文不是越多越好，也不存在适用于全部任务的固定组织方式。

## 文档组织

- `01-主线版本`：TraceAAD 各代方法的最终机制定义。版本文档服务于方法复现，不承担实验流水记录。
- `02-实验结果`：主实验结果、冻结口径、各版本结果和机制诊断。结果文档只保留能够支持方法主张的比较与证据。
- `03-机制验证`：围绕提示上下文、预算分配、算法行为和算子动力学的受控证据。
- `04-研究认识与构想`：论文主线、科学问题、收益形成结构和方法定位。
- `05-文献与基线`：外部研究事实、文献阅读和对比方法基准。
- `06-成果与报告`：面向学术汇报的最终材料、图表资产和完整工作流水。工作流水保留每次工作的实现与判断，不纳入论文主线删改。

## 命名规范

- 主线版本使用 `TraceAAD-Vx.y-机制设计.md`；版本演进总表使用 `00-机制设计演进.md`，历史方法使用 `TraceAAD-历史机制.md`。
- 主实验与索引使用 `00-主题.md`；版本结果使用 `Vx.y-实验结果.md`，同一版本的批次在主题后追加 `-正式批`、`-复核批`等明确后缀。
- 日期驱动的分析使用 `YYYY-MM-DD-主题.md`；机制验证目录使用同样的日期主题格式，并以 `README.md` 作为该验证的结论入口。
- 研究认识快照使用 `YYYY-MM-DD-主题.md`；长期维护的证据分析保留主题名，并用连字符分隔对象与分析内容。
- 文献单篇阅读保持 `NN-论文短名.md`，各类索引统一以 `00-` 开头；周报使用 `YYYY-W##-科研周报.md`。
- 工作流水固定使用 `YYYY-W##.md`，每周文档只追加工作留痕，不因整理主线而改名或删除。

## 阅读主线

先阅读 `04-研究认识与构想` 中的研究定位与任务收益结构，再阅读 `02-实验结果` 中的主实验和当前版本诊断，最后查看 `01-主线版本` 与 `03-机制验证` 中的机制定义和受控证据。`05-文献与基线` 保存外部依据，原始 JSON、日志和脚本保存可复核事实。

## 证据口径

论文叙事只使用相同真实评价预算下的结果，并区分训练 best、held-out 泛化、重复均值、单路结果和不完整批次。解析率、修复率、代码长度、结构距离、算子标签和后端信息用于解释搜索行为，不直接作为算法质量。
