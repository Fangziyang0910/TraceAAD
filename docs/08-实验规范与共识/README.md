# 实验规范与共识

任务与计分实现见[任务注册](../../benchmarks/tasks.py)与各任务目录。启动命令见[实验入口](../../experiments/README.md)，状态查询与远端操作见[执行入口](../../experiments/infra/AGENT_OPERATIONS.md)。本文记录条件与共识，运行状态写入批次清单。

## 1. 任务

主比较包含TraceAAD与EoH、ReEvo、MCTS-AHD、FunSearch、PathWise、CALM、Shinka七种基线，使用六个任务，`--suite co6`。所有分数越小越好。自2026-10-11起采用**四项固定框架内的函数进化＋两项完整求解器进化**。

| task key | 问题与规模 | 待进化函数 | 固定框架 | 分数 |
| --- | --- | --- | --- | --- |
| `tsp_construct` | TSP，50节点，单位正方形均匀坐标 | `select_next_node` | 逐步构造：每步给出当前节点、起点、按距离排序的未访问节点和距离矩阵，函数返回其中一个节点；最后一个节点与回程由框架补全 | 平均回路长度 |
| `cvrp_aco` | CVRP，50客户，容量50，需求1–9，仓库(0.5,0.5) | `heuristics` | 每实例开始前调用一次，返回边先验；ACO 30只蚂蚁×100轮，衰减0.9，α=β=1 | 平均最好路线总长，只计不同节点之间的移动 |
| `fssp_gls` | 置换流水车间，50作业×20机器，时长1–99 | `get_matrix_and_jobs` | NEH初始化；200轮，每轮至多3步真实交换／插入下降，再调用一次函数，在扰动矩阵上对返回的1–5个作业做一步最好改进；保留真实最好解 | 平均 makespan |
| `graph_colouring` | G(300, 0.5) | `solve(adjacency)`，返回完整颜色数组 | 不固定求解框架。DSATUR仅为可整体改写的起始代码。评价器检查每条边并统计不同颜色数 | 平均颜色数 |
| `jssp_construct` | 作业车间，20作业×20机器，每个作业随机机器顺序，时长1–99 | `solve(processing_times, machine_order)`，返回完整开始时间矩阵 | 不固定求解框架。Giffler–Thompson＋MWKR仅为可整体改写的起始代码。评价器检查先后与机器互斥 | 平均 makespan |
| `op_aco` | OP，50节点，路程预算3，奖励按到仓库距离 | `heuristics` | 每实例开始前调用一次，返回边先验；ACO 20只蚂蚁×50轮 | 负的平均最好奖励 |

问题定义、函数签名与返回值使用方式写在各任务的 `template.py`，求解与检查逻辑在 `evaluation.py`，数据在 `dataset.py`（TSP为`get_instance.py`）。源码与命令链接见[六任务入口](../../experiments/co6/README.md)。FSSP 和 JSSP 直接返回最大完工时间，图着色直接返回使用颜色数。全部实例等权平均，不按参考算法归一化。

旧版OBP与VRPTW保留用于历史实验，不属于当前六任务主比较。CO-Bench任务适配器已移除。

两项完整求解器每实例只调用一次，允许辅助函数，构造、局部搜索、接受与重启均由程序决定。图着色返回非负整数颜色，编号无需连续。JSSP返回有限非负开始时间，列索引是工序位置。评价器用原始实例独立检查，修改输入副本不能改变约束或目标。

任务key保留以复用运行入口。`jssp_construct`现在表示完整JSSP求解器。两项运行配置的 `task_eval.interface` 为 `full-solver-v1`，评价设置标识也随接口改变。它们与此前的优先级函数实验分批报告。旧档案不改写，不使用当前接口续跑或补测，复现须使用对应批次的源码快照。其余四项的任务条件保持不变。

## 2. 数据

- 每个任务 **训练16个实例，同规模测试50个实例**。两者来自互不重叠的固定随机流，与搜索种子无关。
- TSP：训练种子2024，测试种子2025。CVRP：种子1234的同一随机流中依次取出的不重叠划分。OP：训练种子1234，测试种子4567。FSSP、图着色、JSSP：总种子20261007，每个实例的随机流为 `[总种子, 任务流, 划分流, 实例编号]`。
- 数据与参考值在评价器初始化时生成，不计入限时。

## 3. 评价

- **固定框架任务（TSP、CVRP、FSSP、OP）：生成函数在全部实例上的平均 CPU 时间不得超过 2 秒／实例。** 每个实例先累计全部生成函数调用的CPU时间，再对全部实例等权取平均。函数之外的时间不计入。预算由调用探针计量（进程CPU时间），等待与进程抢占不计入。固定框架不在程序可修改范围内。
- 图着色与JSSP的生成函数是完整 `solve`，平均预算为10秒CPU／实例，覆盖其全部求解过程及调用的辅助函数。没有额外的固定求解器计算。数据与参考生成、输入复制和最终合法性检查不计入函数预算。
- **六个任务的单实例墙钟安全上限统一为120秒**，包含进程启动、固定框架与生成函数，只用来终止卡死或长期不返回的程序。从实例进程启动时计时，等待调度器分配核心的时间不计入。
- 单个实例超过2秒或10秒CPU均额不会直接淘汰。全部实例合法完成后，若`生成函数CPU总时间 / 实例数`超过均额，则该次评价记为超时、不给分。等于均额可以通过。训练16个实例对应32／160秒CPU总预算，测试50个实例对应100／500秒CPU总预算。总量是各实例CPU时间之和，不是并行评价的墙钟时间。
- 任一实例超过120秒安全上限、报错或违反返回值要求，该次评价仍失败，没有分数，并取消剩余实例。不使用成功子集计算平均成绩或平均耗时。成功时目标值按全部实例等权平均。原始评价记录保存逐实例时间、CPU总时间与`mean_function_cpu_seconds`。多评价种子各自独立检查全部实例的平均预算。
- 新规则使用`revision=research-protocol-v6-20261012-raw-objective`及`function_budget_scope=mean_instance`，统一用于训练程序、训练最终选择与独立测试。旧批次的逐实例CPU规则保留，不能用当前代码改变旧搜索的接受条件或覆盖旧结果。旧配置的独立测试按其保存的预算及逐实例规则执行。改变共同评价预算须使用新批次。
- 各实例在独立进程中运行，全局变量互不共享。不同实例可以并行，由所在机器的 CPU 调度器分配核心，每个实例绑定一个核心。评价可在本机（性能核 0、2、…、14 号）或 server3（0–51 号物理核）进行，不同机器的 CPU 核心视为同一评价条件。
- 每次评价的结果（含失败类型与每个实例的计时）写入运行目录：TraceAAD 在 `events.jsonl`，基线在 `evaluations.jsonl`。超时率按此统计。
- 分数只由最终可行解的质量决定。时间只作约束。限时由评价器执行，任务提示不写限时。这是当前提示协议选择，不表示时间、规模或资源信息不属于算法设计。
- **提示只呈现任务本身，不呈现评价的组织方式。** 生成与修复提示可包含问题定义、固定框架如何使用返回值、函数接口与返回值要求、分数含义，以及方法按其机制展示的已评价程序、分数与程序自身的错误和耗时。实例个数与划分、种子、失败发生在哪个实例或第几次调用、并行与调度等评价记账不进入提示。模型面对的是待设计的算法问题，不是这套测试的运行细节。利用评价细节做针对性改进是作弊式适配，也误解了自动算法设计要解决的问题。超时修复给出实测耗时对时限，是在陈述函数要求被违反的程度，不属于评价记账。
- BLAS／OpenMP 单线程。
- 所有方法在训练与测试中使用同一评价条件：相同数据。ACO 种子为 `1234 + 实例编号`。程序的 Python／NumPy 随机种子为 `(730241 + 实例编号) % 2**32`。

## 4. 搜索与最终程序

- 每路预算 **1000次生成尝试**，初始化／种子、解析失败、重复、新颖性拒绝和数值微调程序都计入。反思、策略、代码说明及新颖性判别调用不产生程序，单独记录模型调用。未返回程序的接口故障不消耗生成尝试数。
- 每个方法每个任务 **3路**，搜索种子0、1、2。
- 最终程序：搜索结束时，按训练成绩取前 5 个程序，在训练集上按当前评价条件重新评价，从中确定成绩最好的有效程序（同分取排名靠前者）。最终程序确定后只做一次同规模测试。不设验证集。测试结果不用于选择或修改程序。测试失败记为失败。

## 5. 模型、采样与方法设置

| 项目 | 当前约定 |
| --- | --- |
| 生成模型 | DeepSeek-V4.1-Flash，API模型名`deepseek-v4.1-flash`，后端`deepseek` |
| 原生思考 | 所有主比较关闭：`enable_thinking=False`，`thinking.type=disabled`。不发送`reasoning_effort` |
| 默认采样 | `temperature=1.0`、`top_p=0.95`。方法阶段覆盖见下表 |
| 消息与token计数 | 保留system/user角色；使用发布的`deepseek-ai/DeepSeek-V4.1-Flash`分词器及关闭思考的消息格式 |
| 请求超时 | 当前共享客户端600秒；实际值写入`run_config.json.llm` |
| 输出上限 | 沿用各方法入口默认值，见下表；实际`max_tokens`逐请求记录 |

关闭原生思考不删除方法提示中的分析、reflection或世界模型步骤。high／low仅用于独立诊断。此前诊断中的不发送`max_tokens`也不作为正式搜索设置。

| ReEvo | 16384 | DeepSeek初始化偏移0，初始化和后续调用均为1.0／0.95；原类默认+0.3仍保留给其他模型 |

## 6. 报告与可比较条件

轨迹实验先说明使用哪段搜索过程、哪个组件读取、影响哪个决定及观察窗口。完整搜索报告最终质量与成本。单步或多步检验报告对应响应，不自动升级为全局收益。记录、展示、数值统计和模型学习是不同用法，比较条件继续按下文核对。

每个任务、每个方法报告三路同规模测试成绩的均值与各路数值，训练成绩同样报告三路。同时列出有效路数、失败或未完成状态、实际调用次数和token开销。先运行一路用于检查时，仍需补齐三路后报告完整方法比较。

合并比较时核对任务接口、规模、数据划分、评价预算、生成模型与思考模式、生成次数预算和最终选择规则。方法独有提示、搜索机制与已记录阶段参数是被比较的方法设置。改变共同条件时使用新批次。旧接口、旧模型、high／low诊断与当前关闭思考结果按各自条件报告。

每个批次清单保存执行主机、源码commit或文件哈希与实际命令。每路`run_config.json`保存模型、参数、任务评价设置和搜索设置。本文表达共识，批次记录证明实际执行条件。计算资源的端点、CPU池和worker上限集中在[执行入口](../../experiments/infra/AGENT_OPERATIONS.md)，不重复维护机器状态。
