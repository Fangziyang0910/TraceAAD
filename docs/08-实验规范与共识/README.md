# 实验规范与共识

本文是当前可比较实验设置的唯一规范正文，2026-10-11更新。新实验按本文执行；已启动批次按其配置与源码快照解释。

任务与计分实现见[任务注册](../../benchmarks/tasks.py)与各任务目录。启动命令见[实验入口](../../experiments/README.md)，状态查询与远端操作见[执行入口](../../experiments/infra/AGENT_OPERATIONS.md)。本文记录条件与共识，运行状态写入批次清单。

## 1. 任务

主比较包含TraceAAD与EoH、ReEvo、MCTS-AHD、FunSearch、PathWise、CALM、Shinka七种基线，使用六个任务，`--suite co6`。所有分数越小越好。自2026-10-11起采用**四项固定框架内的函数进化＋两项完整求解器进化**。

| task key | 问题与规模 | 待进化函数 | 固定框架 | 分数 |
| --- | --- | --- | --- | --- |
| `tsp_construct` | TSP，50节点，单位正方形均匀坐标 | `select_next_node` | 逐步构造：每步给出当前节点、起点、按距离排序的未访问节点和距离矩阵，函数返回其中一个节点；最后一个节点与回程由框架补全 | 平均回路长度 |
| `cvrp_aco` | CVRP，50客户，容量50，需求1–9，仓库(0.5,0.5) | `heuristics` | 每实例开始前调用一次，返回边先验；ACO 30只蚂蚁×100轮，衰减0.9，α=β=1 | 平均最好路线总长，只计不同节点之间的移动 |
| `fssp_gls` | 置换流水车间，50作业×20机器，时长1–99 | `get_matrix_and_jobs` | NEH初始化；200轮，每轮至多3步真实交换／插入下降，再调用一次函数，在扰动矩阵上对返回的1–5个作业做一步最好改进；保留真实最好解 | 相对NEH的平均makespan偏差（%） |
| `graph_colouring` | G(300, 0.5) | `solve(adjacency)`，返回完整颜色数组 | 不固定求解框架；DSATUR仅为可整体改写的起始代码；评价器核验每条边并统计不同颜色数 | 相对DSATUR构造的平均颜色数偏差（%） |
| `jssp_construct` | 作业车间，20作业×20机器，每个作业随机机器顺序，时长1–99 | `solve(processing_times, machine_order)`，返回完整开始时间矩阵 | 不固定求解框架；Giffler–Thompson＋MWKR仅为可整体改写的起始代码；评价器核验先后与机器互斥 | 相对MWKR调度的平均makespan偏差（%） |
| `op_aco` | OP，50节点，路程预算3，奖励按到仓库距离 | `heuristics` | 每实例开始前调用一次，返回边先验；ACO 20只蚂蚁×50轮 | 负的平均最好奖励 |

问题定义、函数签名与返回值使用方式写在各任务的 `template.py`，求解与核验逻辑在 `evaluation.py`，数据在 `dataset.py`（TSP为`get_instance.py`）。源码与命令链接见[六任务入口](../../experiments/co6/README.md)。FSSP、图着色、JSSP的相对偏差均为`100 × (objective - reference) / abs(reference)`，负值表示优于参考。

旧版OBP与VRPTW保留用于历史实验，不属于当前六任务主比较；CO-Bench任务适配器已移除。

两项完整求解器每实例只调用一次，允许辅助函数，构造、局部搜索、接受与重启均由程序决定。图着色返回非负整数颜色，编号无需连续；JSSP返回有限非负开始时间，列索引是工序位置。评价器用原始实例独立核验，修改输入副本不能改变约束或目标。

任务key保留以复用运行入口；`jssp_construct`现在表示完整JSSP求解器。两项运行配置的 `task_eval.interface` 为 `full-solver-v1`，评价身份也随接口改变。它们与此前的优先级函数实验分批报告；旧档案不改写，不使用当前接口续跑或补测，复现须使用对应批次的源码快照。其余四项的任务条件保持不变。

## 2. 数据

- 每个任务 **训练16个实例，同规模测试50个实例**。两者来自互不重叠的固定随机流，与搜索种子无关。
- TSP：训练种子2024，测试种子2025。CVRP：种子1234的同一随机流中依次取出的不重叠划分。OP：训练种子1234，测试种子4567。FSSP、图着色、JSSP：总种子20261007，每个实例的随机流为 `[总种子, 任务流, 划分流, 实例编号]`。
- 数据与参考值在评价器初始化时生成，不计入限时。

## 3. 评价

- **固定框架任务（TSP、CVRP、FSSP、OP）：候选函数每个实例最多使用 2 秒 CPU 时间，按该实例上全部调用累计；函数之外的时间不计入。** 预算由调用探针实时计量（进程CPU时间），超出即判为超时。固定框架不在候选可修改范围内；进程被抢占和等待的时间也不计入函数CPU预算。
- 图着色与JSSP的候选函数是完整 `solve`，每实例10秒CPU覆盖其全部求解过程及调用的辅助函数。没有额外的固定求解器计算；数据与参考生成、输入复制和最终合法性核验不计入函数预算。四项固定框架任务继续只累计可进化函数的CPU时间。
- **安全上限：固定框架任务每实例20秒墙钟；图着色与JSSP每实例30秒墙钟**，包含进程启动、固定框架与候选函数，只用来终止卡死的程序。从实例进程启动时计时，等待调度器分配核心的时间不计入。
- 任一实例超时、报错或违反返回契约，该次评价失败，没有分数；成功时按实例等权平均。
- 各实例在独立进程中运行，全局变量互不共享。不同实例可以并行，由所在机器的 CPU 调度器分配核心，每个实例绑定一个核心。评价可在本机（性能核 0、2、…、14 号）或 server3（0–51 号物理核）进行，不同机器的 CPU 核心视为同一评价条件。
- 每次评价的结果（含失败类型与每个实例的计时）写入运行目录：TraceAAD 在 `events.jsonl`，基线在 `evaluations.jsonl`。超时率按此统计。
- 分数只由最终可行解的质量决定；时间只作约束。限时由评价器执行，任务提示不写限时。
- BLAS／OpenMP 单线程。
- 所有方法在训练与测试中使用同一评价条件：相同数据；ACO 种子为 `1234 + 实例编号`；候选的 Python／NumPy 随机种子为 `(730241 + 实例编号) % 2**32`。

## 4. 搜索与最终程序

- 每路预算 **1000次候选**，初始化／种子、解析失败、重复、新颖性拒绝和数值微调候选都计入。反思、策略、代码说明及新颖性判别调用不产生候选，单独记录模型调用；未返回候选的接口故障不消耗候选数。
- 每个方法每个任务 **3路**，搜索种子0、1、2。
- 最终程序：搜索结束时，按训练成绩取前 5 个程序，在训练集上按当前评价条件重新评价，冻结其中成绩最好的有效程序（同分取排名靠前者）。冻结后只做一次同规模测试。不设验证集；测试结果不用于选择或修改程序；测试失败记为失败。

## 5. 模型、采样与方法设置

| 项目 | 当前约定 |
| --- | --- |
| 生成模型 | DeepSeek-V4.1-Flash，API模型名`deepseek-v4.1-flash`，后端`deepseek` |
| 原生思考 | 所有主比较关闭：`enable_thinking=False`，`thinking.type=disabled`；不发送`reasoning_effort` |
| 默认采样 | `temperature=1.0`、`top_p=0.95`；方法阶段覆盖见下表 |
| 消息与token计数 | 保留system/user角色；使用发布的`deepseek-ai/DeepSeek-V4.1-Flash`分词器及关闭思考的消息格式 |
| 请求超时 | 当前共享客户端600秒；实际值写入`run_config.json.llm` |
| 输出上限 | 沿用各方法入口默认值，见下表；实际`max_tokens`逐请求记录 |

关闭原生思考不删除方法提示中的分析、reflection或世界模型步骤。high／low仅用于独立诊断；此前诊断中的不发送`max_tokens`也不作为正式搜索设置。

| 方法 | 当前入口默认输出上限 | 采样覆盖或明确适配 |
| --- | ---: | --- |
| TraceAAD | 8192 | 使用模型默认采样 |
| EoH | 16384 | 使用模型默认采样 |
| ReEvo | 16384 | DeepSeek初始化偏移0，初始化和后续调用均为1.0／0.95；原类默认+0.3仍保留给其他模型 |
| MCTS-AHD | 16384 | 生成使用默认采样，思路重述发送temperature=0；与官方客户端把0回退为默认值的行为不同 |
| FunSearch | 16384 | 使用模型默认采样；数据库的cluster temperature属于父代选择，不是LLM温度 |
| PathWise | 16384 | 当前实现保留初始化temperature+0.3，即DeepSeek下1.3；其他阶段使用默认采样 |
| CALM | 16384 | w/o GRPO；temperature／top_p按任务配置，见下表 |
| Shinka | 16384 | 生成、meta与novelty判别使用同一生成模型；embedding独立 |

这些输出上限是本项目当前入口默认值，不是所有原论文的统一规定。方法独有种群、算子、父代选择与上下文参数保存在各入口及`run_config.json.method_params`；官方来源、提示与适配核对见[基线审查](../03-现象与检验/2026-10-11-七种基线官方实现忠实性审查.md)。PathWise保留的1.3与本批ReEvo适配后的1.0不同，不能笼统写成所有方法各阶段温度相同。

| CALM任务 | temperature | top_p |
| --- | ---: | ---: |
| TSP | 0.9612113151100183 | 0.8822595888215602 |
| CVRP | 0.5746373293518763 | 0.9037059170405967 |
| OP | 0.7592716186561026 | 0.9340793100759698 |
| FSSP、图着色、JSSP | 0.8 | 0.95 |

CALM具体设置来源为[任务参数](../../baselines/calm/task_config.py)。Shinka使用阿里云`text-embedding-v4`，兼容接口为`https://dashscope.aliyuncs.com/compatible-mode/v1`，novelty相似度阈值0.99；型号与接口写入运行配置，凭据仅保存在环境变量或被忽略的.env中。

原始请求与回复保存在`calls.jsonl`（结束后压缩），记录阶段、实际采样参数、finish_reason与API usage。`token_usage.json`实时累计输入、生成、reasoning与缓存token，结束时写入`summary.json`。生成token已包含reasoning时不重复相加；缺少usage或reasoning明细按缺失记录，不伪造零用量。反思、meta、novelty和重试的实际调用均进入成本统计，1000候选不等于1000次请求。

## 6. 报告与可比较条件

每个任务、每个方法报告三路同规模测试成绩的均值与各路数值，训练成绩同样报告三路。同时列出有效路数、失败或未完成状态、实际调用次数和token开销。先运行一路用于检查时，仍需补齐三路后报告完整方法比较。

合并比较时核对任务接口、规模、数据划分、评价预算、生成模型与思考模式、候选预算和最终选择规则。方法独有提示、搜索机制与已记录阶段参数是被比较的方法设置。改变共同条件时使用新批次；旧接口、旧模型、high／low诊断与当前关闭思考结果按各自条件报告。

每个批次清单保存执行主机、源码commit或文件哈希与实际命令；每路`run_config.json`保存模型、参数、任务评价设置和搜索设置。本文表达共识，批次记录证明实际执行条件。计算资源的端点、CPU池和worker上限集中在[执行入口](../../experiments/infra/AGENT_OPERATIONS.md)，不重复维护机器状态。
