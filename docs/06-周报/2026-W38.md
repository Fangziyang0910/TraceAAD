# TraceAAD 周报｜2026-W38（9月14日—9月20日）

## 本周概况

这周我主要研究一个问题：模型继续改进算法时，应该更多参考当前算法的形成过程，还是参考其他分支中已有的好算法？V10.11 的上下文对照和 V11.0 的结果让我看到，这两类信息各有用途，而父代机会分配也会改变它们在完整搜索中的效果。

## 主要进展

我整理了 V10.11 四组上下文实验：短形成轨迹、无轨迹、带完整代码的形成轨迹，以及档案参考。TSP、VRPTW 的训练结果更支持短形成过程；CVRP、装箱从跨分支参考中得到的信号更强；OP 的结果没有给出同样清楚的选择。这里比较的是完整搜索的三次重复，任务差异不能直接写成固定的“任务对应算子”规则。

V11.0 则把父代选择推向高分程序，并按算子提供不同参考。五路测试补齐后，CVRP 的三个测试规模相对 V10.11 默认组都有改善，TSP、OP、VRPTW 回落。过程复盘发现，高分程序得到较多机会时，Pivot 的父代改进率和新分支的继续开发都受影响；同时，只有 Idea 和分数的参考未必能把其他算法的具体机制带进代码。版本同时改变了分配和上下文，暂时不能只归因其中一项。

为了拆开这两个因素，我建立了 B/C 交叉组合：分别把 V11 的父代选择配 V10.11 的上下文，以及把 V10.11 的父代选择配 V11 的上下文。运行中出现过记录不完整的旧批次，随后从新批次重跑；截至本周，这组实验仍没有完整的终局与独立测试结论。我同时完成了 V11.1 的第一版机制和运行检查，用节点级机会统计与算子上下文继续探索这个问题。

## 目前的发现

目前较可信的是：任务结构影响哪类历史信息有用，而“单次超过父代”和“把新结构发展为全局更好的算法”不能混为一谈。还不清楚 V11.0 的任务差异究竟有多少来自选父、多少来自参考内容。V11.1 的配置是一项待验证的设计，不是从现有数据推出的最优映射。

B/C 的部分早期记录无法可靠续跑，后端速度和 CVRP 的评价成本也让不同路次进度差很多。我会在相同评价次数下等完整结果，再做未见实例测试；之后固定选父规则单独比较上下文，固定上下文再比较机会分配。成绩见[正式版本结果](../02-实验结果/01-正式版本平均结果.md)和[辅助对照结果](../02-实验结果/03-辅助与分支版本结果.md)。
