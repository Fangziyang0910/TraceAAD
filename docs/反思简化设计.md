# 反思简化设计

本文保留V1反思实现的细节。两版完整机制、经验归属与默认设置分别见[V1正式设计](EvoTrace-v1设计.md)与[V2正式设计](EvoTrace-v2设计.md)。

**反思将被移除区域的算法设计经历压缩为树上的经验。** 程序提供实际代码、分数、错误和已有经验；模型联系尝试过的算法思想与结果，凝练对计算过程的认识，为后续生成提供思考材料。

方法主线见[树状种群与反思简化](树状种群与反思简化.md)，区域划分见[树状种群管理](树状种群管理.md)，实现见[reflection.py](../evotrace_v1/reflection.py)。

## 证据与归属

`ConsolidationPlan` 将每个移除节点分到一个区域。每个区域调用一次模型：

| 操作 | 提供的证据 | 写回位置 |
| --- | --- | --- |
| 路径收缩 | 保留祖先与后代的代码、两端净差分、中间逐步差分与评价、入边及被移除节点的旧经验 | 重连边的 `variation_experience` |
| 分叉整理 | 保留承接节点的基准代码、每个移除节点相对真实父代的差分、评价与错误、承接节点及移除区域的旧经验 | 最近保留祖先的 `selection_experience` |

虚拟根通过 `root_selection_experience` 承接被淘汰的初始尝试。初始版本没有算法父代，直接提供完整受评代码。

代码先移除注释与程序文档字符串，差分保留全部改动行。任务接口说明保留，候选生成时的设计自述不进入模型反思。程序按真实父代计算分数变化，并为区域之外的真实父代提供一次完整基准代码；区域内用局部尝试编号连接差分，使每个改动都有可读的基准。

## 合并经验

模型将经历压缩为简短研究笔记，保留值得记住的计算思想、结果和旧经验。准确描述经历本身即可，不要求每段经历都提炼解释或一般规律；自然形成的解释保持试探性，后续设计由生成模型决定。淘汰表示种群管理中的移除，不等于否定算法思想。旁支输入用局部尝试编号连接真实父子关系，先展示当前代码比较，再集中展示各分支携带的旧经验，避免把旧摘要混作当前代码事实。

两类反思统一返回一个非空`experience`字符串，建议约120词。路径经验自然描述算法发展与中间经历，分数变化头由程序添加；选择经验联系旁支尝试中的计算思想与结果。经验补充当前代码无法直接表达的经历，不再分别生成核对稿、最终变化和中间尝试三份文本。程序清理临时节点编号与未转义控制字符；模型返回的经验不再按字符位置截断，长度由简洁输出要求与请求token上限控制。确定性回退仍以960字符预算整理旧记录。默认输出上限为1536 tokens。生成上下文以经验称呼这些摘要；Explore将方向概览与经验作为构思新计算方式的材料。

调用失败或未提供模型时使用确定性摘要；调用失败仍记录辅助请求成本。完整提示、原始响应、最终经验、用量和异常随重构记录保存，恢复方式见[模块说明](../evotrace_v1/README.md)。

输入取舍的实际问题见[首轮运行审阅](记录/2026-11-11-EvoTrace-V1机制与提示词运行审阅.md)：入口与最优节点预摘要会遗漏内部错误和旧经验，按行截断差分会遮住计算。因此当前直接提供区域内各步证据。
