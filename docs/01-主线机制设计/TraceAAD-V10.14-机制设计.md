# TraceAAD V10.14 正式机制

## 版本身份

V10.14 正式版采用 2026-09-28 启动的最终五任务四重复批次 `20260928_v1014_3_template2`。每路完成 1,000 次候选尝试，并完成独立选择集评价。代码、运行模块和原始清单保留当时的内部标识 `v10_14_3`／`v1014_3`，以维持运行记录可追溯；研究文档统一称其为 **V10.14**。

此前提出的轨迹闭合与局部重验是研究原型，不属于正式版的在线主机制。正式版关闭在线重验、固定三步开发票和行为资格门槛。相关原始推理另存于[轨迹重验原始构想](TraceAAD-V10.14-轨迹重验原始构想.md)。

## 研究目标

在固定候选预算下，让 LLM 搜索既能提出不同算法结构，也能开发已有候选，并用独立数据从训练候选中选择程序。主要目标是独立选择后的程序质量；Idea 非空率、动作次数、源码数量和探针区域数量只用于诊断。

## 正式搜索机制

### 1. 有界混合初始化

默认提出八个初始化候选：前半部分独立生成，后半部分可参考已产生的有效根。失败、无效和重复提案照常消耗预算。每个有效且源码唯一的根最多获得一次 Refine bootstrap；不会为了凑足有效根而免费重试。

### 2. 完整代码交付与可选 Idea

提示要求模型以普通文本给出 `Idea:` 和 `code:`，后者包含完整 Python 程序。完整、可执行代码是必要交付，Idea 是可选说明：缺少 Idea 不会单独否决有效代码，Idea 的内容也不作为算法正确或机制有效的证据。原始响应、实际评价源码和传给下一轮的上下文分别留存。

正式批次固定使用完整代码模式。交付失败、语法错误、重复程序和评价失败都计入候选尝试，不做隐藏的免费重采样。

### 3. 受约束的开发动作

在 Refine、Tune、Pivot、Transfer 中，从当前可用动作等概率抽取。Tune 只用于显式数值参数调整；Transfer 需要不同语法组的参考程序。普通 Refine 可修改结构。主循环中的 Pivot 使用独立上下文，不向模型提供父程序、父代历史或 donor，作为结构发现入口；该预算没有强制赠送后续开发步骤。

### 4. 全档案父代竞争

所有有效候选都保留为事实记录。父代竞争按 AST 语法组去重：AST 身份忽略注释和格式，保留标识符、数值、docstring 与语句顺序。同一语法组共享开发次数，但每个程序的源码、分数与形成来源仍独立保存。

正式选父使用任务内经验中分位质量，加上按使用次数递减的探索项：

\[
S(a)=Q_{\mathrm{midrank}}(a)+\frac{1}{\sqrt{n_a+1}}.
\]

其中分位项减轻不同任务原始分数尺度对调度的影响，使用次数项给较少开发的语法组有限机会。同分优先使用次数少、记录更早的候选。这是搜索规则，不是长期潜力或收益的统计估计。

### 5. 有限历史与行为诊断

当前完整程序、最近直接尝试和有限形成事件进入请求；额外历史最多 4,000 token、6 个事件、形成深度 6。Idea 原文完整保存，送入上下文时按 tokenizer 上限显示。形成记录描述观察和来源，模型解释仍视为待检验假设。

行为探针只在训练数据的固定状态上描述程序决策，不改变任务分数，也不作为父代准入或算法语义等价判断。正式版未启用按行为区域分配主搜索预算。

### 6. 独立选择与测试隔离

搜索结束后，从训练档案冻结最多五个语法不同的候选，再由独立选择集选出最终程序。选择集不进入搜索提示或父代调度。正式 held-out 测试应在选择完成后单独运行；V10.14 当前保留的最终批次尚无正式 held-out 结果。

## 正式实验协议与证据边界

最终批次包含 TSP、VRPTW、CVRP、OP 和在线装箱五个任务，每任务四路，每路 1,000 次候选尝试。训练评价使用固定种子面板 `[730241]`；失败和重复计入候选预算。独立选择分数与训练前沿分开报告。

完整协议见[正式运行说明](../../experiments/traceaad_v10_14_3/README.md)，训练和选择结果见[正式实验结果](../03-机制探索与验证/2026-09-29-V10.14-正式实验结果与分析.md)。原始运行目录仍保留内部 `_3` 标识，这只是实现和批次身份，不再表示一个与 V10.14 并列的正式版本。

本批联合使用了交付、选父、独立 Pivot 和语法去重等机制，不能从整批成绩单独归因某一项。五任务四重复可以描述本配置下的跨路结果，但不足以证明普遍优势；没有 held-out 结果时，不声称已验证泛化或达到 SOTA。
