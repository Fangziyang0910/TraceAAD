# TraceAAD V10.13：质量抽样与四动作程序开发

V10.13 是当前实验机制。它研究在固定评价预算下，如何从已评价程序中选择继续开发的父代，以及四种改写动作各需要什么材料。候选的真实评价决定是否进入档案；动作名称和模型说明本身不代表算法质量或行为变化。

## 机会分配与预算

当前工作配置使用 8 个评价有效的初始程序：前 4 个独立生成，后 4 个可参考容量允许的既有根代码及训练分数，尝试补充不同决策原则；失败候选不推进根序号。根数可配置，混合方式对任意根数先独立生成向上取整的一半。

之后每轮等概率选择 Refine、Tune、Pivot 或 Fuse。在全部有效节点上按实测 fitness 构造 ESS 目标为 8 的 softmax 质量分布，再混入 12.5% 全档案均匀概率抽取父代。每轮生成一个候选；解析成功后调用一次评价器。初始化和后续开发共用每路 1000 次评价预算，调用评价器即计一次，包括失败评价；解析失败不消耗评价预算。有效程序加入档案，预算结束时按实测质量选最好程序。

## 动作与信息

| 动作 | 提供的材料 | 目标 |
| --- | --- | --- |
| Refine | 父代、最近至多 3 个形成步骤、至多 2 个同父试验 | 改进表示、比较或组件协调 |
| Tune | 与 Refine 相同，局部试验优先 Tune 子代 | 调整真正影响决策的参数、尺度和交互 |
| Pivot | 父代 | 改变核心假设或决策原则 |
| Fuse | 父代和一个不同的参考程序 | 吸收互补计算并形成更好的程序 |

Refine 和 Tune 的同父试验优先提供一个超过父代的最佳子代，以及一个未超过父代的最近子代。Fuse 从代码不同于父代的节点中选一份参考，质量抽样与均匀抽样各占 50%；无可用参考时执行 Refine。上下文容量不足时先删减附加历史、局部试验或参考，保留父代完整代码。相同代码的不同评价节点仍保留各自形成关系，不合并为同一个搜索状态。

## 候选表达

模型默认返回完整 Python 程序，也可对当前父代提交精确的局部修改；一句 Idea 只用于记录意图。两种表达最终都形成可评价程序，需通过任务接口和 Python 语法检查。解析失败不评价，也不产生算法节点；本版本不安排额外的模型修复回合。

## 研究边界与证据

8 个根是当前工作配置，不是已验证的最优根数。现有初始化对照只固定 8 根比较独立、顺序和混合生成方式。改变根数也会改变固定总预算下的后续开发次数；当前使用混合方式不能证明 8 根或 4+4 分界最优。

四动作的真实代码变化、父代与前沿的改进、后续开发和 held-out 结果需要分别检验。输出可解析或节点增加只说明流程执行，不说明哪种动作或上下文带来质量收益。
