# 轨迹条件化修订与局部重验：早期构想

这份构想没有进入[正式版 V10.14](TraceAAD-V10.14-机制设计.md)。

早期想法从一条真实程序形成路径出发：

```text
p00 ──加入修改 A──> p10 ──加入修改 B──> p11
```

在旧背景中观察到 A 有收益，并不能直接说明加入 B 后 A 仍然有益。设想精确撤销当前代码中的 A，构造“保留 B、不含 A”的 `p01`，再在相同评价条件下比较四个程序，判断 A 的作用是否随代码背景改变。

若对照程序能够从实际修改中精确重建，比较结果还可以作为有条件的证据进入下一次代码修订。这份构想需要分别检验两个问题：局部反事实是否值得其构造与评价成本，以及向模型提供比较证据是否能改善后续决策。找到一个更好的回滚程序，只能说明该程序本身值得保留，不能单独证明证据改善了生成。

“背景改变会改变组件作用”本身不足以说明在线重验值得花费搜索预算；这也是该构想没有成为正式机制的原因。
