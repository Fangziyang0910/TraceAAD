# 轨迹条件化修订与局部重验：早期构想

> 这份构想没有进入正式版 V10.14 的主机制。正式机制见 [TraceAAD V10.14 机制设计](TraceAAD-V10.14-机制设计.md)。与早期试跑、实现检查和测试有关的其他结果已按整理决定删除；本文只保留原始问题表述，不报告这些结果。

早期想法从一条真实程序形成路径出发：

```text
p00 ──加入修改 A──> p10 ──加入修改 B──> p11
```

在旧背景中观察到 A 有收益，并不能直接说明加入 B 后 A 仍然有益。设想精确撤销当前代码中的 A，构造“保留 B、不含 A”的 `p01`，再在相同评价条件下比较四个程序，判断 A 的作用是否随代码背景改变。

若对照程序能够从实际修改中精确重建，比较结果还可以作为有条件的证据进入下一次代码修订。核心主张因此包含两个独立问题：局部反事实是否值得其构造与评价成本，以及向模型提供比较证据是否能改善后续决策。找到一个更好的回滚程序，只能说明该程序本身值得保留，不能单独证明证据改善了生成。

回看后，我不再把这条路线作为正式 V10.14 的中心 idea。它的直觉起点合理，但“背景改变会改变组件作用”本身并不反直觉；而要建立方法价值，还需要一个明确、可检验的收益预测。正式版改用结构发现、候选发展和独立选择组成搜索协议，具体规则见正式机制文档。
