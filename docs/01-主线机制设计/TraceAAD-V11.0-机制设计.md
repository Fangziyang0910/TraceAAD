# TraceAAD V11.0：代码级机会分配与算子条件化参考

V11.0 以 V10.11 generic 为基线，同时改变**父代机会分配**与 **Pivot/Fuse 的参考材料**。研究问题是：按不同代码的质量和已开发次数选择父代，并按动作提供档案思想，能否让有限评价预算形成更好的程序。它是两项机制的联合版本，不单独检验任何一项。

## 固定条件与改动

五个任务、每任务五次重复，每路 1000 次真实评价；从 8 个顺序参考初始化的有效根开始。Refine、Tune、Pivot、Fuse 各有 25% 调用概率；Refine/Tune 保留 V10.11 的当前程序和最近最多 8 条真实形成记录。任务、评价器、生成输出要求和一次失败修复沿用 V10.11。四算子改为共用以下父代选择规则；Pivot 不再额外进行一半均匀抽样。

## 父代选择

同一 AST 表示的程序视为同一份代码 $x$，即使它在形成树中有多个节点。相同代码的有效评价取平均 fitness，再在不同代码间计算中秩百分位 $q_t(x)\in[0,1]$；同分时共享中秩。$n_t(x)$ 是从该代码直接发起的累计候选尝试数，包括失败与退步；$T$ 是初始化后累计候选尝试数。每轮选择得分最高的代码：

$$S_t(x)=q_t(x)+0.1\sqrt{\frac{\log(1+T)}{1+n_t(x)}}.$$

并列代码均匀选择；若同一代码对应多个历史节点，再均匀选一节点作为父代。子代只以自身实测质量参与后续竞争，不把后代成绩回传给祖先。探索加分是启发式分数，不是统计置信界：在 $T=1000$ 时，未开发代码的加分最多约 0.263；若已有代码的百分位为 1，低于约 0.737 的新代码无法仅凭该加分胜出。这给低分新方向的开发机会设了明确边界。

## 生成上下文

| 动作 | 模型可见的主要材料 | 设计意图 |
| --- | --- | --- |
| Refine / Tune | 当前完整程序、实测 fitness、最近至多 8 条形成记录 | 分别改进现有计算或校准影响决策的参数；相对 V10.11 保持不变。 |
| Pivot | 当前完整程序、实测 fitness、最多 8 条档案参考的 Idea 与 fitness | 提出不同的主要决策方法。 |
| Fuse | 与 Pivot 相同 | 从当前程序和参考思想中选择可组合的计算；不再提供单份 donor 完整代码。 |

参考候选必须有有效评价和非空 Idea；排除与父代 AST 相同的代码，同一代码只取最近一条记录。按实测 fitness 排名，同分取中秩，以 $1/r$ 权重无放回抽样最多 8 条。参考可以来自当前形成路径，也可以来自其他分支；抽到参考不等于模型实际采用其中的机制。Fuse 没有可展示的参考时按 Refine 执行，Pivot 仍可仅依据当前程序提出替代方法。

## 检验边界

与 V10.11 generic 的比较同时改变选父规则、Pivot 的均匀机会和 Pivot/Fuse 上下文，不能把质量变化单独归因于档案参考。检验需要分别看新代码首次得到开发的机会、预算在头部代码的集中度、参考思想是否落实为代码或决策变化，以及父代改进、全局前沿和 held-out 成绩。算子标签只表示生成意图，不能替代对实际代码行为的检查。
