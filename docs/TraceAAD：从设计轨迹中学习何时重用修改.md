# TraceAAD：从设计轨迹中学习何时重用修改

Oct 25, 2026 · @matt pocock

## 摘要

基于大语言模型的自动算法设计（LLM-driven automatic algorithm design，LLM-AAD）通过反复修改程序来搜索高性能算法，并在此过程中产生大量“在程序 p 上做修改 m，得到收益 Δ”的经验。经验能否服务于后续决策，取决于同一个修改对当前程序是否仍然有效。文字经验可以启发新的修改，代码改动也可以在共享结构中直接复用；但在程序背景变化后，如何以少量重放可靠地判断经验是否仍然适用，仍是搜索需要解决的问题。

我们提出 TraceAAD，从设计轨迹中学习同一个修改何时值得重用。它包含三个机制。第一，将搜索发现的修改沉淀为可核验的**变换**（transformation），固定其设计操作与语义参数，并在每次重放后核验执行，使多次评价归属于同一个行动对象。第二，利用**设计轨迹**（design trajectory）中的已有评价安排**配对重放**（paired replay），补全同一变换在背景变化前后的局部对照。直接父子对照测量路径修改与变换之间的上位效应（epistasis）；新增执行由收益模型对当前程序的预测分歧选择。第三，以单次尝试的**期望正增益**（expected positive gain）为准则选择下一次修改，并由全局、条件与谱系三类收益模型对后续结果的预测表现决定各自的权重；收益条件由 LLM 提出，由执行结果检验。自由修改持续发现新变换，重放则同时承担改进程序与检验经验两项职能。TraceAAD 输出高质量程序，以及一份带有执行记录与条件收益证据的变换库。

## 1 引言

自动算法设计的目标是在少量人工参与下，为给定问题构造高性能的算法。以大语言模型为核心的方法在这一方向上进展迅速：FunSearch \[1\] 和 EoH \[2\] 把 LLM 作为进化搜索中的变异算子；ReEvo \[3\]、HSEvo \[4\] 和 MCTS-AHD \[5\] 改进了搜索的组织方式；AlphaEvolve \[6\] 和 ShinkaEvolve \[7\] 把这一流程扩展到更大的代码库与科学问题。它们共享同一个基本循环：选出父代程序，由 LLM 修改它得到子代，评价子代，再更新种群。

这一循环的每一轮都产生一条经验：“在程序 p 上做修改 m，得到收益 Δ”。在以完整程序为搜索单位的流程中，修改通常只以父代与子代之间的代码差异存在；后续搜索主要选择程序，缺少对同一修改的显式追踪。对演化编码系统的大规模分析 \[8\] 提供了三项相关观察：重新执行同一提示几乎从不得到原来的程序，但所得程序能恢复原得分的中位数 0.76，说明搜索传递的是结构性收益而非具体代码；同一谱系中约 30% 新增的代码行，与该谱系此前删除的代码逐字相同；带来增益的修改集中在少数几类，且出现得很少。这些观察提示，经验在搜索中有所传递，而将其落实为可识别、可核验的操作，有助于追踪同一修改在不同程序上的结果。

已有工作从多个方向利用搜索历史。ReEvo \[3\] 与 HSEvo \[4\] 将成败对比总结为反思；RefineEvo \[9\] 维护正反两类经验；EvoMem \[10\] 保存带来源的修改经验以供检索；DeltaEvolve \[11\] 以语义差分组织相邻版本的改动；PhyloEvolve \[12\] 在系统发生树上组织修改轨迹；HiFo-Prompt \[13\] 与 CCTS \[14\] 为见解或概念维护效用分数；DGS \[15\] 学习代理模型，预测对给定父代执行某一提示算子的结果。这些方法把历史转化为更好的上下文或选择信号，但每次复用经验时，LLM 都会重新生成一个修改，系统并不核验其是否执行了原有的操作。Code Graph \[41\] 更进一步，将修改保存为带锚点的代码改动，并在同一代码图中直接施加到其他程序上；其随机森林根据修改组合预测候选程序的性能，并以聚合 Shapley 贡献生成搜索摘要。

要在少量重放下判断经验对当前程序是否适用，需要处理三个相互关联的问题（图 1）。**第一，保持重用操作的一致性。** 依据文字经验重新生成时，需要核验执行了哪个操作、是否夹带其他改动，才能将结果归到同一个修改上。**第二，检验程序变化后历史结果是否仍然适用。** 一次成功或失败未必能迁移到后续程序。前述约 30% 的重复引入，可能是浪费的重试，也可能是条件改变后合理的再尝试，需要对照证据来区分。**第三，在稀少观察下确定经验的使用范围。** 修改组合预测可以利用共享代码图中的结构信息；跨代码结构重放时，还需要保持行动可比，并判断哪些程序条件能够预测收益。经典进化计算中的自适应算子选择 \[16\] 与超启发式 \[17\] 根据历史调整稳定的算子；TraceAAD 研究如何将搜索在线发现的修改转化为这样的行动，并主动检验其适用性。

第三个问题决定了经验的使用范围，因为修改的效果取决于它所作用的程序。以“先用低成本规则筛除大部分候选，只对剩余候选做昂贵评价”为例（图 2）：在对每个候选执行昂贵前瞻的构造式算法中，它节省大量计算；在评价本身就很廉价的算法中，它只会增加开销。成功的修改值得重用，但并非处处值得；失败亦然，在一个程序上失败的修改，在此后改变了的程序上未必仍然失败。因此，经验能否迁移，取决于影响修改效果的程序条件是否仍然成立，而不只取决于两个程序相隔多远。

&#91;embedded content: 图 2 · 同一个修改的效果取决于程序（示意）\]

这一认识引出本文的核心观察：**设计轨迹中的已有评价可以用于补全局部对照。** 设变换 τ 已施加于程序 q，随后一次路径修改 σ 将 q 变为 p。只需再将 τ 施加于 p，便得到同一变换在 σ 前后的两份边际收益；二者之差正是 σ 与 τ 之间的上位效应（epistasis），即一个修改的效果在多大程度上依赖于另一个修改 \[43, 44\]。当 q、p 与规格冻结后重放得到的 τ(q) 都已在同一协议下评价时，只需新增评价 τ(p) 即可完成对照。由此，轨迹不再只是交给 LLM 的历史摘要，而成为获取条件收益证据的来源。

我们的目标不是证明已有方法无法积累经验，而是检验：当修改成为稳定、可核验的对象，且轨迹被用来获取对照证据之后，经验能否积累得更有效、用得更准确。为此，我们提出 TraceAAD（图 3），它由三个机制组成，分别处理上述三个问题：

1. **可核验的变换（行动基础）**：将改进了父代的修改沉淀为变换，固定其设计操作与语义参数，只允许变量与接口随目标程序适配；每次重放后核验实际执行是否符合规格，执行失败只计入执行可靠性，不计为该操作的负面证据。
2. **沿设计轨迹的配对重放（经验来源）**：在路径修改前后施加同一变换，测量程序变化对其边际收益的影响；当不同收益模型对当前程序上新增执行的期望正增益预测分歧较大时，优先安排这样的诊断重放。完全相同的程序直接复用评价，历史失败不构成禁令。
3. **条件信用与选择（决策核心）**：为每个变换并行维护全局、单条件与谱系三类收益模型，以它们对后续执行结果的预测表现分配权重，并按单次尝试的期望正增益，用 Thompson 采样在重放与自由修改之间选择。收益条件由 LLM 提出，由执行结果检验。

由此形成一种分工：LLM 负责提出与实现修改，搜索负责记录修改的执行结果，并学习在何处重用它们。可核验的变换是行动基础，配对重放是经验来源，条件信用是决策核心。TraceAAD 估计的始终是一个修改作用于一个程序的单步结果：每次重放既产生一个候选程序，也更新一份关于该修改适用范围的证据，无需预测程序在未来搜索中的潜力。

本文的贡献如下：

- **问题**：研究如何在少量重放下，可靠地判断搜索发现的修改对当前程序是否仍然适用，并将操作一致性、对照证据与经验使用范围连接起来。
- **方法**：提出 TraceAAD，将搜索发现的修改转化为可核验的行动，利用设计轨迹中的已有评价构造局部对照，学习修改收益怎样随程序背景变化，并指导下一次重用。
- **评估**：给出可检验的预测及其实验协议，以 Code Graph 为主要完整方法对照，并在等量新增评价下比较随机重放、非配对主动重放与轨迹配对主动重放。

## 2 相关工作

**LLM 驱动的自动算法设计。** FunSearch \[1\] 首先展示了把 LLM 嵌入进化搜索可以发现新的数学构造与启发式。此后的工作从表示、搜索组织与模型三方面改进这一流程：EoH \[2\] 同时演化自然语言思路与代码；ReEvo \[3\] 引入反思；HSEvo \[4\] 结合和声搜索与遗传算法；MCTS-AHD \[5\] 用蒙特卡洛树搜索组织候选启发式；LLaMEA \[18\] 生成完整的元启发式算法；MEoH \[19\] 处理多目标设计；AlphaEvolve \[6\] 与 ShinkaEvolve \[7\] 把循环扩展到大规模代码与科学发现；AdaEvolve \[25\] 按近期进展自适应地调节搜索强度与岛屿间的算力分配；EvoTune \[23\] 与 CALM \[24\] 用搜索反馈微调 LLM 本身。Zhang 等 \[20\] 的分析表明进化搜索框架对这类方法至关重要；LLM4AD \[21\] 与综述 \[22\] 对这一方向做了系统整理。TraceAAD 不改变父代选择、种群管理或模型参数，只改变给定父代后做什么修改，因此可以嵌入上述任一框架。

**搜索历史的利用。** 这是与本文最接近的一类工作。ReEvo \[3\] 与 HSEvo \[4\] 将父代之间的对比总结为反思；RefineEvo \[9\] 维护正反两类、依情境而定的经验；EvoMem \[10\] 保存带来源的修改经验，按任务与程序上下文检索；HiFo-Prompt \[13\] 为每条见解维护以子代表现更新的效果分数，并全局地选取高分见解；CCTS \[14\] 以高低表现程序之间的似然比估计概念效用并调整父代选择；EvoPH \[26\] 以执行反馈提炼经验并修改提示；PathWise \[27\] 以蕴涵图记录搜索轨迹；PhyloEvolve \[12\] 在系统发生树上组织修改轨迹并汇集精英轨迹；DGS \[15\] 为父代与提示算子的联合动作建立代理预测，说明生成前的决策可以从搜索经验中学习。DeltaEvolve \[11\] 同样认为修改比完整代码更适合作为经验的单位，把父代到子代的改动写成“从什么到什么”的摘要、新旧逻辑以及“为何有效”的假设；但这些改动只作为启发，其复用结果不被追踪，假设也不被检验。

与本文最接近的是 Code Graph \[41\]。它将修改（correction）定义为带锚点的语法改动，在同一代码图中机械复用。它用修改组合的二进制表示训练随机森林以排序未评价的候选，并聚合 Shapley 贡献生成搜索摘要；这种组合预测可以利用共同出现的修改及其依赖。因此，本文不把“复用修改”“修改级信用”或条件建模本身作为独占主张。TraceAAD 重点研究两个环节：通过规格与核验，在不共享代码块的程序上保持操作一致；利用轨迹中的已有评价主动补全局部对照，检验经验对当前程序是否仍然适用。变换库及其条件证据还可在后续运行中继续使用。这些设计能否改善选择与资源效率，由第 4 节的实验检验。表 1 对比各方法的重用与收益学习方式。

**信用分配的层次。** 从信用分配的角度看，现有工作的信用落在不同层次：程序（适应度选择与 MCTS-AHD 的节点价值）、概念（CCTS）、见解（HiFo-Prompt）、提示算子（DGS）、岛屿（AdaEvolve），以及同一代码图中带锚点的修改（Code Graph）。LLM4EO \[28\] 让 LLM 在演化过程中在线设计作用于解的算子，并按成功率选择，信用是全局的。经典的自适应算子选择 \[16\] 与超启发式 \[17\] 则在固定算子上分配信用。TraceAAD 把信用落在可跨越代码结构重放、并经核验的变换上，并让信用随程序条件而变。其中使用的 Thompson 采样 \[39\] 是标准的在线决策工具，不构成本文的贡献；本文关心的是被选择的行动是什么，以及更新其价值的证据如何获得。

**代码变换的学习与应用。** 软件工程中已有工作把修改抽象为可重复应用的规则。Getafix \[29\] 从历史修复中学习修复模式并对候选修复排序；Refazer \[30\] 从少量示例中学习语法变换；SemOpt \[31\] 从开源提交中挖掘优化策略，以静态分析规则定位适用位置，再由 LLM 改写；RuleFlow \[32\] 以 LLM 生成带前提条件的重写规则，并在生成时验证其等价性与加速效果；Allain 等 \[33\] 评估了 LLM 从代码差异合成变换规则的能力。这些工作为变换的表示与重放提供了可行的技术基础，但其适用性由静态规则决定，收益在创建时一次性验证，不从后续在不同程序上的结果中学习规则在哪里有效。TraceAAD 区分两类条件：执行前提决定变换能否实施，由结构与不变量检查判定；收益条件决定实施后是否值得，由执行结果学习。

**按程序预测变换的效果。** Milepost GCC \[34\] 根据程序特征预测哪些编译优化对该程序有利；算法选择 \[35, 36\] 根据实例特征预测最适合的算法；Prophet \[37\] 以修改及其上下文的特征学习补丁正确的概率。它们针对固定的变换集合，并在离线数据上训练；TraceAAD 的变换集合由搜索自身在线生成，观察稀少，因而需要主动获取有区分力的证据，并让数据决定经验的使用范围。

**适应度地形与上位效应。** 上位效应刻画一个变化的效果如何依赖于其他变化，是适应度地形研究的核心概念 \[42\]。遗传算法研究以实验设计的视角度量基因位点之间的上位效应 \[43\]；蛋白质工程中的双突变循环（double-mutant cycle）以四个变体的 2×2 对照估计两个突变之间的相互作用 \[44\]。TraceAAD 的配对重放在 LLM-AAD 中构造同样的对照：路径修改与变换扮演两个“突变”，设计轨迹提供其中三个已评价的变体。不同之处在于，这里的“突变”是由 LLM 发现、可在不同程序上重放的设计操作，对照的目的是决定下一次修改，而不是刻画整个地形。

**分析性工作与库学习。** Pelleriti 等 \[8\] 系统分析了演化编码系统实际做出的修改。他们发现，重新生成虽然几乎不能复现原程序，却能恢复大部分得分，即搜索携带的是结构性收益；TraceAAD 把这种结构性收益显式化为可核验的操作，并为它积累执行结果。程序合成中的库学习（如 DreamCoder \[38\]）同样从已有解中抽象可复用成分，但其标准是压缩与复用；TraceAAD 的标准是重放后能否带来增益。

## 3 方法

### 3.1 问题设定

**自动算法设计与评价协议。** 给定问题实例的分布 𝒟，程序 p 的性能 f(p) 定义为它在 𝒟 上的期望得分，越大越好。评价在固定的训练实例与随机种子上进行，父代与子代使用配对的实例与种子，其收益估计为

```latex
\widehat{\Delta}(p, c) = \frac{1}{m}\sum_{i=1}^{m}\big[s(c, x_i) - s(p, x_i)\big]
```

其中 s(·, x\_i) 是在实例 x\_i 上的得分。测试实例不参与生成、条件求值或信用更新。宿主搜索框架负责初始化、父代选择与子代保留；TraceAAD 只决定给定父代之后做什么修改，以及如何利用每次修改的结果。

**尝试记录与设计轨迹。** 子代 c 相对父代 p 的代码改动称为一次**修改**（edit）m。每次尝试，无论是否产生有效程序、是否进入种群，都留下一条**尝试记录**，包含父代、选项、实际绑定、子代、执行是否合规、收益估计、执行前测得的条件、评价协议、资源开销与来源（发现、普通重放、诊断重放或缓存复用）。全部记录按宿主真实的父子关系构成**谱系树**，d(p, q) 表示 p 与 q 在树上相隔的修改次数。程序 p 的**设计轨迹**（design trajectory）T(p) 是父代位于 p 的祖先路径上的全部记录：产生了祖先的记录称为**路径修改**，说明 p 是怎样形成的；其余记录称为**旁支尝试**。对于使用多个父代的算子，记录保留全部来源，并指定主父代以延伸祖先路径。

**变换与重放。** **变换**（transformation）τ 是一个可以在不同程序上再次实施的修改，以规格表示，其身份由设计操作与语义参数共同确定（3.3）。若 p 满足 τ 的执行前提，称 τ **可应用**于 p。将 τ 施加到 p 上称为一次**重放**（replay），得到子代 τ(p)；通过核验的重放称为 τ 的一个**实例**。

**单次尝试的目标。** 令 A ∈ {0, 1} 表示一次尝试是否通过执行核验并产生满足任务要求的有效程序。定义归一化正增益

```latex
G = A \cdot \frac{\big[\widehat{\Delta} - \delta\big]_+}{s_g}
```

其中 δ 是由评价噪声确定的改进阈值，s\_g > 0 是在运行开始时确定并冻结的增益尺度；原始带符号的增益完整保存。对父代 p 与选项 o（重放某个变换，或由 LLM 做一次**自由修改**），选择准则是单次尝试的期望正增益：

```latex
\mu(p, o) = \mathbb{E}[G \mid p, o] = v(p, o)\cdot \rho(p, o)\cdot z(p, o)
```

其中 v 是产生合规有效程序的概率，ρ 是合规执行后超过改进阈值的概率，z 是超过阈值后的平均归一化增益。这一分解区分了两类失败：执行器没有完成规定的操作，与规定的操作没有带来改进。前者降低尝试的实际价值，但不构成该设计操作的负面性能证据：预筛选的实现破坏了可行性检查，不等于预筛选本身在该程序上无效。μ 衡量的是局部改良，即子代是否改进父代、改进多少；在宿主也保留未改进子代的情形下，它不等于子代对整个搜索的价值（附录 B.2）。

**每一轮的决策。** 给定父代 p，这一轮要在可应用于 p 的变换与自由修改之间做出选择，使期望正增益尽量大，同时为以后的决策积累证据。这面临三个困难，对应引言中的三个问题：只有修改成为可核验的对象，μ 才能对同一个变换累积估计（3.3）；历史结果是否仍适用于 p，取决于此后的程序变化，需要有针对性地获取对照证据（3.4）；μ 随 p 变化，而每个变换只在少数程序上执行过，对 p 的估计必须在全局经验与条件经验之间做出权衡（3.5）。

### 3.2 概览

TraceAAD 可以嵌入任何维护种群的进化搜索框架。它不改变父代选择与子代保留，只改变给定父代后做什么修改，以及如何利用每次修改的结果。它维护两个共享的数据结构：尝试记录的集合 R 与变换库 L。L 中的每个变换带有规格、执行记录、收益条件的求值结果，以及各收益模型的后验与权重。

&#91;embedded content: 图 3 · TraceAAD 总览\]

如图 3 所示，搜索框架给出父代 p 后，TraceAAD 依次做四件事：

1. 列出满足执行前提的变换及其合法绑定，求值或读取 p 的收益条件（3.3、3.5）。
2. 若本轮属于诊断份额，且存在对新增执行预测分歧较大的合格轨迹对照，则安排相应的配对重放（3.4）；否则按各模型的权重抽样每个选项的期望正增益，用 Thompson 采样在重放与自由修改之间选择（3.5）。
3. 重放选中的变换并核验（3.3），或由 LLM 做一次自由修改（3.6）；若子代与已评价的程序完全相同，直接复用其评价（3.4）。
4. 评价子代并写回记录，更新各收益模型及其权重；若自由修改改进了父代且不属于已有变换，则沉淀为新变换，其发现记录不计入条件信用（3.3）。

三个机制形成一条链：机制一提供可核验的行动对象，机制二沿轨迹为这些对象获取条件变化的对照证据，机制三据此学习条件信用，并决定对当前父代重放什么；每次执行的结果又回到记录中，成为下一次决策的证据。

### 3.3 机制一：可核验的变换

**针对的问题。** 现有方法复用经验时，由 LLM 依据文字重新生成修改。重新执行同一提示几乎从不得到原来的程序，尽管所得程序能恢复原得分的中位数 0.76 \[8\]：结构性收益在一定程度上可以通过重新生成恢复，但系统并不知道被恢复的是哪个操作、执行是否到位，结果也就无法归到同一个对象上。需要保持的不是代码逐字相同，而是设计操作相同，并且这一点可以核验。

**规格。** 变换以如下字段表示：

| 字段 | 含义 |
| --- | --- |
| 身份与版本 | 由设计操作、语义参数、绑定策略与执行器版本共同确定 |
| 执行前提 | 程序必须具备的接口、结构与可检查条件 |
| 操作与不变量 | 必须发生的设计变化，以及必须保留的计算与约束 |
| 绑定与语义参数 | 作用位置的定位方式，以及必须固定的算法选择 |
| 核验器 | 编辑范围、修改特征、依赖、接口与小规模运行检查 |
| 收益条件假设 | 至多三条可在执行前求值的条件 |
| 来源 | 原始父代与子代、代码差分、评价及规格生成记录 |

**固定设计操作，只适配实现。** 变量名、接口名称与数据结构的角色可以随目标程序绑定；评分函数、候选截断规则、搜索策略等决定算法行为的选择属于语义参数，必须固定，改变它们即构成新的变体。例如，“以到当前城市的距离预评分，保留最近的十个候选”是一个具体的变换；“选择某种廉价评分，保留适当数量的候选”则尚未固定主要的算法决策。真正决定效果的选择不能作为“适配细节”交还给 LLM 临时决定，否则一个变换名下的信用会混入每次参数选择的优劣。

**沉淀与合并。** 自由修改改进父代后，系统依据实际代码差分提取规格。若一次修改包含不可拆分的多个计算，作为整体变换保存；若它混合了多个独立的设计改变，则不把总增益分别归给它们，拆分需要额外评价。只有设计操作、语义参数与绑定策略都一致的记录才共享信用；规格扩展或执行策略改变时创建新版本，旧结果不自动归入新版本。自由修改中恰好符合已有变换的改动保留关联标签，但不与显式选择后的受约束重放混合估计，以免执行来源不同造成混淆。

**发现记录不作为验证。** 变换之所以被沉淀，是因为它的第一次执行成功了。若把这条经过成功筛选的记录计入收益估计，改进概率会被系统性地高估。因此，原始成功只用于定义变换、提供实现示例，标记为**发现记录**；条件信用只来自规格冻结之后的重放。

**重放与核验。** 能写成确定性重写规则的变换由匹配器直接执行，不调用 LLM；其余变换由 LLM 按规格在受限范围内实现，只允许改动匹配位置及满足不变量所必需的代码。核验器检查实际改动是否符合操作、不变量与任务接口，并进行限时的小规模运行。需要修复时，至多允许一次保持同一操作的受约束修复，全部调用计入同一次尝试的开销。未通过核验的尝试不进入该变换的性能记录，只进入执行可靠性记录。

**保证。** “同一个设计操作”成为可检验的性质：一个变换名下的全部性能观察都来自同一种操作、同一组语义参数，且均为规格冻结后的重放，因而可以被累积与比较；执行可靠性与性能收益分开记录。这是机制二与机制三的前提。

### 3.4 机制二：沿设计轨迹的配对重放

**针对的问题。** 同一谱系中约 30% 新增的代码行与此前删除的代码逐字相同 \[8\]。这类重复究竟是浪费的重试，还是条件改变后合理的再尝试，取决于此后的程序变化是否改变了相关修改的效果。一种直接的做法是假定谱系相近的程序共享收益；但相邻程序可能只经历了一次修改，而这次修改恰好改变了某个变换赖以生效的条件，来自不同分支的程序反而可能共享这些条件。因此，关键不在于“历史结果离当前程序有多近”，而在于“程序变化之后，同一个修改的收益改变了多少”。

**配对重放。** 设变换 τ 已在程序 q 上完成重放，随后一次路径修改 σ 得到 p = σ(q)。将 τ 再施加于 p，定义配对差异

```latex
D_{\tau;\sigma}(q) = \big[f(\tau(\sigma(q))) - f(\sigma(q))\big] - \big[f(\tau(q)) - f(q)\big]
```

它度量同一变换的边际收益在程序变化 σ 前后改变了多少，即 σ 与 τ 之间的局部上位效应 \[43, 44\]。若 q、p 与规格冻结后重放得到的 τ(q) 已在同一协议下评价，完成对照只需新增评价 τ(p)（图 4），新增评价计入搜索预算。当 p 与 q 相隔多个步骤，或位于具有近期共同祖先的不同分支时，记录背景收益差异 D_τ(q, p) = Δ̂(p, τ(p)) − Δ̂(q, τ(q))。这种差异对应整体背景变化，不归因于其中某一个修改。

构成对照须满足三个条件：q 与 p 存在上述可追溯的轨迹关系；τ 在两个程序上都满足执行前提；绑定对应同一计算角色。q 上还须有规格冻结后、通过核验的重放记录，相关评价协议须一致。已有收益条件发生变化是选择对照的优先依据，不是入口门槛。即使所有已知条件取值相同，谱系模型与其他模型对新增执行的预测分歧仍可触发诊断。这样可以检验 LLM 提出的条件未覆盖的背景变化。

&#91;embedded content: 图 4 · 沿设计轨迹的配对重放（示意）\]

**主动选择诊断。** 轨迹限定可比较的对照，模型分歧选择值得新增的执行。对当前父代 p 与变换 τ，以各模型对 μ(p, τ) 的预测均值在模型权重下的方差作为分歧分数 S(p, τ)（附录 A.5），优先选择分数最大的合格候选。这是面向行动价值的分歧启发式，与按委员会分歧选样的思路一致 \[47\]。分数相同时，优先选择已有收益条件发生变化的对照，再优先选择相邻程序、路径较短的程序，以及相应背景变化上已有对照较少的变换。所有分数均未超过阈值时，不消耗诊断份额。诊断只在宿主已选出的父代上进行，不改变父代调度；没有可比较的轨迹时，普通跨程序重放仍然积累数据。

**测量与决策分开。** D 保留带符号收益，用于描述观察到的局部交互或背景收益差异；μ 估计截断并归一化后的期望正增益，用于决定下一次尝试；S 衡量模型对新增执行行动价值的分歧，用于诊断选择。μ(p, τ) − μ(q, τ) 不预测带符号的 D。旧程序 q 上的实际结果用于补全对照，不用各模型对 q 的回顾性预测制造诊断分数。

**证据只计一次。** 配对中的两次重放各是一条执行观察，按常规更新收益模型；它们的差值用于诊断选择、解释与离线评估，不作为第三条独立样本再次计入。

**重复与回退不是禁令。** 若子代与一个已评价的程序在完整评价键（程序、依赖、评价器、实例、种子与运行环境）上完全相同，直接复用其评价，但缓存分数不作为新的独立观察。除此之外，局部代码相同、重复历史失败或撤销过去的改动，都不构成禁令：它们的结果与其他执行一样进入收益模型，是否值得再次尝试由机制三判断。成功经验的迁移需要条件，失败经验的迁移同样需要条件。

**作用。** 配对重放利用已有评价获取背景变化前后的收益证据。前三个状态齐备时，对照只需一次新增评价。它是否能在有限预算内持续提供有用证据，取决于合格对照的发生频率和重放覆盖范围；这些量与选择收益一起报告（第 4 节）。

### 3.5 机制三：条件信用与选择

**针对的问题。** 带来增益的修改稀少，却往往只被使用一次 \[8\]；而修改的效果又依赖程序（图 2），不加区分地四处重放同样会浪费评价。对给定父代，系统需要在“全局上通常有效”的经验与“在相似条件下有效”的经验之间做出权衡，而在数据稀少时，这一权衡本身也应当由证据决定。

**执行前提与收益条件。** 执行前提不满足时，变换无法实施；收益条件不满足时，变换仍可能有用，只是其收益分布需要另行估计。冻结规格时，LLM 为每个变换提出至多三条收益条件假设 h\_j(p)，每条都是可在执行前求值的命题，如“每步候选数大于 50”“评分函数占运行时间一半以上”，由静态检查或固定探针求值；数值阈值在后续重放之前固定，无法求值时记为未知，而不按假处理。

**收益模型。** 每个统计单元维护三个量的后验：执行成功 A \~ Bernoulli(v)，合规执行后的改进 Y \~ Bernoulli(ρ)，改进时的归一化增益 Z \~ Exponential(λ)。采用共轭先验 v \~ Beta、ρ \~ Beta、λ \~ Gamma，于是 μ = vρ/λ，且每次观察都可以闭式更新（附录 A）。对每个变换 τ，系统并行维护一组收益模型：

- **全局模型 M\_0**：一个统计单元，汇集 τ 在规格冻结后的全部实例。
- **单条件模型 M\_j**：按条件 h\_j 的真假各用一个统计单元；条件未知时退回全局预测。
- **谱系模型 M\_gen**：以 γ^{d(p, q)} 为权重汇集各实例，把“谱系相近的程序收益相近”作为一个可检验的假设，而不是预设。

单条件模型不要求多个条件同时匹配，因而不会把少量数据切碎为大量联合状态。

**以预测表现分配权重。** 每次执行之前，各模型给出对本次结果的预测；结果出现后，按其预测概率更新权重：

```latex
\pi_{j,t+1} \propto \pi_{j,t}\cdot P_{M_j,t}\big(A_t, Y_t, Z_t \mid x_\tau(p_t)\big)
```

其中 x\_τ(p\_t) 是执行前测得的条件取值。这是前序（prequential）评价下的贝叶斯模型平均 \[45, 46\]：哪个模型更能预测尚未发生的执行结果，哪个模型就获得更大的权重。未通过核验时只更新执行部分，未改进时不产生增益幅度的观察。初始时一半权重给全局模型，另一半由其余模型均分。收益条件由 LLM 提出，使用权重由执行证据决定；运行中依据已有结果提出的新条件，只从提出之后的预测开始接受评分，不以解释过的数据证明自身。

**选择。** 对每个可应用的变换，先按模型权重抽取一个模型，再从该模型的后验中抽取 v、ρ、λ，得到 μ̃(p, τ) = ṽρ̃/λ̃；自由修改以其全局统计同样抽样。系统执行抽样值最大的选项，即 Thompson 采样 \[39\]。证据充分且增益高的重放被优先选择；证据不足的重放因后验较宽仍有机会；没有值得重放的变换时，自由修改自然被选中。由于估计的是期望正增益而不只是改进概率，稀少但增益大的结构性修改不会被频繁但增益小的调参淹没。

&#91;embedded content: 图 5 · 为父代 p 决定重放什么（示意）\]

图 5 给出一个例子：τ2 在 p1 上未改进，且 p1 → p 未改变其收益条件，各模型都预测其期望正增益较低；τ4 在 p0 上未改进、在 q2 上改进，全局模型与条件模型对它在 p 上的预测分歧较大，适合安排配对诊断；τ5 在与 p 满足同一获得支持的收益条件的 q1、q2 上都带来了增益，因而最可能被重放。

**保证。** 经验的使用范围由证据决定：条件获得支持之前，全局模型保留权重；能够预测后续执行的条件获得更大的权重；谱系相近是否意味着收益相近，同样由预测表现裁决。随着运行的积累，变换库成为一份“操作 + 执行记录 + 条件收益证据”的知识。

### 3.6 自由修改、预算份额与多子种群

**自由修改。** 变换库只能重放已经出现过的修改，新的修改来自自由修改。自由修改沿用宿主的算子组合与提示策略，并把 p 的设计轨迹摘要提供给 LLM：路径修改各做了什么、带来多少增益，未改进的旁支尝试作用于何处。它产生的子代同样复用完全相同程序的评价；若改进了父代且不属于已有变换，就由机制一沉淀为新变换。两种产生子代的方式各有分工：自由修改负责发现，重放负责利用与检验。

**预算份额。** 新的变换只能来自自由修改，若完全依赖有限动作集合上的后验抽样，行动库的扩张可能受到抑制。因此，每十次尝试中至少两次保留给自由修改，至多一次用于诊断重放（须存在合适的对照与足够的模型分歧），其余机会由 Thompson 采样在变换与自由修改之间分配；变换库为空时全部执行自由修改。诊断的 10% 是预算上限，实际使用比例由对照机会与预测分歧共同决定，不等于机制实际得到使用的比例。这些比例是初始配置，其敏感性在开发任务上检查（附录 A）。

**多子种群。** 为了让搜索容纳不同的算法思路，种群可划分为若干子种群，各自从不同的初始思路出发；父代选择与保留规则沿用已有的多种群做法。所有子种群共享尝试记录与变换库。一个子种群中沉淀的变换，只要在另一子种群的程序上满足执行前提，就可能被重放；它在新思路中是否仍然有效，由条件模型与实际执行结果决定。

### 3.7 算法流程

算法 1 汇总了一轮的步骤。模板型重放不调用 LLM；规格型重放与自由修改各需一次调用，受约束修复至多再加一次；规格沉淀与条件提出只在触发时调用。

```text
算法 1  TraceAAD
输入：宿主搜索框架，评价器，评价预算与模型调用预算，变换库 L（可为空，或来自此前的运行）
初始化：尝试记录 R ← ∅，评价缓存 ← ∅
暖启动：执行固定次数的自由修改，冻结任务级弱先验与增益尺度 s_g

while 预算允许下一次完整尝试:
    p ← 宿主选择父代
    Γ ← 满足执行前提的变换及其合法绑定；求值或读取 p 的收益条件        ▷ 3.3 / 3.5
    if 本轮属于自由修改份额，或 Γ 为空:
        o ← 自由修改                                                           ▷ 3.6
    else if 本轮属于诊断份额，且存在 S(p, τ) > κ_d 的合格轨迹对照 (q, p, τ):
        o ← S(p, τ) 最大的候选变换（同分按对照优先规则选择）                                                    ▷ 3.4
    else:
        for o′ ∈ Γ ∪ {自由修改}: 按模型权重抽样 μ̃(p, o′)                       ▷ 3.5
        o ← argmax μ̃
    保存执行前各模型的预测与条件取值
    c ← 受约束重放 o 并核验（至多一次受约束修复），或由 LLM 做自由修改     ▷ 3.3 / 3.6
    if 未通过核验或没有有效程序:
        记录失败与全部开销；更新执行可靠性与模型权重；continue
    若完整评价键已存在则复用结果（不作为新观察），否则评价 c                ▷ 3.4
    记录收益、实际绑定、来源与开销；对规格冻结后的重放更新各模型及其权重一次   ▷ 3.5
    若完成配对对照，登记带符号的 D 及背景关系，不追加独立样本                                     ▷ 3.4
    if 自由修改改进了父代且不属于已有变换:
        沉淀并冻结规格、语义参数、核验器与收益条件；原始成功记为发现记录    ▷ 3.3
    宿主决定 c 是否进入种群
输出：最优程序，以及带有执行记录与条件收益证据的变换库 L
```

## 4 实验设计

TraceAAD 的核心主张是：把修改转化为可核验的变换，并以沿轨迹的配对重放获取条件证据之后，系统能学到同一个修改在不同程序上的价值差异，并据此做出更好的下一次修改。实验围绕一条论证链组织：执行对象是否稳定 → 条件证据是否改善未见程序上的选择 → 决策上的增益是否覆盖完整搜索中的资源开销 → 知识能否跨运行积累。若主张成立，应当观察到：

- **P1**：在相同的变换内容下，按规格执行并核验所得的记录，比把变换作为启发交给 LLM 所得的记录，操作更一致，对下一次重放收益的预测也更准确。
- **P2**：同一变换在不同程序上的收益存在显著差异，不同父代上的变换排序会发生反转；以程序为条件的选择，在未参与估计的程序上选出实际收益更高的变换。
- **P3**：在新增评价数量相同、收益模型与执行器相同的条件下，轨迹配对主动重放比随机重放与非配对主动重放带来更好的后续选择；后两种主动方式使用相同的预测分歧准则。
- **P4**：变换能迁移到与其来源不共享代码块的程序（其他子种群与后续运行），且同时迁移条件证据比只迁移规格更能减少负迁移。

**实验设置。** 主任务采用 EoH、ReEvo 与 MCTS-AHD 使用的标准基准：旅行商问题与容量约束车辆路径问题的启发式设计、在线装箱问题以及流水车间调度问题；加入 Code Graph \[41\] 使用的选址-路径问题以便直接比较，并选取评价代价较高的代码优化任务。各任务固定算法接口、目标、时间约束与训练—测试划分。至少使用两种能力水平的 LLM，并固定版本与调用设置。主结果使用空变换库启动，暖启动、沉淀、探针、核验、失败、诊断与修复全部计入开销；分别报告固定评价预算与固定模型调用预算下的结果。统计单位是独立的搜索运行，而不是同一运行中的程序；机制实验按初始化家族或独立运行划分数据，避免把相邻程序分别放入训练集与测试集。

**RQ1：规格与核验能否形成稳定的行动对象？（P1）** 冻结同一批变换、源实例与目标程序，比较三种执行方式：作为启发交给 LLM 自由实现、按规格受约束执行、按规格执行并核验。度量实际语义操作是否符合规格、是否夹带无关改动、执行成功率、每次有效执行的开销，以及各方式积累的记录对下一次重放收益的预测准确度。语义一致性由独立审查结合功能测试评定，不以方法自身的核验结果证明自身；重点是操作的一致性与收益分布，而非逐字节的复现率。

**RQ2：条件信用与配对重放能否改善下一次修改的选择？（P2、P3）** 在独立的发现运行中形成变换库并冻结；在未参与发现的程序家族上，交叉评价兼容的“父代—变换”组合，建立受控结果矩阵。先检验同一变换的跨程序收益差异与排序反转，再比较全局信用、仅用谱系距离、条件模型，以及把同样历史证据交给 LLM 选择。Code Graph 的修改组合代理预测作为单独的机制参照，完整 Code Graph 在 RQ3 比较；每个修改一个全局分数仅是简化机制对照，不代表完整 Code Graph。核心指标是被选变换的留出执行收益、未改进尝试比例，以及相对矩阵最优选择的损失。

为区分一般主动选样与轨迹配对的作用，固定收益模型、执行器、宿主父代序列及共同的可应用性与绑定规则，比较三种新增评价策略：

| 策略 | 新增评价怎样选择 |
| --- | --- |
| 随机重放 | 从当前父代的可执行变换中随机选择。 |
| 非配对主动重放 | 按相同的 S(p, τ) 选择，不要求存在轨迹对照。 |
| 轨迹配对主动重放 | 按 S(p, τ) 在合格轨迹对照对应的变换中选择。 |

三组使用相同的初始记录与新增评价预算；轨迹配对组仅额外要求对照资格。两种主动策略使用相同的分歧阈值和未过阈值时的普通选择规则。同一变换有多个参考程序 q 时，只把当前父代上的执行作为一个候选。无合格对照或分歧未过阈值时，轨迹配对组回到相同的普通选择，并记录回退比例。先在存在合格对照的轮次比较三种策略，再在包含回退的完整序列上比较实际收益。若轨迹配对组只优于随机重放，证据支持主动选样；若还优于非配对主动重放，才支持轨迹对照约束使同等评价预算更有用。

同时记录三类机会与覆盖指标：存在合格对照的决策轮比例；每个变换在规格冻结后实际获得的前瞻重放次数；这些重放覆盖的不同程序背景数，并分开报告已知条件取值相同与不同的背景。另报告实际诊断比例、未触发原因和同等预算下的选择收益。先用这些指标判断对照机会是否足够，再判断其能否成为搜索效率的主要来源。

**RQ3：TraceAAD 能否提高完整搜索的资源效率？** 优先比较宿主原方法、完整 Code Graph，以及使用相同收益模型的非配对主动重放版本；在固定任务与预算后，再选择与历史利用方式最接近的方法作为补充。将 TraceAAD 嵌入多个框架，与原框架成对比较。报告测试性能、最优程序随预算变化的曲线、单位资源的有效改进、核验失败开销，以及对照机会、实际诊断比例与诊断回报。消融固定宿主、初始化与自由修改策略，优先检验核验、条件模型、谱系模型与轨迹配对的作用；发现记录排除、自由修改最低份额、改进概率与期望正增益、后验均值与 Thompson 采样的差别作为后续机制分析。局部重复比例只作为诊断指标：某次重复若在新条件下带来改进，应视为有效的再尝试。

**RQ4：变换库能否形成可迁移的设计知识？（P4）** 将冻结的变换库用于未见的初始化家族与后续独立运行，比较冷启动、只迁移变换规格、同时迁移规格与条件证据三种设置，度量达到同等性能所需的资源、条件预测的质量与负迁移的比例；既有运行的知识成本单独报告。案例分析至少展示一次跨程序的收益排序变化，以及系统如何据此改变下一次修改的选择。主检验集中于同一任务分布下的跨运行迁移，跨任务迁移作为补充。

### 附录 A 统计实现与实现细节

**A.1 位置与绑定。** 修改的位置定义在语法树上：对父代与子代做语法树差分，找出发生变化的最小语句级节点，以“所在函数 + 从函数根到该节点的路径”标识。位置沿谱系传递：每次路径修改的差分给出前后两个程序之间的节点对应，沿祖先路径复合这些对应，即可把祖先上的位置映射到当前程序。配对重放要求 τ 在 q 与 p 上的绑定对应同一计算角色，即二者的作用位置在这一映射下相互对应。若 τ 的实例已出现在 p 的路径修改中且其位置此后未被改动，τ 对 p 视为不可应用，因为其效果已在 p 中；同一变换也不在同一程序上以相同绑定重放两次。

**A.2 评价协议与缓存。** 父代与子代使用配对的实例与随机种子，Δ̂ 取逐实例得分差的平均，以减少评价噪声对比较的影响。改进阈值 δ 在评价确定时取一个很小的容差；评价有随机性时，取初始程序重复评价所得差值标准差的两倍。完整评价键由程序的归一化代码、依赖、评价器版本、实例、种子与运行环境构成；命中缓存的结果直接复用，但新的生成尝试命中旧程序时只记录其出现频率，不把缓存分数当作新的独立观察。运行时间型任务使用相同硬件与配对计时协议。

**A.3 统计单元与更新。** 每个统计单元（全局单元，或某条件取真、取假时的单元）维护

```latex
A \sim \mathrm{Bernoulli}(v), \qquad Y \mid A = 1 \sim \mathrm{Bernoulli}(\rho), \qquad Z \mid A = 1, Y = 1 \sim \mathrm{Exponential}(\lambda)
```

于是 μ = vρ/λ。指数分布是低样本下的工作模型，其适用性通过留出预测与决策效果评价，而不作为对真实增益分布的断言。采用独立的共轭先验 v \~ Beta(a\_v, b\_v)，ρ \~ Beta(a\_ρ, b\_ρ)，λ \~ Gamma(k\_0, b\_0)（shape–rate 参数化，k\_0 > 2）。记 n\_v 为合规有效次数，n\_f 为执行失败次数，n\_+ 为改进次数，n\_− 为合规但未改进次数，S\_+ 为归一化正增益之和，则

```latex
v \mid \mathcal{R} \sim \mathrm{Beta}(a_v + n_v,\, b_v + n_f), \quad \rho \mid \mathcal{R} \sim \mathrm{Beta}(a_\rho + n_+,\, b_\rho + n_-), \quad \lambda \mid \mathcal{R} \sim \mathrm{Gamma}(k_0 + n_+,\, b_0 + S_+)
```

抽样后计算 μ̃ = ṽρ̃/λ̃。谱系模型以权重 w\_q = γ^{d(p, q)} 代替计数，各计数项与 S\_+ 均改为加权和，因此证据越少、越远，后验越接近先验、越不确定。同一批记录不会同时进入先验与更新项。

**A.4 模型权重与预测评分。** 对变换 τ 的模型集合 {M\_0, M\_1, …, M\_J, M\_gen}，每次规格冻结后的重放之前记录各模型的预测分布，执行之后以其后验预测概率更新权重：合规与否的概率来自 v 的 Beta–Bernoulli 预测分布，改进与否来自 ρ 的预测分布，增益幅度来自 λ 的 Gamma–指数预测分布（即 Lomax 分布）。未通过核验时只计入执行部分，未改进时不计入幅度部分。初始权重为 π\_0 = 1/2，其余模型均分另外的 1/2。条件未知时，相应模型给出与全局模型相同的预测，其权重因而不因这次观察而相对改变。报告时，将执行可靠性的变化与性能收益的变化分开展示。

**A.5 诊断的选择。** 对宿主选出的父代 p，先按 3.4 构造合格轨迹对照 (q, p, τ)。条件变化是同分时的优先依据，不是入口门槛。令 μ̂_M(p, τ) 为模型 M 在执行前给出的期望正增益后验均值，定义

```latex
\bar{\mu}(p,\tau) = \sum_M \pi_{\tau,M}\widehat{\mu}_M(p,\tau), \qquad
S(p,\tau) = \sum_M \pi_{\tau,M}\big[\widehat{\mu}_M(p,\tau)-\bar{\mu}(p,\tau)\big]^2
```

S 只衡量模型对新增执行的行动价值预测分歧，不预测带符号的上位效应，也不等同于信息增益。q 上的实际结果只用于完成配对。对同一 τ 的多个参考 q，不重复增加该变换的选择机会；按条件变化、路径长度与已有对照覆盖情况选择参考。只有 S 超过阈值 κ\_d 时才安排诊断，取分数最大的候选；同分时按 3.4 的规则选择。无合格对照或所有分数均未过阈值时，该次机会回到普通选择，并记录原因。

**A.6 先验与暖启动。** 主版本以前 16 次自由修改建立任务级弱先验，所有模型共用同一套冻结的先验，暖启动记录不再作为后续单元的普通样本重复加入。执行成功率与改进率的 Beta 先验取加一平滑后的暖启动频率，总强度为 2。若暖启动出现正增益，以超过阈值部分的平均值确定 s\_g，使归一化正增益的先验平均尺度为 1；若没有，则依据非零配对增益的绝对值或任务预先规定的尺度确定。取 k\_0 = 3、b\_0 = k\_0 − 1，使 E\[1/λ\] = 1。

**A.7 规格、核验与独立审查。** 规格以结构化记录保存。判断新修改是否属于已有变换时，先按操作与语义参数的文本嵌入检索库中最相近的若干变换，由 LLM 判断操作、语义参数与绑定策略是否一致，再由程序检查新改动是否满足该变换的修改特征。模板型重放以带元变量的“模式 → 替换”规则表示，由结构化重写工具（如 Comby、Semgrep 的自动修复或 LibCST）执行；一个规格型变换积累三个以上实例后，LLM 尝试为其写出模板，模板能复现已有实例的改动时被采用。规格型重放把规格、参考实例的改动与标出匹配位置的父代交给 LLM，要求改动限于匹配位置及满足不变量所必需的代码。核验器自身的准确性由独立审查与受控实验评估（RQ1）。

### 附录 B 设计取舍

**B.1 为什么把信用落在具体修改上。** 信用分配要求被分配信用的单位既能被识别，也能在新的情境中再次出现。程序可以被识别，却不会在别处再次出现；见解、概念与提示算子可以反复使用，但每次使用产生的修改都不同，它们得到的信用混入了 LLM 每次实现的差异。具体修改在成为可核验的变换之后同时满足两点：它的身份由设计操作与语义参数确定且可以核验，它在不同程序上的结果可以直接比较。经典的自适应算子选择 \[16\] 之所以能够工作，正是因为算子满足这两点；TraceAAD 在 LLM-AAD 中重建了这一前提。

**B.2 为什么估计单次尝试的期望正增益。** 若宿主框架丢弃未改进的子代（如以父代为基准的替换），一次失败的代价只是一次评价，对所有选项都一样。此时决策关心的是改进的概率与幅度，而不是失败的程度。只估计改进概率，会偏向频繁但增益小的调参；估计带符号的期望增益，则会惩罚失败时损失大、成功时增益也大的结构性修改，而这种损失在子代被丢弃后并不会真正发生。期望正增益 E\[G\] 正好对应这一代价结构。将执行成功率 v 纳入其中，是因为执行失败的尝试同样消耗调用与时间：执行器经常出错的变换，即使其操作本身有效，单次尝试的价值也较低。在也保留未改进子代的框架中（如按种群排名保留子代），期望正增益仍是局部改良的合理准则，但不再等于子代对整个搜索的价值；TraceAAD 不试图估计后者（B.3）。

**B.3 为什么只估计单步结果。** 程序在未来搜索中的潜力不可观察，对它的任何估计都依赖额外的模型与假设；单步结果则在每次重放后直接得到。长期效果由宿主框架通过选择逐步累积，TraceAAD 不替它做这件事。由于目标包含增益的幅度，单步决策也不会只追逐容易得到的小改进。

**B.4 为什么用配对重放，而不预设谱系相近即收益相近。** 预测变换在程序上的结果，与协同过滤中预测用户对物品的评分同构：程序对应用户，变换对应物品，执行结果对应评分。邻域方法 \[40\] 用相似用户的评分做预测；谱系提供了一种现成的相似度，相距 d 的两个程序只差 d 次已记录的修改。但这种相似只是代理：一次修改就可能改变关键条件，而不同分支的程序也可能共享条件。因此，TraceAAD 不预设谱系相近即收益相近，而是把它作为谱系模型交给预测评分裁决；配对重放则测量背景变化前后的实际收益差异，并按新增执行的预测分歧选择对照。这样的观察是否比同样主动但不要求配对的选样更有用，由 RQ2 检验。代码文本的相似度也可作为补充预测参照，核心比较仍是上述三种新增评价策略。

**B.5 为什么历史失败不是禁令。** 修改的效果依赖程序，这对失败同样成立：在祖先上失败的局部配置，在此后的修改之后可能成功。若在评价之前无条件拒绝，系统永远得不到这样的证据，而这恰是学习修改在哪里有效所需要的。因此，只有评价键完全相同的程序才直接复用评价：评价确定时，重新评价不提供新信息；评价有随机性时，重新评价只是再抽一次噪声，挑出更幸运的一次正是赢家诅咒。其余重复与回退都作为普通观察进入收益模型，局部重复的比例只作为诊断指标。

**B.6 为什么收益条件由 LLM 提出、以预测表现检验。** 可能决定变换效果的程序性质是开放的，固定的特征集合（如 Milepost GCC \[34\] 的程序特征）难以覆盖在线产生的变换。LLM 能提出有语义的候选条件，但它对“修改在哪里有效”的判断本身并不可靠：DeltaEvolve \[11\] 写下的“为何有效”的假设从未被检验。与显著性检验相比，以前序预测评分分配权重更适合在线场景：它不需要预先确定样本量，也不因反复检验而膨胀错误发现；条件只用提出之后的数据评分，避免以解释过的数据证明自身。采用单条件模型而非联合条件，可以避免在数据稀少时把样本切碎。错误的条件只会失去权重，评分本身不调用 LLM。

**B.7 为什么排除发现记录。** 变换之所以被沉淀，是因为它的第一次执行成功了；这条记录经过了成功筛选，计入估计会使改进概率系统性偏高，属于选择偏差。同理，自由修改中事后识别出的同类改动，其执行来源与受约束重放不同，混合估计会引入混淆。二者都保留为关联记录，用于定义变换与解释结果，不进入条件信用。

**B.8 为什么保留自由修改的最低份额。** Thompson 采样在给定的动作集合上平衡探索与利用，但新的变换只能来自自由修改。若变换库早期出现几个高收益的变换，后验抽样可能长期偏向它们，使行动库停止扩张。最低份额保证发现持续进行；诊断份额的上限则防止信息收集挤占改进程序的机会。

**B.9 刻意没有引入的部分。** TraceAAD 不估计程序的长期价值，不训练神经代理模型，不让 LLM 决定是否重放，也不改变父代选择与种群管理；多样性只通过子种群维持；对局部重复不设专门的拒绝规则。三个机制分别处理操作一致性、对照证据和经验使用范围；它们各自的实际作用由 RQ2 的受控比较与 RQ3 的消融检验。

### 附录 C 扩展

**C.1 跨任务迁移。** 变换的设计操作常常不依赖具体任务（如候选预筛选、增量评价、缓存），绑定则随任务而定。把一个任务的变换库带到另一个任务时，执行前提在新任务的程序上重新匹配；收益条件保留，但各模型的权重重置为初始值，重新接受预测评分。RQ4 以此方式进行跨任务迁移的补充实验。

**C.2 复合变换。** 若配对重放显示两个变换之间存在稳定的正向上位效应，或它们经常在成功的路径上先后出现，可以把它们合并为一个复合变换。与库学习 \[38\] 以压缩为标准不同，复合变换只有在重放结果优于依次重放其组成部分时才保留。

**C.3 用重放记录训练模型。** 重放记录是一种干净的数据：同一个修改作用于不同程序的可观察结果。它可以用来训练以程序为条件的结果预测器，也可以作为微调 LLM 的数据，与 EvoTune \[23\]、CALM \[24\] 用搜索反馈训练模型的思路结合。

**C.4 多目标与多保真评价。** 多目标设置下（如 MEoH \[19\]），对每个目标分别估计 μ，决策时按宿主框架的标量化或支配关系合并。评价昂贵时，重放得到的子代可以先在少量实例上评价，再决定是否完整评价；期望正增益的后验可以按保真度分层。

**C.5 人工参与。** 变换库由可读的规格、收益条件及其模型权重组成。领域专家可以审阅它，加入新的变换或条件假设；专家给出的假设与 LLM 提出的一样，只在提出之后的重放上接受预测评分。

### 附录 D 变换示例

**D.1 一个变换的规格。** 以图 2 中的候选预筛选为例，设它沉淀自旅行商问题构造式启发式上的一次改进。参考实例的改动如下：

```python
# 父代（片段）：对每个未访问城市做昂贵的前瞻评分
best, best_score = None, float('inf')
for v in unvisited:
    s = lookahead_cost(route, v, dist)
    if s < best_score:
        best, best_score = v, s

# 子代（片段）：先按到当前城市的距离保留最近的 10 个候选
kept = heapq.nsmallest(10, unvisited, key=lambda v: dist[route[-1]][v])
best, best_score = None, float('inf')
for v in kept:
    s = lookahead_cost(route, v, dist)
    if s < best_score:
        best, best_score = v, s
```

沉淀出的规格为：

```yaml
变换: 候选预筛选（距离预评分，保留 10 个）
身份与版本: 操作 + 语义参数 + 绑定策略 + 执行器版本 v1
执行前提:
  - 存在一个循环，逐一遍历已通过可行性过滤的候选集合 C，对每个候选调用评分函数 g，并选出得分最优者
  - 程序中可取得当前位置与距离矩阵
操作与不变量:
  - 在该循环之前，按到当前位置的距离保留 C 中最近的 10 个候选，循环改为遍历保留的候选
  - 原有的可行性过滤先于预筛选执行
  - 保留的候选仍由 g 评分，选择规则不变
  - |C| ≤ 10 时保留全部候选
绑定:
  - C、g、当前位置与距离矩阵在目标程序中对应的变量与函数
语义参数（固定）:
  - 预评分：到当前位置的距离
  - 保留数量：10
核验器:
  - 评分循环之前出现对 C 的截断（如 heapq.nsmallest），截断键为距离
  - 评分循环遍历截断后的集合，且仍调用 g
  - 改动限于匹配位置；在 3 个训练实例上限时运行通过
收益条件假设:
  - H1：每步候选数大于 50（运行计数）
  - H2：g 的调用占运行时间一半以上（运行剖析）
  - H3：距离与 g 给出的候选排序高度一致（在少量实例上测量秩相关）
来源: 发现记录（父代、子代、代码差分与评价），不计入条件信用
```

这一变换有了几个规格型重放的实例后，LLM 尝试把它写成模板；模板能复现已有实例的改动时被采用，此后的重放不再调用 LLM：

```text
模式（元变量记为 :[x]）
    for :[c] in :[C]:
        :[body]
约束
    :[body] 中调用 :[g](..., :[c], ...)，且求最优者
替换
    :[C]_kept = heapq.nsmallest(10, :[C], key=lambda :[c]: :[dist][:[cur]][:[c]])
    for :[c] in :[C]_kept:
        :[body]
```

**D.2 配对重放（示意）。** 以下数字只用于说明机制，不是实验结果。评价目标是在固定运行时间内获得更好的解。设 τ 为 D.1 的变换，q 是一个构造式启发式，σ 是一次改变了候选生成方式的路径修改，p = σ(q)。

| 程序 | 不使用 τ | 使用 τ | τ 的增益 |
| --- | --- | --- | --- |
| q：原候选生成方式 | 70 | 78 | +8 |
| p = σ(q)：改变了候选生成方式 | 73 | 72 | −1 |

配对差异 D = (−1) − (+8) = −9：τ 的边际收益在 σ 之后由正变负。即使前瞻评分函数的源码没有任何变化，候选生成方式的改变也改变了评分函数面对的输入。q、p 与 τ(q) 已在轨迹中评价，这一对照只新增了 τ(p) 一次评价。系统不会把 τ 永久标记为失败，也不会继续把 +8 当作 τ 在所有程序上的收益；它检查冻结的收益条件是否区分了这两次执行，并用后续重放检验这种区分是否具有预测力。

**D.3 条件模型的权重（示意）。** 设该变换已在六个程序上完成规格冻结后的重放，两条假设的取值与重放结果如下：

| 程序 | H1：候选数 > 50 | H2：g 占时 > 50% | 重放结果 |
| --- | --- | --- | --- |
| q1 | 是 | 是 | 改进 |
| q2 | 是 | 是 | 改进 |
| q3 | 是 | 否 | 未改进 |
| q4 | 是 | 是 | 改进 |
| q5 | 是 | 否 | 未改进 |
| q6 | 否 | 是 | 改进 |

H1 为真与为假的两组都不能区分成败；H2 为真时全部改进，为假时全部未改进。在前序评分下，单条件模型 M\_H2 对这些结果的预测概率持续高于全局模型 M\_0 与 M\_H1，其权重随之上升。若后续执行延续这一模式，对一个 H2 为假的父代，按权重抽样的期望正增益会很低，变换不会被重放，尽管它的总体改进率是 4/6；反之，若 H2 不能预测新的结果，M\_H2 的权重会回落，全局模型重新主导。六个实例只用于说明逻辑，实际权重的变化取决于后续执行的数量与结果。这正是图 2 所描述的情形：同一个修改在评价昂贵的程序上有效，在评价便宜的程序上无效。
