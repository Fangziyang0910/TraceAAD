# 对原算法的改动检验

2026-10-06。Explore 提出的是对当前算法的一次改动，改动在它所针对的原算法上检验。实现标识为 V10.19，代码位于 `traceaad/v10_19/`，入口为 `experiments/traceaad_v10_19/`。程序选择、尝试记录、形成路径，以及 Refine 与 Crossover 的上下文和目标句，与 [V10.18](新设计的开发过程.md) 相同。诊断见 [新设计开发诊断与改动检验](../03-现象与检验/2026-10-06-新设计开发诊断与改动检验.md)。

## 0. 要解决的问题

**一个改动是否有价值，要看它加到原算法上之后，原算法是否变好。**

V10.18 把新设计从首版开始单独开发。开发看不到原程序，只与自己的上一版比较。结果是：首版落后 1%–10% 的设计很少追上（3 步内超过原程序 4.6%，V10.17 为 21.6%）；首版越差，越容易“自我改进”，开发预算的约 60% 落在首版落后 10% 以上的设计上。V10.17 的改写能看到原程序，追上得快，但多数是回到原程序再调参数。

## 1. 认识：受控改动

算法专家在一个成熟系统上做实验：改一处，其余不动，比较改动前后。改动失败时，先检查实现是否按意图工作；几次之后仍不成立，就放弃并记下结论。

| 环节 | V10.17 | V10.18 | V10.19 |
| --- | --- | --- | --- |
| 首版写什么 | 改变决策方式（实际多为重写，相似度中位数 0.62） | 同左 | 改变决策方式，保留改动不替换的部分 |
| 谁得到开发 | 随机 1/8 | 全部（首版进入前五名者除外） | 首版没有超过原程序的全部改动 |
| 开发看到什么 | Refine 上下文：形成路径含原程序及更早的历史 | 设计自己的形成过程；原程序只有分数与一句 Design | 原程序完整代码与测量；改动从首版起的形成过程；其他开发尝试 |
| 开发的目标 | 保留当前版本的核心思想，超过当前版本 | 让设计的计算按意图工作，超过当前版本 | 保留改动引入的计算，超过原程序 |
| 何时结束 | 固定 3 步 | 至少 2 步；连续 2 步无改善；最多 8 步；进入前五名 | 某个版本超过原程序；或已开发 3 步 |
| 结果记在哪里 | 各版本自己的经验 | 同左 | 原程序的尝试列表与经验按改动的最好版本记录 |

## 2. 规则

### 2.1 Explore 是对当前算法的改动

目标句：

> Write an algorithm that scores better than the best found so far by changing how the current algorithm makes its decisions, not by tuning it. Keep unchanged the parts of the current algorithm that the change does not replace.

前一句不变（V10.17 起保留：锚定当前算法、改变决策方式）。后一句限定改动范围。首版只替换要替换的计算，分数才主要反映新想法的作用，而不是丢掉了多少成熟细节。上下文与 V10.18 相同。

### 2.2 落后于原程序的改动得到至多 3 步开发

每次 Explore 提出得到新的有效程序（包括修复后有效）时，开启一次探索。

| 条件 | 结果 |
| --- | --- |
| 提出没有产生新程序（重复、修复失败） | 结束（no_program） |
| 改动的最好版本超过原程序 | 结束（improved），普通选择接手 |
| 已开发 3 步 | 结束（cap） |
| 预算用完 / 上下文超限 | 结束（budget / context） |

首版已超过原程序时不开发。每步从改动已达到的最好版本出发，动作为 Develop，照常计入预算，失败照常修复。3 步来自 V10.17：第 1、2、3 步后超过原程序的累计比例为 10.3%、17.0%、21.6%。

### 2.3 开发与新提出共用 Explore 的份额

算子抽样为 Refine 0.40、Explore 0.35、Crossover 0.25。抽到 Explore 时，有正在开发的改动就执行它的下一步，否则选择父代并提出新改动。Refine 份额恢复到接近 V10.17 的水平（普通 Refine 约 38%，另有约 10% 短程改写）。

预期占用：多数首版落后于原程序，每个提出平均约 2.4 步开发；约 990 次搜索生成中，Explore 份额约 346 次，对应约 100 次提出与约 245 次开发。

### 2.4 Develop 的上下文与目标

| 区块 | 内容 |
| --- | --- |
| Current Algorithm | 改动已达到的最好版本，附分数、耗时与调用量 |
| The Algorithm the Change Was Made To | 一句事实：Explore 改动了这个算法，首版得分及与它的比较；本搜索当前最好分数。随后是原程序的测量、Design 与完整代码 |
| How the Change Has Been Developed | 从改动首版开始的形成路径（失败的首版折入修复步骤），每步给 Design、分数与 diff |
| Other Attempts on This Change | 本次改动中没有进入上述路径的开发尝试及结果；产生原程序代码的尝试注明 |

目标句：

> Make the change work in the algorithm it was made to: keep the computation the change introduces and write a version that scores better than that algorithm. Every version and attempt shown above has already been evaluated.

Analysis 要求说明：当前算法与原程序在计算上有何不同，为什么分数更差，什么改动能保留新计算并使分数更好。首版与原程序同分时也会开发（OBP 前期常停在 Best Fit 的 744.5），这时“为什么分数更差”的措辞不准确；正式批次启动后才发现，本批次保留原措辞。

这样设计的理由：

- **原程序完整可见**：开发可以重用原程序中与改动无关的成熟部件。V10.18 隐藏原程序后，开发很少追上。
- **比较对象是原程序**：原样写回原程序得到的是已知代码，没有新结果；只调原程序的参数不满足“保留改动引入的计算”。V10.17 的改写以“超过当前版本”为目标，回到原程序就是最容易的改进。
- **超过原程序即结束**：这时改动已经成立，新版本的分数高于一个经过质量选择的程序，普通选择会继续精炼它。

### 2.5 改动的结果记回原程序

一次 Explore 是从原程序出发的一次尝试。改动结束后，它的结果是改动达到的最好版本：

- **尝试列表**：原程序的尝试列表在这次 Explore 后面写明 `developed in N further steps: best version score Y (improved/worse/same score)`；改动仍在开发时写明 `the change is being developed`。之前列表只给首版分数，一个最终成功的改动会显示为“变差”。
- **经验**：原程序的 `k` 按改动的最好版本是否超过它计数。Develop 尝试仍计入它们出发的版本。

### 2.6 不改变的部分

- 程序选择：`exp(β(q − q_max)) × (k + 3r)/(n + 3)`。
- Refine、Crossover 的上下文与目标句；修复；初始化；最终选择与替补；评价协议与时限。
- 不在提示中展示过去的想法列表，不加入任务专用信息。

## 3. 检验

完整搜索，5 个任务 × 3 路，种子 0–2，两路 Qwen 服务交替，搜索与评价在本机运行（与 V10.18 同一主机）。批次 `20261006_local_v1019`。

| 过程 | 看什么（`diagnostics.json` 的 `explorations`） | 预期 |
| --- | --- | --- |
| 改动范围 | `first_version_similarity_to_start_median` | 高于 V10.17/18 的 0.62 |
| 首版是否成立 | `first_version_improved_start` / `new_programs` | 高于 V10.18 |
| 开发能否让改动成立 | `developed_improved_start` / `developed`，`developed_improved_start_by_steps` | 不低于 V10.17 的 21.6% |
| 新计算是否保留 | `improved_development_similarity_to_first_median`、`..._to_start_median`；`development_returned_start_code` | 与首版的相似度高于 V10.17 的 0.63 |
| 预算 | `development_share_of_search_generations`、`proposal_share_of_search_generations` | 开发约 20%–25% |

再看结果：TSP 前期速度、CVRP 是否出现结构跳跃、各任务 held-out 是否不低于 V10.17。会改变方向的结果见[诊断](../03-现象与检验/2026-10-06-新设计开发诊断与改动检验.md#v1019-的检验与预期)。
