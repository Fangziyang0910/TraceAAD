# 生成后的继续改写

这一阶段比较怎样选择生成起点，以及提出程序后接着改写会产生什么结果。曾尝试按当前质量、已有投入和后代结果组织选择，也尝试先生成文字设计再实现。随机续开发中，退步入口多数未恢复来源水平；后来的同等开发样本又显示，所选 Explore 程序能在少量生成内明显改善。两组需要结合所选设计、生成上下文、开发窗口，以及实际保留的计算来理解。

<summary>对应实现与实验定位</summary>

| 实现标识 | 尝试 | 观察 |
| --- | --- | --- |
| V9.14–V9.15 | V9.14 保留 8 个有效根、单父形成树，Refine/Explore 概率为 0.7/0.3，并展示最近 8 条来时路。V9.15 在质量上加入初生保护和历史增长信号，用 ESS 控制抽样范围。 | V9.15 的增长项广泛改变父代排序，初生保护影响较小；所分析运行的最好程序深度由约 77–115 降至 13–22，任务收益不一致。 |
| V9.16 | 随机给有效 Explore 子代连续三次 Refine；entry 只记录来源，不承担算法类别识别。 | 所分析的 415 个初生退步入口中，45 个恢复来源水平，23 个超过来源父代；最终最好程序未直接来自这些发展段。三次发展共占用 1368 个 primary slots（包含未退步入口）。 |
| V9.17 | 采用 Discovery、Maturation、Competition、Development、Reopening 阶段；按当时实现的分组比较质量，固定发展块增益决定是否延续。 | 连续改写使同一入口的后续结果可观察，同时减少独立提出的次数。 |
| V9.18 | 回到每次评价后重新选择，比较纯质量与质量加短暂机会项；另行测试全局事实提示。 | `q-atomic` 与 `q+O-atomic` 分开预算分配的比较，全局事实提示作为另一项变化。 |
| V9.19–V9.20 | 曾把执行行为距离用于覆盖和参考检索，随后转向由控制器选择已测程序、生成端选择 Develop/Explore/Crossover 的分工。 | 分配、上下文和算子共同变化；行为距离的测量结果见独立校准。 |
| V9.21–V9.22 | V9.21 每次提出 continue/branch 两份设计说明，每份独立生成两份实现并全部评价。V9.22 改为动态 scaffold mid-rank，分别记录相对当前实现和稳定脚手架的响应，以 action UCB 分配两种动作。 | V9.21 首跑暴露固定 root-MAD 质量尺度饱和、两种比较基准不一致；V9.22 是对此进行的机制修订。 |

</details>

最好程序的形成步骤变少，可以帮助定位投入变化。接着改写是否值得，取决于相同预算下获得的新增收益；退步后的恢复要沿代码检查保留、修正或替换了什么。当前问题见[研究主线](../04-研究认识与构想/研究主线与问题.md)。
