# 尝试记录与经验使用

搜索已经做过哪些改动，结果怎样，能否帮助下一次选择和生成？本方法把失败、重复与修复也记录为尝试，并让选择与生成读取这些结果。实现为 `traceaad/v10_16/`，运行见[实验入口](../../experiments/traceaad_v10_16/README.md)。

## 要解释的现象

TSP 的超时率按每 250 次尝试分段，从 2% 升到 16%；耗时至少 20 秒的父代上，220 次 Refine 都讨论时间，仍有 89 次超时。同一程序多次失败后的下一次改进率也更低。由此提出的解释是，过去的尝试缺少反馈。[假设的形成与更新](../04-研究认识与构想/从专家设计过程看自动算法设计.md)

## 程序与尝试

程序以规范化代码识别，保存评价结果。每次生成记录起点、动作、产生的程序和测量结果。重复尝试指向已有程序，失败程序保留错误，修复从失败程序出发。选择起点只使用有效程序。

形成路径展示通向当前程序的改动；直接尝试展示从它出发做过的试验；前沿进展展示哪些生成推动了全局最好分数。这样可以读取三类经验，而每条经验都对应具体程序与测量。

## 测量计算代价

评价器在候选函数外加上计数包装，并将计数器放在共享内存中。评价进程超时终止后，搜索进程仍能读取计数器，确认此前完成了多少次调用。

- 每次评价记录两项：已完成的函数调用次数，以及函数内部花费的总时间。只计最外层调用，递归和通过目标名调用的辅助函数不会重复计数。
- 计数包装附加在程序文本上，所以像 OBP 这样每个实例都重新执行程序文本的评价器，同样会被计数。
- 对于有效程序，模型看到的是：`Score · Evaluation time · N calls to the function, about F s inside it`。以 TSP 为例，16 个实例共 768 次调用，模型可以据此自己估算每次调用的代价。ACO 任务的 N 是实例数，F 是启发式矩阵的计算时间，评价时间的其余部分属于蚁群。
- 对于超时，报告已完成的调用数和函数内累计耗时；若终止时函数仍在执行，另标明正在执行第几次调用。累计耗时包含这次未完成调用已花费的时间。
- 训练实例的规模仍然不写进上下文。调用次数与单次耗时提供程序的实测代价，供模型估算计算量。

## 起点选择

每个有效程序都是独立的候选，权重为

```
w_i = exp(β · (q_i − q_max)) × (k_i + s·r) / (n_i + s)
```

- `n_i`：从程序 i 出发的算子尝试次数（Refine、Explore、Crossover）。修复不单独计次，而是计入它所修复的那次尝试。
- `k_i`：其中产生了比 i 更好的新程序的次数。写回已有的更好程序不算。
- `r`：本次运行汇总的成功率，即 `(Σk + 1) / (Σn + 2)`；`s = 3` 是先验强度。在 V10.15-5/-6 的数据上，`s = 3` 能复现成功率随失败次数下降的曲线：连续失败约 3 次后降到一半，约 10 次后降到四分之一，与观测到的 1–4 次失败后约减半、15 次以上降到 1% 左右相符。
- **β 用于调整分数差对应的质量权重**：取让目前观测到的分数值在 ESS 意义上分布于 8 个有效档位的温度。它沿用了 V10.13 以来 ESS=8 的分配宽度；按排名统计，这个宽度与观测到的收益梯度吻合（第 1 名每千次约 25–36 次超过全局最好，第 21 名以后为 5–12 次）。之所以在观测到的分数值上拟合 β，而不是在程序上拟合，是因为程序上的 ESS 在最高分并列不少于 8 个时没有有限解：温度会趋于无穷，其余程序的权重全部变成 0。OBP 三路突破 Best Fit 的那一步，父代都比 Best Fit 差，所以这种退化是有害的。

这条规则让持续产生改进的程序获得更多机会；反复尝试没有进展时，经验权重下降。接近时限的程序若频繁生成超时子代，也会降低权重。

## 生成上下文

| 动作 | 展示的经验 |
| --- | --- |
| Refine | 最近最多 8 步形成路径，最近最多 8 次直接尝试 |
| Explore | 最近最多 8 次直接尝试，最近最多 8 次前沿进展 |
| Crossover | 两侧各最多 4 步形成路径，主程序最近最多 8 次直接尝试 |
| Repair | 失败程序、错误行或超时测量 |

每次直接尝试展示动作、Design、分数和耗时，或失败、重复的结果。修复结果附在被修复的尝试后。形成路径将失败与修复合为一步，diff 展示有效起点到修复结果的变化，另写明错误与出错行。这个呈现方式来自一个具体失败：完整展示失败 diff 后，模型曾把已经删除的错误代码抄回。

Refine 与 Crossover 的目标是超过展示的程序和尝试，Explore 的目标是超过全局最好并改变决策方式。简短 Analysis、Design 与完整代码的生成格式沿用[形成路径方法](生成目标与形成路径.md)。输入超限时先裁最旧的历史或进展，再裁最旧的直接尝试。

## 候选解析与最终选择

整段回复解析失败时，再读取最后一个明确 `Code:` 标签后的完整实现。训练前 5 个程序进入独立选择集，某个候选失败时由下一名替补，最多替补 5 次。实现保留 8 个根、16 次初始化上限、0.45/0.30/0.25 算子比例及原训练、选择时限。

## 检验得到的认识

加入记录后，失败率没有随搜索下降。TSP 较低的总超时率主要对应从接近时限的父代出发更少；相近耗时父代上的子代超时率大体接近。经验权重改变了搜索投入，生成侧仍受时间与质量权衡的限制。

逐行耗时剖析重放没有提高改进率。同等开发实验则发现，少量开发能明显提高新设计的可判断水平。当前研究已转向怎样从开发过程判断思想潜力。[当前问题与认识](../04-研究认识与构想/研究主线与问题.md)
