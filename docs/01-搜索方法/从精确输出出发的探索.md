# 从精确输出出发的探索

2026-10-09。实现标识为 V10.22，代码在 `traceaad/v10_22/`，入口为 `experiments/traceaad_v10_22/`。实验条件见[实验准则](../../experiments/PROTOCOL.md)。

## 认识

**模型提出什么，取决于它对当前算法的分析；搜索的结果材料改变不了这个分析。** V10.21 的 TSP 搜索中，Explore 的一半提议用 MST 或 1-tree 下界替换补全模拟，超过起点的不到 5%；把整个搜索中这些提议的失败列给模型，提议的比例不变。后期各步骤 70%–89% 的分析把“计算代价”当作当前算法的限制，这类改动超过起点的比例更低。[现象与检验](../03-现象与检验/2026-10-09-Explore的先验与精确决策.md)

**最强的结构都在近似“这次调用的精确输出”。** TSP 中规划整条剩余路线、走它的第一步（5.70，逐个候选打分为 5.81–5.94）；CVRP 中构造完整解、把解中的边作为先验。改进算法的专家先问精确决策需要什么，再问用什么计算近似它；V10.21 的 Explore 问的是“当前算法捕捉不到什么”，得到的是同一规则里某一项的下一个常见估计。

## 规则

V10.22 沿用 V10.21 的搜索、份额（Refine／Explore／Crossover 0.45／0.30／0.25）、开发、选择、执行与提示原则（只交代问题、接口与成绩，不提时间）。改动只在提示：

- **Explore 的目标**以当前算法为准，与 Refine、Crossover 一致：
  > Write a version of the current algorithm that scores better than it by changing what it computes to produce its output, not by tuning it. Every version and attempt shown above has already been evaluated.
- **Explore 的分析**从精确输出出发：
  > which output would lead to the best final result for the inputs the function receives, and what computing that output exactly would require; what the current algorithm computes in its place; and which different computation would come closer to that output
- **Explore 的材料**：任务、当前算法、从它出发的尝试。去掉“最好成绩怎样提高”的列表：它只列成功并带分数，去掉后重复提议从 57% 降到 46%；目标也不再以搜索最好为准。
- **Refine 的分析**问限制成绩的是什么：“what limits the current algorithm's score, and what change keeps its core idea and makes it score better”。原句“what limits the current algorithm”多被读成计算代价。开发步骤使用同一 Refine 提示。
- **后续起点程序**要求与已有程序不同的核心思想、尽量得分高，不再要求“超过上面所有程序”：后者把已展示的最好程序变成要追的对象。

Crossover、Repair、第一个起点程序的提示与输出格式不变。

## 检验

六个任务各 3 路，种子 0–2，预算 1,000。除成绩外检查过程：每路出现了几种决策结构，新结构是否得到开发；Explore 分析中把计算代价当作限制的比例；MST 类提议的重复程度。固定状态生成中，新分析在同样 3 个状态上把 MST 提议从 11/15 降到 6/18，但模型仍多以“计算太贵”为由换成其他便宜估计，没有出现整条路线规划。
