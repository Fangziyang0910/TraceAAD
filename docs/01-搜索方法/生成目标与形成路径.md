# 生成目标与形成路径

这里记录生成材料、目标句与回复格式的实际设置。相关对照研究模型怎样利用形成历史，以及写代码前文字怎样影响本次修改；这些认识被用于本组搜索配置。实现为 `traceaad/v10_15/`，运行参数见[实验入口](../../experiments/traceaad_v10_15/README.md)。

## 为什么研究这些信息

强结果形成过程显示，找到有效计算结构之后，还要保留、修正和组合它。固定父代的历史配对观察到严重退步减少；格式配对发现，写代码前针对当前任务作出简短决策，对 Refine 有帮助。[形成路径](../03-现象与检验/2026-09-09-强结果形成路径.md)、[格式实验](../03-现象与检验/2026-10-01-写代码前的决策与Design格式.md)

另一个实际问题是目标句怎样定义改进。若只要求超过当前程序，当前程序退步后，模型常原样返回更早的程序。固定父代的提示配对中，撤回次数从 19/45 降到 2/45。目标因此改为超过展示过的全部已评价程序，让继续开发指向新的收益。

## 模型看到什么、要做什么

| 动作 | 材料 | 目标 |
| --- | --- | --- |
| Refine | 当前代码、最近最多 8 步形成路径；每步完整 diff、分数与耗时 | 沿当前开发线生成优于展示程序的算法 |
| Explore | 当前代码、全局最好分数；参考卡默认关闭 | 改变决策方式，超过全局最好 |
| Crossover | 当前与参考程序，两侧各最多 4 步形成路径 | 组合有效计算，超过两侧展示的程序 |
| Repair | 失败代码与具体错误 | 恢复有效程序 |

Refine、Explore、Crossover、Repair 先用几句话分析本次决定，再给简短 Design 和完整代码。初始化直接给 Design 和代码。分数与耗时放在对应程序旁，接口说明给出允许的计算范围。总输入超限时删去最旧的完整历史步骤，保留最近改动。

## 搜索规则

所有生成共用候选预算，包括初始化、重复、失败与修复。程序以规范化代码识别。父代按训练质量 Boltzmann 抽样，ESS 目标为 `min(N, 8)`；最高分并列数量达到目标时，在并列程序中均匀抽样。

Crossover 的参考先要求质量不低于中位数，再在代码相似度较低的一半中均匀抽取。Refine、Explore、Crossover 的概率为 0.45、0.30、0.25。每次生成后重新选择起点。失败最多追加一次付费修复。

搜索结束后，训练分最高的 5 个程序进入独立选择集；选定的程序再做 held-out。训练、选择与测试的数据各自承担搜索、选优与泛化评价。

## 参数

| 参数 | 值 |
|---|---|
| 预算 | 1000 次候选尝试（含初始化、修复、失败、重复） |
| 根 | 8 个有效且互不相同；前 4 个独立生成，后 4 个参考已有根；初始化尝试上限 16 |
| 选父 | 程序上的质量 Boltzmann，ESS 目标 `min(N, 8)`；最高分并列不少于目标时在并列程序中均匀抽样；三个动作共用 |
| 动作 | Refine 0.45 / Explore 0.30 / Crossover 0.25 |
| Refine 历史 | 最近 ≤8 条边；每一步给完整 diff；只按总输入上限从最旧步骤开始裁剪 |
| Explore 参考 | 默认 0 个（`explore_cards`，上限 4）；启用时最多 4 个档案 Idea 与分数；显示 Idea 去重，再按代码差异贪心选择；加全局最好分数，不给形成轨迹 |
| Crossover | 主程序和参考程序各最近 ≤4 条边的完整 diff；参考选择要求质量 ≥ 中位数、代码相似度 ≤ 候选中位数，均匀抽取 |
| 输出 | 修改与修复：简短 Analysis → Design（≤60 词）→ Code；初始化：Design → Code；Design 描述实际算法 |
| 判定容差 | `1e-9 · max(1, |父代分数|)` |
| 修复 | 每个失败候选最多 1 次，计入预算 |
| 模型 | Qwen3.8-27B AWQ；thinking 关闭；官方非 thinking 采样 temperature 0.7、top_p 0.8、top_k 20、min_p 0、presence_penalty 1.5、repetition_penalty 1.0，全部显式发送 |
| 评价时限 | 墙钟超时。训练：TSP/VRPTW/OBP 30 s、OP 60 s、CVRP 120 s；选择：构造类为训练的 2 倍，ACO 按实例数放大；held-out：TSP 3,000 s、VRPTW/OBP 1,000 s、ACO 3,600 s；BLAS/OpenMP 单线程 |
| Token | 输入 ≤24,320，输出 ≤8,192 |
| 最终选择 | 训练分最高的 5 个程序（同分取较早者），在独立选择集上选最优 |
| 随机数 | 选父、动作、参考三路独立，都由运行种子（`repeat − 1`）派生 |

## 已有结果与后续问题

目标调整与服务器运行配置组合后，TSP、VRPTW 的改善延续到独立测试和更大规模；CVRP、装箱整体接近，OP 有一路选择失败。[独立测试与前一配置对照](../02-实验结果/2026-10-03-分析格式调整-held-out结果.md)

过程记录还显示，减少撤回之后，TSP 生成了剩余路径补全与局部搜索结构，VRPTW 沿 Refine 与 Crossover 完善前瞻。接下来从这些实际代码变化理解收益来源。[生成目标与计算限制](../03-现象与检验/2026-10-01-生成目标与计算限制.md)

后续尝试开始保存失败、重复与修复，让模型读取从当前程序出发做过的试验。相关规则与检验见[尝试记录与经验使用](尝试记录与经验使用.md)。完整提示以[prompts.py](../../traceaad/v10_15/prompts.py)为准，运行与选择协议见[运行说明](../../experiments/traceaad_v10_15/README.md)。
