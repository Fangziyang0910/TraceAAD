## 1. 改进起点和范围

从 V10.17 的完整机制出发，保留选择反馈、历史分工、性能目标和完整代码交付，精炼形成历史说明与修改类算子的提示。此次不设计新的预算分配器，也不再使用倒数排名。目标不是继续修补废弃版，而是在可信基线上检验失败／修复信息修正及针对性的提示调整。

另行进行当前协议适配：六任务、16 个训练实例、每实例候选 CPU 2 秒／墙钟 20 秒、训练 top-5 重测冻结、独立测试 50 例。旧版独立选择集不再使用。任务事实与分数方向按当前评价器说明，提示不叙述时间预算。这些是实验条件变化，不作为方法贡献。

## 2. 保留 V10.17 的搜索机制

### 父代选择

分数越低越好。有效程序 i 的权重为：

\[
w_i=\exp[-\beta(f_i-f_{\min})]\frac{k_i+3r}{n_i+3},\qquad
P(i)=\frac{w_i}{\sum_jw_j},\qquad
r=\frac{\sum_jk_j+1}{\sum_jn_j+2}.
\]

n_i 是从程序 i 出发的普通算子及续写尝试数，k_i 是其中产生更好新程序的次数；修复结果归回原提案，修复本身不重复增加 n_i。重复与交付失败仍计作尝试。改善判断沿用相对浮点容差。

质量温度 beta 在当前不同分数值上标定，使质量权重的 ESS 为 `min(不同分数数目, 8)`；当不同分数不超过 8 个时 beta=0。这里的 8 与经验先验强度 3 均沿用旧版，不重新调参。

这个因子用于根据已发生的尝试调整投入，不被解释为长期潜力预测器。参考程序继续从质量较好的一半中筛选，再从与父代代码较不相似的一半中抽取。

### 算子和续写

- 普通算子份额：Refine 45%、Explore 30%、Crossover 25%。
- 新有效 Explore 程序按固定独立抽签，以 1/8 概率获得至多 3 次 Refine，每步从该次探索目前最好的程序出发。抽签复用 V10.17 的实现。
- 所有新有效程序，包括退步程序，照常进入档案。一次失败最多修复一次。
- 初始化 8 个根，初始化尝试上限 16。每路总预算 1000；初始化、重复、失败、修复、续写均计费，不增发预算。

## 3. 历史材料保持原来的分工

| 操作 | 材料 | 目标 |
| --- | --- | --- |
| Refine | 当前完整代码、最近至多 8 个形成步骤、最近至多 8 次直接尝试及总尝试／改善数 | 保留核心思想，超过当前程序 |
| Explore | 当前完整代码、直接尝试、最近至多 8 次全局最好刷新及当前最好值 | 改变决策计算，超过搜索最好 |
| Crossover | 当前与参考完整代码、各至多 4 个形成步骤、当前程序的直接尝试 | 适配参考中的有用计算，保留当前核心并超过当前程序 |
| Repair | 失败完整源码、真实错误 | 修复并保留原本打算实现的算法 |

Explore 与旧版一样不读形成链，但保留全局进展。直接尝试与形成路径的职责不混合。根初始化继续沿用“不同核心思想并优于展示的根”的原目标，不在这次同时更换。

Refine、Explore 目标直接复用 V10.17；Crossover 保留当前核心与超父目标，改为适配可能有用的计算：

```text
Refine:
Develop the current algorithm further: keep its core idea and write a version
that scores better than it. Every version and attempt shown above has already been evaluated.

Explore:
Write an algorithm that scores better than the best found so far by changing
how the current algorithm makes its decisions, not by tuning it.

Crossover:
Adapt a computation from the reference algorithm that could improve the current
algorithm. Keep the current algorithm's core idea and write a version that scores better than it.
Every version and attempt shown above has already been evaluated.
```

交付统一为 Analysis（初始化不要求）、至多 60 词的 Design、完整自包含 Python Code。移除优先 edit、SEARCH/REPLACE 与编辑基底规则。源码规范化、去重、错误处理复用共享实现；不从模板补入遗漏依赖，这是现有 V10.17 整理版的执行规则。

## 4. 形成历史：显示修复前后的实际变化

有效父代 A → 失败提案 B → 修复版 C，在历史中仍占一个形成步骤，但显示：

1. A 与 C 的评价结果，B 的错误，以及 B、C 各自的 Design；
2. A → B 的真实 diff；
3. B → C 的真实 diff。

不再只显示 A → C 的净 diff。一个步骤内的两个差异一起保留或裁剪，不能只留下修复版、丢掉失败提案。此修改同时作用于 Refine 的形成历史和 Crossover 的两边历史；正常形成步骤的实际 diff 与评价事实仍沿用基础实现；历史引言及修改类算子的措辞按第7节调整。初始化根修复仍沿用旧版描述，没有另加历史模块。

上下文限额、裁剪顺序和回退沿用旧机制。Refine 的必要最新步骤放不下时，使用已有的上下文处理／Explore 回退；不额外叠加废弃版的裁剪规则。`history_edge_ids` 继续记录步骤的有效终点，终点的真实 parent 指向失败程序，可从档案还原两次变化。

该调整修正信息缺失，尚不声称能提高算法质量。实际需要检验的是修复删掉的计算能否被正确理解，以及后续是否产生更有用的修改。

## 7. 已实施的提示精炼

本轮仅调整形成历史的解释和三个修改类算子的指令，不改变搜索公式、参数、材料数量、裁剪顺序或评价协议。标识从 `v1025-v1017-base-1` 更新为 `v1025-v1017-base-2`；前一标识的断点不能混用。共享构造器仅将原有历史引言改为可由版本覆写的类属性，其他版本继续使用原文。

### 历史说明

```text
The steps that produced the current algorithm, oldest first.
Each step gives its outcome, Design and code changes.
Design describes the proposed algorithm; scores report the results of whole programs.
When a proposal failed and was repaired, the step shows the failure, both Designs,
and separate diffs for the proposal and its repair.
```

这段文字只在有形成步骤时出现，Crossover 的参考历史使用 reference algorithm。没有形成步骤的根仍明确说明没有记录的改动，不要求模型虚构历史。实际分数和 diff 不变；整份程序的成绩不被表述为某个部件已经验证的贡献。

### Analysis 完整内容

输出格式仍为 `Analysis: <a few sentences: ... . It will not be shown again>`，后接原来的短 Design 与完整代码。下面是实际插入的内容：

```text
Refine:
what limits the current algorithm, using its code and any available code changes
and evaluated outcomes, and what change could improve it while retaining its core idea

Crossover:
which computation in the reference could help the current algorithm, considering
the code and any available changes and outcomes, and how to adapt it to work
with the current computation while retaining the current algorithm's core idea

Repair:
what caused the failure, and how to fix it while retaining the intended decision computation
```

Refine 仍要求超过当前程序。分析从代码与已有结果出发，而非凭空列举通用缺点；`any available` 兼容没有形成历史的初始化根。保留核心思想不被改写成最小代码改动。

Crossover 的目标见第3节。目标与分析同时去掉 `what the reference algorithm does well` 的预设，要求识别可能有用的实际计算并适配到当前程序。参考可能弱于当前算法；整体分数也没有验证具体部件的贡献。该改动不新增退出选项或要求超过参考程序。

Repair 的原目标已经要求保留打算实现的算法，本轮使 Analysis 与它一致。超时、数值错误和其他失败仍传入原始错误，不新增修复预算，也不要求保留不可行的实现细节。

### 保留与检验边界

Explore 的目标、Analysis、全局进展保持原文；初始化、Design格式、任务文本和接口说明也保持原文。前次讨论的 `not just by tuning its parameters`、Design 改写和移除 TSP 的 `novel` 均未采用：先限制改动范围，不把所有可能更准确的措辞一次投入运行。历史数量与裁剪参数不动。

已有撤回目标与格式对照支持提示会改变生成行为，但不证明这组新措辞提高算法质量。[格式证据](../03-现象与检验/2026-10-01-写代码前的决策与Design格式.md)、[目标取舍](提出后的短程改写.md)。后续应检查是否依据实际代码及结果修正判断、Crossover 是否适配可识别的计算、Repair 是否保住原决策计算，再看算法收益；更长分析或更低重复率不能替代这项判断。本轮没有调用真实模型或启动正式搜索。
