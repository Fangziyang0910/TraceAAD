# V12.1：检查代码是否实现设计，并补写缺失的计算

V12.1 在程序搜索中保存模型提出的设计、实际代码和评价结果。Explore 提出新计算后，搜索可以参考同一计算的已有实现，再检查新代码是否实现设计、是否保留起点中未被替换的计算。检查指出缺失且新程序没有优于起点时，模型最多补写两步。

全部实现位于 `traceaad/v12_1/`。个体与文件结构见[实现说明](../../traceaad/v12_1/README.md)，运行命令见[实验入口](../../experiments/traceaad_v12_1/README.md)。

## 程序个体与生成预算

模型输出可以解析为所需字段时，创建一个 `Program` 对象。此后校验、评价、修复、代码检查和历史展示都围绕该个体组织。

| 内容 | 个体字段 |
| --- | --- |
| 模型分析、算法设计说明、源码 | `analysis`、`idea`、`code` |
| 个体编号、本次生成在预算中的位置 | `id`、`generation` |
| 父个体、参考个体、被修复个体 | `parent_id`、`reference_id`、`repair_of` |
| 生成操作、原始调用 | `action`、`request_id`、`call_ids` |
| 评价状态、成绩、错误与耗时 | `status`、`fitness`、`failure`、`eval_seconds`、`function_seconds` |
| 设计匹配、探索归属、代码检查 | `link`、`exploration`、`verdict` |

`idea` 保存回复中的 `design`。同一源码可以属于不同个体，每个个体独立评价。源码哈希只用于保存、读取和完整性检查。

```text
程序生成请求 → 解析输出
  ├ 格式不符、截断或缺少代码 → 保存调用和错误日志，不创建个体
  └ 解析成功 → 创建 Program → 校验源码 → 运行评价 → 更新个体状态
                               └ 失败时可生成一个 Repair 个体
```

语法错误、接口不符、运行错误、返回值不合法和超时都是个体的失败状态。解析失败也消耗一次生成预算，但不占个体编号。提出设计、设计匹配和代码检查不单独创建程序个体，其请求与 token 消耗另行记录。

## 初始化与普通搜索

初始化逐个生成程序。默认得到 5 个有效起点，或达到 16 次初始化生成后结束。第一个起点独立生成，之后展示全部已有有效起点的设计、代码和成绩，要求提出更好的核心思想。相同代码也算新的起点个体。初始化和修复都计入生成预算；初始化按自身次数上限执行，不因整场预算小于起点数而提前结束。没有有效起点时，结束状态为 `no_valid_root`。

普通搜索先选择父个体，再按固定份额选择操作：

| 操作 | 默认份额 | 目标与材料 |
| --- | ---: | --- |
| Refine | 45% | 保留当前算法的核心思想并改善成绩。展示父个体、最近至多 8 步形成路径，以及从它出发的至多 8 个算子子代及结果 |
| Explore | 30% | 改变当前算法的决策计算，争取超过搜索最好成绩。展示父个体、从它出发的算子子代，以及最近至多 8 次最好成绩刷新 |
| Crossover | 25% | 将参考算法的有用计算引入父个体。展示双方代码与成绩、双方各至多 4 步形成路径，以及从父个体出发的算子子代 |

父代来自全部有效个体。权重为：

\[
w_i=\exp[-\beta(f_i-f_{\min})]\frac{k_i+3r}{n_i+3},
\qquad r=\frac{\sum_i k_i+1}{\sum_i n_i+2}.
\]

其中，\(f_i\) 是训练成绩，越小越好。\(n_i\) 是从该个体产生的 Refine、Explore、Crossover 子代数，\(k_i\) 是其中最终改善父代成绩的数量。若子代被修复，以修复个体的结果判断这次改动。解析失败没有产生子代，不进入这项个体统计。Complete 不计入该统计。\(\beta\) 根据不同训练分数值校准，使质量权重的有效样本数接近 8；分数值不超过 8 个时取 0。

Crossover 先排除父个体，再取成绩不差于种群中位数的参考候选。按代码 token 集合的 Jaccard 相似度取较低的一半，从中随机选一个。没有候选时改为 Refine。相似度在这里用于选择参考，不用于识别或拒绝重复代码。

## Explore：提出、匹配、实现

一次 Explore 产生一个程序个体，生成过程可以包含以下请求。

1. **提出设计。** 模型返回 `analysis` 与 `design`，不写代码。分析说明当前算法遗漏了什么，新计算要捕捉什么。设计为空、格式不符或回复截断时，结束这次生成并记录解析失败。
2. **匹配已有实现。** 从其他有效个体中检索设计说明，排除已明确判为未实现设计的个体。相同设计文本只列分数最好的一个。按嵌入余弦相似度取至多 20 个，请模型判断哪些与新设计基于同一主要计算。匹配结果中取训练成绩最好的个体，同分取编号小的。没有候选或没有匹配时，直接实现提案。
3. **实现设计。** 保留提出时的材料，加入完整提案；若有匹配，再展示该个体的设计、完整代码与成绩。模型返回代码。新个体的设计与分析取自提出阶段，代码取自实现阶段。

设计匹配比较的是设计文本及其主要计算，不合并个体、不复用旧成绩。提示只说明参考程序已被评价且与提案计算相同，具体如何使用由模型决定。默认展示匹配程序；`display_probability` 可控制其展示概率。

## 检查代码与补写

Explore 的有效版本接受两项独立检查。检查只展示任务、设计和相关代码，不展示程序成绩。

| 检查 | 输入 | 回复字段与含义 |
| --- | --- | --- |
| 是否实现设计 | Design、当前版本代码 | `computes` 描述实际计算；`missing` 指出没有实现的主要计算 |
| 是否保留原有计算 | Design、起点代码、当前版本代码 | `computations` 逐项对照起点计算；`dropped` 指出未被设计替换却被删除的计算 |

第一项明确判为未实现设计时，不执行第二项。常数变化、实现细节变化，以及只为被替换计算服务的代码，不作为原有计算丢失。

判断字段为空或表示“没有缺失”时通过；指出缺失时不通过。回复截断、JSON 无效或缺少判断字段时，记为未判断。未判断本身不触发补写。这里的检查是模型对代码的判断，不是程序分差的因果证明。

| 最近有效版本的情况 | 后续操作 |
| --- | --- |
| 没有明确指出缺失，或成绩已优于起点 | 结束本次探索 |
| 没有实现设计，且未优于起点 | 在最近有效版本上补写设计 |
| 丢失原有计算，且未优于起点 | 从起点重新写入设计，同时展示已有版本和检查意见 |
| 达到补写次数上限、未抽中补写，或整场生成预算用完 | 结束本次探索 |

默认最多补写两步。每步产生新的 `Program`，失败时可修复一次。检查始终对照本次 Explore 的原始设计和起点。补写不会因为生成了相同代码而提前停止。

检查结果写入个体的 `verdict`。未实现设计的有效个体仍可按成绩作为父代和 Crossover 参考，但不作为该设计的已有实现参与后续匹配。形成路径与后续提示会注明缺失内容及补写结果。

当前保留三个配置：

| 配置 | 补写规则 |
| --- | --- |
| `Config` | 需要补写的探索都按检查意见补写，最多两步 |
| `DrawConfig` | 需要补写的探索以 0.5 概率获得补写；抽签按探索编号与搜索种子固定 |
| `ResampleConfig` | 使用相同触发条件，但原样重发首次实现请求，从起点独立实现，不展示检查意见 |

## 修复与输出

已经创建的失败个体可以得到一次 Repair。修复提示包含设计、源码与具体错误；超时反馈给出实测耗时与对应时限。修复个体沿用被修程序的设计，保存自己的分析和代码，并通过 `repair_of` 关联来源。修复仍失败时，不继续修复同一次生成。解析失败不触发 Repair。

所有请求使用 JSON 对象。生成、匹配、补写、修复和检查共用 `output_tokens`，默认 16384。匹配和代码检查使用温度 0；程序生成使用运行配置的采样设置。不设置本地输入 token 阈值，也不按输入长度删除已选材料或切换操作。

| 请求 | 回复字段 |
| --- | --- |
| 初始化、Refine、Crossover | `analysis`、`design`、`code` |
| Explore 提案 | `analysis`、`design` |
| Explore 实现 | `code` |
| 设计匹配 | `analysis`、`same` |
| Repair、按检查补写 | `analysis`、`code` |
| 设计实现检查 | `computes`、`missing` |
| 原有计算检查 | `computations`、`dropped` |

Explore 的分析随提案进入实现和补写提示。其他程序分析保存在各自个体中，不作为后续历史材料展示。完整请求和原始回复保存在调用日志中。

## 最终选择与恢复

默认按训练成绩取前 5 个有效个体，在训练集重新评价，再确定成绩最好的有效程序。同分取训练排名靠前者。相同源码的个体也分别参与重评。最终程序确定后，独立测试只评价它，不用于重新选择。共同条件见[实验规范](../08-实验规范与共识/README.md)。

事件直接保存个体元数据。恢复时重建 `Program` 对象、搜索进度与随机状态。已保存的检查结果直接读取；调度器中断后，继续评价已经创建的待评价个体，不重新生成。旧双结构档案不由当前实现续跑。文件格式见[结果格式](../../experiments/infra/SEARCH_FORMAT.md)。

早期检查与补写的实测观察见[2026-10-14 诊断](../03-现象与检验/2026-10-14-设计实现检查与补写.md)。当前规则是否改善固定预算的完整搜索，仍需按实际运行条件比较结果与模型成本。
