# 按实例陈述计算预算

2026-10-08。实现标识为 V10.21，代码在 `traceaad/v10_21/`，入口为 `experiments/traceaad_v10_21/`。搜索机制与 [V10.20](当前规则引导的搜索.md) 相同：份额 Refine/Explore/Crossover/Deepen 为 0.40/0.25/0.20/0.15，Explore 与 Deepen 的提出开启探索，1/8 得到 3 步开发。改动只在提示，共两处。实验条件见[实验准则](../../experiments/PROTOCOL.md)。

## 1. 时间用程序消耗它的单位来陈述

**问题。** V10.20 只给出整套训练评价的限时，并在测量行写“about 12.3 s of the 60 s limit”。但待进化函数每个实例可能只调用一次（ACO），也可能调用几千次（图着色）。模型据此把整套限时当成一次调用的预算：

| 现象 | 例子 |
| --- | --- |
| 读时钟的程序把整套限时设为单次调用的上限 | CVRP 程序写 `time_limit = 115.0`，函数对 10 个实例各调用一次，第一个实例就超时；图着色程序写 `time_limit = 45.0`，而函数每次评价被调用 7,113 次 |
| 超时集中在要求多用时间的步骤 | V10.20 中 Deepen 的超时率 8.7%，Explore 4.0%，Refine 1.6% |
| 不读时钟的程序同样缺少换算依据 | 模型只看到整套耗时，要自己除以实例数与调用次数 |

时间预算属于一个实例：限时 = 实例数 × 每实例预算。算法设计者想的是“解一个实例能做多少计算”和“每次决策能花多少时间”，提示应直接给出这两个量。

**规则。**

- 评价段落写出每实例预算：“Each instance has a time budget of 10 seconds, which includes the fixed solver. Instances are evaluated one after another, so the whole evaluation must finish within 160 seconds.” 测试说明为同一每实例预算下的 50 个实例。
- 每个程序的测量行改为每实例：`Score: -11.75 · Time per instance: about 0.77 s of the 10 s budget · 445 calls to the function per instance, about 1 ms each`。形成路径、尝试记录和最佳进展中的耗时也写成每实例。
- 超时说明写出“the 160 s limit for 16 instances (10 s per instance)”；修复超时程序时，给出它所出发的程序的同一组测量。
- Deepen 的目标与 Analysis 改为每实例：“spends more of the per-instance time budget”“how much computation per instance that search can use within the time budget”。

试跑中，Deepen 的分析直接写出“With ~0.65 s used out of 10 s per instance”，读时钟的程序把上限设为每实例 9.5 秒，并按实例计时。

## 2. 去掉禁止注释的输出规则

V10.20 要求“Write no comments or docstrings in the code”。程序按规范化源码保存，规范化本身去掉注释与文档字符串，所以这条规则不改变任何保存或展示的内容，只拿走了模型写代码时的笔记。V10.20 的运行错误主要是未定义变量、索引越界和形状不匹配这类一次写成、未经推敲的错误（Explore 8.1%、Deepen 8.6%）。V10.21 只要求“Write nothing after the code block.”。

## 3. 检验

六个任务各 3 路，种子 0–2，预算 1,000，本机评价，模型为 server3 两个端点各 9 路。

| 检查 | 量 |
| --- | --- |
| 超时是否下降 | 各步骤的超时率，尤其 Deepen 与 Explore |
| 运行错误是否下降 | 各步骤的运行错误率 |
| 计算是否被用起来 | 最好程序与前五名的每实例耗时；Deepen 子代相对父代的耗时倍数 |
| 最终成绩 | 每任务 3 路同规模测试成绩的均值 |

## 4. 运行中观察

10月8日，各路完成约 200–480 次尝试时，程序明显用上了预算：读时钟的程序多把上限设为每实例 9.5 或 9.8 秒。超时率随之升到 5.2%（Deepen 13.0%，Refine 4.2%）。这些上限没有扣除固定框架自身的耗时（CVRP 的蚁群约 1 秒，FSSP 外层约 0.7 秒），也没有留出负载波动的余量。测量行给出的是每实例总耗时，模型看不到其中框架占多少；下一步可在评价段落写出框架每实例的实测耗时。
