# 按改动种类定义的步骤

2026-10-09。实现标识为 V10.23，代码在 `traceaad/v10_23/`，入口为 `experiments/traceaad_v10_23/`。实验条件见[实验准则](../../experiments/PROTOCOL.md)。

## 认识

**一步改了什么，首先取决于上下文里示范了什么改动；其次取决于分析要回答的问题；目标句的作用最小。** 三组证据指向同一点：

- 在 Refine 的材料上换成 Deepen 的目标，模型仍然只做 Refine 式的小改；同一目标只配任务和当前代码，搜索计算增加到 12–17 倍。[重放](../03-现象与检验/2026-10-06-V10.20重放与ACO评价噪声.md)
- V10.22 的 TSP 中，Crossover 的两份程序只差一个系数，模型就把系数改成参考的值；Refine 读完 8 步调权重的形成路径，分析写“第 7 步的衰减有效”，然后再调一次权重。
- 只改分析的问句，加入计算的比例就会大幅变化（V10.21 的 Refine、Explore 从便宜程序出发为 20%–29%，V10.22 为 2%）。

**搜索因此会重复自己已经做过的改动。** 做出的改动进入形成路径和尝试记录，又成为下一步的示范。早期只调权重的搜索，后面也一直调权重；早期出现了补全模拟的搜索，后面的 Refine 也在模拟上继续开发。这能解释为什么各版本之间的差别落在重复差异之内，而同一版本各路差别很大：哪一路在前期出现结构改动，很大程度上决定了它的上限。V10.21 的 Explore 能看到“刷新最好成绩的改动”列表，TSP 中这些多是增加计算的改动，所以它还有一个结构改动的来源；V10.22 去掉了这个列表，又把分析改成从“精确输出”出发（模型随即认为精确计算不可行，转向便宜的估计），这个来源就没有了。

**所以每一步要先定义改动的种类，再给与之相配的材料。** 前沿方法正是这样定义算子的：LACE 的局部精炼只改一个决策部件，重设计替换骨架；EoH 把形式不同、修改形式、改参数、简化分开；Shinka 区分定向 diff 与结构重写。它们的材料主要是代码和分数。[算子提示对照](../05-相关工作/LLM-AAD中的算子设计与上下文组织调研.md)

**对固定框架里的一个函数，结构改动是把“用公式估计”换成“把后果算出来”。** 六个任务的函数都只给框架一个输入：TSP 的下一个节点、ACO 的边先验、FSSP 的扰动矩阵与作业、图着色的改色评分、JSSP 的工序排序。模型对这类函数的默认理解是“给每个选项打分的公式”。让它“考虑当前算法漏掉的影响”，它会再加一项特征：在 V10.22 前期状态上，这样问的首版几乎都是“没考虑回到起点的距离”“没考虑机器负载”，然后加一项（[行为检查](../03-现象与检验/2026-10-09-V10.23行为检查.md)）。把区别直接说出来——公式只能估计一个选项会带来什么，计算还可以通过构造、模拟或改进其后的部分解把它算出来——同样的状态上，首版就变成了补全模拟（TSP 6.91→6.21、6.95→6.26）、JSSP 按 Giffler–Thompson 模拟剩余调度、FSSP 实际计算移动后的 makespan、CVRP 先构造满足容量的路线再写先验。TSP 的最好程序（补全剩余路线再用 2-opt 改进）和 CVRP 的强程序（构造完整解，再把解中的边写入先验）正是这类计算。这句话定义的是“不同种类的计算”，不指定任何方法。

**模型对一类计算有代价反射，但它不会封住搜索。** 对“每个候选都做完整补全”的程序，Refine 和 Develop 常以“O(n³)，代价太高”为由把它换回前瞻或公式，提示里没有任何时间信息时也是这样。写出实例规模、说明“只按解计分”都没有改变这一点。但反射只针对这种形态：已经限定候选再做局部改进的程序，Refine 会继续加计算。Explore 超时后的 Repair 先写出完整计算、再缩到能运行的规模，是 FSSP、图着色、JSSP 上最常超过起点的路径。[第二轮检查](../03-现象与检验/2026-10-09-V10.23行为检查.md#第二轮任务给出规模并说明只按解计分)

## 规则

搜索、份额（Refine／Explore／Crossover 0.45／0.30／0.25）、选择、开发概率与步数、执行条件都与 V10.22 相同。提示仍只交代问题、接口与成绩，不提时间，不点名任何方法。

| 步骤 | 改动种类 | 材料 | 分析回答什么 |
| --- | --- | --- | --- |
| Refine | 只改计算中的一个部分，其余不动 | 任务、当前代码与分数、形成路径（至多 8 步）、从它出发的尝试 | 改哪个部分，为什么能提高成绩 |
| Explore | 换一种计算来决定输出，而不是改公式的项或参数；可以把选项带来的后果实际算出来；保留新计算仍要用的部分 | 任务、当前代码与分数、从它出发的尝试；没有形成路径 | 当前算法在决定输出前实际算出了什么、只估计了什么，新版本改为算出什么 |
| Crossover | 把两个算法的计算组合成一个，保留各自有助成绩的部分 | 任务、两份代码与分数、从当前程序出发的尝试；没有双方的形成路径 | 各自计算了什么对方没有的，新算法保留哪些 |
| Develop | 保留 Explore 引入的新计算，改进它的实现与使用 | 形成路径只从 Explore 的起点开始，加上从当前版本出发的尝试 | 新计算哪里还不好，这一版怎样改进 |

目标句：

> **Refine**：Improve one part of the current algorithm's computation and keep the rest unchanged, so that it scores better than the current algorithm.
>
> **Explore**：Write a version of the current algorithm that decides its output through a different kind of computation, not by changing terms or parameters. A formula over features of the options only estimates what each option leads to; a computation can also work out what an option leads to, by constructing, simulating or improving the part of the solution that follows from it. Keep the parts of the current algorithm that the new computation still uses. The new version should score better than the current algorithm.
>
> **Crossover**：Write one algorithm that combines computations of the current algorithm and the reference algorithm, keeping from each what helps the score, so that it scores better than the current algorithm.
>
> **Develop**：The steps above, from the algorithm the exploration started from, changed how the algorithm arrives at its output. Develop this new computation: keep it, and improve how it is implemented and used, so that the algorithm scores better than it does now.

每个目标句后都附 “Every version and attempt shown above has already been evaluated.”。Design 改为说明“所实现的算法为得到输出计算了什么”，不再要求陈述“核心思想”：后续步骤读到的历史因此描述计算，而不是一个没有操作定义的“核心思想”。起点程序与 Repair 的目标不变。超时不再只写 “timed out”，而是写出运行到了哪里，例如 “Timed out: on one instance, the evaluation stopped after the function had returned from 14 of its 48 calls.”；总调用数取自本次搜索中有效程序在每个实例上的调用数，框架只调用一次的任务写 “before the function returned from its single call”。这句出现在 Repair 的错误、尝试记录和形成路径中，不含任何秒数。

与 V10.22 相比，改了这些地方：

- Refine 从“保留核心思想、写出更好的版本”改为“只改一个部分”。分析不再问“什么限制了成绩”，那个问句让模型把计算代价当作限制。
- Explore 不再从“精确输出”出发（模型随即认为精确计算不可行，换成便宜估计），改为区分“用公式估计后果”和“把后果算出来”。
- Crossover 去掉双方的形成路径（原占提示约 70%），不再预设参考程序有当前程序缺少的长处（V10.21 中 85% 的参考总分比当前程序差）。
- 开发步骤原来调用普通 Refine，读到 Explore 之前的全部调参历史，常常退回旧程序；现在只读从 Explore 起点开始的路径。

## 检验

在 server3 上运行六个任务各 3 路，种子 0–2，预算 1,000。除成绩外检查过程：各步骤子代中加入计算的比例；Crossover 是否仍在两份程序之间平均系数；Explore 的首版是什么计算，开发是否保留了它；前期是否出现补全、构造或改进类结构。启动前在 V10.22 前期状态上读了各步骤实际写出的程序，第一批运行到 55–100 次尝试时又检查了一轮，见[行为检查](../03-现象与检验/2026-10-09-V10.23行为检查.md)。当前批次为 `20261009_server3_v1023c`。
