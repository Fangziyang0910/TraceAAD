# EvoTrace：研究问题与思路

研究目标是在有限预算下找到并持续精炼更好的算法，让设计过程形成的经验帮助后续算法发现。

**个体适应度评价与演化过程学习是两个不同层次。** Fitness反映算法当前已经实现的性能；演化轨迹还提供理解算法如何改进、哪些方向值得继续、哪些策略可以迁移的信息。算法演化既产生候选算法，也产生关于如何继续搜索的知识。

当前科学问题是：**如何将算法演化过程转化为后续发现的学习信号，使轨迹引导的算法改进、跨代经验学习与节点选择相互促进？**

## 三个机制

EvoTrace围绕同一演化过程组织三个相互关联的机制：

1. **轨迹节点价值评估与预算分配。** 先按 Base 的质量偏好分配机会，再用近期、起点质量相近的真实轨迹结果修正分配。反馈直接记当时实际产生的冠军改善 $Y_i=\max(f_i^*-f(c_i),0)$，不再把父代改善平移到另一质量水平。候选动作只借同一算子、最近 $\min(B,256)$ 次评价内、质量状态 $(f(p),f^*)$（C 另含参考成绩）相近的历史；轨迹只以连续纵量做 $[0.5,1]$ 的温和相似度修正。共享经验最多按 16 条等效尝试与本地反馈合成每评价收益率 $V_g$，再按经验强度 $\eta_g$ 修正 Base 联合概率，单动作乘子封顶 4 倍。没有可比经验的动作保持 Base 权重。具体实现说明见[机制1](机制设计/机制1-轨迹节点价值评估与预算分配.md)。
2. **轨迹引导的上下文与算子。** 每次决策只读它需要的事实，轨迹独有的事实是干预证据：同一份代码上做了什么改动，结果如何。精炼读形成路径和同起点的改动与结果，融合读同起点的改动与结果和参考算法，探索只读当前代码。
3. **轨迹反思与经验学习。** 机制三从不同节点的改进经历中，提炼带计算条件的设计经验，供后续算法借鉴。机制二围绕当前算子主动组织局部轨迹，机制三把其他分支和较早阶段的认识带入当前设计。反思比较真实实现、修改及结果，记录一项计算在什么条件下怎样起作用、受到什么限制，以及认识怎样影响后续修改。全局共享的是经验，不是所有分支必须遵循的算法结构。允许性能比较，但结论保留对应的实现条件；新轨迹改变条件或揭示新关系时，回看相关实现并修订。具体规格见[机制3](机制设计/机制3-轨迹反思与经验学习.md)。

V24.1 保留每10次已评价非初始化尝试反思一次、最多6条活跃经验和 Explore 不读经验。十次决定调用周期，证据按完整的相关改进片段组织，补齐父代代码、实际修改、同起点比较和经验代表来源。经验保存稳定编号、计算条件、具体认识与来源，局部更新和归档；未读材料在超限或失败后保留。Refine/Crossover 使用短条件经验解决当前计算或接入计算的问题，不增加检索器、信用分或生成前调用。

三者形成的研究闭环是：节点周围的轨迹支持价值判断与预算选择，所选算法结合轨迹上下文和经验产生候选，评价形成新轨迹，再更新经验与节点价值。

方法叙述见[Method](method.md)，各机制规格见[机制设计](机制设计/README.md)。

## 关键未知量

- **轨迹材料的作用。** 消融探针中，去掉子代后子代好于父代的比例从27.5%降到16.7%，去掉祖先没有变化（[记录](记录/2026-W45.md)）。同起点的干预影响生成。它能否带来更好的最终算法，看V21批次的结果。
- **经验质量。** 笔记记录的是计算思想还是常数取值，以及生成采用的思想是否来自局部视图之外。它决定经验是带来迁移，还是强化局部调参。
- **成本。** V20每次评价后另有一次反思请求，完整体的评价速度约为无反思组的一半。V24.1 每10次已评价尝试触发反思，输入包含完整计算背景和旧来源，不能沿用 V24 只读差分时的15%–20%成本粗估；需按实际调用、token、延后材料与评价次数报告。
- **轨迹在可比窗口内还有多少增量。** 本版只按质量状态与形成路径借用已兑现的冠军改善，不提前记多步收益。关键是轨迹相似度在起点质量相近时能否进一步区分 R、E、C，以及单次突破主导分配的程度是否需要再调窗口与封顶。
- **CVRP早期落后。** 约190次评价时，V20的6路都停在8.44–8.55，Base三路中有两路已降到约8.0。需要看Base这两路的突破来自什么修改，区分评分选错节点与生成未提出该类修改。
