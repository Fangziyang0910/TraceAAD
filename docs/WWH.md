# EvoTrace：研究问题与思路

研究目标是在有限评价预算下找到并持续精炼更好的算法，让设计过程形成的经验帮助后续算法发现。

## 当前叙事：让种群保留自己的演化轨迹

**问题。** 有限预算下，搜索效果取决于每一次评价投向哪个算法，以及每一次修改是否有针对性。这两项决定所需的依据蕴含在演化轨迹中：每个算法由哪些修改逐步形成，从它出发做过哪些尝试，不同设计方向各自取得了怎样的进展。

**原因。** 现有搜索结构难以利用演化轨迹。种群有界，但只保留算法及其成绩。搜索树保留全部轨迹，但规模无界，内容是未经整理的单步修改。反思得到的经验存放在种群之外，与种群各自更新。保留哪些算法与保留哪些演化经历，被当作两件事处理。

**思路。** 种群的更新与演化轨迹的整理面对同一批对象，可以统一为对同一结构的更新。EvoTrace由四个部分组成。

1. **树状种群。** 种群是一棵规模有界、持续生长的树。节点是算法，连接表示算法之间的发展关系，并带有这段发展的经验记录。
2. **反思简化。** 每扩展并评价一批候选后，通过剪枝和反思简化整理这棵树。反思简化沿路径收缩中间步骤，得到阶段经验；在分叉处比较后续方向，得到比较经验。淘汰算法与凝练经验在同一次更新中完成。
3. **轨迹引导的预算分配。** 依据算法的成绩、发展历程和已有尝试的结果，决定下一批评价的投向。
4. **轨迹引导的生成算子。** 改进读取当前算法的形成过程与已有尝试，融合读取两个算法各自的发展分支，探索读取各设计方向的概貌。

## Base

Base是不利用轨迹经验的基础演化搜索，也是所有比较的共同对照。父代按当前成绩做纯Boltzmann采样，`P(p) ∝ exp(-f(p)/tau)`，成绩越小越好；算子按固定概率选择；交叉参考在共同质量候选池中均匀随机选择。演化生成只读当前算法的代码、自包含设计与成绩，交叉增加参考的设计与成绩。规格见[Base](TraceAAD-Base.md)，选择规则的讨论与证据见[预算选择记录](记录/2026-11-09-Base预算选择候选.md)。

## 留档：演化轨迹的三个机制

树状种群之前，EvoTrace围绕同一演化过程组织三个机制。它们的叙事、设计与实现保留作留档，其中的认识是当前叙事的来源。

1. **轨迹节点价值评估与预算分配。** 先按Base的质量偏好分配机会，再用近期、起点质量相近的真实轨迹结果修正分配；交叉参考用轨迹嵌入选择形成经历差异最大的个体。见[机制1](机制设计/机制1-轨迹节点价值评估与预算分配.md)。
2. **轨迹引导的上下文与算子。** Refine通过当前算法的形成路径和同起点尝试决定改什么，Crossover通过参考的形成与历史接入决定借什么，Explore通过既有方向及其后续发展决定探索什么。见[机制2](机制设计/机制2-轨迹引导的上下文与算子.md)。
3. **轨迹反思与经验学习。** 从不同节点的改进经历中提炼带计算条件的设计经验，并随新轨迹修订。见[机制3](机制设计/机制3-轨迹反思与经验学习.md)。

方法叙述见[Method](method.md)与[论文引言旧稿](paper.md)。保留的实现为V21.3（Base＋机制2）、V22.2（V21.3＋机制1）、V23.2（Base＋机制1）和V24.1（V21.3＋机制3），对应关系见[版本与机制](机制设计/实现说明.md)。

三个机制留下的主要认识：

- 同起点的已有尝试改变生成。消融中去掉它们后，子代好于父代的比例从27.5%降到16.7%；去掉祖先链没有变化（[W45](记录/2026-W45.md)）。
- 按次数触发的全局笔记逐渐跟随当时成绩最好的程序（[W46](记录/2026-W46.md)）。
- Base与三个机制的效果比较，以及由此修正的认识，见[三机制效果审计](记录/2026-11-10-Base与三个轨迹机制的效果和认识修正.md)。
- 轨迹的信息增量与作用位置的讨论见[价值边界](记录/2026-11-10-演化轨迹的价值边界.md)与[作用位置](记录/2026-11-10-演化轨迹的信息增量与三个机制的作用位置.md)。
