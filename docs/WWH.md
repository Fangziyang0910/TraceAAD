# EvoTrace：研究问题与思路

研究目标是在有限预算下找到并持续精炼更好的算法，让设计过程形成的经验帮助后续算法发现。

**个体适应度评价与演化过程学习是两个不同层次。** Fitness反映算法当前已经实现的性能；演化轨迹还提供理解算法如何改进、哪些方向值得继续、哪些策略可以迁移的信息。算法演化既产生候选算法，也产生关于如何继续搜索的知识。

当前科学问题是：**如何将算法演化过程转化为后续发现的学习信号，使轨迹引导的算法改进、跨代经验学习与节点选择相互促进？**

## 新研究方向：持续生长的树状种群

2026年11月10日提出的研究构想：将树的发展关系与种群的演化更新融合，维护一个持续生长的树状种群。核心是**树的剪枝与简化算法**：扩展一批候选并评价，再剪枝、压缩路径和重连代表节点，随后继续生长。树的形状随搜索变化，整体由深度范围、分支数量范围或总节点数等结构约束控制。

代码树结构比较、嵌入相似度等可辅助识别相近实现与不同计算方向，使剪枝与简化兼顾个体多样性和发展关系的保留。简化轨迹通过代表节点的Design及其发展关系，为后续设计提供局部、两个分支和全局视野。

贡献定位分为两层：第一层是树状种群的数据结构及其剪枝与简化算法，研究如何组织和更新算法个体及其演化关系；第二层是基于该结构的三个AAD机制，研究如何利用这一结构进行价值评估与预算分配、轨迹引导的生成、反思与经验学习。完整构想见[持续生长的树状种群与剪枝简化](记录/2026-11-10-持续生长的树状种群与剪枝简化.md)。

11月11日调研后，我将第一层贡献具体到面向AAD的剪枝与简化算法。PhyloEvolve已有持续演化森林、剪枝与轨迹生成，PathWise已有图与种群混合框架，Empirical已有谱系中间节点收缩和重连。当前研究重点是将分支剪枝、路径收缩与代表节点重连组织成受结构约束的种群更新算法，并让更新后的结构服务不同视野的设计决策。证据与区别见[相关工作调研](记录/2026-11-11-树状种群与剪枝简化的相关工作调研.md)。

11月11日讨论确认：反思并入简化，称为**演化轨迹的反思简化**。树上一片区域被收缩时，它的经历凝练成记录，写在保留的边和节点上。沿深度收缩得到阶段经验，在分叉处整理得到比较经验。更新循环为“生长—评价—剪枝—反思简化”。两层贡献随之调整：第一层是面向AAD的树状种群及生长、剪枝、反思简化三个操作，原机制3进入这一层；第二层是读同一棵树的预算分配与轨迹引导生成。面向AAD的适配出发点是树同时是生成的材料，保留什么经历决定后续修改。完整设计见[树状种群与反思简化](机制设计/树状种群与反思简化.md)。

## 三个机制

EvoTrace围绕同一演化过程组织三个相互关联的机制：

1. **轨迹节点价值评估与预算分配。** 先按Base的质量偏好分配机会，再用近期、起点质量相近的真实轨迹结果修正分配。反馈直接记当时实际产生的冠军改善 $Y_i=\max(f_i^*-f(c_i),0)$，不再把父代改善平移到另一质量水平。候选动作只借同一算子、最近 $\min(B,256)$ 次评价内、质量状态 $(f(p),f^*)$（C另含参考成绩）相近的历史；形成路径以连续纵量做 $[0.5,1]$ 的温和相似度修正。共享经验最多按16条等效尝试与本地反馈合成每评价收益率 $V_g$，再按经验强度 $\eta_g$ 修正基础联合概率，单动作乘子封顶4倍。交叉参考1.0也归入此机制：在与Base相同的合格候选池中，用轨迹嵌入选择形成经历差异最大的参考；Base在该池中均匀随机选择参考算法。预算收益修正与轨迹参考选择可分别消融。具体实现说明见[机制1](机制设计/机制1-轨迹节点价值评估与预算分配.md)。
2. **轨迹引导的上下文与算子。** 让演化过程中的形成、修改、评价与后续发展成为下一次设计的依据。Refine通过当前算法的形成路径和同起点试错决定接下来改什么；Crossover通过参考的形成与历史接入决定借什么、怎样适配；Explore通过既有方向和后续发展决定新的或值得重新实现的计算方向。按算子组织不同过程材料，使用简单有界窗口，保留真实Diff、评价、必要Design与当前完整代码，删除重复包装和未经验证的历史解释。保留单次`analysis → code → design`，不要求模型得出历史结论、逐项归因或引用编号。当前实现为V21.3，规格见[机制2](机制设计/机制2-轨迹引导的上下文与算子.md)。
3. **轨迹反思与经验学习。** 机制三从不同节点的改进经历中，提炼带计算条件的设计经验，供后续算法借鉴。当前机制二按算子职责组织不同的演化经历，机制三研究把其他分支和较早阶段的认识带入设计。反思比较真实实现、修改及结果，记录一项计算在什么条件下怎样起作用、受到什么限制，以及认识怎样影响后续修改。全局共享的是经验，不是所有分支必须遵循的算法结构。允许性能比较，但结论保留对应的实现条件；新轨迹改变条件或揭示新关系时，回看相关实现并修订。具体规格见[机制3](机制设计/机制3-轨迹反思与经验学习.md)。本轮恢复机制二的三类轨迹用途并简化材料组织，不新增反思与历史解释层；既有V24.1仍使用其原有机制组合。

V24.1在V21.1上每10次已评价非初始化尝试触发反思，一次聚焦一个计算问题，先对应具体实现、实际修改和成绩方向，再提炼设计含义。经验持续保存，每次生成最多展示6条；超过展示预算时选取5条内容匹配经验并轮换1条。旧经验可以通过结构邻近、计算内容匹配和生成时的展示记录回到反思。来源保留1–3个完整案例，允许不同分支共同细化同一认识。源码、修改与结果相邻呈现，使用稳定编号。Refine/Crossover结合条件经验完成各自计算任务，Explore使用当前代码视图。提示用正面行动说明任务，展示选取在本地完成。

三者形成的研究闭环是：节点周围的轨迹支持价值判断与预算选择，所选算法结合轨迹上下文和经验产生候选，评价形成新轨迹，再更新经验与节点价值。

方法叙述见[Method](method.md)，各机制规格见[机制设计](机制设计/README.md)。

## 关键未知量

- **轨迹材料的作用。** 消融探针中，去掉子代后子代好于父代的比例从27.5%降到16.7%，去掉祖先没有变化（[记录](记录/2026-W45.md)）。同起点的干预影响生成。它能否带来更好的最终算法，看V21批次的结果。
- **经验质量。** 笔记记录的是计算思想还是常数取值，以及生成采用的思想是否来自局部视图之外。它决定经验是带来迁移，还是强化局部调参。
- **成本。** V24.1 每10次已评价尝试触发反思，输入包含完整计算背景和旧来源，不能沿用 V24 只读差分时的15%–20%成本粗估；需按实际调用、token、延后材料与评价次数报告。
- **轨迹在可比窗口内还有多少增量。** 本版只按质量状态与形成路径借用已兑现的冠军改善，不提前记多步收益。关键是轨迹相似度在起点质量相近时能否进一步区分 R、E、C，以及单次突破主导分配的程度是否需要再调窗口与封顶。
