# EvoTrace：研究问题与思路

研究目标是在有限预算下找到并持续精炼更好的算法，让设计过程形成的经验帮助后续算法发现。

**个体适应度评价与演化过程学习是两个不同层次。** Fitness反映算法当前已经实现的性能；演化轨迹还提供理解算法如何改进、哪些方向值得继续、哪些策略可以迁移的信息。算法演化既产生候选算法，也产生关于如何继续搜索的知识。

当前科学问题是：**如何将算法演化过程转化为后续发现的学习信号，使轨迹引导的算法改进、跨代经验学习与节点选择相互促进？**

## 三个机制

EvoTrace围绕同一演化过程组织三个相互关联的机制：

1. **轨迹节点价值评估与预算分配。** 先按固定比例抽取算子，再在该算子对应的价值下选择节点。价值是节点在本次算子下超过其轨迹参照的概率，乘以这一超越转化为新最好的概率；两者都从冷启动在线学习。
2. **轨迹引导的上下文与算子。** 每次决策只读它需要的事实，轨迹独有的事实是干预证据：同一份代码上做了什么改动，结果如何。精炼读形成路径和同起点的改动与结果，融合读同起点的改动与结果和参考算法，探索只读当前代码。
3. **轨迹经验学习与累积。** 评价后记录实际代码变化，在同起点比较或接续结果形成时凝练带适用条件的经验，供其他节点借鉴。

三者形成的研究闭环是：节点周围的轨迹支持价值判断与预算选择，所选算法结合轨迹上下文和经验产生候选，评价形成新轨迹，再更新经验与节点价值。

方法叙述见[Method](method.md)，各机制规格见[机制设计](机制设计/README.md)。

## 当前检验

**V21只检验第2个机制。** 它在正式Base上只改变上下文、算子提示和输出顺序（`analysis → code → design`），不含反思、经验和轨迹评分。结果回答：只改变模型读到什么和被要求决定什么，能否找到更好的算法。规格见[V21](机制设计/V21.md)。Base也在11月5日改了父代选择和失败信息，所以两者都跑新批次：`20261105_base_co6`和`20261105c_v21_co6`。

## 关键未知量

- **轨迹材料的作用。** 消融探针中，去掉子代后子代好于父代的比例从27.5%降到16.7%，去掉祖先没有变化（[记录](记录/2026-W45.md)）。同起点的干预影响生成。它能否带来更好的最终算法，看V21批次的结果。
- **h偏高。** 评分复查中，0.1%–1%相对差距的转化率预测34%，实测15%，落后于当前最好的节点获得43%的预算。它决定预算是否过多流向次优节点。
- **经验质量。** 冒烟中的经验措辞偏强，且有重复。它决定经验学习是增益还是噪声。
- **成本。** 每次评价后另有一次反思请求，完整体的评价速度约为无反思组的一半。比较时需同时报告评价次数与模型调用。
- **一步价值的短视。** P和h只看下一次生成能否超过参照，不计拓展在后续精炼中的回报。
- **CVRP早期落后。** 约190次评价时，V20的6路都停在8.44–8.55，Base三路中有两路已降到约8.0。需要看Base这两路的突破来自什么修改，区分评分选错节点与生成未提出该类修改。
