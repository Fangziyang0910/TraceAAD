# TraceAAD: Sustained Algorithm Exploration through Age-Matched Competition and Behavioral Niching

方法设计文档 · 2026 年 10 月 28 日

LLM 自动算法设计需要在有限预算下持续探索和改进候选算法。这一过程面临两种相互关联的困难：尚未充分开发的算法可能过早失去演化机会；已获得机会的开发轨迹又可能被趋向已有设计的高分后代接管。TraceAAD 将同龄竞赛与行为小生境结合，以实际投入协调开发机会，以行为相似性组织局部竞争。每个候选经过执行评价后进入全局档案，并参与相应小生境的精英竞争；其生成消耗归于发起小生境，接受后的进展归于目标小生境。后续生成以小生境精英及其开发轨迹为上下文。该设计将机会分配、候选接受与经验利用连接起来，支持不同算法方向的持续发展。整个过程通过普通聊天 API 生成完整算法函数，并以执行评价驱动搜索。

## 1. 研究动机与核心认识

LLM-AAD 通过生成、评价和选择候选程序搜索高性能算法。候选的当前表现同时受到算法设计与精炼程度的影响。一个较新的设计可能需要若干次改进，才能显现其价值。因此，有限预算下的搜索需要决定哪些算法值得继续投入，以及这些投入如何推进后续开发。

我们借鉴 Go-Explore 对困难探索的分析，将这一问题分为**脱离（detachment）与脱轨（derailment）**两个方面 [1]。在本文的 LLM-AAD 语境中，脱离指尚未充分开发的方向过早失去机会；脱轨指生成偏离当前开发方向。

脱轨的影响取决于搜索如何接受后代。假设轨迹 A 生成了一个行为接近已有方向 B 的高分候选。如果该候选接管 A 的父代，其代码与成绩就会继续进入 A 的开发上下文。此后，分配给 A 的机会将持续用于发展 B。我们的轨迹分析记录了这一过程：在 5 个最终回到初始做法的冠军谱系中，方向变化均发生在 Diverge 后的前一至两次开发；其中一个 OP 案例随后将已偏离的子代纳入生成上下文 [5，§2.3]。

由此得到的核心认识是：有效探索需要同时维持开发机会与开发方向的连续性。 搜索既要给予新起点适当的开发时间，也要组织后代之间的竞争，使不同方向能够在各自已有进展上继续发展。

## 2. 总体框架

TraceAAD 以行为小生境组织候选算法。每个小生境维护一个当前精英、一段已接受的开发轨迹及其实际投入。当前精英作为后续生成的父代，开发轨迹提供与该父代相关的历史经验。新候选依据执行行为参与相应小生境的竞争，优质程序可在小生境之间迁移。

方法包含两个核心机制。

全局程序档案保存全部尝试及其评价结果，并维护搜索得到的最好算法。各小生境则通过局部竞争维护自己的开发状态。全局档案积累搜索成果，小生境组织持续开发，同龄竞赛协调资源投入。

一次迭代依次完成：

同龄选择 → 小生境轨迹上下文 → 完整程序生成 → 执行评价 → 行为归属与局部竞争 → 开发状态更新。

## 3. 同龄竞赛（Age-Matched Competition）

### 3.1 开发年龄与阶段表现

小生境的开发年龄是实际分配给它的开发尝试数。每次尝试均计入年龄，包括无效生成、执行失败，以及最终迁移至其他小生境的候选。

小生境的阶段表现由其已接受程序中的最好成绩给出。其精英、阶段成绩与生成历史共同读取同一份接受记录。这使机会分配与实际开发进程保持一致。

递增收益老虎机研究关注持续投入能够改善表现的候选，并研究如何在固定预算内识别值得开发的对象 [2]。TraceAAD 据此采用同投入比较：候选在相同开发年龄下的表现，决定其是否进入下一阶段。

### 3.2 检查点与机会分配

检查点设为第 5、10、20……次开发尝试。新小生境在首次检查点前获得初始开发机会。到达年龄为 r 的检查点时，将其已接受最好成绩与参照冠军在相同年龄 r 时的历史成绩比较。

不差于参照的小生境继续保持活跃，其余小生境暂停。调度器优先选择年龄较小的活跃挑战小生境；缺少活跃挑战者时，继续开发冠军。参照冠军取当前精英成绩最好的小生境。停滞后的发散生成提供新的开发起点。

历史检查点保存当时的成绩、参照对象和比较结果。跨小生境迁移产生的新成果进入当前状态与后续阶段，历史快照保留其发生时的信息。快照及参照不足时的处理采用附录 B 所列参考协议。

### 3.3 生成消耗与接受进展

若 A 获得一次生成机会，而候选被 B 接受，则 A 的年龄增加一次，B 的当前精英得到更新，B 的年龄保持不变。A 的同龄成绩继续由 A 自己的接受记录确定。

这一规则保留两类信息：资源消耗记录搜索实际在哪里发起，开发进展记录成果实际推进了哪里。 同龄竞赛据此评价各小生境的阶段表现，跨小生境迁移则使有价值的成果继续参与搜索。

## 4. 行为小生境（Behavioral Niching）

进化计算中的小生境方法通过局部竞争支持多个搜索区域并行发展。拥挤机制将竞争限制在相似个体之间，为维持不同子群提供了算法基础 [3]。在 LLM-AAD 中，BehaveSim 依据算法执行行为衡量相似性，并在与 FunSearch 的结合中，将新程序分配到行为相近的岛屿 [4]。

TraceAAD 将这一原则用于开发轨迹的组织：候选首先获得行为归属，再参与目标小生境的精英竞争。接受结果同时更新后续父代、开发历史与同龄成绩，使局部竞争贯穿搜索的选择和生成环节。

### 4.1 行为记录与候选归属

执行器在固定诊断输入上记录候选的可观察行为。具体表示与算法接口对应，例如启发式矩阵的候选排序、构造算法的选择序列，或迭代算法的中间解序列。各任务采用一致的诊断输入与随机种子，并缓存已评价程序的行为记录。

候选与各小生境已接受的程序进行比较，归入距离最近的小生境。小生境的行为参照集合随接受事件增长，反映其实际开发过程。参考实现采用候选到该集合的最小距离；任务表示、距离聚合和并列规则详见附录 B。

BehaveSim 的具体度量使用中间解序列与动态时间规整（DTW）[4]。本文采用其行为组织思路，任务级表示按附录 B 的协议确定。行为距离在机制中承担候选归属与竞争范围选择的作用。

### 4.2 局部精英竞争

确定目标小生境后，候选与该小生境的当前精英比较。候选成绩更好时，更新精英并加入已接受开发轨迹；否则，保留其全局评价记录，维持现有精英。

这一过程将适应度竞争组织在行为相近的开发区域内。沿当前方向取得的改进可以成为新的开发起点；接近另一方向的候选，则参与那个方向的竞争。

### 4.3 跨小生境迁移

当候选的发起小生境与接受小生境不同，形成一次跨小生境迁移（Cross-Niche Transfer）。迁移保留候选的真实父代、生成来源和评价结果，同时更新目标小生境的精英与开发轨迹。

## 5. 小生境轨迹上下文（Niche-Conditioned Context）

候选接受决定小生境的演化状态，也决定下一次生成使用的经验。TraceAAD 以**小生境轨迹上下文（Niche-Conditioned Context）**连接局部竞争与程序生成。

每次开发提示包含任务与接口约束、当前精英的完整代码、实测成绩，以及本小生境已接受的开发记录。记录按接受时间组织，展示此前的程序改进和对应结果。跨小生境迁移条目保留来源，使上下文准确反映当前程序的取得方式。

任务模板在开发提示中保留函数签名、输入输出说明和运行约束；实现主体由当前父代提供。历史材料按既定上下文预算选取。LLM 根据这些信息生成完整候选函数，执行器评价其有效性与任务成绩。

行为小生境决定哪些成果延续当前开发，轨迹上下文将这些成果转化为下一次生成的依据。 两者共同减少一次方向变化通过父代与历史反复传播的机会。

## 6. 两个机制的协同

同龄竞赛与行为小生境分别处理开发过程的两个维度。前者沿时间比较实际投入与阶段表现，后者沿行为相似性组织候选竞争。二者共同作用于小生境的接受轨迹。

若 A 生成了一个接近 B 的高分程序，行为归属先确定它参与 B 的竞争。A 的父代、开发历史和同龄成绩由 A 的接受记录维持；B 则可通过迁移获得改进。下一轮选择重新依据各小生境的年龄与表现分配机会，生成继续读取被选小生境的当前状态。

因此，一次偏离可以产生跨小生境贡献，同时保留原方向的后续开发入口。TraceAAD 将持续探索落实为三个相互衔接的过程：依据投入分配机会，依据行为组织竞争，依据已接受轨迹积累经验。

小生境由初始化和停滞后的发散生成建立。普通开发候选通过局部竞争推进已有小生境。预算耗尽时，从全局档案中返回实际评价成绩最好的有效程序。

## 7. 实验设计与过程分析

实验围绕一个主要问题展开：在相同搜索预算下，机会分配与行为小生境的结合能否发现更好的算法？ 模型、生成设置、评价实例和最终测试条件保持一致，同时记录行为采集与距离计算的额外成本。

核心消融采用“同龄竞赛开／关 × 行为小生境开／关”的 2×2 设计。关闭行为小生境时，候选沿生成来源参与成绩竞争；开启时，行为归属统一决定精英、历史和阶段成绩的更新。四组使用相同的接口化开发提示。模板函数体的影响另设对照。

过程分析重点记录小生境存续、行为重定向、局部改进和跨小生境贡献。行为重定向率由候选的来源与目标是否一致计算；潜在接管事件进一步要求候选优于来源精英。最终成绩、最好成绩随预算的变化，以及产生全局改进的来源共同反映搜索收益。

附录 A 给出统一搜索流程，附录 B 汇总实施协议，附录 C 用一个简化模型解释局部竞争对探索连续性的作用。

## 附录 A：统一搜索流程

下述流程从已建立有效根程序的小生境开始。年龄计数按一次候选生成尝试执行，初始化与修复的具体配置见附录 B。

```text
输入：小生境集合，全局程序档案，总搜索预算

while 预算尚未耗尽：
    A ← 同龄竞赛选择的小生境
    p ← A 的当前精英
    context ← 任务接口 + p + A 的已接受开发轨迹
    q ← LLM 根据 context 生成的完整候选函数

    记录调用成本
    A 的年龄增加一次
    执行评价 q，并将尝试及真实父代 p 写入全局档案

    if q 有效：
        按任务成绩更新全局最好程序
        计算并缓存 q 的行为签名

        if 行为签名可用：
            B ← 与 q 行为最近的小生境
            记录来源 A、目标 B 及距离信息

            if q 优于 B 的当前精英：
                B 的精英 ← q
                将 q 加入 B 的接受轨迹与行为参照
                保存 q 的真实生成来源
                # B ≠ A 时，B 的年龄保持不变
        else：
            按预先固定的行为记录失败策略处理

    if A 到达检查点：
        用 A 的已接受最好成绩开展同龄比较
        保存本次阶段表现及参照快照
        更新 A 的开发状态

    按既定停滞规则启动发散生成，建立新的小生境

返回：全局档案中任务成绩最好的有效程序
```

签名不可用时保留候选的全局成绩和错误记录。该分支的局部更新策略属于附录 B 的待配置项。

### B.2 距离聚合与并列规则

原稿建议将候选到某小生境的距离定义为其与该小生境接受程序的最小行为距离。设小生境 j 的接受集合为 H_j，程序行为距离为 d，则：

\[
D(q,H_j)=\min_{p\in H_j} d(q,p),\qquad j^*=\arg\min_j D(q,H_j).
\]

执行时先逐程序计算距离，再对每个小生境取最小值，最后选择最近的小生境。该设置采用相对距离排序，普通开发阶段将候选分配至现有小生境。

并列时，参考规则为：来源小生境若属于并列最近者，优先选择来源；否则按固定小生境编号选择。距离的浮点并列容差在任务配置中统一记录。

## 附录 C：探索连续性的简化模型

考虑一个简化的吸收模型。某方向 A 获得 r 次开发尝试。每次仍从 A 开发时，以固定条件概率 ε 生成一个能够凭成绩接管父代的偏离候选。接管后，后续搜索持续从新方向出发。在这种更新方式下，r 次尝试后仍保留 A 开发起点的概率为：

\[
\Pr(\text{A 的开发起点仍被保留})=(1-\varepsilon)^r.
\]

再考虑理想的行为竞争规则：它将上述偏离候选送入相应方向的竞争，同时保留 A 的开发起点。在已经分配给 A 的 r 次尝试中，未偏离尝试数的期望为：

\[
\mathbb{E}[N_{\mathrm{aligned}}]=r(1-\varepsilon).
\]

前一式刻画开发起点的存续，后一式刻画保持原开发方向的尝试数。两者揭示了候选接受规则的作用位置：一次生成偏离是否改变其后所有尝试的出发点。

实际运行中，行为归属的准确程度与小生境获得的预算共同影响这一过程。实验通过行为重定向、精英更新和阶段存续记录，分析局部竞争如何改变探索连续性。
