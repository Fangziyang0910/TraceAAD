# TraceAAD V10.13：简洁的持续算法开发

V10.13 维护一个已评价程序档案。每轮选择一个开发动作和父代，让模型直接生成完整程序或精确修改父代，评价后把有效程序加入档案。运行管理不参与搜索决策。

## 搜索过程

1. 顺序生成 8 个有效初始程序。后续初始提示可以看到容量允许的既有初始程序。
2. 每轮以相同概率选择 Refine、Tune、Pivot 或 Fuse。
3. 在全部有效程序上构造 ESS 目标为 8 的质量 softmax，再混入 12.5% 均匀概率并抽取父代。
4. 模型生成候选；解析成功后调用一次评价器。每次评价器调用消耗一个预算，解析失败不消耗评价预算。
5. 评价成功的程序作为新节点加入档案；预算耗尽后保存最好程序和运行摘要。

## 四种动作

| 动作 | 提供的材料 | 目标 |
| --- | --- | --- |
| Refine | 父代、最近至多 3 个形成步骤、至多 2 个同父试验 | 改进表示、比较或组件协调 |
| Tune | 与 Refine 相同，局部试验优先 Tune 子代 | 调整真正影响决策的参数、尺度和交互 |
| Pivot | 父代 | 改变核心假设或决策原则 |
| Fuse | 父代和一个不同的参考程序 | 吸收互补计算并形成更好的程序 |

Fuse 从代码不同于父代的节点中选择一份参考，质量抽样和均匀抽样各占 50%。如果没有可用参考，本轮按 Refine 执行。上下文过长时依次移除较早历史、局部试验和参考程序，父代代码保持完整。

## 输出与解析

默认输出是一段 Python 代码，可以带一行 `Idea:`。小修改可以返回一个 JSON edit：

```json
{"mode":"edit","edits":[{"search":"原代码","replacement":"新代码"}]}
```

解析器只提取 Python 代码块或完整 JSON 对象，应用精确替换，然后检查目标函数名称、参数和 Python 语法。它不解析多层包装、结构化说明、参考声明或额外元数据。

## 保存内容

- `nodes.jsonl`：有效程序、分数、父代、动作和 Fuse 参考。
- `events.jsonl`：每轮状态、评价编号、分数和是否超过父代或当前最好值。
- `llm_calls.jsonl`：模型输入、输出和服务返回的用量。
- `tree_state.json`：继续运行所需的随机状态和计数。
- `logs/run_summary.json`：结束状态和最好程序。

状态文件只用于继续未完成运行，其他文件直接保存生成内容与评价结果。
