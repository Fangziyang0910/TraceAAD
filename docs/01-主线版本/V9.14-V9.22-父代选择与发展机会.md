# V9.14–V9.22：父代选择与发展机会分配

这一阶段的研究对象是：已测程序怎样竞争下一次评价预算，初生方向是否获得连续开发，以及开发收益按程序、方向还是思想记录。版本依次试用了质量抽样、短发展块、机会加分和思想级生成；以下只记实际规则与观察，不把跨版本成绩归因于某一个规则。

| 阶段 | 机会分配与生成方式 | 已记录的观察 |
| --- | --- | --- |
| V9.14–V9.15 | V9.14 保留 8 个有效根、单父形成树，Refine/Explore 概率为 0.7/0.3，并展示最近 8 条来时路。V9.15 在质量上加入初生保护和历史增长信号，用 ESS 控制抽样范围。 | V9.15 的增长项广泛改变父代排序，初生保护影响较小；所分析运行的最好程序深度由约 77–115 降至 13–22，任务收益不一致。 |
| V9.16 | 随机给有效 Explore 子代连续三次 Refine；entry 只记录来源，不承担算法类别识别。 | 所分析的 415 个初生退步入口中，45 个恢复来源水平，23 个超过来源父代；最终最好程序未直接来自这些发展段。三次发展共占用 1368 个 primary slots（包含未退步入口）。 |
| V9.17 | 采用 Discovery、Maturation、Competition、Development、Reopening 阶段；方向质量决定能否参与竞争，固定发展块增益决定是否延续。 | 发展块使单个方向的连续响应可观察，同时减少新入口覆盖。 |
| V9.18 | 回到每次评价后重新选择，比较纯质量与质量加短暂机会项；另行测试全局事实提示。 | `q-atomic` 与 `q+O-atomic` 分开预算分配的比较，全局事实提示作为另一项变化。 |
| V9.19–V9.20 | 曾把执行行为距离用于覆盖和参考检索，随后转向由控制器选择已测程序、生成端选择 Develop/Explore/Crossover 的分工。 | 这些版本同时改变分配、上下文和算子，不能仅凭终局成绩识别行为距离的作用。 |
| V9.21–V9.22 | V9.21 每次提出 continue/branch 两个思想，每个思想独立生成两份实现并全部评价。V9.22 改为动态 scaffold mid-rank，分别记录相对当前实现和稳定脚手架的响应，以 action UCB 分配两种动作。 | V9.21 首跑暴露固定 root-MAD 质量尺度饱和、两种比较基准不一致；V9.22 是对此进行的机制修订。 |
