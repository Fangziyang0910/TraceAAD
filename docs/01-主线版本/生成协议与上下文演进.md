# 生成协议与上下文演进：V10–V11

V10 阶段逐步把复杂的联合机会规划收敛为容易观察的生成循环：明确父代、算子和参考材料，每次生成一个候选，评价后重新选择。主要经验是让上下文表达具体试验，让输出协议直接承载可执行程序。

## V10.0–V10.3：从联合规划到单次生成

V10.0 将机会写为 `(状态, 算子, 参考)`，估计机会价值并分配覆盖。V10.1 扩展多算子，V10.2 改为每次一个算子，并用质量权重与 `1/sqrt(attempts+1)` 调整机会。V10.3 进一步缩短提示，把生成任务从复杂的外部判断转向具体改写。

这些版本提出了贯穿后续的问题：候选持续新增时，访问惩罚和不断增长的竞争范围会怎样影响精炼？增加算子后，模型实际产生了什么变化？先记录父代、操作、具体计算和相对结果，才能回答。

## V10.4–V10.6：Idea 与代码怎样配合

V10.4 将思想与实现拆为两次调用。实际执行遇到设计文本过长、未完成设计进入下一步和实现阶段上下文不充分等问题。V10.5 回到单次 Idea+Code，固定 Refine/Pivot/Fuse=0.50/0.15/0.35，Pivot 父代一半按质量、一半均匀选择，让换向接触更多起点。

V10.6 尝试生成后再总结实现。30 组二次 Idea 配对核查显示，重新总结能修正部分公式，也会保留语义错误。思想文本适合说明意图，代码变化适合记录实际计算；增加一次解释调用的价值应由后续生成收益决定。

## V10.7–V10.7R：参考可见与试验可理解

V10.7 按质量分层展示参考，改善了材料覆盖和部分格式表现。诊断发现，看到一组程序及其分数，还不足以理解哪个改动对哪个父代有效。V10.7R 据此围绕设计任务组织证据：明确设计底座，给参考标注实际角色，保留完整程序与形成关系，修正历史编号和材料归属。

预算仍按评价推进。参考材料的数量、来源与实现细节影响模型看到的条件，应作为独立变量比较。

## V10.8：完整父子转移

V10.8 以程序节点分配机会，将真实父子代码转移与评价组织为形成历史，结合 Refine、Pivot 和 Fuse。模型可以看到变化前后程序，沿着同一路径理解结构如何形成。

后续诊断记录了两个实际缺口：后期分配可能随档案增大而扩散，退步的新结构又很少得到直接开发。其 864 个有完整观察窗的退步 Pivot 中，只有 50 个在随后 100 次评价内得到直接 Refine/Fuse 请求；353/3400 个有效 Fuse 与 donor AST 相同，其中 254 个复制了较差 donor。完整代码可见之后，还需明确迁移目标和发展机会。

## V10.9：新结构试用、局部试验与 Tune

V10.9 固定质量 ESS 目标为 8，取消次数惩罚，给近期结构变动少量限时试用；初始化让后续根读取已有方法。当前父代的直接成败子代进入上下文，Fuse 强调具体部件迁移，新增 Tune 负责数值精炼。

这组变化对应不同问题：质量集中支持持续开发，局部试验补充形成链，参考代码提供互补计算，Tune 强化保结构调整。结果随任务变化，正式比较保留在各版本结果页。错误快照中的解析与执行问题也推动了后续接口简化。

## V10.10：简化正常开发，单独处理错误

V10.10 移除新结构试用和直接子代试错上下文，统一短形成路径，并加入宽容解析、具体错误记录和一次修复。随后修订为顺序参考初始化、代码优先接受，再改为生成目标函数并由任务模板重建程序。

首版和修订版是两个独立完成批次，具体参数、批次及第三次函数级修订集中在[V10.10 机制设计](TraceAAD-V10.10-机制设计.md)。这条演进线的主要取舍是：正常搜索保留少量相关材料，错误发生后再给针对性反馈。


## 后续修订：档案材料与节点机会

<a id="v10-12"></a>

### V10.12：在短轨迹外追加两张卡片

V10.12 保留 V10.11 generic 的 ESS-8 父代分配、四算子各 25%、Pivot 的一半均匀选择、最近八条短形成轨迹和 Fuse 完整 donor。每次生成另加两张只含 Idea 与 fitness 的 profile card，按档案排名 softmax（tau=8）无放回抽取并排除父代；所有算子采用相同规则。

研究问题是跨分支思想能否补充形成关系。原设计计划三重复，最终完成批次为 `20260921_v1012`，五任务×四重复、每路 E1000。原设定的后续选择是：若 TSP/VRPTW 任一同规模相对 generic 恶化超过 1%，就不增加卡片。最终测试未通过该门槛。

<a id="v11-1"></a>

### V11.1：固定温度节点抽样与算子上下文

V11.1 从 V11.0 的 code 级最高分选择改为节点级抽样。令 q_i 为 fitness 百分位，a_i 为节点作为直接父代的选择次数，t=Σa_i：

`s_i=q_i+0.1*sqrt(log(1+t)/(1+a_i))`

`P(i)=softmax(s_i/0.2)`

新节点 a_i=0；选择时加一，生成或评价失败不撤销；修复不重新选父，因此不额外增加次数。重复代码仍是独立节点。四算子各 25%，共同使用该分布，温度全程固定。

Refine/Tune 读取当前程序与最近八条短形成记录；Pivot 读取最多八张 Idea+fitness 档案卡；Fuse 在档案卡之外展开第一张参考的完整代码。卡片按排名 softmax（tau=8）无放回抽取，排除当前节点，保留既有容量裁剪与参考回退。相同算子在所有任务使用相同规则。

该版本把确定性头部开发改为随机机会分配，并让不同动作使用不同材料。最终 manual 批五任务×五重复、每路 E1000。两版的结果、缺失项和工件路径统一见[V10.12 与 V11.1 测试](../02-实验结果/2026-09-23-V10.12与V11.1-heldout测试.md)，V11.0 的研究发现见[机制分析](../02-实验结果/V11.0-机制分析.md)。

### V10.8

```text
输入：任务接口、固定模型、真实评价器、评价预算 B
档案：有效程序树、全部尝试事件、评价收据与选择次数

1. 从头生成并评价，获得 8 个有效根；初始化评价计入 B。
2. 在评价预算仍有剩余、运行状态允许时：
   a. 抽取 Refine / Pivot / Fuse。
   b. 按该算子的质量与次数分布抽取一个可用节点作为底座。
   c. 使用该节点自己的实测评分与形成历史。
   d. 若为 Fuse，尝试选择 donor；不可用时改为 Refine。
   e. 提取底座最近的连续父子形成边。
   f. 选择每条边的完整表示，并按容量从最老端整边删减。
   g. 构造完整提示；记录请求、随机状态与本次机会计数。
   h. 一次生成短 Idea 和完整代码。
   i. 解析通过后检查是否原样返回父代/donor；重复则拒绝，否则评价并将有效程序加入树。
   j. 保存全部尝试事件、实际评价收据、节点评分及累计最好值。
   k. 返回 a，重新决定下一次任务。
3. 返回按节点实测评分选出的全档案最佳程序。
```

以上是健康运行的主流程；预算用完时若有效根少于 8 个，系统以“初始化未完成”状态结束。
