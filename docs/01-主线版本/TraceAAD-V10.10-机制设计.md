# TraceAAD V10.10：轨迹搜索、一次错误修复与实验结果

V10.10 通过形成路径组织算法开发上下文，以 Refine、Tune、Fuse、Pivot 四类动作推进搜索，并对失败候选提供一次错误反馈修复。首版在 TSP、CVRP、OP 和 OBP 上较 V10.8/V10.9 改善；修订版 V10.10R 进一步改善 TSP、VRPTW 和 OBP 的多数测试规模，但 OP、CVRP 回落。两个已完成批次呈现出明确的任务差异。

## 1. 版本与实验对应

V10.10 经历了三次机制修订。实验表中的 **V10.10** 对应首版，**V10.10R** 对应第二版；第三版改变了生成对象和程序存储格式。

| 版本 | 日期与代码版本 | 主要变化 | 实验记录 |
| --- | --- | --- | --- |
| 首版 V10.10 | 2026-09-10，`cb6ab356` | 简化提示与上下文，移除新结构试用和直接子代试错上下文，加入宽容解析、具体报错和一次修复 | `20260910_v1010_formal`，15/15 路完成搜索与 held-out 测试 |
| 修订版 V10.10R | 2026-09-11，`8ba1c0ba` | 顺序参考初始化、统一短形成路径、代码优先解析、三要素算子指令和更具体的错误反馈 | `20260911_v1010_formal`，15/15 路完成搜索与 held-out 测试 |
| 第三版 | 2026-09-12，`787f12e9`，含 `1e0e660a` | 生成目标函数，由任务模板重建程序；上下文与节点存储改为函数级文本 | 本页第 5 节收录机制修订，未列独立质量批次 |

两个已完成批次均采用五任务、三个重复（seed 0/1/2）、每路 1000 次评价预算，思考模式关闭。下文先说明共同搜索流程，再列出各版的具体设计。

## 2. 共同搜索流程

搜索先建立 8 个有效根节点，随后反复执行“选择算子与父代 → 组装上下文 → 生成候选 → 解析与评价 → 保存节点和形成关系”。四个开发算子各以 25% 的概率抽取，贯穿整个搜索过程。

| 算子 | 设计动作 |
| --- | --- |
| Refine | 继续改进当前算法的决策方法与实现 |
| Tune | 保留主要计算结构，校准影响决策的系数、阈值、指数或调度参数 |
| Fuse | 以当前程序为宿主，吸收另一程序中的有用计算并整合为连贯算法 |
| Pivot | 围绕不同的主要决策机制提出替代算法 |

有效候选作为节点进入档案，记录代码、模型说明、实测 fitness、算子、父代和 donor。形成路径沿父指针串联历史改进；失败候选及其报错进入事件记录。每次调用评价器均计入预算，包括初始化、执行失败和修复后的评价；解析失败和输入复制只产生模型调用与处理成本。完整记账规则见[评价预算与成本口径](../02-实验结果/00-评价预算与成本口径.md)。

### 父代与 donor 分配

父代从全部有效节点中选择。内部 fitness 统一为越大越好，质量分布为：

\[
q_i=\frac{\exp[\beta(f_i-f_{\max})]}{\sum_j\exp[\beta(f_j-f_{\max})]},\qquad
\operatorname{ESS}(q)=\frac{1}{\sum_i q_i^2}\approx\min(N,8).
\]

每步根据当前 fitness 分布求解系数 \(\beta\)，使质量概率集中在约 8 个有效候选上；节点不足或最高分大量并列时采用可达到的集中程度。Refine、Tune、Fuse 按 \(q\) 选择父代，Pivot 按 \(0.5q+0.5U\) 选择，其中 \(U\) 为全部有效节点上的均匀分布。节点被开发的次数单独记录，选择概率由当前质量分布决定。

Fuse 先排除宿主及与宿主 AST 相同的候选，再在剩余档案上计算 ESS-8 质量分布 \(q_d\)，按 \(0.5q_d+0.5U_d\) 抽取一个 donor。模型根据两份程序判断可迁移的计算；候选集为空时执行 Refine。第二版将这套既有分配规则从早期消融框架中独立出来，采样行为保持一致。

### 一次错误修复

候选发生代码提取、语法或接口校验失败，或评价返回执行错误、超时、非法结果、非有限 fitness 时，系统优先安排一次修复。修复输入包括任务接口、完整失败输出和核心报错；核心报错去除路径并限于 2000 字符，执行异常补充候选代码最深栈帧的行号和函数名，超时消息给出整次评价的实际时限。模型的任务是保留原决策方法并修正报告的失败。

修复使用新的 `candidate_id`，通过 `repair_of` 关联原候选，并沿用原算子、父代与 donor。修复成功后接入原有效父代；再次失败或复制输入后结束本次修复。额外调用以 `stage=repair` 记录 token 和耗时。评价准备故障及框架异常终止运行，交由运行恢复流程处理。

## 3. 首版设计

首版在 V10.9 上简化生成过程：父代使用上述质量与均匀混合分配，取消近期新结构的额外试用概率；正常上下文聚焦当前算法及其来路，移除当前节点的直接子代试错记录。算子提示强调具体设计动作，失败输出携带报错进入一次修复。

这套设计把正常开发与错误修复分开：前者利用已有算法及形成信息提出改进，后者处理本次生成的具体失败。首版结果覆盖 15 路完整搜索及其 held-out 测试，TSP、CVRP、OP 和 OBP 相对 V10.8/V10.9 改善，VRPTW 的三个测试规模仍落后于 V10.8。

## 4. V10.10R 修订设计

### 顺序参考初始化

第一个根节点只根据任务接口生成。从第二个根起，模型按生成顺序读取此前有效根的完整程序与实测 fitness，再生成下一候选，直到得到 8 个有效根。初始化候选经过常规解析与评价；已有根全部进入上下文，根间允许重复。初始化完成后直接进入四算子搜索。

### 统一短形成路径

四个算子统一读取当前完整程序、fitness 和最近至多 8 条形成边。每条边包含生成时的 Idea、所用算子及前后 fitness，按从旧到新的顺序展示。Idea 保存模型对算法的原始说明。Fuse 额外读取本轮 donor 的完整程序与 fitness。

提示按“任务接口 → 当前程序 → 当前程序的形成路径 → donor（仅 Fuse）→ 算子指令 → 输出要求”组装。祖先信息以形成边摘要呈现，完整代码集中在当前程序和本轮 donor。算子指令统一说明设计对象、设计动作与改进目标。

普通生成和修复使用相同的输出容量计算：

\[
\text{max\_output\_tokens}=\min(16384,32768-256-\text{input\_tokens}).
\]

系统按完整提示检查容量；输入占满可用上下文时报告容量错误。静态提示对照选取首版的 OP、CVRP、VRPTW 共 450 个选择情境：Fuse 输入中位数由 14.3–19.9K 降至 4.3–5.5K tokens，Refine 由 10.1–13.9K 降至约 3–3.7K；Tune、Pivot 因加入形成路径增加约 1–1.4K。全部提示的最大输入由 29,184 降至 7,581 tokens。

### 代码优先解析

模型输出一个包含完整实现的 Python 代码块，并可附约 500 词以内的 Idea。解析器提取唯一完整程序，依次进行语法、目标函数和编译校验。说明独立提取，支持代码前后的 Idea 标题、普通正文和空说明，来源记为 `tagged`、`prose` 或 `missing`。

代码按原文保存，保留注释、字符串和文档字符串。多个代码块、提取位置不明确、空代码或服务标记为长度截断且围栏未闭合的输出进入错误处理。正常开发阶段用 AST 检查父代和 donor 的直接复制；初始化按前述根节点流程处理。连续 50 次不可评价输出触发运行终止检查。

对首版 22,414 条已保存响应进行静态重放：旧解析的 7,772 次 `invalid_output` 中，7,676 次经新解析通过语法、接口与编译校验，30 次暴露真实代码错误，66 次仍存在提取问题；14,641 条新旧均接受的响应代码完全一致。该测量记录的是解析阶段的接受情况，搜索质量见下文独立批次结果。

### 具体错误反馈

VRPTW 为四类非法构造分别提供条件消息：depot 上无可行客户、已在 depot 又返回 depot、返回节点超出可行候选集、路线覆盖不全。TSP 接口说明补充逐步调用、近邻序候选、末节点自动补入和重复选择中止等实际调用行为。运行环境说明给出 Python、NumPy 版本及整次评价时限。修复读取最近一次失败响应，评价收据保留 `error_type`、`error` 和 `traceback`。

## 5. 第三版：目标函数生成

第三版将生成对象从完整程序改为目标函数。模型先输出 `Idea:`，说明主要决策规则、关键计算或参数及相对输入算法的变化，再输出 `Code:` 中的目标函数定义。系统将函数放回任务模板，由模板提供 import 和任务脚手架，重建完整程序后评价。

上下文中的函数文本经 `ast.parse` / `ast.unparse` 规范化。`tree_state` 和 `run_summary` 保存函数级代码，首版与第二版则保存完整程序。因此，第三版节点用于评价时需要先重建程序。本节收录了这次实现修订；本页质量结果来自首版与第二版两个已完成批次。

## 6. 实验结果

两个批次各完成五任务 × 三重复 × 每路 1000 次评价，随后对每路训练 best 进行相同实例的 held-out 测试。TSP、VRPTW 使用 seed 2025、每个规模 16 个实例；OP、CVRP 使用 test seed 4567、每个规模 64 个实例；OBP 使用 seed 2025 的六组多规模测试。下表为三重复均值，完整逐路数值与标准差见[V10.10 实验结果](../02-实验结果/各版本实验记录/V10.10-实验结果.md)。

| 任务与规模 | 首版 V10.10 | 修订版 V10.10R | 修订后的变化 |
| --- | --- | --- | --- |
| TSP 50 / 100 / 200，路径长度 ↓ | 6.1879 / 8.5360 / 12.0492 | 6.0584 / 8.4287 / 11.7853 | 三个规模均改善 |
| CVRP 50 / 100 / 200，路径长度 ↓ | 9.1173 / 15.4616 / 27.9271 | 9.4247 / 15.9508 / 28.4282 | 三个规模均回落 |
| OP 50 / 100 / 200，prize ↑ | 15.1973 / 30.8072 / 55.4265 | 14.9691 / 29.8987 / 52.8977 | 三个规模均回落 |
| OBP 1k / 5k / 10k，容量 100，箱数 ↓ | 419.133 / 2028.467 / 4043.933 | 414.800 / 2027.133 / 4039.867 | 三个规模均改善 |
| OBP 1k / 5k / 10k，容量 500，箱数 ↓ | 80.933 / 402.467 / 804.400 | 81.133 / 401.933 / 803.400 | 5k、10k 改善，1k 增加 0.2 箱 |
| VRPTW 50 / 100 / 200，总距离 ↓ | 20.1481 / 34.1757 / 57.1681 | 19.1630 / 32.6558 / 54.3061 | 三个规模均改善 |

按各结果页记录的五基线比较，15 列主表（TSP、CVRP、OP 各 3 列，OBP 6 列）的平均名次分别为 2.133 和 2.867。两版 TSP 均为三个规模第一；首版 CVRP 均为第二。VRPTW 单独统计：首版三个规模均为第二，修订版按更新后的 EoH 基线三个规模均为第一。

训练 best 与 held-out 的主要变化一致：TSP 和 VRPTW 的训练与测试均改善；CVRP 路径长度由 8.762526 增至 8.866203，OP prize 由 14.843333 降至 14.759333，两者在训练与 held-out 上均回落；OBP 训练 best 由 726.333 降至 724.750，held-out 的 capacity=100 三个规模均改善，capacity=500 中两个规模改善、一个规模增加 0.2 箱。

## 7. 研究发现与下一步

V10.10 首版获得了多任务改善，修订版则呈现任务分化：TSP、VRPTW 和 OBP 的多数规模继续改善，OP、CVRP 同时退步。初始化、上下文、解析与提示的组合修订改变了各任务的搜索结果，后续机制选择应分别考察构造型任务与 ACO 启发函数任务。

上下文压缩与程序解析各有直接测量结果：前者显著降低 Fuse、Refine 的输入长度，后者接受了此前因说明格式而失败的大量程序。算法质量由两个完整批次的训练与 held-out 结果呈现，两类指标分别记录生成接口效率和最终求解效果。

下一步采用相同任务、种子、每路 1000 次评价和 held-out 设置，对初始化、形成路径与算子提示分别做对照。优先检查 OP、CVRP 的下降来源，同时统计 Fuse 的实际部件迁移、Tune 的参数变化、候选的后续开发收益，并并列报告评价次数、有效程序数、模型调用/token 与求解耗时。
