# TraceAAD V10.10：轨迹搜索与一次有界错误修复
V10.10 在 V10.9 基础上收束为短形成路径、四算子均分、sequential informed initialization 和一次有界错误修复。代码优先解析、具体错误反馈和顺序中性的输出契约把生成重点放在可执行程序与实际决策机制上。正式批次采用五任务、三重复和每路 1000 次真实评价。

## 相对 V10.9 的修改

donor 分配沿用 V10.9，初始化收缩为下文的 sequential informed initialization；四个算子各占 25%，不预设哪种设计动作对所有任务更重要。提示明确操作目标，放宽对具体修改手段的限制。移除两项机制：新结构不再因近期出生或开发不足获得额外选择概率；普通生成上下文不再注入当前节点的直接子代试错记录。正常搜索上下文统一为下文的短形成路径，不再按算子排除历史或展开历史代码。一次错误修复临时读取本次失败输出和报错，不构成历史试错记忆。

错误处理包括：

1. **代码优先解析。** 系统从响应中提取唯一完整的候选程序，并独立保存已有算法说明；程序通过语法、目标函数与编译校验后进入既有重复检查与真实评价。描述的提取规则全部是确定性的：存在明确 Idea 标题时读取对应段落（标题可在代码前后，接受大小写、加粗、Markdown 标题与无冒号等形式，取最后一个明确标题）；没有标题时把代码之外的非空正文按原顺序保存为说明；纯代码输出说明为空字符串。三种来源（tagged / prose / missing）记入 `parse_mode`。响应标签、位置或描述缺失不触发模型修复；说明是模型原始陈述，不做语义核验或补写。代码提取不改写程序内容：thinking 清理只作用于代码区之外的响应包装（经偏移映射取回原文），沿用既有换行与外围空白规范化后归档，注释、字符串与文档字符串完整保留。多代码块、无法确定边界、空代码块仍拒绝；服务报告 `length` 且代码围栏未闭合时不恢复，正常结束缺闭合围栏的既有恢复保留。
2. **保存具体报错。** 评价收据和失败事件保存 `error_type`、`error`、`traceback`，解析失败记录可行动的原因。复用现有评价器返回的错误字段，不添加静态分析依赖或额外任务预检。VRPTW 的四个非法构造出口（depot 上无可行客户、已在 depot 又返回 depot、返回节点超出可行候选集、路线覆盖不全）各自携带条件消息，经 `InvalidEvaluationResult` 映射为 `invalid_result`；成功评分与失败候选集合不变。TSP 的任务契约补充调用语义事实（逐步调用、近邻序 unvisited、末节点自动补入、重复选择中止）；契约以 Evaluation Runtime 段写明实际 Python/NumPy 版本与整次评价时限，机制同时记录运行环境版本。
3. **最多一次错误条件修复。** 候选代码提取或校验失败，或评价时产生 `exec_error`、`runtime_error`、超时、非法结果和非有限 fitness 时，在下一候选位置优先请求修复。输入为任务接口、保留原代码文本的完整失败输出，以及清除路径后最多 2000 字符的核心异常类型和消息；runtime/exec 错误附候选代码最深栈帧的行号与函数名，超时反馈保留真实时限数字并说明其覆盖整次评价批次；有父代时只展示其成绩作为比较基准。完整错误和调用栈仍存入日志。修复指令为一句话：保留原决策方法，修正报告的失败。修复输出按代码优先解析正常检查；再次失败或复制输入立即结束修复链。评价准备故障和框架异常记录后终止运行，不调用 LLM 猜测修复。

修复用新的 `candidate_id` 和 `repair_of` 关联原始候选，保留原 operator、parent 和 donor 来源。`llm_calls.jsonl` 通过 `stage=repair` 区分额外调用，并保留 token usage 与耗时。修复没有独立抽取算子或重选父代，不再次增加父节点设计机会计数；成功节点接在原有效父代下，失败候选保留在事件中，不冒充有效树节点。统计每个算子时应同时按 `repair_of` 区分原始生成与修复。

**每一次真实评价都计入 1000 次预算，包含初始失败和修复后的评价。** 解析失败不计评价，但 LLM 调用照常记录。预算已耗尽时不发起修复；不再按本地提示长度跳过修复。已知失败和修复候选均复用现有持久化、收据与恢复流程；未知评价结果继续阻断，不能据此启动修复或重复评价。

输出契约顺序中性：要求返回单个代码块中的完整实现，并附一段描述该代码所实现算法的 Idea（主要决策机制、关键计算及其如何决定输出，约 500 词内的宽松表达空间，不是写满要求或拒绝阈值）；解析器接受 Idea 前置、后置、普通正文或为空，输出契约不再把标签和位置塑造成门槛。同时要求保持目标函数签名与返回契约、补齐必要 import/helper；不保留变量先定义之类防御性提醒。没有新输出标记、JSON Schema、错误记忆库、自动补 import 或额外 smoke evaluator。

依据：V10.9 错误快照中有 144 次解析失败和 203 次评价失败；V9.16的历史修复恢复过 810/929 个初始失败，但含额外评价成本，不能直接视为同预算搜索提升。V10.10 复用成熟的限次报错回喂机制，并以统一真实评价预算检验其净效果。

**解析修订的冻结响应重放（2026-09-11）**：对 `20260910_v1010_formal` 全部 15 路、22,414 条已持久化响应零 LLM 重放（脚本，报告存于本地 results/analysis/）。旧解析的 7,772 次 `invalid_output` 中，7,676 次（98.8%）新解析直接接受且代码通过语法、接口与编译校验；30 次暴露了被 "Missing Idea" 掩盖的真实代码错误（语法/接口）；66 次仍为不可恢复的提取问题（无/多代码块、截断）。14,641 次新旧均接受的响应代码文本完全一致（零差异），新解析对任何旧有效输出零回归。已接受响应的说明来源：tagged 18,078 / prose 2,620 / missing 1,620。重放只证明解析回收，不证明这些程序运行成功或搜索成绩提升；实际收益需新批次检验。

## 研究出发点

自动算法设计的目标，是在有限评价预算内发现并开发真正改善求解行为的算法。程序当前的分数只说明其当前实现的效果；一个整体较差的程序可能含有可迁移的好部件，一个尚未调好的结构可能提供后续开发空间。形成思想、借鉴部件与数值精炼因此需要交织进行。

历史强结果呈现出互补的路径：TSP V9.14 通过内部求解结构的变化打开空间；CVRP V9.7 长时间开发几何、容量和参数关系；MCTS-AHD 的 OP/CVRP 用跨程序组合产生突破；CALM 的 OBP 强调保结构数值搜索；VRPTW V9.19 中先退步的迁移分支经后续修正获得收益。这些是过程证据，不能把其成绩单独归因给某个算子、某种树搜索或某段提示。

尤其是 MCTS-AHD CVRP 样本 566：两个输入 9.1767、9.9765，组合后为 8.8431；样本 857：8.8106、8.9159 组合后为 8.7302。较差整体中可有好部件，较好部件之间也能进一步形成协同。不能仅以 donor 的整体质量判断迁移价值。

V10.10 将这些经验落实到同一条决策链：**评价机会给谁 → 需要解决哪个设计问题 → 提供哪些真实试验 → 生成什么改动 → 是否改变求解行为 → 是否值得继续开发**。不安排固定的“探索结束时刻”，也不把 fitness 停滞自动解释为 idea 停滞。

## V10.8 的机制缺口

详细证据与统计边界见V10.8 机制分析。该分析对应 1080 正式批的 9584 次评价快照，1081 个体调度及其 A/B/C/D 实验须分别解读。

| 现象 | 底层问题 | V10.10 对应改动 |
| --- | --- | --- |
| 后期质量分布随档案规模扩散，反复开发还会降低选择权重 | 节点数量、被选次数不能直接代表值得开发的思想数量 | 固定质量 ESS 目标 8，取消次数惩罚 |
| 353/3400 个有效 Fuse 与 donor AST 相同，其中 254 个复制更差 donor | 输入两个程序不等于有针对性的部件迁移 | 以宿主为基础借鉴有用计算，允许替换与重组，拒绝输入 AST 复制 |
| 严格仅数值修改为 119/4436 个有效 Refine | 宽泛 Refine 不保证充分数值开发 | 单列 Tune，专门执行参数设置改进 |
| 历史代码与 donor 实码反复展开导致上下文过重 | 完整事实档案不等于生成所需上下文 | 使用 Idea/operator/fitness 的统一短形成路径，完整代码保留在档案中 |

分析用 AST 去掉了文档字符串；V10.10 在线去重保留文档字符串，避免错误抹去可被程序读取的内容。两个重复率口径不可混用。

## 预算分配：按当前质量集中开发

初始化 8 个有效根节点。其后独立抽取设计任务：Refine、Tune、Fuse、Pivot 各 25%，比例在全程不变。当前证据不足以支持一套跨任务通用的偏置，因此采用中性均分，把差异交给父代选择、算子提示和实际生成结果。

父代候选集 A_t 为全部有效归档节点，质量分布为 Boltzmann 形式 `q_i = exp[β(f_i − f_max)] / Σ_j exp[β(f_j − f_max)]`。β 不是人工调节的超参数，而是每步按当前 fitness 分布求解的尺度自适应系数，使 `ESS(q) ≈ min(N, 8)`；对 fitness 做正仿射变换（乘正数、加常数）不改变 q。所有内部 fitness 均为越大越好。节点数不足 8 或最高分大量并列时使用可达到的目标。ESS=8 只控制质量分布的有效集中宽度，是当前固定的透明默认值，不声称为理论最优。

- Refine / Tune / Fuse：父代直接按 q 抽样，不施加父代被选次数惩罚。
- Pivot：`P(parent) = 0.5 q + 0.5 U`，50% uniform mixture 是固定的全局探索比例，同样不声称为最优超参数。

`parent_selection_counts` 仅记录各节点实际被开发次数，不参与当前选择概率；日志保留它是为了离线分析开发频次。删除 recent 候选池及其 20% 混合概率、64 次评价窗口、2 次请求门槛。新节点与其他节点按同一规则竞争，不因新出生、结构变化或尚未开发而获得额外优待。AST 仅用于识别输入复制，不在线计算修改类别。父代资格不要求通过各算子的提示容量检查。

## 初始化：Sequential informed initialization

保持 8 个有效根目标。第一个根只看任务接口独立生成；从第二个根起，生成上下文按生成顺序依次包含已评价的全部已有根的归档原始代码（不做任何视图清洗）与实测 fitness，模型据此再提出一个有竞争力的候选。这是初始化的完整机制：existing programs + fitness → next program。

fitness 只作为已有候选的实测表现进入生成上下文，不承担其他初始化控制功能。已有根按生成顺序完整展示，一次组装后检查完整输入容量，已选提示随候选持久化；超容时明确报错，不筛选或截断候选。

初始化不做任何重复规避：不比较已有根的 AST，不按 fitness 判断重复，不筛选展示的候选；生成结果按正常有效性解析与评价流程处理。生成完成后直接进入正常搜索，不设 bootstrap 或额外开发阶段，后续开发由原有 Refine、Tune、Fuse、Pivot 完成。此机制对所有任务一致，不注入任务专属种子或历史优胜代码。相关历史证据见初始化比较。

## Fuse donor selection

从全档案中排除当前 parent 及与其 AST 相同的程序。对剩余候选重新计算 ESS-8 质量分布 q_d，按 `P(d) = 0.5 q_d + 0.5/N` 单次抽取一个 donor；无候选时本轮 Fuse 回退为 Refine。该分布仅提供质量偏置与全档案覆盖，不建模 host–donor 互补性。

## 上下文：统一短形成路径

输入不再扣除固定 16K 输出预留。每次请求的输出上限取 `min(16384, 32768 - 256 - 实际输入tokens)`，普通生成与错误修复一致；只在完整输入已没有输出空间时阻断。

正常搜索统一提供当前程序的完整归档代码（不做任何视图清洗）、实测 fitness 和近期形成路径。形成路径沿真实父指针提取，按从旧到新展示，每步为该步生成算法的 Idea 描述、所用算子及前后 fitness；Idea 是生成时对算法的描述，不是经核验的代码差分或因果解释。默认保留最近八条形成边（`traj_gens=8`），八是沿用早期轻量来路深度的透明默认值，不声称为最优。Fuse 额外提供本轮 donor 的完整代码与成绩。完整历史代码、diff 与来源关系保留在搜索档案中，生成上下文不展开祖先代码、diff 或历史 donor。

| 操作 | 算法材料 |
| --- | --- |
| Refine / Tune / Pivot | 当前完整代码、成绩、短形成路径 |
| Fuse | 当前完整代码、成绩、短形成路径，加本轮 donor 的完整代码与成绩 |

组装顺序固定为任务接口、当前程序（Fuse 中标题为 Host Algorithm，其余为 Current Algorithm）、当前算法的形成路径、donor（仅 Fuse，标题 Donor Algorithm）、算子指令、输出契约；一次组装后检查聊天输入总容量，超容明确报错，不自动丢材料或重选 donor。根节点无形成边时自然没有历史段。`context_best_fitness` 取提示中真正出现的评分的最大值。当前节点的直接子代尝试保存在档案中但不进入其形成路径。OP 任务继续通用读取任务提供的 evaluator 设计说明，不按任务名称追加专用提示。

依据（静态验收，2026-09-11）：取 `20260910_v1010_formal` 三个运行（OP/CVRP rep2/VRPTW rep1 各 150 个真实选择情境）重建新旧提示并以真实 tokenizer 计数：Fuse 中位数 14.3–19.9K 降至 4.3–5.5K，Refine 10.1–13.9K 降至约 3–3.7K，Tune/Pivot 因新增八步历史增加约 1–1.4K；全部 450 个提示的最大值从 29,184 降至 7,581 tokens。上下文更短可直接确认；生成与最终搜索收益需实验确认。

## 算子各司其职，又允许形成与精炼交织

| 算子 | 要回答的设计问题 | 修改边界 |
| --- | --- | --- |
| Init | 在已有方法及其实测表现之后，还能提出什么有竞争力的决策方法？ | 首根独立生成，后续根参考全部已有根的实码与成绩 |
| Pivot | 当前假设之外，什么决策方法值得试？ | 结合任务、当前算法与形成路径，提出围绕不同主要决策机制的替代方法 |
| Fuse | donor 的哪些计算能弥补宿主的哪个不足？ | 识别宿主不足与 donor 计算的对应关系，定向迁移整合为以宿主为中心的连贯算法，目标超过两个输入 |
| Refine | 当前设计最值得继续开发的是什么？ | 基于代码与形成路径找到最有价值的下一步改进，作为一个连贯精炼实现 |
| Tune | 哪些参数关系真正影响决策？ | 保留决策方法与计算结构，校准一组有影响力的系数、阈值、指数或调度 |

算子指令按"设计对象 + 认知操作 + 结果目标"三要素书写，全部为正向动作，不要求输出分析过程，也不含"donor 无用可不融合"之类的防御性出口——host-only 的有效改进仍可入档，但提示职责是尽量促成真正的融合。

Tune 是专门的参数改进任务。删除在线 `edit_kind` 分类和数值 AST 归一化；原始输出及有效节点代码继续保存，需要时离线分析修改类型。解析结果、解析方式与错误原因在本次候选内复用，不为写日志重新解析。

搜索请求在线拒绝与父代或 donor AST 完全相同的输出，不花评价预算；注释和格式变化不能绕过该检查，初始化请求不做该检查。保留原有连续 50 次不可评价输出熔断，LLM 成本单独记录。没有全档案语义去重，也不会声称已杜绝所有无效计算。

## 评价与可复核性

每路 1000 次真实评价包含初始化、评价失败和修复后的评价。LLM 失败、解析失败与输入复制不占评价次数，但记录其调用和时间。沿用已有持久化候选、评价收据、未知评价阻断与恢复规则；版本 10100 的机制、源码与采样参数必须一致才能恢复；后端等价，地址及服务模型名称可随空槽分配同步更新。V10.10 使用独立目录与检查点，不能拼接 V10.9 的实验进度。

本次 15 路检验的是完整 V10.10 系统，不足以独立识别各因素收益。与 V10.8、历史强结果比较时，应按相同真实评价预算对齐 best-so-far 曲线、最终质量和三次重复；历史额外修复评价、固定初始程序与算法运行耗时须注明；当前后端按等价服务处理。跨任务 SOTA 目标需要进一步同条件比较和未知实例/跨规模验证，不能用训练面板单次最好分宣布达成。

重点检查：好结构何时到达、后续获得多少请求及延迟收益；Fuse 是否复制输入、是否真迁移部件以及是否超双亲；Tune 实际动作与增益；每次评价的求解耗时和 LLM 成本。若只增加结构变化而未带来后续收益，或只增加数值修改率而终局变差，应修正机制，不把中间指标当成功。
