# TraceAAD 机制设计演进

TraceAAD 的版本演进围绕一个问题展开：如何把有限评价预算和已经发生的算法试验转化为下一次更有效的设计决策。

## 当前主线

V11.0 在 V10.11 generic 基础上推进两个机制：

- 预算分配从节点级 ESS 质量抽样转向唯一代码的质量百分位与有限探索分数；
- Pivot/Fuse 从单一父代形成上下文转向最多 8 个参考节点的 Idea 与实测适应度。

Refine/Tune、四算子均分、单亲搜索树、任务契约、一次有界修复和真实评价预算保持一致，并加入断点恢复契约。V11.0 正式实验显示，全档案精英参考在 CVRP-ACO 上形成稳定收益，其他任务呈现不同的历史偏好，当前主线由统一历史模板转向任务条件化证据组织。

## 演进阶段

| 阶段 | 版本 | 研究推进 |
|---|---|---|
| 基础搜索 | V1–V8 | 建立候选生成、真实评价、树结构和持久化闭环 |
| 形成轨迹 | V9.0–V9.22 | 研究父代关系、连续开发、算子分工和行为反馈 |
| 生成协议 | V10.0–V10.6 | 收束 Idea/Code 契约，建立代码优先解析、摘要对齐和有界修复 |
| 轨迹条件生成 | V10.7–V10.10 | 精简上下文，验证短形成路径、算子意图和有限预算下的持续改进 |
| 经验组织 | V10.11–V11.0 | 比较形成轨迹、随机档案、代码历史与精英传播，建立任务收益结构 |

## 版本文档的阅读口径

每个版本文档只定义该版本的机制、预算和可观测行为。最终质量以相同真实评价预算下的重复均值和 held-out 结果为准；事件日志、错误类型、参考来源和开发深度用于说明机制如何运行。

## 研究记忆点

版本演进不是功能堆叠，而是把生成上下文、搜索调度和行为证据逐步分离，再重新建立它们之间的可检验关系。V11.0 的核心推进是把“历史是否有用”具体化为“哪类任务状态需要哪类历史证据”。
