# TraceAAD V10.7 机制设计

## 1. 目标与版本

原 V10.7 的目标是在有限真实评价预算下，通过少量跨质量程序对照帮助生成更强算法。该配置默认模式为 `sampled_trajectory_v1`；单次输出 Idea → Code，没有独立校准或后置摘要。完整代码与真实 fitness 为主要依据，Idea 是设计陈述。

历史讨论原文保留此前方案和审查前的实现记录，本页为当前规范。运行说明提供命令。

## 2. 档案与树

从头生成 8 个有效根，初始化评价计入预算。每次只生成一个候选。所有有限有效 fitness 的程序入档，包括退步、持平与重复代码。保留单父树及 donor 引用，最终返回全档案最高 fitness 程序。长程序仍在档案，不因提示放不下删除。

## 3. 父代分配

沿用 V10.6 的质量 ESS 校准与按 node ID 的选择次数修正，先选父再按等价条件分布选算子。请求比例 Refine/Pivot/Fuse = 0.50/0.15/0.35。不增加保活、潜力估计、停滞触发或新颖奖励。参考曝光不增加父代次数。

重复代码产生新 node ID 时仍拥有独立次数，本轮不改变分配。实验分析应同时统计按节点与按完全相同代码汇总的父代选择集中度。

## 4. 上下文采样

候选来自请求前已完成评价的全档案，fitness 必须有限。不要求登顶、超父、特定算子或跨血缘。排除与底座相同的代码；同代码的多条记录均匀选一条完整真实记录，不拼接 Idea 与 fitness。

在去重后的全部候选上，按真实 fitness 的线性插值 1/3、2/3 分位数分 low/middle/high。等于边界归较低层，同分不拆层。此时不做全档案精确 token 预筛。

每份参考先均匀选非空层，再在层内均匀选程序；后续参考优先未使用的层。抽中后才检查完整组合是否可容纳。容量失败在同层无放回重试，层耗尽再换层，每个位置最多 32 次；达到上限就减少参考数量。默认最多三份程序，包括底座。不存在扫描全档案并逐候选请求 tokenizer 的预筛。

Init 保持从头生成，不采参考。均匀对照在同样的去重候选上直接均匀抽程序，其余容量、格式和算子规则完全一致。

## 5. 算子

- Refine：明确指定底座的 Algorithm 序号，沿其主要思路改进，可借鉴其它程序。
- Pivot：所有程序作为已知材料，设计替代主要思路，不绑定继承某个底座。
- Fuse：以选中父代与采到参考中 fitness 最高者为主输入，其它参考作辅助；并列按较小 ID 选 donor。允许同血缘。不要求贡献比例或超双亲才入档。
- Fuse 没有可用的不同代码参考时回退 Refine，父代不变，不重抽候选。

## 6. Prompt 与容量

展示顺序按内部 higher-is-better fitness 从低到高排列，并列按 ID。Prompt 每份只含 Algorithm 序号、Fitness、Idea、完整原始 Code。不显示来源 ID、血缘、创建算子或虚构前后版本关系。排序不更换指定父代。原祖先历史区不叠加。

Idea 输出要求不超过 100 words；原始 Idea 完整入档。提示视图最多 256 实际 tokens，超过时整段省略；若组合仍超限，进一步省略各程序 Idea，再精确计数。完整代码始终保留，长 Idea 不得单独剥夺父代资格。该视图规则对父代和参考相同。

默认窗口 32768、输出预留 16384、安全余量 256，完整输入最多 16128 tokens。最终采用服务端精确 chat token 计数；不会再调用模型压缩，也不会截断代码。父代资格依据完整代码与必要指令是否可放入。

## 7. 生成与评价

单次 Idea → Code；复用原解析、接口与编译检查，正式评价原始归档模块。生成失败不占评价预算，正式评价失败和超时占预算。完整闭合代码在 length 结束时仍按原规则处理。没有第二次校准、行为探针或自动修复。

## 8. 日志、预算与恢复

每路 1000 次真实评价，五任务各三次重复，seed=0/1/2。采样只增加输入与计数成本，不新增评价机会。

记录 context_policy、context_node_ids（展示顺序）、实际程序数与每程序 tokens、父代/donor 序号、质量边界和层、尝试与拒绝、参考不足数量、完整 prompt_tokens，以及 sampling_seconds、scheduling_seconds、tokenizer_requests。后者是计数接口调用数（缓存未命中），不包含客户端内部 HTTP 重试或 apply-template 子请求；实际耗时见 tokenizer_calls.jsonl。llm_seconds 与 eval_seconds 分别记录生成和评价时间。

选定材料、Prompt、RNG 在请求前共同持久化。恢复复用原 Prompt，不重新采样；未知评价保留占位并阻止重复调用。源码及配置不一致时拒绝恢复旧检查点。

## 9. 配置与比较

| 模式 | 行为 |
| --- | --- |
| ancestor_history | 原 V10.7 单次调用＋祖先历史基线 |
| uniform_trajectory_v1 | 全档案均匀采样、有界容量检查 |
| sampled_trajectory_v1 | 默认，全档案质量分层采样、有界容量检查 |

max_context_programs 默认 3。traj_gens=8、history_tokens=8192、donor_topk=5 只控制祖先模式，不作为新模式容量参数。单路和批量入口显式记录模式，批次配置漂移时拒绝恢复。

祖先基线与采样方案同时改变材料数量、代码展示、排序、donor 与算子指令，只能检验整体方案。均匀与分层两组共享格式和其它机制，主要差别为抽样分布。搜索收益以完整搜索和 held-out 比较为准，覆盖率不作为成功指标。
