# TraceAAD V10.13-r2：代码优先、按需证据与算法互补

V10.13-r2 修复了已确认的文字拒收、探索机会偏向单一算子和恢复重复评价问题，并将上下文收敛为“当前代码 + 简短 Idea/fitness + 一次按需读取”。LLM 负责提出算法改进、判断参考思想是否有用并生成或编辑代码；搜索器负责分配机会、真实评价和保存证据。工程行为已有回归验证，算法质量尚无 r2 正式训练或 held-out 结果，不能据此承诺跨任务提升。

## 版本边界与研究问题

这是 **`v10.13-r2`**，不是运行中的 `20260923_v1013` 批次的在线补丁。旧批次使用独立冻结运行时；r2 的机制指纹、解析协议和恢复协议不同，禁止用 r2 续跑旧 checkpoint。原版定义保留在 [V10.13 机制设计](TraceAAD-V10.13-机制设计.md)，问题与历史证据保留在 [设计复审](../04-研究认识与构想/2026-09-23-V10.13设计复审与下一步机制.md)。本文是 r2 的权威机制定义。

当前问题不是怎样让模型填写更完整的解释，而是：在有限真实评价预算下，怎样让有价值的算法假设得到生成、实施和后续开发机会，同时减少接口故障和与当前决策无关的信息。

本轮针对三个假设实施完整机制，不安排消融：

1. 将 Idea 与代码接受解耦，允许精确局部编辑，可减少与算法质量无关的输出损耗。代码进入 evaluator 才是验证起点，解析成功本身不是质量证据。
2. 固定总探索量，但让所有算子都能访问探索父代，可避免非精英只能被要求 Pivot 的耦合。是否改善弱父代的开发价值仍待观察。
3. 将候选参考的广泛展示与 LLM 的互补判断分开，并让完整参考实现按需出现，可能比强制随机 donor 或全算子默认堆卡片更有效。轻量摘要也可能误导；这是待检验假设。

## 预算与机会分配

沿用现有任务说明、模板、数据、种子、安全评价器和结果格式，不修改任务契约。默认每路 E1000，目标 8 个有效初始化节点；初始化、评价失败、超时、重复代码和修复后的真实评价均占同一预算。格式失败和上下文读取不占 evaluator 预算，但消耗 LLM 调用、token 和时间，必须单独报告。

有效节点全部进入 archive。四算子 Refine、Tune、Pivot、Fuse 各 25%，不因早期偶然成功自动关停某种操作。继续使用原始 higher-is-better fitness 校准质量 softmax，使可达的有效样本量接近 8：

\[
q_i=\frac{\exp(\beta(f_i-f_{\max}))}{\sum_j\exp(\beta(f_j-f_{\max}))},
\qquad \operatorname{ESS}(q)=1/\sum_iq_i^2\approx\min(8,|A|).
\]

每个算子都按同一个分布抽 parent：

\[
p_i=0.875q_i+0.125/|A|.
\]

原版三个算子用 q、Pivot 用 0.5q+0.5U，在算子均分时边际分布也是 0.875q+0.125U。r2 保留这一总探索质量，把探索机会从 Pivot 独占改为与算子独立；不增加“先 Pivot 后强制 Refine”等继续开发规则。每次正常开发只计一次 parent opportunity，额外读取和修复均不重新抽父代。修复有独立 candidate_id，通过 repair_of 关联原候选。

这仍然是质量优先分配，不是已解决的后代价值预测；archive 中多个相同程序仍各自拥有父代概率。独立 island、基于语义簇的预算和 learned value 不在本轮范围内。

## 提示：提出算法动作，减少填表负担

所有提示保留完整任务与当前父代代码。共同证据说明仅强调：fitness 测量整个程序；Idea 是作者描述；缺失描述意味着未知；有效改进应进入实际返回结果的计算。不会要求输出推理链、机制证明或完整行为审计。

| 算子 | 提示要完成的算法动作 | 默认新增材料 | 一次可选读取 |
|---|---|---|---|
| Init | 从任务结构和算法知识提出有竞争力的初始设计；已有样例用于寻找另一个有潜力的假设 | 容量允许时保留先前有效 root 的完整代码、Idea/fitness | 无 |
| Refine | 改进剩余问题表示、候选比较或组件协调，保留仍有用的计算 | 最近至多 3 条形成边的 Idea/fitness | 同一父代的至多 2 条局部试验摘要 |
| Tune | 校准影响决策/采样的参数、阈值、权重和调度，可考虑交互与状态依赖 | 最近至多 3 条形成边的 Idea/fitness | 同一父代的至多 2 条摘要，已有 Tune 子代时优先只看它们 |
| Pivot | 重新考虑主要假设，从表示、决策规则或搜索组织上提出竞争性替代设计 | 至多 3 张不按分数排序的参考思想卡 | 自选其中 1 份完整实现 |
| Fuse | 寻找能弥补 host 弱点的参考计算，协调尺度、假设和组件作用，目标是超过双亲 | 同上 | 同上 |

Refine/Tune 可 edit 也可完整重写。Pivot 不以新颖性本身为目标。Fuse 不强制混合：如果没有参考有用，可以直接改进 host。提示明确要求按思想互补性选择，而不是只按最高 fitness 选取。完整英文运行提示只有一个权威来源：[prompts.py](../../traceaad/v10_13/prompts.py)；输出接口见 [parsing.py](../../traceaad/v10_13/parsing.py)。

不同算子不同上下文有合理用途基础，但表中的映射不是已经证实的跨任务最优配置。特别是 Tune 是否也需要形成历史、Pivot 是否需要任何参考，仍有不确定性；本轮先实现用户认可的完整机制。

## 上下文取舍：不给未经组织的历史 diff

**历史默认只提供作者 Idea 与系统测量的 fitness，以及解释这些记录必需的节点/形成关系。** 不附原始历史 diff、冗长运行日志、父代热度、路线排名或伪语义距离。当前完整代码始终是实际实施锚点。

Idea+fitness 的好处是紧凑，不是“绝不会错”：描述可能没有落实到代码，fitness 也不能证明某个组件导致提升。因此不从一次成败提炼禁用规则，不把 donor 整体高分解释为每个组件都有价值。

Refine/Tune 可以返回 `{"mode":"context","trials":true}`。读取对象仅是当前 parent 的已评价直接子代：一条分数最高且超父的试验，以及一条时间最新且未超父的试验；两类不存在时不伪造记录。Tune 若有 Tune 子代则优先在该子集中选择。返回节点关系、算子、前后 fitness 和短 Idea，不返回子代代码或 diff。没有有效子代会明确提示空记录。

这份笔记不是完整试验史，也不包含运行失败候选的诊断材料；只能帮助模型知道“哪些改动曾被提出、整体结果如何”，不能确认代码实际只改变了哪一项。模型仍可不读、不同意描述或再次尝试相似思想。V10.9 已做过局部试验记忆，r2 的区别在于按需、少量、用途限定，不能称为首次发明。

最多一次读取，不增加无限 agent 规划/工具循环。第二次 LLM 请求读取会进入有界格式修复，而不是继续追加上下文。Init 和修复只提交完整实现。模型输出 edit 中的 search/replacement 是**新代码的精确编辑指令**，与向模型提供历史 diff 是两件事。

上下文上限默认 24,320 input tokens，输出上限 8,192，总上下文保留 256 token 余量。超限时依次删除最旧形成边、局部试验、参考卡、所请求的参考完整程序；整个程序作为单位移除并记录原因，不截断代码。任务、当前父代和输出协议放不下时明确失败，不擅改任务。初始化从最早完整样例开始移除。Idea 展示每字段最多 280 字符，旧文本最多 480 字符，并标明缩短；完整原始响应与元数据仍保存。

## Donor：广泛展示，模型判断互补性

搜索器不声称能够可靠分类通用算法。候选池只排除与 host 完全相同的 AST，并合并参考池内完全相同的实现；相同实现取最新一次已评价代表，不选最高测量值。AST 仅用于排除精确代码重复，不作为语义距离或行为类别。

依次不放回抽取最多三张思想卡，再随机打乱展示顺序：

1. 按 ESS 质量分布抽一张，保留有效经验。
2. 对剩余实现均匀抽一张，使中低分思想仍能出现。
3. 对剩余实现按 `1/(1+exposure)` 抽一张，减少总是展示相同程序；exposure 是该精确实现所有副本的累计展示次数。

只为实际进入首轮提示的卡片增加 exposure，不把曝光少当成质量高。候选生成模型依据 host 代码、参考 mechanism/change/transfer 与实测 fitness，自行判断哪个计算值得借鉴。需要实现细节时返回 `{"mode":"context","reference_id":ID}`，下一轮只新增所选一份完整程序。它也可以只从 Idea 得到启发，或者不使用任何参考。

这是一种**语义判断由 LLM 完成的候选筛选接口**，不是已验证的语义检索器。未进入三张卡的互补算法仍可能被漏掉；缺失/不准确的 Idea 也会影响判断。不会根据卡片来自哪个抽样源在提示中暗示优劣。

日志区分 reference_ids（曾提供的候选卡）、loaded_reference_id（实际提供的完整实现）、donor_id（模型最终声明采用的参考）。读取不等于采用，声明采用也不是因果迁移证明。修复后的声明重新读取，缺失时不沿用旧声明制造归因。后续应同时看超父、超声明 donor、超双亲、超当时前沿及 held-out；超父率不能代表创造性组合。

## 轻量结构化输出与 edit mode

结构化的是可执行接口，Idea 不设硬性长度或必填门槛。模型可以只返回：

```json
{"mode":"full","code":"def score(x):\n    return x"}
```

可选 `idea` 是短文本，或只写有信息的几个字段：

```json
{
  "mechanism": "程序主要依据什么进行决策",
  "change": "相对本轮父代改变什么计算",
  "transfer": "其中什么计算可能被其他设计借用"
}
```

三项均建议一句话；没有信息就不写。无需复杂参数表、标签体系、置信度、证明或额外摘要调用。原始 Idea 超长、字段缺失或类型异常不拒收有效代码；不让 LLM 填 fitness。`donor_id` 也是可选字段，只有本轮提供过的整型节点 ID 才进入声明记录。

edit 示例：

```json
{
  "mode": "edit",
  "base_hash": "提示中的当前父代 SHA256",
  "edits": [{"search": "return x + 1", "replacement": "return x + 2"}],
  "idea": {"change": "调整会影响后续决策的偏置"}
}
```

要求 1–32 个顺序替换，每个 search 非空、在当前版本文本中精确匹配一次，包含空白；base_hash 必须对应完整父代。补丁应用后检查目标函数、接口、同步函数、语法和模块编译，再交 evaluator。edit 不重插模板语句，不移动顶层代码。full 沿用既有模板依赖合并逻辑；它仍不是任意 Python 模块语义的完备保持器，生成代码是否满足任务以真实评价为准。

保留旧 Idea+Python 代码块和纯代码输出的解析兼容。当前实现是 **JSON 提示约定 + 本地严格执行字段检查 + 有界修复**，没有要求服务端支持 JSON Schema，也不声称已实现约束解码。这样可以复用当前模型服务；若将来启用服务端 schema，应独立冻结请求配置和核对后端兼容性。

一个失败候选最多修复一次，保留 parent/operator 和 opportunity 归属，修复只返回 full，不再请求上下文。能重建的失败程序直接送回完整程序和错误；补丁应用失败才带完整 edit base 和编辑请求。可选 Idea 不挤占修复提示，不截断程序。未知评价基础设施故障阻断，不通过 LLM 修复掩盖。

## 持久化与真实预算

流程是 `scheduled → generated → parsed → evaluating → evaluated → committing → clear`。读取会回到新的 scheduled 调用，但沿用候选和父代机会。LLM call_id 在调用前保存，已落盘响应在恢复后复用。

在调用 evaluator 前，先保存唯一 evaluation_id 和预算预约；返回结果先追加并同步 `evaluations.jsonl` 回执，再保存 evaluated。节点/事件随 committing checkpoint 保存，随后通过唯一 ID 幂等投影到 `nodes.jsonl` 和 `events.jsonl`。恢复时核对指纹、预算、完整记录集合和映射关系。独占 writer lock 防止同一路有两个写者；截断的 journal 尾部先另存 `.torn-*` 保留证据。

**外部评价调用不能仅靠本地文件实现无条件 exactly-once。** 若 checkpoint 显示 evaluating 且回执缺失，可能是尚未调用，也可能已经调用但结果未落盘。程序标记 `uncertain_evaluation` 并阻止自动重评，预约预算保留，启动器标记 blocked。需要结合运行记录人工判定；不能悄悄释放预算或重新评价。在没有崩溃歧义的正常运行中预算就是实际 evaluator 次数。

一次上下文读取会多用一轮 LLM。`llm_calls.jsonl` 保存每轮 prompt/response、call_id、context_round、usage 和耗时；event 的 llm_seconds 汇总该候选所有已落盘调用，recorded_llm_calls 与预约 llm_calls 分开。服务端已执行但未留下响应的调用成本可能未知，不把它估作零。比较 r1/r2 时，同 E1000 之外也要报告实际 LLM 调用、已报告 token、耗时和歧义状态。

## 验证、未做事项与下一步

代码、提示、抽样、edit 语义、一次读取、一次修复及崩溃恢复由 [方法测试](../../tests/method/test_traceaad_v1013.py) 验证；[启动测试](../../tests/experiments/test_traceaad_v1013_launch.py) 检查批次分配和不确定评价阻断。测试使用假 LLM/小型评价器和临时目录，不消耗正式实验预算。故障注入覆盖调用/评价回执/节点/事件写后中断及阶段 checkpoint，另覆盖第二轮上下文响应恢复。它们证明协议行为，不证明搜索质量。

本轮未启动 r2 正式批次，未触碰旧批次的冻结机制、进程或任务契约。后续完整比较继续复用五任务、4 个种子重复、每路 E1000、既有 held-out 方案和 `experiments/infra/evaluate.py`；不在批次中途修改机制。达到预算停止；基础设施故障或无回执评价阻断并保留逐路缺失，不用不完整批次提前排名。

下一步能改变研究选择的证据是：

- 同预算重复结果与 held-out 是否改善；没有改善就不能用解析率提升声称成功。
- 局部读取后是否产生超过父代、并被后续继续开发的候选；读取率或重复 prompt 减少本身不是收益。
- Fuse 是否超过双亲和前沿；只有超父则更可能是在传播已有好机制。
- edit 是否保住预期修改并减少实施错误，而非只缩短文本；full 始终是合法退路。

**后续研究记录：LLM 结构发现 + 数值校准。** 设想由 LLM 产生连贯算法结构与少量可调参数，再用独立数值搜索校准。尚需解决哪些参数真正改变行为、参数域/条件依赖、评价预算如何共享及跨实例过拟合；本轮未加入参数提取器、优化器或相关预算路由。

**独立搜索空间不必先分类。** 多个独立种群、不同随机种子和有限迁移即可保护“不会立刻互相挤占”的搜索机会，但不保证它们最终学到不同算法。保护机会与测量语义/行为多样性是不同问题。通用算法分类目前没有可靠依据，r2 不用 lineage、AST 距离或自述标签冒充类别，也未实现 islands。
