# V10.13 设计演进

V10.13 的修订集中在减少生成接口负担，让已有局部试验与可执行参考直接服务于算法改写。r1、r2、r3 是不同批次的历史设计；当前机制见[r3 定义](TraceAAD-V10.13-r3-机制设计.md)与[讨论清单](../04-研究认识与构想/2026-09-24-V10.13机制清单.md)。

## r1：回到程序、质量与算子

r1 将形成树用于保存来源，以 ESS-8 质量分布选择程序，由 Refine、Tune、Pivot、Fuse 提出不同改进。它移除了路线语义分群和行为审计表，模型输出 Idea 与完整代码。

设计复审发现，文字接受门槛可能拒收可运行代码；探索父代主要与 Pivot 绑定；恢复流程也存在重复评价风险。下一次修订因此同时处理输出接受、各算子的探索机会及候选持久化。

原批次为 `20260923_v1013`，对应运行时 `experiments/traceaad_v10_13/results/runtime_20260923_v1013/`。

## r2：代码优先、按需读取与编辑

r2 采用四算子各 25%、8 个有效初始根、每路 1000 次评价预算。保持 ESS-8 质量分布，将均匀探索机会分给各算子，Idea 与代码接受解耦。模型可以输出完整代码、精确编辑，或先请求一次局部试验/参考实现，再完成候选。

这种设计希望让模型判断需要什么材料，但动作 JSON、额外字段和往返读取增加了格式成本。候选持久化则将生成、预约、评价回执和状态投影分开，使恢复能够依据已有事实继续。

### 早期诊断（partial，2026-09-24 01:22:11）

固定快照包含 2471 个候选事件：1726 个有效、638 个解析拒收、107 个评价失败。解析拒收占 25.82%；进入评价的候选中失败占 5.84%。主要问题之一是可执行程序被外层协议拒收。

对旧响应离线重放时，1726 个原有效程序的代码全部一致，另有 323 次旧拒收变得可解析，315 次仍拒收。这个结果直接支持放宽代码提取；新增可解析程序未重新评价，质量仍未测量。

## r3：材料直接给出，默认输出 Python

r3 取消额外读取回合。Refine/Tune 直接读取已有局部试验摘要；Pivot 只看当前程序；Fuse 使用一份完整参考，按 50% 质量、50% 均匀选择。默认输出单 Python 块和可选一句 Idea，仍允许宿主绑定父代的唯一精确编辑。四算子概率、父代分布和评价任务沿用 r2。

修订时原有验证记录为 350 项测试通过；离线重放和启动预检分别保存在 `review_r3_20260924/`。这些记录对应当时的修订，本次文档整理没有重新运行实验。

### 批次衔接与早期观察（partial）

r2 批次 `20260924_v1013r2` 于 2026-09-24 01:43:49 按用户要求停止，结果保留。停止时 CVRP rep1/2/3/4 与 OBP rep2 各有一次 evaluating 预约未收到完整回执，共 5 次；它们保留 pending 状态。

r3 批次 `20260924_v1013r3` 在 01:44 启动，五任务×四重复、seed 0–3，每路 E1000，8 个有效根，输入/输出 token 上限 24320/8192。01:47:53 快照记录 130 次模型调用与 130 次有效评价：Init112、Fuse7、Pivot4、Tune3、Refine4，full127/edit3，无拒收、评价失败和修复；已出现一次 inline trial。

早期接口运行顺畅，同时也出现编辑后 AST 不变或读取参考后同分的候选。下一步应比较相同完成评价预算下的质量、后续开发及调用成本，而不能仅依据早期有效率判断算法收益。后续观察集中在[V10.13 实验观察](../02-实验结果/2026-09-24-V10.13实验观察.md)。
