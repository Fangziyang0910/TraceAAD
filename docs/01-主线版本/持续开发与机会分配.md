# 持续开发与机会分配：V9.14–V9.22

这一阶段围绕一个问题展开：当前质量、已发生的改善和未来开发机会应该怎样联系？质量集中可以支持深度精炼，发展窗口可以观察初生结构，但额外统计和保护规则只有真正改变机会分布才有价值。

## V9.14–V9.15：程序质量与轨迹发展态

V9.14 采用单父算法树、8 个有效根、Refine/Explore=0.7/0.3，以及最近 8 条父代来时路。候选评价后立即更新，节点保存实测质量与直接开发次数，形成树负责追踪来源。

V9.15 在质量分数上加入初生保护与历史增长信号，并以 ESS 控制抽样范围。诊断显示轨迹增长项广泛改变父代排序，初生保护对实际选择作用较小；best 深度由约 77–115 降至 13–22，任务收益出现分化。过去增长是已兑现的响应，下一次改写的收益还取决于当前代码和生成条件。因而“增长快”适合作为待检验状态，直接将其加到质量上需要检查实际分配。

## V9.16：给 Explore 子代三步发展

V9.16 保持 Refine/Explore=0.7/0.3，对有效 Explore 子代随机提供连续三步 Refine。entry 只记录来源；它帮助统计投入与后续结果，不承担算法类别识别。

当质量 ESS 随 `max(0.1N,2)` 增长时，后期竞争范围不断扩大。所分析的 456 次 landing 使用 1368 个 primary slots；415 个初生退步入口中，45 个恢复来源水平，23 个超过来源父代。三步发展能修复一部分候选，但最终最好程序并未直接来自这些 landing。

由此更值得问：能否挑出更有希望的入口，或者把固定三步换成依据实际响应延续？历史批次的 primary slot 与 repair 计数保留在原始工件，现代预算规则见统一规范。

## V9.17–V9.18：发展块与原子机会

V9.17 组织 Discovery→Maturation→Competition→Development→Reopening。方向已达到的质量 Q 决定是否进入竞争，固定发展块增益 g 决定是否继续；两者分别承担准入和延续。该设计能清楚观察一个方向的发展，却也减少了新入口覆盖，续段效果随任务变化。

V9.18 回到每次评价后重新选择，在质量分数上加入短暂机会项，并另设 Global-Facts-Lite Explore 上下文。`q-atomic` 与 `q+O-atomic` 比较机会项，随后再讨论全局事实。这个拆分让预算分配与提示信息各自成为可研究的变量。

相关实验保留为[自适应调度消融](../03-机制验证/02-搜索调度与预算分配/2026-08-24-V9.17自适应调度消融/README.md)与[机会评分消融](../03-机制验证/02-搜索调度与预算分配/2026-08-25-V9.18机会评分消融/README.md)。

## V9.19–V9.20：机会与辅助生成分工

这一阶段曾将执行行为距离用于在线覆盖与参考检索，随后研究重心转向更简洁的机会分配与条件生成。保留下来的有用分工是：控制器决定从哪个已测程序继续，生成环节决定采取 Develop、Explore 或 Crossover，并组织相应材料。行为分析的旧专题已清理，不再作为当前设计入口。

## V9.21–V9.22：思想假设与不同实现

V9.21 从同一状态提出 continue 和 branch 两个思想，每个思想独立生成两份代码，形成 `2 ideas × 2 realizations`。四份实现都评价，候选间没有中途上下文传递。这使“思想是否值得发展”与“某一次实现是否成功”得到初步区分。

首跑暴露了固定 root-MAD 质量归一化饱和，以及 working implementation 与 stable scaffold 基准不一致的问题。V9.22 改用动态 scaffold mid-rank，分别记录相对当前实现和稳定脚手架的响应，并以 action UCB 分配 continue/branch。这个修订强调：质量尺度、比较基准和动作信用会直接改变下一次机会。

## 阶段认识

发展的成本应与其最终带来的前沿收益一起判断。对 TraceAAD，简洁的起点是质量抽样加少量明确的探索机会；有了实际响应后，再决定是否引入发展块、共享信用或思想级统计。优先比较入口选择与续段，而非一次性叠加多个潜力分数。

成绩见[历史版本结果](../02-实验结果/各版本实验记录/历史版本-实验结果.md)，后续简化见[生成协议与上下文演进](生成协议与上下文演进.md)。

## 历史配置摘录

以下参数对应各自版本，便于阅读旧结果；当前规则见当前机制定义。

### V9.15

#### 5.1 四机制因果正交表

| 机制组件 | 输入信息 | 作用目标 | 因果职责 |
| :--- | :--- | :--- | :--- |
| **真实质量 $q(a)$** | 历史评价表现 | 整体基准质量 | 保证成熟最优解的确定性利用 (Exploitation) |
| **初生保护 $B(a, o)$** | 父代质量 $q(p)$、Refine 次数 $n_R$、任务尺度 $s_t$ | 初生 Explore 节点 | 给 Explore 新节点有界限、快衰减的生存宽限 |
| **轨迹延续 $C_{\text{traj}}(a)$** | 祖先增益历史 $\Delta q$、头顶空间 $h(a)$ | 成长型上升分支 | 识别稳定上升期轨迹并追加投资；逼近最优时自然归零 (Investment) |
| **算子调度 $\pi(o \mid \mathcal{H})$** | 停滞步数 $n_{\text{stag}}$ | 全局生成意图 | 动态平衡深挖与跨盆地结构重探索节奏 (Intent Modulation) |
| **ESS 广度控制** | 候选池规模 $\vert\mathcal{T}_t\vert$ | 采样分布锐度 | 维持前 10% 候选池的稳定竞争广度，废除人工 UCB 加分 (Concentration Control) |

#### 5.2 核心超参数基准

| 参数 | 符号 | 基准值 | 设计依据与物理含义 |
| :--- | :---: | :---: | :--- |
| 基础探索率 | $p_0$ | $0.20$ | 前沿推进期的基准探索比例（约 80% 算力用于精炼） |
| 停滞响应窗口 | $W_{\text{stag}}$ | $50$ | 停滞反应的特征步长尺度 |
| 停滞最大增益 | $\alpha_{\text{stag}}$ | $0.30$ | 长期停滞时探索率最大提升幅度（最高达到 0.50） |
| 探索率边界 | $[p_{\min}, p_{\max}]$ | $[0.15, 0.50]$ | 保证任何时期均维持适度精炼与探索 |
| 保护跨度系数 | $\delta_t / s_t$ | $2.0$ | 最大补偿不超过 2 倍任务历史改进标准尺度 |
| 轨迹回溯窗口 | $k$ | $\min(6, \text{depth})$ | 评估局部轨迹斜率的经验窗口深度 |
| 目标采样比例 | $\rho_0$ | $0.10$ | 候选池有效采样宽度维持在前 10% |
