# TraceAAD V10.9：由轨迹支持思想形成、迁移与精炼
V10.9 将已有方法中的初始化、跨程序迁移和数值精炼统一到一条设计链，在五任务、三重复和每路 1000 次真实评价下检验完整搜索表现。

## 研究出发点

自动算法设计的目标，是在有限评价预算内发现并开发真正改善求解行为的算法。程序当前的分数只说明其当前实现的效果；一个整体较差的程序可能含有可迁移的好部件，一个尚未调好的结构可能提供后续开发空间。形成思想、借鉴部件与数值精炼因此需要交织进行。

历史强结果呈现出互补的路径：TSP V9.14 通过内部求解结构的变化打开空间；CVRP V9.7 长时间开发几何、容量和参数关系；MCTS-AHD 的 OP/CVRP 用跨程序组合产生突破；CALM 的 OBP 强调保结构数值搜索；VRPTW V9.19 中先退步的迁移分支经后续修正获得收益。这些是过程证据，不能把其成绩单独归因给某个算子、某种树搜索或某段提示。

尤其是 MCTS-AHD CVRP 样本 566：两个输入 9.1767、9.9765，组合后为 8.8431；样本 857：8.8106、8.9159 组合后为 8.7302。较差整体中可有好部件，较好部件之间也能进一步形成协同。不能仅以 donor 的整体质量判断迁移价值。

V10.9 将这些经验落实到同一条决策链：**评价机会给谁 → 需要解决哪个设计问题 → 提供哪些真实试验 → 生成什么改动 → 是否改变求解行为 → 是否值得继续开发**。不安排固定的“探索结束时刻”，也不把 fitness 停滞自动解释为 idea 停滞。

## V10.8 的机制缺口

详细证据与统计边界见V10.8 机制分析。该分析对应 1080 正式批的 9584 次评价快照，1081 个体调度及其 A/B/C/D 实验须分别解读。

| 现象 | 底层问题 | V10.9 对应改动 |
| --- | --- | --- |
| 后期质量分布随档案规模扩散，反复开发还会降低选择权重 | 节点数量、被选次数不能直接代表值得开发的思想数量 | 固定质量 ESS 目标 8，取消次数惩罚 |
| 864 个有完整观察窗的退步 Pivot，只有 50 个在随后 100 次评价内获得直接 Refine/Fuse 请求 | 新结构出生与后续开发脱节 | 给近期结构变动候选一小部分有期限的开发概率 |
| 同一最好程序多次开发失败，但形成路径保持不变 | 形成历史不能替代该底座后来的试错经验 | 当前程序的直接成败子代优先进入上下文 |
| 353/3400 个有效 Fuse 与 donor AST 相同，其中 254 个复制更差 donor | 输入两个程序不等于有针对性的部件迁移 | 保持宿主逻辑、寻找具体缺陷与对应部件，拒绝输入 AST 复制 |
| 严格仅数值修改为 119/4436 个有效 Refine | 宽泛 Refine 不保证充分数值开发 | 单列 Tune，记录请求与实际修改类别 |
| 历史 Fuse 边缺少当时 donor 的完整代码 | 只能看到变更，难以追踪部件来源 | 展示被选历史转移的 donor 实码与评价关系 |

分析用 AST 去掉了文档字符串；V10.9 在线去重保留文档字符串，避免错误抹去可被程序读取的内容。两个重复率口径不可混用。

## 预算分配：保持集中开发，并给新方向试用机会

初始化 8 个有效根节点。其后独立抽取设计任务：Refine 25%、Tune 25%、Fuse 35%、Pivot 15%。比例在全程不变。Tune 从原 Refine 的 50% 中拆出，不额外扩大局部开发的总请求份额。

质量分布为 `q_i ∝ exp(β(f_i − max f))`，调节 β 使有效样本数 ESS 尽量接近 8。所有内部 fitness 均为越大越好。数量不足或最高分大量并列时，使用可达到的目标；固定目标不代表实际只选择 8 个程序，也不保证最高分节点独占预算。

- Pivot：`p_i = 0.5 q_i + 0.5/N`，全程保留换结构和重新组合的机会。
- Refine / Tune / Fuse：通常使用 q；存在近期待开发候选时，使用 `0.8 q + 0.2 Uniform(recent)`。
- recent：距出生小于 64 次评价、被选作父代不足 2 次，且相对父代在统一数值常量后 AST 不同的节点。根节点不进入此池。计数是已完成调度的父代请求数，包含无效输出和 Pivot 请求。

这是一种有界试用，**不是潜力识别器、思想聚类或每个新节点的开发保证**。AST 只能筛掉一部分纯数值变化，仍可能把重命名误认为结构变化；调度保留其真实标识，不把它称为“发现新思想”。20% 只作用于非 Pivot 请求，因此全局请求概率中最多 17% 分配给近期试用成分；池为空时全部回到质量分布。近期优质节点也可进入池，实际开发仍由质量和试用共同决定。

选择此策略，是为了同时避免档案增长冲淡优质结构和低初分新结构立即失去机会。8、64、2、20% 均为本版冻结的研究选择，尚未证明最优；V10.8 分配消融保留独立身份，暂停后排在 V10.8 正式批与本版之后恢复。

## 初始化：让后续起点知道已有方法

保持 8 个有效根目标。第一个根依据任务接口独立生成；后续根在完整输入容量内读取已有根的代码和实测 fitness，依据真实决策规则提出另一个有竞争力的假设。允许借鉴和重新组织已有部件，要求差异体现在实际选择或搜索行为，避免只改名称、无效项或不改变决策的分数变换。提示不保证行为多样性，仍需查看实际执行行为和完整搜索收益。

优先尝试展示最新根、最早根、次新根、次早根，依次向中间收拢；真正呈现时按根的生成顺序排列。这个规则仅提供时间覆盖，不声称识别思想多样性。每个程序完整纳入或整块跳过，使用包含聊天模板的真实输入 token 检查；不按最高分筛选。记录全部已知根、实际展示根、遗漏原因和代码视图，已选提示随候选持久化。

Init 输出与任一已有根 AST 完全相同时，在评价前拒绝；保留文档字符串，同分但不同代码仍可评价。没有语义硬去重，不增加初始化评价上限，不插入每根一次的强制开发。后续开发由原有 Refine、Tune、Fuse、Pivot 完成。此机制对所有任务一致，不注入任务专属种子或历史优胜代码。相关历史证据见初始化比较。

## donor：整体质量与部件价值分开处理

候选为档案中除当前节点及其 AST 相同程序之外的所有程序，包括祖先、后代和低分程序。以 `0.5 q_donor + 0.5 Uniform` 无放回抽样，最多检查 32 个能否连同宿主完整放入上下文。没有合适 donor 时记录原因并回退 Refine。

保留低分 donor 的机会是为了获得可迁移部件；混合分布本身不宣称找到了互补部件。**相关性判断交给看到宿主、donor 和实测轨迹的生成模型**：宿主的什么缺陷值得处理，donor 的哪个计算可能处理它，以及量纲、尺度、约束和其他组件如何衔接。当前没有额外 LLM 排序调用或未经验证的相似度打分。

Fuse 明确保留宿主与无关有效逻辑，禁止整体换成 donor 或简单外包给两个完整程序的包装器；允许为了连贯适配改变相关计算。找不到有用部件时允许改进宿主，不为组合而组合。目标仍是超越两个输入，但单次未超越不等于组件无价值。

## 上下文：从“它怎样形成”到“现在该试什么”

最低输入始终包含完整任务接口、完整当前程序，以及 Fuse 的完整 donor。代码是依据；输出仍为一次调用生成自包含 Idea 和完整代码，不增加规划调用。

证据按以下优先顺序尝试装入，总证据预算 8192 tokens，并校验完整聊天输入上限：

1. 当前节点最近的一个不改善直接试验，以及最好的一个改善直接试验。Tune 优先使用请求为 Tune 的试验，然后分别按时间/成绩排序。只使用已成功评价并归档的子节点；评价异常不冒充思想失败证据。
2. Fuse donor 自身的最近一条形成边。
3. 当前节点向前最多三条形成边，先近后远。每条独立标明真实 source、target、算子和评价号，不把不相连的边拼成一条链。

每条保留完整差分或更短的完整目标代码。直接试验的源是已完整展示的当前程序；形成边额外携带完整源代码，保证独立可重建。历史 Fuse 边也提供其 donor 的完整实码。某条放不下时整条跳过并记下原因，不截断程序或差分。`context_best_fitness` 只计算真正展示的节点。

这些证据支持模型辨认有效关系、比较参数设置和重新提出假设。整体成绩不被描述成某一个改动的因果收益，也不使用未经核验的长经验摘要。OP 额外注明已核对的执行事实：仓库列始终被候选掩码屏蔽，修改 `heuristic[:, 0]` 本身不改变采样；静态先验在 ACO 前计算。它是接口执行事实，未注入历史优胜算法。

## 算子各司其职，又允许形成与精炼交织

| 算子 | 要回答的设计问题 | 修改边界 |
| --- | --- | --- |
| Init | 已有哪些方法，还值得提出什么有竞争力的决策假设？ | 首根独立生成，后续根参照已有实码；允许复用部件 |
| Pivot | 当前假设之外，什么组织结构值得试？ | 改变主决策机制，允许复用有效计算 |
| Fuse | 哪个部件能解决当前宿主的具体不足？ | 保留宿主，定向迁移并适配 |
| Refine | 这个结构中哪一个问题还没有解决好？ | 一个具体改进假设，保持无关有效计算 |
| Tune | 已有规则的哪些数值关系还没校准好？ | 提示要求仅改变少量有关数值常量 |

Tune 是专门的生成任务，不是硬性 AST 修复器。所有合法非复制程序仍按真实评价入账，所有成功解析的非初始化输出均记录 `edit_kind=same/numeric_only/structural`，包括评价失败与输入复制，用于检查是否遵循要求。严格类别不等于行为类别：改变索引常量可能改变算法行为，改变量名也会归为结构变化。后续必须把成功代码与实际求解行为一起检查。

在线拒绝与任一输入 AST 完全相同的输出，不花评价预算；注释和格式变化不能绕过该检查。保留原有连续 50 次不可评价输出熔断，LLM 成本单独记录。没有全档案语义去重，也不会声称已杜绝所有无效计算。

## 评价与可复核性

每路 1000 次真实评价包含初始化和评价失败。LLM 失败、解析失败与输入复制不占评价次数，但记录其调用和时间。沿用已有持久化候选、评价收据、未知评价阻断与恢复规则；版本 1091 的机制、源码与采样参数必须一致才能恢复；后端等价，地址及服务模型名称可随空槽分配同步更新。旧 1090 批次归档为 superseded，不能混入新版结果。

本次 15 路检验的是完整 V10.9 系统，不足以独立识别各因素收益。与 V10.8、历史强结果比较时，应按相同真实评价预算对齐 best-so-far 曲线、最终质量和三次重复；历史额外修复评价、固定初始程序与算法运行耗时须注明；当前后端按等价服务处理。跨任务 SOTA 目标需要进一步同条件比较和未知实例/跨规模验证，不能用训练面板单次最好分宣布达成。

重点检查：好结构何时到达、后续获得多少请求及延迟收益；近期候选是否被有效开发；Fuse 是否复制输入、是否真迁移部件以及是否超双亲；Tune 实际动作与增益；直接试验证据是否减少重复尝试；每次评价的求解耗时和 LLM 成本。若只增加结构变化而未带来后续收益，或只增加数值修改率而终局变差，应修正机制，不把中间指标当成功。
