# TraceAAD V11.1：固定温度的节点级机会分配与算子条件化上下文

## 设计定位

V11.1 延续 V11 的原始目标：把 V10.11 对照中观察到的上下文差异组织到不同算子中，使每种设计动作获得合适的信息，并在有限评价预算下合理分配下一次开发机会。

V11.1 不预测某个节点“继续设计的收益”，也不把 `attempts` 解释成收益估计。它只定义两件事：用节点当前质量和已经获得的父代机会抽样下一次直接父代；让四种设计动作分别看到与其动作匹配的信息。

父代抽样使用节点级评分的固定温度 softmax。上下文按算子固定组织，不按 task 名称路由。Fuse 的第二份完整程序用于帮助理解参考思想的具体做法，不要求拼接两份程序。

## 实验设置：模型与服务端点

V11.1 的生成模型统一记为 **Qwen3.8-27B**。本地端点配置名 `Qwen3.8-27B` 与远程端点配置名 `qwen3.8-27b-awq` 在本项目中视为同一个模型，使用相同的生成参数：`temperature=1.0`、`top_p=0.95`、`top_k=20`、关闭 thinking。`local`、`server1`、`server3` 和 `server3b` 只是同一模型的服务端点与容量池，不构成模型对照，也不作为算法质量变量。实验报告中不得把端点标签或服务地址写成不同模型，端点信息只用于复核资源分配和运行状态。

## 设计原则

1. **机会分配与信息配置是两件事。** 父代选择使用所有有效节点的统一分布；算子只决定本次生成需要哪些信息，不另建四套预算机制。
2. **预算单位是节点。** 一个算法就是一个节点，独立保存代码、Idea、fitness 和 `attempts`。节点每被选中一次作为直接父代，`attempts` 加一；新节点从零开始。节点不去重、不校对、不聚合。
3. **质量优先但保留低次数机会。** 保留 V11 的 fitness 百分位和低 `attempts` 奖励，再用固定温度 `tau=0.2` 的 softmax 抽样；`attempts` 只记录直接父代分配次数。
4. **算子条件化而非 task 条件化。** 同一个算子对不同 task 使用同一类信息组织；task 只作为结果分析维度，不进入上下文选择规则。
5. **固定策略优先。** 不增加任务分类器、阶段识别器、结构簇、血缘统计、在线算子控制器、额外探索配额或复杂度惩罚。
6. **提示和任务契约保持稳定。** 只改变父代抽样规则与算子已有的上下文输入，不改任务说明、评价器、解析协议、修复流程和算子比例。

## V10.11 对照提供的依据

| 已有上下文 | 现有观察 | V11.1 的使用方式 |
|---|---|---|
| 短形成轨迹 | TSP/VRPTW 的连续修改和阶段关系更容易被保留 | Refine、Tune 使用当前算法和短形成轨迹 |
| 档案 Idea+fitness | CVRP/OBP 中跨路径参考有一定收益 | Pivot 使用档案参考卡片 |
| 档案参考加第二个完整算法 | V10.11 的 Fuse 保留了可执行的第二个算法；V11 删除后只剩 Idea+fitness | Fuse 同时使用档案参考和一份帮助理解参考思想的第二参考算法代码 |

这些结果是对“算子需要什么信息”的间接证据，不是 task 规则，也没有证明任何一种上下文对所有 task 都最优。因此 V11.1 固定一个可解释的联合配置，不把当前 task 差异写成路由器。

## V11.1 的算子上下文

定义三个输入块：

- **T（短形成轨迹）**：当前算法完整代码、fitness 和最近最多 8 条形成步骤；每步只展示修改说明、算子和前后 fitness，不恢复整段历史的完整代码，沿用已有容量裁剪。
- **A（档案参考）**：当前算法完整代码、fitness 和最多 8 个档案 Idea+fitness 卡片；卡片按排名 softmax（`tau=8`）无放回抽取，沿用已有 `rand_ctx` 机制。
- **C（第二参考算法代码）**：将 A 中首次抽中的参考节点同时提供完整代码，帮助理解参考思想的具体做法；其余卡片不展开代码，不另建参考选择机制。

| 算子 | 固定上下文 | 目的 |
|---|---|---|
| Refine | T | 保留主要思想，改进现有算法的具体做法 |
| Tune | T | 在保留主机制的前提下校准参数、阈值和权重 |
| Pivot | A | 参考独立想法，寻找不同的主机制 |
| Fuse | A + C | 在当前算法基础上借鉴参考算法的有益设计思想，取长补短，形成协调一致的改进算法 |

同一配置用于所有 task。档案参考沿用已有容量裁剪；参考抽样只排除当前节点，不进行代码比较或去重。若 Fuse 没有可用的第二参考算法，则沿用已有回退流程；不为 Fuse 新增另一套参考选择机制或预算机制。

四个算子各占 25%，共享同一个父代分布。Pivot 尝试替换主要决策机制，Fuse 则吸收参考算法的长处来改善当前做法。Fuse 的提示核心为：

> 以当前算法为基础，借鉴参考算法中有益的设计思想，取长补短，形成协调一致的改进算法。

## V11.1 的节点级父代选择

设当前全部有效节点为 `i = 1, ..., N`，节点 fitness 为 `f_i`，节点作为直接父代被选中的次数为 `a_i`。保留 V11 的评分形式，但把统计对象改成节点：

\[
q_i=\operatorname{percentile}(f_i),
\qquad
s_i=q_i+0.1\sqrt{\frac{\ln(1+t)}{1+a_i}},
\qquad t=\sum_i a_i.
\]

其中 `q_i` 是当前 fitness 百分位，越好越接近 1；`a_i` 是该节点已被选为直接父代的次数；`t` 是所有节点的 `attempts` 总和。

父代在全部有效节点中按固定温度 `tau=0.2` 的分数 softmax 抽样：

\[
P(i)=\frac{\exp((s_i-s_{\max})/\tau)}
{\sum_j\exp((s_j-s_{\max})/\tau)},
\qquad \boxed{\tau=0.2}.
\]

减去 `s_max` 只是数值稳定处理。固定温度提高这个分数尺度上的质量偏好；V11.1 不使用 ESS、前八限制、均匀混合或动态调整温度。

当前表现好的节点更容易获得开发机会；质量接近时，分配次数少的节点更有机会。在同一轮的 `t` 下，`attempts` 越高，低次数带来的额外优待越小。产生更好的算法后，它作为 `attempts=0` 的新节点参与后续选择。

这一定义有四个边界：

- 节点每被选中一次作为直接父代时，`a_i` 加一；新节点从零开始。候选随后生成无效或评价失败，也不撤销这次已经分配的父代机会。
- 同一候选的修复请求不再次选择父代，因此不增加父代选择次数。
- Init 没有父代，不增加任何节点的父代计数。
- 两个节点即使代码完全相同，也各自拥有独立的 `a_i` 和抽样概率；不做代码比较、去重、校对或聚合。

## 为什么使用固定温度 `tau=0.2`

V11 分数由 fitness 百分位和小幅低 `attempts` 奖励组成。对这个分数尺度直接使用默认温度 1，质量偏好过弱；固定 `tau=0.2` 控制既定评分转化为选择概率的强度，同时增强质量差异与低次数奖励对选择概率的影响，不改变两者在评分中的相对权重。

V11.1 不使用 ESS、前八限制、均匀混合或动态温度。节点数变多时，实际获得机会的节点数由分数分布和固定温度共同决定；这正是本版本要检验的机会分配行为。由于分数使用百分位而不是原始 fitness，跨 task 的数值尺度不会改变 softmax 的定义。

固定温度也不预测某个节点继续开发的收益；它只规定当前分数如何转成下一次父代机会。后续若要改变温度，应作为独立版本的机制变量。

## 相对 V11.0 的逐项修改

| 机制位置 | V11.0 | V11.1 | 要克服的问题与依据 |
|---|---|---|---|
| 父代质量单位 | 按唯一 AST code 聚合 fitness | 每个有效节点单独计算 fitness 百分位 | V11 的 `num_codes` 通常接近 `num_nodes`，代码聚合没有形成有意义的开发臂，反而改变了预算单位 |
| `attempts` | 同一 AST code 被开发的次数，在结算时增加 | 节点被选为直接父代的次数，在选择时记录 | 只记录父代机会分配；重复代码节点各自独立计数 |
| 父代选择 | 取最高分 code，再在其节点中均匀选一个 | 对全部有效节点按 `tau=0.2` 的 V11 分数 softmax 抽样 | 质量优先，同时让低 `attempts` 节点保留机会 |
| 父代集中度 | 由最高分选择决定 | 固定 `tau=0.2`，不使用 ESS、前八限制或均匀混合 | 四个算子共享分布，不引入动态温度或算子特例 |
| Refine | 当前算法 + 短形成轨迹 | 保持不变 | V10.11 已有连续形成信息的正向证据，没有理由同时改动 |
| Tune | 当前算法 + 短形成轨迹 | 保持不变 | 参数校准仍需要当前计算和形成关系 |
| Pivot | Idea+fitness，使用 reciprocal-rank | Idea+fitness，改用已有排名 softmax（`tau=8`） | 保留替代方向输入，减少 reciprocal-rank 把大量长尾条目带入上下文的问题 |
| Fuse | Idea+fitness，无完整第二算法 | Idea+fitness + 一个第二参考算法完整代码 | 让模型理解参考思想的具体做法；不要求拼接两份程序 |
| 其他组件 | 四算子各 25%、初始化、解析、修复、评价器、真实预算、持久化 | 全部保持不变 | 限制修改范围，便于把变化归因于父代粒度和上下文输入 |

## 完整搜索顺序

初始化完成后，每轮先按既有的 25%/算子抽取一个算子；然后在全部有效节点中按统一的 `tau=0.2` 分布抽取父代并将该节点的 `attempts` 加一；再按算子组装对应上下文：Refine/Tune 使用当前代码、fitness 与短形成轨迹，Pivot 使用当前代码、fitness 与档案 Idea+fitness，Fuse 再提供一份第二参考算法代码；生成、解析、一次修复、真实评价和节点持久化全部沿用 V11。父代选择不因算子或 task 改变。

真实评价后，将有效算法加入节点集合，独立保存代码、Idea、fitness，且 `attempts=0`。下一轮根据更新后的 fitness 百分位和分配次数重新抽样；已有有效节点仍留在候选集合中。

这使 V11.1 的核心保持清楚：用固定温度的节点评分抽样分配下一次机会，用短形成轨迹支持连续改进，用档案 Idea+fitness 支持机制替换，并用一份第二参考算法代码帮助 Fuse 理解参考思想的具体做法。

## 明确不加入的机制

V11.1 不加入：

- AST 代码、父链、分支或结构簇的预算统计，以及代码去重、校对和聚合；
- 血缘/谱系分类、行为簇、兼容性评分或任务分类器；
- 根据近期改进率在线改变算子概率；
- 根据代码长度直接惩罚 fitness；
- 动态决定参考数量、上下文模式或温度；
- 以“第二参考算法”建立新的类别、谱系或控制器，也不要求拼接两份程序。

这些设计都需要额外定义和独立证据。V11.1 先使用最小、可读、可复核的节点级选择规则承载已有上下文发现。

## 实现范围

V11.1 已在独立模块中实现，机制代码与 V11.0 分开保存，实验入口位于 `experiments/traceaad_v11_1/`：

- `llm4ad/method/traceaad_v11_1/selection.py`：节点级 V11 分数计算、按固定 `tau=0.2` 的 softmax 父代抽样、`tau=8` 的排名 softmax 无放回参考抽样。
- `llm4ad/method/traceaad_v11_1/prompts.py`：算子条件化上下文构建；Refine/Tune 的短形成轨迹，Pivot/Fuse 的档案卡片，并为 Fuse 将首次抽中的参考展开为完整代码；复用已有容量裁剪和输出契约。
- `llm4ad/method/traceaad_v11_1/traceaad.py`：搜索主循环（调度、生成、解析、评估、结算）与检查点续跑（每结算一个候选保存全树快照，中断的在途候选从最近检查点重做）；在抽取时递增并持久化节点 `attempts`。
- `llm4ad/method/traceaad_v11_1/parsing.py`：输出解析与模板目标函数锚定；`tree.py`：节点与搜索树；`storage.py`：journal 持久化与恢复。
- `experiments/traceaad_v11_1/run.py`、`launch.py` 和 `freeze.py`：提供单路运行、批次调度和冻结运行时入口。

任务契约、评价器、初始化、修复、解析、算子比例、真实评价预算、持久化流程、已有容量裁剪和运行时冻结方式保持不变。父代次数沿用既有持久化设施保存，不增加其他控制机制。

## 设计结论

V11.1 的最小修正版是：**节点级 V11 分数 + `tau=0.2` 的固定温度抽样 + 固定的算子上下文**。它让质量较好的节点更容易获得机会，也让分配次数较少的节点保留机会；四个算子共享父代分布，只使用与设计动作对应的信息：当前算法和短形成轨迹、档案 Idea+fitness，以及 Fuse 的一份第二参考算法代码。Fuse 是借鉴参考思想形成协调改进，不是代码层面的强制组合；`attempts` 也只记录父代分配次数。
