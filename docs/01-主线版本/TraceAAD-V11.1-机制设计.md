# TraceAAD V11.1：算子条件化上下文与节点级预算分配

## 设计定位

V11.1 延续 V11 的原始目标：把 V10.11 对照中观察到的上下文差异组织到不同算子中，使算子得到更合适的经验，并让未知 task 在有限评价预算下更稳定地开发。

V11.1 只修正两处已经有证据的问题：

1. V11 把父代选择变成了最高分代码的确定性开发；
2. V11 的 Pivot/Fuse 参考输入缺少形成关系和可执行的第二个算法代码。

父代预算改为节点级分数 softmax。它不再使用 ESS 目标、AST 代码聚合或额外的均匀混合。上下文仍按算子固定组织，不按 task 名称路由。Fuse 中的第二个完整算法只称为“第二参考算法”或“组合参考代码”，它表示被拿来比较和组合的已有算法，不表示血缘关系。

## 设计原则

1. **联合设计继续保留。** V11.1 同时规定父代预算分配和算子上下文配置；不把版本缩减成只修预算的版本。
2. **预算单位是节点。** 一个有效评价记录对应一个搜索节点。节点被选为父代多少次，就有多少次父代开发计数；该计数不按 AST、代码相同与否或分支名称合并。
3. **直接使用 V11 分数。** 保留 V11 的质量百分位和低开发次数奖励，只把最高分选择改为分数 softmax 抽样。分数已经是无量纲的百分位加小奖励，因此 V11.1 不再增加动态 ESS 校准。
4. **算子条件化而非 task 条件化。** 同一个算子对不同 task 使用同一类信息组织；task 只作为结果分析维度，不进入上下文选择规则。
5. **固定策略优先。** 不增加任务分类器、阶段识别器、结构簇、血缘统计、在线算子控制器或复杂度惩罚。
6. **提示和任务契约保持稳定。** 只改变父代采样粒度与已存在的上下文输入，不改任务说明、评价器、解析协议、修复流程和算子比例。

## V10.11 对照提供的依据

| 已有上下文 | 现有观察 | V11.1 的使用方式 |
|---|---|---|
| 短形成轨迹 | TSP/VRPTW 的连续修改和阶段关系更容易被保留 | Refine、Tune 使用当前算法和短形成轨迹 |
| 档案 Idea+fitness | CVRP/OBP 中跨路径参考有一定收益 | Pivot 使用档案参考卡片 |
| 档案参考加第二个完整算法 | V10.11 的 Fuse 保留了可执行的第二个算法；V11 删除后只剩 Idea+fitness | Fuse 同时使用档案参考和一个第二参考算法的完整代码 |

这些结果是对“算子需要什么信息”的间接证据，不是 task 规则，也没有证明任何一种上下文对所有 task 都最优。因此 V11.1 固定一个可解释的联合配置，不把当前 task 差异写成路由器。

## V11.1 的算子上下文

定义三个输入块：

- **T（短形成轨迹）**：当前算法完整代码、fitness 和最近最多 8 条形成步骤；沿用 V10.11 的组装与容量裁剪。
- **A（档案参考）**：当前算法完整代码、fitness 和最多 8 个档案 Idea+fitness 卡片；卡片按排名 softmax（`tau=8`）无放回抽取，沿用已有 `rand_ctx` 机制。
- **C（组合参考代码）**：Fuse 额外看到一个第二参考算法的完整代码和 fitness。它只是可执行的比较材料，不是血缘、谱系或特殊类别。

| 算子 | 固定上下文 | 目的 |
|---|---|---|
| Refine | T | 围绕当前实现和实际形成步骤做局部、连续改进 |
| Tune | T | 在保留主机制的前提下校准参数、阈值和权重 |
| Pivot | A | 参考独立想法，寻找不同的主机制 |
| Fuse | A + C | 同时参考多个想法，并拥有一个可直接检查和改写的第二算法 |

同一配置用于所有 task。若档案卡片被容量裁剪为空，Pivot 退化为当前算法加任务契约；Fuse 尽量保留第二参考算法，只有在没有可用第二参考算法时才沿用已有的 Refine 回退。容量裁剪不新增上下文数据结构。

## V11.1 的节点级父代选择

设当前有效节点为 `i = 1, ..., N`，节点 fitness 为 `f_i`，节点作为父代被选中的次数为 `a_t(i)`。保留 V11 的评分形式，但把统计对象改成节点：

\[
q_t(i)=\operatorname{percentile}(f_i),
\qquad
s_t(i)=q_t(i)+0.1\sqrt{\frac{\ln(1+t)}{1+a_t(i)}}.
\]

这里的 `t` 是截至当前的正常父代选择次数；修复请求不单独推进这个计数。

父代按分数直接 softmax 抽样：

\[
P_t(i)=\frac{\exp(s_t(i)-s_{\max})}
{\sum_j\exp(s_j-s_{\max})}.
\]

减去 `s_max` 只是数值稳定处理，等价于普通 `softmax(scores)`；V11.1 不引入 beta、温度、ESS 目标或动态集中度控制。

这一定义有四个边界：

- 节点被正常选为父代时，`a_t(i)` 加一；新节点从零开始。
- 生成无效或评价失败仍算一次父代开发请求，因为预算已经花在这个节点上；同一候选的修复请求不再重复增加父代计数。
- Init 没有父代，不增加任何节点的父代计数。
- 两个节点即使代码完全相同，也各自拥有独立的 `a_t(i)` 和抽样概率。AST 代码如仍用于档案卡片去重，只能是上下文展示规则，不能进入父代预算统计。

## 为什么取消 ESS

ESS=8 能把不同规模的节点池压缩到近似固定的有效支持数，但它是 V10.11 的一个经验性集中度设定，不是 V11 分数 softmax 的必要条件。把 ESS 保留到 V11.1 会继续引入一个隐藏的全局控制器，也会让“从最高分贪心改成随机分数选择”的效果难以单独解释。

直接 softmax 的代价是：节点数变多时，有效支持数会随分数分布变化，不能保证永远只有约 8 个节点得到预算。这个代价是可见且可解释的；当前版本的目标是先取消 V11 的确定性锁定，而不是再用一个自适应目标把分布重新压窄。由于分数使用百分位而不是原始 fitness，跨 task 的数值尺度不会额外改变 softmax 的定义。

直接 softmax 也不等于保证探索充分：如果未来发现分数分布过平或过尖，应在后续版本单独讨论一个固定温度，而不是在 V11.1 中预先加入 ESS、均匀混合和更多反馈状态。

## 相对 V11.0 的逐项修改

| 机制位置 | V11.0 | V11.1 | 要克服的问题与依据 |
|---|---|---|---|
| 父代质量单位 | 按唯一 AST code 聚合 fitness | 每个有效节点单独计算 fitness 百分位 | V11 的 `num_codes` 通常接近 `num_nodes`，代码聚合没有形成有意义的开发臂，反而改变了预算单位 |
| `attempts` | 同一 AST code 被开发的次数，在结算时增加 | 节点被正常选为父代的次数，在选择时记录 | “被选择了几次”才对应父代开发预算；不再把重复代码和开发次数混为一谈 |
| 父代选择 | 取最高分 code，再在其节点中均匀选一个 | 对所有节点按 V11 分数 softmax 抽样 | V11 中约 99.7%–100% 的正常开发落在 `q≥0.95` 的 code，最高分选择压缩了替代方向 |
| ESS/均匀混合 | 隐含依赖 V10 ESS；Pivot 另加均匀混合 | 全部取消；一个节点级 softmax 供四个算子共享 | 减少未经 V11 独立证据支持的集中度和算子特例，直接检验 softmax 是否能解除锁定 |
| Refine | 当前算法 + 短形成轨迹 | 保持不变 | V10.11 已有连续形成信息的正向证据，没有理由同时改动 |
| Tune | 当前算法 + 短形成轨迹 | 保持不变 | 参数校准仍需要当前计算和形成关系 |
| Pivot | Idea+fitness，使用 reciprocal-rank | Idea+fitness，改用已有排名 softmax（`tau=8`） | 保留替代方向输入，减少 reciprocal-rank 把大量长尾条目带入上下文的问题 |
| Fuse | Idea+fitness，无完整第二算法 | Idea+fitness + 一个第二参考算法完整代码 | V10.11 的 Fuse 有可执行组合材料；V11 删除后无法检查和改写另一个算法的实际计算 |
| task 路由 | 不同 task 的结果容易被解释成特殊规则 | 不按 task 名称选择上下文 | 面向未知 task，只保留算子层信息假设，避免对现有 task 过拟合 |
| 其他组件 | 四算子各 25%、初始化、解析、修复、评价器、真实预算、持久化 | 全部保持不变 | 限制修改范围，便于把变化归因于父代粒度和上下文输入 |

## 完整搜索顺序

初始化完成后，每轮先按既有的 25%/算子抽取一个算子；然后对所有有效节点计算 V11 分数并按同一个 softmax 抽取父代，同时记录该节点的父代选择次数；再按算子组装 T、A 或 A+C；生成、解析、一次修复、评价和节点持久化全部沿用 V11。父代选择不因算子或 task 改变。

这使 V11.1 的核心变化保持在两处：把错误的“按代码开发计数”改为“按节点选择计数”，把最高分硬选择改为直接分数 softmax；上下文部分只恢复 V10.11 已有的算子信息模式。

## 明确不加入的机制

V11.1 不加入：

- AST 代码、父链、分支或结构簇的预算统计；
- 血缘/谱系分类、行为簇、兼容性评分或任务分类器；
- 根据近期改进率在线改变算子概率；
- 根据代码长度直接惩罚 fitness；
- 动态决定参考数量、上下文模式或温度；
- 以“第二参考算法”建立新的类别、谱系或控制器。

这些设计都需要额外定义和独立证据。V11.1 先使用最小、可读、可复核的节点级选择规则承载已有上下文发现。

## 实现范围

V11.1 只需要修改两个已有模块：

- `traceaad.py`：移除父代选择对 `CodeBook` 的依赖；在有效节点上计算 V11 分数、直接 softmax 抽样，并持久化节点父代选择次数。
- `trajectory.py`：保留 Refine/Tune 的形成轨迹，保留 Pivot 的档案卡片，并为 Fuse 增加一个第二参考算法的完整代码输入；复用已有容量裁剪和输出契约。

任务契约、评价器、初始化、修复、解析、算子比例、真实评价预算和运行时冻结方式保持不变。事件流只记录实际父代节点、算子、上下文模式、参考节点和第二参考算法节点，记录本身不反馈成新的控制器。

## 设计结论

V11.1 的最小修正版是：**节点级 V11 分数 + 直接 softmax + 固定的算子上下文**。它去掉 ESS、AST 开发臂、按 task 路由和血缘式命名，只保留有已有实现和实验迹象支持的三类信息：当前算法及短形成轨迹、档案 Idea+fitness、以及 Fuse 所需的第二参考算法完整代码。这样既修复 V11 的精英锁定，又避免把一个尚未验证的假设扩展成复杂控制系统。
