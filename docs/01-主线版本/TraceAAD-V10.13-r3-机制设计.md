# TraceAAD V10.13-r3：单轮上下文与 Python 优先输出

r3 按用户的奥卡姆剃刀要求，删除 r2 中模型需要额外处理的读取和卡片选择流程。LLM 每次拿到已组织好的必要材料，直接生成或编辑算法；进化搜索继续负责分配评价机会。目标是减少接口损耗，让模型把能力用于算法设计。

依据是 [r2 早期运行诊断](V10.13设计演进.md)：25.82% 候选在评价前拒收，大量响应只因封装未被识别；39.9% 局部读取为空；一些 OBP 候选改了公式和说明，却不改变实际选择。用户已授权修正后重启实验。r3 使用新批次 `20260924_v1013r3`，不覆盖 r2，不用新代码恢复 r2 checkpoint。

## 保留的搜索机制

- 五任务 × 四重复、seed 0–3、每路 1000 次评价预算、8 个有效 root；沿用任务说明、模板、数据、模型请求配置、后端分配与 held-out 口径。
- 四算子各 25%。所有算子的父代分布仍为 `0.875 q + 0.125 U`；q 使用 ESS-8 质量 softmax，最高分并列多于 8 时按并列数提高可达目标。
- 所有真实评价，包括失败、修复、重复代码，均计 E；解析拒收只计模型成本。
- 形成关系、原始响应、评价回执和阶段 checkpoint 保留；一个失败最多修复一次，不重新分配父代。缺回执的评价预约仍阻断自动恢复。
- 不新增语义分类器、agent、多样性评分、island、数值优化器或强制 continuation。不同代码不视为已证明的不同算法；同分不直接合并。

## 每个算子的输入与动作

每轮都提供任务和当前代码。Idea 为可选短句，显示上限 480 字符；缺失或过长不拒收代码。

| 算子 | 附加上下文 | 算法动作 |
| --- | --- | --- |
| Init | 容量允许的既有 root 程序 | 从任务知识提出有竞争力的决策原则，避免只换公式而保持相同选择 |
| Refine | 最近至多3条形成边；已有的至多2条同父 trial Idea/fitness | 改进表示、比较或组件协调，考虑什么情况下能做出更好的决策 |
| Tune | 同上；有 Tune 子代时优先选它们 | 校准有效参数、尺度和交互，使其可能影响选择或采样 |
| Pivot | 无参考卡、无额外轨迹 | 重新考虑核心假设，用模型知识探索替代表示或决策原则 |
| Fuse | 一份完整参考代码及短 Idea/fitness | 借鉴能弥补 host 弱点的计算，协调尺度与交互；不合适则直接改进 host |

局部 trials 沿用 r2 的“最佳超父子代 + 最新未超父子代”，直接放入本轮提示；没有就不出现，不再请求读取。没有历史原始 diff，也不生成额外摘要。

Fuse 的参考池排除 host 的相同 AST，并以最新已评价节点代表精确代码副本；每次以 50% 概率按质量 q 抽一份、50% 概率均匀抽一份。取消三卡片、低曝光权重与模型选卡调用。这样保留中低分参考的机会。LLM 根据实际代码判断是否有可借鉴的计算。

`reference_ids` 与 `loaded_reference_id` 记录实际提供的完整参考；可选 `donor_id` 记录模型声明。Python 默认输出无需填 donor 字段，后续效果分析可以比较 host 与所展示参考。

上下文超限时按整项裁剪最旧形成边、trial、整份参考，并记录原因；不截断代码。任务和 parent 放不下则明确失败。输入/输出 token 上限仍为 24320/8192。

## 一次生成，两个简单出口

默认输出是一个 Python 代码块，可以在前面附一句 Idea。不要求把完整 Python 塞进 JSON 字符串，也不要求 mechanism/change/transfer 三字段。兼容已有结构化 Idea 和 JSON full 输出，但不在提示中要求它们。

局部修改仍可使用：

```json
{"mode":"edit","edits":[{"search":"return x + 1","replacement":"return x + 2"}],"idea":"调整实际使用的偏置"}
```

edit 自动使用当前候选的 parent。每个 search 必须非空且唯一，顺序应用，目标接口和语法必须正确；保留 1–32 项实现上限。

解析遵守代码优先：原来单一完整 Python 块的解释保留；否则，从外围文字/围栏中读取唯一明确 JSON 对象。不改写代码字符串或猜测转义，多个冲突对象仍拒绝。缺结束围栏但完整可解析的 Python 也可接收。不会因为作者说明缺失而拒收代码。语法通过仍须真实评价。

删除 `mode=context` 的运行分支。每个正常候选只发一次生成请求，修复是另一个 candidate_id 且沿用同一次父代机会。日志保留 `context_reads=0` 等字段以兼容分析格式，旧 checkpoint 通过 revision/机制指纹被拒绝。

## 检验与证据边界

1. 使用假 LLM/小评价器检查 inline trial、单参考、edit、模板接口、父代机会及崩溃恢复。
2. 对 r2 01:22 的响应前缀离线重放：1,726 个已有效程序全部保持同一代码；323 次旧拒收可接受；剩余拒收保留，包含已删除的 context 请求。没有调用真实 evaluator，没有回填原批次。
3. 测试通过后，按用户授权停 r2、保留 manifest/checkpoint/日志/routing 身份，以同配置新启动20路 r3。机制不能在运行中热修。
4. 启动检查只判断单轮执行、解析/编辑、预算回执和实际代码路径。质量须看相同 E 的重复训练前缀及完赛 held-out；不会以解析率恢复宣称算法效果恢复。
