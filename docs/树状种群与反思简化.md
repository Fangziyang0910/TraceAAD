# 树状种群与算法设计经验

**树状种群使算法的优胜劣汰，同时成为积累和复用算法设计经验的过程。**

## 从算法演化到经验积累

演化式算法设计通过生成和评价子代、选择保留个体，逐步改进算法种群。父子算法的代码变化及其评价结果记录了算法如何发展，也为积累算法设计经验提供了依据。

算法不断被选择和淘汰，仅保留当前算法及其分数，无法直接呈现此前的演化过程；保存全部历史算法又会使种群持续增长。EvoTrace将反思纳入种群更新，在淘汰算法时总结相关演化过程中的设计经验，使经验随种群演化持续积累。

## 为什么用树状种群

树中的节点表示算法个体，父子关系记录演化轨迹。路径记录连续的算法变化，分支记录从同一祖先开始的不同演化过程。虚拟根连接初始个体，本身不对应算法。确定保留节点及连接它们的分叉节点后，其余节点可组织为连接保留节点的路径区域，以及从保留节点延伸出的子树区域。

这些关系同时确定反思范围和经验的保存位置。路径区域中的演化过程经反思后形成边经验，保存在重连边上；子树区域中的演化过程经反思后形成节点经验，保存在相应的祖先节点上。经验由此保留在与相关算法相联系的位置，并在后续更新中继续整合。

## 淘汰与反思共同完成种群更新

选择规则确定保留的算法，树结构据此组织待简化的区域。反思读取相应的代码变化、评价结果及已有经验，生成以自然语言表达的算法设计经验。两种操作共同实现这一过程：

- **路径收缩与边经验。** 移除中间节点及沿途未保留分支，重连两端的保留节点。反思总结相应的算法变化及评价结果，将形成的边经验保存在重连边上。
- **子树剪枝与节点经验。** 剪除不再保留的子树。反思总结分支中的算法设计及其表现，将形成的节点经验保存在这些子树所依附的保留节点上。

反思是这一更新中的压缩过程。若一条已收缩边后来进入更长的待收缩路径，其边经验继续参与反思；若同一节点产生更多待剪分支，相应算法及评价结果与已有节点经验共同进入反思。算法个体不断更替，设计经验通过节点和边继续保留。

具体选择规则使用适应度与代码结构距离确定代表算法，再保留连接代表的共同祖先。区域中的待移除节点数达到阈值后执行反思与简化，精确公式与参数见[V3设计](EvoTrace-v3设计.md)。

## 从经验积累展开到后续搜索

更新后的种群包含用于生成子代的代表算法，也保存相应的演化轨迹与设计经验。预算依据代表算法的适应度排名，以及以其为主父代已消耗的评价次数分配。生成上下文则按算子组织：

- **精化（Refine）** 读取当前算法的演化轨迹、已有子代记录及相关经验，结合其演化过程提出改进。
- **交叉（Crossover）** 读取两个算法自最近公共祖先之后的演化轨迹及经验，理解和组合双方的设计；若只共享虚拟根，则参考两条初始谱系各自的路径。
- **探索（Explore）** 参考种群中可行算法的设计、评价结果与经验，构思核心计算过程不同的算法。

各算子的上下文在输入限制内展示相关内容。新子代经评价后进入树中，参与后续选择、淘汰与反思。种群演化不断产生新的设计经验，积累的经验又参与后续算法生成。

## 核心贡献

1. **树状种群结合算法优胜劣汰与经验积累。** 以演化关系组织算法个体及其设计经验。
2. **淘汰与反思共同完成种群更新。** 在路径收缩与子树剪枝时分别形成边经验和节点经验，并在后续更新中持续整合。
3. **更新后的种群支持后续搜索。** 代表算法参与预算分配，演化轨迹与设计经验用于精化、交叉和探索。
