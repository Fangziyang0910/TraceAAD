# 树状种群与反思简化

**EvoTrace通过反思压缩搜索经历，使算法种群在持续更新实现的同时积累设计经验。** 一个实现作为开发起点的价值，与其经历对后续设计的参考价值不同。树状种群将候选竞争与发展关系组织在一起；动态反思简化利用保留结构同时确定历史整理范围与经验承接位置。

本页阐述当前V3的研究问题与核心思路。精确规则和参数见[V3正式设计](EvoTrace-v3设计.md)。[V2设计](EvoTrace-v2设计.md)和[V1设计](EvoTrace-v1设计.md)保存各自机制，历史实验按各自冻结源码解释。现有[英文主稿](paper.md)与[中文对照](paper-中文.md)对应V2及其冻结证据，尚未改写为V3结果。

## 1. 研究问题

有限评价预算下的自动算法设计（automated algorithm design, AAD）需要持续决定：从哪个实现继续开发，以及已有尝试能为下一次设计提供什么。程序质量决定当前实现的表现，试错经历则提供计算选择及其结果之间的比较。两者来自同一搜索过程，更新方式却不必相同。

一个实现退出候选集合后，围绕它形成的比较仍可能有用。直接删除相关历史会失去这些材料；逐次保留全部实现又会扩大待选择和待读取的内容。需要解决的问题是：**如何在更新可开发算法时，凝练被移除的经历，并保持这些经历与后续设计起点之间的联系？**

种群更新同时选择搜索历史的表示：值得继续开发的实现保持程序形式，退出种群的相关经历经过反思凝练为经验。树的派生关系为这一转换提供范围与位置。当前种群由此同时保存开发起点及与之相联系的设计记忆。

## 2. 用一棵树组织实现与经历

树中每个算法节点保存可执行实现、计算描述和评价反馈。每条结构边表示主父代派生关系。Crossover另存参考来源，不增加第二条结构边。完整尝试档案保留原始代码和评价，当前树保存下一步搜索可直接选择和读取的状态。

| 树上的位置 | 保存的经验 | 为后续设计提供的材料 |
| --- | --- | --- |
| 节点的选择经验（selection experience，S） | 归属该位置的已移除旁支尝试及结果 | 围绕这一位置试过哪些计算选择 |
| 边的变异经验（variation experience，V） | 保留端点之间被收缩的发展，以及中间节点的同轮移除旁支 | 当前实现如何形成，沿途有哪些替代尝试 |

每个节点都是一个算法个体。树边记录它如何从主父代发展而来，不按算子额外划分路线。Init产生初始个体；Refine、Crossover、Explore描述生成任务。Explore要求构思新的主要计算，其后代仍作为普通个体参与种群竞争。

## 3. 一次保留决策，同时更新结构与经验

初始化完成后，每次受评实现入树触发一次维护。维护从同一树快照确定质量与差异代表、近期可行节点及连接它们所需的分叉。该保留集合同时决定旁支剪枝和路径收缩。

质量代表体现当前成绩与代码差异；近期保留依据个体自身的出生或直接开发时钟；必要分叉保留候选之间的派生联系。更优后代不单独取消祖先的代表资格，父代活动也不连带刷新子代。所有保留可行个体，包括内部祖先，仍可直接开发。树规模由这些规则共同形成，没有固定容量上限。

保留端点之间的中间版本及其同轮移除旁支，进入重连边的变异经验；其余旁支进入最近保留祖先的选择经验。例如，`A → B → C → D`附有`B → X`，只保留A和D时，B、C、X及它们携带的旧经验共同进入`A → D`，A原有经验仍留在A。每个移除节点在本轮维护中只归属一个区域。同轮各区域读取同一维护前材料。

两类经验对应简化操作，均可包含改进、同分、退步及失败；选择经验参与生成与后续反思。简化保留各存活个体自身的直接投入与历史子树投入。收缩交接经验，不把祖先的投入转嫁给后代；剪掉旁支也不减少祖先已经花掉的预算。

反思以代码差分、程序计算的结果标签、错误反馈及旧经验为材料。比较对应各次尝试的实际父代，区分整段净结果与中间单步结果。经验先陈述观察，再按证据给出可能解释；组合修改的结果不足以单独确定某个部件的作用。后续移除经验的承载位置时，旧经验随相应区域继续交接。

树上经验提供对发展过程的凝练表示，尝试档案保存相应的完整代码与评价。

## 4. 从更新后的树继续搜索

预算分配同时利用个体之间的竞争关系和个体之间的发展关系。所有保留可行个体直接按概率竞争，权重为“质量倍率的排名质量次方，除以1加历史子树评价数”。默认质量倍率为10，表示相同投入下最好与最差个体的权重比。适应度排名体现当前质量，沿祖先累计的实际投入调节重复开发。祖先的累计投入只降低祖先自己的权重，新后代以自身质量和零开发投入独立参赛。

质量偏好与投入折扣在同一规则中连续作用，随机抽样保留旧基点和弱初稿的机会。每次完成一个尝试后更新排名和概率，不设探索/利用阶段。计数表达预算偏好，不预测未来突破；持续产生近同新版本的重复开发问题尚未被这条规则消除。

三个算子按当前设计任务读取同一棵树：

| 算子 | 读取范围 | 设计任务 |
| --- | --- | --- |
| Refine | 实际形成路径、路径经验与当前个体的尝试 | 修改当前实现 |
| Crossover | 两份实现、真实共同祖先与祖先之后的双支发展 | 判断可借用的计算并完成融合 |
| Explore | 当前种群个体的设计、成绩、来源及节点和边经验 | 构思主要计算不同的实现 |

派生树保留来源联系，生成视图控制读取范围。形成路径保留Explore步骤，并明确它是计算转向而非局部调参；初稿分数描述该实现的表现，不等于整个思想的潜力。Explore概览直接读取种群个体。输入超过预算时缩减完整条目，树结构、预算与经验归属不随展示取舍改变。

## 5. 核心主张

1. **带经验的树状种群。** 将可开发算法、派生关系与凝练经验组织于同一演化结构，使当前种群同时提供开发起点及其相关历史。
2. **动态反思简化。** 将种群更新与经历压缩结合，由保留结构共同确定历史整理范围及经验承接位置，使被移除尝试继续参与后续算法生成。

预算分配和三类视图让更新后的结构参与搜索，分别决定从哪里开发、为当前设计读取哪些经历。

实证研究围绕经验交接对后续生成和最终算法质量的作用展开：同预算搜索比较整体效果，固定状态下的经验读取对照识别经验的作用，程序评价与模型调用共同反映搜索成本。V3实现检查与认识变化见[本周记录](记录/2026-W46.md)，V2历史回放见[修复与验证](记录/2026-11-14-V2最小修复与回放.md)。
