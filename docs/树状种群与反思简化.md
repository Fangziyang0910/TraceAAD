# 树状种群与算法设计经验

**树状种群使算法的优胜劣汰，同时成为积累和复用算法设计经验的过程。**

论文标题为 **Reflective Elimination: Accumulating Design Experience in Tree-Structured Algorithm Populations**，中文为**反思式淘汰：在树状算法种群中积累设计经验**。方法名为 **TREES（Tree-structured Reflective Evolutionary Search，树状反思式演化搜索）**。EvoTrace保留为内部代码与运行记录代号。标题以反思式淘汰点明核心更新，以设计经验积累说明其价值，以树状算法种群明确组织方式。路径收缩与子树剪枝实现这一更新；经验继承描述跨轮整合的性质，预算分配与算子上下文说明同一种群如何支持继续搜索。

## 演化产生的不只有当前算法

演化式算法设计不断生成、评价和选择算法。父子之间的变化及其结果记录一次修改，连续的父子关系记录算法如何发展，共同祖先产生的分支记录从同一起点出发的不同演化过程。这些经历为后续设计提供了当前代码与分数之外的信息。

算法不断更替，经验也需要随之整理。只保留当前实现，无法呈现它此前的发展；一直保留全部算法，又会使种群持续增长。这里需要回答三个相联系的问题：哪些经历应当一起总结，形成的经验应保存在何处，后续设计如何利用它？

## 树如何联系经验的形成与复用

树中的节点表示算法个体，父子关系记录演化轨迹。保留选定算法及连接它们的分叉祖先后，其余节点被划分为两类互不相交的区域：连接保留算法的路径区域，以及从保留算法延伸出的子树区域。路径区域也包含中间节点产生、随之移除的分支。每个待淘汰节点都有明确的区域归属。

这一区分对应两类演化经历。路径区域描述两个保留算法之间如何发展，适合凝练为重连边上的经验；子树区域描述从某个保留算法出发的分支，适合凝练为该祖先节点上的经验。因此，淘汰规则与演化关系共同组织反思范围和经验位置。

这些位置同时支持后续使用。精化读取当前算法的形成轨迹及从它出发的尝试；交叉在此基础上加入一个参考算法及其发展经验；探索读取结构不同的代表算法的设计与经验，不给代码。经验由此与后续仍在使用的算法及其关系保持联系。

## 淘汰与反思共同完成种群更新

TREES通过反思式淘汰（Reflective Elimination）落实这一过程，包含两种操作：

- **路径收缩与边经验。** 反思读取保留端点之间的每个算法及其沿途分支，连同它们承载的已有经验。移除中间节点和相关分支后，将形成的边经验保存在重连边上。
- **子树剪枝与节点经验。** 反思读取保留祖先及其已有节点经验，以及从它出发、已不包含选定后代的分支。剪除这些分支后，将其凝练为更新后的节点经验。

反思是更新中的压缩过程。已有边经验随更长路径再次收缩而进入新的反思；已有节点经验随更多分支被剪除而继续更新。若承载经验的节点后来退出种群，其经验也进入所属区域的反思。因此，经验的积累不要求最初产生或承载它的算法一直存活。两种操作使用同一个事实反思提示：区域中每个算法给出来源与结果、设计、失败原因、已有经验与代码；经验只记录每个有信息量的尝试实际计算了什么（若为修改则相对起始计算的变化）与实测适应度或失败，不写规则、建议或推测原因。

具体规则先依据适应度与代码结构距离选择代表，再补齐分叉祖先；区域达到节点数阈值后执行反思与简化。该更新保持代表集与存活节点之间的祖先关系。初始化完成后，每次更新的算法节点数由代表上限与区域阈值共同约束，与评价预算无关。精确规则见[V3设计](EvoTrace-v3设计.md)，证明见论文附录C。

## 同一种群如何支持继续搜索

经验积累使当前算法带着此前发展所形成的认识参与后续生成。预算分配与生成上下文使用这棵树的不同信息：预算依据当前代表的适应度排名，以及以其为主父代执行精化或交叉消耗的评价次数；生成则结合相应的轨迹与经验。新代表可以利用祖先经验，而其预算权重从自身的子代评价次数起计。

- **精化（Refine）** 结合当前实现、从根到当前算法的演化轨迹、局部分支及相关经验，提出下一次修改。
- **交叉（Crossover）** 结合当前算法的形成轨迹与另一代表算法的设计、路径经验及源码，组合双方的计算思想。
- **探索（Explore）** 结合根经验以及代表算法的设计描述与评价结果（不含局部演化经验与源码，函数接口由任务模板给出），从零构思不同的核心计算并挂载于虚拟根下开启新谱系。

各算子在输入限制内读取相关内容。子代经评价后进入种群，产生新的演化经历，并参与下一轮选择、淘汰与反思。核心更新由此延伸为一个持续过程：演化产生经历，淘汰组织经验，积累的经验参与后续生成。

## 贡献与论证的层次

论文首先提出结合淘汰与反思的种群更新，说明树如何同时组织算法更替与经验积累；继而展示这一表示对预算和生成的用途；最后以结构性质和搜索记录支撑上述过程。三者构成递进关系。

结构分析证明代表集保持不变，并给出更新后的算法节点数上界。当前代表覆盖版的12次搜索共记录3,519次评价，其中147次反思读入更早更新产生的经验，占490次反思的30.0%。真实TSP案例进一步追踪一条分支退出后，其经验经过后续反思进入另一保留分支的生成上下文。记录直接呈现经验的跨轮继承与复用；经验对搜索表现的影响由受控比较检验。
