# 树状种群与反思简化

**EvoTrace 将种群竞争与树结构的发展关系结合，把种群维护定义为演化树的简化与经验压缩过程：路径收缩凝练为边经验，子树剪枝凝练为节点经验，再由同一棵树支撑后续的父代分配与算法生成。**

## 研究问题

自动算法设计（automated algorithm design，AAD）在有限评价预算下围绕候选算法持续修改、融合与探索。算法之间的派生关系天然构成一棵演化树：若保留全部历史程序，种群与上下文会迅速失焦膨胀；若直接淘汰旧个体，已付出的评价代价随之流失；若将经验拉平放入脱离结构的全局列表，又会丢失“某项认识是在哪个算法基点、哪段修改过程上得出的”。

EvoTrace 以同一棵树统一候选竞争、经验压缩与上下文组织：节点是参与竞争的算法个体，边记录派生关系；个体退出时，其试错过程按所在拓扑位置压缩为节点经验与边经验，留在树上继续服务后续设计。

## 树简化与经验压缩

随着搜索推进，近期仍在参与演化的可行算法、全局最优算法以及连接它们的最近公共祖先（lowest common ancestor，LCA）保留在树中，维持活跃分支之间的派生骨架。其余不再保留的节点在积累足够比较样本后成批简化，只对应两种基础树操作：

1. **路径收缩 $\to$ 边经验。** 两个保留算法之间的中间过渡版本（连同依附其上的未保留分支）收缩为一条连接边，凝练*起始算法是如何一步步演变为后继算法的*。
2. **子树剪枝 $\to$ 节点经验。** 从某个保留算法（或初始根）出发而未继续保留的分支归并回该节点，凝练*从这一算法基点出发探索过哪些方向、实测结果如何*。

反思读取被简化区域内的代码变化、实测结果及已有经验，合成简短的算法设计笔记写回对应节点或边；后续简化会连同既有笔记继续整合。树结构由此自然决定**哪些尝试一并整理、经验附着在何处、以及后续生成从何处读取**。

## 基于同一棵树的预算分配与生成

留在树中的独立可行算法按**全局名次质量**与**沿演化路径共享的累计评价投入**竞争父代机会：在同一演化路径上尚未超越最优祖先的后代，共享该最优祖先累计消耗的子树评价次数，不会因自身刚出生而反超更优父代或因同族改写增多而无界扩张；一旦后代严格刷新路径最优成绩，即作为新的路径起点从零累计投入参选；长期投入而未再突破的分支则随累计评价增加自然让出探索预算。

三种生成算子按各自职责读取同一棵树：
- **Refine** 读取从根到当前算法的演化路径、沿途的边/节点经验及当前算法的直接子尝试；
- **Crossover** 读取两个算法的最近公共祖先及分叉之后各自走过的演化分支与经验；
- **Explore** 通览树中保留的代表算法及其附着经验，寻求主计算不同的新思路。
