# 树状种群与反思简化

**EvoTrace以树状种群统一组织候选算法、派生关系与演化经验，以动态反思简化维护这一持续演化的结构。** 树依据局部演化状态按需选择算法、简化结构，并将被移除部分的经历凝练到保留的边和节点上，供后续搜索使用。

两版完整机制分别见[V1正式设计](EvoTrace-v1设计.md)与[V2正式设计](EvoTrace-v2设计.md)，作为机制阅读与确认的依据。本页记录研究问题与核心思路，第5节保留V1的64→32概述；在线批次继续使用各自冻结源码。

设计取舍见[自洽性审查](记录/2026-11-13-动态压缩自洽性审查.md)，工作区修改与验证见[实施记录](记录/2026-11-13-动态反思简化实现与验证.md)。

## 1. 核心问题

自动算法设计在有限评价预算下反复选择并修改候选算法。算法在谱系中既是可继续开发的个体，也承载与其他尝试的发展联系。因此，候选集合的更新需要同时处理派生关系与相关经历。

**当前问题：如何让树状种群在持续生长中完成个体选择与结构更新，并利用被移除尝试中的经验支持后续设计？**

树与种群结合、动态剪枝和轨迹利用已有先例，见[相关工作核对](记录/2026-11-11-树状种群与剪枝简化的相关工作调研.md)。本研究聚焦树状种群的更新机制，以及更新后的结构如何继续参与搜索。

## 2. 核心思路

树状种群是方法主体：节点保存候选算法，派生关系连接发展脉络，边与节点上的经验承接已简化的经历。它同时支持算法选择与历史利用。

动态反思简化是其核心更新机制，接替此前固定容量触发的反思简化。树上不同区域的发展进程不同，因此更新依据局部演化状态触发。一次更新共同完成算法选择、结构简化与经验凝练：路径经历写入重连边的变异经验，旁支经历写入承接节点的选择经验。更新后的树继续用于选择父代和生成算法。

V2依据节点最近使用与当前候选质量一次确定保留集合，再补回连接保留路线所需的分叉，同时剪除旁支和收缩路径。最近40次评价内出生或实际用作父代、参考的可行节点保留，前半候选中的非冗余质量代表受到保护；冠军必留。同轮不因删除而重算排名，不设宽度、长度触发或固定容量。访问统计与经验沿同一分区交接，当前算法的直接开发次数与承接历史分开。参数是待检验设置。

## 3. 定位与贡献

核心贡献是**树状种群及其动态反思简化机制**：通过局部状态驱动的更新，在同一搜索结构中衔接个体选择、发展关系维护和经验积累。基于树的预算分配与多尺度生成上下文是这一结构的应用。

论文围绕问题、核心思路及其作用展开，具体保留规则与简化过程在方法部分定义，见[英文主稿](paper.md)与[中文对照](paper-中文.md)，包含摘要、引言、相关工作和方法初稿。

## 4. 树保存什么

虚拟根连接初始算法，本身不占候选容量。默认初始化5个可行算法。每个已评价版本都是节点；不可行版本暂存为叶节点，不能参与父代或参考选择，并在下一次重构时移除。

| 位置 | 保存内容 | 用途 |
| --- | --- | --- |
| 节点 | 代码、设计描述、适应度或错误 | 后续修改的起点 |
| 边 | 主父子关系、算子与交叉参考来源 | 记录派生关系 |
| 边的变异经验 | 祖先到后代的修改、中间尝试及结果 | 说明算法怎样形成 |
| 节点的选择经验 | 归属该节点的已淘汰旁支尝试及结果 | 说明从这里出发试过什么 |

Init与Explore创建设计方向，Refine与Crossover继承主父代方向。Crossover只向主父代连边，另存参考来源。方向起点可以被压缩，方向编号和累计评价数仍由后代承载。

## 5. V1实现：生长、淘汰与反思简化

本节描述现有容量触发的实现。它已实现路径收缩、旁支整理与两类经验，更新时机仍由节点总数统一决定。

两次重构之间，搜索持续生成并评价后代。默认达到64个节点时重构，更新后最多保留32个可行算法。

**淘汰。** 内部算法与叶节点共用质量与代码差异选择。冠军优先保留，少量近期且评价不足的Explore方向获得有限保护。每次选入候选，同时补齐必要最近共同祖先（Lowest Common Ancestor, LCA）与路径上的初始算法，按完整集合核算容量。结构补入的算法也参与后续距离比较。公式、参数和采用依据见[树状种群管理](树状种群管理.md)。

**反思简化。** 保留集合确定后，每个移除节点归入一个整理区域：

| 操作 | 结构变化 | 经验归属 |
| --- | --- | --- |
| 路径收缩 | 删除保留祖先与后代之间的中间节点，直接重连两端 | 新边的变异经验 |
| 分叉整理 | 删除不通向任何保留后代的旁支 | 最近保留祖先的选择经验；虚拟根承接被淘汰的初始方向 |

例如A→B→C→D只保留A与D时，B、C的修改与结果凝练到A→D。如果A的另一子代E被淘汰且没有保留后代，E的尝试整理到A上。旧经验随承载它的节点或边进入下一轮整理。

程序提供真实代码、相对实际父代的差分、评价、错误和已有经验；模型联系这些尝试中的算法思想与结果，压缩为对计算过程的认识，供后续设计参考。经验不要求逐项罗列修改，也不规定下一步动作。两端分数变化由程序计算。反思输入与输出约定见[反思简化设计](反思简化设计.md)。

重构后，全部可行节点都能参与搜索；每个算法只有一条入边；节点数满足容量上限，连接存活分支的必要分叉保持显式连接。

## 6. 选择父代与生成算法

**预算分配。** 当前采用ShinkaEvolve式自适应加权父代采样，适应度越小越好：

$$
\text{采样权重}=\operatorname{sigmoid}\!\left(10\frac{\text{适应度中位数}-\text{当前适应度}}{\max(\text{中位数绝对偏差},10^{-6})}\right)\frac{1}{1+\text{累计子代数}}.
$$

中位数绝对偏差（Median Absolute Deviation, MAD）不超过 $10^{-9}$ 时，用非零绝对偏差的中位数作为尺度，尺度下限仍为 $10^{-6}$。累计子代数跨重构保留，包含失败和已淘汰尝试。

算子按固定比例抽取：Refine 0.45、Explore 0.30、Crossover 0.25。V2交叉参考先排除主父代与相同源码，在可用参考中统一过滤低质量节点，再优先选未配对且AST结构距离最大的参考；V1保留原小种群全池规则。所有候选均已配对时允许复用；无不同源码参考时改用Refine。精确规则见[V2 allocation.py](../evotrace_v2/allocation.py)。

**生成上下文。** 三个算子直接按树上位置读取材料，在一次调用中输出 `analysis → code → design`：

| 算子 | 读取内容 | 当前设计决定 |
| --- | --- | --- |
| Refine | 根到父代的形成路径、父代的选择经验与近期子尝试、父代代码和成绩 | 下一步改什么 |
| Crossover | 共同祖先及其选择经验、通往两端的分叉路径、参考设计与成绩、主父代代码和成绩 | 借用什么计算、怎样接入 |
| Explore | 不同方向的入口思想、发展经验与相关尝试经验；父代代码 | 获得新鲜的算法思想 |

形成路径中的单步边展示代码差分，收缩边展示阶段经验。Explore将已有思想和经验作为构思材料，明确允许重新选择表示、信息与计算过程，以前瞻、构造后改进、子问题求解作为开放式启发；方向编号、累计评价数与结构筛选信息保留在运行记录中。Crossover的共同祖先只展示一次，两条分支分别展示后续发展。V2默认读取完整相关路径、子尝试和方向，Explore也读取方向内部已凝练的边经验；仅超过实际输入窗口时缩减展示并记录，详见[V2设计](EvoTrace-v2设计草案.md)。展示的差分序列提供起始基准代码；Crossover默认提供参考源码及当前父代近期尝试，参考源码与两种经验展示可独立开关。Explore以入口与近期发展描述连接相关经验。

任务说明明确整体目标、可观察输入、返回对象及外层求解器如何使用它。Refine先展示当前实现，Crossover先展示两份实现，再提供相关发展与尝试；Explore先读思想与经验，再读一个参考实现。生成先简述本次计算选择，再给出完整代码，最后客观描述代码实际实现的核心思想，不要求预测性能。设计描述不要求逐项列举公式、参数或固定句数。初始化强调返回决策对完整解的作用，展示已有思想与成绩，不按成绩排序粘贴全部既有实现；示例代码和失败实现按需提供。超时修复以降低核心计算成本为目标。

## 7. 实现与验证问题

代码与用法见[EvoTrace-V2](../evotrace_v2/README.md)及保留的[EvoTrace-V1](../evotrace_v1/README.md)。当前实现独立持有搜索循环、任务、模型请求、评价进程与记录恢复，并直接管理树更新和区域反思。

[离线选择实验](记录/2026-11-11-统一种群选择离线实验.md)支持统一选择过程满足结构与容量约束。完整搜索的阶段结果和异常分别见[阶段结果](记录/2026-11-12-EvoTrace-V3阶段结果.md)与[机制诊断](记录/2026-11-12-EvoTrace机制诊断.md)。这些结果决定后续修改，不能由代码检查替代。

动态机制首先要检验最近使用、质量保护和预算分配组成的反馈是否支持有效搜索，并核算其模型成本。随后要区分的作用是：两种经验是否改善后续生成；分叉处的选择经验是否补充自身形成路径；三尺度上下文是否优于只读父代代码。对照应分别保持树状种群、预算分配与评价条件一致。
