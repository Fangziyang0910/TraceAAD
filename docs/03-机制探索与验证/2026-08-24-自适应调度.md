# 自适应调度与固定周期对照（V9.17）

## 1. 实验目标与规则设计

检验在一次搜索运行中观察到的正向增益（block gain $g > 0$），是否足以支持自适应延长当前假设的发展（Development）预算，而非机械轮转到发现（Discovery）阶段。

- **实验臂设置**：两臂共用 V9.17 搜索状态、生成与竞争机制，仅改变全体 active sweep 结束后的预算调度规则：
  - **Adaptive**：$g > 0$ 的假设进入下一轮 sweep 继续精炼，直到该轮没有成功假设为止；
  - **FixedCycle**：一轮全体 sweep 结束后立即无条件进入 Discovery 阶段。
- **实验规模**：5 任务 × 3 独立重复，同 seed 配对，共享首次 Development 决策前的 checkpoint，各自运行至 1000 个 primary evaluator slots。

### 2.6 过程量审计

Adaptive 的实际调度因任务结构产生显著分化：

- 每周期平均 sweep 数为 1.59–3.25（CVRP 最高达 2.29–3.25，TSP rep2 最低为 1.59；FixedCycle 恒为 1）。
- Adaptive 机制下每路追加 development blocks 25–103 个；推进局部 hypothesis frontier 2–47 个，推进 global frontier 0–8 个。
- 正 block gain 后下一 block 再成功的比例全部 $\le 0.47$（CVRP 达 0.42–0.47 最高，TSP rep2 与 OP rep3 仅 0.08 / 0.06）。
- Discovery 间隔：Adaptive 平均 30.0–41.3 个 slot，FixedCycle 稳定在 27.6–27.9。

## 3. 机制分析与决策

1. **机制事实**：追加 blocks 能否提高终局质量高度取决于该任务的二次命中率。只有在命中率与追加量最高的 CVRP 上自适应追加才完整成立（held-out 9 格 + 训练三重复全部同向优于 FixedCycle）；而在 TSP 训练侧与 OP 上，由于正增益再成功率极低（0.06–0.24），盲目延长开发反而拖累全局搜索。
2. **控制器决策**：不能简单基于单次局部正增益无节制追加开发预算；后续调度机制必须综合考量局部开发潜力与全局多样性更新，避免在假性突破节点上过度消耗评价资源。
