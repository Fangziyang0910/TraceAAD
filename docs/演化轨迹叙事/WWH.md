# EvoTrace：研究问题与思路

> 演化轨迹叙事。保留迁移时的内容，不再作为当前研究入口；当前设计见[树状种群与反思简化](../树状种群与反思简化.md)。

研究目标是在有限评价预算下找到并持续精炼更好的算法，让设计过程形成的经验帮助后续算法发现。

## 当前叙事：让种群保留自己的演化轨迹

**问题。** 有限预算下，搜索效果取决于每一次评价投向哪个算法，以及每一次修改是否有针对性。这两项决定所需的依据蕴含在演化轨迹中：每个算法由哪些修改逐步形成，从它出发做过哪些尝试，不同设计方向各自取得了怎样的进展。

**原因。** 只维护当前算法，无法表达被淘汰个体的经历；逐步保存全部历史，又使材料持续增长。需要共同决定保留哪些算法、哪些经历，以及以什么粒度表达这些经历。

**思路。** 种群的更新与演化轨迹的整理面对同一批对象，可以统一为对同一结构的更新。EvoTrace由四个部分组成。

1. **树状种群。** 种群是一棵规模有界、持续生长的树。节点是个体，边是亲代—后代关系，边的类型是产生它的算子。可行个体构成种群；失败的尝试作为不可行个体进入树，不能被选中，到下一次反思简化时并入经验并移除。Explore的后代挂在父代之下，设计方向是由Refine边和Crossover边连起来的子树。
2. **反思简化。** 每生成并评价一代后代后，环境选择整理这棵树，它由淘汰和反思简化组成。反思简化沿路径收缩中间步骤，得到边上的变异经验；在分叉处整理后代，得到节点上的选择经验。淘汰算法与凝练经验在同一次更新中完成。
3. **轨迹引导的预算分配。** 依据算法的成绩、发展历程和已有尝试的结果，决定下一批评价的投向。
4. **轨迹引导的生成算子。** 改进读取当前算法的形成过程与已有尝试，融合读取两个算法各自的发展分支，探索读取各设计方向的概貌。

## Base

Base是不利用轨迹经验的基础演化搜索，也是所有比较的共同对照。父代按当前成绩做纯Boltzmann采样，`P(p) ∝ exp(-f(p)/tau)`，成绩越小越好；算子按固定概率选择；交叉参考在共同质量候选池中均匀随机选择。演化生成只读当前算法的代码、自包含设计与成绩，交叉增加参考的设计与成绩。规格见[Base](TraceAAD-Base.md)，选择规则的讨论与证据见[预算选择记录](../记录/2026-11-09-Base预算选择候选.md)。
