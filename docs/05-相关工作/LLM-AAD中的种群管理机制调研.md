# LLM-AAD 中的种群管理：保存、竞争与开发机会

这些方法管理的并非同一个对象：有的保存程序，有的决定谁继续生成，有的保留不同方向，还有的控制程序之间能交换什么信息。把它们都称为“种群管理”，容易误以为换一种容器就会改善搜索。

## 方法之间真正不同的地方

| 方法 | 实际分配或保留的对象 | 对 TraceAAD 的提醒 |
| --- | --- | --- |
| EoH、ReEvo | 按质量或动作类型选择父代，另行决定哪些程序留在种群 | 父代选择与候选存留是两件事。 |
| FunSearch | 多岛内按评价签名分组，再选择程序进入提示 | 信息隔离也会改变生成分布；岛屿数量本身不是收益。 |
| MCTS-AHD | 形成树上的选择、扩展与最大值回传，并使用跨分支精英参考 | 保存谱系不等于给退步节点足够的开发机会。 |
| MAP-Elites、PartEvo | 在行为或表征划出的区域内保留代表 | 区域是否有意义取决于描述器；覆盖率不能代替最好算法质量。 |
| QUBE、Monte Carlo Elites | 依据后代质量或进入档案的频率估计生成起点价值 | 当前质量与后代产出可以不同；区域共享统计还依赖区域内状态足够相似。 |
| ShinkaEvolve | 质量权重叠加较少繁衍次数的优待 | “使用少”记录的是机会，不直接测量新颖性或未来潜力。 |

这些差异见[EoH](https://arxiv.org/abs/2401.02051)、[ReEvo](https://arxiv.org/abs/2402.01145)、[FunSearch](https://www.nature.com/articles/s41586-023-06924-6)、[MCTS-AHD](https://arxiv.org/abs/2501.08603)、[MAP-Elites](https://arxiv.org/abs/1504.04909)、[PartEvo](https://proceedings.neurips.cc/paper_files/paper/2025/hash/e389b15166cf98966ba058965a8c17e3-Abstract-Conference.html)、[QUBE](https://arxiv.org/abs/2412.20694)、[Monte Carlo Elites](https://arxiv.org/abs/2104.08781) 与[ShinkaEvolve](https://arxiv.org/abs/2509.19349)。

## 本地结果怎样限制解释

[BehaveSim 校准](../03-机制探索与验证/2026-09-07-BehaveSim群体距离校准.md)中，CVRP 的距离排序随探针变化较大；按这种距离划区域，很可能把测量不稳误认为搜索状态。[机会评分消融](../03-机制探索与验证/2026-08-25-边界机会评分.md)在 TSP200 退步；OBP 上两种评分规则数学等价，成绩差异来自随机搜索路径，不能算作机会分数的收益。[Pivot 两步干预](../03-机制探索与验证/2026-09-07-Pivot两步价值.md)也没有观察到退步方向在下一次 Refine 中超过起点。

因此，保存一个候选、认为它与别的候选不同、预测它值得继续开发，是三个不同判断。前两个可以用档案和描述器实现；第三个仍要看给定成本后的真实后代，而不能由谱系、距离或低访问次数直接推断。

奖励目标也要分清：全局最好值每次增加的量相加，恰好等于终点最好值相对起点的改善；容易偏离终点目标的是“超父率”或后代平均分等代理量，而不是这项恒等式。
