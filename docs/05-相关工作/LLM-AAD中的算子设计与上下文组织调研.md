# LLM-AAD 中的算子与上下文：模型实际改了什么

给模型一个动作名称或一段历史，只是在改变生成条件。算法是否改变，要检查生成代码的计算、执行时的决策和评价结果。这几层不能由模型自己的说明互相替代。

## 相关方法提供了什么

| 方法 | 做法 | 值得区分的地方 |
| --- | --- | --- |
| EoH | 区分探索、一般修改、调参与去冗余 | 修改意图不同，不保证实码遵从。 |
| ReEvo | 用短期与长期反思指导交叉和精英变异 | 语言反思是建议，并非代码作用的因果解释。 |
| MCTS-AHD | 区分机制修改、参数修改和跨程序参考 | 主父代、参考程序与动作承担不同职责。 |
| DeltaEvolve | 当前代码配多层历史修改摘要 | 模型生成的修改摘要不等于实际 diff。 |
| MEMOIR | 局部诊断与跨分支记忆分开 | 失败记录要连同发生条件保存，不能变成永久禁令。 |
| AlphaEvolve | 同时使用程序数据库、评价反馈与多种输出形式 | 材料选择、修改范围和代码交付方式不应混成一个“算子”。 |

来源：[EoH](https://arxiv.org/abs/2401.02051)、[ReEvo](https://arxiv.org/abs/2402.01145)、[MCTS-AHD](https://arxiv.org/abs/2501.08603)、[DeltaEvolve](https://arxiv.org/abs/2602.02919)、[MEMOIR](https://arxiv.org/abs/2605.17539)、[AlphaEvolve](https://arxiv.org/abs/2506.13131)。

## TraceAAD 的经验

[提示组件配对实验](../03-机制探索与验证/2026-09-03-提示组件与上下文.md)没有发现一种文本改动能跨任务稳定提高单步候选质量；少数均值差受极端程序影响。[五任务强结果形成路径](../03-机制探索与验证/2026-09-09-强结果形成路径.md)则有更具体的代码现象：TSP 的突破改变了求解结构，CVRP 的强结果长期协调已有信号，VRPTW 的前瞻结构要继续修正等待与终止评价。有些 Idea 或代码注释与实码不符，高分也不证明解释正确。

这使“更多历史会帮助设计”的说法过于粗糙。形成链、局部失败和跨分支程序可能分别帮助保留结构、避免重复尝试或引入新计算；但只有材料真正改变了实现和后续结果，才能称为有用经验。[研究主线](../04-研究认识与构想/研究主线与问题.md)保留本地反例。
