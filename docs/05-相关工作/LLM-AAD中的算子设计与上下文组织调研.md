# 算子提示：前沿方法怎样定义一步修改

[相关工作目录](README.md) · [方法总览](AAD代表方法与机制.md) · [LACE 精读](2026-10-07-LACE互补启发式精读.md)

2026-10-09。对象：LACE、EoH、MCTS-AHD、ReEvo、HSEvo、ShinkaEvolve、FunSearch、AlphaEvolve、CALM、PathWise 的实际算子提示，与 TraceAAD V10.22 的真实请求对照。提示文字取自公开代码、补充网页或论文附录，见文末来源。

## 最值得保留的认识

**前沿方法用“改动的种类和大小”定义算子；我们用“本步的成绩目标和立场”定义算子。** LACE 的局部精炼要求“找出一个决策部件（构造步骤、邻域选择规则、平局规则、接受准则、时间分配），只改它”；反思重设计要求“先诊断结构弱点（例如贪心构造没有改进步骤、改进步骤太局部），保留合理部分，替换算法骨架，父代越弱改得越大”。EoH 把“完全不同的形式”“同骨干的新形式”“修改形式”“只改参数”“简化”分成五个算子。我们的 Refine、Explore、Crossover 都写“写出比当前算法分数更好的版本”，区别只在“保留核心思想”“改变计算而不是调参”“借入参考的长处”这类立场。改动具体是什么种类，留给模型自己决定。

**前沿方法至少有一个算子不要求这一步就胜出。** LACE 的差异注入写明“新颖比质量更重要”，重设计“父代越弱越大胆”；EoH e1、Shinka 的 different 变体只要求不同。我们三个算子都以“比当前算法更好”为目标。结构性改动的首版通常更差（[V10.20 重放](../03-现象与检验/2026-10-06-V10.20重放与ACO评价噪声.md)），所以这个目标对所有算子都偏向最安全的改法：在已有打分式上加项、调权。

**前沿方法的材料主要是代码和分数；我们的材料主要是逐步修改历史。** V10.22 的 TSP 与 CVRP 请求中，形成路径占 Refine 提示字符的 72%、Crossover 的 66%–67%。EoH、LACE、FunSearch、Shinka 都不给逐步 diff；ReEvo、HSEvo 只给少于 20–50 词的反思。

## 1. 各方法的算子

| 方法 | 算子 | 父代与材料 | 要求的改动 | 是否要求本步胜出 | 输出 |
| --- | --- | --- | --- | --- | --- |
| LACE | O1 局部精炼 | 偏强父代（概率 ∝ 1/平均排名）；代码与排名 | 只改一个决策部件，其余不动，不重写 | 改善其弱实例 | 只要代码 |
| | O2 反思重设计 | 偏弱父代（概率 ∝ 平均排名） | 诊断结构弱点，保留合理部分，换骨架；父代越弱越大胆 | 否 | 只要代码 |
| | O3 互补交叉 | 在不同实例上强的两个程序 | 按实例特征分派两种策略，或各跑一点后取好的 | 否 | 只要代码 |
| | O4 比较综合 | 同一批实例上的胜者与败者 | 找出胜者做对了什么，加入针对败者教训的修正 | 隐含 | 只要代码 |
| | O5 差异注入 | 组合中全部程序 | 换一个无人使用的范式（如大家都做贪心 + 2-opt，就试 DP、beam search、LNS、ILP 松弛取整） | 否，“新颖更重要” | 只要代码 |
| | O6/O7 修错、提速 | 失败代码与报错，或分阶段耗时 | 最小补丁；保留结构的定向提速 | — | 只要代码 |
| EoH | e1 / e2 | 多个程序及其描述 | e1：形式完全不同；e2：先找共同骨干，再写受其启发的新形式 | 否 | 一句描述 + 代码 |
| | m1 / m2 / m3 | 一个程序 | m1：修改后的不同形式；m2：只改参数；m3：去掉冗余、过拟合部件 | 否 | 一句描述 + 代码 |
| MCTS-AHD | e1 / e2 / m1 / m2 / s1 | 程序带目标值 | 与 EoH 相同的分工；e2 写明“与第 k 个形式相近、受第 1 个启发”；m1 要求“引入新机制、新公式或程序段” | e2、s1 要求低于参考 | 一句描述 + 代码 |
| ReEvo / HSEvo | 交叉 / 精英变异 | 较好、较差两份代码 + 反思 | 按反思改写；HSEvo 另有参数调优（和声搜索） | 否 | 只要代码 |
| ShinkaEvolve | diff / full / cross | 当前程序、指标、灵感程序 | diff：定向修改，不重写；full 五种：默认、完全不同、受上下文启发、结构重组、参数化 | 否 | 名称、描述、代码 |
| FunSearch | 唯一算子 | 按分数排序的 2 个旧版本 | 无指令，续写下一个版本 | 否 | 只要代码 |
| AlphaEvolve | 唯一算子（可演化元提示） | 之前表现好的程序与指标、当前程序 | “提出一个改进想法”，diff 输出 | 否 | diff |
| CALM | 简化 / 注入 / 替换 / 交叉 | 程序与分数分布 | 都限定小改；替换写明三种具体对象（固定规则、常数、平均分配的信用） | 交叉要求更好 | 想法 + 代码 |

## 2. 与 TraceAAD 的差别

| 维度 | 前沿方法 | V10.22 |
| --- | --- | --- |
| 算子由什么定义 | 改动种类和大小，常给出部件词汇 | 本步成绩目标 + 立场；不给部件词汇 |
| 是否有“允许首版更差”的算子 | 有（LACE O2/O5、EoH e1、Shinka different） | 没有，三个算子都要求比当前好 |
| 主要材料 | 代码与分数 | 形成路径占 Refine、Crossover 提示的约 70% |
| 是否看到整个种群 | 探索类算子看多个程序（EoH e1/e2、LACE O5、MCTS s1） | Explore 只看当前程序和从它出发的尝试 |
| 父代与算子的配合 | LACE：强父代局部改，弱父代重设计 | 所有算子共用同一父代选择 |
| 交叉的伙伴 | LACE：实例上互补，或同批实例的胜负对 | 档案较好的一半中代码差异大者；V10.21 有 85% 比当前程序总分差 |
| 写代码前的文字 | 多数只要代码，或一句描述 | Analysis + Design + Code |

最后一行有直接证据。V10.22 只把 Refine 的 Analysis 从“什么限制当前算法”改为“什么限制当前算法的成绩”，Refine 从便宜程序出发时加入计算的比例就从 20%–28% 降到 2%。一句分析要求就能这样改变行为，而且这种影响事先难以预测。前沿方法多数不强制写分析。

## 3. 对 V10.22 TSP 停滞的解释

V10.22 的 TSP 几乎不再增加计算，停在单步打分式。真实请求说明了模型怎样理解这一步：

- 一次 Refine 的形成路径有 8 步，几乎都是在调整距离项和回程项的权重。模型的分析写道“第 7 步的 n^-0.5 衰减有效”，然后退回上一版、把权重改成 0.4。
- 一次 Crossover 的当前程序与参考程序只差一个系数。模型的分析是“参考用 0.25，当前用 0.5”，于是把系数改成 0.25。

LACE O2 举的结构弱点之一是“贪心构造没有改进步骤”。在我们的 TSP 接口里，与之对应的正是 V10.21 最好程序的结构：对候选补全剩余路线，再用 2-opt 改进这条路线。V10.22 三路约 2,100 个程序中，只有一次 Refine（第 616 次）在模拟路线上写了 2-opt，而且超时。我们的提示没有定义“结构改动”是什么，形成路径又示范了几十步调权重，模型自然按调权重来理解“改进”。

前沿提示的这些做法也不是都经过检验。LACE 正文没有逐个算子的消融；EoH 的算子消融只说明组合有用。我们自己的重放还说明：写明做法或去掉历史后，计算增加 12–17 倍，但首版成绩没有变好，这类结构需要开发才能成立。所以能借鉴的是算子的定义方式，不是具体措辞。

## 4. 建议的最小检验

在 V10.22 前期的便宜状态上做固定父代重放（TSP、CVRP、OP，各取第 50–150 次附近的父代），每组生成相同次数：

1. V10.22 Refine，原样。
2. 局部改动：“找出当前代码中的一个决策部件并只改它，其余保持不变”；材料只有任务、当前代码和分数；只要求 Design 和代码。
3. 结构重设计：“说明当前函数每次调用计算了什么、缺少什么结构，保留合理部分，替换计算骨架”；不要求这一步就超过当前程序；材料同第 2 组。
4. 第 3 组，再加 LACE 式的通用结构例子（例如“只有一步打分，没有对剩余部分的构造或改进”）。这一组与“提示不写方向”的规则冲突，只作为区分解释的干预。

测量加入计算的比例、改动的种类（加打分项、加构造、加改进）、首版相对父代的成绩；第 3、4 组再各做 3 步 Refine 开发后比较。判断规则：如果第 3 组就能出现补全或改进结构，而且开发后不劣于第 1 组，就说明问题在算子定义和材料，按第 2、3 组重写算子。如果只有第 4 组出现这类结构，就要重新讨论“提示不写方向”的边界。如果各组都没有，限制来自模型先验或接口，改提示收益有限。
