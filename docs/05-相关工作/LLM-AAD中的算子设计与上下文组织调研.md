# 算子设计与生成上下文

[相关工作目录](README.md) · [方法总览](AAD代表方法与机制.md)

算子表达本次修改的意图，上下文提供代码、历史与参考。两者共同参与候选形成：修改要求引导设计方向，参考材料提供已有计算和试验经验，代码与执行结果呈现最终实现。

## 修改意图与参考材料的配合

| 方法 | 做法 | 机制含义 |
| --- | --- | --- |
| `EoH` | 区分探索、一般修改、调参与去冗余 | 动作提示表达修改偏好，生成代码呈现实际实现。 |
| `ReEvo` | 用短期与长期反思指导交叉和精英变异 | 反思将质量差异转为后续生成的文字建议。 |
| `MCTS-AHD` | 区分机制修改、参数修改和跨程序参考 | 主父代、参考程序与动作承担不同职责。 |
| `DeltaEvolve` | 当前代码配多层历史修改摘要 | 语义摘要表达改动含义，代码 diff 保存具体变化。 |
| `MEMOIR` | 局部诊断与跨分支记忆分开 | 失败条件为经验检索提供适用范围。 |
| `AlphaEvolve` | 同时使用程序数据库、评价反馈与多种输出形式 | 数据库、提示和输出协议分别参与材料选择、修改与交付。 |

修改要求和上下文材料承担不同作用。动作提示表达探索、精炼或融合的偏好，主程序与参考程序提供计算起点，历史和反思提供过去试验中的反馈。

## 本地试验中的文本、代码与算法变化

本地结果的解释落在具体计算变化上。[提示组件配对实验](../03-机制探索与验证/2026-09-03-提示组件与上下文.md)尚未观察到跨任务稳定提高单步质量的文本改动，少数均值差受极端程序影响。[强结果形成路径](../03-机制探索与验证/2026-09-09-强结果形成路径.md)则记录了具体修改：TSP 改变内部求解方法，CVRP 持续调整已有信号，VRPTW 引入前瞻后继续修正等待与终止评价。部分 Idea 或注释与实际代码存在出入，反映了设计说明与实现之间的差异。

形成历史、局部失败记录与跨分支参考，可能分别帮助保留有效计算、减少重复尝试和引入其他方法。代码变化与后续结果为这些解释提供检验依据。项目的研究问题见[研究主线](../04-研究认识与构想/研究主线与问题.md)。
