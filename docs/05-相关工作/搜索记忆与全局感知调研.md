# 搜索记忆与全局感知调研

[相关工作目录](README.md) · [算法设计中的直觉判断](../04-研究认识与构想/算法设计中的直觉判断.md) · [Jev 原理与特性](../04-研究认识与构想/Jev决策模型的原理与特性.md)

本文调研 LLM 自动算法设计中怎样保存、整理和使用搜索经验，并从"全局记忆 + 直觉判断"的角度整理对 TraceAAD 的启发。资料来自本地论文源码与 2026 年的 arXiv 预印本。

## 结论

1. **现有记忆几乎都用来改变生成内容，很少用来改变预算去向。** 多数方法把经验写成建议，放进生成提示。父代选择、算子份额与停止仍由分数规则决定。Sedima、EvoMem、SeaEvo 都明确写出"不改变父代选择"。
2. **记忆的组织单位正在从"程序"移向"思想"。** MEMOIR 以设计为分支，PACEvolve 维护思想池，SeaEvo 按策略族分组，Back to the Beginning 把知识当成搜索对象。但多数方法用文本嵌入聚类或谱系来定义"同一思想"。只有 PACEvolve 用 LLM 判断新想法与已有想法是否概念相同。
3. **结构比数量重要。** 有证据表明，只给模型更多历史没有用，整理后的结构才有用：LinTree 发现原始历史不如显式树结构。Sedima 去掉聚类层后收益减半。EvoMem 的随机记忆只带来 5.6% 的收益。
4. **写记忆和读记忆都交给大模型的长文本推理。** 写入靠反思或总结请求，读取靠模型在长上下文中自由判断。这正是我们在 Jev 实验中看到的风险：问法决定答案，模型偏向熟悉的方向。
5. **空白。** 没有方法把记忆建立在一组便宜、校准、针对单一关系的判断上，再用代码维护按思想组织的时间线，用比较式判断分配预算。这是 TraceAAD 可以形成工作的位置。

## 分析框架

比较一个记忆机制，问五个问题：

| 问题 | 含义 |
| --- | --- |
| 单位 | 一条记忆记的是什么：程序、改动、建议、思想、组件 |
| 写入 | 谁写、何时写；依据什么材料 |
| 组织 | 按什么归组：时间、谱系、文本相似、语义判断 |
| 读取 | 谁读、读多少；检索还是全读 |
| 作用 | 改变哪个决定：生成内容、参考程序、父代、算子、停止 |

前四项决定记忆里有什么，第五项决定记忆有没有改变预算。

## 方法

### 一、文字经验池：把试验压缩成建议

| 方法 | 单位 | 写入 | 组织与读取 | 作用 |
| --- | --- | --- | --- | --- |
| ReEvo | 短期反思（一对程序的好坏比较）与长期反思 | 每代由反思模型写 | 长期反思逐代改写 | 交叉与精英变异的提示 |
| HiFo-Prompt | 洞见（设计原则） | 每代从精英程序提取；Jaccard 相似度去重 | 按效用分数取前几条；效用 = 效果 − 使用次数惩罚 + 近期奖励；效果按后代分数用 EMA 更新 | 生成提示 |
| RefineEvo | 正负经验：改动摘要、建议、适用条件 | 每次评价后比较子代与父代；显著变好或变差才写 | 按语义相似检索；按下游结果更新效用并修剪 | 生成提示 |
| ShinkaEvolve | 元草稿：程序摘要、全局洞见、实现建议 | 每 T 代总结一次 | 全部附在提示后 | 生成提示 |
| MeEvo | 元洞见：收敛诊断、局限分析、改进路径 | 每个周期读全部推理记录、分数与错误 | 整体使用 | 生成新程序 |
| Sedima | 三层：原始记录、洞见、洞见簇 | 每次评价后由 LLM 写一条洞见 | 嵌入聚类（相似度 0.8）；检索 3 簇、每簇 3 条，合成 3 条建议 | 只进入变异提示，不改选择与种群 |
| EvoMem | 思想卡与程序卡 | 运行结束后离线写；LLM 判断是否为同一机制再合并 | 多历史材料检索，至多 3 张卡 | 只进入变异提示，跨运行迁移 |
| FormuEvo | 条件—策略—效果条目 | 成功与失败的改动都写 | 搜索后再提炼成与问题无关的知识 | 生成提示，跨问题迁移 |

**证据。** Sedima 在 AlgoTune 与 ALE-Bench 上平均提升 5.5% 与 6.6%，按评价次数计，达到基线最好成绩所需的步数少 32.3%。它增加了蒸馏与合成请求，未按总调用量比较。消融中，无记忆 1.61，随机检索 1.62，只有洞见层 1.65，完整三层 1.69。EvoMem 在 Circle Packing 上，随机记忆只补上 5.6% 的差距，只检索不过滤 18.7%，完整方法 97.4%。

**认识。** 记忆的内容要与当前状态相关，随机或泛泛的建议几乎没有作用。这些方法改变的都是"生成什么"，不是"在哪里生成"。

### 二、改动记忆：保存"怎样变好"

| 方法 | 单位 | 组织 | 作用 |
| --- | --- | --- | --- |
| DeltaEvolve | 语义差：FROM/TO 思想摘要（20–40 tokens）、逐项改动与假设、完整代码 | 三层逐级展开 | 用改动代替整份代码作为参考，节省上下文 |
| PhyloEvolve | 改动轨迹（状态、改动、分数增量）与高价值改动目录 | 按谱系组织成树与森林；改动按平均增益、方差与次数打分 | 下一步提案的上下文；Designer 在停滞时另起一棵树 |

DeltaEvolve 的对照实验值得注意：在 AlphaEvolve 框架中，遮掉分数只保留高分代码，效果接近标准做法。随机选上下文程序却保留分数，效果明显下降。**选什么材料，比告诉模型分数更重要。** 这与本项目的认识一致：展示的尝试会被模仿。

### 三、按思想组织的记忆

这一类最接近"专家记得几个思想各自的经过"。

**MEMOIR。** 每个分支对应一个算法设计。分支内保存每次修复与改进的记录和评论。分支结束时，反思把整个分支压缩成一条约 272 tokens 的全局记忆：设计与核心启发式、限制改进的失败或停滞模式、给后续提案的回避指令。新分支的提案读全局记忆，以避开已试过的设计。预算只有 16 次执行，分支数与分支深度是固定参数。

**PACEvolve。** 把"思想"（例如"给优化器加 Nesterov 动量"）与"假设"（某组超参数）分开，维护一个持久的思想池：
- 新提出的思想先经过 LLM 分类器，判断是否与池中已有思想概念相同。相同则归入已有思想，否则新建。
- 每个思想下的假设数有上限，达到上限就把实验历史总结成要点。
- 思想数也有上限，达到上限由 LLM 丢弃最没有希望的方向。被丢弃的失败永久记录，防止重新发现。
- 用"相对进展"的指数平均作为动量，低于阈值时回退到更早的状态，或与其他岛交叉。
- 选哪个思想，由智能体读完整个思想池后决定。

消融显示，层次化上下文提高了平均和最好结果，但如果当时最好的思想是局部最优，它不会被淘汰。加上动量回退后，最差的运行被消除。

**SeaEvo。** 每个程序附一段策略描述及其嵌入。策略族由嵌入的 k-means（5 族）每代重算。每 10 代，LLM 读全部策略描述与分数，把各族标为有效、饱和或未充分探索，并写出指导。指导只进入提案提示。父代选择不变。参考程序按与父代的互补覆盖选取。Circle Packing 上，只加这一判断时平均从 2.502 升到 2.563，三项都加为 2.630。

**Back to the Beginning。** 把知识（设计原则）当作搜索对象，代码只用来检验知识。它给出一个"失真—压缩"权衡：以思想为单位，会丢掉实现细节（失真）。但搜索空间更小，泛化更好（压缩）。思想单位有利的条件是"一致"：属于同一思想的程序，质量相近。

**AutoSND。** 先让 LLM 对每个程序写统一的结构描述（结构族、局部信号、邻域范围、更新方式、高代价结构），再由代码统计各结构项在好、差、慢、失败程序中的比例，最后由 LLM 读统计写出"复用、避免、界限"三类规则。这是"语义标注 + 代码计数 + 归纳"的分工。

**BEAM。** 单位是可复用的函数组件。精英程序中的函数进入组件库，按适应度、新颖性、使用次数与年龄打分，生成时只提供函数名与用途供直接调用。

### 四、全局状态感知与搜索控制

| 方法 | 感知的全局状态 | 控制的决定 | 由谁判断 |
| --- | --- | --- | --- |
| RefineEvo Planner | 种群收敛与多样性、各算子近期有效率与成功率 | 搜索模式与算子子集；算子长期无效时改写其提示 | LLM |
| HiFo-Prompt Navigator | 停滞与进展计数、Design 文本互不相同的比例 | 探索、开发或平衡三种模式，转成提示中的设计指令 | 阈值规则 |
| PACEvolve | 相对进展的动量 | 回退或跨岛交叉 | 公式 |
| CORAL | 智能体自读共享记忆（尝试、笔记、技能） | 心跳机制定期提醒反思、整理笔记，停滞时转向 | 智能体自身 |
| MeEvo | 收敛状态分类（早熟、稳步、振荡、停滞） | 生成内容 | LLM |
| Clade-AHD | 一个子树全部后代的评价，汇总为 Beta 分布 | 用 Thompson 采样选扩展点 | 公式 |
| GAE | 程序 AST 的图嵌入 | 父代与改动种类，由强化学习策略选择 | 学习的模型 |

只有少数方法让全局状态改变预算去向。Clade-AHD 与 PACEvolve 的单位是一组程序，但组由谱系或时间定义，不由语义定义。

### 五、为什么需要整理过的记忆：现象研究

- **LLM 变异会回到同一形态。** Mutation Without Variation：没有选择压力时，87% 的变异链中超过 93% 的变异回到已见过的结构形态，变化多是常数替换。
- **原始历史不够，结构要显式。** LinTree：让模型看完整推理轨迹，并不能稳定超过只看当前状态的启发式搜索。在轨迹中标出"回到了哪个状态"之后，任务表现与搜索效率都提高。
- **反复改写会丢失细节。** ACE（Agentic Context Engineering）把反复整体改写导致记忆越来越短、细节消失的现象称为 context collapse，并改用逐条增量更新。
- **进展集中在前期。** RelayEvolve 发现搜索进展高度前置，前期轨迹的表现有信息量，但噪声大。

## 横向认识

**1. 记忆写给生成器，不写给分配。** 大部分方法的逻辑是：经验 → 建议 → 生成更好的程序。预算分配仍是"按分数选父代"。但本项目的观察是，搜索的预算大量落在同一思想的调参版本上（CVRP 第 300 次，前 24 个程序中 21 个是同一思想）。这种浪费发生在分配层，生成提示改不了它。

**2. "同一思想"的判断方式决定记忆的质量。** 现有做法有三种：

| 做法 | 代表 | 问题 |
| --- | --- | --- |
| 谱系 | PhyloEvolve、Clade-AHD、MEMOIR | 后代可能换了思想（Explore），不同谱系可能收敛到同一思想 |
| 文本嵌入聚类 | SeaEvo、Sedima、ShinkaEvolve 拒绝采样 | 措辞相近不等于计算相同；ShinkaEvolve 中嵌入足以识别近似重复代码，LLM 新颖性判断只带来边际提升 |
| LLM 判断 | PACEvolve 分类器、EvoMem 合并、V12.0 匹配 | 由生成模型写长回复，成本高；判断标准随提示变化 |

识别"几乎相同的代码"，嵌入已经足够。识别"代码不同、主计算相同"，需要读代码的语义判断。

**3. 写入时的压缩方式决定记忆是否可信。** 反思与总结由生成模型自由写出，会编造或泛化。Sedima 与 MEMOIR 都要求记忆链接回原始证据。AutoSND 的做法更稳：LLM 只给每个程序写结构标注，统计由代码完成。

**4. 读取时的决策方式决定记忆是否被正确使用。** 把整个记忆放进长上下文，让模型自由决定（PACEvolve 的思想选择、CORAL 的智能体），等于把综合判断交给一次推理。本项目的 Jev 实验显示，这类综合判断会退化成"选分数最好的"，并且随问法变化。

**5. 证据强度。** 多数方法的消融只在一两个任务上，多为单次运行。比较按评价次数，不按总调用量。可以相信的共同结论是：相关的、整理过的记忆有用。随机或泛泛的记忆没有用。显式结构比原始历史有用。

## 对 TraceAAD 的启发

### 可以直接借用的做法

| 做法 | 来源 | 在本项目中的用途 |
| --- | --- | --- |
| 思想与具体实现分层 | PACEvolve、DeltaEvolve | 一个思想下记录多个实现与改动 |
| 每条记忆链接原始证据 | Sedima、MEMOIR | 思想记录中每个结论都指向具体尝试 |
| 语义标注 + 代码统计 | AutoSND | 判断由 Jev 给出，计数与时间线由代码维护 |
| 失败永久记录 | PACEvolve、MEMOIR | 被否定的思想不再被当成新思想 |
| 饱和与未充分探索的标记 | SeaEvo | 由比较式判断得出，并直接作用于名额 |
| 增量更新，不整体改写 | ACE | 思想记录逐条追加，避免压缩丢失细节 |

### 现有方法没有做的事

**用直觉判断建立思想级记忆，并让记忆直接决定预算。** 具体是三层分工：

1. **写记忆：原子判断。** 每次尝试结束后，用 Jev 回答几个关系问题：这个程序属于哪个已有思想（同一）。这次是否检验了它的设计（检验）。这次改动属于哪类（覆盖）。每个问题只读少量材料，便宜，正反顺序可平均。
2. **维护记忆：代码。** 每个思想一条记录：出现时间、各次实现与成绩、各类改动的次数与结果、最近一次进展的时间、阅读与失败的记录。由代码追加与计数，不由模型改写。
3. **读记忆作决定：比较式判断。** 在思想之间比较："哪个已给够尝试""哪个相对前景尝试太少""停止哪个最后悔"。名额在思想之间分配，再在思想内选版本与改动种类。

与最接近的工作相比：

| | PACEvolve | SeaEvo | 本构想 |
| --- | --- | --- | --- |
| 思想如何界定 | 生成模型分类新提案 | 嵌入 k-means | Jev 读代码判断主计算是否相同 |
| 思想记录 | 假设历史，达到上限后由 LLM 总结 | 策略描述与分数 | 代码维护的时间线与计数，带证据来源与推理过程接 |
| 谁决定投入 | 智能体读全部记忆自由决定；动量触发回退 | 父代选择不变，只改提示 | 比较式判断给出名额，代码组合 |
| 作用的决定 | 思想选择与回退 | 生成提示 | 名额在思想间分配、思想内选版本、改动种类 |

### 要先回答的问题

1. **"同一"判断在整场搜索的规模上是否稳定。** 判断要一致：同一程序不能在不同时刻归入不同思想。随着程序增多，组不能链式合并成一个大组。可以离线在已有记录上增量建组，检查稳定性。
2. **思想单位是否"一致"。** Back to the Beginning 的条件是同一思想的程序质量相近。V9.21 中，同一设计的两份实现有 30.1% 结果类别不同。这说明思想的价值不能由一次实现代表，要汇总多次实现。这正是思想级记忆要做的事，但也意味着思想内仍要选版本。
3. **现在的预算实际怎样分布在思想上。** 用已有记录离线统计：每个思想得到多少尝试、何时停滞、停滞后还得到多少尝试。这能直接说明分配层浪费了多少，以及思想级分配有多大空间。
4. **最终检验靠运行搜索。** 离线统计只用于确认机制按设计工作。机制是否有效，看固定协议下实际搜索的结果。
