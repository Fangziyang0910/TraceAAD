# 高层算法与求解器设计

自动算法设计的对象可以是评分函数、算法组件、启发式集合、问题约简、完整求解器或设计器本身。不同对象开放的决策范围、评价方式和部署成本并不相同。

## 从单个规则到互补集合

EoH-S 直接优化启发式集合的实例覆盖；InstSpecHH 为不同实例选择成员。集合收益来自算法之间的互补性，部署时则需要决定如何选择或组合。这个方向适合任务分布明显分化、单一规则难以覆盖的情形。

集合设计需要衡量程序在不同实例上的互补性，部署时还要决定选用哪个成员。它与在生成阶段融合多个程序的计算不同：前者保留多个求解器，后者产出一个新程序。

## 框架也是设计变量

RedAHD 搜索问题约简与模板，A2DEPT 开放完整 solver，BEAM 分开算法结构和函数实现，DGA²D 用算子图生成 pipeline。它们都把原来由人固定的控制流程带入设计空间。

分层有一个自然优势：模型可先讨论结构选择，再集中实现组件。困难也随之明确——结构变化可能让原有组件失效，局部表现未必解释整体性能。阶段执行反馈、组件接口和可复用代码可以帮助协调这些变化。

## 设计器本身能否被设计

MoH 将优化器作为外层对象，用它产生下游启发式并评价跨任务效用。Hercules 和 AutoSND 则从现有程序中提炼组件或结构策略，改善后续搜索效率。这里出现了一条连续谱：复用算法组件、学习设计建议、演化设计过程。

## 从函数槽位逐层扩大设计空间

设计对象可拆成问题表示、算法骨架、组件、参数和运行控制。EoH-S 主要改变规则集合与实例覆盖；RedAHD 改变问题约简；A2DEPT 和 BEAM 开放更多求解器结构。它们的搜索空间并不因都输出代码而相同，比较成绩时需要同时看评价预算、有效候选比例和部署成本。

## 相关工作与来源

<a id="paper-10"></a>
### EoH-S

演化互补启发式集合，以逐实例最优成员的平均表现评价集合覆盖，贪心保留互补成员。实际部署还需要成员选择策略。

来源：论文：*EoH-S: Evolution of Heuristic Set using LLMs for Automated Heuristic Design*；本地来源：`eohs.tex`；设计对象：一组协作/组合使用的启发式，而非单一启发式。

原文入口：[arXiv:2508.03082](https://arxiv.org/abs/2508.03082)

<a id="paper-29"></a>
### RedAHD

连同问题约简、实例映射、解映射和模板一起搜索，使启发式设计能够更换基础求解框架。

来源：论文：*Reduction-Based End-to-End Automatic Heuristic Design with Large Language Models*；本地来源：`papers/RedAHD_Reduction_Based_End_to_End_Automatic_Heuristic_Design_with_Large_Language_Models/main_neurips.tex`；设计对象：从问题描述到可执行启发式的端到端 COP 设计。

原文入口：[arXiv:2505.20242](https://arxiv.org/abs/2505.20242)

<a id="paper-30"></a>
### Hercules

抽象精英计算组件来指导生成；扩展版本预测候选性能和置信度，以选择性真评减少搜索时间。

来源：论文：*Efficient Heuristics Generation for Solving Combinatorial Optimization Problems Using Large Language Models*；本地来源：`papers/Efficient_Heuristics_Generation_for_Solving_Combinatorial_Optimization_Problems_Using_La/sample-sigconf.tex`；设计对象：GLS、构造式、ACO 启发信息与 NCO attention 重塑。

原文入口：[arXiv:2505.12627](https://arxiv.org/abs/2505.12627)

<a id="paper-31"></a>
### MoH

外层生成启发式优化器，内层在多任务上评价其产出，以跨任务效用选择元优化器。

来源：论文：*Generalizable Heuristic Generation Through LLMs with Meta Optimization*；本地来源：`papers/Generalizable_Heuristic_Generation_Through_LLMs_with_Meta_Optimization/main.tex`；设计对象：生成“生成/改进启发式的优化器”，而非仅一条启发式。

原文入口：[arXiv:2505.20881](https://arxiv.org/abs/2505.20881)

<a id="paper-32"></a>
### InstSpecHH

离线生成实例子类的启发式库，近邻迁移扩充候选，在线按实例特征选择算法。

来源：论文：*LLM-Driven Instance-Specific Heuristic Generation and Selection*；本地来源：`papers/LLM_Driven_Instance_Specific_Heuristic_Generation_and_Selection/main.tex`（含 `section/framework.tex`、`section/experiments.tex`、`supp_content.tex`）；设计对象：按实例生成并选择启发式，而非一个全局规则。

原文入口：[arXiv:2506.00490](https://arxiv.org/abs/2506.00490)

<a id="paper-33"></a>
### A2DEPT

搜索完整 solver，保存程序树，结合退火接受与历史节点抽样探索结构变化，并用维护闭环处理开放代码。

来源：论文：*A2DEPT: Large Language Model–Driven Automated Algorithm Design via Evolutionary Program Trees*；本地来源：`papers/A2DEPT_Large_Language_Model_Driven_Automated_Algorithm_Design_via_Evolutionary_Program_T/paper.tex`；设计对象：完整可执行 solver 程序。

原文入口：[arXiv:2604.24043](https://arxiv.org/abs/2604.24043)

<a id="paper-34"></a>
### BEAM

外层 GA 搜索算法结构，内层 MCTS 完善函数实现，外部记忆维护可复用函数并配合参数校准。

来源：论文：*BEAM: Bi-level Memory-adaptive Algorithmic Evolution for LLM-Powered Heuristic Design*；本地来源：`papers/BEAM_Bi-level_Memory-adaptive_Algorithmic_Evolution/bare_jrnl_new_sample4.tex`，含 `sections/beam_framework.tex`、`sections/benchmark.tex`、`sections/experiments.tex`、`sections/appendix.tex`；设计对象：完整求解器（算法结构 + 函数实现）。

原文入口：[arXiv:2604.12898](https://arxiv.org/abs/2604.12898)

<a id="paper-51"></a>
### DGA²D

用带实现的算子图描述算法，策略采样 pipeline，将终端收益分配给实现转移和边，再调整图与策略。

来源：论文：*DGA²D: Directed Graph-Guided Automated Algorithm Design*；本地来源：`papers/DGA2D_Directed_Graph_Guided_Automated_Algorithm_Design/paper.pdf`；设计对象：由功能算子有向 walk 组成的完整算法 pipeline。

原文入口：[arXiv:2608.00700](https://arxiv.org/abs/2608.00700)

<a id="paper-52"></a>
### AutoSND

先广搜并记录执行状态和操作，再形成结构策略指导后续树搜索，分别追求质量与速度。

来源：论文：*AutoSND: From Execution Evidence to Structural Policies for Automated Network Dismantling Heuristic Discovery*；本地来源：`papers/AutoSND_Execution_Evidence_to_Structural_Policies/paper.pdf`；设计对象：完整网络拆解程序。

原文入口：[arXiv:2608.03653](https://arxiv.org/abs/2608.03653)
