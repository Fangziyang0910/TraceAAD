# LLM-AAD 中的程序交付：哪些想法真正进入评价

输出形式会影响一个算法想法能否变成被评价的程序。截断、补丁定位失败或要求额外说明，可能让可用的代码消失；这时“没有好后代”混合了算法质量和交付损失。

## 方法差异

| 方法 | 交付方式 | 可观察的取舍 |
| --- | --- | --- |
| EoH | 同次响应给思想和代码 | 说明可帮助表达意图，也会占用输出。 |
| ReEvo | 代码生成与反思调用分开 | 只要求代码的响应不等于整个搜索没有语言反馈。 |
| MCTS-AHD | 先生成代码，后用额外调用描述 | 事后描述仍需与实际代码核对。 |
| AlphaEvolve | 可用完整代码或精确匹配的编辑 | 较短补丁需承担基底匹配和重建失败。 |
| ShinkaEvolve | 支持多种改写和重采配置 | 生成轮数不能直接当作模型调用或有效候选数。 |

来源：[EoH](https://arxiv.org/abs/2401.02051)、[ReEvo](https://arxiv.org/abs/2402.01145)、[MCTS-AHD](https://arxiv.org/abs/2501.08603)、[AlphaEvolve](https://arxiv.org/abs/2506.13131)、[ShinkaEvolve](https://arxiv.org/abs/2509.19349)。

## 本地经验

V10.13 的接口试验出现过可解析代码因外围文字被拒收，也出现过参考程序进入提示却没有改变算法决策的情况。前者是候选交付损失，后者是经验没有落实；两者不能合称“方向没有潜力”。完整代码、结构编辑和多轮修复哪种更有效，本地还没有固定状态、固定总成本的对照。[V10.13 机制](../01-主线机制设计/TraceAAD-V10.13-机制设计.md)与[W39 记录](../06-总结与周报/2026-W39.md)保留当时的观察。
