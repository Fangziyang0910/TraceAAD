# 代码交付与评价成本

[相关工作目录](README.md) · [方法总览](AAD代表方法与机制.md)

输出形式参与决定哪些算法进入评价。完整代码、局部编辑和额外说明，分别涉及输出长度、程序重建与解析约束；截断和格式失败则影响有效候选的形成。

## 交付形式与资源消耗

| 方法 | 交付方式 | 交付特点 |
| --- | --- | --- |
| `EoH` | 同次响应给思想和代码 | 说明可帮助表达意图，也会占用输出。 |
| `ReEvo` | 代码生成与反思调用分开 | 代码响应和反思调用分别承担实现与反馈。 |
| `MCTS-AHD` | 先生成代码，后用额外调用描述 | 额外调用提供候选描述，代码保留实现细节。 |
| `AlphaEvolve` | 可用完整代码或精确匹配的编辑 | 较短补丁需承担基底匹配和重建失败。 |
| `ShinkaEvolve` | 支持多种改写和重采配置 | 重采配置影响每轮的调用数与有效产出。 |

交付成本由生成、解析、重建和修复共同构成。生成轮数描述搜索步骤，模型调用数描述请求数量，有效候选数描述成功进入评价的产出，三者对应不同的计数口径。

## 本地接口试验中的接受与执行

V10.13 的接口试验记录了两个环节的现象：部分可解析代码因外围文字被拒收，部分参考程序进入提示后未改变算法决策。前者体现接受规则的影响，后者呈现参考材料的实际使用情况。

本地对完整代码、结构编辑与多轮修复的认识仍来自接口观察，固定状态、固定总成本的比较尚未完成。[V10.13 机制](../01-主线机制设计/TraceAAD-V10.13-机制设计.md)与[W39 记录](../06-总结与周报/2026-W39.md)保留当时的依据。
