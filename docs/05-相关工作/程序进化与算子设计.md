# 程序进化与算子设计

[相关工作目录](README.md) · [方法总览](AAD代表方法与机制.md)

程序进化通过反复生成、评价和选择候选来设计算法。语言模型负责提出修改，任务接口限定可改的计算范围，搜索过程决定哪些程序成为后续生成的起点。

## 修改范围与生成方式

修改范围决定模型可以提出哪类算法变化。`ELM` 以代码 diff 表达修改，`LMX` 通过多个父代的条件续写实现重组，`FunSearch` 将变化集中在固定骨架中的关键函数。`EoH` 则用不同提示表达探索、结构修改、调参和简化，使生成带有明确的设计意图。

代码变化对算法行为的影响取决于改动位置。一行阈值可能改变全部选择，大段重写也可能保留原排序。`Controlling Mutation` 直接控制代码修改比例，`HSEvo` 将结构生成与数值优化分开，`EvoStage` 以阶段反馈组织设计，分别处理修改幅度、参数校准和阶段协调。

## 参考材料与候选形成

模型可以利用参考材料构思和实现候选。`AlphaEvolve` 使用参考程序，`LMX` 提供多个父代，`RoCo` 让不同角色讨论并整合建议。这些方式分别引入可复用代码、组合起点和协作意见，同时承担检索、协调或额外模型调用的成本。

每次生成多少候选、由哪个模型生成，也会影响搜索。`ShinkaEvolve` 与 `TurboEvolve` 同时管理模型、程序档案或批量生成，规定每次尝试的候选数量与后续开发方式。批量提出候选侧重拓宽当轮选择，连续修改侧重利用已有反馈。

相关方法的具体做法见[算子与上下文综述](LLM-AAD中的算子设计与上下文组织调研.md)。

## 论文笔记

<a id="paper-01"></a>

### `ELM`（Evolution through Large Models）

`ELM` 用代码 diff 模型生成程序变异，根据父程序与修改消息生成候选。`MAP-Elites` 保存不同机器人的高质量程序，搜索产物同时用作条件生成训练数据。

- 论文：*Evolution through Large Models*
- 本地资料：`papers/Evolution_through_Large_Models/main.tex`
- 研究对象：可执行 Python 程序（Sodaracer 的生成程序）。

论文链接：[arXiv:2206.08896](https://arxiv.org/abs/2206.08896)

<a id="paper-02"></a>

### Language Model Crossover（`LMX`）

`LMX` 用多个父代的条件续写实现重组，少量父代按顺序进入 few-shot prompt；父代排序同时影响模型的继承偏好。

- 论文：*Language Model Crossover: Variation through Few-Shot Prompting*
- 本地资料：`papers/Language_Model_Crossover_Variation_through_Few_Shot_Prompting/main.tex`
- 研究对象：字符串、表达式、图像提示与 Python 程序。

论文链接：[arXiv:2302.12170](https://arxiv.org/abs/2302.12170)

<a id="paper-03"></a>

### Evolving Code with a Large Language Model

Formulate–Interface–Check 为 `GP` 中的初始化、选择、交叉和变异提供统一接口，该工作关注各环节交给 LLM 的收益与成本差别。

- 论文：*Evolving Code with a Large Language Model*（Hemberg, Moskal, O'Reilly，MIT CSAIL，期刊版）
- 本地资料：`papers/Evolving_Code_with_A_Large_Language_Model/ELM_GP_jrnl_2023.tex`
- 研究对象：符号回归 Python 表达式（框架化论文）。

论文链接：[arXiv:2401.07102](https://arxiv.org/abs/2401.07102)

<a id="paper-04"></a>

### `FunSearch`

`FunSearch` 将设计范围限定在固定骨架中的关键函数，以分数与程序长度组织岛内采样。多个岛及周期重置维护不同探索方向。

- 论文：*Mathematical discoveries from program search with large language models*
- 本地资料：`s41586-023-06924-6.pdf`
- 研究对象：数学构造或算法骨架中一个可执行的关键函数。

论文链接：[DOI:10.1038/s41586-023-06924-6](https://www.nature.com/articles/s41586-023-06924-6)

<a id="paper-05"></a>

### `EoH`（Evolution of Heuristics）

`EoH` 用思想与代码共同表示个体，以相异重组、共同思想扩展、结构修改、调参和简化五类提示表达设计动作，配合排名选择与精英截断。

- 论文：*Evolution of Heuristics Towards Efficient Automatic Algorithm Design Using Large Language Models*
- 本地资料：`main.tex`
- 研究对象：组合优化问题的启发式函数/代码。

论文链接：[arXiv:2401.02051](https://arxiv.org/abs/2401.02051)

<a id="paper-07"></a>

### `HSEvo`

`HSEvo` 将算法结构与数值参数交给不同搜索方式：`GA` 和反思寻找骨架，和声搜索校准模型生成的参数。

- 论文：HSEvo
- 本地资料：`papers/HSEvo/aaai25.tex` 与 `appendix.tex`
- 研究对象：组合优化启发式代码（BPO、TSP-GLS、OP-ACO）。

论文链接：[arXiv:2412.14995](https://arxiv.org/abs/2412.14995)

<a id="paper-11"></a>

### Controlling the Mutation in LLMs

修改比例是 Controlling the Mutation in LLMs 控制变异幅度的依据。请求比例来自重尾分布，行级提示表达修改要求，代码差异用于测量遵从度。

- 论文：*Controlling the Mutation in LLMs for Efficient Evolution of Algorithms*
- 本地资料：`samplepaper.tex`
- 研究对象：LLM 生成的算法代码变异。

论文链接：[arXiv:2412.03250](https://arxiv.org/abs/2412.03250)

<a id="paper-12"></a>

### `AlphaEvolve`

`AlphaEvolve` 以父程序、参考程序和反馈作为代码 patch 的生成条件，用数据库管理候选，级联评价逐步筛选可执行且高质量的修改。

- 论文：AlphaEvolve
- 本地资料：`main.tex` 及 `methods.tex`、`results.tex`、`ablations.tex`、`appendix.tex`
- 研究对象：可执行程序中的可演化函数。

论文链接：[arXiv:2506.13131](https://arxiv.org/abs/2506.13131)

<a id="paper-13"></a>

### `ShinkaEvolve`

`ShinkaEvolve` 在档案式程序进化中管理模型来源和重复候选，多模型 bandit 调节生成来源，嵌入拒绝采样减少近重复提议。

- 论文：ShinkaEvolve
- 本地资料：`main.tex` 与 `sections/`
- 研究对象：可执行优化程序、MoE load-balancing loss、竞赛启发式等。

论文链接：[arXiv:2509.19349](https://arxiv.org/abs/2509.19349)

<a id="paper-14"></a>

### Evolutionary Discovery of RL Algorithms via LLMs

该工作用程序进化设计强化学习的更新逻辑。宏观变异修改语义模块，交叉根据质量与代码距离选择第二父代。

- 论文：*Evolutionary Discovery of RL Algorithms via LLMs*
- 本地资料：`main.tex`
- 研究对象：固定网络与优化器下的 RL 更新规则/损失代码。

论文链接：[arXiv:2603.28416](https://arxiv.org/abs/2603.28416)

<a id="paper-39"></a>

### `RoCo`

`RoCo` 通过 explorer、exploiter、critic 和 integrator 的角色分工讨论并融合候选，外层进化选择组织后续开发。

- 论文：*RoCo: Role-Based LLMs Collaboration for Automatic Heuristic Design*
- 本地资料：`papers/RoCo_Role_Based_LLMs_Collaboration_for_Automatic_Heuristic_Design/main.tex`
- 研究对象：ACO 启发信息及角色化 LLM 协作流程。

论文链接：[arXiv:2512.03762](https://arxiv.org/abs/2512.03762)

<a id="paper-55"></a>

### `EvoStage`

`EvoStage` 以顺序阶段组织算法设计，中间执行反馈为后续方向提供依据，并与整体探索、整体改进算子配合。

- 论文：*Advancing Automated Algorithm Design via Evolutionary Stagewise Design with LLMs*
- 本地资料：`papers/EvoStage_Evolutionary_Stagewise_Algorithm_Design/paper.pdf`
- 研究对象：多阶段优化算法与调度规则。

论文链接：[arXiv:2603.07970](https://arxiv.org/abs/2603.07970)

<a id="paper-58"></a>

### `TurboEvolve`

`TurboEvolve` 用一次调用产生多个候选，按岛的停滞程度配置候选数。聚类播种、跨簇注入和精英保留共同组织多方向搜索。

- 论文：*TurboEvolve: Towards Fast and Robust LLM-Driven Program Evolution*
- 本地资料：`papers/TurboEvolve_Fast_and_Robust_LLM_Driven_Program_Evolution/paper.pdf`
- 研究对象：多岛程序进化及 warm-start seed pool。

论文链接：[arXiv:2604.18607](https://arxiv.org/abs/2604.18607)

<a id="paper-68"></a>

### `REvolve`

`REvolve` 将奖励函数分量作为进化对象，以人类偏好和 Elo 提供评价反馈，岛内变异与杂交维护不同奖励设计。

- 论文：*REvolve: Reward Evolution with LLMs using Human Feedback*
- 本地资料：LaTeX 源码目录 `REvolve_Reward_Evolution_with_LLMs_using_Human_Feedback/`
- 研究对象：RL 的奖励函数（Python 代码种群），评价为人类 pairwise 偏好 + Elo 与自然语言反馈的组合 $F:\Omega\to\mathbb R\times\mathcal L$。

论文链接：[arXiv:2406.01309](https://arxiv.org/abs/2406.01309)
