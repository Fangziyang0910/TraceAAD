# 程序进化与算子设计

相关工作将语言模型用于生成程序变化，再由评价和搜索过程决定哪些候选得到保留。不同方法主要区别在改动对象、操作粒度、参考材料和候选保留方式。

## 从代码变异到设计动作

ELM 用 diff 学习协调修改，LMX 用多个父代的条件续写实现重组，FunSearch 将搜索集中到固定骨架中的关键函数。EoH 再把修改意图分成探索、结构改写、参数调整与简化。这几条路线共同建立了一个清楚的接口：父程序、任务和修改意图进入模型，可执行候选返回搜索器。

这些工作中的“算子”并非统一对象：LMX 的多父续写侧重程序重组，EoH 的提示动作区分探索、修改与简化，FunSearch 则将生成限制在固定函数槽位。是否真正形成不同算法行为，需要看生成后的代码和执行结果，不能只依据提示中的动作名称。

## 改动粒度与参数校准

Controlling Mutation 直接要求修改一定比例的代码，HSEvo 则把结构生成与数值优化分工，EvoStage 把复杂设计拆成可反馈的阶段。代码改动量与决策变化不等价：一行阈值可能改变全部选择，大段重写也可能保留原排序。

上述方法分别把改动粒度交给生成模型、提示动作或外层搜索器控制。比较它们时，需要区分局部参数校准、组件替换和整体结构改变所开放的设计空间。

## 参考与协作怎样产生收益

AlphaEvolve 的 inspirations、LMX 的多父代和 RoCo 的角色讨论都扩大了一次生成可利用的材料，也分别增加了参考检索、协调或多模型调用成本。它们对一次候选形成过程的干预不同，不能只用参考数量比较。

ShinkaEvolve 和 TurboEvolve 将生成来源、候选批量与档案组织结合。单轮多候选与多轮连续修改使用预算的方式不同，所观察到的收益也不能直接归因于某一个算子。

## 相关工作与来源

<a id="paper-01"></a>
### ELM（Evolution through Large Models）

代码 diff 模型根据父程序与修改消息生成变体，MAP-Elites 保存不同机器人的高质量程序；搜索产物再用于条件生成训练。

来源：论文：*Evolution through Large Models*；本地来源：`papers/Evolution_through_Large_Models/main.tex`；设计对象：可执行 Python 程序（Sodaracer 的生成程序）。

原文入口：[arXiv:2206.08896](https://arxiv.org/abs/2206.08896)

<a id="paper-02"></a>
### Language Model Crossover（LMX）

把少量父代按顺序放进 few-shot prompt，以续写完成重组；父代排序同时改变模型的继承偏好。

来源：论文：*Language Model Crossover: Variation through Few-Shot Prompting*；本地来源：`papers/Language_Model_Crossover_Variation_through_Few_Shot_Prompting/main.tex`；设计对象：字符串、表达式、图像提示与 Python 程序。

原文入口：[arXiv:2302.12170](https://arxiv.org/abs/2302.12170)

<a id="paper-03"></a>
### Evolving Code with a Large Language Model

以 Formulate–Interface–Check 统一 GP 中的初始化、选择、交叉、变异等接口，突出各环节交给 LLM 的收益与成本差别。

来源：论文：*Evolving Code with a Large Language Model*（Hemberg, Moskal, O'Reilly，MIT CSAIL，期刊版）；本地来源：`papers/Evolving_Code_with_A_Large_Language_Model/ELM_GP_jrnl_2023.tex`；设计对象：符号回归 Python 表达式（框架化论文，非新机制论文）。

原文入口：[arXiv:2401.07102](https://arxiv.org/abs/2401.07102)

<a id="paper-04"></a>
### FunSearch

固定算法骨架，进化关键函数；岛内按分数与程序长度采样，多个岛保留探索方向并周期重置。

来源：论文：*Mathematical discoveries from program search with large language models*；本地来源：`s41586-023-06924-6.pdf`；设计对象：数学构造或算法骨架中一个可执行的关键函数。

原文入口：[DOI:10.1038/s41586-023-06924-6](https://www.nature.com/articles/s41586-023-06924-6)

<a id="paper-05"></a>
### EoH（Evolution of Heuristics）

以思想与代码表示个体，组合相异重组、共同思想扩展、结构修改、调参和简化五类提示，配合排名选择与精英截断。

来源：论文：*Evolution of Heuristics Towards Efficient Automatic Algorithm Design Using Large Language Models*；本地来源：`main.tex`；设计对象：组合优化问题的启发式函数/代码。

原文入口：[arXiv:2401.02051](https://arxiv.org/abs/2401.02051)

<a id="paper-07"></a>
### HSEvo

将结构生成与参数优化分工：GA 和反思寻找骨架，和声搜索校准模型生成的数值参数。

来源：论文：HSEvo；本地来源：`papers/HSEvo/aaai25.tex` 与 `appendix.tex`；设计对象：组合优化启发式代码（BPO、TSP-GLS、OP-ACO）。

原文入口：[arXiv:2412.14995](https://arxiv.org/abs/2412.14995)

<a id="paper-11"></a>
### Controlling the Mutation in LLMs

通过重尾分布采样请求修改比例，再用行级修改提示控制变异幅度；代码差异用于测量遵从度。

来源：论文：*Controlling the Mutation in LLMs for Efficient Evolution of Algorithms*；本地来源：`samplepaper.tex`；设计对象：LLM 生成的算法代码变异。

原文入口：[arXiv:2412.03250](https://arxiv.org/abs/2412.03250)

<a id="paper-12"></a>
### AlphaEvolve

父程序、参考程序和反馈共同驱动代码 patch，数据库管理候选，级联评价逐步筛选可执行且高质量的修改。

来源：论文：AlphaEvolve；本地来源：`main.tex` 及 `methods.tex`、`results.tex`、`ablations.tex`、`appendix.tex`；设计对象：可执行程序中的可演化函数。

原文入口：[arXiv:2506.13131](https://arxiv.org/abs/2506.13131)

<a id="paper-13"></a>
### ShinkaEvolve

档案式程序进化结合多模型 bandit 与嵌入拒绝采样，分别调节生成来源和近重复候选。

来源：论文：ShinkaEvolve；本地来源：`main.tex` 与 `sections/`；设计对象：可执行优化程序、MoE load-balancing loss、竞赛启发式等。

原文入口：[arXiv:2509.19349](https://arxiv.org/abs/2509.19349)

<a id="paper-14"></a>
### Evolutionary Discovery of RL Algorithms via LLMs

把强化学习更新逻辑作为程序进化对象，宏观变异修改语义模块，交叉根据质量与代码距离选择第二父代。

来源：论文：*Evolutionary Discovery of RL Algorithms via LLMs*；本地来源：`main.tex`；设计对象：固定网络与优化器下的 RL 更新规则/损失代码。

原文入口：[arXiv:2603.28416](https://arxiv.org/abs/2603.28416)

<a id="paper-39"></a>
### RoCo

explorer、exploiter、critic、integrator 分工讨论并融合候选，外层继续用进化选择。

来源：论文：*RoCo: Role-Based LLMs Collaboration for Automatic Heuristic Design*；本地来源：`papers/RoCo_Role_Based_LLMs_Collaboration_for_Automatic_Heuristic_Design/main.tex`；设计对象：ACO 启发信息及角色化 LLM 协作流程。

原文入口：[arXiv:2512.03762](https://arxiv.org/abs/2512.03762)

<a id="paper-55"></a>
### EvoStage

把设计分成顺序阶段，用中间执行反馈修正后续方向，再与整体探索、整体改进算子结合。

来源：论文：*Advancing Automated Algorithm Design via Evolutionary Stagewise Design with LLMs*；本地来源：`papers/EvoStage_Evolutionary_Stagewise_Algorithm_Design/paper.pdf`；设计对象：多阶段优化算法与调度规则。

原文入口：[arXiv:2603.07970](https://arxiv.org/abs/2603.07970)

<a id="paper-58"></a>
### TurboEvolve

一次调用产生多个候选，按岛的停滞程度调节候选数；聚类播种、跨簇注入与精英保留组织多方向搜索。

来源：论文：*TurboEvolve: Towards Fast and Robust LLM-Driven Program Evolution*；本地来源：`papers/TurboEvolve_Fast_and_Robust_LLM_Driven_Program_Evolution/paper.pdf`；设计对象：多岛程序进化及 warm-start seed pool。

原文入口：[arXiv:2604.18607](https://arxiv.org/abs/2604.18607)

<a id="paper-68"></a>
### REvolve

进化奖励函数的分量，以人类偏好和 Elo 提供反馈，岛内变异与杂交维护不同奖励设计。

来源：论文：*REvolve: Reward Evolution with LLMs using Human Feedback*；本地来源：LaTeX 源码目录 `REvolve_Reward_Evolution_with_LLMs_using_Human_Feedback/`；设计对象：RL 的奖励函数（Python 代码种群），评价为人类 pairwise 偏好 + Elo 与自然语言反馈的组合 $F:\Omega\to\mathbb R\times\mathcal L$。

原文入口：[arXiv:2406.01309](https://arxiv.org/abs/2406.01309)
