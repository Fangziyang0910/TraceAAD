# 反馈与实现协议

生成协议规定模型输出什么，反馈协议规定解析、执行或评价失败后怎样继续。相关工作的接口从固定函数槽位到完整程序、从整体代码到局部编辑各不相同；比较时需要区分设计自由度和输出形式。

## 设计对象与输出格式

固定任务中的启发式函数、完整求解器和算法集合是不同设计对象。输出一整段 Python，并不意味着搜索空间已经扩展到整个求解器：EoH/MEoH 的函数可以被提取后嵌回任务模板，FunSearch 也围绕固定骨架开放函数槽位。讨论自由度时，应看哪些计算允许改变。

完整代码易于表达结构变化；精确编辑能保留宿主代码并减少无关重写。AlphaEvolve 的 SEARCH/REPLACE 提供了后一种方式，也允许输出完整代码。这是表达方式的差异，不自动扩大可变的算法范围。

输出格式影响候选的解析与接受。额外的结构字段能够保留意图，也增加格式约束；解析成功率、合法程序拒收率和真实算法质量衡量的是不同环节。

## Idea 的作用是提出和说明设计

Idea 或自然语言说明记录生成意图，代码和执行反馈记录实际发生的变化。ReEvo 的反思、MCTS-AHD 的摘要与代码编辑协议处于不同环节，不能把文字说明直接当作机制执行证据。

额外的摘要或反思调用会增加生成成本，也可能改变下一轮模型看到的信息。MCTS-AHD 的二次摘要侧重保存搜索经验，AlphaEvolve 的编辑机制则控制程序修改形式，两者不承担同一职责。

说明长度与信息完整度有取舍：短说明易于控制上下文成本，长说明可能包含具体计算，也可能重复背景。方法比较时需要分开记录说明、代码和执行反馈各提供了什么信息。

## 失败怎样变成下一次生成的材料

| 反馈 | 说明了什么 | 可采用的后续动作 |
|---|---|---|
| 解析失败 | 响应未形成明确、可接收的候选 | 确定性提取与接口检查；必要时一次格式修复 |
| 运行异常、超时、非法返回 | 候选未完成任务要求 | 给出报错位置、接口条件或时限，进行有界修复 |
| 有效但质量下降 | 本次算法改动在评价集上退步 | 保存父子计算差异，供继续开发或换向 |
| 重复代码 | 再次提出已知程序 | 单独记录，并按重复策略决定是否再评价 |
| 基础设施故障 | 本次没有得到可信的候选评价 | 修复设施并按预算规范结算 |

反思、修复和重采样改变候选生成分布。ReEvo 侧重从质量差异提炼改进意见；带错误反馈的调试器侧重恢复可执行性；丢弃失败候选则把预算留给其他提议。它们利用的反馈内容与额外成本不同。

有界修复与多轮调试都会消耗生成或评价资源。报告收益时，需要区分从不可执行变成可执行，以及在可执行候选之间进一步提高质量。

## 评价预算与生成成本

文献的计数单位包括模型调用、候选生成、实际评价以及有效评价。比较效率前应核对各方法的预算定义；未进入评价的生成请求也会产生模型成本。

重复代码与解析错误也应分开：前者可能是合法候选，是否跳过评价取决于去重规则；后者尚未形成可评价对象。预算不计入某项，并不意味着它没有消耗模型调用和时间。
