# 相关工作

这里按研究问题查阅 LLM 驱动的自动算法设计工作。阅读时先比较模型看到了什么、实际生成了什么，以及哪项对照帮助解释变化；方法中的树、记忆、种群和规划提供不同实现供比较。

[代表方法与机制](AAD代表方法与机制.md)概括各方法的设计对象和主要做法，下面的专题展开具体论述。同一方法可能出现在多篇文档中，因为它同时涉及生成、选择或学习。

## 按轨迹用途横向比较

下表按研究对象和决策用途组织论文笔记。

| 使用什么过程信息 | 使用者与决定 | 现有笔记入口 |
| --- | --- | --- |
| 当前程序的形成关系、父子修改与路径历史 | 生成器；下一次修改、路径扩展和参考 | [经验记忆与条件生成](经验记忆与条件生成.md)：DeltaEvolve、PhyloEvolve；[路径规划](机会分配与搜索规划.md)：MCTS-AHD、PathWise、PoH |
| 程序／分支的后代结果、访问与多条搜索的投入 | 选择器、预算控制器；起点、扩展、开发深度和转向 | [机会分配](机会分配与搜索规划.md)：QUBE、Clade-AHD、BaSE |
| 同分支试验、跨分支经验与检索到的适用建议 | 生成器或策略；参考什么经验、从哪里开始、下一步怎样改 | [记忆与检索](经验记忆与条件生成.md)：ReEvo、MEMOIR、RefineEvo |
| 全局访问、重访、分布和停滞的过程 | 分析者；解释生成偏好与搜索竞争，是否用于在线策略另查 | [搜索行为](多样性与搜索行为.md)：Mutation Without Variation、Fitness Landscape、Code Evolution Graphs |
| 搜索请求、动作及其评价结果构成的训练样本 | 生成模型或动作策略；后续生成、动作选择及经验复用 | [模型学习](搜索经验与模型学习.md)：CALM、EvoTune、AHD-Agent |

同一方法可能连接多个用途。保存历史、检索其中一部分、在线作决定、更新模型参数是不同环节。候选算法的求解轨迹与LLM推理文本也应和算法设计的搜索轨迹分开。

本地方法和实验用同一组问题定位：用了什么轨迹、谁使用、改变哪个决定、结果与成本怎样。见[轨迹用途索引](../01-搜索方法/搜索轨迹的记录与使用.md)。
