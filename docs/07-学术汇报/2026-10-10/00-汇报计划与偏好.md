# 2026-10-10 晚学术汇报：计划与偏好

> 2026-10-10汇报记录，部分解释已于10月11日纠正。本文与演示素材保存当时叙述，不构成独立验证或当前论文定位；当前目标见[研究主线](../../04-研究认识与构想/研究主线与问题.md)。

## 场合与形式

- 听众：导师和同学。
- 内容：通用智能优化领域认识，AAD 相关工作与研究认识，TraceAAD 核心机制，实现与实验效果，总结与下一步。
- 形式：HTML slide，配学术风格示意图和简单动画。
- 语言：约 80% 向 ASD-STE100 靠近。它是表达原则，不要求中文机械遵守英文技术词典。落实为：短句，一句一个意思，术语稳定，先结论后解释，一页一个结论。保留必要的科研精度。
- 技术：每页一个 HTML（1920×1080），内联 SVG 和少量 JS，`deck/index.html` 拼接并带概览墙。位置：`deck/`。风格：已选定"论文插图风"（米白底、衬线、青绿主线、橙红焦点、图带编号），见 `deck/direction-approved.md`。
- 工作方式：一步一步讨论，不一次考虑全部。

## 总体认识

汇报是一条闭环：领域地图 → 我们的认识 → 由认识推出的机制 → 机制的证据 → 回到地图指出下一步。

- 机制不是模块列表。每个关键设计对应 Part 2 中的一个认识。
- 重点是"形成了什么认识"，不是"读过多少论文"。
- 进化过程不只是代码搜索。代码生成之前的分析与决策是另一个要研究的对象。

## 五个部分

### Part 1　研究领域：通用智能优化在做什么

- 流程：自然语言问题 → 优化问题建模 → 算法选择 → 算法配置 → 必要时自动算法设计（AAD）→ 求解与评估。
- 目的：解释各项研究任务之间的关系，不罗列整个领域。
- 聚焦：我们当前研究其中的 AAD。
- 图：动态领域地图。后面 Part 5 回到这张图。

### Part 2　研究认识：我们逐渐理解了什么

- 材料：EoH、AutoMOAE、LACE 及其他 LLM 驱动的算法进化方法。
- 要回答的问题：
  - 当前 AAD 方法实际在搜索什么？
  - LLM 在算法进化中承担什么角色？
  - 代码生成之前的 Analysis 有什么作用？
  - Design 与 Code 是什么关系？
  - 为什么有些进化机制能改进算法，另一些失败？
- 图：几张对比图。
  - 传统进化：候选算法的生成与评估。
  - LLM 带来语言层面的分析与设计。
  - 由此提问：进化是代码搜索，还是应该关注代码生成之前的决策？
- 要求：展示认识，不展示文献数量。

### Part 3　核心机制：TraceAAD（V10.17）

- 以 V10.17 为准，不逐版本介绍。写法像一篇论文的引言加方法：针对什么问题、提出什么机制、解决了什么、效果怎样。重点仍是机制。详见 `03-Part3-TraceAAD机制.md`。
- 每个设计对应 Part 2 的一条认识和一个实测的缺口。
- 动画重点：总框架循环、选择权重变化、一次真实搜索的形成路径（CVRP 第 3 路，42 步）。

### Part 4　实验结果：机制实际表现如何

- 保持科研严谨。图清晰准确，不用炫酷动画。
- 至少三类图：

| 图 | 目的 |
| --- | --- |
| 与代表性 Baseline 对比 | 展示实际效果 |
| 不同任务上的表现 | 判断改进是否有一定普遍性 |
| 关键机制或典型案例 | 解释为什么出现这些结果 |

- 重点指标：held-out 任务表现、平均排名、评估预算公平性。
- 实验条件以 `docs/08-实验规范与共识/README.md` 为准。

### Part 5　研究展望

- 总览一页（`31-outlook.html`，置于总结之后），再每个方向一页（`32-train`、`33-decision`、`34-metric`）。每页：解决什么问题、现在的痛点、大致怎么做，配示意图或动图。三个方向都建立在已记录的改进过程上：
  1. 训练：用搜索记录训练模型，把算法改进的底层模式内化。
  2. 决策：选起点、选算子、选上下文现为概率抽样或固定规则，由决策模型读取搜索状态、预测各选择的收益。
  3. 度量：更稳的算法行为度量（如 BehaveSim），用于判断新设计是否成立，并分配探索与利用。
- 不罗列十几个 Future Work。
