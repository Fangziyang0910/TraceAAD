# V18：同龄竞赛与有限偏差搜索

研究问题与机制设计见[独立方法说明](../../docs/机制设计/V18.md)。

实现依据：[机制设计稿 v1.1](../../docs/TraceAAD：同龄竞赛与有限偏差搜索.md)。V18 的程序评价、结果存储与原子检查点均由本包实现。

- 外层以不同源码起点的开发任务为单位，在年龄 5、10、20……按历史最好质量与当前冠军同龄比较。持平仍合格。冠军参考不足且仍可开发时等待；若冠军已无可用接续，则暂缓该次比较、允许其他任务继续，不虚构缺失成绩。合格任务按年龄、创建顺序选择。
- 内层在每次有效且源码不同的父子比较后保留 FOLLOW 与 RETRY。成绩较好者优先，同分优先父代；另一接续记一次偏差。窗口从 `H=2` 开始，`D=min(H-1,floor(log2(H)))`，窗口完成后深度加一。同一偏差轮次优先早期替代。
- 程序、开发状态、开发任务分开存储。读取已展开状态不调用模型；RETRY 创建新状态，真正重新生成。无有效新候选的重试保持原接续地址，不增加决策深度。路径经验只沿采用的祖先读取；未采纳的有效尝试另列规范化差分，明确标记为未采纳，不混入发展路径。
- 默认五个不同的有效根、最多十六次初始化请求。已存在的有效源码不能再创建零龄任务；记录关联到原来源任务，不重置年龄或历史曲线，调用与评价照常计费。全局改进与上次新起点请求之后均满四十次请求，且至少剩六次请求时发散。
- 普通聊天 API 只需输出完整 Python 源码，不使用 JSON、思想标签、行为签名或额外反思请求。任务模板只提取接口与文档说明，不展示模板函数体。
- 生成提示遵循公共实验协议，不提供实例数量、规模、种子和时间预算。实际失败的诊断信息仍进入对应尝试的反馈。

## 预算、异常与恢复

`budget` 统计所有模型请求，含初始化、Diverge、API 故障、解析失败、无效程序、超时与重复。`generate(..., retry_limit=0)` 关闭模型客户端的隐藏重试；失败后由下一次明确获配的状态重试。源码仅按换行与首尾空白规范化比较，重复候选仍评价和计费。

`max_no_change=3` 限制同一生成操作连续未产生有效新候选的次数。计数键为操作类型与父代／参考源码哈希，跨状态、任务与恢复保存；不提供父代的 Init 共用一个键。Develop 的无新候选包括无效回复、原样复制父代，以及该父代此前已经生成过的有效源码；有效且此前未从该父代生成的不同源码会清零计数。Init/Diverge 的无新起点包括无效结果和本路已存在的有效源码。这里没有行为去重，也不把训练成绩持平当作复制。

尚未取得任何有效起点时，Init 沿用原 `init_attempt_limit=16` 的初始化额度；不同的无效程序不因此在第三次就结束启动。取得首个有效起点后使用三次上限，每次记录实际 `no_change_limit`。生成规则版本为 `v18-repeat-guard-1`，恢复必须匹配此版本，避免将预检或旧规则状态静默续接。

到达上限后，关闭该生成操作在当前运行中的后续调用。遍历器跳过其未展开状态，继续其他可用接续；没有可用接续的任务标为 EXHAUSTED，历史成果保留。开启发散时，无合格开发任务会提前触发新起点入口：先尝试尚未关闭的 Diverge，参考对应的 Diverge 已关闭时使用不提供任何父代的 Init。新起点请求重新计算停滞间隔。所有可用开发与建根入口均关闭时，以 `stop_reason=no_eligible_generation` 提前冻结最好程序，报告实际消耗，不补足虚假调用。关闭发散的消融不启用补充建根；关闭同龄竞赛时开发剩余可用任务中成绩最好者。

训练实例、任务执行限制和最终选择采用[公共实验协议](../../experiments/PROTOCOL.md)。全部任务保存越小越好的 `fitness`；`request.raw_score` 保存评价器原值，`request.quality=-fitness` 保存设计稿使用的越大越好质量。`objective=maximize` 对自定义评价器的原值取反后存入 fitness；当前六任务使用默认 `minimize`。

每次请求发送前保存预算预留及开发状态，收到回复后先保存程序与调用，再执行评价。评价调度器中断时恢复评价，不重发模型请求；发送边界中断、无法确认服务端完成情况的请求保守计费，并记录 `interrupted` 与未知用量。计数摘要按本包的用量估算规则计算，逐调用的原始 `usage` 仍保留，不把缺失用量称为实测值。

`resume.json.state.v18` 保存配置、提示版本、任务、状态树、遍历栈、生成失败计数与待完成请求。恢复要求配置与提示版本匹配。`max_seconds` 在请求之间检查；正在执行的请求由 API 和任务评价超时约束。恢复一个已经取得回复的请求时先完成评价，再冻结结果。

所有有效程序参与最终选择，包括替代分支、重复回复和暂停任务中的程序。同分取最早程序；不重评、不用测试集重新选择。固定程序的独立测试见[测试入口](../../experiments/README.md#3-独立测试)。

## 入口

```bash
uv run python -m experiments.traceaad_v18.run --task tsp_construct --dry-run
uv run python -m experiments.traceaad_v18.launch_host \
  --batch BATCH_NAME --suite co6 --repeats 3 --budget 1000 \
  --backends server3 --eval-workers 8 --output-tokens 8192 \
  --scheduler-socket /tmp/traceaad-1003/scheduler.sock
```

批量入口默认只预览，`--launch` 启动搜索。正式批次使用冻结快照及“搜索 → 冻结结果检查 → 独立主测试”的流水线，具体命令写入批次清单。

四组消融通过 `--no-same-age`、`--no-lds` 组合；`--no-early-first` 改为晚期替代优先。其余初始化、发散、提示与评价相同。`--context-tokens` 为输入与输出共同的上下文上限；默认 32768，先删最旧本地反馈，再删最旧路径片段，保留任务、接口、当前源码及成绩。必要内容仍放不下时报告 `prompt_too_large`，不发送超限请求。

Python 调用方可传 `initial_programs=[Program(..., status="valid", fitness=原始成绩)]` 使用已经评价的起点，最多 `roots` 个。它们只在新运行导入，其原始元数据另存于 `request.acquisition`；来源成本须由调用方提供并在比较时保持一致。

## 验证与日志

当前提示版本为 `v18-context-3`。路径历史与未采纳尝试采用 AST 规范化差分，去掉注释与格式变化；完整父代保持原文并放在历史之后。局部尝试明确标记复制、改善、退化与同分，并说明其差分未被当前路径采纳、错误不代表当前父代无效。Develop 与 Diverge 的主要指令保持不变；用有限重试和实际尝试信息处理重复，不仅依赖禁止复制的措辞。

输出要求为无围栏的完整源码。兼容正常结束但漏写闭合围栏的回复，只移除外层围栏；源码、接口及执行检查照常进行。`finish_reason=length` 仍拒收，不补写或修复代码。此前 context-2 的18组定向配对曾改善复制率，随后完整搜索暴露了重复任务与持续重试循环；该历史小样本不作为本次机制修订的收益证据。[此前审计](../../experiments_result/analysis/v18_prompt_20261029/README.md)。

`20261029_v18_co6` 使用 `20261029_traceaad_v18_final` 的原冻结源码；其中额外提供实例数和运行限制的提示偏离公共协议。随后批次 `20261029_v18_context2_co6` 使用 `20261029_traceaad_v18_context2_frozen` 与 `v18-context-2`。这两批现均已停止，保留全部结果、源码与恢复点；历史运行只能使用自己的冻结源码恢复。[此前重跑记录](../../experiments_result/traceaad_v18/launch_20261029_context2/)保存提示修订的源码校验、配置及停止边界。

当前批次为 `20261029_v18_loopfix_co6`，10月29日15:42（北京时间）从零启动六任务 × 种子0、1、2，各1000次请求上限。源码冻结于 `TraceAAD_runs/20261029_traceaad_v18_loopfix_final`，启动前核对454个文件，使用 `v18-context-3` 与 `v18-repeat-guard-1`。422项测试通过；最终六任务各8次真实预检均取得有效程序并完成独立测试，已知复制父代的12次定向请求验证了关闭条件后不再调用该条件。正式批次继续使用共享模型池和原评价条件，并在预算耗尽或所有生成入口关闭后执行独立主测试。该预检验证搜索闭环，不证明最终算法质量提高。[修订及重跑记录](../../experiments_result/traceaad_v18/launch_20261029_loopfix/README.md)。

[机制测试](../../tests/method/test_v18.py)覆盖原稿的十二项检查以及接口故障、无效值、真实执行超时、发送与评价中断、上下文预算、最大化目标和消融；[入口测试](../../tests/experiments/test_v18_entry.py)核对六任务条件及18路参数传递。

## Python 包入口

本目录自带本版的配置、搜索、提示、选择、个体、评价、历史、状态、存储、执行限制与 `runtime/` 运行实现。公开入口为 `Config`、`Program`、`TraceAAD`、`Evaluation`、`LLM`、`OpenAIAPI`，原有类名 `TraceAADV18` 也可使用。任务评价对象与模型客户端由调用方传入；本包提供源码解析、模型请求、隔离执行和调度客户端。运行需要 Python 3.14 与 NumPy、OpenAI、Requests 等第三方依赖。

```python
from traceaad.v18 import Config, TraceAAD

search = TraceAAD(evaluation=task, llm=client, run_dir="runs/example", config=Config())
summary = search.run()
```

`loop.py` 负责生成、评价、修复与检查点，`search.py` 和包内辅助模块组织本机制。各模块使用包内相对导入；复制整个目录并改名后可作为独立 Python 包导入。实验入口位于 `experiments/traceaad_v18/`，自带运行准备、模型路由、批次启动与存储工具；标准实验从 `benchmarks` 读取任务和数据。
