# TraceAAD V18.1：新思想出生与有限同龄选择

研究问题与机制设计见[独立方法说明](../../docs/机制设计/V18.1.md)。

V18.1 通过出生审核识别实际决策机制，以精炼年龄组织历史比较，并用有限同龄机会补充按质量与直接改进经验进行的父代选择。初始化、Refine、Explore、Crossover 与 Repair 负责形成和修改程序，执行反馈进入后续生成，最终按训练成绩选优。

## 出生与精炼年龄

有效程序先按去掉 docstring 的 Python AST 查重。重复程序保留基础个体记录和评价，但继承首次程序的出生标识与年龄，不重新获得保护。

其他有效程序由独立 `BirthCheck` 请求审核实际代码。审核读取当前程序、主父代、交叉参考和已有机制描述，不读取分数或生成者的设计自述。回复必须给出机制描述、判断依据及当前代码的真实逐字片段。登记表较大时按代码标记集合的 Jaccard 相似度检索，优先保留主父代及参考的机制，直到满足输入上限；每次记录实际检查的出生编号及遗漏数。这不能保证识别未检索到的旧思想。

- 核心决策机制首次有效实现：新 `birth_id`，年龄 0。
- 延续已有机制：继承出生标识，在来源版本年龄上加 1；主父代与参考同属该机制时取较大年龄加 1。
- 旧机制重现但不直接来自该机制的版本：沿用旧标识及额度，年龄取该思想已达到的最大年龄加 1。
- 普通修复与原失败生成合为一个形成步骤，不额外增加一代。
- 审核失败、超出 24000 输入 token 或无法确认：保守继承主父代。无有效父代时建立未确认记录，不授予同龄保护。

出生审核是可检查的启发式，不保证准确识别语义等价或所有思想变化。年龄是精炼深度，不是累计请求成本。

## 比较与预算

保留每个出生标识首次到达每一年龄的成绩，之后不改写该历史。某个个体与其他思想在相同年龄的历史成绩比较，不拿成熟版本的当前成绩作为年轻参照。每个思想在一个年龄最多贡献一份历史记录。

同龄排名使用平滑胜率：`(1 + 胜出数 + 0.5 * 持平数) / (2 + 参照数)`。没有同龄参照时为 0.5。只有该思想当前最深年龄中的最好个体参与同龄通道；同分取较小程序编号。普通通道仍保留基础版全部有效个体。

父代分布为 `0.75 * P_basic + 0.25 * P_same_age`。同龄通道把排名归一化；基础通道仍按当前质量和直接改进率选择。实际抽样先选通道，再选个体，并记录混合概率、通道、排名和参照数。

每个确认的新思想共享 12 次同龄通道选择额度。额度在请求发出前扣除，失败、重复和中断均不退还；追加 Repair 不另消耗保护机会，但仍消耗生成预算。精炼版本和旧机制重现继承已用额度。达到精炼年龄 8 或额度耗尽后，该思想永久退出本轮同龄通道，包括它的低龄旧版本。没有保护候选时全部预算交回基础选择器。参数是本次实验默认值，不代表最优设置。

## 预算与恢复

每路 1000 次生成回复，包含初始化、解析失败及 Repair。最终接口故障沿用基础版成本记录规则，不占生成回复数。出生审核不占这 1000 次，最多每个不同有效程序一次，无内部重试；全部审核请求及用量进入 `calls.jsonl[.gz]`，`stage=birthcheck`，输出上限 2048。因而比较方法时必须同时报告生成次数、总请求数、token 与评价成本。

出生注册表、已用保护机会、去重索引及待审核程序保存在 `resume.json` 的 `state.v18_1`；每个程序的年龄和判定保存在 `request.maturity`。待审核程序恢复时不重新生成或评价。审核发送前预留状态，收到回复后先保存调用及原始回复，再解析；发送边界中断则记一条执行结果未知的请求，保守继承，不重发审核。未知请求的实际用量无法恢复，单列 `uncertain_audit_calls`。`--no-same-age` 保留审核记录，但父代选择回到基础实现及原随机流。

## 实验

`python -m experiments.traceaad_v18_1.run --task tsp_construct --dry-run` 预览单路。六任务 × 种子 0 / 1 / 2 共 18 路，各 1000 次生成。共享模型和 CPU 调度、16 训练实例、50 独立测试实例、生成函数限制沿用公共协议。冻结训练最好程序后再执行主测试，不用测试成绩选优。

## Python 包入口

本目录自带本版的配置、搜索、提示、选择、个体、评价、历史、状态、存储、执行限制与 `runtime/` 运行实现。公开入口为 `Config`、`Program`、`TraceAAD`、`Evaluation`、`LLM`、`OpenAIAPI`，原有类名 `TraceAADV181` 也可使用。任务评价对象与模型客户端由调用方传入；本包提供源码解析、模型请求、隔离执行和调度客户端。运行需要 Python 3.14 与 NumPy、OpenAI、Requests 等第三方依赖。

```python
from traceaad.v18_1 import Config, TraceAAD

search = TraceAAD(evaluation=task, llm=client, run_dir="runs/example", config=Config())
summary = search.run()
```

`loop.py` 负责生成、评价、修复与检查点，`search.py` 和包内辅助模块组织本机制。各模块使用包内相对导入；复制整个目录并改名后可作为独立 Python 包导入。实验入口位于 `experiments/traceaad_v18_1/`，自带运行准备、模型路由、批次启动与存储工具；标准实验从 `benchmarks` 读取任务和数据。
