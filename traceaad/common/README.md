# 共享搜索实现

V12.0 使用这里的一次生成、一次修复、评价、落盘和最终选择。当前实验按训练重评成绩冻结一个程序，再在独立测试集评价。`traceaad/v12_0/` 集中表达搜索规则、配置和提示词。

| 文件 | 职责 |
| --- | --- |
| `search.py` | `Search` 执行初始化、生成与选择 |
| `state.py` | `Facts` 保存程序、尝试、评价和探索；`Progress` 保存恢复进度 |
| `delivery.py` | 提取最终程序，校验任务接口；不补入模板依赖 |
| `evaluation.py`、`probe.py` | 固定种子、隔离评价、超时与调用测量 |
| `instance_evaluation.py` | 六任务共用的逐实例时限、并发执行与资源归还 |
| `prompts.py`、`history.py` | 组织实测历史、失败与修复，裁剪提示词；V12.0 定义任务文字与评价段落，仅展示成绩，使用 Refine、Explore、Crossover 三种步骤 |
| `selection.py` | 质量乘尝试收益；Crossover 参考程序选择 |
| `canonical.py`、`storage.py` | 代码规范化、源码去重、原子提交、调用归档与测试记录 |

## 记录与使用的边界

`state.py`保存搜索事件、程序来源和进度，`history.py`重建形成路径，`prompts.py`选择有限视图，`selection.py`使用质量与直接尝试计数。源码记录、被展示材料和实际选择不是同一层；V12.0 的短程开发主要由固定规则控制。[轨迹用途](../../docs/01-搜索方法/搜索轨迹的记录与使用.md)按研究问题比较这些用法，本页只说明共享实现。

## V12.0 规则

V12.0 独立定义 Refine、Explore、Crossover、随机短程开发、逐实例执行与最终训练重评，并在 Explore 中增加复提接续。它直接使用公共 `Search` 与 `PromptBuilder`，不依赖旧版本。三个实验组只通过配置切换接续和展示概率。

改机制时，修改 `v12_0/` 中的规则与提示。公共层负责执行、评价和记录。历史版本实现已移除，其运行数据仍按原记录解释。

记录格式、实验入口和历史读取见[结果格式](../../experiments/infra/SEARCH_FORMAT.md)。

任务条件在 `benchmarks/tasks.py`，模型请求策略在 `core/llm.py`。`Search` 使用它们的结果，不检查 SDK 私有状态，也不重复构造任务参数。候选在 `core/evaluate.py` 的 `program_context` 中准备种子和测量，然后执行；六任务的基线通过同一安全入口使用逐实例执行器。恢复须先核对运行配置与评价身份；历史复现使用该批次源码，不能用当前评价器续跑旧接口档案。已有结果原样保留。
