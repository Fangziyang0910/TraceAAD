# 当前搜索实现

V10.15–V10.19 共用一次生成、一次修复、评价、落盘和最终选择。版本目录集中表达该版本的规则和提示词。

| 文件 | 职责 |
| --- | --- |
| `search.py` | `Search` 执行初始化、生成与选择；`DevelopingSearch` 在 Explore 抽样时继续开放的改动 |
| `state.py` | `Facts` 保存程序、尝试、评价和探索；`Progress` 保存恢复进度 |
| `delivery.py` | 提取最终程序，校验任务接口；不补入模板依赖 |
| `evaluation.py`、`probe.py` | 固定种子、隔离评价、超时与调用测量 |
| `prompts.py`、`history.py` | 组织实测历史、失败与修复，裁剪提示词 |
| `selection.py` | 质量乘尝试收益；Crossover 参考程序选择 |
| `canonical.py`、`storage.py` | 代码规范化、源码去重、原子提交、调用归档与测试记录 |

## 从版本规则开始阅读

| 版本 | 保留的差异 |
| --- | --- |
| V10.15 | 按程序质量选择父程序；独立的形成路径提示；可选 Design 参考卡片；不测量函数调用数；只评价训练前五名，不替补选择失败的程序 |
| V10.16 | 质量乘尝试收益；展示当前程序的尝试和搜索最优的改进过程 |
| V10.17 | 目标针对当前设计；随机抽取 1/8 新 Explore 程序，最多三步 Refine，每步从已达到的最好版本开始 |
| V10.18 | Explore 抽样继续开放的新设计；开发在进入前五名、停滞或达到上限时结束；上下文只给出原程序的分数和 Design |
| V10.19 | 判断改动能否超过原程序；最多三步 Develop；展示原程序全文；开发的最好结果计入原程序的经验 |

改概率或步数时，直接修改版本 `Config`。改研究机制时，修改版本的选择、停止规则或提示词。共用代码只处理这些版本确实相同的步骤。普通生成准备与开放探索还原只有一份实现，抽样顺序及各版本的开发概率、停止规则、归因规则保留。

记录格式、实验入口和历史读取见[结果格式](../../experiments/infra/SEARCH_FORMAT.md)。

任务条件在 `benchmarks/tasks.py`，模型请求策略在 `core/llm.py`。`Search` 使用它们的结果，不检查 SDK 私有状态，也不重复构造任务参数。候选在 `core/evaluate.py` 的 `program_context` 中准备种子和测量，然后执行；实例隔离由任务负责。当前实现 revision 为 `research-simple-v2-20261006`。
