# TraceAAD V10.14

实现对应[机制设计文档](../../docs/01-主线机制设计/TraceAAD-V10.14-机制设计.md)。主循环采用串行会话；算法实现位于 [traceaad/v10_14](../../traceaad/v10_14/)。没有引入多 agent、在线算子信用或新的 bandit 层。

## 运行

先检查冻结配置，不调用模型、不创建运行目录：

```bash
uv run python -m experiments.traceaad_v10_14.run --task tsp_construct --budget 1000 --dry-run
```

单路运行：

```bash
uv run python -m experiments.traceaad_v10_14.run \
  --task tsp_construct --run-name v1014_trial_1 --budget 1000
```

复用通用批量调度器，先查看计划：

```bash
uv run python -m experiments.launch --method traceaad_v10_14 \
  --batch v1014_trial --tasks tsp_construct online_bin_packing \
  --repeats 3 --run-arg=--budget=1000 --dry-run
```

去掉 `--dry-run` 才会调用模型或启动搜索。后端、模型和运行环境沿用共享入口的参数。结果保存在 `experiments_result/traceaad_v10_14/<task>/<run-name>/`。

搜索、冻结候选和选择集评价完成后，状态为 `finished`。最终程序通过共享测试入口评价：

```bash
uv run python -m experiments.infra.evaluate \
  experiments_result/traceaad_v10_14/tsp_construct/v1014_trial_1 \
  --output-dir experiments_result/v1014_heldout
```

共享监控器支持 `--experiment traceaad_v10_14`。V10.14 的进度横轴是**候选尝试**，不能将其数字与 V10.13 的评价次数直接等同。

## 固定的执行口径

| 机制 | 当前实现 |
| --- | --- |
| 初始化 | 默认 8 次提案，前 4 次独立、后 4 次参考此前有效根；按尝试序号推进。每个有效唯一根最多一次 Refine bootstrap。小预算先将提案数缩为 `min(8, max(1, budget // 2))` |
| 代码身份 | 保存实际评价源码和 SHA-256；不使用 AST 重新生成执行代码。缺失的任务 imports 会显式补入；原始响应另存 |
| 形成事实 | 程序快照、锚点、尝试、评价、请求、修改证据、局部对照分开记录；相同源码允许不同形成状态 |
| 区域 | 初始化结束后，在有效公共状态探针结果上按质量起点＋最远点选择至多 8 个固定参考；距离为决策描述向量的不同比例 |
| 冠军／挑战者 | 同分保留较早冠军；挑战者须代码不同、行为距离至少 0.01 且不为零，质量不低于冠军减 `0.1 × max(abs(q), 1)`；同区挑战者按质量、较早 ID 竞争 |
| 主干 | 冠军质量中秩 `r^-2` 乘有界停滞折扣；默认实质进展阈值 `1e-6`。源路线产出达到检查点阈值的结果可清零；导入冠军只有真实跨阈值才重置 |
| 试用 | 搜索候选预算最多 20%，每票最多 3 步；区域按已消费试用额度反比分配。没有挑战者时第一步发现方向即扣票；新子代和跨区不续票 |
| 试用工作状态 | 沿最新有效且全局未见的子代推进，允许退步；失败或重复保留原工作锚点，最好程序独立保存。票级净收益、全局纪录增量分别记录 |
| 再激活 | 已试用源码不会因新节点 ID 再次获得挑战者资格；新的精确背景比较可使其重新竞争一次，仍要通过质量／差异门槛和预算上限 |
| 局部重验 | 搜索候选预算最多 10%；只尝试活动冠军／挑战者最近相邻两次真实修改。旧修改必须能进入当前证据包；优先停滞区域、高质量状态、较大历史差分与近期状态 |
| 精确闭合 | 唯一文本匹配、同一基底原子编辑、拒绝重叠、原路径及逆向回环精确相等。构造失败保持未知，不让模型补写近似对照 |
| 重验会话 | 一个重建候选＋一个直接后续候选；对照无效则记录未成立并释放未执行额度，不填罚分计算组件贡献 |
| 直接后续 | 从当前程序与对照中质量更高者继续，同分保留当前程序。比较信息包含历史／当前差分、交互、种子面板及结论边界；直接收益与后续收益分开记录 |
| 算子 | 主干合格 Refine:Tune:Transfer 为 2:1:1。Tune 只在显式数值赋值存在时开放；donor 要代码不同，同任务且可执行，有探针时排除相同描述向量 |
| 假设 | 试用从真实修改记录或失败源码建立可修订假设，后续读取同一假设、实际差分和诊断。语法变化与请求契约偏离仅作诊断，不拒收有效候选，也不充当算法语义分类 |
| 上下文 | 默认 4,000 token、6 个事件、1 个 donor，donor 也占证据额度；优先当前重验、直接尝试，再按最近修改涉及函数与近期性取形成证据。保存实际入选与被裁掉的 ID |
| 输出 | 默认完整 Python；也可运行前固定 `--output-mode edit`。拒绝截断、未闭合／多代码块、编辑失配。代码必需，Idea 可缺省；不在运行中静默切换后端 |
| 修复 | 每条错误链最多一次。主干需下次正常获得机会；票内消耗原额度。修复读取失败源码与真实诊断；Edit 修复基底是失败源码 |
| 服务故障 | 记录为服务错误，保留已用成本，不增加算法停滞计数。SDK 重试关闭；连续 3 次服务故障停止运行，不做隐藏免费重采样 |

这些阈值是可运行的首版默认值，不是按测试集调得的最优参数。可通过 CLI 显式调整的参数进入冻结身份；模型参数、算法源码或评价身份变化时拒绝沿用旧运行。

## 评价、行为与资源

公共状态全部由**当前训练评价器的数据**确定，不读取选择集或测试集。TSP、VRPTW 使用训练实例上固定基线的若干可行动作现场；在线装箱使用训练物品序列上的固定 best-fit 状态；ACO 使用训练实例的静态 prior 输入。描述向量分别记录选中节点、前若干名排序或边 prior 的行排序。它们是有限的决策探针，不是算法语义的完整表示。

每次评价先独立计算任务质量，再在新命名空间中运行公共状态探针；探针结果不改变任务分数。探针失败会单独记录，程序仍可按已有任务质量竞争，缺失探针不被解释为新行为。通用自定义任务没有适配器时使用一个明确标记为 `unpartitioned_quality` 的质量区域。

默认种子面板为 `[730241]`，每个种子单独调用安全评价器。候选模块顶层、Python 和 NumPy 全局 RNG 均在加载候选前设种子；ACO 的 solver 种子使用原 `aco_seed + panel_seed`。不承诺控制候选自行引入的系统熵或外部随机源。单种子的正／负结论只称为固定面板观测，不声称统计显著或普适因果效应。可用 `--evaluation-seeds 730241 730242 730243` 明确增加重复和成本。

`--budget` 是包含初始化、无效输出、重复和精确重建的候选次数上限；`--max-evaluations` 默认等于候选上限乘种子数，单独限制搜索执行。完整成功的相同源码／协议／种子面板可复用缓存；失败结果不充当有效分数。每个会话预留整票候选及最坏评价额度，只有未执行预留可释放。

可选 `--max-total-tokens` 以整会话的输入上限＋输出上限保守预留；有实际 usage 时记实际值，缺失时记保守上界。若选择字符估算 tokenizer，token 限制也是该估算口径，不应宣称是服务端精确计数。`--max-seconds` 在搜索调用边界检查，不会中途伪造返回或修改四点比较的单次任务超时。选择集费用单列，不从搜索中偷偷借额度。

程序化 API `TraceAADV1014(..., selection_evaluation=...)` 使用明确的独立选择评价器。没有提供选择评价器时只完成搜索，状态为 `search_complete`，不冒充最终选择完成。

## 最终选择与记录

命令行默认从全档案按训练质量、较早 ID 排序，去重后冻结至多 5 个候选。ACO 使用 `val_50`，保持 ants／iterations／workers，并按选择集与训练集实例数之比放大单次超时，避免将更大的选择集误当作同一执行工作量；TSP、VRPTW、装箱使用与训练规模配置相同、种子为 `20260927` 的独立数据，区别于训练 2024 和最终测试 2025。选择结束不恢复生成；所有选择候选失败则返回 `selection_failed`。

主要产物：

- `search.jsonl`：追加式事实、实际请求、原始响应、执行诊断、会话、预算与恢复状态。
- `logs/run_summary.json`：候选和执行用量、各通道成本、程序数量、最终所选程序；`fitness` 保留训练值，`selection_fitness` 单列。
- `finalists.json`：搜索结束后冻结的候选集合及其源码。
- `selection.json`、`best_program.py`：独立选择结果与实际最终程序。

同配置可续跑；在外部调用开始前写入持久化预留。若中断导致模型／评价结果不确定，拒绝自动重放，避免把一次未知成本调用变成免费机会。已经提交的候选、会话和重验后处理可以按记录恢复。尾部损坏的日志也会明确报错。

## 检查与研究边界

```bash
uv run python -m pytest -q tests
ruff check traceaad/v10_14 experiments/traceaad_v10_14 \
  tests/method/test_traceaad_v1014.py \
  tests/experiments/test_traceaad_v1014_experiments.py
```

测试包括真实执行的合成闭合方格（旧差分 +4、当前差分 −3、交互 −7）、无效对照拒绝、精确编辑、修复计费、提示可见性、退步试用、缓存、协议身份、中断恢复，以及五任务小规模评价和独立选择。测试使用确定的响应替身，不调用真实 LLM；因此不能作为 V10.14 搜索质量提高的证据。

2026-09-27 另对 V10.13 正式批次每任务 `rep1` 的前 100 条有父代和祖父代的有效相邻路径做了只读重建抽查：TSP 0/100、CVRP 0/100、OP 1/100、装箱 4/100、VRPTW 0/100，共 5/500 可精确闭合；5 份重建源码均可编译，但没有执行任务评价。输入为 `experiments_result/traceaad_v10_13/<task>/20260924_v1013_<任务缩写>_v1013_rep1/search.jsonl`。多数拒绝源于修改无法唯一匹配或后续已改变原修改，也有空修改束。

这是旧生成政策下、按时间取样的可构造性诊断，不是 V10.14 在线覆盖率估计，也没有选择只展示成功案例。它说明严格重验可能很少触发。当前实现保留精确条件，提示要求尽量保留无关源码；没有合格重验对象时将机会交回普通开发，不通过放宽反事实身份来制造成功率。

可用 `--recheck-fraction 0` 关闭重验，`--trial-fraction 0` 关闭连续票，`--no-comparison-feedback` 保留重建及候选入档但不把有组织比较交给后续生成。`--evidence-policy none/trajectory/bag/conditional` 控制历史表示。正式因果实验仍需固定锚点或分叉状态、配平成本；直接比较两个不同种子的完整运行不能替代这些对照。
