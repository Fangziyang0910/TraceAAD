# 实验条件与比较

**本页说明当前约定，最终选择规则更新于 2026-10-17。** 一次实验实际用了什么条件，应由该次 `run_config.json`、源码快照和调用记录确定。当前约定不回填历史缺失信息。

## 任务与数据

当前主比较使用 `co6` 六任务。任务注册、数据规模与计算预算见 [benchmarks/tasks.py](../benchmarks/tasks.py)。

| 任务 | 搜索修改的对象 | 最小化目标 |
| --- | --- | --- |
| [TSP](../benchmarks/tsp_construct/) | 固定逐步构造中的 `select_next_node`。 | 平均回路长度。 |
| [CVRP](../benchmarks/cvrp_aco/) | 固定蚁群算法（ACO）的边先验 `heuristics`。 | 平均路线总长。 |
| [FSSP](../benchmarks/fssp_gls/) | 固定引导式局部搜索（GLS）中的 `get_matrix_and_jobs`。 | 平均最大完工时间。 |
| [图着色](../benchmarks/graph_colouring/) | 完整 `solve`。 | 平均颜色数。 |
| [JSSP](../benchmarks/jssp_construct/) | 完整 `solve`。 | 平均最大完工时间。 |
| [OP](../benchmarks/op_aco/) | 固定 ACO 的边先验 `heuristics`。 | 负的平均奖励。 |

统一按 `fitness` 越小越好解释。模板说明函数接口与返回值用途，评价器说明固定框架和合法性检查，数据生成代码说明实例分布与种子。

| 数据条件 | 当前约定 |
| --- | --- |
| 训练 | 每任务 16 个实例。 |
| 同规模测试 | 每任务 50 个实例，与训练使用固定且不重叠的数据划分。 |
| 聚合 | 实例等权；当前六任务没有独立验证集。 |
| 完整求解接口 | 图着色与 JSSP 使用 `full-solver-v1`，与早期优先级函数实验分开比较。 |

## 评价与计算预算

| 任务类型 | CPU 计量范围 | 平均 CPU 上限 | 单实例墙钟上限 |
| --- | --- | --- | --- |
| TSP、CVRP、FSSP、OP | 生成函数及其调用的辅助计算。 | 2 秒／实例。 | 120 秒。 |
| 图着色、JSSP | 生成的完整求解函数及其辅助计算。 | 10 秒／实例。 | 120 秒。 |

全部实例合法完成后，检查：

> 平均 CPU 时间 = 生成函数累计 CPU 时间 ÷ 实例数。

超过平均上限则评价失败；单个实例超过均额不会直接淘汰。墙钟上限从实例进程启动时计时，包含启动和固定框架，不包含等待调度器分配核心的时间。

每个实例进程可新分配的内存上限为 2 GiB（`INSTANCE_MEMORY_BYTES`），由内核的 `RLIMIT_DATA` 执行：超出时分配失败，候选程序得到 `MemoryError`，按运行错误处理。fork 继承的数据段不计入，它主要是父进程未使用的 BLAS 缓冲区；候选程序启动的 BLAS 线程缓冲区按主机核数占用上限中的 0.2–0.5 GiB。六种方法训练最好程序的峰值为 0.10–0.12 GiB，这个上限只拦截失控程序，例如对无限生成器调用 `list()`。评价进程的 `oom_score_adj` 设为 1000，主机内存仍然耗尽时，内核先结束候选程序。2026-10-21 之前的批次没有内存上限。

任一实例报错、返回非法结果、超过内存上限或触及墙钟上限，整次评价失败，并取消剩余实例。成绩不按成功子集计算。时间作为约束，成绩由解的质量决定。

训练、同规模测试和方法执行的最终重评使用上述预算规则。实例隔离执行，BLAS／OpenMP 使用单线程。程序与固定框架的随机种子按实例固定。计量和执行见 [probe.py](../traceaad/base/probe.py)、[instance_evaluation.py](../traceaad/base/instance_evaluation.py)，测试条件见 [evaluation_execution.py](infra/evaluation_execution.py)。

生成提示提供任务、接口、返回值用途、成绩含义和该方法实际展示的反馈。超时修复可以提供实际耗时与时限。

以下内容一律不进入生成提示，现有任务与以后新增的任务都适用，不得加回：

- 实例数量与实例规模，例如节点数、作业数、机器数、顶点数；
- 数据划分与种子；
- 评价记账，例如哪些步骤计时、哪些不计时；
- 时间限制与计算预算；
- 评价器的执行机制，例如每个实例重新执行、输入为副本、成绩不按参照归一化；
- 固定框架的计算量设置，例如迭代轮数、局部搜索次数、蚂蚁数；
- 以“不限制”为名列举的算法方向。

程序在运行时从输入读取规模。所有方法使用同一份任务说明；方法只增加自己的提示结构。[任务检查](../tests/task/test_tasks.py)中的 `test_generation_text_gives_no_instance_count_or_size` 核对六任务的说明与模板，[提示检查](../tests/method/test_prompts.py)中的 `test_task_text_is_the_one_every_method_sees` 核对 TraceAAD 与基线的任务说明一致。

## 搜索预算与最终选择

独立 `traceaad_base` 按[Base机制文档](../docs/TraceAAD-Base.md)运行：每路1000次完整评价，包含初始化、失败与修复重评；模型调用另计。训练和主测试均沿用任务实例与计分规则，全部实例共享总时限，不应用上节的单实例墙钟与平均函数CPU限制。紧凑输出重跑批次按每实例10秒乘实例数设置总时限：训练160秒，主测试500秒；实际条件在运行配置中单独标明。

主比较约定每个方法、每个任务运行 3 路独立搜索，种子为 0、1、2，每路预算为 1000 次生成尝试。这是实验约定，不表示所有批次都已完成。

初始化、解析失败、重复程序、修复和其他生成程序的调用，均按方法规则计入。没有返回程序的接口故障不消耗生成次数，但请求与成本仍需记录。

V18 按其[设计规格](../traceaad/v18/README.md)使用总请求预算：接口故障也消耗一次请求，且不安排隐藏重试；初始化、Diverge 与全部开发请求均计入。历史版本保留原计数规则，比较时分别报告生成结果数、实际请求数与接口故障数。

V18.1 沿用基础 TraceAAD 的生成回复预算，独立 `BirthCheck` 不占生成次数，但审核请求、失败和 token 均记录。每个不同有效程序最多审核一次，审核无内部重试。因而其1000次生成不能与V18的1000次总请求直接当作等成本；比较时另外对齐实际模型请求或token成本。出生与精炼年龄及有限保护规则见[V18.1说明](../traceaad/v18_1/README.md)。

V18 的重复闭环修订禁止相同有效源码重复建根，并在同一生成操作连续三次没有有效新候选时关闭该操作。所有开发及建根入口均不可用时可提前结束，仍执行已冻结赢家的独立测试；报告实际请求数及终止原因，不把未用预算计为已执行请求。

取得首个有效起点之前仍使用原16次初始化额度，以避免将不同的无效初始化误判为复制循环；取得有效起点后再应用三次限制。

搜索结束后，直接固定训练成绩最好的有效程序；同分取记录编号较小者。TraceAAD 和基线都不增加候选训练重评，不重新选择赢家。基线的 `selection_evaluations` 为 0。实现见 [TraceAAD](../traceaad/base/traceaad.py) 与[基线记录器](../baselines/shared/profiler.py)。历史批次按各自保存的选择规则解释。

最终程序确定后进行独立测试。测试结果不用于选择或修改程序。失败与未完成的路次如实报告。

## 模型与成本

当前默认后端为 DeepSeek，主比较关闭原生思考。模型、端点和默认采样设置见 [base.py](infra/base.py)，TraceAAD 搜索默认值见 [config.py](../traceaad/base/config.py)。实际条件以运行配置和调用记录为准。

相同生成次数不代表相同请求数、token 数或评价成本。反思、检查、重试与辅助模型调用分别计数。

| 成本记录 | 怎样解释 |
| --- | --- |
| 调用中的 `usage` | 接口返回的用量。缺失字段仍需标明缺失。 |
| TraceAAD 汇总 token 数 | 优先使用 `usage`；缺失时输入可能使用提示计数，输出可能使用配置上限。汇总可能包含估算。 |
| 评价次数与时间 | 分开报告搜索、最终重评和测试成本。 |

因此，不能把全部汇总 token 数称为接口实测用量。具体回退规则见 [state.py](../traceaad/base/state.py)。不同模型、思考模式、接口或计算预算分开报告。

## 怎样解释结果

比较前核对任务接口、数据、评价条件、模型、生成预算和最终选择规则。报告各路结果、有效路数与实际成本。单步改进、多步开发和完整搜索回答不同问题，需要写明观察范围。

实验记录说明要区分的解释、实际操作、原始数据位置、观察和认识变化。放宽条件后的补评注明新条件。选择机制是否有效，要看对应预算下的收益，不能只由某个过程指标判断。


## V19.2 当前候选的版本与成本语义（2026-11-01）

`bounded_development_20261101` 使用 schema 5，与旧版 V19.2 的轨迹信用机制分开解释。新旧记录不得仅因方法目录名相同而合并。旧检查点不在新语义下续跑。

全局默认仍为1000次实际评价；局部 `development_calls=4` 限制一个开发过程的实际模型请求，包含生成、格式/程序修复、接口失败及中断时已发出的请求。初始化另计。最多一次修复还受到过程剩余额度限制。0.45/0.30/0.25 是过程首步算子分布，总Refine比例会增加。对照必须报告这项变化，并区分接续、操作总量和修复可用性的效应。

搜索结束仍固定全部有效记录中的训练最好程序，同分取较早编号，再执行独立测试。成本分别报告评价、生成尝试、实际调用和tokens；探索性分析看过的测试结果不作为后续机制调参后的独立确认。完整候选及待执行对照见[设计](../docs/机制设计/V19.2.md)。本次机制重构未启动正式在线批次。

接续对照入口为 `--reselect-parent`：保留相同请求块、首步操作规则与修复额度，普通episode后续Refine重新选择段代表，初始化保护保持不变。实际操作次数可能因不同父代的成功/修复结果而分化，须报告。`--no-local-history` 是反馈形式整体消融，不能单独当作源码diff效果。

## V19.3 轨迹反思的实现条件（2026-11-01）

独立`traceaad_v19_3`使用`global_trajectory_reflection_20261101`机制标识和自身schema 1。默认1000次实际评价，包括初始化、运行失败与修复；顺序取得5份有效且规范化源码不同的初始算法。每次尝试最多一次共享修复。生成和反思分别请求，默认输出上限16384与2048 tokens；请求、角色、提供方usage缺失、排队时间与评价分别记录。

`local`、`siblings`与`trajectory`只改变反思可见范围，依次为本次尝试、增加同父代旁支、再增加近期主链。各组共用搜索、经验结构、BM25、效用维护和生成提示。`none`关闭反思，辅助比较模型预算的其他用途。每次实际展示的经验与原文随尝试保存；效用按最后一个实际已评价版本对所选父代更新一次，接口或解析故障没有算法评价时不评分。

当前实验入口明确使用全部实例共享的墙钟总时限，默认每实例10秒形成总额度（训练160秒）；使用2 GiB内存上限，与逐实例CPU约束分开解释。训练赢家固定后再测试，测试结果不反馈搜索。不同模型配置明确对应其tokenizer和上下文窗口。完整入口见[V19.3实验说明](traceaad_v19_3/README.md)。

11月1日正式启动`20261101_v19_3_co6`，六任务×种子0、1、2，共18路，每路1000次评价。使用与主比较相同的Qwen共享模型池，温度1.0，关闭原生思考；匹配Qwen tokenizer及49152-token上下文窗口。反思范围为`trajectory`，训练赢家固定后自动主测试。条件、源码与实际调用核对见[启动记录](../experiments_result/traceaad_v19_3/launch_20261101/README.md)。反思范围对照和冻结源—目标迁移检验尚未执行。

## V19.4 三环机制的实现条件（2026-11-01）

独立`traceaad_v19_4`使用`trajectory_process_learning_20261101`机制标识及schema 1。每路1000次实际评价，初始化为五次基础尝试，所得有效不同源码进入候选；空档案继续初始化。每次尝试共享至多一次修复，失败与修复重评分别消耗评价。连续十次无实际评价时终止。

生成提供近期形成过程、同起点尝试及全局经验，评价后进行独立轨迹反思。正负经验全部保留，双池BM25使用共同语料统计；已呈现经验的结果记录不作为单次淘汰依据。选择采用排名质量乘以局部演化响应因子，最近256次开发评价、一跳父子参考强度2、5%均匀项。`rank`固定响应0.5，`direct`只使用直接响应，`neighborhood`使用完整规则；三个预算对照保持其余机制相同。

正式配置沿用共享Qwen池、温度1.0、关闭原生思考、49152-token上下文及匹配的实际tokenizer。生成与反思输出上限分别为16384和2048。评价使用全部实例共享墙钟总时限，每实例10秒形成额度，训练160秒、主测试500秒，内存2 GiB。训练赢家固定后独立测试，同分取较早版本。

[准备入口](traceaad_v19_4/README.md)分别生成18路主组、18路排名对照、18路直接响应对照，以及六任务各5次评价的预检计划。预检初始化一次、跳过主测试，其条件与正式组分开记录；准备配置不代表正式批次已启动。
