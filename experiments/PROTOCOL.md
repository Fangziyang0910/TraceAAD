# 实验准则

今后所有实验按本文执行。任务与计分条件的实现是 `benchmarks/tasks.py` 与各任务目录，执行条件见第3节；限时只由评价器执行，提示不提时间。

## 1. 任务

六个任务，`--suite co6`。所有分数越小越好。自2026-10-11起采用**四项固定框架内的函数进化＋两项完整求解器进化**。

| task key | 问题与规模 | 待进化函数 | 固定框架 | 分数 |
| --- | --- | --- | --- | --- |
| `tsp_construct` | TSP，50节点，单位正方形均匀坐标 | `select_next_node` | 逐步构造：每步给出当前节点、起点、按距离排序的未访问节点和距离矩阵，函数返回其中一个节点；最后一个节点与回程由框架补全 | 平均回路长度 |
| `cvrp_aco` | CVRP，50客户，容量50，需求1–9，仓库(0.5,0.5) | `heuristics` | 每实例开始前调用一次，返回边先验；ACO 30只蚂蚁×100轮，衰减0.9，α=β=1 | 平均最好路线总长，只计不同节点之间的移动 |
| `fssp_gls` | 置换流水车间，50作业×20机器，时长1–99 | `get_matrix_and_jobs` | NEH初始化；200轮，每轮至多3步真实交换／插入下降，再调用一次函数，在扰动矩阵上对返回的1–5个作业做一步最好改进；保留真实最好解 | 相对NEH的平均makespan偏差（%） |
| `graph_colouring` | G(300, 0.5) | `solve(adjacency)`，返回完整颜色数组 | 不固定求解框架；DSATUR仅为可整体改写的起始代码；评价器核验每条边并统计不同颜色数 | 相对DSATUR构造的平均颜色数偏差（%） |
| `jssp_construct` | 作业车间，20作业×20机器，每个作业随机机器顺序，时长1–99 | `solve(processing_times, machine_order)`，返回完整开始时间矩阵 | 不固定求解框架；Giffler–Thompson＋MWKR仅为可整体改写的起始代码；评价器核验先后与机器互斥 | 相对MWKR调度的平均makespan偏差（%） |
| `op_aco` | OP，50节点，路程预算3，奖励按到仓库距离 | `heuristics` | 每实例开始前调用一次，返回边先验；ACO 20只蚂蚁×50轮 | 负的平均最好奖励 |

问题定义、函数签名与返回值的使用方式写在各任务的 `template.py`；固定框架在 `evaluation.py`；数据在 `dataset.py`（TSP 为 `get_instance.py`）。

两项完整求解器每实例只调用一次，允许辅助函数，构造、局部搜索、接受与重启均由程序决定。图着色返回非负整数颜色，编号无需连续；JSSP返回有限非负开始时间，列索引是工序位置。评价器用原始实例独立核验，修改输入副本不能改变约束或目标。

任务key保留以复用运行入口；`jssp_construct`现在表示完整JSSP求解器。两项运行配置的 `task_eval.interface` 为 `full-solver-v1`，评价身份也随接口改变。它们与此前的优先级函数实验分批报告；旧档案不改写，不使用当前接口续跑或补测，复现须使用对应批次的源码快照。其余四项的任务条件保持不变。

## 2. 数据

- 每个任务 **训练16个实例，同规模测试50个实例**。两者来自互不重叠的固定随机流，与搜索种子无关。
- TSP：训练种子2024，测试种子2025。CVRP：种子1234的同一随机流中依次取出的不重叠划分。OP：训练种子1234，测试种子4567。FSSP、图着色、JSSP：总种子20261007，每个实例的随机流为 `[总种子, 任务流, 划分流, 实例编号]`。
- 数据与参考值在评价器初始化时生成，不计入限时。

## 3. 评价

- **固定框架任务（TSP、CVRP、FSSP、OP）：候选函数每个实例最多使用 2 秒 CPU 时间，按该实例上全部调用累计；函数之外的时间不计入。** 预算由调用探针实时计量（进程 CPU 时间，纳秒精度），超出即判为超时。固定框架的耗时对所有候选相同，却随核心与负载相差约 3 倍，所以不计入；用 CPU 时间而不是墙钟时间，进程被其他程序抢占、等待的时间不计入。
- 图着色与JSSP的候选函数是完整 `solve`，每实例10秒CPU覆盖其全部求解过程及调用的辅助函数。没有额外的固定求解器计算；数据与参考生成、输入复制和最终合法性核验不计入函数预算。四项固定框架任务继续只累计可进化函数的CPU时间。
- **安全上限：固定框架任务每实例20秒墙钟；图着色与JSSP每实例30秒墙钟**，包含进程启动、固定框架与候选函数，只用来终止卡死的程序。从实例进程启动时计时，等待调度器分配核心的时间不计入。
- 任一实例超时、报错或违反返回契约，该次评价失败，没有分数；成功时按实例等权平均。
- 各实例在独立进程中运行，全局变量互不共享。不同实例可以并行，由所在机器的 CPU 调度器分配核心，每个实例绑定一个核心。评价可在本机（性能核 0、2、…、14 号）或 server3（0–51 号物理核）进行，不同机器的 CPU 核心视为同一评价条件。
- 每次评价的结果（含失败类型与每个实例的计时）写入运行目录：TraceAAD 在 `events.jsonl`，基线在 `evaluations.jsonl`。超时率按此统计。
- 分数只由最终可行解的质量决定；时间只作约束。
- BLAS／OpenMP 单线程。
- 所有方法在训练与测试中使用同一评价条件：相同数据；ACO 种子为 `1234 + 实例编号`；候选的 Python／NumPy 随机种子为 `(730241 + 实例编号) % 2**32`。

资源由调度器统一分配：CPU 调度器管理所在机器的评价核心（每个物理核一个线程）。模型请求发往 `deepseek` 后端（`deepseek-v4.1-flash` 网关，同时 24 个请求已验证）。运行与远端操作见[实验入口](README.md)。

## 4. 搜索与最终程序

- 每路预算 **1000次候选**，初始化／种子、解析失败、重复、新颖性拒绝和数值微调候选都计入。反思、策略、代码说明及新颖性判别调用不产生候选，单独记录模型调用；未返回候选的接口故障不消耗候选数。
- 每个方法每个任务 **3路**，搜索种子0、1、2。
- 所有方法使用同一模型 DeepSeek-V4.1-Flash（`--backend deepseek`，默认），默认采样设置为关闭思考，temperature 1.0，top_p 0.95（模型卡推荐值）。基线保留官方阶段设置：ReEvo初始化温度偏移、MCTS-AHD思路重述temperature=0、CALM任务配置的temperature／top_p；实际调用参数写入日志。提示长度用该模型发布的分词器和消息格式在本地计数，保留system/user角色。单user格式已与网关核对，system/user格式已与官方编码器核对。
- CALM运行官方支持的w/o GRPO变体；Shinka生成、meta与novelty判别使用同一生成模型，embedding使用独立服务。当前为阿里云`text-embedding-v4`，模型及接口写入运行配置，相似度阈值保留0.99。
- 最终程序：搜索结束时，按训练成绩取前 5 个程序，在训练集上按当前评价条件重新评价，冻结其中成绩最好的有效程序（同分取排名靠前者）。冻结后只做一次同规模测试。不设验证集；测试结果不用于选择或修改程序；测试失败记为失败。

## 5. 报告

每个任务、每个方法报告3路同规模测试成绩的均值，并列出各路数值。训练成绩同样报告3路均值。

## 6. 命令

```bash
# TraceAAD：打印计划，加 --launch 才启动
uv run python -m experiments.traceaad_<版本>.launch_local --suite co6 --batch <批次> --repeats 3 --budget 1000
# 基线：经本机 CPU 调度器排队运行
uv run python -m experiments.infra.local_queue --method <eoh|reevo|mcts_ahd|pathwise|calm|funsearch|shinka_evo> --suite co6 --batch <批次> --slots 3
# 冻结后的同规模测试
uv run python -m experiments.infra.evaluate <运行目录> --primary
```
