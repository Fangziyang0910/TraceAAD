# 实验条件与比较

**本页说明当前约定，以及核对于 2026-10-16 的实现差异。** 一次实验实际用了什么条件，应由该次 `run_config.json`、源码快照和调用记录确定。当前约定不回填历史缺失信息。

## 任务与数据

当前主比较使用 `co6` 六任务。任务注册、数据规模与计算预算见 [benchmarks/tasks.py](../benchmarks/tasks.py)。

| 任务 | 搜索修改的对象 | 最小化目标 |
| --- | --- | --- |
| [TSP](../benchmarks/tsp_construct/) | 固定逐步构造中的 `select_next_node`。 | 平均回路长度。 |
| [CVRP](../benchmarks/cvrp_aco/) | 固定蚁群算法（ACO）的边先验 `heuristics`。 | 平均路线总长。 |
| [FSSP](../benchmarks/fssp_gls/) | 固定引导式局部搜索（GLS）中的 `get_matrix_and_jobs`。 | 平均最大完工时间。 |
| [图着色](../benchmarks/graph_colouring/) | 完整 `solve`。 | 平均颜色数。 |
| [JSSP](../benchmarks/jssp_construct/) | 完整 `solve`。 | 平均最大完工时间。 |
| [OP](../benchmarks/op_aco/) | 固定 ACO 的边先验 `heuristics`。 | 负的平均奖励。 |

统一按 `fitness` 越小越好解释。模板说明函数接口与返回值用途，评价器说明固定框架和合法性检查，数据生成代码说明实例分布与种子。

| 数据条件 | 当前约定 |
| --- | --- |
| 训练 | 每任务 16 个实例。 |
| 同规模测试 | 每任务 50 个实例，与训练使用固定且不重叠的数据划分。 |
| 聚合 | 实例等权；当前六任务没有独立验证集。 |
| 完整求解接口 | 图着色与 JSSP 使用 `full-solver-v1`，与早期优先级函数实验分开比较。 |

## 评价与计算预算

| 任务类型 | CPU 计量范围 | 平均 CPU 上限 | 单实例墙钟上限 |
| --- | --- | --- | --- |
| TSP、CVRP、FSSP、OP | 生成函数及其调用的辅助计算。 | 2 秒／实例。 | 120 秒。 |
| 图着色、JSSP | 生成的完整求解函数及其辅助计算。 | 10 秒／实例。 | 120 秒。 |

全部实例合法完成后，检查：

> 平均 CPU 时间 = 生成函数累计 CPU 时间 ÷ 实例数。

超过平均上限则评价失败；单个实例超过均额不会直接淘汰。墙钟上限从实例进程启动时计时，包含启动和固定框架，不包含等待调度器分配核心的时间。

任一实例报错、返回非法结果或触及墙钟上限，整次评价失败，并取消剩余实例。成绩不按成功子集计算。时间作为约束，成绩由解的质量决定。

训练、同规模测试和方法执行的最终重评使用上述预算规则。实例隔离执行，BLAS／OpenMP 使用单线程。程序与固定框架的随机种子按实例固定。计量和执行见 [probe.py](../traceaad/probe.py)、[instance_evaluation.py](../traceaad/instance_evaluation.py)，测试条件见 [evaluation_execution.py](infra/evaluation_execution.py)。

生成提示提供任务、接口、返回值用途、成绩含义和该方法实际展示的反馈。实例数、数据划分、种子和评价记账不进入生成提示。超时修复可以提供实际耗时与时限。

## 搜索预算与最终选择

主比较约定每个方法、每个任务运行 3 路独立搜索，种子为 0、1、2，每路预算为 1000 次生成尝试。这是实验约定，不表示所有批次都已完成。

初始化、解析失败、重复程序、修复和其他生成程序的调用，均按方法规则计入。没有返回程序的接口故障不消耗生成次数，但请求与成本仍需记录。

**当前最终选择流程存在差异：**

| 方法 | 结束搜索后怎样选程序 | 额外评价 |
| --- | --- | --- |
| TraceAAD | 固定训练成绩最好的有效个体，同分取编号较小者。 | 无。 |
| 基线 | 按训练成绩取至多 5 个程序个体，重评后从有效结果中选择。不做源码去重。 | 最多 5 个候选程序的训练重评。 |

实现见 [TraceAAD](../traceaad/traceaad.py) 与[基线记录器](../baselines/shared/profiler.py)。比较结果需要报告这项差异及其成本。历史运行按当时保存的选择规则解释。

最终程序确定后进行独立测试。测试结果不用于选择或修改程序。失败与未完成的路次如实报告。

## 模型与成本

当前默认后端为 DeepSeek，主比较关闭原生思考。模型、端点和默认采样设置见 [base.py](infra/base.py)，TraceAAD 搜索默认值见 [config.py](../traceaad/config.py)。实际条件以运行配置和调用记录为准。

相同生成次数不代表相同请求数、token 数或评价成本。反思、检查、重试与辅助模型调用分别计数。

| 成本记录 | 怎样解释 |
| --- | --- |
| 调用中的 `usage` | 接口返回的用量。缺失字段仍需标明缺失。 |
| TraceAAD 汇总 token 数 | 优先使用 `usage`；缺失时输入可能使用提示计数，输出可能使用配置上限。汇总可能包含估算。 |
| 评价次数与时间 | 分开报告搜索、最终重评和测试成本。 |

因此，不能把全部汇总 token 数称为接口实测用量。具体回退规则见 [state.py](../traceaad/state.py)。不同模型、思考模式、接口或计算预算分开报告。

## 怎样解释结果

比较前核对任务接口、数据、评价条件、模型、生成预算和最终选择规则。报告各路结果、有效路数与实际成本。单步改进、多步开发和完整搜索回答不同问题，需要写明观察范围。

实验记录说明要区分的解释、实际操作、原始数据位置、观察和认识变化。放宽条件后的补评注明新条件。选择机制是否有效，要看对应预算下的收益，不能只由某个过程指标判断。
